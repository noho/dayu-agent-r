## 2. 目标、动机与完成定义

### 2.1 直接证据支持的 root cause

fresh production CLI observation 共接受 28 个 Run，但只出现 8 个 `RUN_SUCCEEDED`，其余 20 个以 `runner_candidate_invalid` 进入 `RUN_FAILED`；与此同时交互进程最终 exit 0。失败链的直接证据是：

1. Host 从 strict typed `CompactAcceptedReplacementV4` 构建 previous compacted pair；
2. packed block 路径经 `run_input_material_block()` / `normalized_material_text()` 删除空行并折叠行内空白；
3. readable view 路径仍持有 replacement 原始文本；
4. `validate_previous_compacted_view_pair()` 从 readable typed value 重新渲染，并要求与 packed block 文本完全相等；
5. 合法的多行 `answer_anchor.detail` 因此触发 `HostDurableError`，ordinary Run 在 runner candidate freeze 前失败；
6. PTY harness 只等待 terminal 总数，外层脚本又按计划 action 数机械递增计数；它没有读取每个 Run 的 terminal 类型和 reason，于是把 REPL exit 0 与 Run 成功混为一谈，并继续执行依赖失败 Run 的后续链。

这不是 validator 过严，也不是 prompt 或 scenario 问题。正确修复点分别是 Host previous-pair projection owner，以及 CI observation 对 Host canonical lifecycle facts 的只读投影。

### 2.2 F15 目标

`dayu.host.compact_material` 从一次 canonical typed projection 同时生成 packed `CompactMaterialBlock` 与 `PreviousCompactReadableView`：

- replacement 的每个 previous-view 文本叶子只在 canonical projection 边界归一化一次；
- packed block 与 readable view 都消费同一批 canonical typed atoms；
- 不从 packed/rendered 字符串逆向解析 typed view；
- 不对已经 canonical 的文本再次调用 normalizer；
- strict pair validator 保持完全相等校验；
- rolling compact、ordinary RunInput、reopen/reconnect 与 recovery tier 都消费同一 pair；
- F14 strict cumulative `compacted_source_refs` frontier 保持不变。

完成信号：合法空白、多行 Markdown、列表、表格内容不再造成 pair mismatch；尤其 answer anchor 的 title/detail 与其 packed renderer 始终同源，ordinary candidate freeze 可继续完成。

### 2.3 F16 目标

建立一个 **tracked、可复用、只读** 的 CLI CI observation helper，以 Host EventLog/shared lifecycle terminal contract 为唯一 Run 结果真源，并在 harness、evidence index 与 handbook 中明确分离：

- 每个 accepted Run 的 terminal 类型和 canonical reason；
- OS/PTY process outcome；
- dependent-chain gate outcome；
- evidence capture/validation outcome。

完成信号：进程 exit 0 只表示 REPL 正常退出，不能覆盖 Run failure；任何 required ordinary Run 非 `RUN_SUCCEEDED` 时，其 dependent chain 停止并留下可审计证据，独立 mandatory observation、public evidence 收集与 secret scan 继续执行。

### 2.4 非目标

- 不改变 `CompactAcceptedReplacementV4`、schema 5、Host durable DDL/EventLog event payload、Engine contract、CLI public options 或 compactor LLM schema。
- 不改变 `RUN_SUCCEEDED`、`RUN_FAILED`、`RUN_CANCELLED`、`RUN_LOST` 的 Host 生命周期语义；`RUN_LOST` 仍是独立 lost terminal，不伪装为 failed/succeeded，也不新增 public outbox 语义。
- 不宽松比较、不忽略 validator、不增加 downstream fallback/兼容 shim/heuristic parsing。
- 不改变 prompt、provider、model、tools、caps、formal oracle、scenario expected behavior、scenario predicate 或 scenario registry。
- 不把 harness 变成第二套业务 verdict/oracle。
- 不恢复 F14 已移除的 terminal sequence frontier；F14 accepted coverage frontier 仍只由 strict cumulative `compacted_source_refs` 证明。

## 3. Owner contract 与设计对齐

### 3.1 F15 owner

- Host 是 RunInput、durable accepted replacement、memory/context governance 的 owner。
- `dayu.host.compact_material` 是 accepted replacement 到 packed/readable pair 的 projection owner，也是当前 normalizer boundary。
- `dayu.host.compaction.validate_previous_compacted_view_pair()` 是 strict pair contract validator；它验证 owner 输出，不负责修复或猜测输入。
- Engine 不拥有 accepted replacement 或 previous compacted view，不在 Engine 增加补偿。

### 3.2 F16 owner

- Host EventLog/shared lifecycle terminal types 是每个 Run terminal 类型和 reason 的 owner。
- OS/PTY runner 是 process exit/timeout 的 observation owner；process outcome 不推出 Run outcome。
- tracked utils helper 只做 canonical Host facts 的确定性、只读投影和 dependency decision，不持久化新的业务事实。
- `docs/cli_ci.md` 是 CI evidence/gating handbook 真源；fresh evidence index 是该 contract 的实例，不是业务 oracle。

## 4. F15 设计决策：一次 canonical projection、两个同步输出

### 4.1 canonical projection 边界

在 `dayu/host/compact_material.py` 增加模块私有、严格 typed、不可变的 `_CanonicalPreviousReplacementProjection`（最终命名可在 implementation gate 依现有命名风格微调，但不得成为 public/schema contract）。它由 strict typed `CompactAcceptedReplacementV4` 一次构建，覆盖 previous view 的全部文本 section：

- summary；
- facts 的 claim，同时原样携带其 typed evidence refs；
- answer anchors 的 title/detail；
- open intents 的 text，同时原样携带 type/status；
- references 的 text，同时原样携带 reason/其他非文本 typed fields。

每个文本叶子恰好调用一次 `normalized_material_text()`。canonical 规则沿用现有 normalizer：去除 blank-only lines、折叠每行内部空白、保留非空行边界和 Markdown/list/table 字符；不发明第二套格式规则。

空白边界不在 projector 中“修复”：`CompactAcceptedReplacementV4` typed constructors 与 strict persisted parser 已要求每个必填 title/detail/text 满足 `strip() != ""`。因此 whitespace-only candidate 必须在 accept boundary 被拒绝，whitespace-only persisted payload 必须在 read boundary 被拒绝；pair projector 遇到任何违约值继续 fail closed。严禁静默 skip、补默认文本、重新编号或保留 label 空洞来掩盖 invalid durable truth。

F15 的生产修复覆盖全部 previous-view 文本 section，防止相同 root cause 在 summary/fact/intent/reference 重现；deterministic 格式矩阵重点锁定实际触发事故的 answer anchor title/detail，包括：

- leading/trailing/repeated whitespace；
- blank lines；
- multiline prose；
- Markdown bullet/numbered list；
- Markdown table；
- 多个 anchors 与 ordinal/label 对齐。

### 4.2 packed/readable 同源生成

具体数据流固定为：

```text
CompactAcceptedReplacementV4
        |
        | 每个文本叶子归一化一次
        v
_CanonicalPreviousReplacementProjection
        |                         |
        | typed atoms             | typed atoms
        v                         v
packed CompactMaterialBlock   PreviousCompactReadableView
        \                         /
         \-- strict pair validate/
```

实现约束：

1. 增加 private frozen typed wrapper（例如 `_CanonicalMaterialText`）表达“文本已经由唯一 normalizer 产生”。该 wrapper 只能由模块私有 `_canonical_material_text(raw_text)` 工厂在成功调用 `normalized_material_text()` 后创建；不得用 `bool`、裸字符串参数、`trusted=True` 或调用方约定表达 trust。
2. 增加模块私有 low-level block builder（例如 `_run_input_material_block_from_canonical_text()`），参数必须是 `_CanonicalMaterialText`，并从 wrapper 的 value 派生 size/digest/typed block；它不得再次调用 normalizer。
3. 现有 `run_input_material_block()` 保持普通 raw-input boundary 职责：需要归一化时通过 private factory 得到 typed wrapper，再委托 low-level builder；accepted tool evidence 的既有精确文本路径不得被意外归一化，且不能用该例外削弱 canonical wrapper 的类型边界。
4. previous summary/facts/intents/references 的 packed blocks 与 readable typed items都从 canonical projection 对应 atom 生成，不再一边用 normalized block、一边用 raw replacement。
5. answer anchor 先生成 canonical typed anchor（canonical title/detail + typed ordinal/metadata），再用 `previous_answer_anchor_block_text()` 正向渲染 packed text；readable view直接使用同一个 canonical typed anchor。禁止从该 rendered block 拆 bullet、ordinal、title 或 detail。
6. label/packing 顺序仍由现有 `_pack_previous_blocks()` 决定；readable item 只把生成后的 label 与对应 canonical atom 组合，不通过 label 或字符串反推业务字段。
7. `validate_previous_compacted_view_pair()` 保持 strict exact equality；不加 loose compare、raw fallback、异常吞并或特殊格式分支。
8. `transform_previous_compacted_view_pair_for_recovery()` 继续先验证、同步过滤、再验证；它不重新归一化，也不重建 pair。
9. `build_pre_dispatch_compact_material_view()` 的 F14 `consumed_source_refs`/strict cumulative frontier 逻辑不进入 canonical text projection，避免两个独立 contract 耦合。

### 4.3 F15 invariants

- 一个 replacement 文本叶子只有一个 canonical value。
- packed block `.text` 与 readable typed item 的正向 renderer 完全相等。
- digest/size 从最终 packed canonical text 派生。
- reopen/reconnect 不依赖内存缓存；从 durable strict replacement 重建时得到 byte-identical pair。
- reload fidelity test 必须从 canonical accepted event/artifact 建库，关闭 store 后通过物理只读 reopen 重建；比较完整 typed JSON、block text、digest 与 size，不复用任何首次构建的内存对象。
- recovery tier 只做现有的成对过滤，不改变剩余 atom 文本。
- canonical projection 是临时派生结构，不进入 durable state、prompt/schema 或 public API。
- whitespace-only accepted value 在 accept/read owner boundary 拒绝；projector 不 skip、不 renumber，也不把 invalid replacement 改写成较小的 coverage。

## 5. F16 设计决策：Run terminal、process 与 dependency 分离

### 5.1 tracked reusable helper

新增 `utils/cli_ci_run_observation.py`。该文件是长期跟踪的 CI observation contract；`workspace/tmp/` 两个脚本只作为本轮 fresh real observation 的临时消费者，其源码 digest 必须进入 evidence。

helper 的数据访问路径固定为：

1. 以 `db_path`、`artifact_root` 和 typed observation window 为输入，调用 `open_host_durable_read_store(db_path, artifact_root, HostSQLiteStoragePolicy())` 打开 Host **只读** durable store；
2. 通过 store 的 `run_read` 在 Host read transaction 内构造/调用 `EventLogStore.read_events_after_matching`；
3. filtered reader 的 event filter 只包含 `RUN_ACCEPTED` 与 `HOST_RUN_TERMINAL_EVENT_TYPES`，不直接 SQL 复制 lifecycle/filter/payload 语义，也不读取 `host_runs.status` 作为替代真源。

observation window 是不可变的 `(start_event_sequence, end_event_sequence]`，并可附加 exact `session_id`：start 在发送本次 observation 第一条业务 action 前取得；end 在进程/segment observation 完成后、该次 snapshot read transaction 开始时冻结。helper 使用 filtered reader 返回的 `covered_event_sequence` / `max_event_sequence` 做 event-sequence keyset 推进，直到覆盖 frozen end；禁止 OFFSET。page size 只是读取批次，不是 semantic scan cap。covered sequence 不前进、倒退、越过 end，或 window 内 accepted/terminal 无法完整归属，均 observation-invalid。

职责限定为：

1. 按 window 内 `RUN_ACCEPTED.event_sequence` 升序分配一基 `accepted_ordinal`，同时保留真实 accepted event id/sequence。跨 segment chain 另维护累计 absolute ordinal；事实 identity 始终是 session_id/run_id/event id/event sequence。
2. 为每个 Run 投影恰好一个 terminal：`RUN_SUCCEEDED`、`RUN_FAILED`、`RUN_CANCELLED` 或独立的 `RUN_LOST`；terminal class 由 `HostRunEventType` 机械映射，不新建第二套 lifecycle 枚举。
3. terminal reason 的唯一 persisted 真源是 terminal event row 的 `reason_json`，其唯一合法 shape 是 exact JSON object `{"reason": <non-empty str>}`。四类 terminal producer 都必须遵守同一 shape；missing/null、额外 key、空字符串/纯空白、非字符串、非 object 或 malformed JSON 均 observation-invalid。**禁止 fallback 到 `payload_json`、diagnostic event、日志文本或 `host_runs` 建第二真源。**
4. duplicate terminal 精确定义为：同一 `run_id` 出现两个或更多属于 `HOST_RUN_TERMINAL_EVENT_TYPES` 的 canonical facts；无论第二条 terminal type 与第一条相同还是不同都 invalid。`RUN_CANCELLING`、Attempt terminal及其他 lifecycle/diagnostic events 不参与 duplicate 判断。
5. 产出 typed immutable `RunTerminalObservation`/summary，并提供纯函数 dependency gate：只有明确 `RUN_SUCCEEDED` 满足 success dependency；failed/cancelled/lost 均返回 stopped + upstream Run identity + terminal + reason；未 terminal 在等待期为 pending，deadline 后为 invalid/incomplete。
6. 生成确定性 JSON projection，先按真实 accepted event sequence，再按 terminal event sequence 排序；不同 session 也不依赖文件时间戳、日志文本或偶然查询顺序。

helper 不读取或推导 process exit，不判定财报答案正确性，不改 Host state，也不创建第二份 Run status 真源。

### 5.2 process outcome

`prompt_observe_calibration.py` 保留 PTY 对 exit code/timeout/harness exception 的原始观察，但 fresh artifact 使用明确结构：

```json
{
  "process_outcome": {
    "kind": "exited | timed_out | harness_error",
    "exit_code": 0,
    "timed_out": false
  }
}
```

`kind=exited, exit_code=0` 只表示 REPL 进程退出，不命名为 scenario success，也不覆盖任何 Run terminal。fresh evidence index 不保留 `scenario_success`、含混的顶层 `success/passed`，或把 `execution_outcome=success` 当作综合 verdict 的字段。

### 5.3 per-Run terminal/reason evidence

tracked helper 只返回 typed projection/JSON value，不负责文件 I/O、descriptor 或 digest；每个 scenario/segment 的 temporary harness 负责把该 value 写成独立 `run-terminals.json` 并生成 descriptor/digest。文件至少包含：

- observation window 的 `start_event_sequence` / frozen `end_event_sequence` 与可选 exact `session_id`；
- accepted ordinal、session_id、run_id、`RUN_ACCEPTED` event id/sequence；
- terminal event type、event id/sequence；
- terminal class：`succeeded | failed | cancelled | lost`；
- strict canonical reason，且只来自 exact `reason_json={"reason": <non-empty str>}`；
- required/dependent-chain role。

`RUN_LOST` 必须明确保留为 `lost`，并标注其非 public-outbox 语义；不得映射为 success 或普通 failed。raw SQLite snapshot 可用于受限诊断，但不可代替此 canonical projection。

### 5.4 dependent-chain stop 与 isolation

`prompt_observe_calibration.py` 的 `PtyAction` 增加显式 nullable typed 字段 `required_success_accepted_ordinal: int | None`，禁止解析 magic trigger 字符串表达 dependency。每个 dependent prompt只声明其直接 upstream Run 的累计 absolute accepted ordinal；当前 work unit 不需要多 upstream dependency。跨 segment 在启动 segment 前执行同一 typed segment-level gate。这只是执行依赖，不是 scenario predicate/oracle：

- 发送 dependent prompt 前，helper 查询其明确声明的 upstream Run；
- upstream succeeded：发送下一 prompt；
- upstream pending：继续等待至既有 deadline；
- upstream failed/cancelled/lost：不发送该 dependent prompt及同链后续 prompt，写 `dependency_stopped`，记录 upstream run_id/terminal/reason；
- upstream missing、duplicate terminal、reason malformed 或窗口不完整：不发送 dependent prompt，写 `observation_invalid`，不得猜测成功；
- stop 后只做有记录的 PTY cleanup/EOF，不再等待原计划 terminal 总数。

`f14_real_cli_observation.py` 不再按 `len(actions)-1` 机械递增 `ChainState.terminal_count`，而从实际 accepted/terminal observations推进 ordinal。跨 segment 的依赖同样检查明确 upstream success；被阻断的 dependent segment写 not-run/stopped row，不启动新的业务 prompt。

以下 independent mandatory work 不因一个 Run 失败而短路：

- 已授权的独立 observation scope；
- process artifact 固化；
- canonical terminal/reason evidence 固化；
- public tool evidence 收集；
- evidence index 汇总；
- secret scan。

这实现“dependent chain stop + independent isolation”，但不会在 harness 中复制业务 oracle。

### 5.5 fresh evidence index

新 `execution-index-f15-f16.json` 只汇总明确命名、相互独立的字段：

- target commit、tracked helper SHA、两个 temporary harness SHA、CLI/provider/tool/corpus identity；
- `process_outcomes`：exited/timed_out/harness_error 计数和逐行引用；
- `run_terminal_summary`：accepted、succeeded、failed、cancelled、lost、missing、duplicate/invalid 计数；
- `run_terminal_records`：各 `run-terminals.json` descriptor/digest；
- `dependency_gate`：proceeded/stopped/invalid/not-run 及 upstream terminal/reason引用；
- `evidence_status`：complete/invalid 与结构化 validation errors，只描述 evidence 完整性，不是 scenario verdict；
- `context_compaction_observation`：观察到的 accepted compaction 次数与 replacement refs，仅报告事实；
- `public_evidence`、`secret_scan`、artifact descriptors/digests；
- `oracle_status: pending_user_adjudication`。

index 不包含 `scenario_success`、综合 `success/passed`、或由 exit 0 推导的 scenario verdict。它也不重算 formal oracle。

### 5.6 handbook

更新 `docs/cli_ci.md`，成为以下规则的唯一 handbook 真源：

- process outcome 与 per-Run terminal/reason 的定义和分离；
- EventLog/shared lifecycle terminal contract 的 owner；
- `RUN_LOST` 独立处理；
- success-required dependent chain 的 stop/isolation 规则；
- `run-terminals.json` 与 fresh evidence index 字段；
- missing/duplicate/malformed evidence 的 fail-closed 行为；
- independent mandatory evidence/secret scan 不被 objective Run failure 短路；
- index 不是 formal oracle，scenario 继续由现有 registry/oracle contract裁决。

## 11. 风险与控制

- **格式矩阵偏窄风险**：事故在 answer anchor 暴露，但 root cause 可影响全部 previous-view 文本 section。生产 projection 覆盖全部 section，answer anchor 只作为重点 deterministic matrix，而不是局部特例。
- **双重归一化风险**：如果 composed anchor block 再走 `run_input_material_block()`，会重新引入两条规则。用 `_CanonicalMaterialText` typed wrapper + 专用 low-level builder 锁定边界，不接受 bool/string trust。
- **whitespace skip 漂移风险**：invalid accepted text 若被 projector skip 会改写 durable truth与 coverage。accept/read boundary tests 明确拒绝，projector fail closed且不 renumber。
- **字符串反推风险**：不得从 packed bullets/table 还原 typed anchor；typed canonical anchor 永远先于 renderer。
- **EventLog 扫描截断风险**：冻结 `(start, end]`，复用 filtered reader 的 covered/max sequence 做 keyset 到 end，并对 no-progress/越界/duplicate fail closed；禁止 OFFSET，page size 不成为 semantic cap。
- **reason 双真源风险**：terminal reason 只接受 exact `reason_json` object；payload/log/status fallback 无条件禁止，并由 producer/reader tests 双向锁定。
- **exit 0 误判风险**：fresh index 没有综合 scenario-success 字段；process/run/dependency 分栏，tests 明确覆盖 exit 0 + RUN_FAILED。
- **链停止扩大风险**：每个 action 显式声明 dependency；只停止同链 dependent work，独立 mandatory evidence 继续。
- **temporary harness 不可追踪风险**：长期语义全部位于 tracked utils helper + deterministic tests + handbook；temporary source SHA 进入 evidence。
- **oracle 漂移风险**：implementation diff 明确排除 registry/predicate/oracle 文件，real rerun 只报告 facts 和 pending adjudication。
