### 5.3 Formal chain state machines 与互斥 branch allocation

最多三条 fresh chain，allocation 在任何 provider call 前一次性冻结；每个 workspace只执行一条，不复用 proof state：

### 5.4 Deadlines 与调用上限

- global deadline owner在allocation前一次冻结：global start、global wall deadline=1,800s、provider cutoff=`start+1,620s`、
  finalization reserve=180s、relative ref与file-byte SHA。identity/SHA漂移时任何chain都不得启动。
- allocation owner随后一次性创建三条immutable entries：ordinal、chain id/role、`max_wall_seconds=540`、ordinary/compactor/total call
  caps、state=`not_started`、allocation relative ref与file-byte SHA。`3×540=1,620s`只是allocation maxima总和，不代表三条absolute
  clock在allocation时同时启动；没有第四chain或超时补跑。
- 只有attempted chain在首个segment spawn/provider start前原子创建active deadline owner：`activated_at`、
  `cutoff=min(activated_at+540s, global_provider_cutoff)`、effective wall seconds、state=`active`、active relative ref与file-byte SHA。
  active owner commit同时把publication discriminator不可逆地转为`attempted`；其后即使spawn/provider start失败也不得回退成
  `provider_not_started`，必须写typed attempt terminal/seal。remaining time只能从该active owner与global owner读取；创建失败、
  effective seconds非正、NaN/Infinity或cutoff越过global cutoff时provider不得启动。
- `provider_not_started` chain保持allocation state=`not_started`，active deadline state固定`not_created`；不存在activated_at、cutoff、
  effective seconds、active ref或active SHA，skip seal不得伪造这些字段。
- effective ordinary`max_iterations=20`必须由 production assembly再次证明；因此每 Run ordinary runner-call hard cap为21。
- Chain 01：4 Runs ×21 + 最多3 operations ×5 compactor calls = 99 total runner-call hard cap。第三个operation若在R4已启动segment
  内出现，可在同一cap/deadline内消耗最多5次compactor calls并产生canonical terminal；只禁止terminal后的新segment。
- Chain 02 / 03：各 3 Runs ×21 + 2×5 = 73。全 F20 formal hard cap为`99 + 73 + 73 = 245`。
- 每个segment effective timeout是caller requested、active deadline remaining、global provider-cutoff remaining三者最小正值，且全部
  owner refs/SHA必须匹配；production provider/transport失败不授权重试segment，失败原样seal并进入execution index。

## 10. Risks、open questions 与 stop conditions

  不再开segment，不得声明reconnect成立或first compactor call=0。
- **proof composition/网络/ledger漂移**：scheduler+local-execution双端口、同durable store admission、OS profile/bootstrap/binary/event-set、

  blocking stop；禁止direct SQL、in-process tool fallback、Python symbol替换或formal wrapper补偿。

- **MiMo provider/transport失败或deadline耗尽**：原样seal，未开始chain按allocation记skip；无第四链。
- **public semantic合格但publication schema失败**：publication verdict FAIL；sealed tree不回写，只有新publication identity可重做。
