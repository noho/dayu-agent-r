## Compactor LLM-facing follow-ups and north star

第一轮 follow-up 已修复三类问题：完整 typed input 被独占 marker 定义为不可信引用材料；当前 user prompt 自足说明 strict input/output 字段、类型、必填性、允许值、八种 `source_kind`、coverage 与同源完整示例；internal validation feedback 与 LLM-facing repair projector 分离，模型只收到自解释的 `required_action` 和 `issues`，且每次基于同一 immutable input 重产 whole candidate。

最新 output business semantics 由 user prompt owner 明确承诺：

- `session_summary` 保存整体任务背景、进展、当前状态与关键约束；`text` 只概括 cited material，`source_labels` 是直接来源标签。
- `session_summary: null` 表示本次完整 replacement 不含摘要；accepted 后当前摘要变为空，包括清除既有摘要，但不影响同一 candidate 的其它四类业务语义项。
- `evidence_facts.claim` 必须由 `support_labels` 指向的 accepted `evidence_material` 或 `previous_evidence_fact` 直接支持；`context_labels` 只能补背景或限定，不能直接支持 claim，也不能弥补 support 不足。
- `answer_anchors` 只整理既有回答、判断或结论；`title` 标识主题，`detail` 保存既有结论及必要条件、边界和不确定性，`source_labels` 只引用 `answer_material` 或 `previous_answer_anchor`。
- `superseded`：旧内容已被更新、更完整或更权威内容替代，继续保留会过时、冲突或误导。
- `redundant`：内容仍有效但必要信息已完整表达，丢弃不损失独立业务信息，且不能掩盖冲突或遗漏。
- `out_of_scope`：内容与当前输入、会话任务及可预见后续无关；不能因难分类、冲突或依据不足而使用。
- `policy_limit`：source 仍相关且原本应保留，当前 repair feedback 明示具体 cap，并且为让完整 replacement 满足该 cap 必须 drop；首次请求、无 repair feedback 或无具体 cap 时禁止猜测或使用。

LLM-facing north star：让无状态、会犯错、会走捷径、上下文有限且偏好模式匹配的模型，在最低认知负担下，只依赖当前输入就能稳定做出正确下一步；文本只保留当前任务所需的动作、输入、输出、判断规则和禁止事项，业务语义自解释，内部治理 label 只作引用，不伪装为事实。

上述文案不改变 Host typed schema、strict parser、accept barrier、Memory replacement、状态机或 provider/model semantics；deterministic validation 证明 owner contract，不代替真实模型行为观察。
