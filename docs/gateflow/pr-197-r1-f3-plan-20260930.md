## 目标、动机、成功信号与非目标

目标是让四个开发分析脚本仅使用操作者显式指定的样本根和适用样本清单，能在任意受控临时根复现同一分析路径。成功信号：必需 CLI 输入缺失时明确拒绝；有效非空清单真实定位所列文件并传入 worker；四文件无固定私人 locator 或样本身份；分析算法、转换调用语义和导出业务字段保持；受影响代码以及激活 venv 后全量 pyright 通过。

动机成立但严重性保持低：直接代码证据证明现行开发脚本不可移植，也把个人 locator 写入当前仓库树；这不是生产下载、转换或财报分析算法的故障。根因 owner 是开发分析脚本的样本输入边界，不能在生产 Fins/Docling 或下游报告中补偿。

非目标：不改 `dayu/`、依赖、生产算法、历史 artifacts、样本选择算法、A/B 单臂转换脚本或其它分析脚本；只容许被触碰 `_number_diff` 内无闭包 `counters` 等价提升为模块级私有 `_number_counters`，不做普遍重构；不读/扫描私人语料、不运行外网 provider、不改用户数据；不迁移旧清单、不追加兼容入口、不构建配置框架、不新增永久测试/覆盖率任务；不建分支/工作树、不 commit/push/PR/merge、不清除历史、不强推。

## 最小 CLI 与样本清单 contract

四个入口共用两个必需参数：`--sample-root DIR` 与 `--manifest FILE`。没有隐式样本根、默认清单、环境变量回退或目录枚举。

| 入口（开发 checkout 内以 `python -m utils.<模块>` 调用） | 其它参数 | 产物/数据根 |
| --- | --- | --- |
| `utils.docling_schema_regression` | `--parallel` 正整数，默认 2；`--out DIR` 可选 | 默认仓库根下 `workspace/tmp/docling-regression` |
| `utils.build_semantic_digests` | `--parallel` 正整数，默认 4；新增 `--out DIR` 可选 | 同上，写 `<out>/digests` |
| `utils.verify_missing_tokens` | `--workers` 正整数，默认 2；新增 `--out DIR` 可选 | 同上，读 `<out>/digests`，读/写 `<out>/verify-cache` |
| `utils.ab_ocr_compare` | 既有 `--out DIR` 仍必需 | 读 `<out>/r`、`<out>/v`，写 `<out>/ab-summary.md` |

删除 schema 的 `--samples/--limit` 与 verify 的位置参数 `stems`，清单就是本次完整选择，不再叠加第二种选择语义。不保留旧选择兼容分支。并行默认值不改；0/负数以用法错误拒绝，而非交给 executor 崩溃。模块方式统一支持 `utils` 内共享 helper 的包导入，不修改 sys.path，不增加 direct-file/module 双模式 import shim；模块 docstring 与 help 给出上述 checkout 命令。开发分析脚本不成为安装后的产品 CLI。

新 manifest 是 UTF-8 JSON 顶层**非空数组**，数组顺序就是输入顺序。字段契约如下，不加 schema version、ticker、baseline、arm locator、自由 extra payload 或选择标签。

| 字段 | 类型 | 必需性 | 含义与规则 |
| --- | --- | --- | --- |
| `pdf` | 非空 `str` | 全部入口必需 | 相对 `--sample-root` 的 PDF 路径；用 `/` 分隔；扩展名不区分大小写为 `.pdf`；不得绝对路径、含 `..` 路径分量或解析到根外 |
| `id` | 非空 `str` | A/B 必需，其它入口可省略 | A/B 原有报告样本标签，来自操作者输入；不由序号/文件名猜测；A/B 内唯一 |
| `kind` | 非空 `str` | A/B 必需，其它入口可省略 | A/B 原有显示说明；不新增枚举或自动分类规则 |

记录只能含上述字段。空白字符串、null、错误类型、未知字段都拒绝；对值不做静默 strip、填默认或宽松转换。前三入口可使用同一份含 `id/kind` 的 A/B 清单，但不消费/导出这两个元数据。不得宣称历史 `samples-2.3.json` 已迁移。

前三入口最小例子：

```json
[{"pdf": "nested/example.pdf"}]
```

A/B 最小例子（也可供前三入口使用）：

```json
[{"pdf": "nested/example.pdf", "id": "example-1", "kind": "合成对照"}]
```

示例不是预装样本；`nested/example.pdf` 必须由操作者在样本根准备。PDF stem 直接由该文件名推导，基线固定同目录 `<stem>_docling.json`，保留已有命名规则；不要求 `fil_cn_` 前缀。清单中 resolved PDF 路径与 stem 均须唯一：四种产物都以 stem 命名，两个目录中同 stem 会覆盖/错误复用，必须在输入 owner 拒绝而不是 worker 中补后缀。

### 路径与输入错误

1. CLI 的 `sample-root/manifest/out`：绝对路径直接使用，相对路径均按启动 cwd 解析后 `resolve()`。manifest 可以放在 root 外；其记录的 `pdf` **始终按 sample-root**，不按 manifest 所在目录。
2. sample-root 必须已经存在且为目录；manifest 必须已经存在且为普通文件。解析 root/每条 PDF 后检查 `pdf.is_relative_to(root)`，所以指向根外的 symlink 也拒绝。root 自身为目录 symlink 时按解析后的目标根处理，不额外发明 symlink 禁令。
3. 在创建输出目录、写报告、查结果缓存或提交 worker **之前**完成全部记录校验：格式、唯一性、PDF 普通文件，以及各脚本必需的输入文件。不 `rglob/glob` 样本根，不从邻接 PDF/旧结果猜样本。
4. schema 基线仍可不存在（现行 `base_parseable/top_key_diff=None`）；若该路径存在却非文件则拒绝。digest/verify/A-B 的同目录基线必需且为文件。verify 的 `<out>/digests/<stem>.json` 与 A/B 两臂 JSON 必需且为文件。即使已有缓存/结果，PDF 和脚本必需基线仍须通过预检。
5. root 不存在/非目录、manifest 不存在/非文件/不可读/JSON 语法错误、空数组、非数组、记录错误、文件缺失、stem 冲突、A/B 元数据缺失或重复 id、非法 worker 数：打印中文错误，包含入口/记录索引/相关路径与缺失项，以 argparse 用法错误 `2` 退出；不产生目录或分析产物，也不部分执行前几条。
6. 输出根存在却非目录同样在写入前拒绝。schema/digest/verify 的输出根可不存在，预检成功后按需要建目录；A/B 输出根及两臂文件必须存在，它只是消费既有输入。
7. 文件内容的 Docling/digest/arm 数据错误仍属于既有分析消费路径，而非新 manifest parser：schema、digest 保持折叠 `error` 的行为；verify、A/B 的读取/解析异常使进程失败，不能变成成功跳过。分析执行期间发生 I/O/转换失败不承诺回滚；本 slice 不增加事务或完整业务 schema 校验。

## Owner 与共享 helper：真实重复支持的最小设计

新增 `utils/analysis_sample_inputs.py`，只承载开发分析的 root/manifest/PDF 定位与同目录基线路径规则；不进 `dayu.runtime`，因为这是开发分析特定输入，不是多业务层的公共运行时能力。

共享理由是四份代码真实重复相同 PDF → stem → 同目录 baseline 规则、四个 CLI 必须一致解释同一非空定位清单、所有产物真实使用 stem 键。若复制四份 parser，会产生多个输入语义 owner。共享仅限这一小型输入 owner；不共享数字算法、Docling 输出类型、executor、缓存策略、报告构建或 pipeline。

共享模块的精确接口/类型：

| 符号 | 类型/职责 |
| --- | --- |
| `AnalysisSample` | frozen dataclass，只有 `pdf_path: Path`、`sample_id: str \| None`、`kind: str \| None`；不存 root/out/cache/payload，不存可从 PDF 推导的重复 stem/baseline |
| `load_samples(sample_root: Path, manifest_path: Path) -> list[AnalysisSample]` | 解析 CLI 路径，校验 root/manifest/记录/PDF/唯一 stem，顺序返回；OSError/ValueError 向 main 交付用于 `parser.error` |
| `baseline_json_path(pdf_path: Path) -> Path` | 唯一的同目录 `<stem>_docling.json` 推导；不读文件 |
| `_read_records(manifest_path: Path) -> list[Mapping[str, JsonValue]]` | 在标准库 json 边界把 `json.loads` 结果标为 `JsonValue`，逐级 runtime 校验顶层/记录后收窄；不直接 cast 为已验证样本 |
| `_resolve_pdf_path(sample_root: Path, relative_pdf: str) -> Path` | 相对路径、扩展名、containment 与普通文件校验；不搜索 |

其它逐字段检查内联在 loader 中即可，不引入 policy/profile/callback/factory/全能 options 类。A/B 的 `id/kind` 必需性、`id` 唯一性均由 `ab_ocr_compare.main` 在完整输入预检阶段检查，缺失或重复经 `parser.error` exit2；使用 `set[str]` 在该入口检查，不改值、不猜标签。非 A/B 三入口不校验重复 id，公共 loader 仅检查已提供元数据的非空字符串类型，不消费其业务身份；其它脚本的基线/产物要求由各入口主线程预检。公共 loader 不承载四种分析状态机或复制生产 schema。所有新增函数、dataclass 和模块中文 docstring 自足说明参数、返回值、异常；新 CLI help 中文说明输入格式、基准路径、缓存与最小例子。

共享导入统一 `from utils.analysis_sample_inputs import ...`；本 plan 的正式执行命令为 `python -m utils.<模块>`，在 checkout cwd 运行。schema/digest 保持 `ProcessPoolExecutor`；verify 保持 `ThreadPoolExecutor`，不统一 executor。ProcessPool worker 保持模块顶层函数，可 pickle；只传普通 `Path`，不传闭包、parser Namespace、回调或 extra payload。

### 结果类型落地范围（A1：仅静态表达已核实字段）

以下是完整的脚本本地有效输入/结果视图，类型名称只用于开发契约，不进入 LLM prompt。Required 是已有下标读取的前置形状，不是新增 runtime validator；缺省或畸形仍沿原消费路径处理。类型分别放在其脚本内，不放输入 helper，不发布产品 schema；只用各脚本实际需要的类型，不跨脚本 re-export。

```python
from typing import NotRequired, Required, TypedDict, TypeAlias, cast

from dayu.contracts.json_value import JsonValue


class SchemaDocument(TypedDict):
    """schema 有效输入视图；cast 不验证内容。"""

    texts: NotRequired[list[JsonValue]]
    tables: NotRequired[list[JsonValue]]
    pictures: NotRequired[list[JsonValue]]

    tables: int
    pictures: int

    top_key_diff: list[str] | None

    """构建中以及异常前可能写入的部分字段。"""

    new_version: JsonValue

    """无 error 的既有完成结果必有 new_version（值可为 null）。"""

    new_version: Required[JsonValue]


class SchemaErrorSummary(SchemaSummaryFields):
    """error 必需，保留异常前可能写入的 version。"""

    error: Required[str]
    new_version: NotRequired[JsonValue]


SchemaSummary: TypeAlias = SchemaSuccessSummary | SchemaErrorSummary


class SchemaAggregate(TypedDict):
    """既有磁盘汇总字段。"""

    total: int
    error_count: int
    failed_stems: list[str]
    closed_json_fail: int
    new_parse_fail: int
    base_parse_fail: int
    top_key_diff_count: int
    version_same_count: int
    identical_count: int

    """下标消费的 text 必需，label 只由 get 消费。"""

    text: Required[JsonValue]
    label: NotRequired[JsonValue]


class DigestCell(TypedDict):
    """既有单元格文本视图。"""

    text: NotRequired[JsonValue]


class DigestTableData(TypedDict):
    """grid 的每一行都是数组，可按原表达式取长度。"""

    table_cells: NotRequired[list[DigestCell] | None]
    grid: NotRequired[list[list[JsonValue]] | None]


class DigestTable(TypedDict):
    """表格可缺省 data。"""

    data: NotRequired[DigestTableData | None]


class DigestDocument(TypedDict):
    """digest 的现有可空数组消费视图。"""

    texts: NotRequired[list[DigestText] | None]
    tables: NotRequired[list[DigestTable] | None]


class DiffBlock(TypedDict):
    """原始 diff 摘要字段。"""

    tag: str
    base_snippet: str
    new_snippet: str
    base_len: int
    new_len: int
    moved_to_table_ratio: NotRequired[float | None]


class NumberTotals(TypedDict):
    """文本与表格两口径合计。"""

    texts: int
    tables: int


class NumberDiff(TypedDict):
    """数字 token 对比。"""

    base_total: NumberTotals
    new_total: NumberTotals
    merged_base_total: int
    merged_new_total: int
    missing_merged: list[str]
    added_merged: list[str]


class GridSize(TypedDict):
    """既有表格行列数。"""

    rows: int
    cols: int


class TableSummary(TypedDict):
    """表格规模摘要。"""

    count: int
    total_rows: int
    largest_grids: list[GridSize]

    new: int

    new: TableSummary

    new_count: int
```

落地位置与规则：

| owner/位置 | 精确落法 | 不变量 |
| --- | --- | --- |
| schema 第三方 `export_to_dict()` 与 baseline `json.loads(...)` 出口 | 各自 `cast(SchemaDocument, ...)` | texts/tables/pictures 是 `NotRequired[list[JsonValue]]`，**非 null 数组**；version 为 `NotRequired[JsonValue]`，允许 null。六处原 `len(...get(..., []))` 保持，不用 Sized、不在取值处铺 cast、不改为 isinstance/default 计数 |
| schema/digest 的 closed-JSON 调用 | 原 `isinstance(exported, dict) and _is_closed_json_value(cast(JsonValue, exported))` | cast 只给已核实 JSON 出口视图；原 bool 校验器继续实际验证，不改为 TypeGuard、跳过校验或新增 validator |
| schema 结果构建/自身 JSON 写出返回边界 | `summary: SchemaPartialSummary = {"stem": stem}`，写盘字段/公式保持，返回 `cast(SchemaSummary, summary)` | 无 error 时原路径一定已写 new_version（其值可能 None）；有 error 时保留此前所有部分字段，不填默认版本或裁剪失败结果。只对自身完成出口表达已核实联合形状 |
| schema 主线程和磁盘回读 | `summaries: list[SchemaSummary]`；`all_summaries: list[SchemaSummary]`；每个所选 result 的 `json.loads` 出口 `cast(SchemaSummary, ...)`；`summary_payload: SchemaAggregate` | `"error" not in s` 对成功/失败联合的收窄让原 `s["new_version"]` 合法，不改原 get guard 或汇总公式。不能把 partial 的 version 谎称无条件必需，也不在消费者补 fallback |
| digest exported/baseline | `cast(DigestDocument, export_to_dict()/json.loads(...))`，`digest: DigestResult` | DigestText.text 显式 Required（_headings 下标）；label 与 get-only 键可 NotRequired。原 `.get/or []/or {}` 与 `_texts_from_exported` 的 isinstance 保持，不添加/删除 runtime 检查 |
| digest 算法局部容器/汇总 | `digested: list[DiffBlock]`、`entry: DiffBlock`、`grid_samples: list[GridSize]`、`manifest: DigestManifest` | grid 为 `NotRequired[list[list[JsonValue]] | None]`，每行可 len；rows/cols/排序/抽样、返回业务字段全部保持 |
| verify exported/cache/baseline JSON 出口 | `cast(TokenDocument, ...)` | get-only TokenText/TokenCell.text 可缺省，原 texts/table_cells 容错规则保持 |
| verify digest JSON 出口/返回 | `cast(VerifyDigest, json.loads(...))`，返回 `VerifyResult` | numbers、missing_merged、added_merged 均 Required，原两层下标不改；缺键继续原 KeyError，不以 get/fallback 静默成功 |

`SchemaSummaryFields/Partial/Success/Error/Summary/Aggregate/Document/ItemCounts` 只在 schema 脚本；`Digest*`、`DiffBlock/NumberTotals/NumberDiff/GridSize/TableSummary/TextLens/PairedTableSummary/HeadingSummary/OrderSummary` 只在 digest；`Token*`、`Verify*` 只在 verify。A/B 未触及的 arm 解析/比较函数不借机做全仓类型治理。所有新类/模块中文概览，函数完整中文参数/返回值/异常 docstring；`_number_counters` 的异常说明指出沿用输入结构错误，不能称新校验器。

cast 在运行时无操作，不担保外部内容实际符合视图。**不得**复制 nullable schema 数组建议（原 len 仍红）、把 digest 的 nullable 规则搬到 schema、用泛 Sized/广泛 cast 掩盖真实错误、把 manifest 直接 cast 为已验证记录。malformed/null schema 输入继续在原计数点抛 TypeError 并折叠 error；字符串等原本可 len 的异常值也不新造拒绝规则。历史内容质量保留原消费边界，不新增全面 schema validator。

这部分是修改 worker 签名所需的有限类型收敛，不是全仓弱类型治理。精确类型已由本次独立配置探针实际检查；若实施发现无法在这些视图/出口与原运行表达式内闭合，或必须改其它算法/生产接口/产品 contract，立即停下，不即兴设计。

### 数据流与状态

`argparse -> load_samples -> 各 main 完整必需文件/元数据预检 -> 确定本次结果键集合 -> 读缓存或 submit worker(Path...) -> 原分析与导出 -> 仅所选结果汇总`。

状态只增加输入阶段：未校验 → 输入有效 → 分析/续跑；输入无效 → exit2，无输出。无 durable state/schema 变更，无 Host/Engine 生命周期变化。分析后的原成功/失败规则保持，A/B 缺输入不再进入分析。基线配对、选择与 worker 的输入路径必须同源；不能 worker 再搜索，也不能输出反推出样本。

1. 用 `TemporaryDirectory(dir="workspace/tmp")` 创建并清理自身合成根；包括 root 下 `nested/fixture.pdf` 的唯一标记字节、真实 `DoclingDocument` 构造的 `fixture_docling.json`，以及 root 外的 manifest。至少两条不同 stem/不同标记的记录用于选择与并行路由验证；单条最小例子用于类型/错误例。输出使用另一临时目录，所有读写都限这批自建路径。
2. 正常 CLI 子进程以 `sys.executable -m utils.<模块>` 执行：schema/digest 预置当前样本的合法结果/digest（可来自下项 worker 调用），验证非空清单续跑；verify 预置真实文档导出缓存和 digest；A/B 预置按已核实 producer 字段构造的 r/v JSON。必须 exit0 且对应选择结果出现。所有输出根额外放一个**未选中的**合法结果/digest：summary/_manifest/report 不能包含它，文件原字节不变；`_manifest.json` 本身不能被计入下一轮。验收不让子进程 cache miss，防止转换初始化或模型下载。
3. 不能以上项全缓存 CLI 作为未缓存输入正确的唯一证据：同一 harness 通过 loader 的真实已解析路径调用三个修改后的 worker。仅在临时 harness 用 `unittest.mock.patch` 替换已核实的 `dayu.documents.docling_runtime.convert_pdf_bytes_with_docling`；stub 有完全相同的有类型参数，断言逐样本原始字节、stream_name 与默认 OCR/table 参数，返回带真实 DoclingDocument 的 `ConversionResult.model_construct(document=...)`（只使用 document 字段）。这不是有效 PDF/OCR 转换测试。每个 worker 必须至少一次 cache miss。另在 harness 的 main 调用中临时替换 executor 为记录 submit 参数并调用真实 worker 的同步验收替身：核对 PDF/基线/out 与每条记录对应，未传全局根或 Namespace；该替身只存在临时验收代码。实际 ProcessPool 的 Path 可序列化性另以可 pickle 的模块顶层路径记录函数在两个 child 中验证，不能把同步替身宣称为真实并行转换成功。不在生产注入 stub/import hook/串行 fallback。
