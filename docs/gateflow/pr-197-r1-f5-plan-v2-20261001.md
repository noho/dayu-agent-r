## 3. 必需契约：同窗读取与年度输入

在现有 `storage/source_meta_read.py` 增加 frozen `SourceMetaIntegrityReadEntry`，必填字段：
`document_id: str`、`source_meta: Mapping[str, JsonValue]`、`integrity: SourceIntegrityClassification`。
它只组合同窗 raw 观察与现有物理分类，不增加 proof/evidence blob、revision 公共承诺或写授权。

新增真实 protocol/FS/core 方法（并在 storage 包正常公开导出类型）：
```python
def read_source_meta_integrity_view(
    self, ticker: str, source_kind: SourceKind, *, batch: BatchToken | None,
) -> tuple[SourceMetaIntegrityReadEntry, ...]: ...
```
- `batch=None`：一次短 publication guard，完整有序枚举→逐份严格 raw meta 读取→一次 whole-kind inspector→按相同 ID 组合。
- `batch` 非空：先校验同 core/ticker/open capability，全部读取/inspection 使用该 staging 根；不重新获取 published guard。
- core 抽取接受显式稳定 ticker 根的私有枚举/get 校验实现；原 F4 published 方法复用它，原行为不变。不得 staged 方法偷读 published 根。
- 完整枚举及每份 raw 读取失败原对象抛出；不返回前缀、不吞为无 anchor（Q2）。inspector 原有 typed/operational 异常原样传播。
- raw parse 校验先于 inspector，避免 inspector 把 JSON ValueError 分类为 unsafe 后掩盖 Q2；读取与 classification 必须在同一稳定根内完成。
- COMPLETE 才可作依据；REPAIR_REQUIRED/UNSAFE/MISSING 不参与年度证据。损坏来源不能降级成可信；后续原完整性预检仍执行。
- 每份 meta 来自独立 JSON 树，顶层 MappingProxy；嵌套值只读。不要全 kind deepcopy/deep freeze；只复制将实际更新的目标 meta。
- finally 释放 guard；读 API 不 begin batch、不写公司/文件/manifest。旧观察跨发布不变；合法深 JSON 保持 F4 行为。

在 selection 增加两个朴素共享函数：
```python
def hk_annual_end_date(*, title: str, category_text: str) -> date | None: ...
def local_hk_annual_ends(
    entries: tuple[SourceMetaIntegrityReadEntry, ...],
) -> dict[str, date]: ...
```
- 前者复用已有家族/年度词与截止日解析，接受 FY/全年 Q4 的原始年度报告/业绩，排除股息、非财报；可信英文原始年度公告也供日期证据，不按语言排除，不从 Q4 标签倒推。
- 后者严格校验 source 字段；只取 COMPLETE、`source_provider=hkexnews`、`ingest_method=download`、`is_deleted=False` 的同 ticker 原始标题/分类；company_id 须等于既有 `ticker_to_company_id` 真源给该 canonical ticker 的身份，不能仅因物理共目录接受跨公司输入。
- 返回 existing source ID→截止日仅供 rebuild 原审计引用；财政日历消费去重日期 tuple。不要引入治理实体、泛化 profile/callback。
- 当前缺 `source_category` 时，保留仅用原标题家族事实的既有能力；不能用旧 form/coverage 补分类。必要字段类型错误不能 str/bool 强转掩盖。
- discovery 与 rebuild 使用同一函数；raw 先 scope/去重→收集年度证据→沿现有语言规则过滤主候选，英文副本不生成主候选；local `source_language` 已持久化，证据函数无需语言参数/标题语言启发式。全部合并，不 local 优先、不多数投票。

## 6. rebuild 的事实与事务

- begin ticker writer batch 后，调用新 view 的 `batch=batch`，同 staging snapshot 同时得到原 meta/分类；共用 local 年度集合。取消点置于 batch 前、读取后、逐目标前、commit 前。
- 选择范围保留已有 old/new identity 加披露日期路由；old identity 只作选中既有缓存的过滤，不成为解析依据。未知命中旧路由/日期窗口时单列，不沿用旧标签。
- facts=None：生产 `FinsDownloadUncertainReport`，report_date 重新取标题直接事实；filings 不追加旧 failed 行（N02）。原 document/internal ID、source/blob/manifest/processed 内容及索引全部不写。
- facts 确定且 COMPLETE：`rebuild_hk_periods` 的 `updates` 中 report_date 仅由 `report_end_date(title)` 转为 ISO/None，report_date_source 调用 §5 `hk_report_date_source(report_date)`；同一 updates 原子写 source/已有 processed，当前行取 updates 日期，两 manifest 从对应 meta 同源投影日期（不新增 marker 字段）。无唯一截止日时日期/来源均显式 None，不读旧值补回；保留 ID、源文件、financials/内容版本。
- 正常发布仍由单 filing batch 暂存 source/manifest 与既有 processed 重处理标记、由 caller commit；`_should_mark_processed_reprocess_required` 仅按已有 processed/前版 source fingerprint 判定，不同步 processed 日期、不改其状态机。rebuild 仍以 `ProcessedUpdateRequest(meta=updates)` 在同 ticker batch 同步已有 processed；storage `merged_meta.update(req.meta)` 保留显式 None 并据合并后 meta 写 manifest，不为 A4 扩大通用 processed 改造。
- 既有 `hk_download_rebuild.py:_PERIOD_VERSION` 升 `hk-period-v3`，只记录新的财期解析语义，不升 document/content 版本，不加历史库迁移；未知 B 仍完全不写源/processed。
- facts 确定但 source 不完整：维持原完整性失败，使用本次确定财期输出，不用 unknown 掩盖 storage 问题。
- 无变更/纯未知 rollback 空 batch；有 A 的元数据更新+B 未知则正常 commit A。未知不让 A 回滚。
- commit 前取消或写失败按原 ticker batch 回滚；回滚行不得报 downloaded。commit 已成功后的取消不得把真实 A 发布计数清零。原源/processed 保全逐字核验。

## 7. operation/public/durable 一致与终态

`FinsDownloadResultSummary` 增必填 `uncertain_reports` tuple 与 `uncertain_count: int`；`from_document_rows` 增必填 tuple 参数。
`discovered = len(document_rows)+uncertain_count = downloaded+skipped+rejected+failed+uncertain`；failed 不含未知，written IDs 仅来自 downloaded。
非 HK source 必须 uncertain=0；来源引用在同 operation 唯一；existing ID 不可同时出现在已确认行与未知行。
normal terminal 由此 owner 派生：failed+uncertain=0→succeeded；否则沿原规则 downloaded/rejected 有值→partial_failure，其余→failed。
将原私有 counts 函数收敛为 `download_terminal_disposition_from_counts(*, downloaded_count: int, rejected_count: int, failed_count: int, uncertain_count: int) -> FinsDownloadTerminalDisposition`，summary/public 共用，不保留旧名字兼容入口。
取消由 runtime owner 显式覆盖为 cancelled，允许非零确认行/未知计数；不改文档分类与写入事实。

**root 已裁：uncertain>0 时整体 FAILURE/job FAILED/CLI exit 1/wait failed；摘要保全 A，A 已发布时 terminal_disposition=partial_failure。**
纯未知为 failed；空查询为 succeeded、discovered=0、unknown=[]，与未知严格区别。已确定 A 的 skip 行按原规则保留。
不引入新的总体 status；`FinsPublicFailure` 六字段不变，EXECUTION、source=HKEXNEWS、无 transport/reason_code，message 说明存在未确认财期，retry_hint 要求可信年度截止日资料。
固定中文说明归 `direct_event_text.py:direct_download_uncertain_period_message() -> str`；direct/job 复用，不调用“未写入任何文档”说明覆盖已发布 A。取消/原 typed 完整性失败优先于该普通未确认终态。

- `FinsDownloadPublicSummary` 增必填 typed `uncertain_reports`、`uncertain_count`、`omitted_uncertain_count`；公开 JSON 增 `uncertain_reports` 与 counts.uncertain。
- known documents 上限仍 10；未知独立最多同一常量 10，至少展示 1 条真实未知；两份列表都有独立 omission，`omitted_count` 仅省略 known rows。
- 不创建重复 public unknown 类型：直接复用安全 typed uncertain report。visible unknown+omitted_uncertain=uncertain_count。
- `_public_download_summary` 的 known omission 必须为 `len(summary.document_rows)-len(public_rows)`；公开校验 `len(document_rows)+omitted_count+uncertain_count=discovered_count`，不可用 discovered 减 known visible 误把未知算成已省略文档。
- `download_contract` 增 `public_uncertain_reports(*, max_json_chars: int) -> tuple[FinsDownloadUncertainReport, ...]`，`to_json_summary(*, max_json_chars: int) -> dict[str, JsonValue]`。
- 二者使用同一私有投影算法：原基础 durable fields/counts/missing+written IDs，先放首条 unknown，缩短 written ID 前缀至可容纳并更新原 omitted_written_document_count；固定该 written 前缀后按排序追加 unknown 至 10/JSON预算，更新 omitted_uncertain_count。
- 使用与 `_assert_bounded_summary` 一样的 `json.dumps(ensure_ascii=False, sort_keys=True)` 长度；runtime 两调用均显式传当前 4096 上界；不得扩大所有 job 上界或裁断真实来源 ID。
- HK 合法 filters≤6、ticker/ID 既有文本界限足以容纳一条；边界测试证明基础+首条可容纳。超预算不是静默空列表，设计验收失败须修 owner 投影。
- public/direct、durable job unknown 列表逐件相同；job 保存全计数/终态/omission/已发布 IDs。CLI/wait 原样消费 public typed 对象，不从字符串或 source 重建。
- durable 非空校验归 `download_contract:validate_download_json_summary(value: Mapping[str, JsonValue]) -> None`：严格完整新 schema/类型、来源、计数守恒、未知引用、两 omission、正常/取消终态。实际写 owner `_record_to_json` 校验，读 owner `_record_from_json` 构造后调用前者；缺字段拒绝，不补默认，不从 JSON 反推财期。
- fresh DOWNLOAD 必填 result_summary 始终为 JSON object：未形成 typed 结果时 QUEUED/RUNNING/CANCELLING 可为 `{}`；启动前取消、发现前 Q2/运输普通异常等尚无 typed 结果的 CANCELLED/FAILED 也合法 `{}`，失败原因仍走原 failure_summary。它表示无业务结果，不表示空查询成功，非旧库兼容；SUCCEEDED、正常完成（含真空查询/纯未知）、已有 typed 结果（含 F6 摘要）一律非空完整 schema，运行时不得将其降为空。
- public 校验复用 download contract 正常终态派生规则，替换当前 `direct_events` 重复的 counts 算法；取消只校验合法 owner 覆盖。

## 8. 取消、错误与迁移点

- `_produce_direct_download`/`_run_download_job` 必须消费 summary 的 cancelled 与 uncertain，不能只检查 cancel flag/failed_count。
- direct `_emit_direct_cancelled_result` 增必填 `download_summary: FinsDownloadResultSummary | None`；启动前传 None，执行后传真实 summary。
- `_direct_result_event` 不再无条件把已有 download 清空：有摘要仅覆盖 terminal_disposition，保留 counts/rows；无摘要才生产零行取消。原 claim 权与 exit 130 保持。
- job `save_cancelled_if_active` 增必填 `result_summary: dict[str, JsonValue] | None`；`save_succeeded_or_cancelled`/`save_failed_or_cancelled_if_active` 增必填 `cancelled_result_summary: dict[str, JsonValue] | None`，前者正常 result_summary 仍必填非空 dict，后者改必填 `dict[str, JsonValue] | None`（无默认）。
- runtime 仅在尚无 typed 结果时显式 None；已有 typed 结果即使零行也由 owner 产生完整正常/failed 与 cancelled 两投影。store 锁内选分支并保存调用方对应投影；DOWNLOAD 的 None 只在当前摘要也空时存 `{}`，当前/本次已有非空结果却缺取消投影则拒绝，不能清空 A 或从 JSON 重算取消摘要。既有终态仍原样返回。
- `_save_succeeded` 增必填取消投影；`_save_failed` 的正常及取消投影均必填可 None，删默认/真假值替代；`_save_cancelled` 增必填结果投影。`_save_failed_from_exception` 同收两必填可 None 投影，download 保留已返回 typed summary，后续收口异常也传真实投影；尚未返回且无 typed cause 的普通异常不新增全局快照。迁移 protocol/FS、三 start/claim 启动前取消、download 正常/typed/unsupported/普通异常、preprocess/upload（含直接 atomic 调用）、测试 store/竞态 wrapper/helper callers；非 download 新参数显式 None，原业务摘要不变。
- Q2/运输错误发生在发现/发布前→原异常；candidate 普通失败继续原单文档结果；F6 typed 中止保全已确认 A+独立 unknown tuple，原 cause 对象及公共原因不变。
- 不扩大 `CnDownloadIntegrityAbort` cause 集合，不捕捉普通异常冒充完整性错误；所有新增 unknown/schema 校验必须在 A 写前完成，避免事后投影错误丢 A。
- 当前 wait 是 observed direct，不读取 durable job；其 failed/cancelled 输出需保留 download JSON，更新 scope_note 为“文档计数统计已确认处理，未知报告单列；整体状态不撤销已发布文档”。
- `_cancelled_outcome` 从 `_required_result(snapshot)` 取取消结果；download 非空时将 operation/status/title/download/scope_note 编成 `ToolCancelledOutcome.message` JSON，reason/hint 保持原取消契约；无 download 的其他 operation 保持原固定说明，不新增 ToolCancelledOutcome 字段。
- shared summary 签名迁移真实点：CN adapter、SEC `_build_sec_typed_summary`、runtime `_execute_download_request` 和 `_empty_download_summary_from_request`、全部 summary 构造测试；CN/SEC 真正无 unknown，显式空 tuple。
- discovery 测试迁移：`test_cn_pipeline.py` 两 client、`test_cn_download_workflow.py`/`test_cn_download_runtime.py` client；`test_cn_report_selection.py` 六个直接 HK selector 测试（原466/511/559/607/666/721）及原106/127两调用均迁移参数/result，sameID 测试保留原 ValueError 断言；真实 CN 候选不以 fake 空结果代替。
