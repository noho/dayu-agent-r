# PR197-R1/F3：分析脚本显式样本输入目标

## Goal confirmation 与授权

用户已接受首轮 PR review 成立项优先修复，并授权当前总控继续；本目标复用 `docs/gateflow/pr-197-full-review-adjudication-20260929.md` 的 F3 和交接 prompt 的明确修复边界，无需重复请求原有授权。

目标：四个分析脚本的样本根、样本选择清单由操作者显式传入，当前代码不再固定操作者私人语料目录与样例身份，便于在任意临时样本根复现。成功信号是 CLI 输入有自足说明、正常输入能驱动同一分析路径、缺少必需输入明确拒绝，当前四文件无私人 locator；受影响代码与全量 pyright 通过。

## 直接证据与 owner

- `utils/docling_schema_regression.py`、`utils/build_semantic_digests.py`、`utils/verify_missing_tokens.py` 的 `SAMPLE_LIBRARY_ROOT` 固定私人路径，工作函数从该全局值读 PDF/基线。
- `utils/ab_ocr_compare.py` 的 `SAMPLES` 固定六份私人 PDF locator 与身份，`main` 没有输入清单参数。
- 缺陷根因是开发分析脚本的样本输入 owner。修复在 argparse/样本定位与 worker 参数传递处；生产 Docling/Fins 行为不改。

## 范围与非目标

- 允许实施文件是上述四个脚本，以及必要且有充分理由的 `utils/` 输入辅助模块；plan 必须证明是否需要共享 helper，不为四种入口造配置框架。
- 保持现有 schema/digest/token/A-B 比较算法、产物业务字段与转换调用语义，允许为显式输入补最小中文 docstring/CLI 用法。
- 不扫描或重转换私人语料，不改变生产路径或用户工作区，不升级依赖，不强推，不清除历史公开提交，不篡改历史证据。
- `utils/` 按项目约束无需新增自动测试或覆盖率；以临时样本与已存在产物验证输入、路径和实际消费，不加镜像测试。命中修改边界的类型问题需在 owner 范围解决，不能传播弱类型或 suppress。
- 已公开历史内容不能由普通修复提交移除；历史级处置仍要求用户另行决定，是本项已分类 residual。
