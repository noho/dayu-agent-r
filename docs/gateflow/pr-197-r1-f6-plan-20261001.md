## 5. 唯一语义 owner 与最小 typed/public/durable contract

### 5.1 产生事实

- storage 分类/异常拥有完整性事实和 publication identity；不依赖 Host、Service、UI 或工作流名称。
- CN/HK workflow 拥有 post-repair 必须 clean 才能进入 company publication 的状态转换，以及操作中止的已处理快照。
- **拟新增** `SourceIntegrityRepairRequiredError(RuntimeError)`，定义于 `dayu/fins/storage/source_integrity.py`。签名 `__init__(self) -> None`，仅表示检查已确认存在待修复来源，不含 phase、路径、ID、revision、原异常文案或新 payload 字段。固定内部异常文字“来源仍需修复，当前操作不能继续”。完整中文 docstring（参数无、返回无、异常无）。由 storage 公共包正常 export，不是兼容 re-export。
- 由 `SelectedSourceRepairRequired` 的已验证分支构造该异常；不从字符串或历史调用顺序推断。新类不承担扫描/重试/修复职责，也不新增 storage API。
- 保留 `SourceIntegrityRevisionConflictError` 的含义/签名/真正抛点；不为二者引入父异常大体系或无当前需要的 adapter profile。
- abort 与 adapter cause 参数明确为三类型 union：`SourceIntegrityPreflightError | SourceIntegrityRevisionConflictError | SourceIntegrityRepairRequiredError`。两处保持同一封闭集合；没有无限开放 Exception cause，也不引入泄漏 download 概念到 storage 的类型别名。

### 5.2 公共失败，唯一 owner 是 ingestion_runtime

`FinsDownloadFailureReason` 保留四个旧值，拟增加两个值；JSON 字段 shape 不变。`FinsPublicFailure` 的 enum/docstring 从“预检”扩大为“下载来源完整性失败”，保留 STORAGE-only reason 与安全文本校验。

| typed cause | classification / reason_code | 唯一 safe_message | 唯一 retry_hint |
| --- | --- | --- | --- |
| SourceIntegrityRevisionConflictError | storage / `source_revision_conflict` | 本地来源版本持续变化，本次下载已停止 | 请等待其它来源写入完成后重新发起下载；若仍失败，请检查并发写入。 |
| SourceIntegrityRepairRequiredError | storage / `source_repair_required` | 本地来源仍需修复，本次下载已停止 | 请检查并修复工作区来源状态后重新发起下载；不要仅按并发冲突反复重试。 |
| 四种 SourceIntegrityPreflightError | 原四个 storage reason，原样对应 | 保留“本地来源完整性预检失败” | 保留现有检查修复及非盲目重试建议 |
| 普通未知 Exception | execution / null | 保留“下载执行失败” | 保留现有脱敏排查建议 |
| provider/configuration/OSError | 原契约 | 原契约 | 原契约 |

两条新增 enum 名为 `SOURCE_REVISION_CONFLICT`、`SOURCE_REPAIR_REQUIRED`。原因和文案只在 `_download_public_failure_from_exception(exc: Exception, *, request: FinsDownloadRequest) -> FinsPublicFailure` 产生；先解原 cause，增加明确 isinstance 分支（在 OSError/泛 execution 前），不按 source、错误文本、cause stack 或 mock 入口猜。

下载 direct 先生成 public_failure，再由其 kind 派生 FinsErrorKind：STORAGE→STORAGE、EXECUTION→EXECUTION、CONFIGURATION/PROVIDER_TRANSPORT→PROVIDER。以当前 runtime 模块级封闭 enum mapping 实现，不重复 exception→reason/message 规则。非下载继续使用 `_classify_direct_error`，取消/unsupported 现有路径不动。`_classify_direct_error` 的唯一调用位于 `_run_direct_producer`；移除其旧下载特判，避免两份真源。该 helper 原签名可保留 `operation_kind` 仅在真实非下载分类需要时使用，否则删该已无语义参数及唯一调用参数，不增 wrapper。

明确签名决策：非下载 helper 改为 `_classify_direct_error(exc: Exception) -> FinsErrorKind`，主体保留现有非下载分支；下载专用 enum projection 为模块级常量 `_DOWNLOAD_PUBLIC_ERROR_KINDS: Final[Mapping[FinsPublicFailureKind, FinsErrorKind]]`，穷尽四个 kind。不新建函数或 class。

### 5.3 消费者与 durable 边界

`FinsPublicFailure.to_json_value(self) -> dict[str, JsonValue]` 仍返回既有六个字段 classification/source/transport_category/message/retry_hint/reason_code；无新 field。

- Direct RESULT 保留 typed failure 和 error_message=`failure.safe_message`，observation 从同一 RESULT 存快照；不额外建 public mapping。
- CLI `_print_download_failure(failure: FinsPublicFailure, stream: TextIO) -> None` 一次 `public = failure.to_json_value()`；从这些字段机械输出既有 detail 字段。字段值用 JSON 编码展示，nullable transport/reason 仅按现有空单元格格式显示。不要用 str/getattr/default/loose parsing 重建原因。JSON 编码由 public owner 已验证的字段直接产生，不需要 UI 重新判断语义。log location hint 仅按 public classification==execution，原未知错误提示保持。
- wait `_failure_message(result: FinsResultSummary) -> str` 已使用 failure.to_json_value；只增测试，无生产修改。scope_note 继续说明文档摘要仅统计已处理文档；不能据 succeeded 文档摘要把操作级失败改成功。
- 后台 `_save_typed_download_failure` 解同 cause，调用同 public owner，保存 `failure.safe_message` 和 `summary.to_json_summary()`。durable failure_summary **仍严格只有 message**；不解析 message 反推出 reason，不把 hint/reason 挪进 result_summary、request_summary 或 extra。
- 真正 RevisionConflict（包括不经过 CN wrapper 的原异常）必须进入 typed job catch，不能落 `_save_failed_from_exception(str(exc))`。catch 与 `_save_typed_download_failure(..., exc: FinsSourceDownloadAdapterFailure | SourceIntegrityPreflightError | SourceIntegrityRevisionConflictError | SourceIntegrityRepairRequiredError) -> None` 同步封闭；裸异常使用既有 request-level 零摘要，wrapper 使用原 persisted_summary。
- `_save_failed`、job record、store schema、eventlog shape 不改；typed/unknown 日志继续 #198 现有路径，不复制原异常字段，不扩大脱敏日志工程。

当前 goal 并不需要新增 job schema：wait 根本不是 job reader；safe_message 足以安全区分两个业务事实，已处理摘要由 wrapper 守恒。**这不等于后台已持久化 reason/hint**。如果 root 把 binding “同事实投影一致”裁决为必须重启后读出完整六字段，则当前接口确实无法满足，最小 choice 是先批准独立 `fins-download-job-reason-code-persistence` goal，由 job contract/store owner 定义失败摘要契约与新库方案，再修订依赖；本作者不自选字段，也不宣告豁免。见 §9 R-1；原独立schema边界不重开确认。

### 6.3 精确调用链、顺序和状态转换

1. 仍按现有初始 selection → 同 guard inventory preflight → repair target 前移。初始 four-preflight 失败仍在首 candidate 前裸 typed 抛出，runtime 产生请求级 FAILED 零摘要。
2. single-filing 不改 Phase A/B 真源、3 rounds、rollback/skip/重取流程。只有真正 identity 不匹配重试耗尽才到 RevisionConflict；新的 typed cause 不放进 retry 循环。
3. workflow single-filing catch 顺序固定：`CnDownloadCancelledError` → `(SourceIntegrityPreflightError, SourceIntegrityRevisionConflictError)` → ordinary Exception。取消原 break 语义保持。此处 RepairRequiredError 目前没有 single-filing production throw，不为它造可达路径。
4. typed catch 中用 `_build_candidate_failed_result(document_id=..., candidate=..., reason_code=..., reason_message=...) -> JsonObject` 建当前 candidate 一条 failed row，append、发 FILING_FAILED，立即 `_integrity_abort(...)`；ordinary catch 仍按原封闭投影继续。为免把 churn 行冒称 preflight，typed catch 用统一文档级固定标记 `source_integrity_failed` 和“本地来源完整性状态阻止文档处理”，两者为 workflow 模块常量。它仅表达当前文档处理失败，不承担 operation reason/hint 的业务分类；operation 分类唯一来自 cause/public owner。迁移原 preflight row 的 category 断言，禁止保留兼容别名。
5. `CnDownloadIntegrityAbort.__init__(self, cause: 三类型union, result: JsonObject) -> None` 与 `_integrity_abort(*, cause: 三类型union, started_at: float, pipeline_name: str, ticker: str, company_info: JsonObject, filters: JsonObject, warnings: list[str], notes: list[str], filings: list[JsonObject], missing_periods: tuple[str, ...]) -> CnDownloadIntegrityAbort` 保留已有参数与原始 cause 对象。filings 是唯一行真源，`_build_summary` 只数这些终态行，`_build_result` 用既有 integrity_failed 状态。不要 count discovery 未处理 tail，不加合成 failed tail。
6. 若当前是 repair filing：失败行已有时立即 abort，不走普通 failed→break 的收尾；若成功/skip 后再查完整 inventory，`NoSourceRepairRequired` 才允许下一步；四种 PreflightError 原样 typed abort；`SelectedSourceRepairRequired` 在此分支改抛 `SourceIntegrityRepairRequiredError()`，caught union 转同一 abort。
7. post-repair abort 不把已成功 repair row 改 failed，不为尚未开始的损坏 source 造 row；company publication gate 未经过，company 保持旧值。mid-filing 前若 company 已独立发布成功，也不回滚或冒称不存在。company 是独立事实，source manifest 的成功由 storage 已提交事实决定。
8. clean 后保留原 cancellation checkpoint → 独立 company atomic batch → repair_gate_completed；pre-swap Preflight abort 原样。不挪取消优先序，不制造新 terminal 状态，不触 F7。
9. adapter `_summary_from_integrity_abort` 保留严格 status 验证及同一逐文档投影；`FinsSourceDownloadAdapterFailure.__init__(self, cause: 三类型union, persisted_summary: _FinsDownloadResultSummary) -> None` 扩准确校验，无 fallback。runtime 必须得到同一 cause 对象和同一摘要事实。
10. 操作 RESULT / job 都 failed；文档 summary 的 terminal_disposition 仍从 rows 推导。仅一个成功 repair row 而操作 post-check failed 时，文档 summary 可为 succeeded（现有 contract），不强改成 failed；mid-filing 一个成功+一个失败 row 则 partial_failure（`FinsDownloadTerminalDisposition.PARTIAL_FAILURE`，`download_contract.py:107,551`）。逐文档 status、计数和 manifest 守恒，不让整体 fail 抹掉 source 成功事实。

不在 public failure 的 hint 中承诺写入已回滚/未提交，因为 publication indeterminate 独立残余未被本 WU 接管。新的失败文案只说操作停止。
