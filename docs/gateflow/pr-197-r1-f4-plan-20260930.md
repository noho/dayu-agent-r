## 4. 最小公共 storage 契约（一个读取方法，无 staged API）

在 `dayu/fins/storage/source_integrity.py` 定义观察类型与纯 target 分类函数；在 `repository_protocols.py` 导入该类型并加入一个方法，Fs repository/core 实现；`storage/__init__.py` 正常导出新公共符号。这是新公共能力的 owner 导出，不是旧路径兼容 re-export。

```python
@dataclass(frozen=True, slots=True)
class SourceInventoryEntry:
    integrity: SourceIntegrityClassification
    source_meta: Mapping[str, JsonValue]

def read_source_inventory(
    self,
    ticker: str,
    source_kind: SourceKind | None,
) -> tuple[SourceInventoryEntry, ...]: ...

def classify_source_inventory_target(
    *,
    ticker: str,
    document_id: str,
    source_kind: SourceKind,
    inventory: tuple[SourceInventoryEntry, ...],
) -> SourceIntegrityClassification: ...
```

`source_kind` 是**必需显式参数**，不是 optional fallback：`None` 表示完整 ticker 双 kind，与既有 preflight 相同；`FILING`/`MATERIAL` 表示完整单 kind，与既有 Phase A 单 kind 相同。该枚举范围参数只限定既有扫描范围，不是 query/profile/callback 框架。禁止默认省略、staged 参数、publication token/生命周期参数。

读取契约：

1. 校验 ticker/source_kind 后 acquire 一个 guard；scope 内每 kind 仅一次 `_inspect_source_kind_unguarded(requested_document_id=None)`；在 finally release。同一私有 core helper `_inspect_source_inventory_unguarded(*, ticker: str, ticker_dir: Path, source_kind: SourceKind | None) -> tuple[_SourcePublicationInspection, ...]` 枚举并汇总原 inspector 结果。`list_source_integrity` 用该 helper 的 None scope 投影 classification，保持原 UNSAFE 返回语义。
2. `read_source_inventory` **先检查整个 scope 的所有 classification**；任一 UNSAFE 抛现有 `SourceIntegrityPreflightError(UNSAFE_PUBLICATION)`，不得部分返回。whole inspector 的 root/empty-untrusted-manifest typed 异常直接透传。只有没有 UNSAFE 后才投影 entry / 构造身份索引。共享 manifest 导致 UNSAFE 时，虽私有 business_meta 尚存在也不得公开。
3. 返回 entry 状态只允许 COMPLETE/REPAIR_REQUIRED；可信 business_meta 非空引用是 inspector 保证的 invariant。意外缺失属于 owner 内部 contract failure，抛 RuntimeError，不空字典/跳过。每份 meta 用 `MappingProxyType(deepcopy(dict(business_meta)))` 脱离 inspection；entry 为浅 frozen，只读顶层，嵌套 JsonValue 不承诺深不可变，消费者不得修改，需要现有 JsonObject 时 copy。无 raw identity observation、私有 revision、路径或未来字段。
4. 稳定顺序 filing 然后 material、各 kind 按 document ID；scope 内不漏实体或 manifest 悬空事实。任何不可信库存拒绝，不当 MISSING/new ID。COMPLETE/REPAIR_REQUIRED meta 字段投影与原 get_source_meta 保持同源。
5. `classify_source_inventory_target` 只接受本次对应 scope 的完整、已可信库存；规范化/校验 exact identities、拒绝 inventory 中跨 ticker 项；命中返回**原 integrity 对象**，未命中在该 owner 构造 revision=None/status=MISSING/reasons=()。这不是 pipeline fallback：whole mode 已将所有无法证明可信缺失的 root/manifest 情况封闭拒绝。禁止额外读或先查 classify。其 MISSING 构造使用 storage 现有 missing classification 真源（从 `_missing_source_inspection` 提取 classification 构造为 `source_integrity.py` 模块级私有 helper，旧 `_missing_source_inspection` 也复用）；只等价移动构造，不改变 inspector 判定。
6. operational OSError、锁错误原样传播；非法调用参数 ValueError；没有新 reason/hint 词表。HK 实际 META/PROVENANCE/IDENTITY_UNTRUSTED 与缺 internal ID 损坏，在身份分配前统一 typed 拒绝，这是总控明确接受的普通 ValueError/FileNotFoundError → UNSAFE_PUBLICATION 投影迁移。

为何需要 kind 参数：仅用双 kind read 替换今日 Phase A filing 检查，会新增 material 扫描；本契约保留原扫描范围。direct filing prepare 不依赖 ticker preflight，封闭拒绝本次完整 FILING 库存中任何 UNSAFE（含坏 sibling），material 在 ticker 双 kind 预检与原 commit 双 kind 闸门拒绝；不新增一次 material 读来替代原 commit 规则。

## 5. 身份 owner：精确类型与算法

在 `cn_download_identity.py`，移除 resolver 的仓储依赖参数；不保留旧 signature wrapper。

```python
@dataclass(frozen=True, slots=True)
class CnDownloadIdentityIndex:
    filing_entries: Mapping[str, SourceInventoryEntry]
    source_documents: Mapping[tuple[str, str], tuple[str, ...]]

def build_cn_download_identity_index(
    inventory: tuple[SourceInventoryEntry, ...],
) -> CnDownloadIdentityIndex: ...

def resolve_cn_download_ids(
    ticker: str,
    candidate: CnReportCandidate,
    identity_index: CnDownloadIdentityIndex,
) -> tuple[str, str]: ...
```

建表只处理 `SourceKind.FILING`，material 同名字段不能匹配；一个 document_id 一份原 entry，重复键为 owner contract 错误而非覆盖。仅当 meta 的 source_provider/source_id **均为 str** 时加入 source_documents，值保留稳定全部 ID tuple，禁止 duplicate 合并成一个值。缺失/非字符串 source_id 不与 candidate 的字符串 source_id 相等，与今日语义一致；不 trim/coerce/猜字段。不在建表时拒绝与所选 source 不相关的业务 duplicate。

查询先按原 `build_cn_filing_ids` 生成 allocated；非 hkexnews 直接返回该值，不访问索引。HK 查询精确 `(candidate.provider, candidate.source_id)` 的全部条目，对每个匹配保留原 internal str/非空检查与原 ValueError；多于一份用原 duplicate ValueError；有匹配返回原 document/internal ID。无匹配时只从 filing_entries 的 allocated entry 检查原 fiscal_period/fiscal_year；纠正则保留原 SHA1 字节公式及两个前缀，否则 allocated。身份规则不能转移到 storage；可信现实缺 internal ID 会先被完整性 owner 拒绝，纯身份负例仍验证其防御 contract，不能拿 fake 把坏 meta 伪造为可信 Fs 库存。

索引是单观察窗口内的浅只读内存值；不跨 Phase A 复用，不持久化，不添加 revision equality/generation。CN 可共享已有检查产生的建表结果，但身份查询仍短路；不为 CN 身份独立读库存。

## 7. repair、retry、取消与提交不变量

- 批初 `(candidate, initial_document_id)` 只服务 accepted/preflight、排序及 repair **调度簿记**。`repair_document_id` 来自该同窗 disposition。循环中的 repair gate 比较固定为 `initial_document_id == repair_document_id`；不能拿当前 Phase A 写 ID 或终态事件反推该簿记匹配。
- 唯一 repair candidate 的 stream 普通终态 failed 时，原 gate break，company 保持旧值。完成/skip 后读一次新的 read(ticker,None)，重新用所选 candidate 构造当前 accepted IDs，preflight 与该新窗口配对；仍存在 SelectedSourceRepairRequired 则抛原 revision conflict。这个当前检查不能混批初 accepted 与新 inventory。通过才原取消检查、原 company publication、repair_gate_completed=True；失败保留已确认 repair、旧 company、已处理列表/cause。无 eager 剩余候选刷新写授权。
- Phase A/B 最多三轮：round=0/1/2；Phase B retry rollback 后，下一轮**一定**新 prepare、重新下载/转换；next_round>=3 抛既有 conflict。COMPLETE skip、period mismatch、overwrite、旧文件复用按 phase_a 事实执行，不用批初 meta。
- 开始一次由 ticker 发；内部 retry 零额外 start；每候选正常完成/普通失败一次终态；取消不构造 failed filing。取消检查保留 payload acquisition/转换/commit 原阶段，原取消异常对象传播；prepare 新检查禁止已取消时读库存，stream 原检查防止 start 后取消仍进 payload。生成器关闭语义保留。
- Phase B 仍调用 `classify_staged_source_integrity(...,batch=token)`；target UNSAFE typed 拒绝、原 same-target revision 比较、rollback/retry、COMPLETE 非 overwrite skip、reset/blob/source/processed 原顺序、commit-start 后 token 消费规则全部保留。没有 staged inventory/uniqueness 断言；commit 双 kind COMPLETE 全树闸门不改。
- 旧批初索引、Phase A 值均不作为 current write capability。resolve→commit 期间另一 writer 在其它 target 绑定同 source 而旧 target 未变，原 target-only 局限仍存在（F4-R01）；不声称本 slice 关闭。
