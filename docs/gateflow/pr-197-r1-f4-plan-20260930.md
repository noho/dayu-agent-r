## 2. 第一性原理、目标与最小边界

问题真实存在：`cn_download_identity.resolve_cn_download_ids:32-44` 每个 HK candidate 全枚举 filing，逐份公开 `get_source_meta`；accepted IDs、repair sort、filing-start、stream 又消费它。list 与每份 get 都各自 acquire/release publication guard。显式日期窗口 selected 无固定数量上限。这既重复读盘/持锁，也让同一次身份解析的多份 meta 可能来自不同 publication。

修复应合并**读取 owner 的观察窗口**，而非改变来源身份、完整性状态或错误判断。本候选选择复用 list/get 的现有 unguarded owner，提供一次有序批量 meta 观察，身份 owner 建一次索引后纯查询；不以 raw meta 可读取冒充 COMPLETE/可信 publication。

| 已确认目标 | 最小设计/验收 |
| --- | --- |
| 消除逐条公开身份读取与独立 guard 循环 | 每个身份观察一个 guard；批初 accepted/repair 共享同一索引；身份解析不调用 public list/get |
| 同窗事实一致、禁止 stale cache | 同一个 batch view 只包含一个 guard 内的事实；filing-start、stream/retry 各取当前观察；批初索引绝不传作写绑定 |
| 保全扫描/匹配/缺 internal ID/duplicate/纠正 allocated | 同源 list/get；成功前缀+首个原读取异常保留旧拒绝先后；纯索引只优化查询，不自行校验完整性 |
| 保全 Phase A/B、错误、取消及已处理 rows | 既有 classification/previous_meta/commit 不替换；start 前与 start 后的原 catch 位置不迁移 |
| 不扩 scope | 单 slice、无 durable schema/generation/cache/长锁/staged API/uniqueness；F5 不倒逼本 API |

**不再采用旧 Phase A 浅结果共享。** 原 start 在 ticker 的 filing try 外、stream 在 yield 之后且有自己的取消检查和 try；合并准备步骤会把流内普通失败/继续迁成 start 前传播。强制 trusted-only inventory 还会把 ValueError/FileNotFoundError 迁成 UNSAFE_PUBLICATION。当前裁决不授权这些变化。保留两个短身份观察窗口是一致性协议的明确部分：start 只是当时的进度标签，stream 使用自己的当前身份；无并发变更时两者绑定相同，有变更时按既有流程分别观察，终态以 stream 实际 ID 为准。不能为“同绑定”造更强事件原子性承诺。

不承诺整 run O(D+S)、不承诺复用 Phase A 物理扫描实现零边际 I/O。本方案保留每实际观察 O(D) metadata 读取/索引成本，但每窗从 D+1 次独立 guards 收敛为一次；批初 S 次及 repair sort 的重复扫描收敛为一次。Phase A/B/commit 的原全树扫描、previous_meta 的单 target 读取保持。该取舍直接服务原裁决，不引入未来机制。

## 4. 精确 storage API、必要类型与读取顺序

新增 `dayu/fins/storage/source_meta_read.py`，仅两个 frozen/slots dataclass（完整中文模块/类概览及属性文档）；不放完整性分类、receipt、文件/manifest/path 字段。

```python
@dataclass(frozen=True, slots=True)
class SourceMetaReadEntry:
    document_id: str
    source_meta: Mapping[str, JsonValue]

@dataclass(frozen=True, slots=True)
class SourceMetaReadView:
    ticker: str
    source_kind: SourceKind
    entries: tuple[SourceMetaReadEntry, ...]
    read_error: ValueError | OSError | None

# SourceDocumentRepositoryProtocol / FsSourceDocumentRepository / core
# source_kind 必填；不支持 None 双 kind 联读，不增加未来范围参数。
def read_source_meta_view(
    self, ticker: str, source_kind: SourceKind,
) -> SourceMetaReadView: ...
```

`entries` 是旧 get 顺序的**成功前缀**；`read_error=None` 才表示完整读取了 list 的全部 ID，否则表示第一个 get 失败、之后未读。它不是不完整 publication 的“可信 inventory”或成功标志。保留原异常对象/类型/message/cause，不新建 reason code 或包一层新 exception。身份查询消费失败 view 时必须按下节顺序抛错，绝不能把前缀当完整集合分配/写入。

core 的精确算法：

1. 使用现有 `_require_external_identity(ticker)`、`_normalize_source_kind`，acquire 一个既有 publication guard。
2. 在 guard 内调用现有 `_list_document_ids_unguarded(ticker, kind)` **完整枚举并排序**。list 异常原样传播，不转成 per-item 错误（旧 list 本来先于全部 meta 和身份匹配）。
3. 依序调用同一个 `_get_source_meta_unguarded(ticker, id, kind)`。只捕获其已知 contract `ValueError | OSError`，保存原异常后 break；不继续读取后项、不吞错、不用默认 meta。guard acquire/release 及其它未声明异常原样传播。
4. 成功 meta 用 `MappingProxyType(meta)` 包装本次独立 JSON 解析产生的业务字典；getter 的 fresh parse 与去私有 revision 投影没有其他公开持有者，嵌套数据独立于其他公开读取和后续发布，无需递归副本。tuple 与顶层只读，嵌套 JsonValue 不承诺深冻结，所有消费者只读。无私有 revision。所有观察值在 guard 内生成，finally 原 `_release_lock_token`；下载/OCR/用户事件/索引构建均不持 guard。
5. 返回带 ticker/kind 的 view。storage 协议 docstring 明确参数/返回/异常与成功前缀语义。现有 public get/list 不委托 batch、不改变签名或拒绝行为。Fs adapter 使用现有 shared core；不加第二层校验/fallback。

为避免扩散既有 `DocumentMeta=dict[str, Any]`：仅将 core `_get_source_meta_unguarded` 返回标注收窄为其现有 `_source_meta_without_revision` 实际返回的 `dict[str, JsonValue]`，其参数和方法体原语义不变。新 API/类型不引用 DocumentMeta/Any/object，不复制 JSON parser 或新增值清洗。既有 persisted/get 公共签名不作全仓迁移。

**成功前缀为何必需：** 有序 A 的 meta 可读且匹配 X、缺 internal ID，后项 Z malformed：旧 X 在 A 就抛缺身份 ValueError；旧 Y 不匹配 A，则在 Z 抛读取 ValueError。简单 eager batch 抛 Z 会篡改 X 原原因；“只返回成功项”会错误放行 Y。view 保存前缀和原异常，让身份 owner 纯查询复刻这两个结果，是最少的读取结果字段，不是新业务状态机。

## 5. 精确 identity API、索引及错误优先级

全部在 `cn_download_identity.py`；来源 literal 抽成模块级私有 Final 常量，原两条错误 message 同样 owner 常量化，不改文本。类型固定：

```python
@dataclass(frozen=True, slots=True)
class CnDownloadIdentityIndex:
    ticker: str
    source_matches: Mapping[tuple[str, str], tuple[tuple[str, str | None], ...]]
    allocated_periods: Mapping[str, tuple[JsonValue, JsonValue]]
    read_error: ValueError | OSError | None

def build_cn_download_identity_index(view: SourceMetaReadView) -> CnDownloadIdentityIndex: ...

def read_cn_download_identity_index(
    ticker: str, candidates: tuple[CnReportCandidate, ...],
    repository: SourceDocumentRepositoryProtocol,
) -> CnDownloadIdentityIndex: ...

def resolve_cn_download_ids(
    ticker: str, candidate: CnReportCandidate, index: CnDownloadIdentityIndex,
) -> tuple[str, str]: ...
```

`candidates` 是本次即将消费的候选集合：ticker batch 传 selected，start/stream 传 `(candidate,)`。读取 helper 在 identity owner 内以私有 provider 常量判断是否有 HK 查询；无 HK 或空集合返回 ticker 对应空的只读索引，零仓储读取，保持非 HK 原短路。有 HK 只调用一次 `read_source_meta_view(ticker,FILING)` → build。调用方不能自行过滤掉即将消费的 HK candidate；不将空索引作失败 fallback。每次调用返回新 index，不跨 publication 保存或更新；无缓存、factory/callback/query 框架。

build 校验 `view.source_kind is FILING`，依序一次遍历成功前缀，按 document_id 保存 `(fiscal_period, fiscal_year)`，按字符串 provider/source_id 建 tuple match 集合。非字符串来源字段不可能与字符串 candidate 相等，故不建 key；空字符串仍保留，不额外拒绝。内部 ID 保留合法非空字符串，其它值用 None 表示旧查询时应拒绝的事实；**不在 build 提前抛缺 internal ID 或 duplicate**，它们是依赖 candidate 的身份规则。使用 tuple/MappingProxyType，不 last-wins、不去重；read_error 原对象随 index 保留。build 不替代 integrity owner。

resolve 的精确顺序：

1. 仍先调用原 `build_cn_filing_ids` 得 allocated；非 HK 原样 return，不查询索引/仓储。
2. HK 校验 index.ticker 等于 ticker（开发契约误用 ValueError，合法生产路径无新业务拒绝）。读取该 provider/source_id 的 match tuple。只要任一匹配的 internal 为 None，就抛原“既有下载来源缺少内部文档身份”。它们均在成功前缀中，故先于首读取错误；有效的多匹配此时还不能抛 duplicate。
3. 若 `index.read_error is not None`，抛**同一异常对象**，不判断或分配身份。即使 candidate 已有唯一匹配或有效重复，旧扫描也要读后项，读取错必须先于扫完的 duplicate/return。
4. 原 `len(matches)>1` 拒绝；一个合法 match 返回原 document/internal ID。
5. 无匹配：若 `allocated[0]` 不在成功前缀的 `index.allocated_periods` 映射中，按未变更处理，返回原 allocated；仅键真实存在时，将 meta 的 fiscal_period/fiscal_year 按原 JSON 值分别与 `candidate.period_projection.identity_period` / `candidate.fiscal_year` 直接比较（不 loose parse/stringify/fiscal 重算）。任一不同，原 SHA1(`ticker|provider|source_id`) 分配 `fil_cn_…/cn_…`；否则返回原 allocated。真实存在的 meta 缺字段仍按原 None 参与直接比较，区别于映射键不存在；不得用默认 `(None, None)` 猜缺席或绕过步骤 3 的原 read_error，读取错误仍先抛。

query 只看该来源 match（合法集合一般常数大小）和 allocated key；缺身份/重复历史集合 query 可 O(match_count)。build O(D)，不宣称所有损坏集合也严格 O(1)。索引不包含 integrity trust/修复授权；raw readable UNSAFE 的来源依然参与原匹配，后续既有完整性闸门负责拒绝。

## 7. 损坏、失败公开投影与继续/取消矩阵

**业务事件顺序不重排。** 内部 view 保存异常是为按原 resolver 位置重新抛，不把内部错误带到 durable result/LLM。公开 projection 矩阵取自 `project_cn_filing_failure`、ticker catches、`ingestion_runtime._download_public_failure_from_exception/_direct_error_kind_from_exception`，本 slice 不修改它们。

| 输入/位置 | 原行为 → 本方案同一行为 |
| --- | --- |
| namespace/root/descriptor 无法 list（包括非隐藏 symlink） | 原 list 的 ValueError/OSError 先于全部身份匹配；batch load 同样直接抛。start 前不造 start/终态 |
| meta 缺失/JSON malformed/identity 不符 | 保存首个原 FileNotFoundError/ValueError；纯查询按前缀规则抛原对象。不会因换 API 变成 UNSAFE_PUBLICATION |
| 匹配但缺/空/非字符串 internal ID | 原 ValueError，早于后项读取错；有效 duplicate 只在无读错后 ValueError。batch accepted/start 阶段原样传播；stream 内普通 failure 并按原 ticker规则继续 |
| 可读 meta，但 provenance/revision/manifest/文件不可信 | 原 identity 仍可匹配；ticker preflight 或流内 Phase A 的既有 UNSAFE/repair 门处理。不漏身份、不替换为 MISSING，不把读 meta 成功等同可信来源 |
| manifest 缺失/损坏/悬空 item、非目录普通文件、隐藏 symlink/special | 身份枚举仍严格用原 list/get；它原来忽略的仍忽略。随后原 inspection 可能 REPAIR_REQUIRED/UNSAFE/typed 拒绝，时点/原因不前移到 batch meta |
| stream 内 FileNotFoundError/OSError | 原 ordinary FILING_FAILED，reason=`storage_failed`、message=`下载产物读写失败`，继续后候选（repair candidate failed 仍 break） |
| stream 内 ValueError/其它普通异常 | 原 ordinary FILING_FAILED，reason=`filing_execution_failed`、message=`财报文档执行失败`；原 typed provider 分类保持 |
| 首候选前或 start 外普通异常到 download runtime | OSError：failure kind STORAGE、reason None、hint=`请确认工作区可读写后重新发起下载。`；ValueError/其它：EXECUTION、reason None、hint=`请保存脱敏诊断并排查失败原因后重试。`；direct error kind 分别 STORAGE/EXECUTION。不能统一改为 typed storage |
| 已有 typed SourceIntegrityPreflightError | 原 STORAGE、既有 reason 映射（如 UNSAFE_PUBLICATION）、hint=`请检查并修复工作区来源状态后重试；重复下载不会自行修复。`；stream 内原一条 failed row + CnDownloadIntegrityAbort 保存已处理 rows/cause；首候选前保持原无候选 typed 路径 |
| Phase B conflict 耗尽 | 原 Exception catch 普通 filing failure/继续，不扩大 typed abort；F6 原 sibling error projection 待独立 WU |
| 取消 | 原 checkpoint 返回/抛同对象路径不迁移；before-first/start 后/stream acquisition/convert/commit 前仍不伪造 failed；已有 rows 守恒，PIPELINE_COMPLETED cancelled 路径保持；direct stream 原取消先于 identity 读取 |

普通 filing 失败后继续、repair failed 后 break、typed 中止和取消是不同分支；不靠默认 status/fallback 统一。manifest 成功规则、summary total/downloaded/skipped/failed、持久摘要与 trace/LLM-facing 词表全部原 owner 不变。本轮没有新增拒绝/继续/错误 reason 的待用户选项。
