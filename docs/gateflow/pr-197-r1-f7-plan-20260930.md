## 2. 第一性原理判断、目标与非目标

问题成立于语义 owner：workflow 产生、adapter 校验的是同一跨边界协议事实；当前分别内联值、跨模块引用私有值、用任意 `str` 参数承接，未来修改需要协调多个定义。现有生产值、投影和异常路径正确，没有证据支持增加状态或改变失败/取消决策。

目标与成功信号固定为：既有 `cn_download_models` 持有唯一封闭 terminal 类型、值和普通入口合法子集；普通下载、取消、私有完整性快照及本地 rebuild 直接消费；adapter 移除对 workflow 私有状态常量的 import，仍按原有入口子集拒绝未知值。serialized 字符串、JSON 字段、文档摘要、原异常 identity、取消时序与 direct/job public failure 保持。

非目标：每文档 `downloaded/skipped/failed` 词表、原因码、storage 完整性分类、public failure/terminal disposition、财期/年度证据、来源选择、候选身份性能、取消状态机、下载版本、真实下载/转换、网络 provider、私人语料、公共配置或通用状态机框架。不给低风险 owner 收敛增加新的 raw JSON parser、结果 DTO/schema、状态迁移表、运行时生产参数硬化或兼容层。

## 4. 已固定的实现决定

### 4.1 owner 中新增五个公共符号

仅在 `dayu/fins/pipelines/cn_download_models.py` 定义、中文说明并加入该模块 `__all__`：

```python
CnDownloadTerminalStatus: TypeAlias = Literal["ok", "cancelled", "integrity_failed"]
CN_DOWNLOAD_TERMINAL_OK: Final[CnDownloadTerminalStatus] = "ok"
CN_DOWNLOAD_TERMINAL_CANCELLED: Final[CnDownloadTerminalStatus] = "cancelled"
CN_DOWNLOAD_TERMINAL_INTEGRITY_FAILED: Final[CnDownloadTerminalStatus] = "integrity_failed"
CN_DOWNLOAD_NORMAL_TERMINAL_STATUSES: Final[tuple[CnDownloadTerminalStatus, ...]] = (
    CN_DOWNLOAD_TERMINAL_OK,
    CN_DOWNLOAD_TERMINAL_CANCELLED,
)
```

三个字面量只在此 owner 定义；子集从同一常量派生，adapter 不再另列字符串/同义常量集合。完整性入口直接与第三个常量比较，单元素无需新集合。完整封闭类型不是允许所有入口接受所有值的授权。

选择 **Literal + Final**，不选 StrEnum：现有模块已经采用此写法；生产 JSON 直接写原生 str，现有解析器返回 str，不需要 enum 实例生命周期、构造 parser 或 `.value` 投影；现有唯一参数只需变窄。临时 strict pyright 正/负探针已证明该写法接受合法常量及条件表达式并兼容 `dict[str, JsonValue]`，拒绝 `str/failed` 参数。无需运行时反射 `get_args` 来生成词表；测试可用它核对类型声明和值一致。

该选择仅实现用户既有词表 owner 裁决，不新增状态/行为选择。生产 `_build_result` 不新增 runtime validation/异常分支；封闭参数由类型门禁约束，adapter 保持对 JSON 的现有 runtime 校验。

### 4.3 runtime 接受矩阵及不变量

| adapter 入口（通过原 `_required_cn_text` 后） | ok | cancelled | integrity_failed | failed/error/unknown/其它文本 |
