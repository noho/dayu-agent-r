## 3. taxonomy/sidecar 最小接口轮廓（提案，当前不存在）

P0 仅提出 `XbrlTaxonomyInput(taxonomy_root: Path, catalog_zip_name: str | None)` 作为**未闭合的形态草案，不冻结产品接口**；它没有携带 workspace/管理员受信根边界或 provenance 清单，不能据此实施可信输入校验。`remote_fetch` 在本 work unit 恒为 False，不放在用户材料 `extra payload`、隐藏环境变量或从原件父目录猜。**一个受控目录**始终保留相对引用所需的 XSD 与 linkbase 散文件；`catalog_zip_name=None` 表示纯相对树，指定文件名则表示同一目录顶层**恰一份**合法 `.zip`，含 `META-INF/taxonomyPackage.xml` 与 `META-INF/catalog.xml`，把绝对 URI 映射到包内文件。相对 `schemaRef`/`linkbaseRef` 由散文件布局解析；绝对 import、绝对 `schemaRef` 与绝对 `linkbaseRef` 均须经 catalog 映射，后两种入口引用的真实可用性分别由 P0-B 独立验证。禁止把散文件与 catalog 拆成互斥 layout，也禁止其它顶层有效 zip 被 Docling 意外收集。Docling `taxonomy` 参数只接受目录；backend 会整树 copytree，收集顶层合法 zip，`BytesIO` 固定写为 `instance.xml`，故 root 中同名文件须拒绝。包形态、映射闭包与 zip 实际可用性仍需 P0-B 复测，不能凭源码承诺。

管理员受控归档 owner 保留来源、许可、每文件 SHA-256、完整相对布局、指定 zip 名及 root 清单，提供可核验的 provenance。目标不变量是 taxonomy root **绝对、规范化、解析后位于用户可写 workspace 外且属于管理员受控输入**；相对路径、`..`/非规范路径、落入 workspace、解析后越界及清单不匹配均须 fail closed。**当前 Documents runtime 没有 workspace 边界或 provenance 清单输入，不能单独执行上述全部判断。** P0 后的 S1 implementation plan 必须明确每项判断的唯一校验 owner 与强制点、持有 workspace 边界或管理员受信根的显式输入、管理员清单及其可信传递通道，并设计 Fins 持有的 workspace 边界校验与 Documents runtime 转换进程内完整性复验如何协作；该接口须双路复审通过，才可冻结并进入产品实现。若仍无法闭合，S1 硬停、产品 gate blocked，不用默认值、CLI 文案或操作者自觉代替。只接普通文件，拒绝 symlink/hardlink/特殊文件、重复或不规范路径，限制文件数、总字节、zip 展开比与临时占用；校验到 copytree 的内容变更窗口也须在 S1 implementation plan 用受控快照/再校验闭合并实测，不能拿预检当隔离。**这些只管输入包，不是 Arelle 后续读取沙箱。** CLI 的 taxonomy 参数、Service/Fins 的 typed 传递和共享 `_DoclingProcessTarget` 的显式字段都只是待设计候选，不把显式参数塞进 `extra payload`。`DoclingUploadService` 的必要改动仅归未来**一个**转换链 slice；具体 OS 隔离 API 必须通过 P0-C 后再冻结。

typed 的真实合规财报 instance**时，按其实际引用形状使用同根组合：先以该 instance 为入口、在离线配置及完整 taxonomy 下由 Arelle 运行 `--validate --validationExitCode`，确认 exit 0、无验证错误，并按 P0 归档契约留存来源/许可、完整 taxonomy、原始 argv、stdout/stderr、exit 与验证记录；只有合法性门槛通过且原始证据已留存，才用**同一 instance**分别运行 Docling Path/Stream，按上述当次采集规则分别记录实际读取/映射目标、结构化输出与原始双流。不合规或无法证明合规的样本不得充当真实正样本，也不能用其 Docling 失败归因产品；验收记录须列明该 instance 的 `schemaRef`、XSD import、`linkbaseRef` 等实际引用形状及逐条解析目标，并以完整原件的全部 context 中 `xbrldi:typedMember` 检查和 Arelle 加载后实际 context 维度值检查，记录无 typed 的原始证据、检查范围、版本与输入哈希。无 typed 的证明仅及该 instance 实际使用的 context/维度值和本次引用形状、taxonomy、版本及配置，不证明所载 taxonomy 不含 typed 维度，也不外推到含 typed 的财报；若不存在、检查范围不闭合或当前 Docling 仍失败，则 goal 3 blocked。AAPL typed 缺陷由已发上游 #4437 跟踪，不能以合成样本代替真实财报 CLI 成功。OS 强制零出站规则的生效证明及逐向量网络 trace 归 P0-C。


**P0-B 当次模型证据探针（仅 Docling 2.127.0 / Arelle 2.45.3）**：在上述三种合成向量和真实样本的 Docling Path/Stream 记录前，先用最小自足、经 Arelle 离线验证合法的无 typed 成功样本、含 typed 的已知导出失败样本，以及缺 Arelle、坏 taxonomy 两个最小失败探针，实测以下三条互斥采集路径；留每次输入/配置/版本哈希、完整异常链和 trace、原始 stdout/stderr、状态与探针快照。① 正常成功或 typed 等 pipeline 阶段错误：`convert(source, raises_on_error=False)` 返回 `ConversionResult`；记录 `status`、`errors`，在本次进程内及时快照可取得的 backend/model，typed 失败不得改记成功。② backend 抛 `DocumentLoadError`：输入拒绝形成 invalid-input `ConversionResult`；记录拒绝类型、原始 cause、状态与 `errors`，**不假定存在 `_backend` 或模型**，该次逐边/映射证据缺失则对应向量 `blocked: run evidence unavailable`。③ backend 构造/导入或其他未被 `DocumentLoadError` 收纳的异常：异常逃出 `convert`，**没有 result**；探针最外层捕获并记录异常类型、消息、cause 链、完整 traceback、双流、Docling/Arelle 版本及输入/配置哈希，直接按同一 blocked 出口处理，不能读取虚构的 `result.errors`。三类必须由运行时观察分类；`raises_on_error=False` 不是构造期全局非抛出保证。此最小探针只验证采集方法，不替代 P0 正式样本、证据归档和合法性门槛。

对①中实际可得的同次模型，把证据分成**三个不同集合**，不可相互冒充。**成功加载目标集合**：遍历 `model_xbrl.urlDocs`，逐项保存 key（Arelle 规范化后的请求 URI）、`ModelDocument.uri`、`filepath`（映射后的目标路径或 archive-entry 形状）和文档身份；这证明该次模型登记的成功加载目标，不代表原始逐引用次数，也不单凭路径形状证明 zip entry 已实际读取。**失败/不可加载请求集合**：保存 `urlUnloadableDocs` 的规范化 URI、标记和相关错误/拒绝信息；它没有完整原始引用元素、也不保证记录全部未加载尝试。**原始引用声明清单**：逐个来源文档的原始 XML/模型元素按其引用机制枚举，每条保存来源文档身份、元素身份及位置、引用类型、原始 URI 文本、适用的 base/解析规则，以及 `attempt_observation=observed|unknown`。清单中的规范化请求 URI、成功/失败状态、所对应的 `urlDocs` 文档身份、`filepath` 与实际 zip entry 读取，只在该次运行有可与该声明元素逐项对账的直接事件时作为已观察结果填写；否则仅保留静态声明和可核的候选解析信息，`attempt_observation=unknown`，不得把候选写成该次执行结果。`observed` 只表示该声明有同次直接可对账的尝试/发现事件，不自动证明目标文件或 zip entry 内容已读取；读取另需其直接记录。对 `schemaRef`/`linkbaseRef` 的成功 href，先检验同次 `hrefObjects` 是否按元素保留每次事件，能逐项对账才标 `observed`；失败 href 可从原始元素列入清单，并与 `urlUnloadableDocs`/errors 对照，但按 URI 聚合的失败项本身不能把每个元素标为 `observed`。XSD import/include、schemaLocation 及其他非 href 发现机制须各自核对其原始元素、规范化规则与同次直接事件；不能把 href 结构的覆盖范围外推到它们，也不能以 `urlDocs` 命中推断每条声明实际调用了 `load`。`referencesDocument` 仅另存为按目标文档聚合的摘要（类型集合、首个代表元素），**不得**用作逐声明事件、次数或 `attempt_observation` 真源。

先以“两个不同元素、原始 URI `typed.xsd`/`./typed.xsd` 同归一个目标”和“另一个元素请求不存在的 `missing.xsd`”的最小样本，分别在 Arelle 与 Docling 同次模型中实测：原始声明数、元素身份、规范化 URI、可直接观察的成功 href 个数、`urlDocs` 目标及 `filepath`、`urlUnloadableDocs` 失败项能否逐项对账；同时检查聚合 `referencesDocument` 确实只保留一个同目标记录。**另增两个独立小探针**：① 分别构造两个不同 `xs:import` 声明同指一个不存在目标、两个不同 `xs:include` 声明同指一个不存在目标，记录各自的静态声明、同次直接事件有无及失败缓存/namespace 短路情形，不能把一个 `urlUnloadableDocs` 项分配成两次已观察失败；② catalog 将引用映射至 zip 内 entry，分别保存 catalog 声明、映射目标形状和该次具体 entry 读取记录有无，不能以 `filepath` 或 OS 对 zip 容器的访问推断 entry 已读。小探针只检验采集能力，不降低正式向量门槛。对每个正式 Path/Stream 向量也必须在**该次转换进程内**调用并保留 `result`，返回后立即、释放结果/模型或清理进程前快照成独立普通数据，记录状态、`errors`、进程/时间窗、输入和 taxonomy/package 哈希及配置。逐声明记录 `attempt_observation` 与直接事件来源；重复失败、非 href 的 import/include/schemaLocation 或 zip entry 若缺对应的同次逐边/逐 entry 运行记录，**该向量及该 Docling 路径**记 `blocked: run evidence unavailable`。其它必须核验的原始 URI/元素、规范化请求、成功或失败结果、实际映射目标无法由完整同次关系闭合时也同样 blocked；不得以静态 XML、聚合摘要、重放或 OS trace 补成 pass。zip entry 的实际读取须有同次文件源/模型中可核的具体 entry 记录；`filepath` archive 形状与 OS 文件 trace 不单独证明 entry 内容读取。`XBRLDocumentBackend` 的临时 taxonomy 目录在 `convert` 返回前已清理，模型所载临时 `filepath` 只能作为当次映射记录，不能事后重读补证。内部属性链 `result.input._backend.model_xbrl`、`urlDocs`、`urlUnloadableDocs`、`hrefObjects` 和 `referencesDocument` 仅为版本绑定的 P0 探针入口，不进入 Dayu 产品或公开契约；属性失效或关系缺口留版本、缺失点及原始证据，按 blocked 回 plan/fix，不加产品 hook。OS trace 只证明可见文件访问，不证明 zip 内逐条 entry/catalog 映射；独立 Arelle 重放继续单列，不能充作 Docling 当次快照。快照本身也不证明转换成功或安全隔离。

**P0-C 安全**：先在每个真实平台找到可运行的强制机制，再以合成 sentinel/本地监听端点跑 §6 全矩阵，对**每个已尝试向量**用 OS 文件/网络 trace 核对根外读取未成功且无出站请求；随后对真实 Docling+Arelle、Dayu 进程链测拒绝、取消、清理及子进程继承。记录平台与目标执行环境，有限矩阵只检验样本覆盖，零出站和文件边界的保证由 OS/受信隔离规则提供。仅 status、应用日志、`workOffline`、预扫描均不算通过。失败记 `blocked: isolation unavailable` 与原始 trace，回 goal/总控裁决。

本版完成的含义仅是待同版 Kimi/MiMo plan review 的 P0 规格、已有结果和 blocked 出口。当前仅有 macOS 项目全树 dry-run；真实安装/跨平台、zip+catalog/真实正样本、三平台强制隔离均未 pass，因此撤下原 S1“受控安装与隔离转换”和 S2“真实 CLI/manifest 成功”的实施承诺。若 P0-A/B/C 以后全 pass，另写 S1 可执行 implementation plan，**先闭合 workspace 外与 provenance 清单校验的唯一 owner、强制点及全部显式输入并经双路复审**，再冻结产品接口和实施；任一项未闭合则 S1 硬停。S1 的共享 capability 真源及其 CLI/help/tool 同源投影必须将无 typed 真实正样本的已验证引用形状、无 typed 范围和部署条件作为公开声明的上限，不能仅凭该正样本宣称一般 `XML_XBRL` 支持；含 typed 的支持须待 Docling 上游修复、同等合法性与真实上传重测通过后才能宣称。若共享 capability 及其投影无法诚实表达该受控范围，S1 接口/文案计划硬停并重新接受同版双路 plan review，不能以模糊的“支持 XBRL”越过范围约束。若 P0 不 pass，让 goal/总控裁决公开 capability 的诚实处置，不自行降级。

## 6. 单一安全矩阵、成本与上游 issue

P0-C 和后续 owner 测试共用：C0 根内正常相对引用（正对照）；C1 `file:` 根外合成 sentinel；C2 绝对本地路径；C3 `../`；C4 HTTP(S) URL 与本地监听端点，含非 taxonomy 用途；C5 URL 编码/大小写/正规化变体；C6 symlink、hardlink、reparse、zip 内路径及 catalog 重定向；C7 Windows UNC、盘符、`\\?\`、8.3 名称；C8 **非 schemaRef** 读取向量：DOCTYPE/外部 ENTITY、XInclude、样式或链接导入、非常规 scheme、可加载扩展/插件入口，各做最小合成输入并记录是触发读取还是解析器在入口拒绝。C1–C8 对各自适用平台均须有界拒绝，且对**每个已尝试向量**的 OS trace 核对无根外读取成功、无出站请求；C7 及 reparse/盘符等 Windows 专属项只在 Windows 实测，不能由 macOS/Linux 代填。矩阵是有限反例集，不宣称穷尽未知输入路径；跨向量不变量须由已证明生效的 OS 文件与网络强制边界保证。不得另写不一致的“非法五类”。对目录/zip 记录数目、总字节、展开比、`instance.xml` 冲突、copytree 耗时/磁盘峰值。现有 `run_docling_pdf_conversion` 的 PDF backend×device 回退链也作用于 XBRL；Documents runtime owner 需审视 XBRL 单次语义，测失败重试次数、取消和清理，避免多次整树复制。

合法 typed 微型输入已锁定 Docling 导出 owner；总控已用纯合成证据提交 Docling [issue #4437](https://github.com/docling-project/docling/issues/4437)，后续如需补证先复核精确版本、完整 XML/XSD、Arelle 验证 exit、Docling Path/Stream 双流栈与无敏感内容，并对账该 issue，不重开同一问题。用户对确证的真正上游问题已有**条件授权**，无需再设授权 gate；本轮用户明确禁止发送、评价或更新。Arelle explicit/缺 taxonomy 支仍需独立验证，不能写成同一已证 bug。
