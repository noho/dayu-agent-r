## 最小设计与唯一 owner

1. **同版状态只消费 O12 storage owner。** 实施时实读 O12 已集成的 `MaterialUploadPublishedState`、状态仓储协议/实现及分阶段 publication precondition：核对其确能同次表达 exact ticker/document ID、company meta、完整 canonical source business meta、presence/tombstone、opaque revision，且 strict 完整性把真缺失与损坏分开。COMPLETE tombstone 的 `source_meta` 必须保留可信 `is_deleted=true`、`deleted_at`、`first_ingested_at`、`created_at`、`document_version`、`source_fingerprint`，不可因“非 active”置 None；状态类型与仓储读取须约束这些字段同版一致。动作重检只消费 O12 材料 batch/skip guard 已有的 writer-owned 同版读取/比较；若确需扩展输入，仅在该 storage owner 补足 exact 动作状态所需字段，不新建 published snapshot、独立 repository、第二次公司读取或下游比较。`is_deleted` 以可信 storage meta/现有 `require_source_meta_is_deleted` 为真源；不能由 `source_meta is None` 或目录存在性猜 tombstone。若 O12 最终契约不能表达这项复验或恢复所需旧值，停止并回 O12 plan gate，不用下游重算。
2. **动作裁决由 Fins shared precondition 持有。** `evaluate_upload_overwrite_precondition` 的纯输入显式包含 `SourceKind`、exact 三态 `missing/active/tombstone`、resolved action、overwrite；三态从 O12 同版状态投影，filing 从其现有状态 owner 投影，均不从异常文本推断。`ALLOWED` 仅表示本项前置条件未拒绝，不替代后续 storage CRUD。以下格子仅针对真缺失或完整可信目标；`auto` 先由既有 action resolver 解析，显式 action 原样保留：

   | kind / exact 状态 | create，无 overwrite | create，overwrite | update，overwrite 任意 | delete，overwrite 任意 |
   | --- | --- | --- | --- | --- |
   | material / missing | ALLOWED，现有 create | ALLOWED，现有 create | `UPDATE_TARGET_MISSING` | `DELETE_TARGET_MISSING` |
   | material / active | `CREATE_TARGET_EXISTS`，同/异内容均拒绝 | ALLOWED，走现有覆盖发布；同内容也不 skip | ALLOWED，沿现有 update/skip | ALLOWED |
   | material / tombstone | ALLOWED 到现有 source upsert/storage 的 create 拒绝；**非**新 typed O14 规则 | ALLOWED 到现有 reset/recreate 路径，保持其现行终态 | ALLOWED，沿现有恢复路径 | ALLOWED，健康重复 delete |
   | filing / missing | ALLOWED，保持现行 | ALLOWED，保持现行 | `UPDATE_TARGET_MISSING`，保持现行 | ALLOWED，保持 filing 现行 delete |
   | filing / active | `CREATE_TARGET_EXISTS`，保持现行 | ALLOWED，保持现行 | ALLOWED | ALLOWED |
   | filing / tombstone | `CREATE_TARGET_EXISTS`，保持现行 | ALLOWED，保持现行 | ALLOWED，保持现行恢复路径 | ALLOWED，保持现行 |

   只将 material active create、missing update/delete 三格升级为 O14/O15 typed 拒绝；filing delete-missing 保持现行允许格，若要改变须另立 goal；其余 filing 规则不因 kind 合并而漂移。material tombstone `create --overwrite` 由当前 `replace_existing`→`reset_source_document` 路径支撑，但其用户可见终态不是本项新承诺；实施时按集成 storage 真相做隔离回归。`UploadOverwritePrecondition` 现有 `CREATE_TARGET_EXISTS`、`UPDATE_TARGET_MISSING` 保留，仅新增 `DELETE_TARGET_MISSING`；各市场和 CLI 不复制表。
3. **请求 admission 先于生命周期。** 在 O12 的实际 typed material admission/validated request 和共享 initial-admission helper 上插入上述动作检查，不另造 request 或公司决策。先执行 O16 静态字段/文件组合与身份校验；读取**一次** O12 同版状态，解析目标动作，再调用 O12 公司决策；命中目标错误时不得被缺名遮蔽。runtime `_validate_runtime_upload_request` 对 direct/job/observation 在 producer/记录创建前执行；独立 SEC/CN/HK pipeline 在首事件前用同一 helper；CLI factory 前预检与 Service/tool 消费同一 validator 和 typed reason。CLI 预检后、runtime 接收前重新读到的新状态按新的 admission 判定；runtime 已接收后的变化不再重判为 usage。
4. **writer-owned 材料复验只进入 O12 共享 publication owner。** O12 最终路径在材料转换前独立提交合法公司意图；本项只在材料自己的 batch/skip guard（现有 `commit_prepared_upload_batch` 邻接入口或 O12 最终同义入口）消费 O12 storage 唯一同版比较，扩展动作/目标状态所需的 writer-owned 复验，不在 SEC/CN workflow、tool 或 CLI 复制状态机、snapshot、guard。admission 的同版 source 是材料 expected source；公司 batch 正常返回的 outcome（keep/skip 则为 admission company meta）是材料 expected company。材料 writer 下的 published/staging 重读必须由 O12 storage owner 完成，并在材料 commit 的首次 swap 前比较 source status/presence/tombstone、完整 canonical meta/revision 与 post-company meta；skip 也在同一 guard 下比较后才报告。若 O12 guard 已覆盖全部漂移键，只补动作投影与测试，不再增加比较路径。**接收后**材料 source 或 post-company 状态变化统一 typed `source_publication_conflict`，即使 fresh 状态可满足另一动作格（包括并发 delete→tombstone），也不改报 usage/target-missing；公司 commit 前的公司漂移/alias 冲突按 O12 公司 guard 处理。公司提交前被拒，零本请求公司/材料发布；合法公司已提交后的材料内容失败、取消或 guard conflict 保留该公司事实，材料零发布，缺权威 manifest 条目不得报成功。O12 alias/identity 优先级及两个各自 guard 的原子比较保持最终合同。若分阶段 guard 无法与 O34 公司事实同真，停止并交最小证据回 O12/本 plan 裁决。
5. **typed usage fact 与 public failure 各有唯一 owner。** 三个 target reason 的 closed-code 增量逐层固定：`UploadOverwritePrecondition` 保留 `CREATE_TARGET_EXISTS`、`UPDATE_TARGET_MISSING`，新增 `DELETE_TARGET_MISSING`；`FinsUploadUsageCode` 同样保留前两码、新增 `DELETE_TARGET_MISSING`；`FinsUploadFailureCode` 当前没有 target 码，新增 `CREATE_TARGET_EXISTS`、`UPDATE_TARGET_MISSING`、`DELETE_TARGET_MISSING`，全部且仅归 `FinsUploadFailureKind.USAGE` 分组。material 三码分别说明 create 目标材料已存在、update 目标材料不存在、delete 目标材料不存在及纠正动作；filing 既有 create/update 文案逐字保持，filing delete-missing 不新增拒绝。

   **现状反例与待实施 producer 边界。** 当前 `FinsUploadUsageFailure` 只有 `code/message`，`code` 接受 `FinsUploadUsageCode | FinsUploadFormatFailureKind`；`ingestion_runtime.py:fins_upload_usage_failure` 仅处理前者，而 `_raise_upload_format_usage` 直接构造后者，绝不能写成 format 已走同一 producer。实施时把 `FinsUploadUsageCode`、`FinsUploadUsageFailure`、`FinsUploadUsageError`、唯一 `fins_upload_usage_failure` producer 及 `_USAGE_MESSAGES` 一起迁入 Fins 下层 `upload_usage_contract.py`（名称按实际导入图确认），迁移全部引用且不留兼容 re-export；它可依赖 `upload_format_contract.py`，`ingestion_runtime.py` 与 `upload_failure.py` 均依赖它，后二者不互相反向 import。producer 明确接受普通 usage code（含全部既有码和三 target）或已由 format owner 校验的 `FinsUploadFormatError`。其中三个 target code **必须同时传入 typed `SourceKind`**：同一 producer 以 `(code, source_kind)` 在唯一 usage 文案/hint 真源中选定业务文本；缺 kind、非 `SourceKind`、`DELETE_TARGET_MISSING + filing` 均在 owner 边界拒绝，非 target code/format error 不借 kind 猜目标。filing `CREATE_TARGET_EXISTS` 保留“create 目标已存在；请改用 update 或允许覆盖”，`UPDATE_TARGET_MISSING` 保留“update 目标不存在；请改用 create”，逐字不变；material 对应为“create 目标材料已存在；请改用 update 或允许覆盖”“update 目标材料不存在；请改用 create”，仅 material 的 `DELETE_TARGET_MISSING` 为“delete 目标材料不存在；请核对目标材料后重试”。三个 target hint 也由该 `(code, source_kind)` 选择并保持安全、可执行，不在 shared precondition、市场 workflow、CLI、tool 或 public mapper 设置第二套文案/hint。`_raise_upload_format_usage` 仅调用 producer 并包装 `FinsUploadUsageError`，不得直接构造 fact、按 kind 查文案表或补 hint。其余普通 usage 的原文案仍由同一 `_USAGE_MESSAGES` 产生；全部 code 的 hint 也在该 producer 唯一产生，非 target 既有码用 owner 定义的安全 hint，不让 tool 补默认值。

   **format 真源与 fact 合同。** `upload_format_contract.py` 的 `FinsUploadFormatError` 已拥有三个 role-specific kind、有界的角色 usage message、canonical `file_label`；实施时由此 owner 增加既有 public 通用 message（当前 `upload_failure.py` 的“文件格式不受支持，请选择支持的文件后重试”）及既有 retry hint（“请查看上传帮助中的支持格式后重试”）的安全投影，再由唯一 usage producer 原样装入同一个 fact，不在 producer/runtime/tool/public mapper 复制 format 文案表。为保留现有 filing usage 角色文案和 format public 通用文案，fact 显式含 `message`（usage/CLI/tool）、`public_message`（public reason）、`hint: str`、`file_label: str | None` 及 closed `code`；普通 usage 的 `public_message` 与 `message` 相同，format 的两种 message 均由 format owner 提供，绝不从异常字符串或 code 反推。**仅 usage fact 的 `hint: str` 为必填合同**：对全部既有/新增 usage code 和三个 format kind 均非空、1..240 字符，禁止控制字符、`/`、`\`；hint 仅由 owner 固定安全文案产生，不插入本地路径、内部 ID 或异常原文。`message/public_message` 均须 1..240 字符、无控制字符；普通 usage 的既有 `YYYY-MM-DD`、`create/update` 等字面斜杠保留，不能误用 public reason 的无斜杠校验使 filing 文案失效。仅能映入 public reason 的 target/format `public_message` 还须通过该 reason 既有 path-free 校验；format message 的文件部分仅来自 canonical label。format fact 的 `file_label` 必为已由唯一 canonicalizer 产生并验证的非空 public label；非 format fact 无文件归属则为 `None`，不从 message 提取。fact 在 owner 构造时拒绝缺失/非法字段；`FinsUploadFailureReason.retry_hint` **保持既有 `str | None` public schema**，非 target/format 的既有 reason（如 `UNEXPECTED_RUNTIME`）仍可为 `None`，JSON 往返不收紧。只有 target/format fact 经唯一 public mapper 投影时，`retry_hint` 必须等于非空 `fact.hint`；禁止消费者 fallback 或全局 reason 必填改造。这些字段与 producer 均为**待实施**，不是当前 API。

   **唯一 public 映射与可达路径。** `upload_failure.py` 是唯一 `FinsUploadFailureReason` 构造/usage→public owner：三个 target usage code 精确映同值 public code、`kind=USAGE`；三个 format kind 均精确映现有 `UNSUPPORTED_UPLOAD_FORMAT`、`kind=USAGE`，保留当前 public 通用 message 与 `file_label`。两类 reason 均直接取同一个 fact 的 `public_message/hint/file_label`；format error 的独立 workflow 异常分类也先经同一 usage producer 装箱再映射；`FinsUploadUsageError` 若到达 public 分类则直接读取其 fact，不从异常文本重建，不能保留第二套 format message/hint 字面量或第二构造路径。其余既有 usage code 在稳定 admission 以 `FinsUploadUsageError` 拒绝，当前 public enum 没有对应 code；不得为其制造 `storage_io`/`unsupported_upload_format` 映射，若集成后可达 public failure 则先回 plan/schema 裁决。CLI 按既有 usage exit 消费 `fact.message`；Service 保留 typed fact；tool 在普通 `ValueError` 前捕获 typed usage，只取 `fact.message/hint` 并保持 tool `invalid_argument`，不增加 Fins code 或 file_label 字段；format 的 label 只在有界角色 message 自然包含时可见，tool 不另拼 label。普通非 Fins `ValueError` 的既有通用 hint 保持。direct 与**实际可达**的 awaited Fins summary 只经上述同一 public mapper 取得 reason，包括 format `file_label`；稳定 target admission 拒绝不创建 job/observation，不能造任务来测试不可达 awaited 分支。`upload_failure.py:fins_upload_failure_from_exception` 在通用分类前精确直通 `FinsUploadFailureError.failure`。接收后漂移沿 O12 同一 material publication conflict reason 投影既有 `source_publication_conflict`；material publication message 写业务可读的“目标材料/来源文档”，filing 既有文案不变。损坏/I/O/锁失败保持 typed integrity/operational，不伪装 target missing 或 drift；对外不泄本地路径、异常原文或内部 ID。

   **CLI 早于 runtime 的 raw format 入口。** 当前 `dayu/cli/commands/fins.py:_upload_material_stream` 在调用 Service 前先执行 `_validated_upload_files`，其 `FinsUploadMaterialFiles.from_upsert_paths` 可直接抛 `FinsUploadFormatError`；`run_fins_direct_command` 现由独立 raw catch 打印 `str(exc)`，因此只修 runtime `_raise_upload_format_usage` 不能覆盖实际 CLI 入口。未来 S1 在 `_validated_upload_files` 的 format 异常边界调用上述**同一个 Fins usage producer**，以原 typed `FinsUploadFormatError` 装箱并抛 `FinsUploadUsageError`；CLI 仅转交 error/fact 给既有 typed usage 投影，保留 `EXIT_USAGE_ERROR`，不通过 `str(exc)`、角色枚举或文件后缀私造 message/hint/file_label。`upload_material` 的该 raw catch 路径须由入口测试证明不再可达；若其它 CLI 命令仍可到达 raw catch，按其自身 owner 边界另行核对，不以本项无证据删除。CLI 的 raw selection、runtime 与 tool 必须比较同一 format kind 的 fact `message/hint/public_message/file_label`；CLI 现有输出仍从 fact.message 取得，任何展示 hint 的位置只能逐字使用 fact.hint。canonical label 算法仍唯一在 `direct_events.py`，format owner 产生/校验并携带值，usage producer/CLI 不重算。

这只在 O12 最终同版 published state、公司独立提交和材料自身 guarded publication 上加入 O14/O15 必需的动作和材料复验。`REPAIR_REQUIRED`/`UNSAFE` 是动作表之前的 fail-closed 边界，健康 tombstone 才进入重复 delete 格；`auto`/skip 维持 O12 与 O13/O33 既有合同。不改持久化数据形状或 tool 协议字段；Fins 内部 typed usage fact 会新增必填 hint、显式 public_message 与 file_label 承载，上述 closed public enum 成员会扩展，现有 Fins public failure JSON 的 `retry_hint` 字段直接承载同源 hint。没有第二个 storage 状态源或第二套公司发布编排。

## 真实 CLI 状态矩阵与证据格式

在隔离 CI-owned workspace 用真实 `dayu-cli upload_material --ticker ... --forms MATERIAL_OTHER --material-name ... --action ...` 和不同内容的两个小型支持文件，只跑**稳定、可复现**状态。逐场景保存 exact argv/cwd、stdin、exit、stdout/stderr、screen、前后文件树 hash/diff、source meta、material manifest、company identity/meta、SQLite/Host EventLog/Trace/Memory/job 查询及进程终态。不得复用冻结 A04 为“不同内容”证据；先补该缺口。可控并发 barrier 只在上述 owner/仓储自动测试验收，不列为真实 CLI 必交证据。

| 初态 / 请求 | 预期 |
| --- | --- |
| fresh + create | 成功发布 v1；ID/manifest/meta 一致。 |
| active + create，无 overwrite，输入相同 | O14 typed conflict；不 started、不 skip、零公司/材料业务 diff。 |
| active + create，无 overwrite，输入不同 | O14 typed conflict；上述零副作用；此行为必须新增真实 CLI 证据。 |
| active + create + overwrite，输入不同 | 成功，同稳定 ID 升版，meta/manifest 同源。 |
| active + create + overwrite，输入相同 | 仍走现有覆盖发布而非 skip；ID/版本/meta/manifest 同源。 |
| never existed + update，overwrite false/true | 两者均 O15 typed update-target-missing；零业务 diff。 |
| never existed + delete（无 files） | O15 typed delete-target-missing；零业务 diff。 |
| 受支持路径存在但后缀不支持 + material upsert | CLI 文件 selection 先于 runtime 拒绝；与同 kind runtime/tool 的 format usage fact `message/hint/public_message/file_label` 同源，CLI usage exit 和角色文案保留，不启动 Service/runtime、无公司/材料业务 diff。 |
| active + update、active + delete | 合法完成，作为正向回归。 |
| tombstone + repeat delete | 成功而非 never-existed；O13 时间幂等另行验收。 |
| tombstone + auto，输入与旧指纹相同 | 解析为 update 并恢复原 ID；保留原 `document_version`（UM-A09 为 v3）及 `first_ingested_at`/`created_at`，`is_deleted=false`、`deleted_at=None`，meta/manifest 同源。 |
| tombstone + auto/update，输入与旧指纹不同 | 解析为 update（auto）或保留显式 update 并恢复原 ID；按既有版本 owner 递增 `document_version`，不重置 v1；保留原 `first_ingested_at`/`created_at`，`is_deleted=false`、`deleted_at=None`，meta/manifest 同源。 |
| active + update/auto，相同内容并有合法公司更新意图 | 按 O12 集成合同 skipped；公司更新生效，材料零 diff。 |
| material tombstone + create，无 overwrite | 记录并保持现有 source upsert/storage 拒绝；不作新 typed O14 接受标准。 |
| 合法公司已独立提交 + 可稳定复现的材料转换/内容失败 | 公司 identity/meta 保留；材料无本请求权威 manifest 条目，文档未成功。取消切点由可控 owner 自动测试验收，不用 sleep 型 CLI 竞态冒充稳定证据。 |

fresh 与已有公司 workspace 各覆盖关键拒绝；US/CN/HK 至少各一次 owner 到 facade 的端到端状态拒绝，全部入口有针对性自动测试。混合优先级（无 files+missing、delete 带 files+missing、缺名+missing）、损坏/UNSAFE 与并发漂移以确定性自动测试为主，不用 sleep 型双进程 CLI 冒充可控 barrier。使用 `--base` 的位置和合法命令参数以实施时 CLI help 为准。真实 CLI 证据只登记运行所用 HEAD、环境、输入 hash，不回填旧 oracle 分数。
