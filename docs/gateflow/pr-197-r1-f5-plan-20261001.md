    参数：ticker 为 exact canonical 主体，source_kind 为来源种类。
    返回：有序同版 COMPLETE/nondeleted 来源视图；无合格来源为空 entries。

本地 admissibility：view ticker 必须等于当前 query/profile canonical ticker；仅 FILING、typed provenance=HKEXNEWS+DOWNLOAD、COMPLETE、nondeleted；`source_title` 必须为非空 str，无类型/无标题仅无年度证据，禁止 `str()` coercion。category 若为非空 str，必须满足同一个报告家族分类；缺 category 的历史 source 只准使用**标题自身明确的报告/业绩家族 token**，仍走同一 owner helper，不由 workflow 的 `meta.get(...) or title` 补偿。不能从 source_id/company 名字猜同公司，不能读 processed、fiscal_year/period、filing date 作锚点。

远端 admissibility：只消费当前查询完整累计响应里经 stock code 匹配、raw 字段验证、source-ID 核心事实去重无冲突的公告；同一个 helper 验 title/category，明确年度且唯一合法截止日。不得因标题含“年度董事会/分红”便提锚点；report/results 互冲突、非财报分类不作年度事实。主候选语言规则保持；官方 raw 英文副本可以作为日期证据（不生成主候选），本地同规则不因 source_language 排除年度依据。此处不增请求、不扩窗口、不历史爬取；stockId mapping/运输异常仍 provider owner。

合并：local + 本次 admissible remote 的 evidence 集合，不 remote 覆盖 local、不多数投票、不挑最新 filing、不选第一条；同截止日可保留多个引用，日期解析去重。每份目标报告按其 **report end date** 取距离 ≤366 天的证据。不同年结月份、任一相关非月末、目标非月末/非季度边界为不确定。无相关 evidence 时，长度型标题不产生季度；有明确季度+明确年份且没有相关冲突时保全现有直接披露规则。远年 evidence 既不能推导季度，也不应凭“tuple 非空”否决本来独立明确的季度（F5-N01 待裁决）。保留真实 title 内年份冲突/财年标签冲突和区间缩写的原 fail-closed 规则。

`fiscal_quarter_at` 保持规则，新增纯 `nearby_annual_end_dates(end: date, annual_ends: tuple[date,...]) -> tuple[date,...]` 给 fiscal_quarter_at/resolve 共用；中文 docstring 明确参数/返回/异常无。366 抽模块私有 Final，绝不用 filing 日期计算邻近。resolver 先确定 relevant dates，再把相关集合用于所有 calendar 分支；没有相关集合与相关冲突须分开，不能以年度全量非空判断 conflict。

同 source_id remote 核心 facts 冲突仍 `_deduplicate_hk_announcements` 原 ValueError（不伪造 fiscal error）；不同 source 的合法相矛盾年度截止日则归 calendar 不确定。remote/local 同来源事实差异不“选更可信”：若产生不同邻近月份，同样不确定；只在日期层发现的冲突不声称源文档损坏。

### 6.1 已发现却无法生成身份：请求级业务失败

selector 必须先完成所有 raw 的 family/period 判断，再调用 HEAD 构造 candidate：合格主语言、位于 query 披露日期窗口、财报家族可与请求 discovery_periods 相交，却 facts=None → 抛该错误。**未确定是哪一季度不能排除成“请求别的季度”**；只有家族本身明确不相交才排除。非财报/英文非主候选继续正常排除；空结果仍空 tuple。清楚含财报家族但 family 内冲突/日期非法同为不确定，不把它归 nonreport。没有任何财报家族事实的新闻不当不确定报告。family 判定从现有 category markers/tokens 抽成唯一模块级 helper，selection 和年度 helper 复用，不能另造宽松字符串 guess。

runtime 唯一 public projection `_download_public_failure_from_exception` 对 typed period error 返回既有 `FinsPublicFailureKind.EXECUTION`、source=HKEXNEWS、transport=None、reason=None，固定：

- safe_message：`已发现财报，但财期依据不足或冲突`
- retry_hint：`请补齐同公司明确年度截止日的完整来源后重试；若年度依据冲突，请先核对并纠正来源。`

这不是 provider transport、storage incomplete，也不是未知异常；direct error_kind 现有 EXECUTION 规则即可。direct unknown-diagnostic 分支按 typed error 排除，避免预期业务失败伪装内部崩溃；不改普通异常日志规则。job 在当前 typed-download catch 中增加该明确类型，`_save_typed_download_failure` 类型 union 同步，仅该新初始错误用现有 `_empty_download_summary_from_request(...FAILED)`，消息从同 public helper 来。既有 `FinsSourceDownloadAdapterFailure` integrity cause union、unwrap、部分摘要路径完全不扩大。

public request summary：`document_rows=()`、五个 counts 都 0、terminal FAILED、missing_periods=()；零值表示**尚无可绑定/处理的文档行**，不是“远端无财报”，财报存在与不确定由 failure 明确说明。现有 owner 已允许初始失败零行 override。若根要求结构化 raw discovered 数或逐条 uncertainty，则 P1 不能满足，转 Q1 的更大 schema proposal；作者不得假称 zero summary 完全解决所有机器可读语义。

取消：新增 view 前后复用 workflow checkpoint，provider 累计请求前后沿既有 checkpoint；命中取消后不再判 uncertainty。运行期 direct/job 原终态仲裁仍决定取消胜出与 summary 发布，不把取消归财期失败。真实 I/O、lock、取消检查普通异常保持原类型/cause；不得把任何异常都 catch 为 period error。

### 6.2 rebuild 的已知真实文档
