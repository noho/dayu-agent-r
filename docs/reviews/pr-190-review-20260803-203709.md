- **入口/函数**: `conversation_compaction_user.md` 是每次 compactor proposal 的 production user prompt template；Host strict parser 与 Context Governance 接受符合该 contract 的 candidate。
- **文件(行号)**: `AGENTS.md:43-49`；`dayu/config/prompts/scenes/conversation_compaction_user.md:31-60`；`dayu/host/compaction.py:157-163`；`tests/host/test_llm_compaction.py:329-374`；`tests/host/test_public_compact_smoke.py:268-319`。
- **输入场景**: fresh model 需要决定一段材料应进入 `session_summary`、`evidence_facts`、`answer_anchors`，或应以 `superseded` / `redundant` / `out_of_scope` / `policy_limit` 中哪一个原因显式丢弃。

- **预期行为**: `AGENTS.md:46` 要求结构化输出在当前 prompt 中自足说明字段名、含义、类型、必填性、允许值和最小示例。至少应为上述 section/field 增加简短业务含义，并分别定义四个 drop reason 的适用条件；无需改变 typed schema、Host accept owner 或增加 semantic verifier。
- **实际行为**: 当前 production parser 只校验 enum/value shape；Context Governance 不会为模型补全这些定义。结构合法但语义分类不一致的 candidate 可以通过并写入 compact artifact / Memory，特别是 drop reason 的 audit 语义无法由当前 prompt 唯一解释。

- **建议改法和验证点**: 由 packaged prompt owner 补齐最短必要语义说明；测试逐字段断言业务含义存在，并覆盖四个 drop reason 的自解释定义。保留现有完整同源示例和 strict Host barrier，不扩大 schema 或 owner boundary。
