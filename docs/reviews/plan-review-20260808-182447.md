## 3. Findings

### 01-未修复-[高]-run root 与 evidence publication path 未绑定 allocation，真实执行可写入 F18 或任意已有父目录

- **位置**：goal 第 15-16、34 行；plan 第 34-41、100 行；`f19_formal_driver.py` 第 58-60、240-351、510-533、557-590、674-691、788-835 行。
- **类型**：contract / state ownership / safety boundary。
- **语义 owner**：Controller 冻结的 F19 run/allocation contract 负责声明本次 formal run 的唯一根目录和每条 chain 的 workspace/evidence layout；driver 负责在任何持久化或 provider spawn 前验证该 contract。

#### 直接证据

goal 明确要求使用“全新 run root”且 F18 public/private tree immutable；plan 也要求双 PASS 后才创建新的 F19 run root，并使三个 workspace 从该 root 的 fresh seed 建立。然而当前实现中：

- `--run-root` 只在 `_harness_argv()` 中原样转发给 harness，没有进入 `_allocation()`、`_deadline()`、`_execution_identity()` 或 `main()` 的路径身份校验。
- allocation 仅验证 `workspace.name == chain_id` 和输入树 digest；同 basename 的 workspace 可以位于任意目录。
- `_validate_wrapper_output()` 只验证 output 是 `evidence_dir` 的同父 sibling、父目录已存在且非 symlink、两者尚不存在；它不验证二者位于当前 F19 run root，也不验证 chain/segment 的预定相对路径。
- `main()` 在上述弱校验后先 `_emit()` 写 projection，再调用 harness；因此错误路径不是只影响显示，而会成为真实 durable evidence 写入位置。

#### 可复现反例

在不创建任何文件、也不调用 provider 的只读反例中，选取既有 **F18 private evidence 父目录** 下两个尚不存在的 sibling 路径，直接调用当前 owner 函数 `_validate_wrapper_output()`。函数接受该组合；测试后候选路径仍不存在且 F18 tree hash 不变。由同一代码路径可知，real mode 若同时提供合法 allocation/deadline/state，就会先在该 F18 父目录写 wrapper projection，再把同一 `evidence_dir` 交给 harness。

这直接违反“F19 全新 run root”和“F18 immutable”，并证明 run/chain/workspace/label 的现有绑定不能推出 publication path identity。错误 setup 仍可越过 driver 的最终 pre-spawn gate，因此当前计划不能安全进入 formal provider 执行。

#### 必要修复

1. 由 allocation owner 冻结 path-redacted 的 F19 `run_root_id`（或等价稳定身份），以及每条 chain 的预期 workspace/evidence 相对 layout；不能只依赖 basename。
2. real mode 在 `_emit()` 与 spawn 前解析并验证：
   - run root 属于当前 allocation 的全新 F19 root，且不是 F18 root；
   - workspace 是该 root 下当前 allocated chain 的精确路径；
   - evidence dir 是该 root 下当前 chain/segment 的精确 private evidence 路径；
   - wrapper output 是该 attempt 的精确 sibling；
   - root、父目录及路径组件不通过 symlink 或 `..` 逃逸。
3. 增加 provider-free owner contract 测试：F18/outside parent、同 basename 错 root、wrong chain/segment、path traversal/symlink 均须在任何写入和 spawn 前失败；正确 F19 layout 才通过。
4. stdout-only preflight 可以继续不要求这些目录已创建，但 real mode 不能以 preflight 的弱路径语义替代 formal durable-path 绑定。
