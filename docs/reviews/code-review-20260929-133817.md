### 002-未修复-低-高代理名在路径规范化阶段透传 UnicodeEncodeError，控制名优先分类被绕过
- **入口/函数**: `plan_upload_assets` 的路径规范化（`dayu/fins/upload_asset_plan.py:256` → `normalize_upload_asset_path:109`）
- **文件(行号)**: `dayu/fins/upload_asset_plan.py:109`（`path.expanduser().resolve(strict=False)`）与 `:256`（整批 tuple 化发生在分类循环之前，无 try 包裹）；对照 F8 fix artifact「UTF-8 编码失败也走封闭非法名原因，不透传异常」的自述承诺

- **预期行为**: 按 F8 裁决与 fix artifact 承诺，UTF-8 不可编码名属 `INVALID_ASSET_NAME` 封闭拒绝（「UTF-8 编码失败也走封闭非法名原因」）；且按裁决优先级，`["META.JSON", 高代理名]` 应先报 `RESERVED_CONTROL_NAME`。

- **严重程度（低/中/高/严重）**: 低。

- **入口/函数**: `canonicalize_fins_public_file_label` 的隐藏判定（`dayu/fins/direct_events.py:1143-1170`）→ planner 错误标签（`upload_asset_plan.py:69`）→ usage/public failure 投影
- **文件(行号)**: `dayu/fins/direct_events.py:1158`（`unicodedata.category(character) in {"Cc","Cf"}` 未含 `Cs` 代理类）、`_validate_safe_text:1172-1210`（无代理拒绝）；`dayu/fins/upload_failure.py:544-566`（`_validate_failure_reason_text` 只拒 `ord < 32` 与分隔符，代理 `ord(0xDC80)>31` 通过）
- **输入场景**: basename 含低代理码位（如 `a\udc80b.txt`，非 UTF-8 卷上 surrogateescape 的真实形态，或 JSON `\udc80` 转义）；本 APFS 工作区不能创建真实 Errno 92 文件，纯规划/tool 输入可达。
- **实际分支**: 分类循环 `:284-289` 正确把 UTF-8 编码失败记为非法名并抛 typed `INVALID_ASSET_NAME`（fail closed 于分类层 ✓）；但 `:69` 的标签投影对低代理不隐藏（Cs 非 Cc/Cf、`_validate_safe_text` 放行），`file_label` 保留 lone surrogate。
- **预期行为**: label owner 契约自述「可安全公开的原始 basename，或固定的文件名隐藏标签」；含代理的字符串不可 UTF-8 编码，不属于「可安全公开」，应退为 `_HIDDEN_PUBLIC_FILE_LABEL`，使 usage message 与 public failure 的「可安全公开/可编码」承诺成立。
- **实际行为**: 探针 typed `invalid_asset_name` 携 `label='a\udc80b.txt'`；usage `message='文件名无法安全保存：a\udc80b.txt；…'` 在 `message.encode("utf-8")` 抛 `UnicodeEncodeError`；`fins_upload_failure_from_exception` 产出的 public failure 经 `json.dumps(..., ensure_ascii=False).encode("utf-8")` 同样崩溃（position 71）。任何以 UTF-8 编码该文案/标签的下游（事件持久化、日志、传输）都会在 closed 错误投影之后再炸一次。
- **直接证据**: 探针输出 `usage.message UTF-8 编码崩溃`/`to_json 后 ensure_ascii=False UTF-8 编码: 崩溃`；`direct_events.py:1158` 类别集合与 `_validate_failure_reason_text` 的 `ord < 32` 判定均放行代理；R2 测试只覆盖 Cc 控制字符与多字节长名，无 Cs 用例。
- **影响**: closed 合同被下游二次失败打断：分类层已 fail closed，但投影层携带不可编码文本，消费者（编码/序列化边界）由实现细节决定是否崩溃或显示 `\udc80` 转义；违反「可安全公开」标签承诺与 plan 验证矩阵的「路径安全/Unicode 边界」意图。
- **建议改法和验证点**: label owner 的隐藏规则显式纳入不可 UTF-8 编码/`Cs` 代理类（或以 `value.encode("utf-8")` 可编码性作为隐藏判据），保持 Cc/Cf 现行为；`_validate_failure_reason_text`/`validate_fins_public_file_label` 同源收紧防回归。验证点：低代理名单独 → typed `invalid_asset_name` + 隐藏标签 + 文案 UTF-8 可编码；两目录同名低代理 → hidden label 的 `DUPLICATE_ORIGINAL_BASENAME`；与 META.JSON 混批两序同 reason。
- **修复风险（低/中/高）**: 低（隐藏判据扩展 + owner 测试；标签对普通名零变化）。
- **严重程度（低/中/高/严重）**: 低。
