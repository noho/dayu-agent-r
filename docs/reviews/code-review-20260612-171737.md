## 补充观察

### 集成测试中的 inline assertions 与 helper 的关系

`test_post_compaction_fact_reuse_uses_raw_accepted_tool_evidence` 在调用 `_assert_label_only_fake_proposal` 后仍保留了对 material JSON 的直接 assertions（`"result_preview" not in material_text`、`"payload:" not in material_text`、`"event-tool-result" not in material_text`）。这些 assertions 检查的是 **material JSON** 层面的泄漏，与 helper 检查的 **proposal JSON** 层面是不同边界，不构成冗余。设计合理。

### `_valid_compactor_material_json` 对旧 `_llm_material_with_long_tool_evidence` 的替换

旧 `_llm_material_with_long_tool_evidence` 构造的 material JSON 缺少 `schema_version`、`answer_material` 和 `instruction` 字段，且 `previous_compacted_view` 为 `[]` 而非 `None`。新 `_valid_compactor_material_json` 补齐了这些字段，使 helper 自测 fixture 与真实 compactor material shape 一致。这是正确的改进。

### `_assert_label_only_fake_proposal` negative test 覆盖度

当前 negative test 只覆盖 canonical ref 泄漏（`payload:event-tool-result-accepted`）。marker 缺失的 negative case 未单独覆盖，但由 positive test 间接验证。这是一个 low-severity 的覆盖度观察，不阻塞 PASS 结论。
