## AGG-02 裁决复验：callable transport 到 canonical token 的 fail-closed 收窄

### Controller 裁决

AGG-02 被裁决为 **rejected as duplicate of S2 R1**：`CnPipeline.download_stream` 的 `cancel_checker` 参数类型为 `Callable[[], bool] | None`，而 converter 边界要求 `CancellationToken`——这是 accepted plan §11.1 已冻结的显式 trade-off。生产路径始终运输同时满足两种 contract 的 composite concrete object；`_canonical_cancellation` 对纯 callable fail-closed。

### 直接证据链（逐行代码验证）

**证据 1 — `_canonical_cancellation` 是 fail-closed 的**:
- `cn_download_filing_workflow.py:889-908` — 完整实现
  - `cancel_checker is None` → 返回 `None`（无取消源）
  - `not isinstance(cancel_checker, CancellationToken)` → `TypeError("cancel_checker 必须实现 canonical CancellationToken")`
  - 否则返回原对象 identity（不创建 wrapper/adapter）
- 只有 **一个 caller**：`cn_download_filing_workflow.py:311` — `cancellation=_canonical_cancellation(cancel_checker)`

**证据 2 — 生产路径始终运输 composite concrete object**:
- `FinsJobCancellationChecker` 同时继承 `CancellationToken` 和声明 `__call__`（`ingestion_runtime.py:904-920`）
- `_DirectCancellationChecker`（`:1570`）和 `_RuntimeJobCancellationChecker` 都实现 callable + `is_cancelled` + `cancel_reason` + `requested_at`
- Runtime 构造 `FinsSourceDownloadAdapterRequest` 时直接赋值 `context.cancellation_checker`（no-op confirmation §4.2 验证为唯一构造点）
- CN/HK adapter 将 `request.cancellation_checker` 原样传给 `CnPipeline.download_stream`

**证据 3 — 类型缺口是 accepted plan §11.1 已冻结的显式 trade-off**:
- Plan §11.1 行 507-509: _"adapter request 中现有 `FinsJobCancellationChecker` concrete object 同时实现 `CancellationToken`；download workflow 的普通 checkpoint 可继续调用其 `__call__`，传给 shared converter 时原样作为 canonical token，不创建 adapter。"_
- S2 adjudication R1 行 23-29: 已基于 SEC/CN/HK 共享 request、依赖方向与 Python 静态契约冲突拒绝该 finding
- 修复后双路 re-review 均通过，S2 gate accepted

**证据 4 — 不存在绕过路径**:
- `download_stream` 参数类型为 `Callable[[], bool] | None`（`cn_pipeline.py:628`），但所有 production caller 均传入 composite object
- Standalone 纯 callable 在 `_canonical_cancellation` 处被 `TypeError` 拒绝——这是 fail-closed，不是静默错误

### 复验结论

**裁决正确。** AGG-02 不是新 defect。类型签名与运行时 contract 之间的缺口是 accepted plan §11.1 与 S2 adjudication R1 已冻结的显式 trade-off。Python 类型系统无交集类型；把共享字段标成 `CancellationToken` 会丢失 SEC 所需的 callable 静态契约；标成 ingestion-owned composite protocol 会造成 pipeline 对上层 owner 的反向依赖。当前 fail-closed 实现与冻结设计一致。
