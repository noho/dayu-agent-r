### 2-未修复-低-finally 块 flush 异常可遮蔽 yield 原始异常类型

- **入口/函数**: `_isolated_inherited_stderr` context manager
- **文件(行号)**: `dayu/fins/pipelines/docling_process_converter.py` (62–88)
- **输入场景**: `yield` 块内抛出 `DoclingRuntimeInitializationError`（或其它非 OSError 异常），随后 `stderr_stream.flush()` 在 finally 块中也抛出 `OSError`（如 broken pipe）。
- **实际分支**: Python 异常链规则：finally 块中抛出的新异常成为 active exception，原始异常变为新异常的 `__context__`。外层 `except Exception` 捕获 `OSError`（flush failure），返回 `CONVERTER_EXECUTION` descriptor。
- **预期行为**: 原始 `DoclingRuntimeInitializationError` 应映射为 `CONVERTER_CONSTRUCTION` descriptor（由 `__call__` 中第一个 `except` 分支处理）。
- **实际行为**: flush `OSError` 遮蔽原始异常，`__call__` 走第二个 `except Exception` 返回 `CONVERTER_EXECUTION`。failure kind 从 `CONVERTER_CONSTRUCTION` 变为 `CONVERTER_EXECUTION`。
- **直接证据**: `docling_process_converter.py:83-86` — `finally: try: stderr_stream.flush() finally: os.dup2(inherited_stderr_copy, stderr_file_descriptor)`。flush 异常在 dup2 之前成为 active exception。`__call__` 的 `except DoclingRuntimeInitializationError` 不再匹配。
- **影响**: 仅在 stderr flush 也失败（broken pipe 等极端情况）时触发。failure kind 变化对用户可见行为无影响（均为 exit 1 + typed content reason），但 kind 语义不精确。原始异常保留于 `__context__` 链中，operator log 可观察根因。
- **建议改法和验证点**: 可在 finally 块中用 `try: stderr_stream.flush() except Exception: pass` 静默 flush 失败，优先保留 yield 原始异常。但当前行为在实际场景中极罕见且 operator 链完整，不阻塞。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
