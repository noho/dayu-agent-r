## Open Questions

1. **config_loader.py `_overlay_roots` 覆盖语义**: workspace 对 `default_execution_profile_id` 等标量字段是全量替换而非 patch。README 已说明不做 deep merge，但用户可能预期 partial overlay。这是设计决策还是需要补充文档？

2. **assembly.py `_select_value` 的 None 语义**: `None` 表示"层未提供"，对 `bool` 字段无法区分"未提供"和"显式传 None"。当前所有层都使用 `bool | None` 且 `None` = skip，但如果未来某层需要显式清空值，模式会破裂。

3. **lane.py `_await_task_after_outer_cancellation` 无超时**: `asyncio.sleep(0.01)` 轮询等待 shielded task 完成，如果底层线程永久阻塞（如 SQLite lock），此循环无生产超时。是否有上层超时保护？

## Residual Risk

1. **配置交叉引用测试缺口**: 无显式测试验证 `execution_profiles.json` 的 `model_id` 引用在 `models.json` 中存在，也无测试验证 scene manifest 的 `default_model_id` 引用有效性。当前由 assembly tests 间接覆盖，但如果配置被手动编辑且 assembly tests 未运行，孤立的配置错误不会被捕获。

2. **`tool_discovery.json` disabled provider 路径**: `financial-tools` provider 设置为 `enabled: false`，无专门测试验证 disabled provider 被正确排除。

3. **`config_loader.py` 的 `_require_exact_fields` 模式**: 添加新的可选字段到任何配置文件时，必须同步更新 `allowed` frozenset，否则会 fail-fast。这是正确的 fail-closed 行为，但需要跨 JSON 和 parser 代码协调。

4. **`lane.py` 单连接模式**: 每次 claim/release/refresh 打开新的 `sqlite3.connect()`。在高并发场景下 `BEGIN IMMEDIATE` + 单写者模式可能导致 `SQLITE_BUSY`；`poll_interval_seconds` 重试循环缓解但增加延迟。

5. **`_PublicHostHandle._closed` watch loop 竞态**: 在单线程 asyncio 下影响极小（最多多 yield 一个 batch 的 stale events），但如果未来引入多线程 host 需要注意。

## Conclusion

3. **LaneController 分支交织**（Finding 3）— 结构性重构可提高认知可读性

其余 Finding 4-6 和 Open Questions 均为低严重程度，可作为后续改进项。
