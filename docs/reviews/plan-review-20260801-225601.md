## 2. Findings

### 1-未修复-[低]-30-file union 声明缺少完整文件枚举

- **位置**: proposal §2.3、plan §9.1 builder inventory table
- **问题类型**: 可实施性
- **当前写法**: proposal 列出 8-file builder inventory table，声明 30-file total mechanical union = 25 + 5 delta，但未给出完整 30-file 清单
- **反例/失败场景**: implementation agent 需要在 §10.5 validation 中重跑 30-file inventory；若 agent 只参考 proposal 而不交叉比对 plan §9.1 的 25-file identity/typed-return table 与本次 5-file delta，可能遗漏文件
- **为什么有问题**: 两个独立 inventory（25-file identity closure 与 8-file builder closure）分散在 plan 不同位置，proposal 未做完整 union 列表，implementation agent 需要自行合并
- **直接证据**: proposal §2.3 只列 8-file builder table；plan §9.1 有 25-file identity table；两表分别在不同 section
- **影响**: implementation agent 若只看 proposal 的 8-file table 可能遗漏 25-file 中的非 builder 文件
- **建议改法和验证点**: 可在 proposal §2.3 或 plan §13 checklist 中增加一个完整的 30-file union 列表作为 implementation agent 的 single source of truth；或者在 §10.5 validation 中明确"25-file identity closure 由 plan §9.1 第一 amendment table 为准，5-file delta 由本次 proposal §2.3 table 为准，union 为两者去重"
- **修复风险（低/中/高）**: 低
- **严重程度（低）**: 低 — §10.5 已要求 implementation 前后重跑 `rg` inventory，且 plan §9.1 有完整 25-file table

### 2-未修复-[低]-file-local factory 语义一致性依赖实现纪律

- **位置**: proposal §3.2、plan §9.1 factory rules、§10.5 validation
- **问题类型**: 测试缺口
- **当前写法**: "identity 必须与同一 event 的 sibling run/operation/attempt/manifest 语义一致" 是编码规则；§10.5 要求 focused tests "断言 identity 与 sibling run/operation/attempt/manifest 一致"
- **反例/失败场景**: implementation agent 可能构造一个 deterministic、typed 的 identity，但其 `run_id` 与 test 的 `compactor_engine_run_id` 不一致，或 `provider` 与 test 的 `runner_spec.provider` 不匹配；如果测试只检查 identity 存在性而不检查字段值与 sibling 的一致性，该 bug 不会被发现
- **为什么有问题**: factory 一致性是 semantic constraint，不是 mechanical constraint；需要 implementation agent 理解 sibling 语义并编写对应的值断言
- **直接证据**: proposal §3.2 "identity 必须与同一 event 的 sibling run/operation/attempt/manifest 语义一致"；§10.5 "断言 identity 与 sibling run/operation/attempt/manifest 一致"
- **影响**: 测试可能通过但 identity 与 sibling 不一致，导致 accepted/rejected event 的 response identity 与 operation/attempt/manifest 失去同源绑定
- **建议改法和验证点**: §10.5 validation 可增加一个具体示例：对 `test_compact_material.py` 的 CB(1) 调用，factory 应从该测试已有的 `operation_id`、`compactor_engine_run_id`、`attempt_number` 构造 identity，并断言 `identity.runner_request_identity.run_id == fixture.compactor_engine_run_id`；此类示例帮助 implementation agent 理解"一致"的具体含义
- **修复风险（低/中/高）**: 低
- **严重程度（低）**: 低 — §10.5 已要求 assertion，且 file-local factory 的 label-based construction 从机制上倾向一致性；风险是 assertion 质量，不是架构缺陷
