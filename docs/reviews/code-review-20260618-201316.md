### 逐项验证

#### Finding A: current_input_ref 诊断顺序

**Production code change** (`context_fallback.py:373-378`):

Before（不可达 None 检查）:
```
window_current_ref = _optional_text(window, _FIELD_CURRENT_INPUT_REF)
if window_current_ref != current_input_ref:          # None != "ref" → mismatch
    raise HostDurableError("...mismatch")
actual_current_input_ref = window_current_ref
if actual_current_input_ref is None:                  # 不可达
    raise HostDurableError("...missing")
```

After（正确诊断顺序）:
```
window_current_ref = _optional_text(window, _FIELD_CURRENT_INPUT_REF)
if window_current_ref is None:                        # 先检查缺失
    raise HostDurableError("...missing")
if window_current_ref != current_input_ref:           # 再检查不匹配
    raise HostDurableError("...mismatch")
actual_current_input_ref = window_current_ref
```

- **正确性**: `None` 检查移到 `!=` 比较之前，消除了不可达代码，改善了诊断精度。Fail closed 行为不变。
- **类型安全**: `window_current_ref` 类型为 `str | None`；`is None` guard 后 `!=` 比较两侧均为 `str`，pyright clean。
- **测试覆盖**: `test_eventlog_context_fallback_provider_fail_closes_on_payload_drift` 新增 `missing_current_ref` parametrize case。Fixture `_context_fallback_failed_payload` 在 `case_name == "missing_current_ref"` 时 `del window["current_input_ref"]` 并重新计算 digest，确保 digest 校验通过后命中 missing 分支。断言 `pytest.raises(HostDurableError, match="fallback current_input_ref is missing")`。
- **诊断顺序完整性**: 测试 parametrize 顺序 `(missing_window, digest_mismatch, missing_current_ref, current_ref_mismatch, ...)` 与 production code 检查顺序一致，隐式验证了分支优先级。
- **AGENTS.md 合规**: 不涉及架构变更、公共契约变更或新增兼容逻辑。✅

   - **Trace**: `_fallback_caps_allow_append(selected_blocks=(current,new), candidate=mid, policy)` → `len(2)+1=3 > 2` → `False` → blocked ✅

2. **`test_recent_window_fallback_char_cap_rejects_append`**:
   - Setup: `item_cap=8`, `char_cap=10`, 3 trace blocks + 1 current anchor, `turn_floor=1`

3. **`test_recent_window_fallback_without_memory_policy_allows_uncapped_append`**:
