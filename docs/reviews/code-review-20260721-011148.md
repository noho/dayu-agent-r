### DS-F03 关闭验证

`test_thinking_renderer_suppresses_records_after_close`（第 121–142 行）直接证明 `CliThinkingRenderer.close()` 的 owner contract：关闭后 `record()` 不再向 stderr 输出。

**排除掩盖分支的证据：**

1. **Dedupe 分支不能掩盖**：close 前使用 `dedupe_key="thinking-1"`，close 后使用 `dedupe_key="thinking-2"`。`_seen_dedupe_keys` 不包含 `"thinking-2"`，因此 dedupe 过滤（thinking.py 第 97–98 行）不会拒绝该 record。若 `close()` 失效，此 record 将通过 dedupe 检查。

2. **倒序/序列过滤不能掩盖**：close 前 `runtime_sequence=1`，close 后 `runtime_sequence=2`。序列检查（thinking.py 第 102–103 行）要求 `runtime_sequence <= last_runtime_sequence` 才过滤；`2 <= 1` 为 false，因此序列过滤不会拒绝该 record。若 `close()` 失效，此 record 将通过序列检查。

3. **Disabled 分支不能掩盖**：renderer 以 `enabled=True` 构造（第 127–128 行），disabled 检查（thinking.py 第 95 行 `not self._enabled`）为 false。若 `close()` 失效，此 record 将通过 enabled 检查。

**close 生产代码前置性**：`record()` 方法（thinking.py 第 95 行）在所有其它检查前首先判断 `self._closed`，确保 close 后任何 record 无条件短路返回。测试直接断言此行为。
