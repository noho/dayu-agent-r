## Review Method

Traced the full production path end-to-end:

1. **Construction validation** — `_OpenHostContextManager.__aenter__` → `_validate_wait_poller_configuration` → `_enabled_wait_poller_configuration`
2. **Supervisor wiring** — `_wait_poller_supervisor_from_open_host_options` → `_OpenHostWaitPollerFactory` → `WaitPollerSupervisor(poller_factory=..., policy=..., owner_id=...)`
3. **Per-round poller creation** — `_OpenHostWaitPollerFactory.create_wait_poller()` → `open_host_durable_store()` (thread-local) → `HostCommandHandle` → `WaitPoller` → `_ClosingWaitPoller`
4. **Resolve path** — `_CommandHandleWaitResolver.resolve_wait()` → `_resolve_wait(command_handle, ...)` → admission → durable write → after-commit → `_ThreadsafeSchedulerWakeupPort.wake_dispatch()` → `call_soon_threadsafe` + `Future.result()`
5. **Normal close** — `_PublicHostHandle.close()` → poller close (`asyncio.to_thread`) → scheduler close → projection catch-up → command handle close
6. **Open failure cleanup** — `except Exception` → poller close → scheduler close → projection catch-up → durable store close
7. **Thread-safety boundary** — `_is_current_event_loop`, `call_soon_threadsafe`, `Future.result()` blocking bridge

Adversarial pass: deadlock analysis of `_ThreadsafeSchedulerWakeupPort`, close error prioritization, per-round connection lifecycle, shared `active_registry` cross-thread access, `enabled` field contract, double-close interaction with poller.
