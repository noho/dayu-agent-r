## Findings

### 001-未修复-低-form_type 参数接收 fiscal_period 值导致语义混淆

- **入口/函数**: `ingestion_runtime._validate_fins_upload_filing_static` (line 1335)
- **文件(行号)**: `ingestion_runtime.py:1335-1341`, `docling_upload_service.py:1917-1951`
- **输入场景**: 所有 CN/HK filing upload 调用
- **实际分支**: `normalized_ticker.market != "US"` 分支，调用 `build_cn_filing_ids`
- **预期行为**: `form_type` 参数应接收 filing form type（如 "10-K"、"20-F"），`fiscal_period` 接收财期
- **实际行为**: `form_type=normalized_period` 将 FiscalPeriod 值（"FY"/"Q1" 等）同时传给 `form_type` 和 `fiscal_period` 两个参数
- **直接证据**: `ingestion_runtime.py:1337`: `form_type=normalized_period`；`cn_pipeline.py:817`: `form_type = normalized_period`；`cn_download_filing_workflow.py:166`: `form_type=candidate.period_projection.identity_period`
- **影响**: 参数名 `form_type` 具有误导性；当前所有调用方一致传入相同值，seed 计算稳定，不影响 ID 正确性。但若未来有人按参数名语义传入真正 form type，将改变所有 CN document ID
- **建议改法和验证点**: 这是 pre-existing design issue，非本 slice 引入。S2 或后续可考虑将 `build_cn_filing_ids` 的 `form_type` 参数重命名为 `identity_key` 或直接移除（因为所有调用方已证明 `form_type == fiscal_period`）。验证点：grep 所有调用方确认 `form_type` 和 `fiscal_period` 始终相同
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

### 002-未修复-低-AssertionError type narrowing 为不可达代码

- **入口/函数**: `ingestion_runtime._validate_fins_upload_filing_static` (line 1286)
- **文件(行号)**: `ingestion_runtime.py:1286-1287`
- **输入场景**: 任何通过 line 1274 非空检查的 fiscal_period
- **实际分支**: `normalize_fiscal_period` 返回 `None` 时抛出 AssertionError
- **预期行为**: 在 line 1274 已确认 `request.fiscal_period` 非空非纯空白后，`normalize_fiscal_period` 的 `strip().upper()` 结果必为非空，必落入 `FISCAL_PERIODS` 检查或 `ValueError`，不会返回 `None`
- **实际行为**: `if normalized_period is None: raise AssertionError(...)` 是不可达的防御代码
- **直接证据**: `filing_semantics.py:307-313`: `normalize_fiscal_period` 对非 None 输入执行 `strip().upper()`，空结果返回 `None`，非空但不在 `FISCAL_PERIODS` 中则抛 `ValueError`。line 1274 已过滤空/纯空白输入
- **影响**: 无运行时影响。类型检查器可能因 `Optional[FiscalPeriod]` 返回类型要求下游处理 None，但运行时永远不会到达
- **建议改法和验证点**: 可接受为防御性编程。若要消除，可让 `normalize_fiscal_period` 在已知非空场景下提供一个 `parse_fiscal_period` 变体返回 `FiscalPeriod`（非 Optional）
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

## Residual Risk

1. **`cn_form_utils.build_cn_filing_ids`（download path）未修改**: 下载路径存在独立的 `build_cn_filing_ids`（`cn_form_utils.py:155`），签名仍为 `form_type: str, fiscal_period: str`。本次修改只覆盖 upload path 的 `docling_upload_service.build_cn_filing_ids`。两个函数逻辑相同但类型签名不同，长期可能 drift。属于 accepted plan §11 残余风险范畴。
2. **无 CLI 端到端 entry/exit 测试**: S1 未包含 CLI entry → usage error → exit 2 的端到端证明。S2 计划覆盖。
3. **`FiscalPeriod` 为 `TypeAlias` 而非 `NewType`**: 类型检查器无法在调用方阻止非法字符串字面量传入 `FiscalPeriod` 参数。运行时依赖 `normalize_fiscal_period` 做验证。当前架构下可接受。
4. **HK ticker 归一化未独立测试**: 测试 parametrize 使用 `"0700.HK"` 但未断言 `NormalizedTicker.market == "HK"`。若 ticker normalization 对 `.HK` 后缀的处理变化，测试可能静默覆盖错误 market。风险低，因 ticker normalization 有独立 contract。
