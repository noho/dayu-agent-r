## Findings

### 1-FINDING-PASS-两个 test caller 精确且无遗漏

- **位置**: Plan diff S3 Allowed tests 新增两行 + 授权文本
- **问题类型**: 范围确认（非缺陷）
- **直接证据**:
  - 全测试 callsite scan 显示仅有 `test_projection_read_model.py:142,145` 与 `test_public_host_admin.py:211,214` 直接构造 `HostCommandHandle` / `create_host_admission_service` 且不在 S3 allowlist。
  - 所有其他 `create_host_admission_service` direct caller（`test_resolve_wait_command.py`、`test_wait_callback.py`、`test_wait_cancel_late_result.py`、`test_wait_expiry_closeout.py`、`test_admission_queue.py`、`test_admission_multiprocess.py`）已在 S3 allowlist。
  - 所有 `HostDispatchScheduler.open` caller 已在 S3 allowlist。
  - `test_command_handle.py` 使用 `create_host_command_handle` standalone factory（自动注入 private port），不需要直接 port 传播，也不在漏列范围内。
- **结论**: 两个新增 caller 精确标识了仅有的 scope 缺口。不存在第三个需要授权的漏列文件。

### 2-FINDING-PASS-composition owner 正确

- **位置**: Plan amendment 授权文本 "各自现有direct test composition root"
- **问题类型**: 架构边界确认（非缺陷）
- **直接证据**:
  - `test_projection_read_model.py:141-154` 绕过 `create_host_command_handle` standalone factory，直接 `open_host_durable_store(...)` + `HostCommandHandle(admission_service=create_host_admission_service(...))`。
  - `test_public_host_admin.py:207-219` 同样绕过 factory，直接 `open_host_durable_store(...)` + `HostCommandHandle(admission_service=create_host_admission_service(...))`。
  - 两者是 direct composition root —— 它们承担了 `create_host_command_handle` 的装配职责，因此也必须承担 terminal port 注入职责。
  - Plan item 9 明确规定 "production constructors显式获得同一opener terminal port"；测试 direct composition root 必须遵循同一 contract。
  - Amendment 正确将 owner 判定为 test composition root，而非 production constructor 或 downstream consumer。
- **结论**: Composition owner 判定正确，与 plan item 9/10 的 fail-fast contract 一致。
