## Open Questions

1. **共享函数对空字符串 action 的语义**：plan §26 定 "None/空动作按既有 pipeline auto 语义处理"。workflow 侧 `str(action or "").strip().lower() or None` 确为空→auto，但 runtime `_normalize_upload_action("")` 抛 "upload_action 不能为空"、tool `_required_upload_action("")` 抛 "action must be..."。实际调用中 CLI（argparse choices/default）与 tool（先拒空）都不会把空串送到共享函数，runtime 则在共享函数之前先拒——因此是既有差异、本 plan 不放大。建议 plan 一句话钉死"空串在共享函数内等价 auto 仅供 workflow 入口；其余入口的空串由各自 action 校验先拒"，避免实现者误用 `_normalize_upload_action`（其空串行为与 §26 矛盾）。
2. **`_validated_upload_files` 的 "缺 files → for_delete()" 语义残留**（fins.py:1137-1138）：plan 保留该函数不动；组合校验前置后其错误分支仅剩合法 delete 无文件（for_delete 语义恰好正确）与合法 upsert 有文件（from_upsert_paths），错误分支成为不可达。是否按"禁止兼容性代码/默认全新设计"顺手把该函数收敛为"仅解析路径 + 格式校验"，由裁决者定；不改也不影响正确性。
3. **workflow/façade docstring 与 Raises 契约文字**：`run_upload_material_stream`、`CnPipeline.upload_material_stream`（cn_pipeline.py 在允许清单内）、`SecPipeline.upload_material*`（sec_pipeline.py 不在允许清单）的 Raises 段需要补 typed usage；若裁决要求 sec_pipeline.py 文字更新，须按 §31 扩权。
4. **真实 CLI run-id 与 workspace/tmp 命名**：plan §56 用 `workspace/tmp/um-o16-cli-<run-id>/`；`<run-id>` 未定义格式（建议 timestamp+case id）。小项，实施时定即可。

## Residual Risks（及建议追踪去向）

1. **O14/O15 target-missing 与组合校验顺序的正式协调**：本切片把组合校验放在一切目标状态读取之前，结构上满足"非法组合不被缺目标遮蔽"；但 material 的 create-on-existing（docling_upload_service.py:462 仅 filing 抛 FileExistsError）与 update-missing（464-465 抛 FileNotFoundError→storage_io）语义仍属 O14/O15。→ 追踪去向：UM-O14/O15 work unit 的 goal/plan。
2. **`fins_upload_failure_from_exception` 不识别 `FinsUploadUsageError`**：typed usage 若在 workflow try 内被抛出（如 Finding 2 的 prepare_upload 判定触发），会被归为 unexpected_runtime。本 plan 靠"组合校验移出 try"规避，但分类器缺口仍在。→ 追踪去向：可并入 Finding 2 的裁定，或后续 upload failure 分类收敛 issue。
3. **独立 pipeline 调用方的 typed 抛出契约**：`SecPipeline/CnPipeline.upload_material(_stream)` 从"业务失败进 result/事件"变为"非法组合抛 typed 异常"；除 service_runtime（经 admission 不会触发）外若有未知外部调用方，将首次见到该异常。→ 追踪去向：deepreview gate 核对 façade docstring 与 README 表述。
4. **单文件覆盖率对巨型文件的可达性**：`ingestion_runtime.py`（9144 行）与 `cn_pipeline.py`（2048 行）的 ≥80% 依赖既有测试面（test_fins_ingestion_runtime.py 12139 行等）；若全量跑仍 <80%，plan §54 的"如实记录、仅为本切片补测"与 AGENTS.md "单文件 ≥80%" 存在张力。→ 追踪去向：implementation gate 的 coverage 报告与裁决记录。
5. **真实 CLI 补跑成本与前置状态串扰**：12+ 个 case 各自全树 SHA + durable 查询；plan 已要求"每个 case 单独 --base、前一 case 的 delete 不改变后一 case 前置"，实施时若复用 workspace 会污染 fresh/existing 前置。→ 追踪去向：implementation gate 的 CLI evidence 验收清单。
