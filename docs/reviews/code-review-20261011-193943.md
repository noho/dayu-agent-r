## Findings

### F-001: 重复 HTML 属性取后值，可能静默漏下真实图片

- 状态：已修复。S1 code-fix re-review 已在 downloader extractor owner 独立复现 HTML 同名属性首值语义。
- 真实入口：`dayu-cli download` -> `SecPipeline._download_single_filing_stream` -> `SecDownloader.list_filing_image_files` -> `_HtmlImageExtractor.handle_starttag`。
- Trigger / 输入：已接受 HTML 中同一标签重复属性，例如 `<img src="first.jpg" src="second.jpg">`，或 `<base href="same/" href="https://outside.invalid/"><img src="plot.jpg">`。
- 分支：`_HtmlImageExtractor.handle_starttag` 先把 `attrs` 转成 `dict(attrs)`，随后只读取该字典中的 `src`、`srcset`、`href`。
- 预期行为：按 HTML 属性语义处理重复属性（首个同名属性生效，或对重复属性明确 typed fail），依赖发现不得被后一个属性替换；首个 `base[href]` 必须保持全文基准，且最终图片集合必须对应浏览器实际引用。
- 实际行为：Python `HTMLParser` 会保留重复属性列表，但 `dict(attrs)` 保留最后一个值。直接探针得到 `{'sources': ['second.jpg'], 'base_href': None}`；第二个输入得到 `base_href='https://outside.invalid/'`，即后一个 `href` 覆盖前一个 `same/`。
- 直接证据：`dayu/fins/downloaders/sec_downloader.py:249-257`；探针还确认标准库返回 `[('src','first.jpg'), ('src','second.jpg')]`，生产 helper 只见 `second.jpg`。`tests/fins/test_sec_html_image_assets.py:110-129`、`:148-170` 未覆盖重复属性。
- 影响：真实 `src`/`srcset` 可能被漏掉而 publication 被标为完整；重复 `base` 还可能把相对图片解析到错误 origin/路径，造成漏图、错图或无必要失败。该问题发生在 fingerprint、files[]、manifest 和 upsert 之前，属于完整集合真源错误，不是展示层问题。
- 可执行修法/验证：在 extractor 的 attribute owner 中按 HTML 规则保留每个属性名的首个值，或对重复属性整体 typed fail；补 owner 测试覆盖重复 `src`、`srcset`、`base href`、大小写属性名，并断言完整 canonical URL 集合、首个 base、零错误请求及最终仓储文件集合。
- 修复风险：低到中；需明确重复属性的产品语义，不能用“收集所有重复值”替代 HTML 首值规则，也不能只在测试中修正。
- Severity: `High / P1`。

### F-002: 百分号编码文件名被过度拒绝，合法 `%25` 资产无法补齐

- 状态：已修复。S1 code-fix re-review 已独立复现合法 `%25` 文件名及危险二次编码拒绝边界。
- 真实入口：同 F-001 的图片发现链路；相对/绝对候选最终进入 `_canonical_image_reference`。
- Trigger / 输入：同申报图片 URL 的 path 为合法单次百分号编码文件名，例如 `.../plot%25.jpg`，对应仓储业务名 `plot%.jpg`；或 base 指向同类合法编码文件名。
- 分支：`_validate_image_address_text` 对 path 做一次 UTF-8 `unquote` 后执行 `if "%" in decoded`，只要解码结果含 `%` 就抛 `ValueError`。
- 预期行为：计划的 URL/name 契约明确支持合法 encoded basename；应只拒绝非法 triplet、编码分隔符、编码点段、控制字符和会形成二次路径歧义的编码，不得把 `%25` 解出的普通字面 `%` 一律视为危险。
- 实际行为：直接探针中 `plot.jpg` 返回 `('plot.jpg', canonical URL)`，但 `plot%25.jpg` 抛 `ValueError: 图片引用地址或文件名不安全`；`plot%20name.jpg` 可正常返回。代码证据为 `dayu/fins/downloaders/sec_downloader.py:397-399`，测试只覆盖 `%2520` 为不安全（`tests/fins/test_sec_html_image_assets.py:182-188`），没有合法 `%25` 正例。
- 影响：实际 SEC HTML 若引用带 `%` 的单组件图片名，会在 begin 前把必要图片判为发现失败，旧 publication 保留但普通补齐永远不能完成；新 publication 也不能建立。
- 可执行修法/验证：把“解码后含 `%`”改成区分字面 `%` 与二次编码路径的安全规则；保留 `%25` 正例，继续拒绝 `%252f`、`%252e`、非法 `%GG`、编码分隔/点段和控制字符；增加 downloader owner 测试并验证 canonical URL、name collision 和完整 fingerprint。
- 修复风险：中；需要精确维护“单次 UTF-8 解码、无二次路径解释”的安全边界，不能简单放开所有 `%`。
- Severity: `Medium / P2`。

### F-003: 基础 descriptor 的非法文件名绕过 typed discovery error

- 状态：已修复。S1 code-fix re-review 已确认非法基础 descriptor 在 downloader owner 投影 typed 安全失败。
- 真实入口：`run_download_single_filing_stream` -> `SecDownloader.list_filing_image_files` 的 `existing_files` 前置校验。
- Trigger / 输入：基础 `RemoteFileDescriptor.name` 不是仓储原样单组件，例如 `../bad.htm`、带路径分隔符或非原样 Unicode 名；该 descriptor 可以来自外部 provider/index 的文件名，生产调用会把它作为 `existing_files` 传入。
- 分支：`list_filing_image_files` 在 `dayu/fins/downloaders/sec_downloader.py:1886-1895` 直接调用 `source_asset_name_collision_key`，该校验异常没有转换为 `SecHtmlImageDependencyError`。
- 预期行为：发现 owner 对基础/图片资产使用同一 storage identity contract；非法基础名应产生封闭的 `SecHtmlImageDependencyError` 和安全诊断，并在 begin 前终止，保持旧 publication。
- 实际行为：直接探针传入 `RemoteFileDescriptor('../bad.htm', ...)` 得到裸 `ValueError: filename 不能包含路径分隔符`。workflow 只捕获 `SecHtmlImageDependencyError` 与取消（`dayu/fins/pipelines/sec_download_filing_workflow.py:468-496`），因此该异常会越过 filing failure 投影；测试没有坏 `existing_files` 名称用例。
- 影响：协议/索引边界输入会绕过 typed failure 和 operator diagnostics，导致整条下载链路异常退出而不是可诊断的 filing failure；虽然发生在 batch 前、未发现半提交，但破坏了失败语义和可恢复性。
- 可执行修法/验证：在基础 descriptor identity owner 的异常边界统一投影为 `SecHtmlImageDependencyError`（安全 reason_code/message），补非法基础名、控制名和 collision 测试，断言零 begin/source mutation、保留旧 publication、CLI 诊断为 typed discovery failure。
- 修复风险：低到中；不要在 workflow 加 `except ValueError` 兜底，应修 downloader/name owner 的异常契约。
- Severity: `Medium / P2`。
