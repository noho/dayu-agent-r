### 001-未修复-中-fresh 边界未收敛 `RuntimeFileLockError`/`RuntimeError`，async job 落 generic `str(exc)`

- **入口/函数**: `_resolve_fresh_filing_request()`（`sec_upload_workflow.py:66`、`cn_pipeline.py:140`）→ `FinsIngestionRuntime._run_upload_job()`（`ingestion_runtime.py:4911`）
- **文件(行号)**: `dayu/fins/pipelines/sec_upload_workflow.py:94-104`、`dayu/fins/pipelines/cn_pipeline.py:168-178`、`dayu/fins/storage/_fs_filing_upload_state_core.py:61-84`、`dayu/fins/ingestion_runtime.py:5000-5001, 5953`
- **输入场景**: fresh `read_filing_upload_state()` 在 publication guard 获取/释放失败时抛 `RuntimeFileLockError`（锁超时/锁文件不可用），或 inspector 内部违约时抛 `RuntimeError`（"exact inspector 未返回 target / 可信状态缺少 business meta"）
- **实际分支**: helper 的 except chain 只有 `FinsUploadPrevalidationError` / `FinsUploadUsageError` / `OSError` / `ValueError` 四类；`RuntimeFileLockError` 继承 `Exception`（`dayu/runtime/filelock.py:24`），不是 OSError/ValueError 子类，两个 helper 均不捕获
- **预期行为**: 与 post-`UPLOAD_STARTED` 路径一致地由 upload-failure owner 收敛为 typed failure；`fins_upload_failure_from_exception()` 已显式把 `(OSError, RuntimeFileLockError)` 映射为 typed `STORAGE_IO`（`upload_failure.py:270-277`）
- **实际行为**: 异常从 async generator 冒出 → `ProductionFinsUploadRunner.run_upload` → `_run_upload_job` 的 `except Exception`（`ingestion_runtime.py:5000-5001`）→ `_save_failed_from_exception` 以 `str(exc)` 持久化（`5953`）。durable job failure 只有裸 message，丢失 typed kind/code/retry_hint JSON；direct 路径则 raw 冒出。同一异常类在 `UPLOAD_STARTED` 之后有 typed 映射、之前没有，收敛不一致
- **直接证据**: state read 的 Raises 契约明确列出 `RuntimeFileLockError`（`_fs_filing_upload_state_core.py:80-81`）与 `RuntimeError`（`:83`）；helper except chain 实测只含四类（sec `:94-104`）；`RuntimeFileLockError` 类继承声明（`filelock.py:24`）；runtime generic 持久化链（`5000-5001` → `5953`）
- **影响**: durable 契约不一致；锁竞争（并发 upload/download 同一 ticker）是真实运行条件，此时 job 记录为 message-only 失败而非 closed failure JSON。message 本身是固定中文文案（无路径泄漏），故不构成 path-free 违反
- **建议改法和验证点**: helper 的 OSError 分支扩为 `except (OSError, RuntimeFileLockError)`（一行，收敛到既有 prevalidation IO failure），或对剩余异常按 `fins_upload_failure_from_exception` 收敛；补一个 fresh lock failure 的 workflow 测试（monkeypatch 抛 `RuntimeFileLockError`，断言唯一 typed failed event + 零 mutation）。若 Controller 裁定本 slice 不扩 scope，至少在 residual risk 显式登记
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
