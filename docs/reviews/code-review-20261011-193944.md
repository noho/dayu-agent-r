- **文件(行号)**：`dayu/fins/downloaders/sec_downloader.py:394`（`path = urlparse(value).path`，校验阶段丢弃 `;` 之后内容）、`dayu/fins/downloaders/sec_downloader.py:476`（`path = unquote(urlparse(resolved).path, ...)`，身份提取阶段再次丢弃）、`dayu/fins/downloaders/sec_downloader.py:478-482`（`name`/canonical 由截断后的 path 生成）。
- **输入场景**：待发布 HTML 的 `img src` / `img srcset` / `picture>source srcset` 候选含未编码 `;`，例如 `plot;1.jpg`、`plot;1.jpg?v=2`、`plot.jpg;x`、`plot;a=1.jpg`；或 base 解析后最终路径段含未编码 `;`。
- **实际分支**：`_validate_image_address_text` 只检查 `urlparse(value).path`，`;` 后文本在 `params` 中因此不被路径校验拒绝；`urljoin` 后仍保留字面 `;`，但 `urlparse(resolved).path` 只返回分号前部分 → `name="plot"`（或 `"plot.jpg"`）→ `canonical = archive_base + quote(name, safe="")`。
- **预期行为**：按 HTTP/URL 语义（RFC 3986 已将 `;` 归入 path 字符；httpx/浏览器发送的请求路径包含 `;`），应把 `;` 视为原样文件名的组成部分，或按 plan 的「不明确路径不修复」契约显式 typed 失败；绝不能静默把依赖改成另一个远端对象。
- **实际行为**：descriptor 变为 `("plot", "https://www.sec.gov/Archives/edgar/data/42/000000000000000042/plot")`；`plot;1.jpg` 与另一候选 `plot` 被合并为同一个资产；随后 GET 请求的是 `.../plot`。探针结果（`probe-params.jsonl`）：
  - `plot;1.jpg` → `[["plot", ".../plot"]]`
  - `plot;1.jpg?v=2` → `[["plot", ".../plot"]]`
  - `plot.jpg;x` → `[["plot.jpg", ".../plot.jpg"]]`
  - 对照：编码形式 `plot%3B1.jpg` → `[["plot;1.jpg", ".../plot%3B1.jpg"]]`，即同一文件名字面/编码两种写法行为不一致。
- **直接证据**：上列探针（经真实 `SecDownloader.list_filing_image_files` + MockTransport，未改写生产代码）；`urlparse` 仅在该函数链中消费 path（`sec_downloader.py:394/476`）；测试文件无任何 `;` 地址用例（覆盖缺口）。
- **影响**：静默错误数据路径：若 archive 中恰存在截断名文件，将下载并登记错误对象、继续发布完整来源，而 HTML 声明的真实依赖从未被满足；若不存在，则请求错误 URL 得到 404，失败诊断指向错误文件名，掩盖真实引用。`;jsessionid=`、cache-buster 类历史 URL 形态在真实网页中常见。
- **建议改法和验证点**：二选一并补 owner 测试（img/src、srcset、base 三入口）：
  - A（推荐，保守、与既有「不明确输入 typed 失败」风格一致）：在 `_validate_image_address_text` 中检查 `urlparse(value).params` 非空 → `raise ValueError(_HTML_IMAGE_REFERENCE_MESSAGE)`（对 candidate 与 base href 均生效）；新增 `plot;1.jpg` 断言 `html_image_reference_invalid` 且零图片 transport。
  - B（如产品决定支持字面 `;`）：抽出统一 helper 在 394/476 两处使用 `parsed.path + (";" + parsed.params if parsed.params else "")` 组成 name，canonical 仍由 `quote(name, safe="")` 生成（`;` → `%3B`，请求语义等价）；新增 `plot;1.jpg` 与 `plot%3B1.jpg` 产出同一 `name`/`canonical` 的断言。
- **修复风险**：低（方案 A，仅新增拒绝分支）；中（方案 B，需覆盖 base/中间段组合且防止再次分叉校验）。
- **严重程度**：中。
