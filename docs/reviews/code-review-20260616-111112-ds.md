## 逐项审查

### 1. 是否真正移除 CLI/Service direct path 的 durable job handle / sidecar / request_cancel(job_id) coupling

**结论**：✅ PASS

**证据**：
- `dayu/cli/commands/fins.py`：`_start_direct_job(...)`、`_wait_for_terminal_handling_sigint(job_id)` 已完全替换为 `_open_direct_stream(...) -> AsyncIterator[FinsEvent]` + `_wait_for_terminal_handling_sigint(events, cancellation_token, sigint_monitor)`。SIGINT 不再调用 `service.request_cancel(handle.job_id)`。
- `dayu/service/fins_direct.py`：Service public API 不再导出 `FinsDirectJobHandle`、`FinsDirectJobEvent`、`FinsDirectTerminalResult`、`stream_job_events_until_terminal(...)`、`wait_for_terminal(...)`、`request_cancel(job_id)`。`__all__` 中不包含任何旧类型。运行时通过 `hasattr()` + `__all__` 成员检查验证已完全移除。
- `dayu/cli/output.py`：不再渲染 job id、sequence、sidecar cursor 或 durable cancel 语义。
- 无兼容 wrapper、无 compat re-export、无旧路径 facade。

### 2. FinsEvent contract 是否严格 typed、中文 docstring、无 Any/object 签名、字段校验不过度误杀正常业务文本

**结论**：✅ PASS

**证据**：
- `dayu/fins/direct_events.py`：所有 dataclass 使用 `frozen=True, slots=True`，字段类型明确（`str | None`、`int | None`、`FinsEventDetail`、`FinsProgress`、`FinsResultSummary`），无 `Any`、`object`、`dict` 裸签名。
- 每个公开类型与模块均有中文 docstring。
- 字段校验覆盖面：PROGRESS/RESULT 互斥、exit code 固定映射（0/1/130）、aware datetime、字段长度上限、禁止内容黑名单（job id pattern、absolute path pattern、内部治理标识文本片段）。长度边界按字段语义分级（message 240、title 120、stage 120、short field 80），合理。
- **一个注意事项**（非 finding）：`_DISALLOWED_TEXT_FRAGMENTS` 黑名单方式对 "cursor" 等普通英文词存在理论上的 false positive 风险，但考虑到字段长度上限（max 240 chars）和财报业务上下文，当前保守策略可接受。
- **一个注意事项**（非 finding）：正则在 `_ABSOLUTE_POSIX_PATH_PATTERN` 中要求至少两级目录深度（`/(?:[A-Za-z0-9._-]+/)+`），单级路径如 `/tmp` 不会被匹配。但考虑到 Fins 工作区路径通常深度较大，这不是生产问题。

## Findings

### Finding DS-001：MEDIUM — 用户可见输出使用旧 "job" 术语

- **文件/行号**：`dayu/cli/output.py:39`
- **严重度**：MEDIUM
- **描述**：`_FINS_EVENT_SUMMARY_PREFIX = "Fins job summary"` 在用户可见输出中使用了旧 "job" 术语。Replacement plan 明确要求 CLI direct 不使用 job lifecycle 术语，输出应反映业务操作语义而非系统内部治理概念。用户执行 `dayu-cli download --ticker AAPL` 成功后将在 stdout 看到 `Fins job summary: ...` 字样。
- **修复建议**：改为 `_FINS_EVENT_SUMMARY_PREFIX = "Fins summary"` 或 `"Fins operation summary"`。

### Finding DS-002：LOW — `_FinsSigintMonitor` 类 docstring 残留旧术语

- **文件/行号**：`dayu/cli/commands/fins.py:169`
- **严重度**：LOW
- **描述**：`_FinsSigintMonitor` 类的 docstring 写为 `"""Fins direct job 运行阶段的 SIGINT 观察器。"""`，使用 "job" 而非 "operation"。虽然 `_FinsSigintMonitor` 是 CLI 内部类型（`_` 前缀），但中文注释应保持术语一致。
- **修复建议**：将 docstring 改为 `"""Fins direct operation 运行阶段的 SIGINT 观察器。"""`。

### Finding DS-003：LOW — CLI 与 Service 存在冗余 `_missing_result_event()` 实现

- **文件/行号**：`dayu/cli/commands/fins.py:750`，`dayu/service/fins_direct.py:513`
- **严重度**：LOW
- **描述**：CLI 的 `_consume_fins_direct_events()` 和 Service 的 `_ensure_result_event()` 各自定义了 `_missing_result_event()` fallback。Service 的版本包含操作上下文（operation_kind, ticker, filing_kind, document_label），而 CLI 的版本硬编码 `FinsOperationKind.PREPROCESS` 且无 ticker。目前 Service 的 `_ensure_result_event()` 已保证正常结束必有 RESULT，CLI 侧 fallback 是 defense-in-depth。如果未来有新的 UI consumer 直接消费 Service stream 而不经 CLI，它们可能错过这个语义保证。但当前这不是生产问题——Service guarantee + CLI fallback 两层防护使 no-result 情况几乎不可能发生。（如果 Service guarantee 失效，CLI 的 fallback 会产出信息量较低的 error，足够触发诊断。）
- **修复建议**：可选择将 CLI 的 `_missing_result_event()` 替换为更通用的 constructor（从上游已知的 operation_kind/ticker 取参数）。非阻塞。
