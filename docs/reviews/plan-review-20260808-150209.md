## Direct contract result

**没有发现任何 B2 registry、CLI CI handbook、predicate 29/30 或 Host design 条款要求 wide → constrained hot-switch，
也没有发现把旧 Trial2 sequence 327 的 root-cause closure列为 B2 mandatory evidence。**

精确 contract 如下：

1. 目标 scenario 的 precondition 是 `relevant-material-over-initial-output-caps`，input class 是
   `initial-request-with-real-caps`；`required_evidence` 只要求 real caps、Host cap/usage audit、accepted
   provenance/omitted exact complement、same-boundary repair/exhausted fallback，以及 artifact/Memory/RunInput/reconnect 同源。
2. Predicate 29 冻结 Host accept barrier、immutable source boundary、真实 output caps、previous EvidenceFact keep/omit、
   bounded whole-candidate repair、exhausted fallback 和 `CompactAcceptedTruthV4` 同源投影；没有 profile transition 条件。
3. Predicate 30 冻结真实 rolling compact、replacement provenance、repair/fallback、Tool Trace、turn-group atomicity 与跨进程
   reconnect；没有 wide baseline 或旧失败 root-cause 条件。
4. `docs/cli_ci.md:538-539` 只要求在相关修复完成后的最终 HEAD 上 fresh 补跑并交用户裁决。sequence 327 尚未被证明是
   产品 defect；合法 fixed-profile fresh chain 若能在最终 HEAD 形成 mandatory truth，不需要先解释一个不属于该 scenario
   input contract 的 hot-switch occurrence。
5. `docs/host/design.md:91-99,119-123` 支持 execution profile 在 opener 前同源构造 context、compactor 与 memory policies；
   从首个 opener 起固定完整 constrained profile 不需要动态 per-Run override，也不改变 public contract。

因此，这条替代路径在语义上成立，而且比恢复一个不存在的 sequence 324 物理 snapshot 更小、更可审计。旧 sequence 327
仍须作为 unresolved owner-observability / cross-opener policy-transition residual 原样保留；它不能被新 chain“解释”、覆盖或重标
PASS，但也不再阻塞 B2 mandatory observation。

## Findings

### MIMO-F18-POINT-001-未修复-中-最新目标已解除 root hard gate，但现有 Gateflow artifacts 仍把它写成 binding stop condition

- **位置**: 用户最新 follow-up 与 `pr-190-f18-goal-confirmation-20260808.md` / `pr-190-f18-plan-20260808.md` 的冲突。
- **问题类型**: 目标漂移 / sequencing / 契约缺失
- **当前写法**: 现有 goal/plan 仍规定只有 sequence 327 具体 root cause 证明后才能进入 formal observation；最新用户方向则明确
  要把旧失败留作 residual、取消其 readiness 前置身份。
- **反例/失败场景**: implementation agent依旧服从旧 artifact，会在不可恢复的 seq324 replay 上停止；若只口头忽略旧 artifact，
  后续 reviewer 又会依据 binding Goal Confirmation 判定 scope violation。
- **为什么有问题**: Gateflow 的 Goal Confirmation 是 scope contract。用户有权修改已确认目标，但 Controller 必须把最新裁决写入
  gate truth，不能让同一 work unit 同时存在两个相反的 entry condition。
- **直接证据**: 现有 goal 的 B2 formal success signal和 plan Slice 3 都写了 root-cause closure hard gate；最新用户 follow-up
  明确撤销其 readiness 前置。scenario registry / predicates 又证明该撤销没有降低 B2 Oracle contract。
- **影响**: 合法 formal chain 被无关 residual阻断，或 implementation/review 对 scope产生互相矛盾的 verdict。
- **建议改法和验证点**:
  1. Controller 在进入 implementation / observation 前追加 goal-confirmation amendment或等价 adjudication，明确：
     sequence 327 verdict=`unresolved residual`，不用于 B2 evidence；fixed-profile chain 是新的 formal entry path。
  2. 更新 plan 的 Slice 2/3 sequencing，删除“exact root cause证明后才可调用 provider”的依赖边；保留 provider-independent
     direct evidence与旧失败不可恢复说明，不伪称问题已修复。
  3. final closeout分别报告：旧 root investigation verdict、fixed-profile real observation verdict、B2 Oracle status。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### MIMO-F18-POINT-002-未修复-中-fixed-profile replacement chain 必须先建立 accepted previous atom，再让 FY2025 evidence自然离开 protected floor

- **位置**: 替代路径的“cap内 baseline + 新真实FY2025 evidence自然越 cap”。
- **问题类型**: 状态机漏洞 / 不可直接实施 / 测试缺口
- **当前写法**: 高层路径正确，但“baseline + 新 evidence”尚未展开为可审计 source-boundary state machine。
- **反例/失败场景**:
  - 首个 compact没有接受 provenance-backed FY2024 EvidenceFact，则下一 boundary不存在 `previous_evidence_fact` atom，无法观察
    keep/omit。
  - 新 FY2025 tool-evidence Run仍位于最近 4 个受保护 turn groups时，`select_compact_segment` 会把它排除；此时即使 Session
    里“已经有 FY2025 evidence”，initial compactor input也没有该 new evidence source，不能证明 cap replacement。
  - unsupported `21.7%/18.2%` 若只在已排除的近期 current/raw material里出现，报告也不能声称 accept barrier在目标 boundary
    拒绝了它们升级。
- **为什么有问题**: Predicate 29要求 previous EvidenceFact immutable atoms与新 evidence material同时存在于同一 immutable
  input；Predicate 30要求 accepted replacement及其 provenance/omitted complement同源。Conversation Memory或最终回答中“看得到”
  不等于 compact source boundary包含该材料。
- **直接证据**:
  - constrained policy冻结 `evidence_fact_item_cap=1`、`evidence_fact_floor=1`、
    `selected_recent_window_turn_floor=4`。
  - `dayu/host/compact_material.py::select_compact_segment` 明确排除 protected recent turn groups；
    `CompactAcceptedTruthV4` 又要求 represented/omitted精确分区同一 source boundary。
  - Predicate 29明确 previous EvidenceFact只能 label keep/omit，新 EvidenceFact只能选当前 evidence material。
- **影响**: chain可能成功 compact，却没有覆盖 previous-vs-new cap竞争；report只能靠 Memory/文本反推，mandatory evidence仍缺失。
- **建议改法和验证点**:
  1. 把 replacement chain写成显式 gates：真实 FY2024 tool evidence → 首个 constrained accepted compact（恰有一个
     previous EvidenceFact及 canonical provenance）→ fresh reconnect验证 previous truth → 真实 FY2025 tool evidence与 unsupported
     percentages → 恰好足以让该 evidence Run离开 4-turn floor 的 bounded follow-ups → 目标 compact。
  2. 在目标 compactor initial input中先断言：真实 caps、一个 previous atom、FY2025 evidence label、unsupported percentage
     material均实际存在；缺一即停止，不能调用后置 analyzer补算。
  3. accepted truth必须断言 FY2025 provenance被 represented、旧 atom的 keep/omit结果明确、Host-owned omitted与 represented exact
     complement；若模型自然选择旧事实而未接受 FY2025，新 chain保留为失败/needs-more-evidence。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### MIMO-F18-POINT-003-未修复-中-独立 repair/fallback chains 仍需预先冻结真实 provider budget与自然分支停止规则

- **位置**: 替代路径的“独立真实链覆盖 repair/fallback/reconnect”。
- **问题类型**: 不可直接实施 / 最佳实践偏离 / 测试缺口
- **当前写法**: 方向允许独立 chains，但未定义每条 chain 的最大 ordinary Runs、compact operations、attempts、reconnect与
  dependency stop。
- **反例/失败场景**: MiMo 在 1-item/160-char caps 下可能第一次就提交合法 candidate，因而没有 repair；也可能在 repair后被
  accepted，不产生 exhausted fallback。若 agent为了追求分支不断新增 prompts/operations，会违反 bounded observation；若把另一条
  chain 的 unit test或旧 Trial2现象补进来，又违反 real-chain evidence要求。
- **为什么有问题**: Host 的每 operation attempt budget虽然固定为 5，但“最多几个 operation / Run”仍是 observation owner的
  外部预算。自然模型分支不可强制，必须用预先冻结的 stop condition管理，而不是事后调整。
- **直接证据**: Predicate 29/30允许 bounded repair/exhaustion；用户明确允许独立真实链且自然未触发时必须
  `needs-more-evidence`，禁止 output injection。当前 constrained profile的
  `max_compaction_attempts_per_operation=5` 只界定单 operation，不界定总 provider调用。
- **影响**: provider成本和尝试次数不可审计；失败可能被后续尝试稀释；B2 report错误宣称完整覆盖。
- **建议改法和验证点**:
  1. 预先冻结最小 chain matrix：replacement/reconnect、bounded-repair、exhausted-fallback各自独立 fresh workspace、唯一目标、
     最大 Run/operation/response/reconnect数量与停止原因。
  2. 单 operation最多 5 compactor responses；一次预定 operation未自然触发目标分支时即按 chain预算停止并标
     `needs-more-evidence`，不得临时增加第二 operation，除非 plan在调用 provider前已显式授权并计入总预算。
  3. prerequisite ordinary Run非 `RUN_SUCCEEDED`、config digest变化、非 MiMo plan、evidence capture不完整或 unexpected setup
     mutation时立即停止该 chain；所有 attempted outcome原样归档。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### MIMO-F18-POINT-004-未修复-中-public evidence 必须能独立证明 mandatory truth，不能让 private hot/SQLite成为唯一桥梁

- **位置**: 替代路径的 external evidence publication与 artifact/EventLog/Memory/RunInput/public Tool Trace同源要求。
- **问题类型**: 架构边界 / 契约缺失 / 可观测性缺口
- **当前写法**: 路径要求按 public/private规则保存，但尚未冻结 public evidence最小集合与最后 writer。
- **反例/失败场景**: 现有 public bundle中的 cold analyzer无法解析 compactor responses；若新 report只写“private hot 6/6”并把
  raw SQLite留 private，公开消费者无法独立验证 accepted/rejected response identity、caps、accepted truth或 reconnect同源。
  反过来若直接发布 raw SQLite/log，又泄漏绝对路径、prompt或 credential-bearing runtime字段。
- **为什么有问题**: Predicate 30明确要求 formal Tool Trace public resolver及 analysis JSON/Markdown投影 compactor identity；用户
  又要求 public/private publication、secret/path scan。public report必须引用 owner-generated、脱敏、可分发的 typed projection，
  不能以 private evidence摘要替代。
- **直接证据**: 旧 public report明确记载 cold analyzer `compactor_responses=0`，hot analyzer、canonical equality、Memory、SQLite
  均留在 private；这对已由用户单独接受的 B1 limitation可保留，但不能自动证明新 B2 mandatory同源链。
- **影响**: B2 evidence表面齐全但无法公开复核，或为了补齐而越过 privacy/secret边界。
- **建议改法和验证点**:
  1. 在执行前冻结 public bundle最小文件：path-redacted Host public resolver/analysis输出、B2-only accepted-truth/equality summary、
     observed behavior report、digest manifest与 final secret/path scan。
  2. raw PTY、完整日志、SQLite before/after与高体量 owner dump留 private；public summary只能从 public Host/API typed fields投影，
     private SQLite只做 Controller交叉核验，不能补出 public缺失字段。
  3. secret/path scan必须是 public tree的最后 writer；其 manifest排除自引用但包含此前全部 public files，并记录完整/零命中。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

## Residual risks and suggested tracking destination

- Trial2 seq325-327：保留在 F18 root-cause report/final closeout为
  `unresolved; original owner exception not durably captured; no causal inference`。如后续合法 fixed-profile chain也出现
  `runner_candidate_invalid`，立即重新升级为本轮 blocking product investigation，不能继续消耗 provider。
- 跨 opener 改变 memory policy是否合法及 fixed consumer checkpoint / policy digest关系：作为 Host projection/session policy

- MiMo自然不触发 repair或exhaustion：在对应 chain/report标 `needs-more-evidence`；B2保持 `unadjudicated`，overall readiness
  不得 ready。
- unsupported `21.7%/18.2%`：只可作为不可信用户/material输入观察其未被接受为 EvidenceFact；不得注入 provider输出或在
  analyzer侧重算成业务事实。

## Final plan review conclusion

`pass-with-risks`

这条替代路径**推翻了前次 review 中“sequence 324 exact replay是 B2 formal observation 的 blocker”这一 gate 结论**：该 replay
本身仍不可实施、旧 root cause也仍 unresolved，但 registry/handbook/predicates并未要求它先闭合。只要 Controller先把最新用户
裁决写回 Gateflow scope，并按上面四项收紧 source-boundary state machine、bounded provider matrix和 public publication contract，
即可直接进入 fixed-profile fresh formal observation。任何 mandatory branch未自然触发都必须如实保留为
`needs-more-evidence`；即使全部观察完成，B2在用户裁决前仍为 `unadjudicated`，overall readiness仍不得标 ready。
