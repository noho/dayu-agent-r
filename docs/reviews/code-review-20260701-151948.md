### S2-CR-F03: Self-close fail-fast — FIXED ✅

- **Controller requirement**: "raise RuntimeError if close() is called from the supervisor thread."
- **Implementation evidence**: `close()` line ~1112: `if thread is threading.current_thread(): raise RuntimeError("wait poller supervisor cannot close from its own thread")`. The RuntimeError propagates through `_poll_once → _run_loop → except Exception → FAILED diagnostics + close_event.set()`.
- **Test evidence**: `test_close_from_supervisor_thread_marks_failed_diagnostics` (line 610) — `_SelfClosingPoller.poll_once()` calls `supervisor.close()` from poller thread; verifies `fatal_errors==1`, `last_error_type=="RuntimeError"`, message contains "cannot close from its own thread", log contains "wait poller loop failed".
- **Status**: Closed. Self-close fails fast with clear error.

### S2-CR-F04: Double-close no STOPPED→CLOSING — FIXED ✅

- **Controller requirement**: "Add an early return for already stopped / failed supervisor or clear self._thread after close."
- **Implementation evidence**:
  1. Early return at close() entry: `if status in (STOPPED, FAILED) and (thread is None or not thread.is_alive()): self._thread = None; self._close_event.set(); return` — blocks STOPPED→CLOSING on repeated close (already-terminal + thread dead/none).
  2. Thread clearing after join: `if self._thread is thread: self._thread = None` — clears reference so subsequent close hits the `thread is None` early-return path.
- **Test evidence**: `test_close_is_idempotent` (line 484) now captures `first_closed` status after first close, then captures `second_closed` after second close; both are `STOPPED`. The `_run_loop` natural exit before close() path is also covered: the early-return condition allows STOPPED + `not thread.is_alive()`.
- **Status**: Closed. Double-close preserves terminal status.

### S2-CR-F05: close_drain_timeout_seconds supports None — FIXED ✅

- **Controller requirement**: "Support close_drain_timeout_seconds: float | None. None must mean no first-timeout diagnostic threshold. Positive floats retain current timeout diagnostic behavior."
- **Implementation evidence**:
  - Field type: `close_drain_timeout_seconds: float | None = 5.0`
  - Validation: `if self.close_drain_timeout_seconds is not None: _require_positive_float(...)` — skips validation for None

- **Test evidence**:
  - `test_runtime_policy_allows_none_close_drain_timeout` (line 384): policy accepts None, `policy.close_drain_timeout_seconds is None`
  - `test_close_with_no_drain_timeout_waits_without_timeout_diagnostic` (line 571): None timeout path — `close_drain_timeouts==0`, no "timeout" in log, close still blocks until adapter releases, status STOPPED
- **Status**: Closed. None supported with correct semantics.
