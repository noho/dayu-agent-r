## Findings

### 1-未修复-低-normalize 失败以未捕获 RuntimeError/OSError 逃出 closed usage-failure 契约

- **入口/函数**: `_validate_fins_upload_filing_static()`（经 `_filing_upload_request_identity()` / `validate_fins_upload_filing_request()` 调起）
- **文件(行号)**: `dayu/fins/ingestion_runtime.py:1095-1098`（调用点）、`dayu/fins/ingestion_runtime.py:976`（`_normalize_fins_upload_path` 内 `resolve(strict=False)`）
- **输入场景**: files 或 primary_selectors 中的路径是 symlink loop（或 `expanduser()` 因 HOME 不可确定抛 RuntimeError）的直调 validator 调用方；此类输入会走到 upsert 分支的 normalize 步骤
- **实际分支**: upsert 分支（line 1094 起）先对 files/selectors 执行 `expanduser().resolve(strict=False)`；symlink loop 在该处直接抛 `RuntimeError("Symlink loop from ...")`
- **预期行为**: 本函数 docstring（line 1050-1051）只声明 `FinsUploadUsageError`；plan §6.2/§7.11 与 goal 5 要求所有 admission 失败都是 closed usage failure。归一化前的旧实现对 loop 路径 `exists()` 返回 False → 投影 `FILE_NOT_FOUND`（可行动 usage error，exit 2）。按同一契约，normalize 失败应投影为既有 `FILE_NOT_FOUND`（或经主控裁决新增 closed code），而不是原始异常
- **实际行为**: 未捕获的 `RuntimeError`/`OSError` 直接穿透静态校验层。CLI 错误映射（`dayu/cli/commands/fins.py:197-215`）只把 `FinsUploadUsageError` 映射为 exit 2 + 可行动消息，该异常落入 line 212 的 `except Exception` → 日志 + 通用“未知失败” + `EXIT_FAILURE`
- **直接证据**: 本机 Python 3.11 实测：自环 symlink 上 `Path.exists()` 返回 `False`（旧路径 → `FILE_NOT_FOUND`），`Path.resolve(strict=False)` 抛 `RuntimeError: Symlink loop from '...'`；helper 自身 docstring（line 970-971）已声明 RuntimeError/OSError 但调用点无任何收敛
- **影响**: 错误分类从 closed、可行动的 usage failure 退化为通用内部失败；违反 static admission 的 closed 契约。无数据/状态风险——发生在 workspace read 与一切 mutation 之前，fail closed 不变
- **建议改法和验证点**: 在 `_validate_fins_upload_filing_static` 的 normalize 调用处捕获 `OSError`/`RuntimeError` 并投影为 `FILE_NOT_FOUND`（携带该路径 basename），或经主控确认新增 closed code；补一条直调 `_filing_upload_request_identity` 的 symlink-loop 测试断言 closed code/message。若主控认为 plan §6.2 已冻结行为且当前两个入口（`dayu/cli/commands/fins.py:682`、`dayu/fins/tools/upload_tools.py:460`，base 64050349 已存在）在构造 request 前已前置 resolve，loop 输入在入口投影处即已抛错、真实用户不可达，可裁决 `rejected-with-reason` 或 `deferred-with-owner`，但建议在 plan/README 中把该边界显式记录
- **修复风险（低）**: 改动限于本 slice allowed 文件；但新增/复用 usage code 触及 plan §6.2 冻结的 closed code 表，方向需主控裁决
