- **输入场景**: 调用时 token 已取消，且 `awaitable` 不是 coroutine（是已经创建的 `Task` 或 `Future`）。
- **实际分支**: `await_or_cancel` (line 110-113)：对 coroutine 做 `awaitable.close()`，对非 coroutine 直接返回 `WaitCancelled`，不做任何操作。`await_or_cancel_or_timeout` (line 223-229)：对 coroutine 做 `awaitable.close()`，对非 coroutine 则 `asyncio.ensure_future(awaitable)` + `_cancel_task_and_wait(target_task)`——主动取消调用方的 Task。

- **影响**: 调用方可能依赖 `await_or_cancel` 的 "不取消已存在的 Task" 行为，升级到 `await_or_cancel_or_timeout` 时会意外取消调用方 Task。
- **建议改法和验证点**: 统一两个 helper 的 pre-cancelled 行为。(a) 若 helper 拥有 awaitable，两者都应在 pre-cancelled 时 `_cancel_task_and_wait`；(b) 若 pre-cancelled 应 short-circuit，两者都不应操作 awaitable。建议选 (a)，与 docstring 一致。

## Open Questions

1. **Suspended 语义与 Runner 关闭的矛盾**: `resolved by design / deferred-with-owner`。当前设计明确 Agent / Runner 都是 run-scoped 一次性对象；suspend 后不复用旧 Runner，恢复由上层调用者构造新的 `AgentRunRequest`。`resume_hint` 后续调整归 Host resume / run recovery work unit。
2. **`ToolExecutionContext.timeout_seconds` 与 `AgentPolicy.tool_execution_timeout_seconds` 的语义关系**: `resolved / fixed`。`AgentPolicy.tool_execution_timeout_seconds` 是 Engine 工具握手 timeout 真源；`ToolExecutionContext.timeout_seconds` 是投影到本次工具调用的预算，不是第二真源。
3. **`RunSuspendedData.reason` 何时会有非 `tool_awaiting` 的值**: `deferred-with-owner`。当前仅有 `tool_awaiting`；若后续新增 suspend reason，再评审是否改为 enum。

## Residual Risk

1. **测试未覆盖 cancel 与 suspend 的竞争窗口**: `resolved by design / fixed by docs and tests`。当前设计明确 `ToolAwaitingOutcome` 已返回后 late cancel 不覆盖 `RUN_SUSPENDED`；docstring 已标注，测试覆盖 outcome 前取消与 `TOOL_AWAITING` 后 late cancel。
2. **double cancel 行为未测试**: `deferred-with-owner`。当前无新 bug 证据；terminal 唯一性和 close 幂等已有基础覆盖，专门 double cancel 测试可归后续 cancellation hardening。
3. **`ToolExecutor.execute` 抛出 `asyncio.CancelledError` 无测试覆盖**: `fixed`。已新增 executor 内部 `asyncio.CancelledError` 测试。
4. **负值 `timeout_seconds` / `poll_interval_seconds` 无输入校验**: `partially covered / deferred-with-owner`。`AgentPolicy` 已覆盖 Engine 工具 timeout 真源校验；runtime helper 独立参数校验归后续 runtime hardening。
5. **`dayu/engine/README.md` 未纳入本次 review**: `fixed`。README 已同步 timeout 真源、run-scoped 一次性 Agent / Runner、cancellation commit boundary，并在后续 re-review 中确认。
