# WU-CM-06 Focused Plan Re-Review

## Reviewed Target

`docs/host/host-issues/wu-cm-06-terminal-summary-text-policy-plan.md`（最新修正版）

## Review Scope

本次 re-review 聚焦 implementation preflight 发现的 Conversation Memory descriptor behavior 写反问题，验证 plan 三个修正点是否符合代码事实。

## Background

Previous plan 在 policy table 中把 Conversation Memory 的 terminal summary descriptor 行为写反：暗示 memory consumer 自己会 follow descriptor。实际代码事实是：

- `dayu/host/memory.py` 的 `_selected_assistant_item()` 只调用 `assistant_final_answer_text_from_run_payload()` 读取 inline `final_answer`，不 follow descriptor。
- `dayu/host/durable/memory.py` 的 `_payload_with_assistant_final_answer()` 在 projection/inline adapter 层用 `assistant_final_answer_continuity_text()` hydrate descriptor-backed terminal artifact content into transient `final_answer`，然后再交给 memory consumer。
- `dayu/host/run_input.py` 的 `_memory_projection_event_from_row()` 同样在 adapter 层做 hydrate。
- `tests/host/test_memory_projection.py::test_projection_consumer_hydrates_terminal_content_as_final_answer` 已覆盖 durable projection hydration 行为。

## Assumptions Tested

1. Plan 的 policy table 对 Conversation Memory 的描述是否准确反映代码事实。
2. Slice 1 memory tests 的修正是否正确描述了 consumer 与 adapter 的职责边界。
3. Slice 2 docstring convergence 的修正是否与代码行为一致。

## Findings

无 material findings。三个修正点均与代码事实一致。

### 修正点 1：Policy Table（第 36 行）

**Plan 写法：**
> `Conversation Memory selected recent window | consumer accepts inline RUN_SUCCEEDED.final_answer only and remains lenient; durable projection / run-input adapters may first hydrate a digest-checked terminal summary artifact content into transient final_answer`

**代码验证：**
- `memory.py:1625-1628` — `_selected_assistant_item()` 调用 `assistant_final_answer_text_from_run_payload(event.payload, text_policy=LENIENT_NON_EMPTY)`，只读 inline `final_answer`。
- `durable/memory.py:213-243` — `_payload_with_assistant_final_answer()` 先检查 inline `final_answer`，缺失时调用 `assistant_final_answer_continuity_text()` 从 descriptor hydrate，再 merge 进 payload。
- `run_input.py` 中 `_memory_projection_event_from_row()` 同样在 adapter 层做 hydrate。

**结论：** 修正准确。

### 修正点 2：Slice 1 Memory Tests（第 65-66 行）

**Plan 写法：**
> - Add a direct consumer test proving `build_conversation_memory_snapshot_from_events(...)` does not follow terminal summary descriptors by itself; descriptor hydration belongs to durable projection / run-input adapters.
> - Strengthen the existing durable projection test proving descriptor-backed terminal summary artifact content is hydrated into transient final answer before memory consumer and still remains selected-recent-window continuity, not evidence-backed fact memory.

**代码验证：**
- `test_memory_projection.py:383-458` — `test_projection_consumer_hydrates_terminal_content_as_final_answer` 已证明 durable projection 层 hydrate 行为：写入含 descriptor 的 `RUN_SUCCEEDED`，projection consumer 通过 `_payload_with_assistant_final_answer` hydrate 后，selected recent window 中出现 artifact `content`。
- `memory.py:1238-1243` — `project_conversation_memory_event()` 对 `RUN_SUCCEEDED` 直接调用 `_selected_assistant_item(event)`，其中 `event.payload` 在 durable projection 路径已被 adapter hydrate。纯 in-memory 路径（`build_conversation_memory_snapshot_from_events`）不会 hydrate。

**结论：** 修正准确，consumer 与 adapter 职责边界正确。

### 修正点 3：Slice 2 Docstring Convergence（第 86 行）

**Plan 写法：**
> - Clarify consumer differences: compaction material uses the strict continuity resolver with artifact fallback; memory selected recent window consumes inline `final_answer` leniently; durable projection / run-input adapters may hydrate descriptor-backed terminal artifact content into transient `final_answer` before memory consumption.

**代码验证：**
- `compact_material.py` 使用 strict continuity resolver（`assistant_final_answer_continuity_text` with `STRICT_NON_EMPTY`）。
- `memory.py` 使用 `LENIENT_NON_EMPTY` 读取 inline `final_answer`。
- `durable/memory.py` adapter 层使用 `STRICT_NON_EMPTY` 做 hydrate。

**结论：** 修正准确。

## Architecture Boundary Review

Plan 修正后，consumer / adapter 职责边界清晰：
- Memory consumer（`memory.py`）：只读 inline payload 字段，不触碰 durable store。
- Durable projection adapter（`durable/memory.py`）：在 projection transaction 内 hydrate descriptor，产出 transient payload 给 consumer。
- Run input adapter（`run_input.py`）：在 read transaction 内 hydrate descriptor，产出 transient event 给 memory projection。

无过度耦合、无反向依赖。
