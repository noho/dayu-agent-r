## Residual Risk

1. **failed/cancelled outcome digest 对齐无专项测试**: `test_callback_digest_matches_resolve_wait_digest_for_completed_and_lost` 只覆盖 completed 和 lost。failed/cancelled outcome 的 digest 对齐由共享模块 `wait_resolution_digest` 保证——`waiting.py` 和 `wait_callback.py` 均从同一入口调用，且 `test_resolve_wait_command.py` 覆盖了 failed/cancelled resolve 行为。分类：covered by shared implementation and existing tests。

2. **`expires_at` 使用 `+00:00` 格式时的 stale 判断**: 当前 `expires_at` 通常为 `None`（schema reserved/unpopulated）。若未来写入路径使用 `+00:00` 格式而非 `Z`，`parse_utc_timestamp` 会拒绝并返回 `INVALID_WAIT_STATE`。这比旧宽松 parser 更严格，是正确的防御行为。分类：tracked by design（写入路径必须使用 `format_utc_timestamp` 产出 `Z` 格式）。

3. **callback stale 并发 race**: stale check 通过后、resolve 执行前的并发 race 仍可能由 resolver 收敛为 `INVALID_WAIT_STATE`。分类：tracked by accepted Slice 1 design behavior。

4. **`HostCommandWaitCallbackPort` 每次调用新建 `DefaultHostResolveWaitService`**: 与现有 `resolve_wait` 函数行为一致；`DefaultHostResolveWaitService` 不持有可变状态。分类：non-issue。
