### 逐项检查

#### 1. tool_request/tool_result 是否从 owner-boundary durable material 派生 — **通过**

- `TOOL_CALL_REQUESTED` trace: `_tool_request_summary_from_payload(payload)` 直接从 request atom payload 读取 `tool_name`、`tool_call_id`、`arguments_inline_json`、`semantic_query_text`、digest/ref。✅
- `TOOL_RESULT_ACCEPTED` trace `tool_request`: `_tool_request_summary_from_tool_result` 通过 `accepted_evidence_envelope` → `tool_call_requested_event_ref` 回读 request atom，并校验 `tool_call_id`/`tool_name`/`normalized_arguments_digest` 与 envelope 一致。✅
- `TOOL_RESULT_ACCEPTED` trace `tool_result`: `_tool_result_summary_from_payload` 从 payload 的 `raw_tool_outcome` 读取。✅
- 所有数据来源都是 EventLog durable material，不依赖内存状态或代码路径。

#### 2. 是否没有从 TOOL_AWAITING / wait / poll / runtime 状态反推业务语义 — **通过**

- `_tool_request_summary_from_tool_result` 只读 `accepted_evidence_envelope` 和 `TOOL_CALL_REQUESTED` request atom，不读 `TOOL_AWAITING`、wait record、poll state。✅
- `_tool_result_summary_from_payload` 只读 `raw_tool_outcome`、`resolution_kind`/`tool_fact_kind`、`outcome_digest`/`payload_ref`/`payload_digest`。✅
- Limited summary fallback 文本为 "request details unavailable in tool trace"，不含 governance 术语。✅
- 测试 `test_wait_resolution_tool_trace_summarizes_request_and_result_details` 显式断言 `"wait-atat-should-not-project" not in cold_text`、`"observation handle" not in cold_text`、`"runtime" not in cold_text`。✅

#### 3. 普通 tool result 与 wait-resolution result 是否一致 — **通过**

- 两者都走 `_EVENT_TYPE_TOOL_RESULT_ACCEPTED` 分支，使用同一 `_tool_request_summary_from_tool_result` + `_tool_result_summary_from_payload`。✅
- identity 校验锚点一致：`tool_call_id`、`tool_name`、`normalized_arguments_digest` 对比 envelope。✅
- digest/ref 校锚点保留：`raw_outcome_digest`、`outcome_digest`、`payload_ref`、`payload_digest` 都输出到 trace summary。✅

#### 4. bounded/redacted summary 是否不泄漏敏感字段、不塞大 payload — **通过**

- `_redacted_json` 使用 `redact_sensitive_json_fields`（与 awaiting accept path 同一脱敏函数）。✅
- Bounding limits: `summary_text` 1200 chars、`arguments_text` 800 chars、`result_text` 1600 chars，截断后追加 `...[truncated]`。✅
- `arguments` 字段只在未截断时内联 object；截断时为 `None`（只保留 `arguments_text`）。✅
- 测试验证 `"<redacted>" in json.dumps(request_summary, ensure_ascii=False)`（敏感字段已脱敏）。✅

#### 5. tests 是否覆盖 hot/cold trace 可读 request/result 明文 — **通过**

- `test_tool_call_chain_projects_hot_rows_and_cold_lines`: 验证 request summary 含 `query_text == semantic_query_text`、`"ticker=AAPL" in arguments_summary_text`；result summary 含 `result_status == "completed"`、`"found filing AAPL 10-K" in result_details`。✅
- `test_wait_resolution_tool_trace_summarizes_request_and_result_details`: 验证 wait-resolution trace 含 `tool_name == "start_fins_download"`、`"ticker=ATAT" in arguments_summary_text`、`"discovered=27" in result_details`；cold JSONL 也含这些明文。✅
