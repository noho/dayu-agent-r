## 已验证但未构成 finding 的攻击面（记录依据）

- **CLI/tool/US-CN-HK 一致性**：CLI 与 tool 均构造 `FinsUploadFilingRequest` 并共享
  `_filing_upload_request_identity -> _validate_fins_upload_filing_static`；US/CN/HK 分支合并后无入口特例
  需求。admission 顺序现状：ticker → source_kind → action → files count → fiscal_year → period required →
  period length → period domain → dates → company → files → identity，与 plan 声称一致；missing/overlong
  priority 在修复前后不变（length check 是 market-neutral 且先于 domain check）。
- **exit 2 与具体 reason**：`EXIT_USAGE_ERROR = 2`（`dayu/cli/exit_codes.py:10`）；CLI
  `run_fins_direct_command` 捕获 `FinsUploadUsageError` → `render_cli_error` → exit 2，stderr 单行
  `dayu-cli upload_filing: {message}`；tool 路径捕获 ValueError → `_failed_outcome(error=INVALID_ARGUMENT,
  message=str(exc))`，message 即 owner 的 usage reason。修复后三市场非法值走同一映射。
- **零启动可证明性**：CLI 有 recording factory + fake Service 记录（`factory_calls`、
  `upload_filing_requests`、`stream_calls`）；tool 有 `_ForbiddenFilingUploadStateRepository`（read 即抛）、
  `_runtime_with_static_admission_guard`、`runtime._observations == {}` 断言。converter/job 无法直接 seam，
  但 observations 为空即蕴含无 operation → 无 job/converter，且 storage 是 mutation 唯一通道
  （CLAUDE.md 仓储约束），forbidden state read 封闭了 storage 交互。
- **workspace 零 mutation / 无 traceback**：CLI usage matrix 已有 seeded workspace tree snapshot 先例
  （`UF-S2-seeded-invalid-report-date`）；`_resolve_workspace_root` 只 resolve 不 mkdir，fresh workspace
  前/后均不存在可断言。进程内 harness 的 exact stderr 单行断言已蕴含"无 traceback"；真实 subprocess 证据
  由用户后续 calibration 覆盖（plan 已排除并登记）。
- **validation priority**：missing（`--fiscal-period 不能为空`）→ overlong（`--fiscal-period 长度不能超过
  240 个字符`）→ domain（新通用文案）顺序在修复前后不变；US 非法值 + 坏文件的优先级变化（period 错误先于
  文件错误）是修复的固有结果，与 goal 一致。
- **slice 顺序（除 F1 外）**：S1 语义层 / S2 入口证据层的拆分粒度合理，S2 prerequisites 依赖 S1 accepted
  commit 正确。
- **owner/架构**：ingestion_runtime 不再 import pipeline 层 helper，消除 domain→pipeline 反向依赖；
  `derive_report_kind` 留在 pipeline 层消费 domain owner，方向正确；CLI/tool 不加业务判断；Host/Engine 未动。
- **过度设计/过度耦合**：未新增层、类、协议、factory、callback、schema、migration、wrapper；无新耦合，
  反而消除一个 duplicate parser 与一个反向依赖。
- **pyright 可达性**：全仓 baseline 实测 0 errors / 0 warnings / 0 informations；类型收窄构造点全仓仅一处
  （`ingestion_runtime.py:1520`），跨文件扩散风险低，S1 的 6 文件 pyright 范围 + S2 全仓 pyright 兜底可接受。
