### 3. Transient delivery owner：per-Session reservation、mailbox + 唯一 in-flight、single-pop、overflow prefix、typed error、readiness、exact-once detach/release（含 DS-F02 fix）

`dayu/host/transient_delta.py` 完整替换旧 `asyncio.Queue(maxsize=256)` + `drain_nowait()` batch drain 模式：

- `HostTransientDeltaHub.reserve()` 在 cursor transaction 前同步检查 per-Session admission cap。
- `HostTransientDeltaHub.attach()` 在 owner-loop 无 await 临界段内把 reservation 转为 subscription 并注册 fanout。
- `HostTransientDeltaSubscription` 使用 `deque` mailbox + 唯一 `_in_flight`。`retained_items = len(mailbox) + (1 if in_flight is not None else 0)`。`pop_next_nowait()` 做 mailbox → in-flight transfer 不减 retained count，且**跳过 watcher-local terminal fence 命中的 stale item**（DS-F02 fix）。
- `_offer()` 做 prospective check（`retained_items + 1 > policy.transient_mailbox_max_items`），overflow 时先 `_detach_from_fanout` 再设 `_overflowed = True`。
- `close()` / `_close_from_hub()` 均幂等 detach + clear retained state + release reservation。
- 低基数 observability 只用 closed `event/outcome/reason` enum，无 identity/payload/item count/byte 维度。

**DS-F02 fix 验证**：`pop_next_nowait()` 在 single-pop owner boundary 内从 mailbox 头部逐项检查 `event.run_id in self._terminal_run_ids`，命中 stale item 直接 `continue`（不进入 `_in_flight`），首个有效 item 才转移为 in-flight。`test_single_pop_filters_prequeued_terminal_stale_item` 覆盖两个场景：(1) stale+valid → pop 返回 valid，retained 2→1；(2) stale-only → pop 返回 None，retained 1→0。红灯证据：修复前 `1 failed`（交付 stale run-1），修复后 `1 passed`。

### 4. Async attach activation：reserve → cursor transaction → no-await recheck/attach/return（subagent: open_host）

`open_host.py::_PublicHostHandle.watch_session_events` 改为 `async def`，返回 `HostSessionEventIterator`。执行顺序：lifecycle gate → `reserve()` → `await durable_actor.call(cursor)` → 无 await 临界段（recheck → `attach()` → iterator 构造 → return）。外层 `except BaseException: reservation.release()` 捕获所有 failure path。旧 `_ClosableHostSessionEventIterator`（含 `cursor_future`、done callback、lazy first-`__anext__` attach）已完全删除。

no-await 临界段（lines 925-936）只有 `_raise_if_closed()` 同步检查，无 `await`，保证 recheck/attach/iterator 分配原子完成。

### 5. Host close 先停/drain producer 再 close delivery（subagent: open_host）

`_close_owned_resources` 关闭顺序：health gate → wait_poller → durable actor drain → scheduler → **transient_delta_hub.close()** → projection → actor handle → actor executor → scheduler store。旧代码 hub 在 scheduler 前关闭，存在 scheduler 仍 publish 到已关闭 hub 的 race。修复后 scheduler close 在 delivery hub close 之前，确保 terminal producers 先停止。open-failure cleanup 路径同样对齐此顺序。
