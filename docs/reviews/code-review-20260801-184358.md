## 完整 S2 F05-F09 回归审查

### Exact key sequence

- `composer.py` 的 `build_interactive_key_bindings` 定义了 `c-m`（Enter）、`c-c`、`c-d`、`escape`（仅 active phase filter）、`c-t`（仅 active phase filter）、`c-j`、`c-r`、`c-x c-e`；
- `c-m` 通过 `_is_exact_xterm_shift_enter` 区分 xterm Shift+Enter 序列与普通 Enter；
- `_exit_with_composer_event` 保存 exact buffer/cursor 后退出 prompt_toolkit application。

### Whole stdin（non-TTY）

- `_read_interactive_non_tty_text` 一次读取、strict UTF-8 解码、CRLF/CR 规范化、outer trim；
- `_run_interactive_non_tty_batch` blank → `EXIT_SUCCESS`；非空 → 至多一个 QUEUE turn；
- invalid UTF-8 → stable usage error，不泄漏 bytes/codec/traceback。

### Escape/CSI/Alt/paste

- `escape` binding 只在 `active_phase` filter 下生效，IDLE phase 的 Escape 由 prompt_toolkit 内部处理（不触发 cancel）；
- CSI 序列、Alt 组合键不匹配 `c-m`/`c-c`/`c-d`/`escape`/`c-t`，由 prompt_toolkit 默认处理。

### Ctrl+C startup/active/double

- startup SIGINT：`_run_existing_session_startup_handling_sigint` 用 `asyncio.wait(FIRST_COMPLETED)` 竞争 startup task 和 sigint_task，SIGINT 先到 → `EXIT_KEYBOARD_INTERRUPT`；
- active 第一次 SIGINT/Ctrl+C：`_request_interactive_cancel` 设置 `cancel_reason`、切换 phase 为 CANCELLING、等待 acceptance 后启动 cancel task；
- active 第二次 Ctrl+C：`exit_intent = EXIT_AFTER_CANCEL`，render 退出提示；
- active 第三次及以后：no-op（`cancel_reason is not None and exit_intent is EXIT_AFTER_CANCEL`）；
- OS SIGINT 和 composer Ctrl+C 共用同一 `_request_interactive_cancel` 路径，生命周期一致。

### Type-ahead / queue / terminal races

- sole QUEUE：active turn 运行中 Enter → `queued = _start_interactive_queued_followup(...)`，最多一个 queued slot；
- third submit → `"one follow-up is already queued; draft kept"`，不提交；
- terminal/Enter race：`test_interactive_terminal_enter_race_submits_exactly_once` 参数化 `enter_before_terminal={True,False}`，验证两种顺序都得到恰好两个 QUEUE Run；
- stale generation guard：`stale_control` 检查 `completion.generation != generation`，丢弃过期 cancel/toggle 事件。

### 真实 Host integration

- `_start_tty_driver` 使用 `_ControlledInteractiveHost` + `_ScriptedComposer` + `_NoopSigintMonitor` 启动 `_drive_interactive_tty_repl` task；
- `_ControlledInteractiveHost.submit_followup` 返回 `FollowupSnapshot`，绑定 watcher 到 run_id，通过 `finish_run` 发布 terminal；
- barrier helper（`_wait_for_submit_count` 等）使用 event-loop ticks，不使用固定时长 sleep。
