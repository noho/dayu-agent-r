## 六项 Findings 的根因、Owner 与修复判定

### 1. `prompt.cancel-closeout-reason-ui-leak`

- Root cause：公共 terminal projection 直接消费并展示 Host typed `cancel_reason`，把内部 watchdog/state-machine 事实误投影为用户语义。
- 唯一语义 owner：`dayu/cli/output.py` 的公共 cancelled terminal-result projection；Host/EventLog 继续拥有 typed reason。
- 修改文件：`dayu/cli/output.py`、`tests/cli/test_output.py`、受影响的 prompt/interactive projection tests。
- 修复后：所有 cancelled terminal status 只投影 `Cancelled.`；没有 reason 字符串黑名单、fallback 或下游重算。真实取消屏幕只出现可理解的 cancel requested / cancelled 状态，SQLite/EventLog 仍保留 `active_cancel_watchdog_closeout` 与 canonical cancellation facts。

### 2. `prompt.repeated-ctrl-c-not-graceful`

- Root cause：旧 prompt helper 让 Host terminal waiter 与第二次 SIGINT 竞争，第二次中断可取消 waiter 并在 Host 未终态时退出；进一步的 adversarial review 发现，caller cancellation 还可能丢失 durable submit 已接受但 callback 未交付的 admission 结果。
- 唯一语义 owner：`dayu/cli/session_execution.py` 拥有 prompt 输入中断合并与等待；`dayu/service/entrypoint_runtime.py` 拥有 caller cancellation 与 Host durable admission disposition 的交接；Host 仍是 Run/attempt canonical lifecycle owner。
- 修改文件：`dayu/cli/session_execution.py`、`dayu/service/entrypoint_runtime.py`、`tests/cli/test_prompt_command.py`、`tests/cli/test_interactive_command.py`、`tests/service/test_entrypoint_runtime.py`。
- 修复后：首次 Ctrl+C/Escape 只发起一次 graceful cancel，后续 Ctrl+C 被合并且不能越过 terminal barrier；Service shield submit 直到明确 accepted/rejected。accepted 时先绑定 observation/callback 再传播 caller cancellation；明确 rejected 时 caller cancellation 保持 exit 130 语义，不被后到的 Host rejection 覆盖。没有 sleep、SQLite 补写、CLI 假终态或测试特例。
- 真实结果：P44/P45/P46、PC-BD-02、PC-CN-07 等取消路径均 exit 130；Run/attempt 为 `cancelled`，EventLog 含 `ATTEMPT_CANCELLED`、`RUN_CANCELLED`，退出时没有 running Run/attempt。

### 3. `prompt.startup-ctrl-c-traceback-or-signal-exit`

- Root cause：console script 与 module entry 在 `KeyboardInterrupt -> 130` boundary 建立前 eager import 完整 application；canonical 130 确定后的 Python teardown 还可能被后续 SIGINT 覆盖，command-local monitor cleanup 也没有恢复前任 handler。
- 唯一语义 owner：`dayu/cli/__main__.py` 的公共 process bootstrap/exit boundary，以及 `dayu/cli/agent_entrypoint.py` 的 command-local SIGINT handler lifecycle。
- 修改文件：`dayu/cli/__main__.py`、`dayu/cli/agent_entrypoint.py`、`pyproject.toml`、`tests/cli/test_arg_parsing.py`、`tests/cli/test_prompt_command.py`、`tests/cli/test_public_package_entrypoints.py`。
- 修复后：两种公共入口共用轻量 lazy bootstrap；application import、parser、资源准备和 Run 创建前的 `KeyboardInterrupt` 统一为 130 且无 traceback。monitor 恢复原 handler；仅在 canonical 130 已确定的 teardown 屏蔽后续 SIGINT。P47、PC-CN-01..06 的 frozen installed-console timing 均 exit 130，且没有 Host 业务状态。

### 4. `prompt.logging-selector-and-debug-stream-contract`

- Root cause：旧 parser 缺少完整公开 spelling/shortcut，跨 root/command/action scope 没有 selector occurrence 真源，quiet 被归约为 error；旧 runtime helper 又把 debug-stream 改写成普通最低日志等级，泄漏普通 DEBUG/VERBOSE。
- 唯一语义 owner：`dayu/cli/arg_parsing.py` 拥有公开 invocation grammar 与 canonicalization；`dayu/runtime/log.py`、`dayu/runtime/log_levels.py` 拥有 canonical threshold 和 ordinary/stream admission。
- 修改文件：`dayu/cli/arg_parsing.py`、`dayu/cli/main.py`、`dayu/runtime/log.py`、`dayu/runtime/log_levels.py`，以及对应 parser/runtime tests、README 和一个直接 enum 消费者测试。
- 修复后：七个 canonical level、`warn`/`warning` 两种公开 spelling 与八个 shortcuts 全部由单一 spec 派生；16 个 selector 在同 scope、跨 scope、相同重复时均互斥。debug-stream 位于等级组外、不改变普通 threshold、只精确放行 stream record，并在 parser/runtime 两层拒绝 quiet 组合；log-file 独立。
- 真实结果：PC-LS、PC-DS、PC-DQ、PC-LC 的 exact argv/exit 全部通过。16 个无显式 log-file memory 场景另以实际 anonymous `TemporaryFile` bytes 证明 threshold、quiet、等价 spelling/group set，且没有 `STREAM_DEBUG` 泄漏。

### 5. `prompt.log-file-missing-parent-exit-code`

- Root cause：旧 `_open_log_file` 把空白 argv 和全部 `OSError` 都归类为 usage，统一 exit 2。
- 唯一语义 owner：`dayu/cli/errors.py` 的 typed usage/resource classification 与 `dayu/cli/main.py` 的 pre-primary destination preparation。
- 修改文件：`dayu/cli/errors.py`、`dayu/cli/main.py`、`tests/cli/test_arg_parsing.py`、README。
- 修复后：空白路径仍为 usage exit 2；父目录缺失是 `CliResourcePreparationError`，明确报错并 exit 1。实现直接打开目标，不创建父目录，也没有 blanket exception remap。
- 真实结果：P62 exact argv exit 1；实际 cwd 的默认 `<run-root>/repo/workspace` before/after 均不存在，missing parent/target log 不存在，Host/runtime/session SQLite 不存在，primary operation 零副作用。

### 6. `prompt.invalid-utf8-owner-and-exit-code`

- Root cause：Python 以 surrogateescape 形成的 POSIX argv `str` 被旧 parser 直接接受，surrogate 可进入 runner/下游或在错误输出时再次触发编码异常。
- 唯一语义 owner：`dayu/cli/arg_parsing.parse_cli_args` 的 argparse 前 invocation-text boundary。
- 修改文件：`dayu/cli/arg_parsing.py`、`tests/cli/test_arg_parsing.py`。
- 修复后：所有 argv token 在 argparse 消费前 strict UTF-8 验证；非法 token 只产生固定、脱敏、ASCII-safe diagnostic 并 exit 2，不回显 bytes/token，不使用 replace/ignore/surrogatepass。
- 真实结果：PC-BD-03 raw-byte exec exit 2，无 traceback/UnicodeEncodeError；filesystem、Host/runtime SQLite、EventLog/Tool Trace 和 primary operation 均无副作用。
