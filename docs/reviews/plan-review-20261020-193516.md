### 4.1 BP1（§7 tracked-only 漏检）——判断：**计划层已修复**

**原反例（DS F1）**：`git status --porcelain --untracked-files=no` 在 HEAD 等于核收 OID 时对未跟踪 `scripts/install-source.sh` 返回 0 且空，editable 安装却真实执行该未跟踪脚本 → 正式验收 false pass。

**v2 修法（§7 L181–201）**：四段联合——① `HEAD == ENTRY_APPROVED_OID`；② `ls-files --error-unmatch` 强制五个必要交付文件在索引；③ `git diff --exit-code "$ENTRY_APPROVED_OID" -- <安装输入 pathspec>` 联合②排除“仅 index 收录”（commit↔工作树字节差异即失败）；④ 限定安装输入路径的 `git ls-files --others` 未跟踪扫描必须为空，**只排除四个具名缓存目录、不用 `--exclude-standard`**；另以 prose 要求 `hash-object --no-filters` 对核收 tree 的原始字节 blob 比对、安装前执行+安装后复核指纹。

**直接证据（作者，逐项核对）**：

- `bp1-old-guard-misses-script`：旧 guard 原样命令 → exit **0**、stdout 空（漏检复现）；`bp1-required-script-rejected` → exit **1**（`ls-files --error-unmatch` 拒绝未跟踪脚本）；`bp1-untracked-script`/`bp1-untracked-source`/`bp1-ignored-source-rejected` stdout 分别为 `scripts/install-source.sh`、`dayu/unapproved.py`、`dayu/ignored_source.py`（含被 gitignore 的源码，证明未用 `--exclude-standard` 时 ignore 规则不豁免）。
- `bp1-tracked-change-rejected` → exit 1（对核收 OID 的 diff 输出真实字节差异），`bp1-tracked-restored` → exit 0。
- `bp1-raw-byte-equality.json`：五个输入（pyproject/README/LICENSE/dayu/\_\_init\_\_.py/公共锁）`hash-object --no-filters` == `rev-parse OID:<file>`。
- `bp1-cache-and-unrelated-allowed`：具名 `__pycache__` 与路径外 `workspace/tmp` 存留时清单为空、exit 0。
- `supplement-input-scope-commands.json`：追加的根 `setup.py` 与 `dayu_extra/probe.py`（新 `dayu*` 包根 .py）未跟踪输入均被拒绝。

**本人独立取证**：

- 真实仓库只读执行 fence 实际命令：`git diff --exit-code HEAD -- <pathspec数组>` exit **0**；`git ls-files --others --exclude=<四具名> -- <pathspec数组>` 恰好输出 `dayu/.DS_Store`、`dayu/config/.DS_Store` 两行（非空 → fence 尾部 `[[ -z ]]` 判失败，方向 fail-closed）。

### 4.3 BP3（有效 ZDOTDIR 检测点）——判断：**计划层已修复**

**原反例（DS F3）**：“非标准 ZDOTDIR 明确失败”与验收 `zsh -lic` 无连接：`.zshenv` 重定向后验收读的是另一份 `.zshrc`——既有 PATH 则伪 pass（证明的不是本次写入），无 PATH 则误 fail；或以强制 `ZDOTDIR=$HOME`/`-f` 伪造“正常 shell”。

**v2 修法（§4.1(1)(6)、§4.3 L98、§6.1(3)、§7 L203–212）**：

1. **写前检测**：§4.3 明确“检测点在任何安装/发布写入之前”，§4.1(1) 再钉死“在创建/复用安装环境及任何入口/profile 写入之前完成”——非 HOME 有效值在**任何变更前**失败（含 venv 创建）。
2. **真实启动后查询**：保留用户真实配置与**继承的 ZDOTDIR**，按与 §4.1(6) 相同的源外 cwd/去 venv 环境启动目标 zsh `-ic` **和** `-lic`，查询启动完成后的 `${ZDOTDIR:-$HOME}`（含 `.zshenv` 中途设置），在该 shell 内断言 `[[ "${ZDOTDIR:-$HOME}" -ef "$HOME" ]]`；查询/断言非零即失败。
3. **不伪造**：明文禁用 `ZDOTDIR=$HOME` 与 `-f`；不另找 profile；只接受与 HOME **同一目录**（`-ef` = 同 device+inode，故 symlink 指向 HOME 亦正确放行、HOME 下子目录正确拒绝）。
4. **验收一致**：§4.1(6) 安装后断言、§7 正式验收代码块内同一断言先于 `command -v` 执行；§7 prose 明确“与写前预检一样保留…不强制重设它”。
5. **测试反例**：§6.1(3) 要求覆盖继承重定向与 `.zshenv` 重定向（**含另一份 `.zshrc` 恰好提供正确 PATH 的伪 pass 反例**），断言写前失败且入口与配置原字节不变；标准 HOME 通过；发布后两种正常模式也断言有效值。

**直接证据（作者，argv 逐条核对）**：`commands.json` 中六条 bp3 命令均为 `/bin/zsh -ic|-lic '<查询 + [[ "${ZDOTDIR:-$HOME}" -ef "$HOME" ]] || exit 1>'`，无 `ZDOTDIR=` 覆盖、无 `-f`：

- 标准隔离 HOME：`-ic`/`-lic` exit **0**，`home_rc=yes alternate_rc=`（HOME 配置被读取）。
- 继承非 HOME ZDOTDIR：`-ic`/`-lic` exit **1**，`alternate_rc=yes`（真实读取 alternate，随后被断言拒绝）。
- `.zshenv` 重定向：`-ic`/`-lic` exit **1**，同上。
- 合成配置前后 SHA 不变（`protected-before/after.sha256` 涵盖该比对，本人逐行核对一致；receipt 记六次查询字节不变）。

**本人独立取证**：

- 不存在的 ZDOTDIR：`-lic` 内断言 exit **1**（fail-closed）。
- **zsh 无 HOME 回退**（隔离 HOME probe）：`ZDOTDIR=/nonexistent…` 启动后 `marker=unset`（HOME 的 `.zshenv` 未被读取）→ 证明该状态下写进 `$HOME/.zshrc` 的 block 永远不会加载，目标在该环境本就不可达，**写前拒绝是正确拒绝而非误杀**。

**影响分析**：DS F3 的伪 pass/误 fail 两个方向均被同一断言在写前关闭；三处检查点（写前/安装后/正式验收）语义同源，不存在“检测点在 A、验收在 B”的断连；不强制重设目录，新正常 shell 仍是用户真实启动（与 goal“新正常 shell”定义一致）。**计划层已修复**；预检实现顺序、断言封装位置等局部规格按指令留实施与代码审核。
