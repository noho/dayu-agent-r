### 1-HIGH-runtime-lane-心跳任务重复创建竞态

- **入口/函数**: `LaneController._ensure_heartbeat_task`
- **文件(行号)**: `dayu/runtime/lane.py:869-876`
- **输入场景**: 两个并发的 `acquire()` 调用同时进入 `_ensure_heartbeat_task`，此时 `_heartbeat_task is None` 对两者均为 True
- **实际分支**: 两个协程先后执行 `asyncio.create_task(self._heartbeat_loop())`，第二个赋值覆盖第一个的引用，第一个 task 成为孤儿继续运行
- **预期行为**: 只应存在一个心跳 task，或者在创建新 task 前取消旧 task
- **实际行为**: 孤儿心跳 task 继续无限运行，双重刷新同一批 token 的 heartbeat，如果孤儿 task 遇到 `RuntimeLaneClaimLostError` 会操作已被新 task 修改的 `_held_tokens`
- **直接证据**: `_ensure_heartbeat_task` (line 869) 只有 `if self._heartbeat_task is None or self._heartbeat_task.done()` 作为 guard，无锁保护，无原子性保证
- **影响**: 重复心跳刷新、孤儿 task 资源泄漏、`_mark_token_lost` 在已被移除的 token 上操作可能抛异常
- **建议改法和验证点**: 在 `_ensure_heartbeat_task` 内先 cancel 已有 task 再创建新的；或将 `acquire()` 改为不可重入（同一 controller 同一时刻只有一个 acquire 调用）
- **修复风险（低）**: 修改范围小，逻辑明确
- **严重程度（高）**: 并发场景下确定性可触发

### 2-HIGH-runtime-cancellation-Python3.11协程close不存在

- **入口/函数**: `await_or_cancel` / `await_or_cancel_or_timeout`
- **文件(行号)**: `dayu/runtime/cancellation.py:116-117, 237-238`
- **输入场景**: 调用 `await_or_cancel(some_coro, token=cancelled_token)`，其中 `some_coro` 是 native coroutine object（`async def` 返回值），运行在 Python 3.11 上
- **实际分支**: `token.is_cancelled()` 返回 True → `asyncio.iscoroutine(awaitable)` 返回 True → `awaitable.close()` 抛出 `AttributeError`
- **预期行为**: 取消的协程应被安全清理，返回 `WaitCancelled`
- **实际行为**: `AttributeError: 'coroutine' object has no attribute 'close'` 向上传播，`WaitCancelled` 永不返回
- **直接证据**: Python 3.11 中 native coroutine 的 `.close()` 方法不是公开 API（PEP 661, Python 3.12 才加入）；项目 `pyproject.toml` 声明 `requires-python = ">=3.11"`；pycache 显示 `cpython-311.pyc`
- **影响**: 取消流程中断，异常传播到调用方
- **建议改法和验证点**: 用 `hasattr(awaitable, 'close')` guard 或直接移除 `.close()` 调用（未调度的协程会被 GC 回收，无需显式 close）
- **修复风险（低）**: 一行修改
- **严重程度（高）**: 在 Python 3.11 运行时确定性触发

### 3-HIGH-engine-agent-CONTEXT_COMPACTION_REQUESTED不可操作

- **入口/函数**: `_consume_runner_event` → `_classify_iteration` → terminal
- **文件(行号)**: `dayu/engine/agent.py:1337-1360, 1457-1458`

## 架构边界审计结论

全量 88 个生产文件审计结果：

- **无反向依赖**: `dayu.engine` 无 import from `dayu.host`；`dayu.runtime` 无 import from `dayu.engine`/`dayu.host`/`dayu.fins`；`dayu.contracts` 无 import from 任何上层包
- **无 `Any` 类型**: 生产代码中零使用
- **无 `# type: ignore`**: 零实例
- **`hasattr`/`getattr`**: 2 处，均 justified（标准日志 marker pattern；Python 3.11 sqlite3 属性兼容）
- **无运行时 lazy import**: 唯一的 `TYPE_CHECKING` guard 是标准模式
- **无兼容性 re-export**: `dayu/engine/__init__.py` 的结构性 re-export 是有意的架构设计
- **类型安全**: 全项目零 `Any`、零 `# type: ignore`、全量类型标注、广泛使用 `Final`/`TypeGuard`/`Literal`/`assert_never`

**架构边界：无违规。**
