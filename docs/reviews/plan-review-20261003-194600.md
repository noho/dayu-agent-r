## 2. 关键假设与证伪尝试（assumptions tested）

- **A1 stdlib 逃逸机制**：「`StreamHandler.emit` 自行吞普通故障并逃逸公共 stderr」为真——真实 stdlib 源（SHA `fb2531d0`）`emit`：`except RecursionError: raise; except Exception: self.handleError(record)`；`handleError` 在 `raiseExceptions and sys.stderr` 下直接 `sys.stderr.write('--- Logging error ---\n')` + traceback + call stack + Message/Arguments（内部对 OSError 静默、对 RecursionError re-raise）。`Handler.handle` 为 filter→acquire→emit→finally release（锁在 handle，不在 emit）。root probe 真实复现 878 bytes 公共 stderr（exit 0）。**DN-R7 动机真实成立。**
- **A2 四类控制流**：KeyboardInterrupt/SystemExit/asyncio.CancelledError/GeneratorExit 均非 `Exception` 子类，stdlib 的 `except Exception` 与其一致地不捕获；计划同界（仅 `except Exception`）。
- **A3 RecursionError**：是 `Exception` 子类。计划专用方法会将其 containment 为 False；stdlib emit 选择 re-raise（且 handleError 打印路径再 re-raise）。计划未点名，但代码形状唯一确定归类，且不写公开 fd、不递归打印，与 DN-R1 补充的四类封闭清单一致（见 R2）。
- **A4 唯一 owner 可取得**：`configure()`（log.py L312–336）先 `_reset_marker_handlers(namespace_logger)` 再 `addHandler` 恰好一个 marker；namespace `propagate=False`；root twin 只挂 root logger。helper 从 `logging.getLogger("dayu").handlers` 以 `isinstance` 发现：必唯一、不会命中 root twin、不会双投递。多次 configure 由原去重规则保证仍唯一。
- **A5 仅换构造类型即可复用既有配置**：`_build_marker_handler`（L399–426）唯一构造行为是 `logging.StreamHandler(stream=stream)`，随后 setLevel / `addFilter(同一 _DiagnosticAdmissionFilter 实例)` / setFormatter(`_LOG_FORMAT`,`_LOG_DATE_FORMAT`) / 打 marker attr；`_reset_marker_handlers` 按 marker attr 去重。全仓（`dayu/`、`tests/`，除 log.py 自身）grep 无任何 `StreamHandler` 引用；既有 `tests/runtime/test_log.py` 通过 `_MARKER_ATTR` 属性发现 handler（L44/277–278），无 exact-type 断言 → 子类换型不破坏既有 owner 测试，「handler 身份=marker 装配/去重身份」读法成立。
- **A6 源身份零漂移**：`_LOG_FORMAT="[%(asctime)s] [%(levelname)s] [%(name)s] %(message)s"` 只消费 created/levelno/name/message——正是 delta 承诺保持的四字段；无 filename/lineno 暴露面；datefmt 不变。
- **A7 锁纪律无死锁**：Handler 锁为 RLock；专用方法 acquire 后调用 stdlib `StreamHandler.flush`（同线程 re-acquire 可重入）；proof 以真实 configure 借出的 level/formatter/filter 在候选实例上真实跑通 write/flush/formatter 负例与四控制流（同对象传播、锁释放）。

## 3. DN-R7 判定：计划已修（plan-level fixed）

实现/业务验证按计划归 S1 未来 gate，本报告不虚报产品修复。判据（全部直接证据）：

1. **逃逸面闭合**：唯一投递路径为专用 `try_deliver_process_record`；`except Exception` 内 format/write/flush/锁的普通故障返回 False，不调用 `StreamHandler.emit`/`handleError`、不写公开 fd、不递归报告；未 configure/缺失/非唯一 owner 返回 False 且加粗禁止 `namespace.handle/callHandlers`、root、lastResort、第三方兜底——关闭旧文本「未 configure 走 stdlib 路由」的公共 stderr 逃逸（§4.1 L85/L87）。
2. **containment 集与实际机制同源**：stdlib emit 的吞错分支（格式化/write/flush → handleError → stderr）在新路径全部就地 False；RecursionError 归入 Exception → False（比 stdlib re-raise 更安静且无递归打印风险）；四类控制流不在 containment，`finally` 释放锁后同对象传播（§4.1 L87；§6.1 要求四类断言）。
3. **无旁路手段**：显式排除全局 raiseExceptions 开关、方法 monkeypatch、CLI 过滤、另建 handler/formatter/filter 副本；proof 断言 raiseExceptions 原值不变。
4. **身份/等级/过滤/format/目的地/marker 去重保持**：构造类型为唯一变化；level/filter 实例/formatter/datefmt/stream/marker attr/装配/去重不变（A5/A6）；「一次投递」由直接调用唯一实例 + namespace `propagate=False` 保证（proof 断言单次出现与四字段不漂移）。
5. **范围外正常 logger 无漂移**：子类不覆写 `emit/handleError/handle/flush`，普通日志路径保持 stdlib 行为；与 root finding `required`（非转发 logger 行为不得越界更改）逐字一致。
6. **Fins 侧无下游 fallback/重试/回写**：helper False 或 reporting 普通 Exception 即结束本次报告（§4.1 L89、§5.2 L143）；不改 outcome/descriptor/rmtree 优先级；控制流回原收口后 re-raise。
