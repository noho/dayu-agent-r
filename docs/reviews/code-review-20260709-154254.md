## Open Questions

### OQ-1: `_bounded_preprocess_summary` 缺少跨字段不变量校验

`_bounded_preprocess_summary`（line 5747-5792）校验了各计数字段非负以及各计数与对应 ID tuple 长度一致，但**未校验** `selected_count == processed_count + skipped_count + failed_count + not_supported_count` 这一跨字段不变量。

当前生产代码 `_execute_preprocess_request`（line 3591-3605）始终将 `document_ids` 完整分区到四个子桶中，因此该不变量在生产路径中自然成立。但 `FinsPreprocessResultSummary` 是 `__all__` 中导出的公共 dataclass，`result_status()` 和 `to_json_summary()` 是公共方法，当未来新增构造路径或测试夹具构造不一致摘要时，`result_status()` 可能返回错误的业务状态。

是否需要在 `_bounded_preprocess_summary` 中新增该跨字段校验，遵循 "fail fast" 原则？

### OQ-2: `read_runtime.py` 中 `meta is None` 时默认 `FinsIngestMethod.UPLOAD` 的正确性

`read_runtime.py:1697-1701` 在 `meta is None` 时默认 `FinsIngestMethod.UPLOAD`，导致 `source_type = SourceType.UPLOADED.value`。对于 `document_id` 以 `fil_` 开头（SEC filing 前缀）的文档，如果 meta 缺失（数据完整性异常），将其分类为 `UPLOADED` 而非 `SEC_EDGAR` 是否在 full-new-schema 下是正确语义？

旧代码有相同行为（`ingest_method = meta.get("ingest_method") if meta else None` → `source_type = UPLOADED`），P0-B 使其更显式但未改变语义。如果 `fil_` 前缀文档的 meta 缺失应视为数据完整性错误而非静默默认，则此行为可能需要在后续 sub WU 中处理。

## Residual Risk

1. **`result_status()` 测试覆盖不足**：现有测试只覆盖了 `skipped_only`（SUCCEEDED）和 `unsupported_only`（FAILED）两种场景。未覆盖：`processed_count > 0` 的 trivial success、`selected_count == 0` 的 trivial failure、`failed_count > 0` 的 failure、以及 mixed 状态（部分 processed + 部分 failed）。`_bounded_preprocess_summary` 的校验失败路径（负数计数、计数与 ID 列表不一致）无直接单元测试。

2. **`FinsUploadPipelineResult.from_pipeline_json()` 测试覆盖不足**：只测试了 `status` 缺失时抛 `ValueError`。未覆盖：可选字段类型非法时的校验行为（如 `deleted` 为字符串而非布尔值）、`status` 为空字符串时的行为。

3. **upload pipeline result status 未做枚举校验**：`FinsUploadPipelineResult.status` 是 `str` 类型，`from_pipeline_json()` 只校验非空文本，不枚举合法值。当前 pipeline 实现（`DoclingUploadService`）固定产出 `"uploaded"` / `"skipped"` / `"deleted"` / `"cancelled"` 等值，但未在 contract 层定义合法集合。若 pipeline 实现未来变更或新增 pipeline 产出未预期的 status 值，下游 `_UPLOAD_RESULT_STATUS_FAILED` 比较逻辑可能漏判。此风险属于 P0-B scope 边界外（P0-B 只要求 "不允许 runtime 用缺省值伪造"），但记录供后续 sub WU 参考。

4. **`SecPipeline` 的 `_build_result` 仍在 P0-B scope 外**：`dayu/fins/pipelines/sec_pipeline.py` 不在 P0-B allowed files 列表中。当前 SEC upload 路径通过 `sec_upload_workflow.py` → `DoclingUploadService` 产出现有 status 值，不受影响。但若未来 SEC download 路径的 result 语义需要收敛，该文件需纳入后续 sub WU。
