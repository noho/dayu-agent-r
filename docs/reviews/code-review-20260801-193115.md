### 1. Stale boundary 与 retry_not_before

- **`recovery_process.py:272`**：stale 边界从 `<=` 改为 `<`，`elapsed == stale_after` 时进入 stale classification 而非 recent。测试 `test_stale_threshold_boundary_is_recent_only_before_deadline` 覆盖 29/30/31 三个边界点，29→`OwnerStillLive`，30→`PositiveOrphanProof`。
- **`retry_not_before` 来源**：只有 `owner_heartbeat_recent` 分支从 `heartbeat_at + stale_after` 同源产生；`process_identity_matched` 明确为 `None`；pid missing/stopped/inconclusive 不产生 deadline。
- **`next_reconcile_at` 聚合**：`_earliest_retry_not_before()` 在 batch 级和 scanner 级两处调用，跨 bounded pages 取 min。scanner 使用固定 `policy.now`、fixed watermark、bounded pages，不读取第二套时钟，不循环扫描。测试 `test_scan_aggregates_earliest_recent_heartbeat_deadline_across_pages` 以 `batch_size=1` 强制多页并验证 earliest aggregate。
- **PASS**：stale 边界精确、deadline 只来自可解析 heartbeat、聚合不破坏 fixed now/watermark/CAS。

### 2. Initial scan activation 后至多一个 task、one-shot delayed

- **`open_host.py:1230`**：initial scan 完成、recovery/health leases 释放、allocation 激活后，才消费 `next_reconcile_at`。
- **`_schedule_delayed_attachment_recovery`**：以 `session_id` 为 key，重复 key 抛 `RuntimeError`。
- **`_sleep_until_recovery_deadline`**：UTC deadline → 单次 monotonic delay → 单次 `asyncio.sleep`。不 polling。
- **`_run_delayed_attachment_recovery`**：sleep 后以 `_utc_now()` 创建新 operation（fresh now），执行一次 scan，不循环。
- **测试覆盖**：`test_immediate_fresh_attach_delays_once_then_recovers_with_fresh_now` 冻结 sleep、验证 deadline 前零 mutation、sleep 后以 fresh now 恢复，且 `observed_times == [initial_now, delayed_now]` 证明时钟不复用。
- **PASS**：一个 task、UTC deadline 一次转换、monotonic delay、fresh now、one-shot，不形成 polling 或其它 Session scan。

### 3. New-work lease 与 actor future 绑定；竞态安全

- **`_run_delayed_attachment_recovery`**：`try_acquire_new_work_lease` 失败直接返回；成功后 `submit` actor，`work_lease.release_when_done(actor_future)` 绑定 future。
- **CancelledError 路径**：actor_future 非 None 时 `await asyncio.shield(actor_future)` 等待收口；异常报告 fatal 后 re-raise。
- **finally 块**：`work_lease is not None` 时 release（future 未提交的场景）；task 从 dict 中移除自身（仅当仍是 current task 时）。
- **Host close 顺序**（`open_host.py:1847-1856`）：`begin_host_close()` → `_cancel_and_join_all_delayed_attachment_recoveries()` → `begin_closing()` → `stop_and_drain()` → `drain_host_close()`。延迟 task 取消在 actor stop 前完成。
- **`_cancel_and_join_delayed_attachment_recovery`**：pop dict → cancel → shield(task)。CancelledError 时返回（正常 cleanup）。非 cancellation 异常透传。
- **测试覆盖**：`test_host_close_cancels_all_sleeping_delayed_recovery_tasks_before_actor_stop` 在 actor stop 入口设 barrier，验证 dict 为空且 task 已取消；`test_attachment_close_cancels_sleeping_delayed_recovery_without_facts` 验证零 EventLog mutation；`test_attachment_close_joins_submitted_delayed_scan_before_mutex_release` 验证 actor 已提交时 close 等待 future 且竞争 opener 保持 RO。
- **PASS**：所有竞态（attachment close/Host close/caller cancellation/child CancelledError/actor failure）均 join；不提前释放 mutex、不吞异常、不泄漏 task、不把正常完成报 fatal。

### 4. Managed wrapper 保持 public Protocol 行为

- **`_ManagedHostSessionAttachment`**：实现 `session_id`、`access_mode`、`aclose()`，满足 `HostSessionAttachment` Protocol。
- **`aclose()` 幂等**：`_close_task` 只创建一次；并发/重复 close 共享同一 cleanup task；`asyncio.shield` 防止 caller 取消。
- **`_close_managed_attachment`**：先 `_cancel_and_join_delayed_attachment_recovery`，再 `attachment.aclose()`。顺序保证 delayed task 取消在底层 attachment close 前。
- **schedule 失败清理**：`attach_session` 中 `_schedule_delayed_attachment_recovery` 抛异常时 `await asyncio.shield(attachment.aclose())` 回滚。
- **PASS**：public Protocol 行为保持、幂等、cancellation-safe。
