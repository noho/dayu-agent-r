## 新增 Review（复审 diff 走读）

### 正常路径清理时序

controller 在 `_submit_*_turn_handling_sigint()` 中创建，`finish_runtime_display()` 按 thinking → activity 顺序清理，`close()` 按 thinking → activity 顺序关闭。两条路径（prompt/interactive）行为一致。

### 取消路径清理时序

controller 的 `finish_and_close_thinking()` 在 SIGINT 后立即调用，关闭 thinking 并清除 guard。后续 `render_cancel_requested()` / `render_local_exit_after_cancel()` 通过 controller 调用 activity display，受 `_activity_closed` 守卫保护。

### `close()` 方法内部时序

`close()` → `close_thinking()`（关闭 thinking + 清除 guard）→ `close_activity()`（清除 guard + 关闭 activity）。`close_thinking` 先于 `close_activity`，确保 thinking guard 在 activity 关闭前被清除。`close_activity()` 内的 `clear_runtime_line_guard()` 在 `close_thinking` 已清除后为冗余调用，但保证了 `close_activity()` 独立调用时的正确性。

### prompt 与 interactive 生命周期差异

- **prompt**: 每轮创建新 controller → 轮结束后 `runtime_display.close()` 统一关闭
- **interactive**: 每轮创建新 controller → 轮结束后 `clear_runtime_line_guard()` + `close_thinking()`；view 在 REPL 外层 finally 通过临时 controller 的 `close_activity()` 关闭

差异源于 view 跨轮复用的设计，controller 正确适配了两种生命周期。

### `_activity_closed` / `_thinking_closed` 幂等守卫

所有 close/finish 方法均有 `_xxx_closed` 守卫，保证：
- 取消路径的 `finish_and_close_thinking()` 与 finally 的 `close_thinking()` 不冲突
- 多次调用 `close()` 幂等安全
