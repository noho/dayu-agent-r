### 1-未修复-严重-engine_ingest._validate_durable_context 缺少 current_attempt_id 校验，过期 Worker Event 可污染 EventLog

- **入口/函数**: `_validate_durable_context` → `_late_rejection_reason` → `_ingest_validated`
- **文件(行号)**: `dayu/host/engine_ingest.py` L853-868, L2484-2503, L835-840
- **输入场景**: Run 被 steer 产生新 Attempt A2 后，旧 Attempt A1 的 worker 仍有未消费的 EngineEvent（如 CONTENT_DELTA）
- **实际分支**: `_validate_durable_context` 只校验 attempt_id/execution_id/dispatch_record_id 的身份一致性，不校验 `run.current_attempt_id == envelope.attempt_id`。`_late_rejection_reason` 只检查 Run/Attempt 是否终态（terminal_event_id 不为 None），旧 Attempt A1（STEERED 但非终态）会被放行。非终态 preview 事件（CONTENT_DELTA 等）被写入当前 Run 的 EventLog 但标记旧 attempt_id
- **预期行为**: 非当前 Attempt 的 EngineEvent 应被拒绝，不写入 EventLog
- **实际行为**: 过期 worker 的 preview/diagnostic 事件通过 durable context 校验，被错误 ingest，污染下游 projection

- **影响**: 过期 worker event 污染 EventLog，下游 memory projection/timeline/audit 读取到属于错误 Attempt 的事件
- **建议改法和验证点**: 在 `_validate_durable_context` L860-868 中增加 `run.current_attempt_id != envelope.attempt_id` 检查，返回 REJECTED+stop_worker_stream。验证：steer 后旧 worker 产出的事件被拒绝，新 worker 的事件正常 ingest
- **修复风险（低）**: 仅增加一个校验条件，不影响现有正确路径
- **严重程度（严重）**:

### 2-未修复-严重-tool_call_aggregator 合成 index 与 provider 原生 index 碰撞，两个不同工具调用数据被错误合并

- **输入场景**: Provider 首个 tool call delta 缺失 `index` 但有 `id`，`_allocate_synthetic_index()` 从 0 开始分配。随后 provider 再发出另一个 tool call 的 delta 且 `index=0`

## Residual Risk

- **测试覆盖缺口**：`dayu/host/durable/run_transition.py` (2900+ 行)、`state.py` (3700+ 行)、`idempotency.py` (289 行)、`liveness.py` (580 行)、`event_log.py` (900 行) 等关键 CAS/transition 模块无 direct 单元测试，仅通过集成测试间接覆盖部分路径
- **并发 Race Condition**：dispatch 路径中的 `asyncio.sleep(0)` 窗口在当前单线程 asyncio 模型下风险可控，但缺乏文档说明和并发模型假设

- **Engine Event 版本兼容**：Engine 新增 event type 时，旧版 Host 会 stop_worker_stream + reject，可能导致 Run 永久无法正常收口
