**完整 backpressure 链**（plan §4.3）：
> Service `await queue.put` 阻塞 → 停止 Host iterator `__anext__` → Host merge iterator 暂停 → Host subscription bounded queue 被 hub `put_nowait` 填满 → subscription owner detach/overflow → iterator 在连续前缀后抛 typed `UNAVAILABLE/slow_consumer` → `_WatcherFailure` 保存原 `HostApiError` → typed diagnostic / Outbox terminal fallback 收口

**terminal/outbox 无死锁**（plan §4.3）：
> relay 满时 terminal 仍由 durable EventLog/Outbox owner提交，Service 在 relay 恢复消费并观察 typed failure 后必须能从既有 Outbox fallback 取得同一 terminal identity，不得丢失或死锁。

**验证点**（plan §8.4）：
> 构造 relay 满、Host overflow 与 durable terminal/outbox 紧邻的受控场景，断言 bounded prefix 后 error 可见、Outbox terminal identity 未丢、Run 不 cancel/fail、等待在 timeout 内收口且 final 只输出一次。

### 为什么不是 new finding

**唯一 watcher runtime queue/factory owner、terminal-only 排除、typed slow-consumer 到 terminal/outbox 无死锁传播均已精确指定。**

## 裁决 C：attach/cursor error timing、Host public typed error 与 cleanup

### 裁决：**FIXED**

### 证据

**Public lifecycle gate**（plan §4.2）：
> 同步调用 `watch_session_events` 时先完成 public lifecycle gate；handle 已关闭时当场抛 `HostClosedError`，且不创建 subscription。

**Cursor failure contract**（plan §4.2）：
> iterator 首次 `__anext__` 必须先 await cursor future；Session 不存在/已 purge 时抛 public `HostApiError(code=NOT_FOUND, retryable=False)`。其它 durable cursor read failure 继续由 `HostCommandHandle._run_read` 的 public error mapping 表达为 `HostApiError`……不得泄漏 `HostDurableError`、actor future/private operation exception。

**Closable iterator owner**（plan §4.2 + §5.3）：
> Host 返回的内部 closable iterator 必须拥有 subscription 与 cursor future，而不能只依赖 async generator 首次进入后的 `finally`。调用方取得 iterator 后从未开始迭代便立即 `aclose()`，也必须 detach；cursor future 由 done observation/owner cleanup 收口，不产生 unhandled-future warning。

> Host 内部 closable iterator 是 cursor future 与 subscription 的共同 owner，不能把 never-started cleanup 寄托在 async generator body 的 `finally`。

**幂等 cleanup boundary**（plan §5.3）：
> 首次 `__anext__` 的 cursor await、后续 merge iteration 与显式 `aclose()` 共享同一幂等 cleanup boundary；cursor typed failure、消费者 task cancel、iterator 异常、正常/never-started `aclose()` 都关闭 subscription，只清理自身，不调用 Host cancel API、不写 EventLog。

**同步 attach 回滚**（plan §5.3）：
> 同步 public lifecycle gate 后，在方法返回 iterator 前注册 subscription 并提交 cursor future；任一步同步失败都回滚 subscription。

**测试覆盖**（plan §8.3）：
> cursor future failure、首次 `__anext__` cancellation、后续 iteration cancellation/error、started `aclose()`、never-started immediate `aclose()` 各自把 subscription count 恢复到 attach 前；同步 attach 中途失败同样回滚，future exception 已观察且无 pending task/warning。

### async generator never-started finally 问题分析

当前 `_watch_session_events`（`open_host.py:911-934`）是裸 `async def` generator。Python async generator 的 `finally` 只在 generator 被至少迭代一次（首次 `__anext__` 进入 body）后才执行。若调用方拿到 iterator 后从未 `__anext__` 就 `aclose()`，`finally` 不执行，资源泄漏。

plan 的解决方案是：不用裸 async generator，改用显式类实现 `__aiter__`/`__anext__`/`aclose`。`aclose` 是独立方法，无论是否迭代过都执行 cleanup。cursor future 在 `aclose()` 或 done callback 中被观察/收口。这是标准 Python 异步资源管理模式，可直接实现。

**adjudication**: plan 已精确定义了 closable iterator owner 的职责边界与所有 cleanup path。

### 为什么不是 new finding

plan 对 cursor error timing（同步 lifecycle gate 抛 `HostClosedError`、首次 `__anext__` 抛 missing/durable typed error）、public error 类型（只抛 `HostApiError`/`HostClosedError`，不泄漏 `HostDurableError`/actor exception）和 cleanup（幂等 detach、同步 attach 回滚、never-started aclose）均已精确指定。具体实现（class-based iterator vs async generator wrapper）是 implementation-level 决策，plan 已给出足够契约。

**attach/cursor error timing、Host public typed error 和 full cleanup（含 never-started aclose）均已精确、可实现。**
