以下是对四个核心变更维度的 adversarial verification 摘要：

### F01 — --config 彻底消失

- `build_parser()` 让 `_register_prompt_command` / `_register_interactive_command` 使用不含 `--config` 的 `command_common_parent`（`arg_parsing.py:249-250`）。`_build_runtime_arguments_parent` 才定义 `--config`，prompt/interactive 的 parser 不继承它。
- `_reject_disallowed_explicit_config()`（`arg_parsing.py:289-313`）在 `parse_cli_args` 末尾、command runner 前，对 `init`、`prompt`、`interactive`、`session resume` 四种命令拒绝 `config_dir is not None`。该函数在 `_finalize_log_level_selection` 之后调用，确保 root-before-command 的 `--config` 也被拦截。
- `_prepare_session_runtime()`（`session_execution.py:496-512`）固定传 `explicit_config_dir=None`，已删除 `resolve_explicit_config_dir` 参数。
- `rg` 确认 `dayu/cli/commands/prompt.py`、`dayu/cli/commands/interactive.py`、`dayu/cli/session_execution.py` 中零 `--config`、`args.config_dir`、`resolve_explicit_config_dir` 残留。
- `test_agent_surfaces_reject_config_in_every_parser_position` 覆盖 `--config` 在 command 前和 command 后两个位置、prompt/interactive/session resume(prompt mode)/session resume(interactive mode) 六种组合，均断言 `EXIT_USAGE_ERROR`。
- `test_non_agent_runtime_commands_accept_config_before_and_after_command` 覆盖 download 和 session list/purge 的正向 config 用例不回归。

### F02 — interactive ticker 彻底消失

- `_register_interactive_command()`（`arg_parsing.py:635-640`）不注册 `--ticker`。
- `build_interactive_context_slot_values()`（`interactive.py:175-188`）改为无参接口，固定 `ticker=None, fmp_api_key=None`。
- `prepare_interactive_session_execution()`（`session_execution.py:275-320`）不接受 `ticker` 参数，固定 `ticker=None` 传给 `new_cli_invocation`。
- `_reject_interactive_resume_ticker()`（`session.py:567-578`）在 `_run_session_resume` 进入 runtime prepare 前拒绝 interactive mode 的 `--ticker`。该拒绝在 `prepare_interactive_session_execution` 调用之前（`session.py:287-288`）。
- prompt 与 prompt-mode resume 的 `--ticker` 保留：`_register_prompt_command` 注册 `--ticker`（`arg_parsing.py:614`），`_resume_prompt_ticker` 读取 `args.ticker`（`session.py:555-564`）。
- `rg` 确认 `dayu/cli/commands/interactive.py` 和 `dayu/cli/session_execution.py` 中零 `--ticker`、`args.ticker`、`_interactive_ticker`、`_resume_interactive_ticker` 残留。

### F03 — 唯一 cli.agent.\<label\> owner

- `CLI_AGENT_SESSION_SCOPE = "cli.agent"` 和 `CLI_AGENT_SLOT_KEY_PREFIX = "cli.agent."`（`host_context.py:26-27`）替代旧 `PROMPT_SESSION_SCOPE`/`INTERACTIVE_SESSION_SCOPE` 及其 prefix。
- `cli_label_slot_key()`（`host_context.py:83-92`）是唯一 label→slot key 映射入口。`slot_ref_for_cli_label()`（`session_identity.py:42-53`）直接委托给它。
- `_ensure_prompt_session` 和 `_ensure_interactive_session` 均调用 `cli_label_slot_key` 并使用 `CLI_AGENT_SESSION_SCOPE`。
- `CliSessionLabelKind` 枚举已删除；`session --kind` 参数已删除；`_add_session_selector_arguments` 不再注册 `--kind`。
- `CliSessionDisplayKind` 用 `LABELED` 取代 `PROMPT`/`INTERACTIVE`；`display_identity_from_slot` 只识别 `cli.agent.*` namespace，旧 `cli.prompt.*`/`cli.interactive.*` 投影为 `OTHER`。
- `rg` 确认 `dayu/cli` 中零 `PROMPT_SESSION_SCOPE`、`INTERACTIVE_SESSION_SCOPE`、`CliSessionLabelKind`、`prompt_slot_key`、`interactive_slot_key`、`--kind` 残留。
- `rg` 确认 `dayu/` 中零 `cli.prompt.`/`cli.interactive.` slot namespace 引用（仅测试中断言旧 namespace 行为为 OTHER 时出现，属于预期）。

### F04 — exact Session 与 memory/runner input continuity

- `test_labeled_agent_surfaces_share_exact_session_and_prior_turn_runner_input`（`test_entrypoint_runtime_interactive_path.py:436-622`）覆盖四种 labeled 顺序（prompt→prompt、prompt→interactive、interactive→prompt、interactive→interactive）。每种顺序通过 `FinalAnswerWorkerFactory` 的 `requests`/`snapshots` 列表直接断言：
  - `first_snapshot.session_id == second_snapshot.session_id`（exact Session 共享）
  - 第二轮 `AgentRunRequest.messages` 包含第一轮 UserMessage 和 AssistantMessage（memory continuity）
  - 第二轮 UserMessage 最后一条是 second_prompt（input continuity）
- `test_unlabeled_agent_invocations_use_fresh_session_without_prior_memory`（`test_entrypoint_runtime_interactive_path.py:628-744`）覆盖 prompt 和 interactive 各自连续两次无 label invocation。断言：
  - `session_id` 不同（fresh session）
  - 第二轮 messages 不含 AssistantMessage（无前轮 memory）
- 测试通过真实 `cli_main.main()` → Service → Host → Engine worker 路径，不 mock Host API 或 session resolution。
- `_RecordingHostOpener` 使用 `open_host(replace(options, worker_factory=worker_factory))` 接入真实 Host，只替换 worker factory。
