## 反例压测结论

### 1. 相同 basename + 相同 bytes 双路径 primary flip

两个不同规范路径 P1/P2 投影出相同 descriptor D，同一请求 `files=[P1,P2]`：

- primary=P1 与 primary=P2 两次 v2 payload 均为 `{fingerprint_version, primary:D, companions:[D]}`，digest 相同，
  `identical_skip_safe=False`。翻转后不可能 skip；role-to-asset 关联经
  `_build_filing_original_asset_identity(filing_primary)` → `assets[].name` exact 命中，P1/P2 的 path-derived identity
  不同，命中无歧义，converter 使用 P2，`primary_document`/`derived_from` 更新为 P2 派生 identity。§5.2 已要求断言
  角色指针更新。**设计正确，保守兜底成立。**

**完备性证明**（本 review 独立推演）：对固定 descriptor 多集，v2 digest 相等 ⇒ primary descriptor 相等且 companions
多集相等。若 `safe=True`，primary descriptor 在该多集中唯一，任何同 digest 请求的 primary 只能是同一 descriptor 文件，
角色翻转不可能发生；若 primary descriptor 落在重复等价类，必然 `safe=False` ⇒ 永不 skip。因此“错误 skip”在 v2
contract 下不可能发生。§4.4 的 unsafe 判定条件（primary descriptor 与任一 companion 全字段相等）恰好是该完备条件的
精确刻画，无遗漏。

### 2. 普通不同 descriptor primary flip

descriptor 可区分时，primary 翻转必然改变 v2 payload 的 primary 字段 → digest 改变 → update/version increment。
§5.1 已冻结断言（not skipped、fingerprint 不同、version=v2、converter 只收到 B、snapshot `primary_document`/
`derived_from`/`get_primary_source()` 指向 B）。**设计正确，测试覆盖。**

### 3. 请求顺序变化

primary 由 identity 定位（与顺序无关），companions 稳定排序。§5.1 末项（同 primary/companions、仅改变 companion
相对顺序 → fingerprint 相同且可 skip）已固定。**无 input order 依赖，测试覆盖。**

### 4. 整组跨目录移动（multi-file）

全部文件换目录、basename/content/primary 不变：descriptors 不变 → digest 不变 → safe 情形 identical-skip。与
单文件 move 语义（goal 3.1.4）及 goal 3.1.2 一致，且与“fingerprint 排除 path identity”的原 plan §12 边界一致。
**设计正确**，但 §5 只固定了单文件 move（§5.3）与多文件 reorder（§5.1），多文件整组移动的 skip 未由 owner test
固定 → Finding 1。

### 5. 重复重传

- safe 情形：第二次重放 digest 相同、safe=True → skip、version 不增长（§5.1 已断言）；
- ambiguous 情形：每次原样重放都 update/version increment（§5.2 已断言）。无限 version churn 真实存在且被 §10
  第 1 行明确分类为 accepted conservative boundary。独立推演确认：一旦集合变化使 primary descriptor 重新唯一
  （如换成不同内容的 companion），digest 改变 → update，之后同集合重放恢复 skip，不会永久锁死。churn 的根因是
  精确区分 ambiguous flip 必须把 path-derived identity 写入 fingerprint，而这会破坏 move identical-skip ——
  amendment 选择保守方案是该张力的正确解法，且已诚实文档化。**接受，已分类。**

### 6. old v1 persisted fingerprint

- 旧多文件 digest（无角色排序 list）与 v2 dict envelope digest 必然不同（非 SHA-256 碰撞）→ 首次 upsert 必然
  update/version increment，不做 dual-read。单文件旧 digest 与单文件新 digest 公式相同 → 普通单文件重传仍
  identical-skip，不产生无谓 update。
- 该过渡行为由 digest 不等自动导出，**设计安全**；但 §4.3 与 §10 第 2 行声称的
  “fixed by safe version transition”没有 §5 测试用旧公式 digest 夹具固定 → Finding 2。

### 7. overwrite / delete / material

- overwrite：§4.4 要求 `_can_skip_upload` 先检查 overwrite/previous/deleted 既有条件，现有实现
  （`1215-1220`）顺序保留，overwrite 恒不 skip，语义不变；
- delete：`prepare_upload` 在 fingerprint 构造前早退（`320-326`），`filing_primary=None` 永不进入 builder；
- material：公式、固定向量 `099dc963...1d7fdd`、skip/update/version 全部保持，`identical_skip_safe=True`；
  §5.3 已要求固定向量逐字节断言。
**无回归路径。**

### 其它核对项

- **路径 identity 泄漏**：v2 payload 只含 descriptors；role-to-asset 关联的内存中间量不序列化；§5.2 显式断言
  source meta/payload 无绝对路径明文。无泄漏。
- **schema 扩大**：`identical_skip_safe` 仅 preparation 内使用不持久化；`fingerprint_version` 在 digest 字符串内部，
  持久化字段仍是 `source_fingerprint: str`；`_UploadSourceFingerprint` 为模块私有。无 public/storage schema 扩大。
- **exact owner**：root cause 在 `DoclingUploadService` 的 fingerprint/skip owner；角色事实唯一来源是
  `FinsUploadFilingFiles.require_primary()`（`upload_format_contract.py:436-447`）；禁止读旧 `primary_document`、
  禁止从 `ordered_files[0]`/`converter_inputs[0]` 反推（§4.1）与语义所有权约束一致。
- **函数签名**：§4.2 三个冻结签名与现有调用点参数顺序兼容（`_can_skip_upload(previous_meta, fingerprint, overwrite)`、
  `_resolve_document_version(previous_meta, fingerprint)` 均保持位置语义）；`prepare_upload` 两处
  `source_fingerprint` 传递需改为 `.value`，§4.5/§7 item 2 已覆盖（“持久化仍只写现有 digest string”）。
- **payload versioning**：`filing-primary-role-v2` 为模块级 `Final[str]`；单文件公式不升级（避免普通单文件
  identical-skip 被无意义打断）；material 无 version 字段。versioning 策略正确。
- **README Finding 2 修正**：§6 的 5 项改动与 `dayu/fins/README.md:572/574` 实际漂移内容逐条对应，且明确“不要声称
  仅 role bool 可解决”，与 §2.3 的反例证明一致。
- **residual 分类**：§10 七行全部有分类与 destination，与 214245 的 R1（UF-FIX08 迁移面）和原 plan §12 一致；无
  unclassified residual。

## Findings

### 1-未修复-低-多文件整组跨目录移动的 identical-skip 未被 owner test 固定
- **位置**: amendment §5.1（只测 reorder）、§5.3（只测单文件 move）；goal 3.1.2
- **问题类型**: 测试缺口
- **当前写法**: §5.1 末项以“相同 primary/companions、仅改变 companion 相对顺序”证明顺序无关；§5.3 保留单文件
  “同 basename/同内容跨目录 skip”。多文件集合整体换目录（全部 path-derived identity 改变、descriptors 不变、
  primary 不变）没有任何测试断言其 identical-skip 与 version 不增长。
- **反例/失败场景**: 用户把同一组多文件从 `dirA` 整体移动到 `dirB` 后原样重传（auto update）：设计上 digest 相同、
  safe=True → skip。但该行为只由“payload 排除 identity”间接导出，若实现 Agent 在 role-to-asset 关联或 companion
  投影中误把 identity/路径因素带入 payload，此场景会变成无谓 update 而所有现有测试仍绿。
- **为什么有问题**: 这正是本 amendment 与 Finding 1 修复的边界场景——move 语义与 role 编码在 v2 payload 中共存，
  其正确性（多文件 move 仍 skip）是该修复不引入回归的直接证据，目前无测试固定。
- **直接证据**: §5.1/§5.3 的测试条款文本；原 plan Slice 3 的 move 断言条款已被 §1 supersession 第 3 项修订；
  现有测试 `test_docling_upload_service.py:2930-2960` 是单文件 move。
- **影响**: 回归不可见（低概率）；“move 语义与 role-aware 兼容”的核心正确性主张缺 owner 级证据。
- **建议改法和验证点**: 在 §5.1 增加一项：多文件 safe 集合整体移动到新目录、primary/内容不变，auto update 断言
  identical-skip、version 不增长、fingerprint 与移动前相同；同时断言移动后 role-to-asset 关联仍命中新 identity。
  全部在 allowed test file 内实现。

### 2-未修复-低-old v1（无角色）多文件 fingerprint → v2 过渡 update 未被 owner test 固定
- **位置**: amendment §4.3（“已有旧 multi-file fingerprint 的首次 upsert 会 update/version increment”）、§10 第 2 行
  （“fixed by safe version transition”）
- **问题类型**: 测试缺口
- **当前写法**: 过渡行为被声明为“有意不兼容、fail safe”，§10 分类为 fixed；但 §5 的测试矩阵全部在 v2 新公式世界内
  构造，没有一项用旧公式（无角色排序 descriptor list）计算 digest 夹具，断言首次 v2 upsert 必 update/version
  increment 且不 skip。
- **反例/失败场景**: 实现 Agent 若错误实现“dual-read”或把单文件公式逻辑误用于多文件过渡（例如想当然地认为旧 digest
  是单文件格式而尝试兼容跳过），会在已持久化旧 digest 的真实 source 上错误 skip 或错误 bump，而现有测试全绿。
  stop condition 6 禁止兼容 skip，但测试未固定该边界，约束只靠文档。
- **为什么有问题**: “fixed by safe version transition”是对既有持久化数据的断言，属于 owner contract 边界；无测试时
  该断言只是注释，未来维护者改动 `_can_skip_upload` 时无法感知。
- **直接证据**: §5.1/§5.2/§5.3 全部以新公式构造 previous_meta；§4.3/§10 第 2 行的过渡声明；现有测试 2519 行的
  fingerprint 夹具按当前公式构造。
- **影响**: 过渡行为回归不可见；UF-FIX08 边界（214245 R1）的实际行为与文档可能漂移。
- **建议改法和验证点**: 在 §5 增加一项：用旧公式手工计算的无角色多文件 digest 作为 previous
  `source_fingerprint`，auto upsert 断言 uploaded、version increment、不 skip；同时固定单文件旧 digest 与单文件
  新 digest 相等仍 skip（防把单文件误升级）。全部在 allowed test file 内实现。
