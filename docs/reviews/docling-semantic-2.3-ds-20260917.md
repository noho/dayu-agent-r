## 对判定口径的观察

1. **heading 判定项对本样本集不适用**：50 份样本 headings new_count/base_count 全部为 0/0——两代导出均未输出 `section-header`/`title` label（或 label 命名不同）。建议在导出层核对 label 字段名，或在后续升级判定中改用其它标题信号。
2. **merged 净差不宜直接当丢失量**：Counter 净差把「出现次数减少 1~3 次」也计入 missing。token 级验证显示 6d3310a5 的 -98 全部来自高频 token 计数差（'12': 482→480 等）与跨页表去重，无任何 token 真丢。merged Δ 显著负的样本必须做 token 级验证才能定性。
3. **`missing_merged` 列表不含计数**：digest 只存 token 字符串，丢 1 次与丢 10 次无法区分，且 30 上限截断会掩盖长尾。后续 digest 建议带计数（如 `"30,967,640": {"base": 4, "new": 2}`）。
4. **`moved_to_table_ratio` 是块级存在性命中率**：1.0 表示块内数字在新版表格单元格全部存在，但同一数字出现次数可能已减少（去重）。ratio 用于排除「真丢」方向有效（ratio 低 → 详查），但不等于「零变化」。
5. **本路差异主旋律是修复**：两代产品在封面/页眉的 OCR 差异极大——2.90 基线大量封面文字为乱码（'Tm ='、'ЛЕЖЕК: 83690'、'AX#1t69:000333'、'Tencent AšTH' 等），2.127 正确识别；正文差异以「表格重建/去重/行标签顺序修复」为主。
6. **两个小瑕疵**（不构成退化）：(a) 腾讯系年报页眉 '二〇二〇' 的 '〇〇' 在新版被识别为 '00'（ab7806e8、0644cb6f 可见）；(b) 部分封面装饰元素有少量噪声（'VOOC'、'2OON'、'美团 美团' 重复），但不影响内容正确性。
7. **财务数字缺失的正负号 token**：pattern 会把 '20-40' 切成 '20' 与 '-40' 两个 token、把表格负值识别为独立 token（'-991','-2001'），判读 missing 列表时需注意这不是符号错位而是分词口径。

## 结论

奇数索引路 50 份：**0 退化、15 修复、35 中性**。本路证据不支持「docling 2.127 相对 2.90 存在语义退化」的假设；相反，封面/页眉 OCR 与表格结构存在系统性改善。三个 merged Δ 最负的样本（-98、-162、-166）经 token 级验证均非内容丢失（跨页表去重、表格重排、装饰图案噪声清除）。
