## 原 finding 计划层闭环逐条裁决

### Kimi F1 / MiMo F1（中，accepted）：helper 自身失败兜底 —— 已闭环（计划层）

- 修订证据：plan「边界、语义 owner 与契约」第 6 段明文规定"`safe_exception_trace` 对 `Exception` 输入的**整个格式化过程不抛出**"，per-frame 校验失败降级 `[external]`，遍历/指纹/容器等内部步骤的非预期 `Exception` 统一返回固定 `exception_type=redacted custom_type=redacted stack=[unavailable]`，且"兜底只在共用 helper 内实现一次；producer 和 CLI 不各自复制宽泛 catch"。
- 契约可测试性：固定降级串与"无 traceback"正常输出（`exception_type=<真实内建祖先>` + `stack=[unavailable]`）可区分，满足 owner 级断言要求；S2 明文列入"注入遍历/元数据/哈希意外失败，断言 helper 不抛出且仅返回固定安全串"，以及 producer/CLI 两侧"helper 内部失败时 RESULT/固定 CLI 失败与退出码不变、无原始 traceback 或秘密进入日志/stderr"。
- 边界声明诚实：plan 明示"这不扩展为 RESULT 构造等其它二次失败的兜底承诺"，与 Kimi F2 的延期裁决不互相冒充。
- 残留观察（非 finding）：契约作用域是 `Exception`；`KeyboardInterrupt/SystemExit` 期间格式化被打断会传播——这是正确语义（不吞中断），无需修。

### MiMo F2（中，accepted）：自定义类型全抑制 → 安全类型指纹 —— 已闭环（计划层）

- 修订证据：plan 第 5 段规定内建祖先经 `vars(builtins).get(name) is class` **身份**证实（防同名 spoof），自定义类型只取 `__module__`/`__qualname__`（均须为 `str`），以 `module + "\0" + qualname` UTF-8 的 SHA-256 前 16 小写 hex 输出，元数据/编码/哈希任一失败回 `redacted`；内建异常 `custom_type=redacted`；指纹明示"只是 operator 诊断标签，不是业务原因或公开分类"。S2 测试要求"两种不同动态异常类名……固定长度 hex 指纹可区分且无原始类型名/秘密"。
- 泄密挑战（任务指定重点）：指纹输入是代码标识符而非秘密值。动态类名嵌入高 entropy 秘密（如 token）时，64-bit hash 前缀不可恢复原文；低 entropy 类名可被字典确认，但类名本身非秘密，且 dayu 自有异常经受信帧相对路径已暴露模块结构，指纹不增加攻击面。判定**无实质泄密**。
- 过度设计挑战（任务指定重点）：goal 成功信号要求"脱敏的**异常类型**与调用栈"，纯内建祖先会把 aiohttp/httpx/urllib3 等第三方异常压成同一 `OSError`（MiMo A10 证据：`runtime/log.py:62` 第三方抑制清单证明外部库异常真实存在）；指纹是满足"可区分且不回溯原名"的最小机制，16 hex 有界、无状态、无注册表。判定**非过度设计**。
- MRO 端点检查：任何 `Exception` 子类 MRO 必经 `Exception/BaseException`（均在 builtins），"找不到内建祖先"不可达；同名自定义类因身份检查失败会正确落到下一个 MRO 项。

### MiMo F3（中，accepted）：默认日志不可查 + hint owner —— 已闭环（计划层），owner 归属正确
