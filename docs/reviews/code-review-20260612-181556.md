### 1. `run_storage_maintenance` 仍为 read-only（default dry-run）

**入口链路追踪**：

```
run_storage_maintenance(host, request)
  -> host._run_read(_ReadStorageMaintenanceStateOperation(...))  # read transaction
       -> read_storage_usage(transaction, db_path)                # read-only
       -> collect_referenced_artifact_paths(transaction)           # read-only
       -> inspect_memory_snapshot_integrity(transaction)           # read-only (S1)
  -> scan_orphan_artifact_files(...)                              # filesystem read
  -> _reclaim_orphan_artifacts_if_requested(...)                  # destructive only when opt-in
  -> _physical_artifact_bytes(artifact_root)                      # filesystem read
  -> _run_wal_checkpoint_if_requested(...)                        # separate connection, DB maintenance
```

S2 变更仅向 `_ReadStorageMaintenanceStateOperation.__call__` 中的 read transaction 增加了 `inspect_memory_snapshot_integrity(transaction)` 调用（`storage_maintenance.py:372-374`），并将结果透传至 `HostStorageMaintenanceResult.memory_snapshot_integrity_issues`（`storage_maintenance.py:313-315`）。该调用完全在 `host._run_read(...)` 事务内执行，不产生任何写入、删除或状态变更。Default dry-run 语义完整保留。

**结论**：无回归，read-only 契约不变。

### 2. `memory_snapshot_integrity_issues` public result 自解释且不泄漏 payload

`MemorySnapshotIntegrityIssue.json_value()`（`memory.py:178-192`）返回字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `failure_kind` | `str` | 损坏分类枚举值（如 `"invalid_json"`） |
| `message` | `str` | operator 可读短错误摘要 |
| `snapshot_id` | `str \| null` | 受影响 snapshot id |
| `session_id` | `str \| null` | 受影响 session id |
| `consumer_id` | `str \| null` | projection consumer id |
| `policy_digest` | `str \| null` | memory policy digest（row identity） |
| `checkpoint_event_sequence` | `int \| null` | snapshot cursor sequence |

**Payload 泄漏检查**（逐 failure kind 核验 message 来源，`memory.py:1263-1306`）：

- `INVALID_JSON`：`f"memory snapshot JSON is invalid: {exc.msg}"` — `exc.msg` 是 `json.JSONDecodeError` 的错误描述（如 `"Expecting value"`），**不是**原始 JSON 内容。
- `SCHEMA_MISMATCH`：`f"memory snapshot JSON schema mismatch: {exc}"` — typed parse 异常消息（如 `"missing required field X"`），不含 JSON 原文。
- `DIGEST_MISMATCH`：静态字符串 — 不含任何 payload 内容。
- `STORAGE_READ_FAILED`：`f"memory snapshot integrity scan failed: {exc}"` — SQLite/durable 错误消息，不含 snapshot JSON。
- `UNSUPPORTED_ITEM_KIND`（via `_memory_snapshot_item_kind_integrity_issues`）：描述 unsupported item kind 名称，不含 item payload。

`policy_digest` 是内部治理标识。按 `AGENTS.md` 约束"内部治理标识只有任务必须引用时才可暴露"，该字段作为 row identity 帮助 operator 定位损坏行对应的 policy 版本，属于任务必须引用。`MemorySnapshotIntegrityIssue` 的 docstring 已将其标注为"可选 memory policy digest"，语义清晰。

**结论**：`json_value()` 输出为自解释 operator-facing JSON，不泄漏 `snapshot_json`、raw row data 或 payload 内容。符合 Agent 语义约束。
