## 3. Six Lenses

1. **Goal-bound minimal design**：每个契约点可映射到 goal（同源年度/未知区分）、binding（A/B 裁决、N01/N02 同 slice）或已裁 Q2/Q3/root 技术选择；未发现 goal drift、无未来 slice 锁入；单完整行为 slice 与用户粗切片要求一致。
2. **Architecture boundary**：storage 持有同窗物理事实与 inspector 组合，calendar/selection 持有财政语义，download_contract 持有公开/持久投影，runtime 只消费不重算（wait 不读 job、adapter 不重算日历）；F4 rawread 未升格 trust；依赖方向单向，未见层穿透。
3. **Best practice**：fresh-schema 必填、无兼容 shim/默认值、同源投影、owner 级验收断言、取消/异常优先级显式化，符合项目约束；异常通道（integrity typed tuple 与封闭 result 分离）避免语义混装。
4. **Optimal-solution**：合并 local/remote 证据不设 local 优先、不多数投票，是 Q3 的直接实现；366 天邻近收敛为单一 `relevant_annual_end_dates` owner 优于在各分支复制过滤；整体 FAILURE+partial 摘要在既有 status 词表内解决，无新枚举。
5. **Overengineering**：无治理实体/泛化 profile/callback；未知类型直接复用为 public 类型；`download_terminal_disposition_from_counts` 是收敛重复而非新增抽象；无多余 wrapper。
6. **Overcoupling**：local/remote 共享函数消除了 discovery/rebuild 双实现漂移；known/unknown 双列表独立 omission 可局部演进；测试按行为切片组织，非按文件机械拆。

## 4. Findings

### F1-未修复-中-同source_id冲突→未知折叠未指明替换去重fail-closed契约
- **位置**: 计划 §4"发现与未知报告"倒数第三条（"同来源去重不制造报告数量；同 source_id 真正冲突保留一条未知…"）；对应 owner `cn_report_selection._deduplicate_hk_announcements`。
- **问题类型**: 契约缺失 / 不可直接实施
- **当前写法**: 以行为散文要求"同 source_id 真正冲突保留一条未知，只投影各版本一致的已知日期，不任挑标题"，但全文未点名该冲突的现役 owner 与现契约，也未声明其去留。
- **反例/失败场景**: 同一 DOC_ID 在多分类累计响应中返回不一致核心事实（跨 t2code 响应标题/日期不一致）时，实施 Agent 若保留现状 `ValueError`（`cn_report_selection.py:756-757`，docstring 明写 fail closed），则整请求写前失败、可确定的 A 同死——恰是用户已否决的 P1 形态；若自行改为未知折叠，又在未获裁决下变更一条 fail-closed 运输契约。两种实现用户可见行为完全不同。
- **为什么有问题**: binding"全部可用可信证据仍不足或冲突时，明确列出该报告的不确定状态""不将'发现但不确定'当作'未发现'"要求该冲突落为 B 未知并继续 A；而"运输失败不得把部分 raw 当完整发现"又要求运输异常不得伪装业务未知。该冲突点正跨在两条规则边界上，计划必须显式钉死归宿，不能留给实施者逆向推断"不任挑标题"一句的含义。
- **直接证据**: `_deduplicate_hk_announcements` 同 ID 核心事实冲突 raise ValueError（`dayu/fins/pipelines/cn_report_selection.py:756-757`）；`list_report_candidates` 按分类完整累计后一次性传入 selector（`dayu/fins/downloaders/hkexnews_downloader.py:302-327`），同一 DOC_ID 跨分类重复返回是现役路径真实可达；计划 §4 仅有一句行为描述，§2 owner 表未列该函数。
- **影响**: 实施 Agent 跑偏（保留整请求失败，违反 A/B 裁决）或擅自改写 fail-closed 运输契约；review 不可验收（两个方向都"符合计划字面"）；后续返工。
- **建议改法和验证点**: 在 §4/§2 显式写明：`_deduplicate_hk_announcements` 的同 ID 核心事实冲突改为"折叠为一条 `FinsDownloadUncertainReport`，日期仅保留各版本一致值，冲突项 None"，并区分于运输失败（缺页/协议错误仍原样终止）；或如决定保留 ValueError，须在计划中论证其为运输完整性而非 B 未知并接受 A 同死。验证点：合成同 ID 冲突 raw（明确标合成）断言 A 正常发布+恰一条未知、未知日期一致值投影、operation 计数不重复。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
