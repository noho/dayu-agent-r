## Detailed Verification

### DS F1: S4 tier 1-3 recovery loop cancellation/stale-state 观测机制

**adjudication 要求**: S4 每次 tier attempt 前、proposal 返回后、commit 前的 durable Run state / input cursor / cancellation / stale-state 检查和测试。

**plan 修复内容**:

- §8 S4 Exact allowed changes 第 259-261 行: "Before each tier attempt, after its proposal returns and immediately before `_append_compacted_event(...)`, check durable Run state, input cursor, session state, execution identity and cancellation/stale-state. Stale, cancelled, session closed, execution replaced or cursor mismatch stops the recovery loop and must not write `CONTEXT_COMPACTED`. Proactive recovery uses a durable Run state observation token for those checks. Reactive recovery reuses the run-local cancellation token from the Engine envelope and still rechecks durable Run state/cursor before commit."
- §8 S4 Completion signal 第 297 行: "stale-state tests cover cancellation between tier 1 failure and tier 2 attempt, cancellation after tier proposal returns, and cursor/execution mismatch before commit; each case must not write `CONTEXT_COMPACTED`."
- §9 Expected Assertions 第 349 行: "Tier 1-3 recovery loop cancellation/stale-state tests cover checks before tier attempt, after proposal return and before commit. Proactive path uses durable Run state observation token; reactive path reuses run-local cancellation token. Stale/cancelled/session-closed/execution-replaced/cursor-mismatch cases do not write `CONTEXT_COMPACTED`."

**验证**: plan 现在明确覆盖了三个检查点（attempt 前、proposal 返回后、commit 前），区分了 proactive 和 reactive 两种路径的 token 机制，并要求测试覆盖每种 stale-state 场景。与 design.md:3190 对齐。

**结论**: ✅ 已修复

### DS F2: S2 fallback selected caps 与 budget estimator loop 集成方式

**adjudication 要求**: S2 fallback selection 的 floor、fallback item cap、fallback char cap、hard budget estimator 优先级。

**plan 修复内容**:

- §8 S2 Exact allowed changes 第 163-168 行: 详细的 5 步算法：
  1. Build protected floor first (never reduced by caps)
  2. Estimate floor-only with hard budget estimator; if exceeds, route to tier 5/fail closed
  3. Append non-floor candidates under both fallback caps (whole-block skip on cap exceed)
  4. Run hard budget estimator after each append; whole-block rollback on overflow
  5. Final set = floor + accepted appended blocks

**验证**: 算法明确了 floor > caps > budget estimator 的优先级，解决了原 finding 中"floor + cap 内 blocks 超标"的场景（步骤 4 处理）。实施 Agent 不需要自行设计三方交互语义。

**结论**: ✅ 已修复
