## Review Method Summary

沿以下关键执行路径逐行走读：

1. **Public contract boundary**：逐条核对 smoke test 的所有 import 与断言是否只使用 public Host/Service/Engine contracts，是否触碰 forbidden paths（durable wait row、dispatch row、scheduler internals、ToolRuntime internals、manual resolve、测试私有 wait id bridge）。
2. **Worker → Host event protocol**：从 `_AwaitingHandle.events()` / `_AnswerHandle.events()` 追踪 `EngineEvent` 构造与 `yield` 路径，确认事件序列（`TOOL_AWAITING` → `RUN_SUSPENDED` / `FINAL_ANSWER`）符合 Host EngineEvent ingest 的状态机预期。
3. **Tool execution handshake**：追踪 `_AwaitingHandle` 通过 `AgentRunRequest.tool_executor.execute(BatchToolExecutionRequest(...))` 走真实 Host ToolRuntime accept barrier 的完整链路，确认 `ToolAwaitingOutcome` 被 Host 正确接受并创建 wait record。
4. **Wait poller resolution**：追踪 `_GatedReadyPollAdapter` 通过 `WaitPollAdapterRegistry` 注册 → Host production poller 轮询 → gate 控制 not-ready/ready 切换 → `resolve_wait` pipeline → resume dispatch 的完整链路。
5. **Service entrypoint workflow**：追踪 `submit_entrypoint_turn_and_wait` 的 `on_run_accepted` / `on_activity` callback → `WAITING` activity 观察 → `get_run` public snapshot → poller gate open → terminal live event → outbox 补读。
6. **AGENTS.md compliance**：检查中文 docstring、类型注解、无 `Any`/`object`/untyped、无兼容性胶水、README 触发规则。
7. **Adversarial failure pass**：检查 timeout、cancel cleanup、premature poll resolution、outbox race、multi-poller conflict、gate synchronization 和 resource cleanup。

### 7. Adversarial failure pass — 通过

| 场景 | 处置 | 证据 |
|---|---|---|
| poller 在 WAITING 观察前提前 resolve | 已防御 | Gate 在双重确认（activity + `get_run`）后才打开；gate 打开前持续返回 `WaitPollNotReady` |

## Open Questions

1. `_OpaqueWaitInput` Protocol（第 305-306 行）定义为空 Protocol，`poll_wait` / `abandon_wait` 使用它作为参数类型标注。当前设计合理（adapter 不消费 wait record 字段），且空 Protocol 在类型系统中接受任意对象。但如果 `WaitPollAdapter` protocol 未来增加新的 required 方法，测试 adapter 不会收到类型检查提示——不过 `WaitPollAdapterRegistration(adapter=...)` 构造时即会 fail fast。**不需要当前修改，但可作为后续类型安全增强的候选**。

## Residual Risk

1. **R1 (Low)：outbox 写入时序** — 当前 smoke 在 `submit_task` 返回后立即读取 outbox，假定 outbox projection 是同步的。现有 entrypoint runtime 测试使用相同模式且未报告 flake。如果未来 outbox 改为异步 projection consumer，该断言可能 flake。缓解：现有 Host 架构中 outbox 是 committed EventLog 的同步 projection；若架构变更，受影响测试矩阵（含本 smoke）会同时暴露。

2. **R2 (Low)：只覆盖 production poller path** — S2 smoke 只验证 poller resolution path，不验证 callback resolution path。这是 plan 的有意选择（callback endpoint 当前没有 ordinary UI/Service 可用的 public wait id discovery contract）。callback E2E smoke 是独立 work unit 范围。

3. **R3 (Low)：deterministic adapter 不覆盖真实 Fins ingestion** — S2 smoke 使用 deterministic `_GatedReadyPollAdapter` 和 deterministic `_AwaitingTool`，验证 public workflow 与 production poller runtime，不覆盖真实 Fins ingestion provider 的外部系统状态转换。真实 Fins poll adapter assembly 已由 S1 和现有 service assembly tests 覆盖。

4. **R4 (Informational)：`_host_assembly` 和 `_open_options` 各自调用 `_tool_bundle()`** — 产生两个不同 `ToolBundle` 实例（内容相同）。当前不影响行为，且 S2 直接组装 public options 而非经过 `compose_open_host_options`——这是 plan 允许的 S2 模式。不需要修改。

5. **R5 (Informational)：`_host_runtime_config` 和 `_execution_profile_config` 的返回值未被 smoke 行为消费** — 两个 helper 的 docstring 已明确标注"未被当前 smoke 行为消费"。它们仅用于构造合法的 `ServiceOpenHostAssemblyResult`，属于必要的 boilerplate。不需要修改。
