- **实际行为**: 缺少独立单元测试。两个都存在、仅 provider id 存在、message 为 None 的路径未被任何测试直接验证。
- **直接证据**: `grep -rn "_terminal_diagnostics" tests/` 返回空结果；`_append_terminal_diagnostic_suffix` 的唯一调用方是 `read_api.py` 和 `outbox.py`，且测试只覆盖了一条路径。
- **影响**: 低。当前代码逻辑简单，四个分支的正确性可以通过代码阅读确认。但如果后续有人修改 `_terminal_diagnostic_suffix` 的分支逻辑（例如修改输出格式、调整截断逻辑），缺少单元测试会增加回归风险。

### 2-未修复-低-Tool Trace diagnostic 测试未覆盖 `raw_payload_ref` 存在时的 `diagnostic_ref` 行为

- **实际行为**: 测试仅覆盖了 `raw_payload_ref` 缺失的场景（`diagnostic_ref=None`），未覆盖 raw payload ref 存在时的行为。
- **直接证据**: `tests/host/test_tool_trace_projection.py:1641-1645` 的 payload 中不含 `raw_payload_ref` 字段。
- **影响**: 低。`diagnostic_refs` 的构造逻辑简单（两元素 tuple → 取第一个），代码阅读可确认正确性。但 plan 明确要求验证该行为。
