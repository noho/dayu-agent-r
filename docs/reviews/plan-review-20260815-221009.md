### `215532-F1`：`_resolve_document_version` 未在签名处绑定 unsafe 行为 → 已修复

**原 finding**：函数签名只改类型（`str` → `_UploadSourceFingerprint`），行为规格在 §4.4 而非 §4.2；实现 agent 可能只改类型不改逻辑。

**修订后 §4.2**（第 199–227 行）：增加 exact branch pseudocode：

```python
# _resolve_document_version 只拥有"既然未 skip、继续发布时使用哪个版本"的决策；
# 不读取 overwrite、is_deleted、primary_document，也不再次决定 skip。
if previous_meta is None:
    return "v1"
previous_version = _text_meta(previous_meta, "document_version") or "v1"
if not source_fingerprint.identical_skip_safe:
    return _increment_document_version(previous_version)
previous_value = _text_meta(previous_meta, "source_fingerprint")
if previous_value and previous_value != source_fingerprint.value:
    return _increment_document_version(previous_version)
return previous_version
```

并附关键不变量文字（第 225–227 行）：
> 只要 `previous_meta is not None`，`identical_skip_safe=False` 就必须**无条件**从 existing source 的 `previous_version` 增长一次，不得再受 digest 相等、previous fingerprint 是否缺失、overwrite 或 deleted 状态影响。

**五层闭合验证**：

| 层 | 闭合方式 | 判定 |
|----|----------|------|
| 签名 | `_resolve_document_version(previous_meta, source_fingerprint: _UploadSourceFingerprint) -> str`；typed result 携带 `identical_skip_safe` | ✓ |
| docstring | pseudocode 注释明确"只拥有 version 决策"与职责边界 | ✓ |
| pseudocode | exact branch 代码：`if not source_fingerprint.identical_skip_safe: return _increment_document_version(previous_version)` 无条件分支 | ✓ |
| data flow | §4.5 绑定 `existing + unsafe: unconditional previous version + 1` | ✓ |
| test | §5.2 冻结 `v1 → v2 → v3` 精确值链（见下条） | ✓ |

**判定**：已修复。implementation agent 可从 pseudocode 直接编码，不再需要跨 §4.2/§4.4 推断。

### `215532-F2`：ambiguous replay 未冻结精确 version 值 → 已修复

**原 finding**：§5.2 只断言"uploaded/version increment"定性行为，未指定 version 值。

**修订后 §5.2**（第 350–353 行）：

> create(primary=P1) 精确断言 `status="uploaded"`、`document_version="v1"`；原样 auto replay(primary=P1) 精确断言 `status="uploaded"`、`document_version="v2"`；再仅翻转为 P2 精确断言 `status="uploaded"`、`document_version="v3"`。该 `v1 -> v2 -> v3` 链必须直接读取 repository meta/typed prepared mutation 的 canonical version，不能只断言定性的"version increment"。

**精确值链推演验证**：

1. create(primary=P1) → 无 previous meta → `v1` ✓

3. flip(primary=P2) → previous=v2, `identical_skip_safe=False` → `_increment_document_version("v2")` = `v3` ✓

并补充 non-ambiguous recovery（第 359–360 行）：v3 后改变 descriptor 使 primary 重新唯一 → digest 改变 → `v4`，随后 replay skipped 保持 `v4`。

**判定**：已修复。version 值精确闭合，implementation agent 无法逃逸。
