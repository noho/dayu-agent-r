## Findings

### F19-RR2-001-未修复-高-R4 gate未验证canonical accepted replacement，raw Run rows可错误放行reconnect

- **位置**: Goal Confirmation第17-21行；plan `Adaptive chain state machine` 第55-64、70-74行；driver `_chain_state` 第605-671行。
- **问题类型**: 语义所有权漂移 / 状态机漏洞 / 测试缺口。
- **当前写法**: plan要求R4仅在replacement target accepted后fresh reconnect，并称每段使用Host typed前置状态。driver实际直接用`sqlite3`查询private `host_runs(status, session_id)`与`host_session_slots`，把raw字符串`succeeded`解释为canonical terminal；R4只要求row count=3、status字符串相等和session_id相等。
- **反例/失败场景**: provider-free临时SQLite只创建`host_runs`与`host_session_slots`两张最小表，不创建`event_log`，插入三个`succeeded/session-x` rows与一个label slot。`_chain_state(..., segment_id="R4")`返回`all_previous_terminals_succeeded=true`和`label_session_exact=true`。该fixture不存在任何`RUN_ACCEPTED`/唯一terminal canonical facts，更不存在accepted replacement或`CONTEXT_COMPACTED`，却会允许wrapper继续写real projection并spawn R4 harness。
- **为什么有问题**: R4的业务前置不是“R1-R3进程均exit/succeeded”，而是R3 target operation已由compaction owner接受并形成同源truth。raw status row、session_id和顺序不能替代canonical lifecycle terminal或compaction operation identity；下游wrapper不能重新解释private表字段来产生该语义。
- **直接证据**:
  - driver第637-663行直接SQL并硬编码`"succeeded"`，没有调用已有typed `utils.cli_ci_run_observation.observe_run_terminals`或Host compaction/EventLog projection。
  - frozen PTY owner已经通过tracked helper读取filtered canonical EventLog window、校验accepted/唯一terminal/session/order，并用shared `RunStatus`投影terminal class；该owner路径可复用，当前driver却绕过。
  - 真实反例输出：`EVENT_LOG_PRESENT 0`，随后`R4_NO_COMPACTION_GATE`仍返回成功projection。
- **影响**: 自然未触发replacement的R3仍可能消耗一次R4真实provider call；所得“fresh reconnect”并未消费accepted truth，不能覆盖mandatory reconnect/durable same-source evidence，且可能被错误纳入execution index。
- **建议改法和验证点**:
  - continuation gate复用tracked canonical Run observation owner或等价Host typed read contract，严格验证前N个Run的accepted/唯一terminal/session与`RunStatus.SUCCEEDED`；不得直接SQL/硬编码status string。
  - R4另加compaction-owner gate：要求R3 target对应唯一accepted compact operation/`CONTEXT_COMPACTED`，绑定当前run/session/source boundary与accepted artifact/truth identity；rejected/failed/no-operation/wrong Run均fail closed。
  - provider-free负测至少覆盖：三个succeeded raw rows但无EventLog、三条canonical succeeded但无compact、compact rejected/failed、accepted compact绑定错误Run/session/source，以及唯一正确accepted compact；前四类必须在wrapper projection与formal spawn前拒绝，最后一类才允许R4。
- **修复风险（低/中/高）**: 中。
- **严重程度（低/中/高/严重）**: 高。
