## Findings

未发现实质性问题。

逐项审查结果：

**1. broad cast / wide mapping cross-function contract 移除**

`_parse_vnext_proposal` 旧签名为 `-> Mapping[str, JsonValue]`，新签名为 `-> ConversationCompactOutputVNext`。旧代码的 `cast(Mapping[str, JsonValue], parsed)` 已移除，`from typing import cast` 也已从生产代码中删除。剩余的 `Mapping[str, JsonValue]` 用法（行 502, 633, 651, 686, 714, 744, 786, 820, 969, 987, 1008, 1036, 1059, 1088, 1114, 1139）全部是局部 JSON object helper 边界或 projection artifact 构造，不构成跨函数 proposal contract。旧的 `_required_mapping`、`_json_mapping`、`_optional_string_or_none`、`_optional_string_tuple_or_none`、`_optional_int_or_none` helper 函数已全部移除。

**2. JsonValue narrowing 无逃逸**

逐行走读 narrowing 链路：

- `json.loads(raw)` 赋值为 `parsed: JsonValue`（行 610）——不使用 `cast`。
- `_json_object(parsed, "proposal")` 内部 `isinstance(value, Mapping)` 校验（行 978），外加非字符串 key 校验（行 980-982）。
- `_required_value` / `_required_string` / `_required_array` / `_required_enum` 等 helper 均通过 `isinstance` 逐层收窄，返回类型无 `Any`、无 `object`、无 `# type: ignore`。
- 枚举构造使用 `_required_enum` 返回 `str` 后直接传入 `StrEnum` 构造函数（如行 672-679），不经过宽映射。
- `_string_tuple` 验证每个元素 `isinstance(item, str)`（行 1180）。

**3. field-path diagnostics 完整性**

- `_field_path(parent, key)` 在 `parent == ""` 时返回 `key`，否则 `f"{parent}.{key}"`（行 953-955）。
- `_item_path(parent, index)` 返回 `f"{parent}[{index}]"`（行 966）。
- 所有 helper 的 error message 均使用 `_field_path(parent_path, key)` 或 `_item_path` 生成的完整路径，不使用裸 key。
- 测试验证 `evidence_backed_facts[0].evidence_kind`（行 262-263）和 `answer_anchors[0].anchor_items[1].ordinal`（行 290-291）完整路径稳定输出。
- `_answer_anchor_children_vnext` 正确拼接嵌套路径：`parent_path=answer_anchors[0]` -> `_field_path(parent, "anchor_items")` = `answer_anchors[0].anchor_items` -> `_item_path(field_path, 1)` = `answer_anchors[0].anchor_items[1]`。

**4. candidate safety-net wrapping**

`parse_conversation_compact_output_vnext` 的 try-except（行 593）捕获 `(KeyError, TypeError, ValueError)` 并包装为 `LLMCompactionProposalError`。测试 `test_parse_conversation_compact_output_vnext_wraps_candidate_safety_net`（行 299-318）验证空 `source_labels` 触发 `SessionSummaryCandidateVNext.__post_init__` 的 `_require_bounded_string_tuple(... require_non_empty=True)` 抛出 `ValueError`，被包装后匹配 `"compactor vNext proposal schema invalid"`。

**5. source label validation / current anchor / unknown / stale / cross-section 行为**

`_validate_vnext_candidate_source_labels`（行 847-908）和 `_validate_vnext_labels`（行 911-941）未修改。现有测试 `test_parse_conversation_compact_output_vnext_rejects_current_anchor_label`（行 226-242）继续通过。source label 校验发生在 candidate 构造之后、返回之前，保留为 accept barrier。

**6. schema_version 前置校验**

`_parse_vnext_proposal` 在构造 `ConversationCompactOutputVNext` 前先校验 `schema_version`（行 614-620），符合 plan Implementation Decision #7。无效 schema_version 抛出 `ValueError`，被 `parse_conversation_compact_output_vnext` 的 try-except 包装为 `LLMCompactionProposalError`。旧的 `ConversationCompactOutputVNext.__post_init__` 中的 schema_version 校验仍保留为安全网。

**7. `_json_object` 非字符串 key 防御**

`_json_object`（行 980-982）显式校验 `for key in value: if not isinstance(key, str)`。虽然 `json.loads` 在 CPython 中始终产生字符串 key，但此防御符合 plan Implementation Decision #4 的 "validate `isinstance(value, Mapping)` and every key is `str`" 要求。

**8. `_optional_non_negative_int` bool 排除**

行 1080 `if not isinstance(value, int) or isinstance(value, bool)` 正确处理 Python `bool` 是 `int` 子类的语义。`True` / `False` 不会被接受为非负整数。

**9. 测试覆盖 S1 范围**

S1 新增 3 个测试：

- `test_parse_conversation_compact_output_vnext_reports_fact_evidence_kind_path`：验证 enum 非法值的完整路径诊断。
- `test_parse_conversation_compact_output_vnext_reports_anchor_ordinal_path`：验证嵌套可选字段非法值的完整路径诊断。
- `test_parse_conversation_compact_output_vnext_wraps_candidate_safety_net`：验证 candidate 构造失败被包装为 `LLMCompactionProposalError`。

这些测试覆盖 S1 的核心行为：field-path diagnostics 稳定性和 candidate safety-net wrapping。S2 full invalid matrix（malformed JSON、top-level non-object、missing key、type error、array overlimit、unknown/stale/cross-section label 等）由 plan 明确分离到 S2 slice。

**10. 分层 / 反向依赖 / LLM-facing 语义约束**

- 生产代码仅 import `dayu.contracts`、`dayu.engine`、`dayu.host`、`dayu.runtime`，不反向 import `dayu.service` / `dayu.ui`。
- LLM-facing 文本（error message）只暴露 field path 和校验原因，不暴露内部类型名、digest、cursor 或 event id。
- 新增的模块级常量（如 `_SCHEMA_VERSION_FIELD`、`_FACT_EVIDENCE_KIND_VALUES`）是 parser 内部实现细节，不进入 `__all__`。

**11. docstring / 类型约束**

所有新增/修改的私有函数均有完整中文 docstring，包含 `:param`、`:returns`、`:raises`。签名无 `Any`、无 `object`、无无类型参数。
