## Review Checklist

### 1. classifier 是否 read-only

**PASS**。`inspect_memory_snapshot_integrity(transaction)` 只调用 `transaction.fetchall()` 读取 rows，不执行任何 `INSERT` / `UPDATE` / `DELETE`。内部 helper `_memory_snapshot_integrity_rows`、`_memory_snapshot_integrity_issues_for_row`、`_memory_snapshot_json_integrity_issue`、`_memory_snapshot_item_kind_integrity_issues` 均只读取，不写入。

### 2. 是否保持 read_memory_snapshot fail-closed

**PASS**。`read_memory_snapshot` → `_snapshot_row_from_host_row` → `_validate_snapshot_digest` + `_validate_snapshot_item_kinds` 链路未被修改。损坏 snapshot 在读路径仍然抛出 `HostDurableError`，不被静默吞掉。测试 `test_memory_snapshot_integrity_classifies_unsupported_old_item_kind` 同时断言 classifier 返回 `UNSUPPORTED_ITEM_KIND` 和 `read_memory_snapshot` 对同一 row 抛出 `HostDurableError`，确认两条路径并行存在且 fail-closed 不变。

### 3. failure kind 是否基于 direct evidence

**PASS**。五种 failure kind 全部基于直接解析/校验证据：
- `invalid_json` ← `json.loads()` 抛出 `json.JSONDecodeError`
- `schema_mismatch` ← `conversation_memory_snapshot_from_json_value()` 抛出 `TypeError` / `ValueError`
- `digest_mismatch` ← `calculate_memory_snapshot_digest(snapshot)` 与 `snapshot.snapshot_digest` 或 `row_snapshot_digest` 不等
- `unsupported_item_kind` ← item_kind 不在 allowed_kinds tuple 中
- `storage_read_failed` ← `sqlite3.Error` 或 `HostDurableError` / `KeyError` 在字段读取时

无间接推断、无 fallback 猜测。

### 4. manual corruption 是否归类

**PASS**。Plan 明确 `manual corruption` 不作为独立 failure kind；手动 SQL 修改导致的损坏被已有五类捕获。测试 `test_memory_snapshot_integrity_classifies_manual_digest_mismatch` 通过 `_replace_snapshot_json` + `_snapshot_json_with_changed_built_at` 模拟手动篡改合法 JSON 内容，结果归类为 `DIGEST_MISMATCH`。

### 5. storage_read_failed 测试是否合理

**PASS**。`test_memory_snapshot_integrity_classifies_storage_read_failure` monkeypatch 模块私有 helper `_memory_snapshot_integrity_rows` 使其抛出 `sqlite3.OperationalError`。这与 plan 指定的 monkeypatch 目标一致（"monkeypatching the classifier's module-private snapshot row reader helper to raise `sqlite3.OperationalError`"）。断言 `snapshot_id is None` 确认扫描级错误不携带 row identity。
