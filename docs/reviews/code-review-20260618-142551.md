## Findings

### 1-未修复-中-`_facts_from_accepted_event` 在 empty-labels 提前返回时丢失已累积 oversized-fact 诊断

- **入口/函数**: `dayu/host/memory.py:_facts_from_accepted_event`
- **文件(行号)**: `dayu/host/memory.py:1807-1850`
- **输入场景**: accepted compact event 的 fact candidates 列表中，先出现 oversized fact（触发 `BUDGET_LIMIT_REACHED` 诊断追加到 `diagnostics` 列表），再出现一个 evidence labels 为空的 fact（触发 `len(labels) == 0` 分支）
- **实际分支**: `dayu/host/memory.py:1824` — `if len(labels) == 0:` 条件成立，执行 `return ((), (_fact_candidate_invalid_diagnostic(...),))`。这个 return 重新构造空 tuple，丢弃了之前循环迭代中 `diagnostics` list 累积的 budget 诊断
- **预期行为**: `_facts_from_accepted_event` 应在 empty-labels 提前返回时保留之前已累积的 oversized-fact 诊断，使 caller 看到的 `fact_diagnostics` tuple 同时包含 `BUDGET_LIMIT_REACHED` 和 `EVIDENCE_BACKED_FACT_CANDIDATE_INVALID`
- **实际行为**: oversized-fact 的 `BUDGET_LIMIT_REACHED` 诊断被静默丢弃，caller 只收到 `EVIDENCE_BACKED_FACT_CANDIDATE_INVALID`
- **直接证据**:
  - `diagnostics` list 在 line 1808 初始化为空 list
  - line 1813-1822：oversized fact 通过 `diagnostics.append(_budget_diagnostic(...))` 累积诊断
  - line 1824-1834：`len(labels) == 0` 时直接 `return ((), (...))` — 这个 return 不包含 `diagnostics` 累积内容
  - line 1850：正常路径 `return tuple(facts), tuple(diagnostics)` 才包含全部累积
  - 同一函数内部两个 return 路径对 diagnostics 累积的不一致处理，构成同一 call path 上的直接证据
- **影响**: 当 compact event 同时包含 oversized fact 和 empty-label fact 时，operator 看不到 oversized-fact 被 skip 的诊断信号。剩余收到的 `EVIDENCE_BACKED_FACT_CANDIDATE_INVALID` 诊断不能推导出预算超限事实。影响仅在异常 compact output（同时出现两种错误）时生效。
- **建议改法和验证点**: 将 empty-labels early return 改为 `return tuple(facts), tuple(diagnostics) + (_fact_candidate_invalid_diagnostic(...),)` 或等效写法，保留所有已累积诊断。同时该 return 也应考虑保留已累积的 `facts`（这是一个已知的 pre-existing fact-loss bug，但本次 S1 不要求修复）。验证点：构造包含 oversized fact + empty-label fact 的 fixture，断言 diagnostics 同时包含两种 reason。
- **修复风险（低）**: 修改只涉及返回 tuple 的组装方式，不改变分支逻辑和状态机。
- **严重程度（中）**: S1 引入 diagnostics 累积模式，但 empty-labels 提前返回路径未同步更新，导致诊断丢失。这是 S1 引入的 observability 回归。

### 2-未修复-低-`_facts_from_accepted_event` empty-labels 提前返回静默丢弃已累积 valid facts（pre-existing，S1 未修复未加剧）

- **入口/函数**: `dayu/host/memory.py:_facts_from_accepted_event`
- **文件(行号)**: `dayu/host/memory.py:1824-1834`
- **输入场景**: accepted compact event 的 fact candidates 列表中，先出现合法 fact（通过 char_cap 与 labels 校验，已 `facts.append`），再出现 empty-labels fact
- **实际分支**: `len(labels) == 0` 时执行 `return ((), ...)` — 重新构造空 tuple，丢弃 `facts` list 中已累积的合法 fact

- **影响**: 一个 compact event 中的合法 fact candidate 因为同一 event 中另一个 fact 的 data issue 被静默丢弃。影响仅在实际出现 empty-labels 的 compact event 时生效
- **严重程度（低）**: Pre-existing bug，S1 既未修复也未加剧（fact 丢失路径与旧代码一致）。S1 新增的 diagnostics 丢失在 Finding 1 中独立处理。本 finding 仅记录为已知缺陷，不作为 S1 blocker
