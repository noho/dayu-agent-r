## Findings

### F19-RR3-001-未修复-高-real write-root identity 无外部真源且 ancestor symlink 校验可被绕过

- **位置**：plan「Fresh setup and budgets」real mode 固定布局要求；`workspace/tmp/f19_formal_driver.py` 的 `_validate_real_paths`（约 810-871 行）及 real `main` 写入顺序。
- **问题类型**：契约缺失 / 架构边界 / 测试缺口。
- **当前写法**：driver 只要求 `run_id` 使用 F19 prefix、`run_root.resolve().name == run_id`，再把其余路径与该调用方提供的 root 下的 expected path 做 resolved equality；symlink 检查只覆盖 `run_root` 与若干 leaf path，以及 `controller`、chain private parent、workspace leaf 自身。
- **反例/失败场景**：
  1. Controller 意图使用 `owner-a/pr190-f19-b2-rr3-scratch` 时，把同 basename 的完整合法布局放在 `owner-b/pr190-f19-b2-rr3-scratch`，并把 `--run-root` 及所有 sibling 参数一致指向 owner-b。`_validate_real_paths` 返回成功；contract 中没有 owner-a 的独立可信 identity，因此无法识别“same-basename wrong root”。
  2. 保持 run-root 为普通目录，但令其 `evidence` 中间组件为指向 root 外目录的 symlink，在目标目录下建立 `private/controller` 与 chain parent。所有 leaf 均不是 symlink，actual/expected 两侧 `resolve()` 又同时穿过同一 symlink，因此 `_validate_real_paths` 返回成功。
  3. 对照检查表明，包含字面 `..` 的路径与 leaf prompt symlink 会被拒绝，说明反例不是测试未进入 gate，而是 root owner 与 ancestor component 未被覆盖。
- **为什么有问题**：plan 明确承诺 F18/outside/same-basename wrong root/traversal/symlink 均在写入前 fail closed。当前比较基准由同一个未经独立绑定的 `--run-root` 自我派生，不能证明 root ownership；`Path.resolve()` 又会抹去中间 symlink 的 lexical identity。后续 allocation/deadline 文件也位于该 root 内，整树复制不能补上独立真源。合法-looking 的 wrong root 或 symlinked evidence tree 因而可进入后续 gate，并最终把 wrapper projection/harness evidence 写到 owner 之外。
- **直接证据**：provider-free scratch 实测输出为 `VALID_LAYOUT=PASS`、`SAME_BASENAME_OTHER_ROOT=ACCEPTED`、`SYMLINK_ANCESTOR=ACCEPTED`；同一矩阵输出 `TRAVERSAL=REJECT`、`LEAF_SYMLINK=REJECT`。driver 861-865 行以 resolved actual/expected equality加 leaf `is_symlink()` 校验，866-871 行仅检查三个 leaf directory，不遍历 root 到 leaf 的每个已有组件。
- **影响**：正式 F19 evidence 的 run ownership 与 publication scope 不可证明；错误 setup 可能写入另一棵同名 run tree或 root 外的 symlink target，使 execution index、secret/path scan 与 durable evidence 的 scope claim 失真。该缺口位于首次 formal write 前，不能留给 publication analyzer 补偿。
- **建议改法和验证点**：
  1. 先明确 canonical run-root/allowed parent 的唯一外部 owner，并让 driver 从不位于可搬移 run tree 内的冻结 contract 获得该 identity；不能继续用 `run_root.name == run_id` 或 root 内自带 JSON 自证 root。
  2. 在任何 `_emit`/spawn 前，对 run root、workspace、evidence、wrapper、controller、allocation/deadline/harness/prompt 从可信 root 开始逐组件做 lexical `lstat`/symlink 拒绝；对尚不存在的 evidence/output leaf 校验全部既有 ancestor，避免 `resolve()` 消除 symlink 证据。
  3. 增加 owner-a/owner-b 同 basename 全树搬移、run-root ancestor symlink、`evidence`/`private`/`workspaces` 任一中间 symlink、outside target、F18 root、traversal、leaf symlink矩阵；每例同时断言 wrapper/output/evidence 均未创建，fake spawn recorder 为零。保留合法 exact root 的正例。
- **修复风险（低/中/高）**：中。
- **严重程度（低/中/高/严重）**：高。

## Special review lenses

- **Goal-bound minimal design**：finding 只要求兑现已确认的 real root/layout fail-closed contract，没有扩展到产品、analyzer 或 future observation semantics。
- **Architecture boundary**：run-root identity 必须由 Controller/external observation contract 单一拥有；不能由待验证 root 内的文件自证，也不能在 publication consumer 补偿。
- **Best practice / optimal solution**：可信 root identity 加逐组件 lexical symlink 检查是最小可验证路径；仅追加更多 `resolve()` equality 或 basename 分支仍无法区分整树搬移。
- **Overengineering / overcoupling**：不需要修改 Host/Engine 或新增通用 runtime abstraction；修复应限于 run-owned external driver 与其 provider-free matrix。
