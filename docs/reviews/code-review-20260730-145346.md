## Findings

### 1-未修复-低-init 两种 `--config` 位置产生不一致的 usage error 消息

- **入口/函数**: `parse_cli_args` (arg_parsing.py:234) vs argparse 内置 unknown argument
- **文件(行号)**: `dayu/cli/arg_parsing.py:234-235`
- **输入场景**: 用户在 init 命令前后放置 `--config`
- **实际分支**:
  - `init --config PATH`: argparse 在 init subparser 触发 `unrecognized arguments: --config PATH`
  - `--config PATH init`: 走到 `parse_cli_args` 中自定义 `parser.error("init 命令不接受 --config")`
- **预期行为**: 两条路径均应返回 exit 2，但项目对用户可见错误信息的约束（AGENTS.md 编码硬约束）期望一致的错误输出
- **实际行为**: 两条路径 exit code 相同 (2)，但错误消息文本完全不同。`--config PATH init` 路径还会打印包含 `--config` 选项的顶层 usage 行，再在下方报错说不接受，构成轻微 UX 矛盾
- **直接证据**: `arg_parsing.py:234-235` 自定义 error vs argparse 内置 `_UNRECOGNIZED_ARGS_ATTR` 错误格式
- **影响**: 仅 UX 不一致，不影响正确性；用户需要额外认知成本理解两条等价非法输入的差异报错
- **建议改法和验证点**: 可在 init subparser 上显式添加 `--config` 并用自定义 `action` 或 `type` 抛出统一错误，或覆盖 argparse 的 `error` 方法统一格式。但此方案引入额外复杂度，收益有限。建议作为 deferred-with-owner，后续 CLI UX 统一 pass 处理
- **修复风险（低）**: 仅影响错误消息格式
- **严重程度（低）**: 不影响正确性、状态、安全

### 2-未修复-低-`tests/cli/test_prompt_command.py` 缺少 `model_id` 精确断言

- **入口/函数**: `test_prompt_command_outputs_fast_live_terminal_and_converts_requests` (test_prompt_command.py:986)
- **文件(行号)**: `tests/cli/test_prompt_command.py:989` (仅变更参数名，未新增断言)
- **输入场景**: `prompt` 命令通过 `--model` 传入模型标识
- **实际分支**: 测试变更仅从 `--model-name` 机械迁移到 `--model`，但未像 `test_interactive_command.py:803` 或 `test_session_command.py:1129` 那样新增 `assert captured_requests[0].assembly_overrides.model_id == _MODEL_ID`
- **预期行为**: 三个 Agent surface 的 `model_id` 映射应有对等断言覆盖
- **实际行为**: prompt 命令的 `model_id` 转换通过共享 helper `_prepare_session_runtime` 隐式覆盖，但该测试未做精确断言。若有后续变更绕过 `_prepare_session_runtime` 或 prompt command 另有 assembly 路径，该回归可能不被捕获
- **直接证据**: `test_prompt_command.py` diff 仅一行变更（`"--model-name"` → `"--model"`），无新增 model_id 断言；对比 `test_interactive_command.py:803` 和 `test_session_command.py:1129`
- **影响**: prompt surface 的 model_id 契约缺少 direct assertion guard；当前由共享实现覆盖，但防御深度不足
- **建议改法和验证点**: 在 prompt 命令的 assembly override 相关测试中增加 `model_id` 显式断言，与其他两个 surface 对齐
- **修复风险（低）**: 纯测试增强
- **严重程度（低）**: 共享 `_prepare_session_runtime` 仍覆盖实际链路，实现本身正确
