## Findings

### F1 — `CompactRepairFeedbackV4.required_action` 带默认值

- severity: low
- file:line: `dayu/host/compaction.py:2437`
- evidence: `required_action: str = COMPACT_REPAIR_REQUIRED_ACTION`
- 规范要求: plan §3 "该 frozen/slots dataclass 无默认值"
- 实际行为: `required_action` 使用模块常量 `COMPACT_REPAIR_REQUIRED_ACTION` 作为 default；`__post_init__` 验证 `self.required_action != COMPACT_REPAIR_REQUIRED_ACTION` 时 raise，即默认值必通过校验。值为 frozen 常量，不可被调用方静默替换为错误值。
- 影响: 极低。调用方不传 `required_action` 时构造正确；传错值时 `__post_init__` 拒绝。不产生语义漂移。
- 反例: 若改为无默认值，所有内部构造点必须显式传 `COMPACT_REPAIR_REQUIRED_ACTION`，增加冗余但不改变行为。
- 建议修法: **accepted-as-is**。默认值是 frozen 常量且 `__post_init__` 强制校验，不构成"隐藏构造遗漏"。若严格遵循 plan 字面要求，可在后续 cleanup 中移除 default，但不阻塞 C1。
- verdict: **accepted**

### F2 — `CompactValidationIssueV4.source_labels` 带 `default_factory`

- severity: low
- file:line: `dayu/host/compaction.py:2339`
- evidence: `source_labels: tuple[str, ...] = field(default_factory=_empty_string_tuple)`
- 规范要求: plan §3 "frozen/slots dataclass 无默认值"（针对 `CompactAcceptedEvidenceFactV4` 和 `CompactAcceptedReplacementV4`）
- 实际行为: `CompactValidationIssueV4` 是 validation report / repair DTO，不是 core accepted domain type。`source_labels=()` 对于无关联 label 的 issue（如 `INVALID_JSON`、`DUPLICATE_JSON_KEY`）语义正确。`__post_init__` 校验唯一性。
- 影响: 无。报告 DTO 的 optional labels 不影响事实边界。
- 建议修法: **accepted-as-is**。plan "无默认值"约束主要针对 accepted fact / replacement / truth DTO；report DTO 的 optional field default 是合理设计。
- verdict: **accepted**

### F3 — `CompactOutputCapsV4` 缺 `__post_init__` 校验

- severity: low
- file:line: `dayu/host/compaction.py:1107-1151`
- evidence: `CompactOutputCapsV4` 有 9 个 `int` 字段、无默认值、`frozen=True, slots=True`，但无 `__post_init__` 校验非负性。
- 规范要求: plan §3 "该 DTO 不拥有默认值、数值校验或配置读取；所有字段只能由 Context Governance 从同一个 MemoryProjectionPolicy 实例机械投影"
- 实际行为: 设计意图是 caps 只由 governance 从 policy 机械投影，DTO 自身不做数值校验（校验在 governance 层）。`validate_compact_policy_usage_audit_replacement_binding_v4` 在 audit 端做 `actual > cap` 校验。
- 影响: 若直接构造 `CompactOutputCapsV4(session_summary_char_cap=-1, ...)`，DTO 自身不拒绝。但 governance 从 policy 投影时 policy 自身校验非负。
- 建议修法: **accepted-as-is**。plan 明确说 DTO "不拥有数值校验"，校验职责在 governance / policy owner。加 `__post_init__` 非负校验不违反设计但超出 plan 承诺。
- verdict: **accepted**
