### 2-HIGH — dispatch.py drain loop 在事务重试耗尽时自我关闭，导致级联不可用

- **入口/函数**: `HostDispatchScheduler._drain_loop()`
- **文件(行号)**: `dayu/host/dispatch.py:2756-2814`
- **输入场景**: 数据库持续繁忙导致 dispatch write 事务重试耗尽
- **实际分支**: 行 2781-2798: 捕获 `HostTransactionRetryExhaustedError` 后设定 `self._closed = True`、cancel 所有 active workers、标记 instance stopped
- **预期行为**: 重试耗尽应进入 graceful degradation — 将此轮未处理的 record 标记为 failed，继续处理下一轮 drain
- **实际行为**: scheduler 自我关闭，之后所有 `wake_dispatch` 调用收到 `RuntimeError("HostDispatchScheduler is closed")`，所有排队和新 Run 永久无法被 dispatch
- **直接证据**: 行 2792 (`self._closed = True`)；对比 `drain_once` 中行 2502-2504 对同一错误的正确处理（将 record 放回队列）
- **影响**: 单个 dispatch 事务重试耗尽 → 整个 scheduler 不可用 → 所有 Run 永久卡在队列中。级联故障放大
- **建议改法和验证点**: 移除 `_drain_loop` 中的 `except HostTransactionRetryExhaustedError` 处理（`drain_once` 已正确处理），或将 `_closed = True` 替换为仅标记当前 drain 轮次失败并继续
- **修复风险**: 低 — `drain_once` 已有正确的重试耗尽处理
- **严重程度**: 高

## Residual Risk

1. **测试密度不均**: `engine_ingest.py` (7136行) 对应 82 个测试函数，`dispatch.py` (4836行) 对应 81 个测试函数。God file 的测试覆盖倾向于"集成测试"而非拆分后的单元测试 — God file 拆分后需重写测试。
