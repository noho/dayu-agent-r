### 逐项审查结论

#### 1. durable memory snapshot integrity classifier 是否 read-only / direct evidence

**结论：PASS。** `inspect_memory_snapshot_integrity()`（`memory.py:500-527`）是纯只读扫描：它通过 Host read transaction 读取 snapshot durable row，按 JSON 解析→schema 校验→digest 校验→item kind 校验的顺序逐行分类，返回 `tuple[MemorySnapshotIntegrityIssue, ...]`。不执行任何 INSERT/UPDATE/DELETE。每个 failure kind 由直接证据驱动：
- `INVALID_JSON` ← `json.JSONDecodeError`（`memory.py:1277-1284`）
- `SCHEMA_MISMATCH` ← `conversation_memory_snapshot_from_json_value` 抛出 `TypeError`/`ValueError`（`memory.py:1285-1292`）
- `DIGEST_MISMATCH` ← `calculate_memory_snapshot_digest(snapshot) != snapshot.snapshot_digest` 或 `row_snapshot_digest != snapshot.snapshot_digest`（`memory.py:1293-1305`）
- `UNSUPPORTED_ITEM_KIND` ← item kind 为 `verified_fact` 或不在 allowed_kinds 中（`memory.py:1359-1379`）
- `STORAGE_READ_FAILED` ← `sqlite3.Error` 或 row 字段读取失败（`memory.py:516-523`, `1219-1226`, `1330-1337`, `1350-1358`）

#### 2. run_storage_maintenance 是否仍 operator-facing explicit maintenance，且 no silent rebuild/overwrite/quarantine

**结论：PASS。** `run_storage_maintenance()`（`storage_maintenance.py:248-317`）保持 operator-facing 显式 maintenance 入口。默认 dry-run（`reclaim_orphan_artifacts=False`），不删除任何文件或 row。memory snapshot integrity issues 仅作为只读诊断出现在结果中，maintenance 不对 damaged snapshot 执行任何 repair/rebuild/overwrite/quarantine 动作。设计文档（`docs/host/design.md`）明确声明："Operator-facing storage maintenance 可以只读分类 damaged snapshot row，分类结果用于诊断，不是 repair authorization；自动 overwrite、quarantine 或 rebuild 必须另行通过显式 maintenance / operator policy 设计，不能静默发生在 command path"。README（`dayu/host/README.md`）明确声明："不 quarantine / rebuild / overwrite memory snapshot"。

#### 3. public result/export/json 是否自解释不泄漏 payload

**结论：PASS。** `MemorySnapshotIntegrityIssue.json_value()`（`memory.py:178-192`）只输出 `failure_kind`、`message`、`snapshot_id`、`session_id`、`consumer_id`、`policy_digest`、`checkpoint_event_sequence`。不内联 snapshot JSON、prompt、tool payload 或大内容。`HostStorageMaintenanceResult.json_value()`（`storage_maintenance.py:210-227`）将 issues 作为 `memory_snapshot_integrity_issues` 列表嵌入，每个 issue 使用 `MemorySnapshotIntegrityIssue.json_value()` 的自解释格式。所有字段名均为业务可读名称，无内部标识符泄漏。测试 `test_storage_maintenance_result_json_value_is_stable_self_explaining_and_non_leaking`（`test_storage_maintenance.py:697`）显式验证 JSON 结构包含 `memory_snapshot_integrity_issues` 键且初始为空列表。
