### 1. 未修复-低-`_drive_interactive_tty_repl` LOST+queued 场景无测试覆盖

- **入口/函数**: `_drive_interactive_tty_repl`
- **文件(行号)**: `dayu/cli/session_execution.py:1276-1277`（`deferred_exit_code` 设置）、`dayu/cli/session_execution.py:1445-1451`（LOST exit 判断）
- **输入场景**: 当前 turn 返回 LOST terminal，同时 type-ahead 已提交一个 sole queued follow-up。
- **实际分支**: `deferred_exit_code` 被设为 `EXIT_FAILURE`（line 1277）；queued task 被 promote 为 `current`（line 1281-1286）；`current is not None` → exit check 不触发（line 1445）→ REPL 继续等待 queued terminal 完成后才 exit。
- **预期行为**: 代码行为是"已 durable accepted 的 queued Run 继续执行并等待 terminal 后才 exit"，这与 exit-after-cancel 的 queued-preservation 契约一致。但 LOST 单独测试 (`test_interactive_lost_is_fatal`) 仅覆盖单 turn 无 queued 场景，该组合路径无覆盖。
- **直接证据**:
  - Line 1277: `deferred_exit_code = terminal_exit_code`
  - Line 1281-1286: queued promote 在 `current = None` 之后执行
  - Line 1445: `if current is None and (deferred_exit_code is not None ...)`
  - 测试 `test_interactive_lost_is_fatal`（line 2176）只用 `("触发 lost",)` 单 turn
- **影响**: 行为自身合理；仅测试覆盖缺口。
- **建议改法和验证点**: 新增参数化测试：LOST terminal + type-ahead queued，验证 queued 必定完成且最终 exit code 为 EXIT_FAILURE。
- **修复风险（低）**: 仅新增测试，不修改生产代码。
- **严重程度（低）**: 真实 LOST+queued 概率极低（LOST 是 Host 灾难性错误）；行为自身符合 queued-preservation 契约。
