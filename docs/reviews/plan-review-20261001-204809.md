## six lenses

1. **Goal-bound minimal design**：5 增 1 删逐项映射 root A4 最小合同（裁决 :65–66）：共享 owner helper、两 writer 复用、CN/SEC 保全、processed 原状态机、三步回归。无目标漂移：未新增字段/enum/数据模型/迁移，未借 A4 扩 CN/SEC 或 processed 通用改造（§6:126 明文禁止）。
2. **Architecture boundary**：来源标签派生放在日期解析 owner `hk_fiscal_calendar.py` 内，writer 只消费；manifest 只投影日期、不承载 marker。`cn_download_source_upsert` 引 `hk_fiscal_calendar` 与现有依赖方向一致（`cn_report_selection`、`hk_download_rebuild` 已引用），无反向依赖、无层穿透。
3. **Best practice**：显式 None 取代粘旧值与 writer-specific fallback，符合项目语义所有权纪律；`Literal["source_title"] | None` 签名可严格类型检查。
4. **Optimal-solution**：owner 模块内纯函数是 root 合同指定的最小路径；替代方案（抽共享 provenance enum）会扩 CN/SEC scope，被合同明确排除，非更优。
5. **Overengineering**：无新抽象层、无 builder/协议扩展；helper 为已解析日期的纯标签派生，最小。
6. **Overcoupling**：两 writer 共享同一规则定义是有意耦合（root：同一日期事实投影「不能各自定义」）；正常 download 与 processed 写入保持解耦；三步回归的跨 step 耦合由翻转 bug 的跨 writer 本质证成，非过度绑定。
