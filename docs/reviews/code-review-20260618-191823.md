### 4-已验证-[低]-event boundary 语义从 attempt.started_event_sequence 迁移到 run.input_event_sequence

**入口/函数**: `DurableAcceptedToolEvidenceMaterialProvider._load_accepted_tool_evidence_materials_tx`

**文件(行号)**: dayu/host/run_input.py (L1380-1385)

**输入场景**: Attempt dispatch 前的 evidence material 读取

**实际分支**: 旧代码使用 `before_event_sequence=current_facts.attempt.started_event_sequence`；新代码通过 `run=current_facts.run` 传入，`build_pre_dispatch_compact_material_view` 内部使用 `run.input_event_sequence`

**预期行为**: accepted tool evidence 读取的上界应覆盖当前输入之前的所有 post-compact delta events。

**实际行为**: `run.input_event_sequence` 是当前 `USER_INPUT_ACCEPTED` 的 event_sequence，`attempt.started_event_sequence` 是 attempt dispatch 的 event_sequence。两者在正常流程中 `input_event_sequence <= started_event_sequence`，新边界更宽或相等，不会遗漏 evidence。旧 SQL 用 `event_sequence < before_event_sequence` 排他上界；新 material view 用 `end_sequence=current_event.event_sequence` 构造 delta，语义一致但边界更准确（以 input 为界，不以 attempt 为界）。

**直接证据**: dayu/host/run_input.py L1380-1385 (新) vs git diff 中旧 `before_event_sequence=current_facts.attempt.started_event_sequence`

**影响**: 无遗漏风险。新边界更准确，以当前输入为上界。

**建议改法和验证点**: 无需修改。

**修复风险（低/中/高）**: 低

**严重程度（低/中/高/严重）**: 低
