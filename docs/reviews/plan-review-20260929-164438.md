## Findings

### 1-未修复-中-usage fact 的唯一 producer 与 hint 合同没有覆盖 format 路径
- **位置**: state plan §5“typed usage fact 与 public failure 各有唯一 owner”、S1 owner 测试；Sol `upload-material-state-plan-prc3f1-fix-20260929.md` §动机与一手 owner 证据、§方案、§测试白名单。
- **问题类型**: 契约缺失 / 语义 owner 不唯一 / LLM-facing 投影不闭合。
- **当前写法**: plan 把当前 `ingestion_runtime.py:fins_upload_usage_failure` 与 `_USAGE_MESSAGES` 写成 Fins usage owner，要求它产生 typed code、message 和 hint；新增 `FinsUploadUsageFailure.hint` 并由“同一个 usage producer”填入；`upload_failure.py` 唯一映射 public reason，tool 只消费同一 fact 的 message/hint。
- **反例/失败场景**: 当前 `FinsUploadUsageFailure.code` 同时接受 `FinsUploadUsageCode | FinsUploadFormatFailureKind`，但 `_raise_upload_format_usage` 在 `ingestion_runtime.py:1121-1134` 直接执行 `FinsUploadUsageFailure(code=error.kind, message=str(error))`，不经过 `fins_upload_usage_failure`/`_USAGE_MESSAGES`。给 fact 增加必填 hint 后，实施 Agent 只能：(a) 让现有 format usage 路径构造失败；(b) 在 `_raise_upload_format_usage` 再造 message/hint，形成第二 producer；或 (c) 让 tool 对 format typed usage 回退 `_INVALID_ARGUMENT_HINT`，破坏同源 hint。若 hint 为 optional，当前 `_failed_outcome(..., hint: str)` 又要求非空 tool hint，typed 分支仍需另定 fallback。
- **为什么有问题**: 这与 plan 自己的“同一 usage producer 填入”“没有第二张 code→hint/message 表”“tool 只读取同一 fact.message/hint”直接冲突。并且 `FinsUploadFormatError` 已有 `file_label`，现有 `upload_failure.py` 的 format→public reason 会保留 `file_label`；仅给 fact 增加 message/hint 未说明该字段如何保持同源，无法证明 tool、direct/awaited public reason 与既有 format projection 不漂移。
- **直接证据**: `dayu/fins/ingestion_runtime.py:707-740`（fact 仅 code/message，code union 含 format kind）、`:1027-1097`（`_USAGE_MESSAGES`/`fins_upload_usage_failure` 只接受 `FinsUploadUsageCode`）、`:1121-1134`（第二个生产构造点）、`dayu/fins/upload_format_contract.py:41-111`（format kind/message/file_label 真源）、`dayu/fins/upload_failure.py:232-239`（format error 映射 `UNSUPPORTED_UPLOAD_FORMAT` 并保留 file_label）、`dayu/fins/tools/_ingestion_tool_helpers.py:55-85`（tool hint 为必填 `str`）。
- **影响**: 实施时可能产生双 message/hint 真源、format typed usage 在 tool 或 job 汇总中丢 hint/file_label、LLM-facing 恢复提示漂移；也可能因必填字段/类型不闭合触发 pyright 或运行时失败。PR-C3-F1 不能视为完整闭合。
- **建议改法和验证点**:
  - 明确定义一个 typed usage producer 覆盖 `FinsUploadUsageCode` 与 `FinsUploadFormatFailureKind`，或明确 format fact 由 `upload_format_contract` producer 唯一产生后只由 usage owner 装箱；禁止 `_raise_upload_format_usage` 自拼 message/hint。
  - 明确 `hint` 为必填、1..240、path-free，或明确 optional 语义并同步修改 tool contract；不允许 tool fallback 到通用 hint。
  - 明确 format kind 到既有 `UNSUPPORTED_UPLOAD_FORMAT` public code 的单一映射，并保持 message/hint/file_label 与原 projection 同源；target 三码仍映为同值 `USAGE` code。
  - owner 测试覆盖全部 format kind、现有 usage codes、三个 target code 的 fact 字段/安全 hint、唯一 public 映射、tool typed 分支 exact message/hint、JSON round-trip 与 filing 旧文案不漂移。
- **修复风险（低/中/高）**: 中。
- **严重程度（低/中/高/严重）**: 中。
