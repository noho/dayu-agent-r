- **位置**：plan §6.6 fingerprint 冻结段；§12 第 5 行"保持 identical-skip"。
- **问题类型**：契约缺失
- **当前写法**：§6.6 规定 filing descriptor 只含 `original_filename`/`sha256`/`size`/`source`；§12 称"fingerprint 排除 identity，因此保持 identical-skip"，未声明与旧 fingerprint 格式（key 为 `name`）的跨界行为。
- **反例/失败场景**：修复前已发布的 filing（meta 存旧 `source_fingerprint` = hash(json([{name,sha256,size,source}]))）；修复后同路径同内容重传，新 fingerprint = hash(json([{original_filename,...}]))，两个 JSON 序列化不同 → fingerprint 不相等 → `_can_skip_upload` 不跳过，走 update（版本 +1、全树以 identity 名重建）。这本身是 fresh-schema 下把旧 basename 树迁移到 identity 树的合理路径，但 plan 未声明，实现者/后续 evidence 可能把首次 update 误判为回归。

- **影响**：用户可见一次性 update 未声明 / 后续 evidence 误判 / 风险后移。
- **建议改法和验证点**：在 §6.6 或 §12 增加一句：跨 schema 首次重传（旧 `name` key）必然 update 一次并完成树迁移，之后 identical-skip 恢复；迁移后 skip 语义归 UF-FIX08 边界说明。可选：Slice 4 Fins README 同句。
