### 01-未修复-[中]-缺少 log-file 与全部合法 debug-stream 组合的行为测试

- **入口/函数**: `parse_cli_args()` 的公开日志参数组合，以及 S5 行为测试矩阵
- **文件(行号)**: `tests/cli/test_arg_parsing.py:1844`、`tests/cli/test_arg_parsing.py:1891`
- **输入场景**: `--debug-stream --log-file diagnostics.log`，以及 14 个非 quiet selector 中任一个与 `--debug-stream --log-file diagnostics.log` 的三项组合
- **实际分支**: `test_debug_stream_is_orthogonal_to_every_non_quiet_selector` 只组合 selector 与 `--debug-stream`；`test_log_file_is_independent_from_every_log_level_selector` 只组合 selector 与 `--log-file`。没有测试 standalone debug-stream + log-file，也没有测试 14 个 selector + debug-stream + log-file。
- **预期行为**: S5 plan 与 frozen `prompt.19-log-selector-exclusion-and-debug-stream` 要求 `--log-file` 同时独立于 selector 和所有合法 `--debug-stream` 组合；测试应直接覆盖这 15 个 argv shape，并断言 canonical ordinary level、`debug_stream=True` 与 `log_file` 同时保留。
- **实际行为**: 当前生产 parser 对抽查的 standalone 与 critical 三项组合解析正确，但现有 suite 无法阻止未来把 `--log-file` 错误放进 debug-stream 冲突组、或在 finalizer 中只对三项组合误拒绝的回归；implementation artifact 的“log-file 全组合”也超过了现有测试证据。
- **直接证据**: `tests/cli/test_arg_parsing.py:1844-1863` 的 argv 不含 `--log-file`；`tests/cli/test_arg_parsing.py:1891-1909` 的 argv 不含 `--debug-stream`。独立对抗性解析确认当前实现能接受两类三项组合，因此这是验收/回归保护缺口，不是已经发生的生产行为错误。
- **影响**: frozen PC-DS 真实场景均使用 `--log-file` 取证；在 S5 单元/行为 gate 内缺少与真实 argv shape 同构的证明，后续三项交互回归可能在进入昂贵真实 CLI 重放前不被发现。
- **建议改法和验证点**: 从现有 `_NON_QUIET_LOG_LEVEL_SELECTOR_CASES` 派生 14 个 case，并增加 standalone case；每个 case 都加入 `--debug-stream --log-file diagnostics.log`，断言 canonical level 未改变、debug stream 为真且 log file 路径保留。不要新增第二份 spelling/spec。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
