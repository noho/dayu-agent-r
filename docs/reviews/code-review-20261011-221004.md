### AGG-001-未修复-高-rebuild 把空 source fingerprint 重新认证为可快跳状态

- **裁决建议**: `accepted`，由 root 最终裁决。
- **入口/函数**: 用户执行 `dayu-cli download --rebuild` 后再执行普通增量下载；问题入口为 `rebuild_single_local_filing`，随后由 `SecPipeline._can_skip_fast` 在普通下载 Phase A 直接快跳。
- **文件(行号)**: `dayu/fins/pipelines/sec_download_state.py:449`、`dayu/fins/pipelines/sec_download_state.py:453`、`dayu/fins/pipelines/sec_download_state.py:475`、`dayu/fins/pipelines/sec_rebuild_workflow.py:346`、`dayu/fins/pipelines/sec_rebuild_workflow.py:393`、`dayu/fins/pipelines/sec_pipeline.py:1357`、`dayu/fins/pipelines/sec_pipeline.py:1359`、`dayu/fins/pipelines/sec_download_filing_workflow.py:248`。
- **输入场景**: 一个 `download_version=sec_pipeline_download_v1.3.0`、`source_fingerprint=""` 的 COMPLETE publication，`files[]` 只有 `report.htm`，该 HTML 引用但未登记 `plot.jpg`。用户先运行本地 `--rebuild`，再运行普通增量下载，期望补齐必要图片。
- **实际分支**: rebuild 读取旧 `source_fingerprint` 为空，进入 `_resolve_rebuild_source_fingerprint` 的本地 descriptor 重建分支，调用 `build_source_fingerprint` 写回非空值；下一次普通下载在 Phase A 满足“非 overwrite + 当前版本 + 非空 fingerprint”，`_can_skip_fast` 返回 `already_downloaded_complete`，在 `list_filing_files`、正式 HTML GET、图片发现和图片 GET 之前返回。
- **预期行为**: 正式下载才拥有 remote descriptor 集合与 `source_fingerprint` 的认证权。rebuild 没有远端发现或 GET，必须原样保留旧 fingerprint，包括空值；因此该 publication 的空指纹状态仍应走基础 GET、完整图片发现和必要 GET，不能由本地 metadata-only rebuild 获得快跳资格。approved plan 已明确“rebuild 不产生新的下载集合认证”“文件 hash/fingerprint/document_version 不因 rebuild 升级”。
- **实际行为**: 空 fingerprint 被改写为 `4d0e52586a7fed04d604b2e98e40da5a98b500b217f9aca017ffa806df00e373`，文件集合仍只有 `report.htm`；普通增量返回 `status=skipped`、`reason_code=already_downloaded_complete`，请求列表为空，缺失 `plot.jpg` 永远不被发现或下载。
- **直接证据**: 独立探针 `workspace/tmp/sec-html-image-assets-aggregate-mimo/probes/rebuild_empty_fingerprint_probe.py` 使用正式 blob/source/batch API 建立边缘 publication，真实执行 `SecPipeline.download(rebuild=True)` 和单 filing workflow；`workspace/tmp/sec-html-image-assets-aggregate-mimo/logs/rebuild_empty_fingerprint_probe-attempt4.log` 记录 fingerprint 从 `""` 变为上述值、`rebuilt_names=("report.htm",)`、普通终态 skip、`ordinary_requests=[]`，探针按预期以 assertion 退出 1。代码上 `sec_download_state.py:449-475` 只在旧 fingerprint 非空时保留它，否则由本地 `file_entries` 构造新 fingerprint；`sec_rebuild_workflow.py:393` 随后写回。测试缺口也同源：`tests/fins/test_sec_html_image_assets.py:390-406` 的 rebuild 用例调用 `_seed(..., version)` 时未设 `empty_fp=True`；`tests/fins/test_sec_pipeline_download.py:2649-2659` 只证明非空 `published-fingerprint` 被保留。
- **影响**: 本地 rebuild 会把一个仍缺必要图片的来源提升为“已有完整下载结果”，普通增量零请求静默跳过。财报 HTML 的必要视觉依赖持续缺失，用户看到 COMPLETE/skipped，无法依靠已承诺的普通补齐路径恢复；只能发现异常后使用 `--overwrite`，破坏成功信号 2、3、4 的一致性。
- **建议改法和验证点**: 在 fingerprint 的正式下载认证 owner 下收束语义：rebuild 对 `previous_meta["source_fingerprint"]` 做原值保留，空值仍为空值，不再从本地 `file_entries`/HTTP metadata 反推 remote fingerprint；若 `_resolve_rebuild_source_fingerprint` 只服务该错误语义，应删除而不是保留兼容 wrapper。新增 owner 回归：空 fp + 当前版本 + 缺图，rebuild 后 `source_fingerprint` 仍为空、`download_version/document_version/files/hash` 不变，普通下载继续 GET HTML、发现 `plot.jpg`、GET 并完整发布；同时保留旧版本 rebuild 不授予 download version、非空 fingerprint 不变和失败原子性测试。修后需独立 re-review，不能用现有非空 fingerprint 测试替代。
- **修复风险（低/中/高）**: 中。修改会收紧 rebuild 对历史空 fingerprint 的处理，可能暴露依赖“由本地 metadata 重建 fingerprint”的旧数据路径；应按当前全新契约修复并以 owner 测试锁定，不加旧库/旧 meta 兼容分支。
- **严重程度（低/中/高/严重）**: 高。
