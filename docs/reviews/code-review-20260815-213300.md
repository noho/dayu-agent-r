#### 3. 100 上限一致性审查

- Runtime: `_MAX_TUPLE_ITEMS = 100` (`ingestion_runtime.py:150`)，校验于 `ingestion_runtime.py:1069`
- Tool schema: `"maxItems": 100` (`upload_tools.py:243`)
- CLI: `nargs="+"` 无显式上限 (`arg_parsing.py:925`)，依赖 runtime 校验

CLI 没有 argparse 级 max 上限，但 runtime 校验保证一致行为。Tool schema 的 `maxItems` 防止 LLM 发送超限请求。CLI 用户输入超限时获得与 runtime 一致的 usage failure。这是可接受的一致性设计——CLI argparse 不支持原生 maxItems，runtime 是单一真源。

#### 4. 碰撞隔离审查

`_build_filing_original_asset_identity` (`docling_upload_service.py:1090-1114`):

```python
digest_input = (
    _FILING_ASSET_IDENTITY_NAMESPACE.encode("utf-8")
    + _FILING_ASSET_IDENTITY_SEPARATOR
    + normalized_path.as_posix().encode("utf-8")
)
path_digest = hashlib.sha256(digest_input).hexdigest()
return f"{_FILING_ORIGINAL_ASSET_PREFIX}{path_digest}{normalized_path.suffix.lower()}"
```

- 不同目录同 basename → 不同 posix path → 不同 digest → 不同 identity ✓
- 同 stem 不同后缀 → 不同 suffix → 不同 identity ✓
- 绝对路径明文不进入 identity ✓
- `original_filename` 独立保存为用户可读 basename ✓
- `_require_unique_filing_original_identities` 断言同次请求 identity 唯一 ✓

测试 `test_filing_same_basename_assets_are_collision_free_and_path_private` (`test_docling_upload_service.py:1253`) 直接验证两个不同目录的 `report.pdf` 产生不同 identity 且不泄漏路径明文。
