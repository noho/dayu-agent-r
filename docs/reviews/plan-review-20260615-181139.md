### DS-001 / MiMo-001 — async/sync boundary（已修复）

修后 plan 已将 S2 从"强制 adapter 消费 async pipeline stream"改为"runtime-owned coarse progress"：

- **L60-62**（第一性原理判断）: "当前 work unit 采用低风险 runtime-owned coarse progress，不在本轮强行改造同步 adapter 去消费 async pipeline stream"
- **L149-150**（Contract 章节）: "本 work unit 不修改 `FinsSourceDownloadAdapter.download(...)` protocol，不新增必填 `event_sink` 参数。"
- **L151**（Contract 章节）: "本 work unit 不修改 `FinsUploadRunner.run_upload(...)` protocol，不新增必填 `event_sink` 参数。"
- **S2 L278**（Slice 2 objective）: "在不修改 adapter/runner protocol 的前提下，把 download/upload 同步调用边界和 preprocess runtime progress 映射为 bounded Fins job `PROGRESS` events。"
- **S2 L290-291**: "不修改 `FinsSourceDownloadAdapter.download(...)` 签名；不要求 `SecDownloadAdapter` / `CnDownloadAdapter` 消费 `download_stream(...)`。"
- **S2 L293**: "不修改 `FinsUploadRunner.run_upload(...)` 签名"
- **S2 L308**: "adapter/runner protocol 保持同步；本 work unit 不改变 `FinsIngestionThreadExecutor` threading model，也不引入 event loop ownership 变更。"

与 adjudication 裁定对照：_"Change S2 to the lower-risk path: do not change adapter protocols in this work unit. Emit coarse progress from FinsIngestionRuntime around existing synchronous adapter/runner calls"_ — 完全满足。

### DS-002 / MiMo-002 — adapter protocol blast radius（已修复）

### DS-003 / MiMo-003 — progress event failure propagation（已修复）

修后 plan 修正了故障传播策略：

- **S1 L253**: "non-terminal progress / observation event append 失败不得导致 job failed；记录 bounded `WARN` 日志并继续执行业务路径。日志只能包含 job id、operation kind、event type、bounded payload keys/counts、异常类型和简短错误文本，不输出原文、绝对路径或 raw payload。"
- **S1 L254**: "terminal event append 失败不得回滚已经保存的 terminal job record；记录 bounded `WARN` 日志，Service terminal fallback 仍可通过 `read_job()` 结束等待。"
- **S2 L309**: "单个 progress event 映射或写入失败不得使对应 job failed；这类事件是观测/UI 信号，不是业务 terminal truth。runtime 记录 bounded `WARN` 并继续执行业务路径。"
- **S2 L310**: "terminal job record 仍是业务状态真源。terminal event append 失败也只记录 bounded `WARN`，Service terminal fallback 仍可结束等待。"

与 adjudication 裁定对照：_"State that non-terminal progress event append failure logs bounded WARN diagnostics and continues. Terminal job record remains truth."_ — 完全满足。旧版"单个 pipeline event 映射失败应使对应 job failed"已被彻底替换。

### MiMo-004 — sidecar file locking（已修复）

修后 plan 明确了 lock 策略：

- **L139**: "event sidecar append/read sequence allocation 必须使用 `FsFinsIngestionJobStore` 已有同一把 runtime file lock，与 job record operations 共享锁保护。除非 implementation 以并发测试证明更窄锁不会导致 sequence race、terminal/event race 或 read-after-terminal gap，否则不得引入独立 sidecar lock。"
- **S1 L233**: "`FsFinsIngestionJobStore` 使用 `<job_id>.events.jsonl` sidecar 追加事件；append/read sequence allocation 使用与 job record operations 相同的 `RuntimeFileLock`，在该锁下读取最后 sequence 并写入下一条。不得默认引入独立 sidecar lock，除非以并发测试证明更窄锁安全。"

与 adjudication 裁定对照：_"Specify that event sidecar append/read sequence allocation uses the same FsFinsIngestionJobStore runtime file lock as job record operations"_ — 完全满足。且留有 evidence-based 例外路径（以并发测试证明更窄锁安全）。

### DS-004 / MiMo-005 — poll interval（已修复）

### DS-005 / MiMo-006 — log helper reuse（已修复）

修后 plan 明确要求复用已有 helper：

- **S5 L464**: "main 不手写 `debug` / `verbose` / `quiet` / `--log-level` precedence 映射；log-level 解析与装配真源仍是 `dayu.runtime.log`。"

### DS-006 / MiMo-007 — synthesized terminal WARN（已修复）

修后 plan 要求合成时记录 WARN：

- **S3 L350**: "写一条 bounded `WARN` 日志后合成 terminal `FinsDirectJobEvent` 并停止，防止事件 sidecar 写入失败导致 UI 悬挂。"
- **S3 L366**: "synthesized terminal fallback 必须 WARN，日志只包含 job id、terminal status 和 fallback 原因，不输出业务 payload。"
- **S3 L372**（tests/validation）: "service 在没有 terminal event 但 job record terminal 时合成 terminal，并产生 bounded WARN。"
- **L568**（Tests/Validation 期望断言）: "Service synthesized terminal fallback 产生 bounded WARN。"

与 adjudication 裁定对照：_"Require a bounded WARN log when Service synthesizes terminal event from terminal job record without seeing a terminal event sidecar entry."_ — 完全满足。

### MiMo-008 — status vs observation/progress event semantics（已修复）

修后 plan 明确了事件类型的语义区分：

- **L114-115**: "可以使用单个 enum，但必须用中文 docstring 或 helper 明确区分 status transition events 与 observation/progress events"
- **L116-123**: 明确列出 7 个 event type，并用说明分隔：
  - "status transition events：`JOB_QUEUED`、`JOB_RUNNING`、`JOB_SUCCEEDED`、`JOB_FAILED`、`JOB_CANCELLED`，只表示 job record 状态已发生对应转换；状态真源仍是 terminal job record，不是 event sidecar。"
  - "observation/progress events：`PROGRESS`、`CANCEL_REQUESTED`，只表示用户可见观察信号或 cancel 请求观察信号，不推进 job state"
- **S1 L231-232**: "`FinsIngestionJobEventType` 的 docstring/helper 必须把 status transition events 与 observation/progress events 分类清楚；单 enum 可接受，但不得让 `PROGRESS` / `CANCEL_REQUESTED` 被实现为 job state transition。"

与 adjudication 裁定对照：_"Clarify event type semantics in the plan. A single enum is acceptable if docstrings/helpers distinguish status events from observation/progress events."_ — 完全满足。
