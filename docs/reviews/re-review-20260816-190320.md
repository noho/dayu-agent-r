## Focus 2：test seam 是否严格匹配 protocols、无过度 mock/错误 owner/脆弱偶然顺序

**通过。**

`_SecPhaseBMutationCalls` dataclass：

- 严格类型：`int` 字段，无 `Any`/`object`/默认值歧义。
- 与 SEC batching/source/blob repository protocol 精确对齐：`begin`/`commit`/`rollback` 对应 `BatchingRepositoryProtocol`；`staged_classify` 对应 `SourceDocumentRepositoryProtocol.classify_staged_source_integrity`；`reset` 对应 `SourceDocumentRepositoryProtocol.reset_source_document`；`blob` 对应 `DocumentBlobRepositoryProtocol.store_file`。

monkeypatch 选择：

- `observe_begin`：只观察 + 委托真实实现，不改变行为。与 protocol 匹配（`begin_batch(ticker) -> BatchToken`）。
- `classify_staged_unsafe`：唯一替换返回值的 monkeypatch。返回值由 `SourceIntegrityClassification.__post_init__` 校验 invariant（`UNSAFE + revision=None + non-empty unsafe reasons`），与 storage owner 产生的 typed fact 格式完全一致。`del batch` 合理——该 spy 不需要使用 batch，但签名必须匹配 protocol。
- `reject_reset`/`reject_blob`/`reject_commit`：fail-closed spy，若被调用则测试立即失败。签名与对应 protocol 方法精确匹配。
- `observe_rollback`：只观察 + 委托真实实现。确保 rollback 真实执行（而非只计数）。

约 260 行 instrumentation 的必要性：

- `_SecPhaseBMutationCalls`（12 行）：typed counter，替代 `nonlocal` 散布的多个计数器。
- `observe_begin`（18 行含 docstring）：必须观察 + 委托，不能只用 `begin_calls` nonlocal，因为需要返回真实 token。
- `classify_staged_unsafe`（22 行含 docstring）：必须返回 invariant-valid typed fact，不能简化。
- `reject_reset`（18 行含 docstring）：fail-closed + 计数。
- `reject_blob`（22 行含 docstring）：签名较长（6 参数含 optional），protocol 要求。
- `reject_commit`（14 行含 docstring）：fail-closed + 计数。
- `observe_rollback`（16 行含 docstring）：观察 + 委托。
- `collect_single`（16 行含 docstring）：async generator 消费 helper。
- test body（~80 行）：seed、pipeline 构造、monkeypatch 注入、filing record、assertion 块。

每个 helper 都有完整中文 docstring（Args/Returns/Raises）。无过度 mock——只 monkeypatch 了 UNSAFE gate 之后的 mutation 边界，provider prefetch 和 Phase A 路径全部真实执行。无脆弱偶然顺序——断言使用精确相等（`calls == _SecPhaseBMutationCalls(begin=1, ...)`），不依赖列表顺序或计数器递增顺序。
