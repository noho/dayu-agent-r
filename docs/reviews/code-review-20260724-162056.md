## Residual Risk

1. **Service 与 Host 布局常量重复**：Service 的 `_directory_candidate` 持有独立布局常量，虽由 Host cross-validate 兜底，但若 Host 未来变更布局且 Service 未同步更新，会导致目录输入被 Service 误分类后再被 Host 拒绝。当前 Host reject 消息足够明确（包含 "does not match input mode layout"），用户可通过传入更具体的 `.dayu` 路径或 cold JSONL 文件绕过。风险等级：低。

2. **`ToolTraceAnalysisInputError` 未在 Host public API 导出**：Service 和 `analyze_tool_trace` 的 docstring 引用该类型，但调用方无法从 `dayu.host` 导入并按类型捕获。当前 CLI 以 `except Exception` 兜底，行为正确，但若未来 Service 需要按 `ToolTraceAnalysisInputError` 做差异化处理（如区分 usage error 和 runtime error），则需先将该类型纳入 Host public API。风险等级：低。

3. **`_build_source` 的 `except (OSError, TypeError, ValueError)` 范围**：当前精确匹配 `ToolTraceAnalysisSource.__post_init__` 可能抛出的异常类型。若 Host 未来新增异常类型（如自定义 `ToolTraceAnalysisContractError`），会穿透 Service 到 CLI 的 `except Exception`。当前不影响正确性（退出码仍为 1），但 user-facing message 会缺少 "Tool Trace 输入布局无效" 前缀。风险等级：低。
