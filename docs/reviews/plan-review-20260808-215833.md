## Assumptions tested

1. **Goal-bound minimal design**：当前 goal 已把三类 sizing predicate 分开，plan 没有扩展成产品修复、wrapper、provider
   request interception、child allowlist、storage 旁路或 B2 自动接受。
2. **Stage/action owner**：`dayu/host/context_budget.py:1429`显式拥有五阶段矩阵；ordinary soft 才
   `compact_soft_threshold`，post-compact normal/soft 为`allow_dispatch`、hard 为`block_hard_threshold`。
   `dayu/host/dispatch.py:2539`与`:2584`在 accepted 后追平 Memory 并以`POST_COMPACT`重建 complete candidate；
   `tests/host/test_dispatch_scheduler.py:5206`直接验证 ordinary budget → request → accepted terminal → post-compact budget →
   Run/Attempt 的顺序。
3. **R2/R3 trigger 与 consumption 不混用**：plan §2、§5.2、§5.3、§5.5、§8、§10均要求 pre-compact
   `ordinary`候选满足`soft <= predicted < hard`、compact action及同 operation request/terminal linkage；每个 accepted 后另取唯一
   `post_compact`候选，直接绑定 accepted truth、满足`predicted < hard`与 allow，并绑定实际 Run/Attempt/execution/dispatch。
   ordinary/post-compact ref 互换和 pre-compact digest 冒充 consumption 均进入二值 corruption failure。
4. **R4 reconnect**：R4 的独立`ordinary`候选必须消费第二次 accepted truth、action=allow、Run/Attempt/dispatch identity 相等且
   proactive operation count=2；soft-trigger/第三 operation 只能在既有 99-call 与 deadline 内收口后 seal 为
   `needs-more-evidence`，不能冒充 reconnect。corruption matrix 明确拒绝 compact action或第三 operation。
5. **真实双端口 seam**：`dayu/host/api.py:837`的同一`HostLocalExecutionOptions`确实同时拥有
   `worker_factory`与`context_compactor`；`dayu/host/dispatch.py:1412`的`HostDispatchScheduler.open`消费该 typed options，
   ordinary dispatch在`:4653`调用前者，proactive path在`:2269`调用后者。该 seam 真实存在，并非 plan 发明。
   plan同时要求两 ledger call identity disjoint、分别与 ordinary runner manifests及compactor proposal manifests/attempts/terminals
   exact equality，且同 durable store/transaction runner、production admission/service API closure成立；direct SQL/store与
   `open_host`调用计数为0。

   provider-free proof，而 formal 固定 stock production CLI/default factory/production compactor，仅在 segment 后读取 canonical truth；
