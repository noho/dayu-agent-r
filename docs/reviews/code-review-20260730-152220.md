### 002-未修复-低-PRESERVE workspace profile 存在性检查与加载之间存在极窄 TOCTOU 窗口

- **入口/函数**: `_load_target_min_context_window`
- **文件(行号)**: `dayu/cli/commands/init.py:415-434`
- **输入场景**: PRESERVE 模式下，workspace profile 文件在 `.exists()` 检查之后、`load_execution_profiles` 读取之前被并发删除或移动
- **实际分支**: `workspace_profile_exists=True` → loader 抛 `ConfigLoadError` → 进入 `if workspace_profile_exists` 分支 → 报 workspace 错误；但如果文件在检查后被删除，loader 的 `_load_layered_config_file` 走 `workspace_path.exists()=False` 路径回退到 package layer，不会抛异常
- **预期行为**: 如果文件在检查后消失，应报 workspace profile missing 或 fallback 到 package layer
- **实际行为**: 若文件在 `.exists()` 之后消失但 loader 先于文件消失完成读取，行为正确；若文件在 loader 的 `workspace_path.exists()` 之前消失，loader 回退到 package layer 而不报错，此时 `workspace_profile_exists` 的 true 判断不会被触发，因为没有异常。极端场景：文件在 `.exists()` 之后、loader 读取 JSON 之前被替换为 malformed 内容，此时 loader 抛 `ConfigLoadError`，`workspace_profile_exists=True`，报 workspace 错误——行为正确
- **直接证据**: `init.py:415-418` 的 `workspace_profile_exists` 检查；`config_loader.py:983-986` 的 `workspace_path.exists()` 回退逻辑
- **影响**: 极窄窗口下的最坏情况是：文件消失时静默回退到 package layer（而非报 workspace 错误），这在 init 锁内且单用户场景下几乎不可触发
- **建议改法和验证点**: 当前实现在 init lock 保护下可接受。若要消除窗口，可在 loader 内部记录 workspace file 是否被读取并传出，但这对当前场景是过度设计
- **修复风险（低/中/高）**: 低（可接受的已知边界）
- **严重程度（低/中/高/严重）**: 低

### 003-未修复-低-Ollama template default 低于 target minimum 时用户无法使用默认值

- **入口/函数**: `_select_model` Ollama 分支
- **文件(行号)**: `dayu/cli/commands/init.py:470-474`
- **输入场景**: 选择 Ollama（choice 14），且 package Ollama template 的 `context_window_tokens` 低于 target execution profile minimum
- **实际分支**: `_read_context_window` 的 default 是 `defaults.context_window_tokens`（Ollama template 值），若低于 minimum 则走 `value < minimum` 分支 retry
- **预期行为**: 按 implementation artifact："Ollama 保留 template default，但低于 target minimum 的默认或显式输入均在 context 步骤 retry"
- **实际行为**: 用户按 Enter 采用默认值 → 默认值低于 minimum → 报错 retry → 用户必须手动输入 >= minimum 的值。行为符合 spec，但 prompt 显示的 `[defaults.context_window_tokens]` 暗示该值可用
- **直接证据**: `init.py:471` 的 prompt 使用 `defaults.context_window_tokens`；`init.py:621` 的 `value < minimum` 检查
- **影响**: 用户体验略差——prompt 显示的默认值实际不可用，需要额外一次 retry 才能发现。不影响正确性
- **建议改法和验证点**: 可考虑在 prompt 中显示 `max(defaults.context_window_tokens, min_context_window_tokens)` 作为实际默认，或在 minimum > default 时将 default 调整为 minimum。但这改变了 implementation artifact 明确记录的 "Ollama 保留 template default" 语义，需 controller 决策
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
