### DC-01: `--thinking` / `--detail` 语义确认

- **入口**: `dayu/cli/arg_parsing.py` — `_new_default_namespace` 设置 `thinking=True`, `detail=True`
- **验证**: `--thinking` / `--no-thinking` 和 `--detail` / `--no-detail` 仅控制 CLI 运行态展示，不进入 `RunnerSpec`、`RunnerCallOptions`、`AgentPolicy`、`AgentRunRequest` 或 provider 请求。CLI 代码中 `thinking` 参数只传递到 `CliThinkingRenderer`，`detail` 参数只控制 `InteractiveRunView` / `CliActivityRenderer` 是否创建。pyright `0 errors` 确认无类型泄漏。
- **结论**: 符合设计意图。默认值从 `--no-thinking` / `--no-detail` 变为 `--thinking` / `--detail` 是有意行为变更，README 已同步。

### DC-02: HostThinkingView / Service EntrypointThinking / CLI renderer 分层确认

- **Host 层** (`dayu/host/engine_ingest.py:897-901`): `REASONING_DELTA` 从 transient delta（不写 EventLog）改为写入 PREVIEW row。`_preview_payload` 补充 `iteration_id` 和 `delta` 字段。
- **Host 读取层** (`dayu/host/read_api.py:1106-1121`): `_thinking_from_row` 只对 `REASONING_DELTA` event_type 投影 `HostThinkingView`，非 reasoning delta 返回 `None`。
- **Host API** (`dayu/host/api.py:2648-2663`): `HostThinkingView` 是 frozen dataclass，`text_delta` 必须非空。`HostEvent.thinking` 默认 `None`，terminal event 不允许携带 thinking（`_validate_host_event_terminal_payload` 抛 `ValueError`）。
- **Service 层** (`dayu/service/entrypoint_runtime.py:221-255`): `EntrypointThinking` DTO 从 `HostEvent.thinking` 转换。`_emit_entrypoint_thinking_from_host_event` 过滤终态事件、run_id 不匹配和重复 dedupe_key。
- **CLI 层** (`dayu/cli/thinking.py`): `CliThinkingRenderer` 消费 `EntrypointThinking`，输出到 stderr，160 字符单行截断，关闭后不再输出。
- **结论**: 三层职责边界正确。Host 不暴露 durable internals，Service 只做 DTO 转换和去重，CLI 只做 stderr 渲染。thinking 不进入 final answer、activity、transcript、outbox terminal projection 或 canonical replay。

### DC-03: MANUAL-F01 snapshot digest fix 确认

- **修改**: `dayu/host/durable/state.py` — `WaitSnapshotRef.snapshot_digest` 从 `str | None` 改为 `str`，校验从 `_require_optional_non_empty_text` 改为 `_require_sha256_digest`。
- **反序列化**: `deserialize_wait_snapshot_ref` 补充 `snapshot_digest is None` 检查，三个字段必须同时存在。
- **计算**: `dayu/host/tool_runtime.py` — `_wait_snapshot_ref` 调用新 `_wait_snapshot_digest` 函数，用 `sha256_digest_json({"captured_at": ..., "snapshot_id": ...})` 计算确定性 digest。
- **结论**: digest 现在是必填且经过 SHA-256 格式校验。反序列化三字段配对检查正确。digest 计算使用确定性 JSON 结构，与 `format_utc_timestamp` 一致。不会引入 outbox/transcript/final answer/activity 污染。

### DC-04: REASONING_DELTA 分类变更确认

- **旧行为**: `REASONING_DELTA` 与 `CONTENT_DELTA`、`TOOL_CALL_DELTA` 一起被 `_is_transient_delta_event` 过滤，不写入 EventLog。
- **新行为**: `REASONING_DELTA` 在 `_is_transient_delta_event` 检查之前被拦截，写入 PREVIEW row。
- **影响**: `CONTENT_DELTA` 和 `TOOL_CALL_DELTA` 仍为 transient delta，不写 EventLog。`REASONING_DELTA` 现在写 PREVIEW row 供 live watcher 投影。
- **测试**: `test_engine_ingest_mapping.py` 更新：旧 `test_delta_events_are_accepted_without_event_log_rows` 拆分为 `test_non_reasoning_delta_events_are_accepted_without_event_log_rows` 和 `test_reasoning_delta_is_accepted_as_preview_for_live_display`。late terminal governance 测试也相应更新。
- **结论**: 分类变更正确，测试覆盖充分。
