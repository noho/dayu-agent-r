## Residual Risk

以下为非阻塞观察项，不构成 merge 阻断。

### RR-1: 无 per-model opt-out 机制

`_runner_spec_from_model(...)` 对所有 OpenAI-compatible 模型统一启用 `OPENAI_X_CLIENT_REQUEST_ID`，无配置项可按模型单独关闭。若未来某个 provider 拒绝 `X-Client-Request-Id` header，当前无运行时旁路，只能回滚此默认值或新增 typed policy 变体。当前代码/配置证据未发现该风险已触发；属于设计决策接受范围。

### RR-2: 测试覆盖边界小缺口

- `_bounded_diagnostic_id` 仅测试超过 256 字符截断，未测试恰好 256 字符的 passthrough 边界。
- `_terminal_diagnostics.py` 未测试 diagnostic id 包含换行符的场景（可能破坏 projection 格式）。
- `read_api._failed_host_event` 通过集成路径仅测试 `provider_request_id=None, client_correlation_id` 存在的情况；`provider_request_id` 和 `client_correlation_id` 同时存在的集成路径未被 `test_read_api_terminal_policy.py` 覆盖（`test_terminal_diagnostics.py` 单元测试已覆盖组合逻辑）。
- Runner `client_correlation_id=None`（`request_identity` 为 None 时）的日志输出未被显式测试。

以上缺口均有单元测试或既有逻辑兜底，不改变 PR 正确性判断。

### RR-3: payload field 常量重复定义

`outbox.py` 和 `read_api.py` 各自定义 `_PAYLOAD_FIELD_PROVIDER_REQUEST_ID` 和 `_PAYLOAD_FIELD_CLIENT_CORRELATION_ID`。当前为模块私有常量，重复不影响正确性；若未来 terminal payload 字段名变更，需同步修改两处。属于 maintainability 观察，不阻塞本次变更。
