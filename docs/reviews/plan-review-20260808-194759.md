## Material finding

### F19-B2-EVIDENCE-001 — 未修复 / 高 — `observation-summary.json` 缺少逐链 budget，publication PASS 夸大

**Contract owner evidence**

- 冻结计划 `docs/gateflow/pr-190-f19-plan-20260808.md:114` 明确要求：`observation-summary.json` “逐链包含 budget、actual ordinary/compactor calls、terminal refs、seal/verdict”。这是 publication producer 对 public summary 的直接 contract，不是下游报告可自行重算的展示偏好。
- 实际 `evidence/public/observation-summary.json` 的三个 `chains[]` object 均没有 `budget` 字段。Chain 01/02 只有 attempted/skipped segments、terminal records、typed counts、Tool Trace、seal 与 verdict；Chain 03 同样没有 budget。
- 顶层 `budget` 只给出 global window、provider cap、统一 `per_chain_cap_seconds=540` 与全局 actual call totals，不能表达每条链是否创建 deadline、该链 deadline identity/SHA、实际可用窗口或未启动原因。
- `material-calibration-wrapper-summary.json` 另存 5 个已启动 segment 的 wrapper-time remaining/effective timeout；这既不是 `observation-summary.json` 中的逐链 budget，也不覆盖未启动 Chain 03。真正的 Chain 01/02 deadline owner files存在于 private controller scope，但没有进入 `observation-summary.json`，也没有在 `execution-index.json` 中以 relative ref + file-byte SHA 绑定。
- 候选报告 `docs/gateflow/pr-190-f19-observed-behavior-report-20260808.md:9` 与 `docs/cli_ci.md:548` 均声称 F19 已补齐 `per-chain budget/count/terminal refs`，并据此给出 `Publication PASS / conforming`；该结论与上述 public bytes 不一致。

**Impact**

Digest 与 secret scan 只能证明已发布 bytes 的完整性/安全性，不能替代缺失的 publication semantic field。当前 public bundle 不能被裁决为符合冻结 F19 publication contract；若按候选文档 closeout，会再次把与 F18 同类的 per-chain budget closure gap 错误标为已修复。该问题不否定五个 canonical succeeded Run，也不把 B2 observation 从 `needs-more-evidence` 改写成产品失败。

**Minimal correction boundary**

修复 owner 是 F19 publication producer，而不是 CLI、产品代码、analyzer、Oracle/scenario registry 或人类报告。当前 public root 已 sealed，不能原地补写。若需要 conforming publication，应创建新的 publication revision，从 immutable private chain-deadline/wrapper owner facts生成每条 chain 的显式 budget record（包括 deadline 是否创建、chain cap/actual window、owner relative ref 与 file-byte SHA；未启动链显式记录 not-started/no-deadline），同步 `execution-index.json`，重新生成 digest，并让 secret scan 成为最后 writer。完成前，候选报告与 `docs/cli_ci.md` 应把 publication verdict 保持为 `FAIL / nonconforming`，不能只在下游文字中补一个解释。
