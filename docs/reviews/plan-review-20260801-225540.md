## 6. Findings

### 001-未修复-低-§3.2 的 `case_label`/`operation_label`/`attempt_label` 三参数命名与部分 call site 实际可用上下文不匹配

- **位置**: Proposal §3.2 迁移规则、§4.2 validation closure、Plan §9.1 行 638-644
- **问题类型**: 可实施性（implementation agent 可能因命名不匹配而困惑）
- **当前写法**: Proposal 与 plan 多处要求 "caller 必须按当前 event 显式传入 `case_label`、`operation_label`、`attempt_label`，由该 factory 据此构造 deterministic、非敏感且对该 event 唯一的 `SuccessfulRunnerResponseIdentity`"
- **反例/失败场景**: `tests/host/test_compaction_terminal.py:_append_terminal()`（行 631）的签名为 `(transaction, operation_id, terminal_type, ordinal)`——有 `operation_id` 但**没有** `case_label` 或 `attempt_label`。其 4 个调用方（行 223/270/276/365）同样没有这两个 label。实施 agent 读到 proposal 的 "必须传 case_label、operation_label、attempt_label" 后，会在该文件中找不到 `case_label` 和 `attempt_label`，可能：
  - 误以为需要重构 4 个调用方以传入这些 label（增加不必要的 signature change）；
  - 或认为 proposal 规则不适用于该文件而自行发挥。
  实际可用的上下文是 `operation_id` + terminal 类型信息，完全足够构造 deterministic、event-unique identity。
- **为什么有问题**: Proposal 的原则（从可用上下文构造 deterministic identity）是正确的，但把参数名具体化为 `case_label`/`operation_label`/`attempt_label` 过于 prescriptive。对于 `_append_terminal()` 这个具体 helper，`operation_id` 本身就提供了足够的 uniqueness context。过度指定参数名会让实施 agent 在找不到这些 label 时产生不必要的困惑。
- **直接证据**:
  - `test_compaction_terminal.py:631`：`def _append_terminal(transaction, *, operation_id, terminal_type, ordinal)`
  - `test_compaction_terminal.py:223/270/276/365`：4 个调用方均只传入 `operation_id`，无 `case_label`/`attempt_label`
  - Proposal §3.2："test/case caller 必须按当前 event 显式传入 `case_label`、`operation_label`、`attempt_label`"
  - Plan §9.1 行 638-640：同源表述
- **影响**: 低——实施 agent 若理解原则（从可用上下文构造 deterministic identity）则不受影响；若机械执行 proposal 的字面要求，可能在 `test_compaction_terminal.py` 中找不到 `case_label`/`attempt_label` 而产生短暂困惑。不阻塞 amendment 通过。
- **建议改法和验证点**: 将 "`case_label`、`operation_label`、`attempt_label`" 改为更通用的表述，例如 "caller 必须从当前 helper/call site 可用的唯一标识上下文（如 `operation_id`、label 或显式传入的区分参数）构造 event-unique identity"。或在 §3.2 增加一句："具体参数名由各文件根据实际 helper 签名确定，不强制统一为 `case_label`/`attempt_label`。"
- **修复风险**: 低（只涉及 proposal 与 plan 文档一处措辞修正）
- **严重程度**: 低
