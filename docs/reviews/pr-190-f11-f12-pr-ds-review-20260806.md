## Residual Risk

- **旧 v2 compact artifact 不可回放**：F12 明确删除了 v2 compact contract 的兼容读取（compact artifact schema-3、diagnostics、explicit drops/reasons）。任何依赖旧 compact payload 的 Session replay 将失败。这是显式的架构决策而非缺陷，但运维上需注意：如果存在使用旧 compaction format 的生产 Session，升级后将无法通过 Hot/Cold Tool Trace 分析这些 Session 的 compactor proposal。PR body 和设计文档已明确记录此限制。

- **`session_summary=null` 的全替换语义**：`CompactCandidateV3` 的 `session_summary` 为 `None` 时表示清空旧 summary（全替换语义），不影响其它四类 Memory。该语义依赖 LLM 正确理解 null vs absent 的区别——JSON Schema 的 `anyOf: [object, null]` 正确建模了此语义，`compact_structure.py` 的 parser 也正确接受 null。但 `required` 中包含 `session_summary`（plan 要求），这意味着 LLM 必须显式写出 `"session_summary": null`；若 LLM 省略该 key，JSON Schema validation 和 parser 的 exact-key check 都会拒绝。residual risk 是某些 provider 的 JSON Schema mode 对 `required + anyOf null` 的处理可能与预期不同（例如，provider 可能在 `required` 列表中允许 null），这在 `Mimo=none`（不使用 JSON Schema transport）的路径上由 Host parser 严格保证，但在 future `json_schema` 路径上需要在 provider 侧验证。

- **compact_structure.py coverage gap**：85% statement coverage 满足 CLAUDE.md >= 80% 要求，但 15% uncovered lines 中有约一半是内部 descriptor 完整性防御分支（在生产代码中不可达），另一半是 parser 错误路径中的 `_required_text` / `_required_text_tuple` / `_exact_object` 调用（如 blank schema text、blank required text、非法 enum 值等）。这些 parser 错误路径对 adversarial LLM output 是实际可触发的，建议在后续工作单元中补齐覆盖。

- **非 TTY interactive 路径**：`composer.py` 从 ~170 行扩展到 ~1375 行，TTY composer 的 phase machine、ESC prefix handling、submit handoff、SIGINT/EOF 边界处理逻辑复杂度显著增加。non-TTY 路径（`binary_stdin` whole-stream read）在主 review 中已读取但未做同样深度的 adversarial 测试（现有 tests 主要覆盖 TTY 路径的 typed event projection）。non-TTY 路径的正确性依赖于 `session_execution.py` 中的 unified composer contract，需在未来 smoke/场景测试中覆盖。
