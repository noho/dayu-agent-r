## Correctness review

1. ticker locator 的唯一产生点仍为 `_derive_storage_key`。ticker namespace 返回经
   `normalize_ticker` 真源验证、且与输入 exact equality 的 canonical ticker；
   document namespaces 保留 namespace-separated SHA-256 locator。
2. lookup、创建、descriptor 校验、batch staging、backup、recovery、writer lock
   与 publication lock 都复用该 helper，没有第二套 ticker 路径派生。
3. `resolve_existing_ticker` 先用 `try_normalize_ticker` 产生 canonical direct
   lookup candidate；无法作为 ticker 识别的候选不会进入严格 locator，而是继续
   使用公司元数据 alias index。
4. `portfolio/id-*` 不会被读取为 AAPL，不会自动迁移，也不会删除；枚举和 recovery
   因 descriptor 与 canonical locator 不一致而 fail closed。

## Adversarial failure pass

- 非 canonical：`aapl`、`aapl.us`、公司名、绝对/相对路径形态均在 storage
  mutation boundary 被拒绝。
- 路径逃逸：`../AAPL`、`AAPL/../MSFT` 无法形成 ticker locator；document ID
  仍经 private mapping 隔离。
- descriptor corruption：collision、字段损坏、business meta mismatch、
  symlink 与 source descriptor mismatch 均保持 fail closed。
- crash recovery：四个 journal phase、非法 journal ticker、损坏 backup
  descriptor 均保持 target old/new 原子性；非法证据保留。
- error leakage：canonical ticker 作为业务事实允许公开；document private key、
  revision、workspace path、local URI、transaction/lock locator 仍受断言保护。
- SEC primaryDocument：Slice 1 的严格 segment 校验拒绝绝对路径、反斜杠、
  dot/dotdot、空 segment、trailing separator 与 drive syntax，不存在 loose
  basename parsing。

## Read tools impact pass

- `dayu.fins.tools`、processors 与 service runtime 未直接引用 `portfolio`、
  `_target_ticker_dir`、`id-*` 或 identity descriptor。
- `list_documents` 对 `aapl.us` 与 `apple` 均经 read runtime/company repository
  解析到 canonical `AAPL`，读取 `portfolio/AAPL`。
- 九个 read tools 的 success/failure/cancelled 路径均通过 provider 集成用例，
  不依赖 ticker 物理目录名反推 document ID，也未新增下游 fallback。
