### 02-未修复-低-SigintMonitor.install() 平台降级时无诊断

- **入口/函数**: `_PromptSigintMonitor.install`、`_InteractiveSigintMonitor.install`、`_FinsSigintMonitor.install`
- **文件(行号)**: `dayu/cli/commands/prompt.py`:105-119、`dayu/cli/commands/interactive.py`:106-122、`dayu/cli/commands/fins.py`:116-132
- **输入场景**: Windows 或不支持 `loop.add_signal_handler` 的平台
- **实际分支**: `NotImplementedError` / `RuntimeError` -> `_installed = False`，静默返回
- **预期行为**: 静默降级是合理的平台兼容策略，但应有最低日志输出，与已登记的 residual risk WU-CLI-01-RR-06 对齐
- **实际行为**: 完全无日志或诊断信号，用户不知道 SIGINT cancel 语义已降级
- **直接证据**: prompt.py:114-118 的 try/except 块捕获异常后直接 return，无 logging 调用
- **影响**: 在不支持 `add_signal_handler` 的平台，SIGINT 会走默认 KeyboardInterrupt 路径。prompt command 的 `except KeyboardInterrupt: return EXIT_KEYBOARD_INTERRUPT` 能兜底，但 Run accepted 后的行为不是 typed cancel，而是直接杀进程。对 CLI 用户来说行为差异不大，但缺少诊断信息。
- **建议改法和验证点**: 至少记录一条 verbose 级日志说明 signal handler 安装失败并降级到 KeyboardInterrupt 模式。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

- **文件(行号)**: `dayu/cli/main.py`:84-97

- **建议改法和验证点**: 去掉 `:raises ValueError` 行或改为 `:raises Exception: 本函数不主动抛出异常。`
- **修复风险（低/中/高）**: 低

## Open Questions

1. **SIGINT 在 interactive 输入态的语义**: 当前 interactive 模式下，输入态 Ctrl-C 产生 `KeyboardInterrupt` -> `EXIT_KEYBOARD_INTERRUPT` -> 进程退出。这与典型 REPL（如 IPython、Node REPL）中 Ctrl-C 只清空当前行的语义不同。plan 中 S4 已明确"输入态 Ctrl-C：清空当前输入或退出当前 command，按实现测试固定"，当前测试固定为退出进程。这是一个有意的设计选择，但 UX 可能需要后续迭代。

2. **`EXCLUDED_COMMAND_NAMES` 的消费者**: 该常量在 `arg_parsing.py` 中定义并导出到 `__all__`，但在 CLI 层内无任何导入或引用。若无外部消费者，建议清理或补注释说明用途。
