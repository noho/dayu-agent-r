### S1-RESIDUAL-01-低-callback vs direct digest alignment test gap for failed/cancelled outcomes
- **入口/函数**: `callback_payload_digest()` / `wait_resolution_digest()` — `dayu/host/wait_callback.py:494` / `dayu/host/durable/wait_resolution_digest.py:30`
- **文件(行号)**: `tests/host/test_wait_callback.py:216`
- **输入场景**: `ResolveWaitFailedOutcome` 或 `ResolveWaitCancelledOutcome` 通过 callback envelope 传入
- **实际分支**: `test_callback_digest_matches_resolve_wait_digest_for_completed_and_lost` 只显式覆盖 completed 和 lost 两种 outcome
- **预期行为**: 四种 outcome (completed/failed/cancelled/lost) 的 callback digest 均应等于同 wait_id/idempotency_key/outcome 的 direct resolve digest
- **实际行为**: failed/cancelled 没有独立的 callback-vs-direct digest 单元测试
- **直接证据**: 测试 `tests/host/test_wait_callback.py:216-241` 只断言 completed 和 lost；failed 和 cancelled 的 callback 路径 digest 对齐无显式测试

- **建议改法和验证点**: 后续 WU 若修改 outcome digest 投影逻辑，应补充四种 outcome 的 callback-vs-direct 全矩阵 digest 对齐测试。

### S2-RESIDUAL-01-低-forbidden_codes frozenset 与 authenticator reason_code 词汇表耦合
- **入口/函数**: `_auth_failed_status_code()` — `dayu/service/wait_callback_endpoint.py:763`
- **文件(行号)**: `dayu/service/wait_callback_endpoint.py:770-778`
- **输入场景**: Host authenticator 返回 `WaitCallbackAuthRejected`，`reason_code` 不在 Service mapper 的预定义 `forbidden_codes` frozenset 中，但语义上表示"已认证但无权限"
- **实际分支**: `diagnostic_code not in forbidden_codes` → 返回 401（默认分支）
- **预期行为**: 已认证但无权限的 callback 应返回 403
- **实际行为**: 若 authenticator 使用的 reason_code 不在 `{"forbidden", "forbidden_credential", "credential_forbidden", "insufficient_permission", "permission_denied"}` 中，会 fallback 到 401
- **直接证据**: `dayu/service/wait_callback_endpoint.py:770-781`，`forbidden_codes` 为硬编码 frozenset
- **影响**: 低。默认 401 是更安全的 fail-closed 行为（不暴露授权信息）；真正的 authenticator 实现只要使用这五个 reason_code 之一即可正确映射。plan 明确 auth 实现属于 Service/Web composition root 的部署决策。
- **建议改法和验证点**: 若后续需要 protocol-level 的 auth-failed sub-status（区分 unauthenticated vs unauthorized），可以在 `WaitCallbackAuthRejected` 中增加 `unauthenticated: bool` 字段，让 Host adapter 直接携带该分类，Service mapper 无需猜测 reason_code 文本。
- **修复风险（低）**: 当前设计为 plan 有意决策，不阻塞当前 gate。
- **严重程度（低）**:

### S2-RESIDUAL-02-低-credential_ref 在非 Bearer Authorization 时暴露原始 header 值

- **实际分支**: `stripped.startswith("Bearer ")` 为 False → 返回完整 `stripped`，即 `Basic YWxhZGRpbjpvcGVuc2VzYW1l`
- **预期行为**: `WaitCallbackAuthInput.credential_ref` 应为"凭据引用或脱敏凭据标识，不承载明文 secret"（plan line 140）

- **修复风险（低）**: 不阻塞当前 gate。
