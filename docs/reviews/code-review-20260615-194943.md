## Residual Risk

1. **event stream 无 terminal 的边界**: `_consume_fins_direct_events` 在 stream 结束无 terminal 时 raise `RuntimeError`（`fins.py:593-595`），由 `run_fins_direct_command` 的 `except Exception` 捕获并转为 `EXIT_FAILURE`。Service 层 `stream_job_events_until_terminal` 的 contract 是否保证必定产出 terminal event 未在 CLI 层验证——CLI 层依赖 Service 层 contract。当前测试 fake 的 stream 总是产出 terminal，未覆盖 "stream ends without terminal" 的 RuntimeError 路径。风险低：该路径有明确错误消息，不会静默丢失。

2. **`_FakeFinsDirectService.wait_for_terminal` 残留**: test double 仍保留 `wait_for_terminal` 方法和 `wait_calls` 列表，`test_live_fins_commands_render_progress_and_terminal_summary` 用 `assert fake_service.wait_calls == []` 做负向断言确认旧路径未被调用。这是有意为之的测试设计，不是 dead code；但若未来 Service interface 移除 `wait_for_terminal`，此 test double 需同步清理。

3. **`output.py` 的 `_FINS_SENSITIVE_KEY_PARTS` 过滤覆盖面**: 当前过滤 `"payload"`, `"raw"`, `"body"`, `"content"`, `"path"`。若 runtime 未来在 summary 中新增含敏感信息的 key（如 `"url"`, `"file"`, `"error_detail"`），需同步更新此 allowlist。当前 S4 scope 内 runtime 产出的 summary key 已被覆盖。
