## Findings

### 1. 中 — AGENTS.md / CLAUDE.md 注释掉 schema 变更治理约束，PR scope 不匹配 [不修复]

- **位置**：`AGENTS.md:61`、`CLAUDE.md:61`
- **问题**：PR 将 `workspace_migrations` 插件进入 `dayu-cli init` 流程的约束注释掉（HTML comment `<!-- ... -->`）。P1 不涉及任何 schema 变更，注释掉此约束不属于 P1 范围，也未在 PR body 中说明理由。
- **后果**：项目级治理约束被削弱，后续 schema 阶段（P1.5 EventLog 等）可能遗忘恢复此约束，导致旧库迁移流程被绕过。
- **建议**：将此变更从 P1 PR 中移除，或在 PR body 中补充明确的注释理由并创建后续恢复 issue。
- **处置**：不修复。

### 2. 低 — `asyncio.create_task` 返回值未存储，后台 task 缺乏生命周期管理 [已补 docstring]

- **位置**：`dayu/host/_run_harness.py:147`
- **问题**：`asyncio.create_task(self._run_to_queue(...))` 返回的 task 对象未被存储。CPython 运行时通过 event loop 内部引用保持 task 存活，但这是实现细节而非语言保证。此外，如果调用方放弃消费 `RunStream.events`，后台 task 仍会运行至完成，没有取消路径。
- **后果**：P1 内存态单 run 场景下实际不会出问题。但后续 Phase 引入 Run 取消治理时，如果沿用此模式，会缺乏取消后台 task 的入口。
- **建议**：P1 可接受；后续 Phase 需要在 `RunHandle` 或 harness 上持有 task 引用以支持取消。docstring 已标注 P1 不提供完整取消治理，风险已知。
- **处置**：已在 `LocalRunHarness.start_run` docstring 中明确 P1 不保存 task handle，也不提供 Host 级取消治理入口。

### 3. 低 — `terminal_result_from_event` 使用 `assert` 做类型守卫 [已修复]

- **位置**：`dayu/host/_event_translation.py:53, 65, 76, 85`
- **问题**：`terminal_result_from_event` 对终态事件的 `data` 字段使用 `assert isinstance(data, FinalAnswerData)` 等断言。`assert` 在 `python -O` 模式下会被跳过，导致后续访问 `data.content` 等属性时抛出 `AttributeError` 而非明确的类型错误。
- **后果**：P1 中 `terminal_result_from_event` 仅在测试和 smoke 脚本中调用，不在主事件消费流程（`_stream_queue`）中使用，影响有限。
- **建议**：P1 可接受；若后续 Phase 将此函数用于生产路径，应改为 `if not isinstance(...): raise TypeError(...)` 显式类型守卫。
- **评估与处置**：虽为低 severity，但显式 `TypeError` 成本低且更符合运行期契约；已将 `assert` 改为显式类型守卫，并补充 mismatch data 测试。
