## Findings

以下是对抗审查点的逐项证据汇总：

### 1. required disposition 贯穿且 repair bypass identical skip

- `_can_skip_upload()` 第一条判断是 `isinstance(repair_disposition, ExistingSourceAutoRepair) -> return False`（`docling_upload_service.py:1287-1288`），确保 repair 不走 identical skip。
- `_PreparedAssetMutation` 的 `repair_disposition` 字段为 required（`docling_upload_service.py:191`），无 default。
- `prepare_upload()` 校验封闭类型后原样携带到 `_PreparedAssetMutation`（`docling_upload_service.py:433-449`）。
- `publish_prepared_upload()` 原样传入 `_store_upload_assets()`（`docling_upload_service.py:496-514`）。
- `_store_upload_assets()` 在 `ExistingSourceAutoRepair` 时调用 `reset_source_document_for_repair()`，否则走既有 `reset_source_document()`（`docling_upload_service.py:578-603`）。

### 2. storage core 是 staged repair 唯一 owner

- `_fs_source_document_core.py:393-487` 实现 `reset_source_document_for_repair()`。
- 验证步骤精确按 plan §6.2 顺序：(1) 校验 expected `REPAIR_REQUIRED` + trusted revision（`_fs_source_document_core.py:432-441`）；(2) exact-target inspect 一次（`_fs_source_document_core.py:444-449`）；(3) 先 conflict gate（UNSAFE/非 REPAIR_REQUIRED/content not COMPLETE/REPAIR_REQUIRED）（`_fs_source_document_core.py:455-461`），再 `has_same_source_publication_identity()` 比较（`_fs_source_document_core.py:462-470`）；(4) `_canonical_remaining_manifest_items_for_repair()`（`_fs_source_document_core.py:472-475`）；(5) reset target directory（`_fs_source_document_core.py:476-481`）；(6) rewrite manifest（`_fs_source_document_core.py:482-487`）。
- comparison `ValueError` 被精确转换为 `SourceIntegrityRevisionConflictError`（`_fs_source_document_core.py:467-468`），且仅包围 comparison 调用，不吞掉 input `ValueError`（`_fs_source_document_core.py:432-441`）。

### 3. target-local damage 不误判 blocked，remaining manifest 只取 non-target

- `_canonical_remaining_manifest_items_for_repair()` 逐 non-target 检查 `content_classification.status`（`_fs_source_document_core.py:120-134`），不消费 aggregate `canonical_manifest_items`。
- 测试 `test_source_repository_repair_facade_resets_target_and_rewrites_canonical_sibling_manifest`（`test_fins_storage_atomicity.py:7198`）显式断言 `before_reset.canonical_manifest_items == ()`（aggregate 为空），同时验证 sibling 的 `canonical_manifest_item` 非空且正确写入 manifest。
- `SourceIntegrityRepairBlockedError` 的三个 closed reason 精确映射：`CROSS_SOURCE_PUBLICATION_UNSAFE`（`_fs_source_document_core.py:106-111`）、`NON_TARGET_SOURCE_INCOMPLETE`（`_fs_source_document_core.py:128-134`）、`CANONICAL_MANIFEST_UNAVAILABLE`（`_fs_source_document_core.py:136-143`）。

### 4. reset/manifest rewrite/blob/final 失败只污染 staging

- `commit_prepared_upload_batch()` 的 finally 分支确保 rollback exactly once（`docling_upload_service.py:1062-1086`）。
- `rollback_prepared_upload_batch()` 保留主异常（`docling_upload_service.py:1109-1116`）。
- 测试 `test_existing_filing_repair_maps_real_staged_failures_and_rolls_back_once`（`test_docling_upload_service.py:3091`）断言 `old_tree == published_tree_sha256`、`batching.rollback_calls == 1`、`batching.commit_calls == 0`。
- 测试 `test_existing_filing_repair_blob_and_final_failures_keep_old_tree`（`test_docling_upload_service.py:3208`）覆盖 blob/final 失败路径。
- 测试 `test_existing_filing_repair_rollback_secondary_failure_preserves_primary`（`test_docling_upload_service.py:3388`）覆盖 rollback 自身失败的 recovery contract。

### 5. facade 纯 delegate，protocol transitional helper 删除
