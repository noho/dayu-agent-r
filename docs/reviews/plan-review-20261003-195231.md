### 2.1 std emit 吞错误分支逐项对照（格式化/write/flush、RecursionError、四类控制流）

| 分支 | std 实际行为（源码实核） | 计划 `try_deliver_process_record` 行为 | 判定 |
| --- | --- | --- | --- |
| format/write/flush 普通 Exception | 吞入 `handleError` → 公共 stderr（DN-R7 根因） | 单一 `except Exception` 边界内 `format → stream.write(message+terminator) → flush`，故障返回 False；**不调用 emit/handleError** | **已修**，根因同源修复在 owner 边界 |
| RecursionError | 显式 re-raise，不进 handleError | 落入 `except Exception` → False | 与 std 有分叉，但 helper 外层同为 `catch Exception → False`，API 面零可观测差异；无 stderr 逃逸方向正确；记录为残余说明，不构成 finding |
| KeyboardInterrupt / SystemExit / CancelledError / GeneratorExit | BaseException 不被 `except Exception` 捕获，原样传播（handle 的 finally 释锁） | 不在 containment 范围，finally 释放已取得锁后**同对象**传播，不返回 False、不降 secondary | 一致 |
