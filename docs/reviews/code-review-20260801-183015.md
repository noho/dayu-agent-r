**F05 exact Shift+Enter/Ctrl+J/Enter**：composer 定义 `XTERM_MODIFY_OTHER_KEYS_SHIFT_ENTER = "\x1b[27;2;13~"`，只在单个 KeyPress 的 raw data 完整等于该序列时插入 LF。Ctrl+J 保持插入 LF；普通 CR/Enter 提交。**直接证据**：`test_composer_shift_enter_exact_sequence` 通过；`test_composer_ctrl_j_submits` 通过。

**F06 non-TTY whole stdin**：non-TTY 使用显式 `BinaryIO` 或标准 `TextIOWrapper.buffer`，只调用一次 `read()` 到真实 EOF。strict UTF-8 decode；失败只投影稳定的 `interactive stdin is not valid UTF-8`。blank batch 为 0 Run / exit 0；非空 batch 只提交一个 `QUEUE,target_run_id=None`。**直接证据**：`test_interactive_non_tty_whole_stdin_*` 系列测试通过。

**F07/F08 typed TTY lifecycle**：删除 `InputReaderComposer` 与 interactive `RunningKeyMonitor` seam；TTY invocation 只有一个 `PromptToolkitInteractiveComposer` stdin owner。composer phase/event/cancel-source 类型封闭。standalone Escape 使用 prompt_toolkit 非 eager sequence resolution。**直接证据**：`test_interactive_escape_*` 系列测试通过。

**F08 Ctrl+C 三阶段**：composer Ctrl+C 与 OS SIGINT 统一进入 invocation state machine：首次 active 中断只建立 single cancel intent；第二次只登记 exit-after-cancel；第三次及之后 no-op。startup reconnect 一次 SIGINT 只取消 caller-local observation，统一 cleanup 后 exit 130。**直接证据**：`test_interactive_startup_sigint_*` 和 `test_interactive_active_sigint_*` 系列测试通过。

**F09 type-ahead/sole QUEUE**：active composer 持续接收 Unicode/paste/edit/type-ahead；第一份非空 Enter 只建立 sole `QUEUE,target=None`，第二份 draft 原样保留并给出有界提示。exit-after-cancel 停止新输入但不取消 sole queued submit。**直接证据**：`test_interactive_exit_after_cancel_waits_accepted_sole_queue_terminal` 通过。
