## 重点挑战项复核（任务指定）

1. **中国本地日 owner**：owner 唯一性由 A1 证实；plan 把修复限定在 `_format_announcement_date` 及必要模块级私有辅助，符合语义所有权约束；固定 UTC+08:00（无 DST）用 `datetime` 固定 offset 表达即可，无 `zoneinfo`/宿主时区依赖，plan 明文禁止读取宿主本地时区。
2. **普通日期字符串**：当前代码 `cninfo_downloader.py:896-897` 对 `\d{4}-\d{2}-\d{2}` 原样返回；plan 保留该语义（保留 provider 日历值）。注意现有测试夹具统一用字符串形态喂 `announcementTime`（`test_cninfo_downloader.py:88-99` 注释自述「测试统一用字符串」），即现有套件大部分路径绕开了数值转换——plan 新增真实毫秒整数用例恰好补上这个日历盲区。
3. **异常时间值**：现状 `isinstance(raw_time, (int, float))` 会暗中接受 `bool`（`True` → 1ms → 1970-01-01）与任意 float。plan 要求「布尔值、浮点值、畸形/越界数字…不能暗中当作有效毫秒整数」并在 owner 测试钉死处置，丢弃路径（`_parse_raw_announcement` 对 falsy date 返回 None）有界。规格足够 code-generation-ready。
4. **先择优后窗口过滤**：A4 证实顺序；plan 不重排该顺序而是设停止条件（真实 provider 单日响应若返回邻日同财年/财期竞争候选并盖过窗口内候选则停下裁决）。在已证据化的 regime（provider 按中国本地日历过滤：03-29 窗口返回两条午夜公告、03-28 窗口为零）下，响应条目天然在窗口内，顺序安全；未证据化的 slop regime 由停止条件与真实 CLI 三日复验兜底。属于目标约束下的最小范围决策，不构成 finding。
5. **跨年财政年度/ID**：A5 证实机制真实存在；plan 的测试矩阵（标题显式年份维持 / 缺年份跨年改变财年与 ID 输入）正是锁这个 owner 行为，且遵守「不宣称 ID 一律不变」的裁决要求。
6. **发布与旧 COMPLETE skip**：A6/A7 证实；plan 把历史数据显式排除并另立核查/migration，不用 overwrite/rebuild/测试预置暗改，符合裁决。
7. **真实 CLI 验收可行性**：A8 成立；三日各自全新 `--base` 避免了旧 COMPLETE skip 污染验收；「真实 provider/Docling 不可用则保留失败证据、不得以 mock 宣称通过」防止验收造假。
8. **最小 scope**：白名单 = 1 个生产文件 + 3 个测试文件 + 条件触发 README；非目标与 goal 逐条对齐，未发现 goal drift（coverage/pyright/README 均为 CLAUDE.md 既定门槛，非新增目标）。
