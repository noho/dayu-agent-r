## PR-001 Verification

修订 plan 第 135-145 行已经移除跨 namespace 同 dest/custom-action mutation 假设，并明确：

- `_root_log_level_selectors`、`_command_log_level_selectors`、
  `_action_log_level_selectors` 是三个不同 typed facts；
- 三套 parent 只复用同一个 option-to-canonical spec，不复用 occurrence dest；
- `session` 与 `tool_trace` 的二级 parser 显式消费 action-scope parent；
- finalizer 在 parse 完成后合并三份 list、校验总 count，再产生唯一 canonical `log_level`；
- `_new_default_namespace()` 每次创建 fresh lists，parser/action 不持有 collector。

本轮最小 argparse 实验直接覆盖：

```text
--debug session --info resume x
  -> root=['debug'], command=['info'], action=[]

session --debug resume x --info
  -> root=[], command=['debug'], action=['info']

session resume x --debug --info
  -> root=[], command=[], action=['debug', 'info']
```

复用同一 parser 的两次 fresh-namespace invocation 分别只得到 root `debug` 与 action `info`，没有
跨 invocation 泄漏。该机制与 argparse subparser 新 namespace/字段回写模型一致，finalizer 能稳定看见
所有 scope-local facts。

S5 第 266-284 行同时要求：16×16 同层完整矩阵、root/command 两顺序、
`session resume` root/command/action 任意两层、同一 parser 连续解析与 fresh namespace，以及其它
公共参数位置保持不变。测试范围足以防止 parent assembly 把 `--base`、`--config`、`--log-file`、
`--debug-stream` 等既有位置语义意外收窄。

## Architecture / Best-practice / Optimal / Overengineering / Overcoupling Review

- selector 产生、scope-local 记录、finalize 校验与 canonical projection 均留在
  `dayu/cli/arg_parsing.py`，没有 prompt-only shim 或下游补偿。
- 三个 dest 是 argparse 已存在三层 namespace 边界的直接建模，不是新业务层或通用 registry；单一 spec
  防止 spelling/canonical mapping 漂移。
- 每 invocation fresh lists 消除了 parser reuse/concurrency 的共享 mutable state风险；parse 后 finalizer
  比 raw argv scan 更可维护、更符合 typed owner contract。
- PR-002 保持 process adapter 与 Host atomic lifecycle 分离；PR-003 保持 runtime 层中立；PR-004 不扩张
  README 职责。未发现反向依赖或新的过度耦合。
