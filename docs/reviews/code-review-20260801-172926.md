## Findings

### 001-未修复-低-generation 参数被传入但未影响运行时行为

- **入口/函数**: `_start_interactive_turn`、`_start_interactive_queued_followup`、`_create_interactive_submit_task`
- **文件(行号)**: `dayu/cli/session_execution.py` (1502-1551, 1554-1597, 1599-1656)
- **输入场景**: 所有 interactive TTY turn 和 queued follow-up 创建
- **实际分支**: `generation` 被存入 `_InteractiveActiveTurn.generation`，但 `_create_interactive_submit_task` 不接收也不使用该参数
- **预期行为**: 若 `generation` 是 turn-level 状态标识，应只存于 `_InteractiveActiveTurn`；若它是 submit task 的输入，应传入并使用
- **实际行为**: `generation` 作为 `_start_interactive_turn` 的命名参数传入，存入 `_InteractiveActiveTurn.generation`；`_create_interactive_submit_task` 不接收 `generation` 参数，submit task 行为不受 generation 影响。`_start_interactive_queued_followup` 没有 `generation` 参数
- **直接证据**: `_create_interactive_submit_task` 签名不含 `generation`；`_InteractiveActiveTurn.generation` 只在 `_drive_interactive_tty_repl` 的 `completed.generation` 读取中被使用
- **影响**: 无功能影响。但函数签名暗示 `generation` 是 turn 创建的输入语义，实际上它只在 REPL driver 层有意义，可能误导后续维护者
- **建议改法和验证点**: 可将 `generation` 从 `_start_interactive_turn` 参数列表移除，在 REPL driver 内部赋值 `current.generation = generation`；或在 docstring 明确说明该参数只存储不参与 submit task 构造
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

### 002-未修复-低-execute_interactive_on_session 中 TTY/non-TTY 路径有三处重复调用块

- **入口/函数**: `execute_interactive_on_session`

- **输入场景**: `run_startup_reconnect=True` 和 `False` 两种入口各有 TTY 和 non-TTY 分支
- **实际分支**: startup=True 时 TTY 和 non-TTY 各调用一次 `_drive_interactive_tty_repl` / `_run_interactive_non_tty_batch`；startup=False 时再次各调用一次；总共四次几乎相同的参数组装

- **实际行为**: 四个分支各自组装参数调用目标函数，参数完全相同，只是 startup 处理不同

- **建议改法和验证点**: 可提取 `_drive_tty_or_batch_repl(tty_mode, effective_composer, effective_binary_stdin, ...)` 消除重复；但当前 startup SIGINT 逻辑嵌入前序分支，提取需注意不引入控制流变化
- **修复风险（低/中/高）**: 低
