## Findings

未发现实质性问题。

以下是对关键正确性路径的逐条走读结论：

### 1. Atomic claim acquisition

`claim_wait_record_for_poll` (`state.py:2039-2125`) 执行 SELECT 候选 + UPDATE claim 在同一个 write transaction 内。UPDATE 的 WHERE 子句完整重复了 eligibility 条件（status, poll_next_observe_at, poll_claim_id/expired）。`rowcount == 0` 通过 `_wait_record_poll_mutation_result` 返回 `CAS_LOST` 或 `NOT_FOUND`，adapter 路径只在 `UPDATED` 时收到 row。Docstring 明确禁止用候选读取触发 adapter 调用。符合 plan 的 atomic claim 要求。

### 2. Terminal resolve clearing claim fields

`_mark_wait_record_terminal_row` (`state.py:5843-5875`) 在 SET 子句中增加 `poll_claim_id=NULL, poll_claim_owner_id=NULL, poll_claimed_at=NULL, poll_claim_expires_at=NULL, poll_next_observe_at=NULL, poll_backoff_attempt=0`。所有终态转换（resolved, failed, lost）复用此函数。`test_wait_record_terminal_transition_clears_poll_claim` 验证 resolved 后四个 claim 字段为 NULL。

### 3. Stale release cannot clear newer claim

`release_wait_record_poll_claim` (`state.py:2165-2198`) 的 WHERE 包含 `AND poll_claim_id = ?`。旧 claim id 不匹配新 claim，rowcount 为 0，返回 `CAS_LOST`。`test_stale_poll_release_cannot_clear_newer_claim` 验证旧 release 后新 claim 不变。

### 4. Abandon CAS race

`mark_wait_record_poll_abandoned` (`state.py:2228-2259`) 的 WHERE 包含 `AND poll_claim_id = ? AND status = ? AND poll_abandoned_at IS NULL`。CAS rowcount 0 时 `_abandon_cancelled_wait` 返回 `(0, 0, 1)`，不写 `poll_abandoned_at`，wait 保持可重试。`test_abandon_cas_conflict_leaves_cancelled_wait_retryable` 用 `_AbandonClaimStealingAdapter` 模拟 claim 被偷后 abandon CAS 失败。

### 5. Missing adapter capped-delay indefinite retry

`poll_once` 中 adapter 为 None 时调用 `_release_with_backoff(outcome=MISSING_ADAPTER)`，写入 durable backoff metadata，不调用 `resolve_wait`。`test_missing_poll_adapter_registration_logs_warning` 验证 `poll_next_observe_at` 非空、`poll_backoff_attempt == 1`、`poll_last_outcome == MISSING_ADAPTER`、`poll_last_error_code == "missing_adapter"`。

### 6. Resolve failure retry reuses idempotency key

`_resolve_claimed_wait` 在 resolve 异常后读取 latest row 判断是否已终态：已终态返回 `CAS_LOST`（claim 已由 terminal mutation 清除），未终态返回 `INVALID_STATE`（release with backoff）。`test_resolve_failure_releases_with_backoff_and_reuses_idempotency_key` 验证失败后重试使用同一 `_poll_idempotency_key`。

### 7. Schema checks and indexes

- Claim all-or-none CHECK (`schema.py:764-774`) 和 `poll_abandoned_at` requires cancelled CHECK (`schema.py:775-777`) 与 Python 侧 `_validate_wait_poll_fields` 一致。
- Active poll index (`schema.py:1144-1154`) 包含 `poll_next_observe_at`, `poll_claim_expires_at`, `created_event_sequence`, `wait_id`，覆盖 claim query 的过滤和排序。
- `WaitPollLastOutcome` enum 值与 schema CHECK 约束值完全一致（6 个值）。

### 8. Batch claim semantics

`poll_once` claim loop (`wait_adapter.py:579-588`) 每次迭代调用 `_claim_next_wait_record` 执行单行 claim CAS。NOT_FOUND 时 break，CAS 冲突时 continue 并递增 `claim_conflicts`，成功时 append。符合 plan "repeated single-row claim attempts up to limit; batch is not all-or-nothing"。

### 9. Backoff calculation

`_backoff_delay_seconds` (`wait_adapter.py:864-877`) 使用 `initial * multiplier^(attempt-1)` capped at `max_delay`。常量值与 Slice 1 模块级默认值一致（30s initial, 2.0x multiplier, 300s max）。`backoff_attempt=1` → 30s, `=2` → 60s, `=3` → 120s, `=4` → 240s, `=5` → 300s (capped)。

### 10. Control doc

`docs/host/issues-implementation-control.md` 更新了 gate 状态、implementation status 和 next entry point，与 Slice 1 完成状态一致。

## Residual Risk

- `_backoff_delay_seconds` 是纯函数但缺少 dedicated unit test。当前通过集成测试间接覆盖（not-ready 后 `poll_next_observe_at` 非空）。风险低。
- `poll_last_outcome` schema CHECK 包含 6 个值（`not_ready`, `adapter_error`, `missing_adapter`, `resolve_error`, `abandon_error`, `abandoned`），plan 中列出的 `resolved`, `lost`, `shutdown_skipped` 未包含。这是正确的 Slice 1 scoping：终态由 `resolve_wait` 处理并清除 claim 字段，`shutdown_skipped` 属于 Slice 2。如果未来 Slice 2 需要 `shutdown_skipped`，需扩展 CHECK 和 enum。
- `poll_backoff_attempt` (singular) 与 plan 中 `poll_backoff_attempts` (plural) 命名不一致。不影响功能，但 plan 文本和实现应保持一致。
- `poll_last_error_message` 在 plan 中未列出，实现添加了它。这是合理的诊断增强。
