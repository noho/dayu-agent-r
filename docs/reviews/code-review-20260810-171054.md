### 2-未修复-低-AST 单 owner 测试对 helper 内部重构敏感

- **入口/函数**: `test_download_mutation_mode_conflict_has_one_production_owner`
- **文件(行号)**: `tests/service/test_fins_direct.py` (新增测试)
- **输入场景**: `_validate_download_mutation_mode` 函数体发生任何改变 `overwrite_existing and rebuild_local_artifacts` AST 结构的重构（例如拆成两个独立 `if`、引入中间变量、改用 `all()` 等）
- **实际分支**: `ast.walk` 匹配 `BoolOp` + `And` operator + 两个 field name 同时在 `Name` 节点中
- **预期行为**: 单 owner 验证不因合法重构而误报
- **实际行为**: 若 helper 内部实现改为 `if overwrite_existing: if rebuild_local_artifacts: raise ...`（嵌套 `if`）或 `if all([overwrite_existing, rebuild_local_artifacts]):`（`all()` 调用），AST 结构改变，测试将误报“无 owner”或找不到匹配，尽管语义等价的单 owner 仍然存在
- **直接证据**:
  ```python
  for boolean_node in (
      node for node in ast.walk(function_node) if isinstance(node, ast.BoolOp) and isinstance(node.op, ast.And)
  ):
      referenced_names = {node.id for node in ast.walk(boolean_node) if isinstance(node, ast.Name)}
      if mutation_fields <= referenced_names:
          owner_names.add(function_node.name)
  ```
  该匹配逻辑仅识别 `ast.BoolOp` + `ast.And` 形式的 conjunction，不覆盖等价的嵌套 `if`、`all()` 或其他布尔组合方式
- **影响**: 未来合法重构可能被测试误拒，增加维护成本；但测试本身不会静默通过（会 fail），因此不会掩盖真正的多 owner 问题
- **建议改法和验证点**: 可考虑补充一个更宽松的语义测试（例如直接调用 `_validate_download_mutation_mode(True, True)` 并断言抛错），与 AST 测试互补；AST 测试保留但添加注释说明其覆盖范围仅限于 `and` 字面量形式的复制。当前不阻塞 ship——测试在现有实现下正确且提供有价值的单 owner 守卫
- **修复风险（低）**: 仅影响测试自身的可维护性，不影响 production
- **严重程度（低）**: 不影响 correctness；测试 fail 时不会静默

## Open Questions

1. **`TypeError` vs `FinsDownloadUsageError` 的不对称处理**: `_validate_download_mutation_mode` 对非 `bool` 字段抛 `TypeError`（→ CLI `EXIT_FAILURE`），对双 true 冲突抛 `FinsDownloadUsageError`（→ CLI `EXIT_USAGE_ERROR`）。两种错误的 exit code 不同。实际路径中 argparse `store_true` 和 builder 默认值保证永远是 `bool`，因此该不对称不可达。是否需要统一两者为同一异常类型以消除理论上的 exit code 不一致？当前判断：不需要——`TypeError` 语义上确实是编程错误而非用户用法错误，且不可达。

2. **help 文本的 argparse 标准互斥呈现**: 当前设计有意不使用 `add_mutually_exclusive_group`（保持单一语义 owner）。argparse 的互斥组会在 `--help` 中自动生成类似 `[--overwrite | --rebuild]` 的用法行。当前用手写 help 文案说明互斥，效果等价但用户需要读文案才能发现。这是否降低可发现性？当前判断：文案清晰且用户在同时使用两个 flag 时会得到明确拒绝，不构成实际问题。
