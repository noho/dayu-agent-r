### 1-未修复-低-`_provenance_from_evidence_blocks` 接收但未使用 `evidence_blocks` 参数

- **入口/函数**: `_provenance_from_evidence_blocks` 在 `dayu/host/compact_material.py:2862`
- **文件(行号)**: `dayu/host/compact_material.py:2875` — `del evidence_blocks`
- **输入场景**: 所有通过 `build_compact_material_pack` 构造 compact material pack 的调用（普通/fallback compact 路径）
- **实际分支**: 函数接收 `evidence_blocks: tuple[CompactEvidenceBlock, ...]` 作为第一参数，但立即用 `del evidence_blocks` 删除局部引用，转而从 `selected_blocks: tuple[RunInputMaterialBlock, ...]` 迭代构造 provenance entries
- **预期行为**: 移除 chunking 后，provenance 必须从 `RunInputMaterialBlock`（携带 `accepted_evidence_id`、`tool_result_event_ref`、`tool_call_event_ref`、`payload_refs`、`artifact_refs`、`source_locator_refs`）构造；`CompactEvidenceBlock` 不含这些 provenance 字段，因此不能作为 provenance 数据源
- **实际行为**: 行为正确 — provenance 正确从 `selected_blocks` 构造。但 `evidence_blocks` 参数变为死参数
- **直接证据**: `dayu/host/compact_material.py:2863-2875` — 函数签名保留 `evidence_blocks`，但实现体第一行就 `del evidence_blocks`，后续只使用 `selected_blocks`。`dayu/host/compact_material.py:1031-1036` — 调用方仍计算并传递 `evidence_blocks`
- **影响**: 仅代码可读性 — 调用方无谓计算 `evidence_blocks`（通过 `_pack_evidence_blocks`），该值同时传入 `CompactMaterialPack.evidence_material`（有效使用）和 `_provenance_from_evidence_blocks`（丢弃）。非正确性问题
- **建议改法和验证点**: 若后续重构，可考虑让 `_provenance_from_evidence_blocks` 不再接收 `evidence_blocks` 参数，或改为从 `selected_blocks` 派生的单参数接口。当前状态不阻塞 merge
- **修复风险（低）**: 仅涉及函数签名变更，调用方需同步删除参数传递
- **严重程度（低）**: 非正确性问题，死参数仅影响可读性

## Residual Risk

1. **长 evidence 超预算风险（deferred-with-owner → WU-CM-13）**: 移除默认 chunking 后，单条超长 evidence 可能让 compactor input 超过 hard context budget。当前 Context Governance 的 budget / fallback / fail-closed 路径处理此场景。WU-CM-13 reactive compact recovery 是此风险的 deferred owner。本 WU 的实现不引入字段级 silent truncation 作为替代。

2. **EventLog delta 很大时的 material view 构造成本（deferred-with-owner → 未来 Host material source performance hardening）**: 移除 `_ACCEPTED_TOOL_EVIDENCE_MATERIAL_LIMIT` 后，`build_pre_dispatch_compact_material_view` 读取全量 post-compact delta，长 session 可能有性能影响。当前实现复用既有 EventLog truth source，未引入 page correctness cap。若真实场景观测到性能问题，由未来 Host material source performance hardening WU 处理。

3. **`PromptLocalProvenanceEntry.chunk_parent_label` / `chunk_ordinal` 字段保留**: `dayu/host/compaction.py:313-314` 的这两个字段在 dataclass 中保留（默认 `None`），测试断言默认路径不填充它们（`test_single_large_evidence_block_stays_whole_with_same_provenance`）。它们作为未来显式 budget chunking 的 schema 占位，本 WU 未删除。这符合 plan 的 "不新增 durable schema" 约束（字段已存在，未新增），且测试覆盖了默认不填充的行为。
