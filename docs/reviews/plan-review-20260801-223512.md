### 4.2 低严重度关注点

#### 001-未修复-低-file-local identity 构造方式在无 run context 的 helper 中 underspecified

- **位置**: Proposal §3.2 五文件迁移边界表、目标 plan §9.1 行 638-644
- **问题类型**: 可实施性（implementation agent 需做局部设计决策）
- **当前写法**: "允许由各自 file-local fixture owner 构造 deterministic、非敏感、typed `SuccessfulRunnerResponseIdentity`"
- **反例/失败场景**: `tests/host/test_compaction_terminal.py:_append_terminal()`（行 650）当前签名为 `(transaction, operation_id, terminal_type, ordinal)`——无 run、iteration、attempt、provider/model 等任何 identity 上下文。其 4 个调用方（行 223/270/276/365）也未传入此类上下文。实施 agent 需在两个选项中做设计决策：
  - a) 扩展 `_append_terminal()` 签名以接收 identity 参数（影响 4 个调用方）；
  - b) 在 helper 内部硬编码 synthetic identity 值。
  选项 (a) 更干净但改变了 helper 的 public contract；选项 (b) 的 identity 值与 operation/attempt 之间无真实语义关联，"sibling 一致性"约束只能做到不矛盾（不声称冲突的值），但无法做到正向一致（identity 值与 operation 同源）。
- **为什么有问题**: amendment 禁止"从 manifest 或 sibling fields 反推"，但对"从哪构造"只给了原则性指导（deterministic、非敏感、typed、sibling 一致），未给出该具体场景的构造策略。不同实施 agent 可能做出不同选择，导致 5 个文件之间的 identity 构造模式不一致。
- **直接证据**:
  - `test_compaction_terminal.py:631-669`：`_append_terminal()` 签名与 body
  - `test_compaction_terminal.py:223/270/276/365`：4 个调用方均无 run context
  - `test_memory_projection.py:449`：helper 同样无 run context 参数
- **影响**: 低——实施 agent 需在 S5 implementation 时做局部设计决策；两种选项均不违反 amendment 硬约束（不改变场景语义、不反推），但可能导致 5 个文件间风格不一致。不阻塞 amendment 通过。
- **建议改法和验证点**: 可在 amendment 或 S5 preflight 中增加一条："无 run/attempt context 的 helper 优先扩展签名以接收 file-local identity 参数，避免在 helper 内部硬编码与场景无关的 synthetic 值"。或在 S5 implementation 开始前由 Controller 统一指定策略。
- **修复风险**: 低
- **严重程度**: 低

- **无 scope creep**: non-goals 明确禁止 implementation、commit、push、PR、改变既有场景语义、扩展 8-file closure、增加 optional/default/compatibility。边界清晰。
