## Residual Risk

### RR-1 — `_tool_display_name` 每次工具 activity 投影需 3 次 DB 读取

- **位置**: `read_api.py:1402-1439`
- **风险描述**: `_tool_display_name` 对每个工具 activity 事件依次读取 `read_run_by_id` → `EventLogStore().read_event_by_id` → `event_payload_object`，涉及 3 次 durable store 访问。在高频工具调用 Session（例如 50+ tools）中，watch event stream 消费可能引入可感知延迟
- **缓解**: Plan 明确此为首版最小实现，后续 Slice 可优化为批量预加载或缓存 effective tool display snapshot。当前 Slice A 为 contract-only，此风险不阻塞 merge
- **Owner**: Slice B/C（Service/CLI 消费 activity 时评估实际延迟）；若实测不影响 TTY 体验可长期保持

### RR-2 — Context compaction / tool awaiting activity 投影缺少直接单元测试

### RR-3 — `PROVIDER_PROTOCOL_ERROR` activity 始终使用 `HostActivityStatus.FAILED`

- **位置**: `read_api.py:1342`
- **风险描述**: `_provider_protocol_error_activity` 将 status 硬编码为 `HostActivityStatus.FAILED`、severity 硬编码为 `HostActivitySeverity.WARNING`。若 provider protocol error 实际为 transient/retryable（例如临时网络错误后自动重试成功），展示为 FAILED 可能误导用户
- **缓解**: Plan 规定 "provider diagnostic activity 只展示 error code / 有界 message"，状态语义由 Host activity projection 定义。当前 severity=WARNING + kind=PROVIDER_DIAGNOSTIC 的组合已区分于真正的 Run 失败。若未来需要细分 transient/fatal，可在 Service/CLI 层根据 error_code 调整展示
- **Owner**: Slice B/C

### RR-4 — `_bounded_summary` 中 `…` 为单字符但 Python `len()` 按 code point 计数，非 BMP 字符可能导致视觉宽度超出

- **位置**: `read_api.py:1491`
- **风险描述**: `_bounded_summary` 使用 `len(normalized) <= _ACTIVITY_SUMMARY_MAX_CHARS` 判断是否需要截断。Python `len()` 按 Unicode code point 计数，与终端显示宽度（East Asian Width）不同。含中文、emoji 等宽字符时，180 code points 的字符串可能在终端中显示宽度远超 180 列
- **缓解**: 当前 activity summary 主要来自工具名（英文）、outcome kind（英文）、argument_key_count（数字），实际出现中文长文本的场景极少。若未来 summary 来源扩展，可在 Renderer 层做终端宽度裁剪而非在 Host projection 层
- **Owner**: Slice C（Renderer 层处置）

### RR-5 — `_tool_outcome_activity_state` 对未知 outcome_kind 默认返回 FAILED/ERROR

- **位置**: `read_api.py:1366`
- **风险描述**: 若未来 Engine 或 ingest preview payload 引入新的 outcome kind（如 `timeout`、`rate_limited`），`_tool_outcome_activity_state` 会将其映射为 FAILED/ERROR，可能不符合实际语义
- **缓解**: 这是 allowlist 的默认防御策略——未知 outcome 视为 failed 而非静默成功。未来可在 allowlist 中新增 outcome kind 映射
- **Owner**: 后续 WU 或 Host ingest preview 扩展时
