### F1 修复复核

#### 1. static admission 只复用 canonicalizer shape owner —— 成立

`_admit_fins_upload_file_basename`（`ingestion_runtime.py:835-851`）只调用
`canonicalize_fins_public_file_label(basename)` 并捕获 `ValueError`，未复制 `/`、`\`、空、dot-segment 等任何字符规则。
canonicalizer 的 `ValueError` 唯一来源是 `_validate_public_file_basename_shape`（`direct_events.py:1111-1130`，
空/dot/路径分隔符）；`_public_file_label_requires_hiding` 内部捕获异常且只返回 bool，不会向 admission 抛出。
依赖方向与既有 `ingestion_runtime -> direct_events` 一致，无反向 import。

#### 2. INVALID_FILE_BASENAME closed/fixed/bounded 且不带 raw basename —— 成立

- 新 code 入 `FinsUploadUsageCode`（`ingestion_runtime.py:666`），closed mapping 测试
  （`test_fins_upload_usage_failure_mapping_is_closed_bounded_and_path_free`）把整个 enum 闭包为 24 个 code 并断言精确文案。
- message 为固定文案 `上传文件名无效；请提供单个非空文件名`（`ingestion_runtime.py:771`），无 `{file_name}` 占位符。
- 不在 `_FILE_USAGE_CODES`（`ingestion_runtime.py:746-753`），因此 `fins_upload_usage_failure` 对带 `file_name` 的调用
  抛 `ValueError("非文件 usage failure 不接受 file_name")` —— raw basename 在 owner 层被结构性排除，而非靠测试约束。
- bounded：`fins_upload_usage_failure` 统一执行 `len(message) > _MAX_TEXT_CHARS` 检查（`ingestion_runtime.py:809-810`）；
  测试断言所有 code 的 message 长度 ≤ 240 且不含 `/Users/` 或 `\`。

#### 3. 检查顺序在 filesystem probe 前 —— 成立

`_validate_fins_upload_filing_static` 的逐文件循环（`ingestion_runtime.py:913-923`）：
`basename = file_path.name` → `_admit_fins_upload_file_basename` → `exists()` → `is_file()` → 两个 suffix 检查。
admission 位于任一 filesystem probe 之前，且 `_validate_fins_upload_filing_static` 整体处于
`_filing_upload_request_identity`（workspace state read 前）与 `validate_fins_upload_filing_request` 入口。
测试 `test_filing_static_admission_rejects_pathful_basename_before_filesystem_probes` 用 monkeypatch 把
`Path.exists` / `Path.is_file` 替换为必然抛 `AssertionError` 的 guard，并在 POSIX 上创建真实文件
`tmp_path / "a\\b.pdf"`（`assert upload_file.is_file()` 证明反斜杠 basename 在 POSIX 真实存在且可被 probe），
证明 admission 先于 probe 命中；Windows 分支用 `Path.name` property 等价 owner fixture 覆盖同一 contract，
并通过真实 `canonicalize_fins_public_file_label` 执行，未绕过 owner。

#### 4. 普通/中文/fragment/Cc/Cf/超长不误拒 —— 成立

`test_filing_static_admission_accepts_every_canonicalizable_basename` 参数化覆盖：
`report.pdf`（普通）、`审计报告.pdf`（普通中文非 fragment）、`job_id_notes.pdf`（fragment）、
`line\nbreak.pdf`（Cc）、`report‮name.pdf`（Cf U+202E）、241 字符超长 —— 均通过 admission 不抛错，
且同时断言 `canonicalize_fins_public_file_label` 的既有投影契约不变（普通原样、需隐藏者投影固定隐藏标签）。
逻辑依据：canonicalizer 对隐藏类输入返回 label 而非抛错，admission 只把 shape `ValueError` 转 typed usage failure，
接受集与 canonicalizer 可产生集严格对齐，无收紧。

  failure label projection 均未动。

  因此 `content/empty_input_file` / `content/docling_*` 不可能再降级为 `runtime/unexpected_runtime`；
  测试通过 `_filing_upload_request_identity` 真实入口证明拒绝发生在 workspace read/publication 前。
