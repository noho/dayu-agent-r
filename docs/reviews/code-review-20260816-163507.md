## 特别挑战结论

- **helper 对 `repair_blocked_reason` 的处理是否与 inspector 闭合原因一致**：可达路径上一致且方向安全——helper
  只提前接受 `CROSS_SOURCE_PUBLICATION_UNSAFE`（inspector 该 reason 的所有产生条件要么已由 target gate 前置
  拒绝、要么逐项裁决会得出同 reason），逐 non-target 裁决与 inspector 的 `NON_TARGET_SOURCE_INCOMPLETE` 条件
  重合。唯一分歧是 Finding 2 所述 sibling-manifest-projection-mismatch 场景（inspector `None`、helper
  `NON_TARGET_SOURCE_INCOMPLETE`），helper 裁决即 plan §6.2 step 4 规则、方向 fail-closed，无错误放行；
  但证明 blocked 事实存在双派生点，见 Finding 2。
- **manifest rewrite 后 final upsert/commit complete-tree 一致性**：PASS。rewrite 写出
  `{ticker, updated_at, documents}`，与 `_read_manifest` 的空默认结构（`_fs_storage_infra.py:2798-2802`）及
  `_upsert_manifest_items` 的 read-merge-write 规则（行 2711-2726）形状一致；空 remaining 写合法空 manifest
  `documents: []`；final upsert 用同一 `FilingManifestItem.from_source_meta` owner 按 document_id 合并新 target
  item 并排序；commit validator 经 `_apply_manifest_facts` 要求每 source public COMPLETE 且 manifest item 与
  canonical projection 全量相等，同 owner 生成保证一致。storage 成功路径测试端到端证明 commit 通过。
