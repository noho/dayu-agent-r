## Findings

### 1-未修复-中-`_UsageManifestPairing` 使用裸字符串而非封闭枚举

- **入口/函数**: `_UsageManifestPairing` dataclass 及其消费者
- **文件(行号)**: `dayu/host/engine_ingest.py:672-673`
- **输入场景**: 任何 usage pairing 路径
- **实际分支**: `status` 字段为 `str`，值为 `_USAGE_PAIRING_STATUS_COMPLETE` / `_USAGE_PAIRING_STATUS_UNAVAILABLE` 裸字符串常量；`reason` 为 `str | None`
- **预期行为**: `status` 应使用封闭 `StrEnum`，`reason` 应使用对应枚举或 `None`，使 pyright 能在编译期捕获非法值
- **实际行为**: 消费者需自行判断字符串值是否合法，无编译期保障
- **直接证据**: `engine_ingest.py:672-673` 定义 `status: str`、`reason: str | None`
- **影响**: 类型安全降级；若拼写错误或新增 status 未同步更新所有消费者，无编译期报错
- **建议改法和验证点**: 将 `status` 改为 `_UsagePairingStatus(StrEnum)`，`reason` 改为 `_UsagePairingReason(StrEnum) | None`；验证 pyright 通过
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### 2-未修复-中-`cast()` 滥用掩盖 `_ContinuationFrozenSources` 可选字段设计缺陷

- **入口/函数**: `_ContinuationFrozenSources` 及其下游消费者
- **文件(行号)**: `dayu/host/engine_ingest.py:6639-6652`
- **输入场景**: Engine continuation 路径（`iteration_index > 0`）
- **实际分支**: `_ContinuationFrozenSources` 字段为 `str | None` / `int | None`，下游在 `if` guard 后用 `cast(str, ...)` 绕过类型检查（8 处 `cast`）
- **预期行为**: 应拆分为 unavailable（字段可选）和 complete（字段必填）两个类型，下游只消费 complete 变体
- **实际行为**: 用 `cast` 代替正确的类型设计，掩盖了可选字段的语义
- **直接证据**: `engine_ingest.py:6639-6652` 含 8 处 `cast(str, ...)` / `cast(int, ...)`
- **影响**: 类型安全降级；若 `if` guard 逻辑有误，`cast` 会静默通过而非在类型检查时报错
- **建议改法和验证点**: 引入 `_CompleteContinuationFrozenSources(frozen=True)` 所有字段非可选；返回类型为 `Union[_Unavailable..., _Complete...]`；消除所有 `cast`
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中
