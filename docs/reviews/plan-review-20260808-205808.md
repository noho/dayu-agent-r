## Findings

### F20-RR2-MIMO-001 — actual pre-forward hard guard 的 production CLI 装配 seam 未被证明

- Severity：high
- 证据：
  - plan `§5.2`（当前 280–286 行）要求 formal driver 通过“既有 audited transparent transport wrapper seam”取得完整
    prepared candidate / manifest，在真实 MiMo forward 前运行 production estimator，并在 `predicted >= hard` 时阻止 forward；
    但没有给出该 seam 的 owner symbol、composition point、run-owned wrapper 文件/身份、安装方式或 request/response byte-transparent
    contract，只在 seam 不可用时把 Slice 1 标为 `setup-blocked`。
  - 当前 production Service assembly 在 `dayu/service/host_assembly.py:890-934` 直接构造冻结 `OpenHostOptions`，并在
    `:922` 固定装配 `DefaultLocalEngineWorkerFactory()`；当前 CLI 在
    `dayu/cli/commands/interactive.py:106-113` 取得该 assembly 后直接 `open_host(options)`，没有 external worker/transport wrapper
    参数或 callback。
  - Host 唯一直接位于完整 request 构造后、Engine 委托前的 typed boundary 是
    `dayu/host/dispatch.py:4647-4668` → `LocalEngineWorker.accept(snapshot, request)`；其 public protocol 位于
    `dayu/host/api.py:803-833`。默认实现随后由 `dayu/host/local_proxy.py:31-80` 接受 request 并进入真实 Engine。要在这里
    fail closed 必须让 production CLI 实际装配一个 delegate wrapper，但本计划没有说明如何做到这一点。
  - 因而当前 plan 没有排除三种会改变证据含义的实现：对 CLI/import 做 monkeypatch、修改 workspace model endpoint/profile 以插入
    HTTP proxy，或绕开真实 production CLI 直接调用自定义 opener。三者对“production CLI”“fixed profile/identity”和
    request-byte equality 的影响不同，不能由实现者临场决定。
- Failure mode：实现可以在 Host/Engine forward 后事后复算而仍声称 guarded，或通过未授权的 runtime patch / endpoint identity
  变化取得 pre-forward interception；反之若不采取这些动作，默认 production CLI 没有装配 guard，正式链会在未满足 binding goal
  的情况下转发 actual accepted snapshot。计划中的 `setup-blocked` stop condition只防止继续消耗 provider，不能证明此前声称的
  “既有 seam”存在，也不能使 plan code-generation-ready。
- Required action：在 plan 中选择并冻结唯一合法的 actual guard composition：给出 owner symbol 与 exact injection path，说明
  production CLI argv/entrypoint、fixed execution profile/model/endpoint identity哪些必须保持不变；冻结 wrapper 的 typed input/output、
  delegate identity、request message/tool-schema byte digest、manifest binding与 guard-before-delegate 顺序。增加 provider-free
  self-test，直接证明 `< hard` 时同一 request bytes恰好委托一次，`== hard`与`> hard`时 delegate/provider create/call均为0，且
  production CLI 实际消费该 wrapper。若当前 public composition boundary无法做到，应把它登记为 blocking owner question并先回到
  goal/design gate，而不是把未知实现路径称为既有 audited seam。
