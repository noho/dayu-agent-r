### NEW-001-无需修复-低-continuation tool schema frozen source 依赖首个 manifest 持久化完整性

- **位置**: §5.3 "selected tool schema：只来自同一 attempt/execution 首个 complete pre-start manifest 引用的 selected-tool-schema descriptor/ref/digest"
- **问题类型**: 契约依赖
- **当前写法**: plan 要求 continuation 的 tool schema 从首个 complete manifest 读取。如果首个 manifest 的 tool schema descriptor/ref 因 payload 损坏或 purge 而不可读，continuation 必须写 `unavailable`。
- **反例/失败场景**: 首个 complete manifest 的 tool schema payload 被 purge 或损坏，但 manifest event 本身仍存在。continuation 无法读取 tool schema descriptor → `unavailable` → conservative fallback。这不是功能错误，但会降低 anchor quality。
- **为什么有问题**: 这是 plan 设计的预期行为（fallback），不是 bug。payload 损坏/purge 是极端场景，已有 closed unavailable 兜底。
- **直接证据**: plan §5.3: "任一 ref 缺失、digest 不匹配、projection 为空/不完整或 crash 使来源不可读时，必须写 `status=unavailable`"
- **影响**: 无 — 已有 fallback 兜底，属于 accepted residual risk。
- **建议改法和验证点**: 无需修改。Slice 3 测试应覆盖 "首个 manifest tool schema payload 不可读 → continuation unavailable → fallback" 场景。
- **修复风险（低）**: 无需修复。
- **严重程度（低）**: 不阻塞。

### NEW-002-无需修复-低-same-candidate idempotent fact 复用需要显式验证

- **位置**: §5.6 "已存在同 identity 且一致的 fact 只表示幂等复用，仍须在同 transaction 重新验证当前 Run state 后才能继续 transition"
- **问题类型**: 实施细节
- **当前写法**: plan 说 same identity + consistent fact = idempotent reuse。但 "一致" 的判定标准是什么？是 payload 完全相等，还是只比较 identity 输入字段？
- **反例/失败场景**: 如果同一个 candidate 被 evaluate 两次（例如 crash recovery 后重新 governance），第一次写入的 fact 的 `conservative_input_tokens=1000`，第二次因为 estimator 公式微调（虽然 plan 说不变）得到 `1001`。此时 identity 相同但 payload 不同 — 应该 fail closed 还是 reuse？
- **为什么有问题**: plan 说 "identity conflict，fail closed" — 这意味着 payload 不一致就是 conflict。但 estimator 公式/常量不变的假设下，同一 candidate 的 estimate 应该 deterministic。如果 estimator 实现有浮点精度问题... 但 plan 要求 `strict int`，所以不会有浮点问题。
- **直接证据**: plan §5.6: "已存在且 payload/identity/result 一致：返回既有 row，不追加；已存在但任一结果矛盾：identity conflict，fail closed"
- **影响**: 无 — deterministic estimator + strict int 保证一致性。
- **建议改法和验证点**: 无需修改。测试应覆盖 "same identity + same payload → idempotent" 和 "same identity + different payload → fail closed"。
- **修复风险（低）**: 无需修复。
- **严重程度（低）**: 不阻塞。
