## Outcome

Plan 的 owner、scope 与“不新增 schema/public contract/cursor”方向正确，但当前 raw frontier 算法还不够 code-generation-ready。主要缺口不是目标，而是如何在不把 evidence id 当 EventLog id、不重读全部已消费大 payload 的前提下，证明一个 Host Run group 已被完整消费。实现前必须把 proof、fail-closed 条件与 query/payload resolution 边界写成唯一算法。

## Evidence checked

- `ContextCompactedSemanticPayload.compacted_source_refs` 从 strict committed boundary 与 represented/omitted partition 派生；`current_input_ref` 被显式排除。
- user / assistant material 的 `canonical_source_refs` 是 EventLog event id；accepted tool evidence material 的 `canonical_source_refs` 是 evidence id。
- `select_compact_segment` 先按 `turn_group_id` 归并 `_AtomicMaterialUnit`，再做 whole-unit exclusion 与 strict prefix budget，不能拆组。
- 当前 `_post_compact_delta_start_sequence` 只用 latest compact terminal sequence，完全不读取 accepted coverage。
- `_pre_dispatch_delta_material_blocks` 现在只对 evidence使用 latest `accepted_evidence_mapping_refs` 提前过滤；这不是 cumulative consumption truth。

## Findings

### F14-PR-01 — High — atomic group coverage proof 未冻结

Plan 写“使用 `run_id`/`turn_group_id` 和已覆盖的 user/answer canonical refs判断完整消费”，但没有冻结 exact predicate。若实现者自行选择“任一成员被覆盖即整组消费”，损坏或旧fixture可令未覆盖成员再次被跳过；若选择“所有EventLog event_id都覆盖”，tool evidence永远无法匹配，因为它的source ref是evidence id。

必须修订为：

1. canonical raw rows先按 `run_id` 分组并保持首row顺序；一个可跳过的Host Run group必须有且仅有一个canonical `USER_INPUT_ACCEPTED` anchor。
2. accepted consumed refs包含该user event id时，依赖既有selector whole-group accept invariant把该组判为已消费prefix；同组可直接映射的user/answer refs若出现矛盾必须fail closed。
3. 未被user anchor证明消费的第一个group即frontier；从该点开始走完整typed projector，并对每个block做all/none ref intersection。发现该未消费group中的evidence id其实已消费，必须作为partial-group corruption fail closed。
4. `run_id=None`、缺user anchor或多个user anchor不能被whole-group proof跳过；作为singleton/不可证明frontier走typed projector，不能猜。

这条 proof 来自 accepted source refs + Host Run atomic selector，不是从terminal位置或ref前缀推断。

### F14-PR-02 — High — accepted chain 的 referential integrity 未说明

现有 strict payload parser验证shape/coverage等式，但 `current_input_ref` 仍只是非空字符串，并未证明它指向同Session、早于terminal的canonical `USER_INPUT_ACCEPTED`。Plan若直接把所有`compacted_source_refs`累积为coverage，损坏的accepted payload可能把错误ref带入frontier。

chain helper必须复用EventLog owner做referential checks：

- 每个`current_input_ref`存在、同Session、canonical fact、类型为`USER_INPUT_ACCEPTED`且sequence早于该compact terminal；多个reactive compact允许复用同一current input。
- 若某个compacted source ref exact匹配EventLog中的`CONTEXT_COMPACTED` id，它只能引用同Session、sequence更早的accepted compact；self/forward/cross-session/wrong-class fail closed。
- 不按ref字符串前缀分类；普通raw/evidence ref的membership仍由typed material projector验证。

### F14-PR-03 — Medium — query与payload resolution边界互相矛盾

Implementation步骤写“读取current input之前所有raw rows”，风险表又要求不重新渲染已证明消费的evidence payload。若直接对全历史调用`_pre_dispatch_delta_material_blocks`，每轮都会解析已消费tool payload/artifact，带来随历史增长的成本，并让本可由accepted replacement继续工作的Session因旧raw artifact损坏而失败。

必须冻结两阶段读取：

1. 只读取relevant EventLog row metadata建立canonical group order并找出最早不可证明已消费的frontier；不在该阶段resolve tool payload。
2. 只对frontier到current input的rows调用现有strict material projector，再按cumulative consumed refs exact过滤。

SQL不能使用unbounded `NOT IN`；accepted refs只在Host内存typed集合中比较。

### F14-PR-04 — Medium — latest projection不应重复解析accepted payload

Plan仍描述多个既有helper分别读取latest replacement、latest evidence aggregate。chain traversal既然已经strict解析每个terminal，就应让builder从最后一个typed chain entry直接投影latest previous view与`accepted_evidence_mapping_refs`，避免同一次build内对descriptor/artifact重复resolve并产生观察不一致窗口。

这不是新source truth；只是复用同一strict typed read。

### F14-PR-05 — Medium — regression fixture 必须保存真实source boundary

当前`tests/host/test_compact_material.py`的`_append_compacted_event`默认通过`source:T1`等synthetic refs构造accepted truth；已有second-compact测试依赖terminal+1跳过raw，因此其boundary未真实覆盖那些raw。若只改生产代码而保留fixture，要么旧测试正确失败，要么实现者会被迫加入兼容分支。

Plan必须要求扩展test helper显式接收current input ref与per-label canonical source refs，并让所有声称“已消费旧raw”的测试写入真实event/evidence refs。默认synthetic helper只可服务不依赖coverage的strict payload shape测试。

### F14-PR-06 — Low — boundary字段的新语义需写明空/不可读row处理

`post_compact_delta_start_sequence` 应表示最早保留material block sequence，而不是最早relevant raw EventLog row。如果某个`RUN_SUCCEEDED`合法投影为无answer block，frontier可越过该row；docs/tests应按material frontier断言，不固定偶然row或terminal sequence。

## Counterexamples used

1. `event_id="tool-result-7"`，`evidence_id="evidence-opaque-42"`：event-id `NOT IN`会错误保留已消费evidence。
2. compact terminal sequence 100覆盖group A，但group B sequence 80–90因recent floor未入boundary：terminal+1会丢B；accepted group anchor proof会保留B。
3. group B的assistant event ref被错误写进coverage、user ref未覆盖：任一成员即消费会再次丢B；all/none检查应fail closed。
4. accepted compact 只引用previous compact event，但此前有protected group：previous ref不能传递消费该group。
5. failed/rejected terminal sequence位于raw之后：只查询canonical`CONTEXT_COMPACTED`可保证frontier不动。
6. 两个reactive accepted compacts共享current input：current ref复用合法，不能要求current input与compact一对一。

## Required plan changes

- 冻结 `_AcceptedCompactChainEntry(event, semantics)` 或等价窄typed entry。
- 冻结chain current-input/previous-compact exact referential validation。
- 冻结metadata-first group proof、frontier后typed projection与partial intersection fail-closed算法。
- 明确latest typed semantics只解析一次并被previous/replacement/evidence投影复用。
- 明确coverage-sensitive fixtures必须使用真实source refs。
- 测试加入opaque evidence id、partial group corruption、shared reactive current input、missing/duplicate group anchor、empty material projection。

## Scope / architecture decision

- Engine、Memory、UI/Service、prompt与tool trace renderer无需生产变更。
