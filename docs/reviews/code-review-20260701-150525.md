## Findings

### 01-未修复-高-默认 _DirectWaitPollerFactory 在 background open() 中复用调用线程 SQLite runner

- **入口/函数**: `WaitPollerSupervisor.__init__` → `_DirectWaitPollerFactory` 默认构造
- **文件(行号)**: `wait_adapter.py` `_DirectWaitPollerFactory` dataclass; `WaitPollerSupervisor.__init__` 中 `self._poller_factory = poller_factory if poller_factory is not None else _DirectWaitPollerFactory(...)`
- **输入场景**: Slice 3 `open_host` 使用默认 `poller_factory=None` 构造 `WaitPollerSupervisor`，然后调用 `supervisor.open()` 启动 background thread
- **实际分支**: `_poll_once()` → `_DirectWaitPollerFactory.create_wait_poller()` → `WaitPoller(transaction_runner=self.transaction_runner, ...)`，其中 `self.transaction_runner` 是 opener 线程的 `HostTransactionRunner`
- **预期行为**: background thread 必须使用线程内 SQLite connection；`HostTransactionRunner` 持有 SQLite connection 且有线程亲和性
- **实际行为**: 默认 `_DirectWaitPollerFactory` 捕获 opener 线程的 `transaction_runner` 并在 background thread 中复用，导致跨线程使用同一 SQLite connection
- **直接证据**: `_DirectWaitPollerFactory` dataclass 字段 `transaction_runner: HostTransactionRunner` 在 `__init__` 时从 supervisor 参数捕获；`_run_loop` 在 `threading.Thread` 中调用 `_poll_once()` → `self._poller_factory.create_wait_poller(self)` → 使用捕获的 `transaction_runner`
- **影响**: 生产路径线程错误 — SQLite connection 不允许跨线程使用，会导致 `ProgrammingError` 或数据损坏
- **建议改法和验证点**:
  1. 当前设计是正确的：`WaitPollerFactory` Protocol 作为 typed port 存在，Slice 3 必须提供线程内 factory。implementation artifact 和 residual risks 已明确记录此约束。
  2. 但默认 `_DirectWaitPollerFactory` 对生产调用方是 **unsafe 的 trap** — 如果 Slice 3 忘记传 `poller_factory`，代码会静默使用 unsafe 默认值而非 fail-fast。
  3. 建议：移除默认 `_DirectWaitPollerFactory`，使 `poller_factory` 成为 `WaitPollerSupervisor.__init__` 的必填参数。这样 Slice 3 必须显式提供 factory，不会意外使用 unsafe 默认值。
  4. 验证：`WaitPollerSupervisor(poller_factory=None)` 应抛出 `TypeError` 或 `ValueError`。
- **修复风险（低）**: 将 `poller_factory: WaitPollerFactory | None = None` 改为 `poller_factory: WaitPollerFactory`，删除默认构造分支，更新测试显式传入 factory。
- **严重程度（高）**: 高，因为默认值对生产路径是 unsafe 的，且 fail-silent 而非 fail-fast。但当前 Slice 2 未接入 `open_host`，所以不影响当前已 ship 的代码；风险在 Slice 3 wiring 时兑现。

### 02-未修复-中-close() 从 poller 线程自身调用时提前返回不等待

- **入口/函数**: `WaitPollerSupervisor.close()`
- **文件(行号)**: `wait_adapter.py` close() 中 `if thread is threading.current_thread(): return`
- **输入场景**: 如果 `open_host` 的 close 序列在 poller 线程内触发（例如 poller 线程是 daemon thread 且 Host close 从同一上下文调用），或未来代码路径意外在 poller 线程内调用 `close()`
- **实际分支**: `thread is threading.current_thread()` → `return`，不设置 STOPPED 状态，不 join
- **预期行为**: `close()` 应保证返回时 poller 已停止或状态已明确
- **实际行为**: 从 poller 线程调用时提前返回，diagnostics 状态停留在 CLOSING，thread 继续运行
- **直接证据**: `wait_adapter.py` close() 中 `if thread is threading.current_thread(): return` — 此分支不更新 diagnostics，不 join thread
- **影响**: 低 — 当前设计中 `close()` 应从 opener 线程调用，不是从 poller 线程。但此 guard 缺少文档说明为什么可以安全提前返回。
- **建议改法和验证点**:
  1. 在 `if thread is threading.current_thread(): return` 前添加注释说明：此分支仅在 poller 线程自身调用 close 时触发（不应发生），此时 loop 将在下一次 `_close_event.is_set()` 检查时自然退出。
  2. 或者：记录一个 warning log 说明 unexpected self-close。
- **修复风险（低）**: 添加注释或 warning log。
- **严重程度（中）**: 中等，因为当前调用路径不会触发此分支，但缺少文档让后续维护者难以理解意图。

### 03-未修复-低-诊断快照更新存在短暂状态不一致窗口

- **入口/函数**: `WaitPollerSupervisor.close()` 和 `_run_loop()`
- **文件(行号)**: `wait_adapter.py` close() 和 _run_loop() finally 块
- **输入场景**: `close()` 和 `_run_loop()` 并发执行
- **实际分支**: close() 设置 CLOSING → close_event.set() → thread.join(timeout) → 如果 timeout 则记录 close_drain_timeout → thread.join() → 设置 STOPPED。同时 _run_loop() 在 finally 中也设置 STOPPED。
- **预期行为**: 最终 diagnostics 状态为 STOPPED（或 FAILED）
- **实际行为**: 两个路径竞争设置 STOPPED，由于 `_diagnostics_with_status` 是纯复制操作且 STOPPED 是幂等终态，最终状态正确。但中间窗口可能短暂显示 CLOSING → STOPPED → STOPPED（两次设置）。
- **直接证据**: close() 最终 `self._diagnostics = _diagnostics_with_status(self._diagnostics, WaitPollerLoopStatus.STOPPED)` 和 _run_loop() finally 中相同操作。两者都在 lock 保护下，但 close() 的 STOPPED 设置在 thread.join() 之后，可能覆盖 _run_loop() already-set 的 STOPPED。
- **影响**: 无功能影响 — STOPPED 是幂等终态，覆盖无副作用。diagnostics_snapshot() 在 lock 下读取，总是看到一致状态。
- **建议改法和验证点**: 无需修改。当前实现正确。
- **修复风险（低）**: N/A
- **严重程度（低）**: 低，纯 cosmetic，无功能影响。

## Residual Risk

- **默认 `_DirectWaitPollerFactory` 是 unsafe trap**（见 Finding 01）：Slice 3 wiring 必须显式传入 `poller_factory`。建议在 Slice 3 或当前 Slice 2 将其改为必填参数。
- **Synchronous adapter calls cannot be forcibly interrupted**: accepted plan residual. Close waits for in-flight calls; operators see close-drain timeout diagnostics.
- **`shutdown_skipped` uses normal durable backoff**: repeated close-during-result races can increase shared backoff. Bounded by `backoff_max_delay_seconds`.
- **`_backoff_delay_seconds` lacks dedicated unit test**: covered indirectly through integration tests. Low risk.
- **No test for `open()` → `close()` → `open()` rejection**: the code raises `RuntimeError("stopped wait poller supervisor cannot be reopened")` but no test covers this path.
