### DL-R01-未修复-中-FinsDownloadDateRange.start_is_explicit typed 字段未穿透 adapter 链，下游从字符串反推 explicitness

- **入口/函数**: `SecDownloadAdapter.download()` / `run_download_stream_impl()` / CN 对应 adapter
- **文件(行号)**:
  - `dayu/fins/download_contract.py:65` — `FinsDownloadDateRange.start_is_explicit` 定义
  - `dayu/fins/ingestion_runtime.py:414` — `FinsSourceDownloadAdapterRequest.date_range` 携带完整 `FinsDownloadDateRange`
  - `dayu/fins/pipelines/sec_pipeline.py:1817` — adapter 仅传递 `request.date_range.start_text`（ISO 字符串或 None），丢弃 `start_is_explicit`
  - `dayu/fins/pipelines/sec_download_workflow.py:443` — `start_is_explicit = start_date is not None` 从字符串存在性反推，而非从 typed field 读取
  - `dayu/fins/pipelines/cn_pipeline.py:1376` — CN adapter 同样仅传 `start_text`
  - `dayu/fins/pipelines/cn_download_workflow.py:253` — `use_default_business_limits=start_date is None` 同样从字符串反推
- **输入场景**: 未来如果 download builder 在非用户显式输入场景下产生非 None `start_bound`（例如默认窗口），typed `start_is_explicit` 会正确保持 `False`，但 `start_text` 会返回非 None 字符串，导致 downstream 将默认窗口误判为显式窗口，错误阻止 SC13 retry 扩大或 CN 业务数量限制。
- **实际分支**: `run_download_stream_impl:443` 的 `start_is_explicit = start_date is not None` 分支。
- **预期行为**: 下游应直接消费 `FinsDownloadDateRange.start_is_explicit` typed field，不反推。
- **实际行为**: adapter 在 `request.date_range → start_text/end_text` 映射中丢弃了 `start_is_explicit`；workflow 从 `start_date is not None` 二次推导。
- **直接证据**:
  - `download_contract.py:155` 明确定义 `start_is_explicit=start is not None`
  - `sec_pipeline.py:1817` adapter 调用链为 `start_date=request.date_range.start_text`，未传 `start_is_explicit`
  - `sec_download_workflow.py:443` 重建 `start_is_explicit = start_date is not None`
  - Plan §5.1 明文要求 "source workflow 不再反解析字符串或从日期值猜 explicitness"
  - Plan §5.3 要求 "SEC request 的 `start_is_explicit` 一路传到 SC13 retry/browse owner"
- **影响**: 当前行为正确（`start_text` 为 None ⇔ 非显式），但引入语义重复，使 typed field 的防错意图落空。若 builder 未来增加默认窗口逻辑，下游反推将产生静默正确性错误：SC13 retry 被错误禁止扩大、CN business limits 被错误关闭。
- **建议改法和验证点**:
  1. `run_download_stream_impl()` 增加显式 `start_is_explicit: bool` 参数，由 adapter 从 `request.date_range.start_is_explicit` 传入
  2. 删除 `sec_download_workflow.py:443` 的 `start_is_explicit = start_date is not None` 反推
  3. `cn_download_workflow.py` 的 `use_default_business_limits` 同样改为接收显式 boolean，由 adapter 从 `request.date_range.start_is_explicit` 传入
  4. 验证点: 构造 `start_is_explicit=True` 但 `start_text=None` 的边界场景（虽然当前 builder 不产生），确保 typed field 生效
- **修复风险（低）**: 当前行为等价，修复不改变可观测行为；仅替换推导方式。需同步改 SEC/CN 两路 adapter。
- **严重程度（中）**: 当前非缺陷，但违反 plan 明确语义约束，且为未来默认窗口等演进留下静默 bug 入口。
