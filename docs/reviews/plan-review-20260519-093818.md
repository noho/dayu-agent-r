## Findings

未发现 blocking finding。

本轮 review 前发现的两个 plan gap 已在 review 前修正：

- semantic repair attempt budget 已从未指定的 bounded retry 补成 `ContextBudgetPolicy.max_compaction_attempts_per_operation` typed 字段，避免魔法数字或 Service callback。
- `CONTEXT_COMPACTION_ATTEMPT_REJECTED` 已从“或等价 diagnostic fact”收紧为固定 canonical fact，避免实现时发散。
- Slice 4 已从“审计并在必要时调整”收紧为必须调整 proactive / reactive transaction 边界。

## Open Questions

无需要阻塞 implementation 的开放问题。

实现阶段仍需在代码中命名并落地 typed proposal failure / reject category。plan 已约束 failure owner、EventLog payload 与测试边界，具体类名可以在 implementation 内按现有 Host 命名风格确定。

## Residual Risks

- Transaction 拆分风险高。当前代码的 proactive 与 reactive compact 都在 transaction path 中调用 `compactor.compact(request)`；实现需要重排控制流、状态 recheck 和后续 dispatch 启动，容易引入重复 event、stale compact 或 missed wakeup。
- Repair state machine 风险高。`CONTEXT_COMPACTION_ATTEMPT_REJECTED`、attempt budget、final FAILED/COMPACTED 的 exactly-once 语义必须和 operation id、cursor recheck、HostEvent emission 一起验证。
- Public API 破坏面明确但不可忽略。`CompactorExecutionBaseline` 已是包根 public export；plan 要求不保留兼容 wrapper，implementation 必须一次性同步 tests、manual smoke 与 README。
- Smoke 可观测性会改变。删除测试侧 compactor object 后，manual smoke 必须依赖 public watch / artifact window / terminal event 观察 compact 成功，不能重新引入测试专用 public hook。

## Project Instruction Check

- 分层边界：pass。plan 保持 `UI -> Service -> Host -> Engine`，compactor governance 收回 Host，Engine 只保留 runner transport retry。
- `dayu.runtime` 边界：pass。plan 明确 `LLMContextCompactor` 不得放入 `dayu.runtime`。
- Public contract：pass。plan 移除 Service-facing `ContextCompactor` 与 raw `policy_ref`，只保留 runner/options/artifact/context budget typed 输入。
- 测试策略：pass-with-risks。plan 覆盖 no-network unit tests、transaction boundary tests、env-gated real provider smoke、pyright 与 host regression；高风险点在实现复杂度，不在测试方向缺失。
- 文档同步：pass。plan 要求 README 只在实现完成后同步当前代码事实，避免提前写未来状态。

## Final Conclusion

`pass-with-risks`。

plan 已清理旧语义和讨论痕迹，架构边界与 design 真源一致，可以进入 implementation。后续 code review 必须重点检查 transaction 外 LLM call、semantic repair EventLog/HostEvent、stale result recheck，以及 public opener 是否彻底移除 Service-side compactor injection。
