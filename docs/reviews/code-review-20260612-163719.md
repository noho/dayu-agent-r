## 6. Residual Risks

### R1: compaction_evidence.py consumer 未在 docstring 中显式命名

**描述：** `_terminal_answer.py` 模块 docstring 列出 consumer 边界时写了 "compaction material 使用本 strict continuity resolver"，但 `compaction_evidence.py:413` 也是 strict resolver consumer，未单独命名。

**严重性：LOW。** `compaction_evidence.py` 构建 initial history material，语义上属于 "compaction material" 的宽泛范畴，与已有 docstring 声明不矛盾。两个 consumer 使用相同的 strict resolver + artifact fallback 策略。

**建议：** 不需要在 WU-CM-06 范围内修改。future work 如需收紧可补充。

**是否阻断：否。**

### R2: Overlong text 保存 vs. caller 截断

**描述：** WU-CM-06 helpers 正确保留 overlong text，但 caller 截断责任分散在多个 consumer（compaction material、run-input adapter、memory consumer）。plan 明确将 caller-side truncation 标为 out of scope。

**严重性：LOW。** 这不是 WU-CM-06 引入的问题；caller 截断在 WU-CM-06 之前就已由各 consumer 自行负责。

**建议：** 如果 compaction material 或 run-input adapter 需要统一的长度治理，应作为独立 work unit 处理。

**是否阻断：否。**

### R3: 非 RUN_SUCCEEDED payload 传入 `assistant_final_answer_continuity_text` 的行为

**描述：** `assistant_final_answer_continuity_text` 的 docstring 注明了只处理 `RUN_SUCCEEDED` payload，但函数本身不做 event type 校验。如果误传入 RUN_FAILED/CANCELLED/LOST payload，函数不会报错，但只要 payload 中无 `final_answer` 或合法 terminal descriptor，会正确返回 `None`。

**严重性：LOW。** 调用方已经在 event type 层面做了过滤（memory.py 的 `_selected_recent_item_from_run_succeeded`、durable/memory.py 的 `_memory_projection_payload` 都检查 `event_type != RUN_SUCCEEDED`）。现有类型系统（函数签名接受 `Mapping[str, JsonValue]`）是合理的设计——不需要额外的运行时 event type 校验。

**是否阻断：否。**

### R4: compaction_evidence.py consumer 的测试覆盖

**描述：** `compaction_evidence.py` 使用 strict resolver，但没有专门测试该 consumer 的 terminal text source-selection 行为。不过该 consumer 调用的 `assistant_final_answer_continuity_text` 函数已在 `test_terminal_summary_payload.py` 中全面测试。

**严重性：LOW。** 函数级别已充分测试。compaction_evidence integration-level 测试属于 smoke/integration 范畴，不在 WU-CM-06 scope。

**是否阻断：否。**
