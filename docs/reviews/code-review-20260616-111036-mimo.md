## Findings

### R1 — Cancel race 丢弃已完成 terminal result

- **文件**: `dayu/cli/commands/fins.py:670-689`
- **严重度**: Medium
- **描述**: `_wait_for_terminal_handling_sigint` 中，当 SIGINT 到达时 `event_task` 可能已经完成并持有 terminal `FinsResultSummary`。当前代码调用 `event_task.cancel()`（对已完成 task 是 no-op），然后 `await event_task` 返回已完成的结果（不抛 `CancelledledError`），代码继续执行到 `return _cancelled_result_summary()`，丢弃了真实的 terminal result。
- **计划约束**: replacement plan Slice B 明确要求 "terminal RESULT 已产出但 CLI 尚未消费时收到 Ctrl+C，最终结果不得被 cancel 覆盖"。
- **修复建议**: 在 `event_task.cancel()` 后、`await event_task` 前，检查 `event_task.done()` 且无异常；若已完成且持有 result，直接 `return await event_task`，不进入 cancelled 路径。
- **测试缺口**: `test_cancel_race_does_not_override_terminal_result` 实际测试场景无 SIGINT；应补充 SIGINT 与 terminal RESULT 并发到达的测试。

### R2 — Cancel race 测试名实不符

- **文件**: `tests/cli/test_fins_commands.py` — `test_cancel_race_does_not_override_terminal_result`
- **严重度**: Low
- **描述**: 测试名称暗示验证"cancel 不覆盖已完成 terminal result"，但实际测试场景是 stream 立即产出 terminal RESULT 且无 SIGINT 触发。这与正常的 success 路径测试重复，不覆盖真正的 cancel race 场景。
- **修复建议**: 重命名或改写为真正的 cancel race 测试：stream 产出 progress 后暂停，SIGINT 到达时检查 event_task 是否已完成 terminal RESULT。

### R3 — Service 和 CLI 双重 missing-RESULT fallback

- **文件**: `dayu/service/fins_direct.py:477-510`、`dayu/cli/commands/fins.py:720-725`
- **严重度**: Low
- **描述**: Service `_ensure_result_event` 在 runtime stream 正常结束但无 RESULT 时注入 failure RESULT；CLI `_consume_fins_direct_events` 在 stream 结束但无 RESULT 时也有 fallback。由于 Service 已保证正常结束有 RESULT，CLI fallback 实质上是 dead code（仅在 Service 层 bug 时触发）。
- **修复建议**: 保留为 defense-in-depth 即可，但 CLI fallback 中的 `_missing_result_event()` 使用 `FinsOperationKind.PREPROCESS` 硬编码 operation_kind，不够精确。可改为从最后见到的 event 推断 operation_kind，或接受当前 dead-code 性质。

### R4 — `_CliFinsCancellationToken` 未实现显式 Protocol

- **文件**: `dayu/cli/commands/fins.py:106-165`
- **严重度**: Low
- **描述**: `_CliFinsCancellationToken` 通过 duck typing 满足 Service 的 `CancellationToken` 参数要求，但未显式实现任何 Protocol。测试中也使用自定义 `_FakeCancellationToken`。
- **修复建议**: 当前 duck typing 可接受；若后续 `CancellationToken` contract 扩展，应考虑显式实现。

### R5 — `ingestion_runtime.py` stub 方法中 `del` 语句

- **文件**: `dayu/fins/ingestion_runtime.py:1696-1779`
- **严重度**: Info
- **描述**: 三个 stub 方法使用 `del request, cancellation_token` 抑制 unused parameter 警告，然后 `raise` + `yield`。这是 Python async generator stub 的正确写法。
- **修复建议**: 无需修改。
