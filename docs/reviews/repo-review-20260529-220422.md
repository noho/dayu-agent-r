### 1-未修复-中-purge 状态常量与 RunStatus enum 不同步

- **入口/函数**: `purge_session_durable` -> `_enforce_no_non_terminal_runs`
- **文件(行号)**: `dayu/host/durable/purge.py:102-130`
- **输入场景**: 任何 purge 前置条件检查
- **实际分支**: 使用模块级字符串常量 `_NON_TERMINAL_RUN_STATUSES` 和 `_TERMINAL_RUN_STATUSES`
- **预期行为**: 状态常量应与 `RunStatus` enum 保持同步，或直接使用 enum
- **实际行为**: `purge.py:102-130` 定义了纯字符串常量（`_RUN_STATUS_ACCEPTED`、`_RUN_STATUS_QUEUED` 等），而 `state.py:56-58` 和 `run_transition.py` 使用 `RunStatus` enum。如果 `RunStatus` 新增值但未同步更新 `purge.py`，purge 的前置条件检查会把新状态误判为"未知状态"（`purge.py:932-933` `raise HostDurableError("Run row status is invalid")`），导致 purge 永远失败
- **直接证据**: `purge.py:102-130` 使用字符串 `_RUN_STATUS_ACCEPTED` 等；`state.py:56-58` 使用 `frozenset((RunStatus.SUCCEEDED, ...))`；两处无共享真源
- **影响**: fail-closed 安全但运维阻塞——新增 RunStatus 值后 purge 永远返回错误
- **建议改法和验证点**: 将 `purge.py` 的 `_NON_TERMINAL_RUN_STATUSES` / `_TERMINAL_RUN_STATUSES` 改为从 `state.py` 导入已有的 enum 常量，或直接使用 `RunStatus` enum。验证点：新增 RunStatus 值时确认 purge 检查仍通过
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

1. **新增 RunStatus / AttemptStatus 值的同步风险**: `purge.py`、`schema.py`（CHECK 约束）、`state.py` 三处都需要同步更新，缺少编译时或测试时的交叉校验。
