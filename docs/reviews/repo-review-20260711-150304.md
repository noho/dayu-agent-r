### 1-未修复-高-WaitPollerSupervisor 单次瞬态异常导致服务永久不可用
- **入口/函数**: `WaitPollerSupervisor.open()` / `WaitPollerSupervisor._run_loop()`
- **文件(行号)**: `dayu/host/wait_adapter.py:1337-1338` + `dayu/host/wait_adapter.py:1446-1472`
- **输入场景**: background poll loop 中发生任何未捕获的 `Exception`（如数据库瞬态锁超时）
- **实际分支**: `except Exception` 设置 `failed = True` 并 `close_event.set()`；`open()` 检查 `FAILED` 状态后 raise `RuntimeError` 拒绝重新打开
- **预期行为**: 一次瞬态错误不应导致永久性服务不可用；应有退避重试或 restart 入口
- **实际行为**: 任何 unhandled exception 导致 supervisor 永久进入 `FAILED` 状态，无法重新 `open()`。所有 POLL 类型的等待（财报下载、预处理、上传）无法自动推进
- **直接证据**: `wait_adapter.py:1460-1471` 的 `except Exception` 设置 `self._diagnostics = _diagnostics_with_fatal_error(...)` + `self._close_event.set()`；`wait_adapter.py:1337-1338` 的 `if self._diagnostics.status is WaitPollerLoopStatus.FAILED: raise RuntimeError(...)`
- **影响**: 生产环境中单次瞬态数据库错误可导致整个 wait polling 服务永久停止
- **建议改法和验证点**: 在 `_run_loop` 中增加 per-round 异常处理，catch 后短暂退避继续循环，只在连续 N 次 fatal error 后才进入 FAILED 状态；或提供 `restart()` 方法重置 FAILED 状态。验证点：模拟单次瞬态异常后 supervisor 自动恢复
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高
