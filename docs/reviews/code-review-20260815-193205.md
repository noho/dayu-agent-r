以下为按 requested adversarial dimensions 的逐项 direct-evidence 闭集审查结论：

### Validation precedence

`_validate_fins_upload_filing_static`（`ingestion_runtime.py:1039-1151`）的校验顺序为：

1. ticker 归一化（1054-1057）
2. source_kind（1058-1059）
3. action 归一化与 enum 校验（1060-1062）
4. raw `files` count > 100（1063-1064）
5. fiscal_year / fiscal_period / period length / period normalization（1065-1082）
6. filing_date / report_date / company_name（1083-1085）
7. **delete 分支**：files → primary rejection，然后 `for_delete()`（1086-1091）
8. **upsert 分支**：路径规范化 → exact-string duplicate → selector cardinality/membership → basename/exists/regular → format suffix → `for_upsert()`（1094-1129）

delete 的 files-before-primary 顺序由代码行 1087-1090 的连续 `if` 确定。测试 `test_filing_delete_rejects_files_before_primary_and_path_normalization`（test_fins_ingestion_runtime.py:1616）通过 monkeypatch `Path.expanduser` 在 delete rejection 前断言路径规范化从未执行，直接证据：monkeypatched `expanduser` 始终抛出 `AssertionError`，而测试成功捕获 `FinsUploadUsageError`。

### Converter/workspace mutation/publication 前拒绝

测试 `test_new_filing_admission_failures_precede_state_jobs_runner_and_workspace_mutation`（test_fins_ingestion_runtime.py:1672）使用 `_build_static_admission_guarded_runtime` 注入 `_ForbiddenFilingUploadStateRepository`、`_ForbiddenUploadRunner` 与 `_HoldingExecutor`。6 个 invalid requests 按预期 closed code 失败后，直接证据断言：

- `state_repository.calls == []`
- `executor.operations == []`
- `runner.requests == []`
- `runtime._observations == {}`
- workspace 树快照前后一致

测试 `test_delete_contract_rejects_before_workspace_repository_bootstrap`（test_fins_service_runtime.py:93）通过 monkeypatch `Path.resolve` 在 workspace root 上抛出 `AssertionError`，确认 delete rejection 在 `FsFilingUploadStateRepository` 构造前完成。

### 100 inclusive

`_MAX_TUPLE_ITEMS = 100`（ingestion_runtime.py:150）。校验条件 `len(request.files) > _MAX_TUPLE_ITEMS`（行 1063）意味着 100 通过、101 拒绝。

- 100 个 distinct files 接受（`assert len(accepted.file_selection.ordered_files) == 100`）
- `(files[0],) * 101` 拒绝为 `TOO_MANY_FILES`，确认 raw count 先于 duplicate 检查

### Raw duplicate selector 保留

`FinsUploadFilingRequest.primary_selectors: tuple[Path, ...] = ()`（ingestion_runtime.py:645）。docstring 明确：「保留每次 occurrence，不表示已验证角色」（行 630）。

### Normalized exact path equality

`_fins_upload_path_identity`（ingestion_runtime.py:979-994）返回 `str(path)` on `expanduser().resolve(strict=False)` 结果，不使用 `normcase`、inode、basename 或 stem。

- `Path("/tmp/Report.pdf")` 与 `Path("/tmp/report.pdf")` 的 identity 不相等（行 1825-1827）

测试 `test_filing_distinct_same_basename_and_same_stem_paths_are_accepted`（行 1857）确认不同目录同 basename、同 stem 不同 suffix 不被误判。

### Single/multi/delete contract

| 场景 | files | selectors | 结果 |
|---|---|---|---|
| delete 合法 | `()` | `()` | `for_delete()` |
| delete + files | `(x,)` | `()` | `FILES_NOT_ALLOWED_FOR_DELETE` |
| delete + primary | `()` | `(x,)` | `PRIMARY_NOT_ALLOWED_FOR_DELETE` |
| single 无 selector | `(x,)` | `()` | 隐式选择 x 为 primary |
| single 匹配 selector | `(x,)` | `(x,)` | 显式选择 x 为 primary |
| single 不匹配 selector | `(x,)` | `(y,)` | `PRIMARY_NOT_IN_FILES` |
| multi 无 selector | `(x,y)` | `()` | `MISSING_MULTI_FILE_PRIMARY` |
| multi 单 selector | `(x,y)` | `(x,)` | 显式选择 x 为 primary |
| multi 重复 selector | `(x,y)` | `(x,x)` | `MULTIPLE_PRIMARY_SELECTORS` |

`_select_fins_upload_filing_files`（ingestion_runtime.py:997-1036）的逻辑：
- 行 1018-1019：`len(primary_selectors) > 1` → `MULTIPLE_PRIMARY_SELECTORS`
- 行 1020-1021：`len(files) > 1 and not primary_selectors` → `MISSING_MULTI_FILE_PRIMARY`
- 行 1023-1026：有 selector 取 `primary_selectors[0]`，无 selector 取 `next(iter(files))`
- 行 1029-1030：`primary_identity not in file_identities` → `PRIMARY_NOT_IN_FILES`

所有场景均有对应测试覆盖。
