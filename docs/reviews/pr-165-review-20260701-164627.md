## Findings

### 01-未修复-低-_abandon_cancelled_wait 中 adapter.abandon_wait() 成功后 lifecycle gate 关闭导致 durable mark 被跳过

- **入口/函数**: `_abandon_cancelled_wait` (wait_adapter.py:867-934)
- **文件(行号)**: `dayu/host/wait_adapter.py:900-927`
- **输入场景**: Poller 取得 cancelled wait 的 claim，调用 `adapter.abandon_wait(record)` 成功执行外部 abandon。在 `adapter.abandon_wait()` 返回之后、`_MarkWaitRecordAbandonedOperation` 执行之前，`close()` 被调用，lifecycle gate 关闭。
- **实际分支**: 第 900 行 `adapter.abandon_wait(record)` 成功返回 → 第 921 行 `if self._lifecycle_gate.is_closed():` 为 True → 第 922 行 `return 0, 0, self._release_shutdown_skipped(record, claim_id), 1` → 跳过第 924-934 行的 `_MarkWaitRecordAbandonedOperation`。
- **预期行为**: 外部 abandon 已成功，但 durable `poll_abandoned_at` 未被写入。下一轮 poller 实例会重新 claim 此 cancelled wait（因为 `poll_abandoned_at IS NULL`）并再次调用 `adapter.abandon_wait()`，造成 double-abandon。
- **实际行为**: Wait 保持 `CANCELLED` + `poll_abandoned_at IS NULL`，claim 以 `SHUTDOWN_SKIPPED` 释放。功能上不会导致 wait 卡住或数据损坏，但外部系统收到重复 abandon 调用。
- **直接证据**: 
  1. 第 900 行 `adapter.abandon_wait(record)` — 外部调用成功，无返回值
  2. 第 921-922 行 — post-abandon gate check，skip durable mark
  3. `WaitPollAdapter.abandon_wait()` protocol（第 119 行）— 无返回值，未定义 idempotency 保证
  4. Plan 第 3063 行 — "If close begins after adapter returns but before resolve_wait, skip resolve, release the claim as shutdown_skipped, and let a later opener retry." — 未单独讨论 abandon 场景
- **影响**: 外部系统收到重复 abandon 调用。`WaitPollAdapter` Protocol 未承诺 abandon idempotency，这取决于具体 adapter 实现。若 adapter 对外部 abandon 做了幂等实现则无功能影响；若外部系统对重复 cancel 敏感，可能产生告警或错误。
- **建议改法和验证点**: 两种方向：(a) 接受当前行为，在 plan/design doc 中明确标注 abandon 的 best-effort 语义和 double-abandon 可能性；(b) 调整 `_abandon_cancelled_wait` 的 gate check 顺序：在 `abandon_wait()` 成功后，优先完成 durable mark 再检查 gate（即把第 921 行的 gate check 移到第 900 行之前，或干脆删除 post-abandon gate check，让 durable mark 在 gate 关闭后仍可提交）。方向 (b) 的风险是 close drain 时间略增（多等一个 write transaction），但避免了 double-abandon。
- **修复风险（低）**: 方向 (a) 零代码变更；方向 (b) 微调控制流，需更新 `test_close_before_resolve_skips_result_and_leaves_wait_retryable` 覆盖 cancelled+abandon+close 竞态。
- **严重程度（低）**: 不影响正确性（wait 状态不变、无数据损坏），仅涉及外部 adapter 调用语义的边界条件。是 plan 已知的 shutdown-during-adapter 设计 trade-off 的 abandon 特化。
