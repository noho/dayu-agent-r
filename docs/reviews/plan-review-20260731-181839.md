## Findings

### PR-001-未修复-高-custom action 仍拿不到顶层 per-parse selector list
- **位置**: 修订 plan `Logging public selector and runtime admission` 第 135-142 行；S5 第
  265-268 行；fix artifact PR-001 第 14-19 行
- **问题类型**: 契约缺失 / 不可直接实施 / 状态所有权错误
- **当前写法**: 修订方案用 `_RecordLogSelectorAction(argparse.Action)` 代替 built-in append，
  并声称该 action 会把每个 scope 的 occurrence 原地追加到
  `_new_default_namespace()` 创建的 `ParsedCliArgs._log_level_selectors`。
- **反例/失败场景**: argparse 的 `_SubParsersAction` 会用新的 subnamespace 解析 command 参数，
  再把 subnamespace 字段复制回顶层 namespace。最小 custom-action 实验中，root action 收到带
  `xs=[]` 的顶层 namespace 并追加 `debug`；subparser action 收到只含 `x='x'` 的新 namespace，
  看不到顶层 `xs`，只能新建 `['info']`。最终结果仍是 `xs=['info']`，原始 per-parse list 则是
  `['debug']`。
- **为什么有问题**: 把 built-in append 换成 custom action 并没有改变 subparser namespace
  isolation。只要所有 scope 继续使用同一 dest，subparser merge 就仍会覆盖 root occurrence；
  `--debug prompt x --info` 继续逃逸“最多一个 selector”检查。fix artifact 把这一项标为已修复，
  但缺少支持该结论的 parser 机制。
- **直接证据**: 本轮只读最小实验打印两个不同 namespace identity：root action 的 namespace 包含
  `{'xs': [], 'cmd': None}`，subparser action 的 namespace 只含 `{'x': 'x'}`；最终输出为
  `Namespace(xs=['info'], cmd='prompt', x='x')`，而顶层原 list 为 `['debug']`。当前生产 parser 在
  `dayu/cli/arg_parsing.py:193-210` 复用 parent 构造 root 与 command subparser，二级 action 还有
  第三层同类 merge。
- **影响**: implementation Agent 按 exact plan 无法生成正确代码；S5 会在新增跨 scope tests 才暴露
  设计失败，被迫在 implementation gate 重新设计。若为了让 action 访问同一个 list 而把 collector
  放进 action/parser mutable state，还会引入跨 parse 调用污染、并发/重入风险，与 plan 的 no-global
  collector 声明冲突。
- **建议改法和验证点**:
  - 修订为 scope-local occurrence ownership：root、command、二级 action 使用不同 typed dest，
    parse 完成后由公共 parser owner 合并这些 list，再做 count 与 quiet/debug-stream 校验。
  - 公开 option-to-canonical mapping 仍只保留一个 spec/source of truth；通过构建独立的
    scope-specific parent/action registrations 复用 spec，而不是复用同 dest/action instance。
  - 不使用 raw argv scan，不在 `argparse.Action` 或 parser 对象保存跨 parse mutable collector。
  - owner tests 除 value assertions 外，要连续复用同一个 parser 执行两次解析，证明 per-invocation
    隔离；覆盖 root+command 两种顺序与 `session resume` root/command/action 任意两层。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

- PR-003 保持 `dayu.runtime` 层中立；ordinary policy 与 stream admission 在单一 runtime source of
