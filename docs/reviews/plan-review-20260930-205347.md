## Findings

### 1-未修复-[中]-计划类型收敛未闭合：声明类型与冻结不动的计数/校验表达式不相容

- **状态**: accepted-candidate
- **位置**: plan「结果类型落地范围」第 2 条（DigestResult/DigestDocument 所在 bullet）与第 4 条（「schema 的顶层 JSON 仍以 `dict[str, JsonValue]`/Mapping 表达」）；对应 `docling_schema_regression._process_one` 的 new/base_counts 计数、`build_semantic_digests._build_one` 的 `closed_json` 行。
- **问题类型**: 契约缺失 / 不可直接实施（类型收敛未闭合）
- **当前写法**: 计划规定 schema 顶层 JSON 以 `dict[str, JsonValue]` 表达、计数字段与公式「不改」，digest 的 exported 以 `DigestDocument` TypedDict 表达、`closed_json` 行「保持」；cast 仅表述为「json.loads/第三方 `export_to_dict` 的类型边界」的局部手段。
- **反例/失败场景**: 实施 Agent 按计划原样落地类型并保持计数/校验行不动后，全量 pyright 必红：(a) schema `len(exported.get("texts", []))` 类表达式在 `dict[str, JsonValue]` 下报 `JsonValue` 不满足 `Sized`（new_counts/base_counts 共 6 处，schema:81-95）；(b) digest `_is_closed_json_value(exported)` 在 `exported: DigestDocument` 下报 TypedDict 不可赋给 `JsonValue`（digests:228）。此时 Agent 若用 `isinstance` 收窄改写计数（texts 为 null/非 list 时从「TypeError→error 折叠」静默变为 0 计数成功），运行行为被改而验收第 4/6 条固定样例不覆盖内容畸形输入，错误行为可带病通过。
- **为什么有问题**: 直接实测证据（见命令记录 #18/#20）表明计划声明的类型无法在不加计划未点名的 cast 的前提下通过计划自己的全量 pyright 门禁；「原计数/校验保持」与类型落地互相挤压，迫使实施者在冻结行上即兴选择，其中行为保持的唯一选项（运行无操作的 `cast`）虽可被第 4 条 cast 规则宽泛覆盖，但计划从未把该需要写出来，而行为改写选项也不被验收拦截。
- **直接证据**: 探针 `workspace/tmp/pr197-f3-review-probe/type_probe.py:20`（`len` 对 `dict[str, JsonValue]` 报 reportArgumentType）与 `type_probe2.py:47`（`DigestDocument` 传 `_is_closed_json_value` 报 reportArgumentType）；cast 变体与 `list[list[JsonValue]]` 行类型的 `len(grid[0])` 探针均 0 错误，证明最小修复可行且运行无操作。schema:81-95、digests:228、plan 第 167-170 行为对应计划/源码位置。
- **影响**: 实施 Agent 跑偏或生成行为漂移代码；返工；review 无法据现有验收断言区分 cast 与 isinstance 两种落地。
- **建议改法和验证点**: 在 plan 类型小节显式补两条：(1) schema `_process_one` 对 texts/tables/pictures 的计数取值处使用运行无操作的 `cast(list[JsonValue], …)`（或等价 Sized 视图），错误折叠语义不变；(2) `_is_closed_json_value(exported)` 调用处对 TypedDict 视图局部 `cast(JsonValue, exported)`，digest 的 grid 行类型声明为 `list[...]` 使 `len(grid[0])` 可表达。验收追加一条：畸形/为 null 的 texts 输入仍走既有 error 折叠（harness 已有 stub 通道，一行负例即可）。实施报告必须说明两处的实际落地方式。
- **修复风险（低）**: 仅 plan 文本级增补 + 无操作 cast；不改算法、不改验收框架。
- **严重程度（中）**: 命中计划自身 pyright 门禁，且存在未被验收拦截的行为改写诱因。
