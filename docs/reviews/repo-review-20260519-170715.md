- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

## Open Questions

1. **`CancellationToken.requested_at` 存废**: 当前 `dayu/contracts/cancellation.py` 中定义的 `requested_at()` 方法在整个 `dayu/` 中无任何调用点（仅协议定义和测试实现）。如果仅为 Host observer/audit 扩展预留，应在 docstring 中明确；如果确认无用，移除可减少协议实现负担。需与 Host 侧 observer 设计对齐。

2. **`ToolParametersSchema.required` 运行时校验**: 当前明确声明"调用方必须保证 required 中的字段名都来自 properties"，但无运行时守护。这是有意设计（信任发布方）还是应补充校验？

3. **`_DefaultLocalWorkerHandle.cancel()` 端到端取消**: 虽然 Engine 层有 15+ 个 CancellationToken 观察点，但 cancel() 作为 no-op 的设计是否满足所有取消场景（如 SSE stream 读取中被 cancel）？需确认 Engine 层的取消覆盖是否完整。
