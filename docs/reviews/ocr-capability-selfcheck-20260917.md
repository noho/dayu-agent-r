## 1. 自检方法

| 项 | 内容 |
|---|---|
| 测试件 | 全部自造、真值已知：① 干净渲染（中文 + 千分位 + 百分比 + 表格）② 模拟扫描件（52,000 噪点 + 旋转 1.8° + 高斯模糊 0.7）③ 传真件（1200→400→1200 往返缩放，1/3 分辨率）④ 扫描 PDF（纯图像、无文本层）⑤ 文本层 PDF ⑥ 5 页多页 PDF |

| 盲测结果 | 88 字符**逐字符零差异**；三种渲染读数完全一致 |

### 1.1 PDF 直读不可用（【程序化证据】，已独立复现）

`Read` 工具直读 PDF 恒定返回 `[Unsupported Document]`。复现脚本：`workspace/tmp/ocr-selfcheck/repro_unsupported_doc.sh`。

根因（三段证据）：

| # | 观测 | 排除项 |
|---|---|---|
| ① | 装 poppler 前/后、重启前/后四次读取结果完全一致；扫描件与文本层 PDF 均失败 | 与依赖缺失无关、与 session 状态无关 |
| ② | 同 session 内 `document` 块 → `input_tokens: 41`（20KB base64 PDF 若被摄入应上千）；模型**逐字引用** `"[Unsupported Document]"` | 端点把 document 块**静默替换为字面文本** |
| ③ | 同 session 内 `image` 块 → `input_tokens: 235`，模型**正确读出**图中数字 | 图像路径通，差别仅在**内容块类型** |

即：端点收到 `document` 块后返回 **HTTP 200**、无 error 字段，把该块替换为字面字符串。**失败模式是静默丢数据，不是报错。**

绕行路径（已验证）：`pdftoppm -png` 转图 → `Read` PNG。

## 2. 能力边界

### 2.1 能可靠做【目视定性观察】

- 判**存在性**：某行 / 某块 / 某表是否印在页面上
- 判**是/否**：画面是正常中文 / 乱码 / 豆腐块 / 空白
- 判**版面**：表格错位、串行、错列、截断
- 读清晰渲染的中文与数字（大字号）

### 2.2 不能做

- 给精确数值并**作为结论依据**
- 给 bbox / 坐标 / 置信度 —— **结构性不可能**：唯一输出通道是自然语言，物理上无法发射坐标或校准概率
- **自陈不确定性** —— 无法可靠区分「有把握」与「在猜」

### 2.3 定量依据

| 量 | 值 |
|---|---|
| 实测 | 88 字符 0 错误（n=1） |
| 单字符错误率 95% 上界（rule of three, 3/88） | **≈ 3.4%** |
| 推论：20 字符金额字段含 ≥1 处错误的概率 | **≈ 50%** |
| 读数**可复现性** | **未知** —— 同文件重读受 harness 缓存 + 自身记忆污染，无法自测；既不能声称稳定，也不能声称不稳定 |

> 统计力度弱是本次自检最主要的局限：n=1、88 字符，单次全对不足以支撑「可靠」。

## 3. 失败的边界条件

| 条件 | 实测阈值 / 表现 | 证据 |
|---|---|---|
| 分辨率 | 14px 字仍可读（**低于预期**）；更低未测 | 盲测通过 |
| 噪点 / 旋转 / 模糊 | 52,000 噪点 + 1.8° 旋转 + 0.7 模糊 仍可读 | 扫描件测试 |
| 缩放往返 | 1200→400→1200 仍可读 | 传真件测试 |
| ⚠️ **源图本身缺字形** | **会误判为「OCR 失败」** | 实测踩坑：夹具用无 CJK 字形的 Helvetica 渲染 → 画面为豆腐块，一度判为 OCR 失败。**目视「识别失败」必须先排除源图问题** |
| ⚠️ **前视污染** | **会「读」出期望值** | 本次亲身发生，已作废重做（见 §1） |
| ⚠️ **图像通道可用性不稳定** | 见 §5.1 | 本 session 可用；`visual-verification-ds-20260917.md` 记载另一 session 对 PNG/JPEG 多档尺寸一律 `[Unsupported Image]` |
| 中文乱码判别 | **未单独测** | 是/否判断比逐字符读数粗粒度，预期更可靠 —— 但这是**推断，不是实测** |
| 长文档 / 多页 / 手写 / 印章 / 极低 DPI | **未测** | 不应假定可用 |

## 4. 派发要点

### 4.1 派发前必做

1. **先跑 `pdftotext -layout`**（poppler 已装，`/opt/homebrew/bin/`）。判定源 PDF 有无文本层：`pdffonts <file>` 有输出即有文本层。
   - 有文本层 → **Tier-0 程序化真源，可能直接消解该目视任务，无需派发**。
   - 无文本层（`pdftotext` 返回空）→ 才启用目视，且须配 Tier-0。
2. **探测图像通道**：派发时先让该 Agent 读一张已知内容的样图，确认通道可用（见 §5.1）。不可假定。
3. **核对受派资格**：确认受派 Agent **未读过该任务的任何含真值材料**（报告、diff、token 清单、既往结论）。
   不满足则**不派发**（约束 6）—— 否则产出的是「看起来独立、实际不独立」的证据。

### 4.2 派发给本 Agent 的操作要点

- **必须先转图**：`python utils/rasterize_pdf.py <pdf> --pages N --out-dir <dir>`，不得直读 PDF
- **300 DPI + 局部裁剪放大**，不要给整页缩略图 —— 首次读扫描件是在缩略图下「读对」的，但那不具备逐位把握
- 问题设计成**判别式**（有/无、A/B、正常/乱码），而非开放读数式
- **prompt 内不得写入真值**；真值落盘，待其给出读数后再对照

### 4.3 工具

```
python utils/rasterize_pdf.py <pdf>                          # 全部页，默认 300 DPI
python utils/rasterize_pdf.py <pdf> --pages 3                # 单页
python utils/rasterize_pdf.py <pdf> --pages 1,3-5            # 逗号 + 区间混用
python utils/rasterize_pdf.py <pdf> --pages 3 --out-dir /tmp/pages --dpi 150
```

输出 `<prefix>_p03.png`（页码两位补零、按页码升序），越界/非法表达式/缺依赖均以明确错误信息 + exit 2 退出。pyright: 0 errors。
