## Open Questions

- **Host -> Engine 依赖边界是否有 ADR？** 当前 Host 直接 import Engine contracts（AgentRunRequest、EngineEvent）和函数（run_agent_and_wait、run_agent_messages），这是有意为之的 execution boundary 还是待重构的技术债？`local_proxy.py` 也直接调用 `run_agent_messages`，与 `llm_compaction.py` 同源。
- **HostEventKind 是否应包含 LOST 成员？** RunStatus.LOST 和 AttemptStatus.LOST 在状态机中存在，但 HostEventKind 无对应成员。LOST Run 通过 watch_session_events 发出 PROGRESS 事件，消费方永远等不到 terminal event。
- **dispatch scheduler 的 `_active_tasks` 是否有最大并发数限制？** admission 层瞬间提交大量 dispatch 是否会导致 asyncio task 风暴？
- **llm_compaction 的 `asyncio.wait_for` timeout 后 Engine 侧 provider 请求是否被真正取消？** `_signal_timeout_cancellation` 只标记 Host token，Engine 不检查该 token 时 provider 请求继续消耗资源。
- **20ms 轮询间隔在生产环境是否可接受？** `_watch_session_events_after` 使用 `asyncio.sleep(0.02)` 无退避，空闲 session 每秒产生 ~50 次 SQLite 读取。

## Residual Risk

- `dayu/host/tool_runtime.py`（~48000 token）仅验证 import 边界，未完整走读内部逻辑。
- `dayu/host/wait_adapter.py` 和 `dayu/host/memory_repair.py` 仅读取头部，外部 job 轮询和增量更新逻辑未覆盖。
- compaction state machine 端到端路径（request → proposal → quality check → accept/reject → fallback）跨越 4 个模块，模块间隐式契约未做集成级验证。
- Host schema version 15 migration 路径未在本次审查范围内。
- `_watch_session_events_after` 轮询循环无空闲迭代上限；消费方取消或 host.close() 可终止，但无超时保护。
- `_execution_config_projection.py` 使用 RuntimeError（非 HostDurableError）处理 durable 数据损坏，调用方需同时 catch 两类异常。
- SQLite 单文件数据库在高并发写入场景下的吞吐瓶颈已通过 WAL 模式和 busy retry 缓解，但仍是架构固有限制。
- audit JSONL 幂等依赖文件扫描而非 durable 索引，长期运行后性能可能退化。
