## 关键观察

### 1. missing_merged 数字的性质分析

50 份样本中，14 份触发 `missing_many`（missing ≥ 5）。深度审查后发现：

- **单字符数字（0-9, 12, 31 等）**：出现频率极高，在 base/new 文本中大量分布。这类数字在 diff 中频繁出现于 delete/insert/replace 块，属于文本重组后的计数波动，非真实丢失。
- **节号引用（1.1, 2.1, 4.16 等）**：idx=40 全部 30 个 missing 数字均为节号，且**全部不在任何 diff 块中**。这些节号在 base/new 文本中均存在，仅因文本段落切分方式变化导致 merged 计数口径不同。纯计数伪影。
- **百分比数字（116.8%, 112.7% 等）**：idx=88 有 12 个百分比 missing 且不在 diff 块中。同样是文本切分导致的计数差异。
- **大额财务数字（12,325,470 / 3,255,971,250 等）**：idx=54/30 等样本中出现，但这些数字全部在 delete 块中，且 `moved_to_table_ratio=1.0`（real_delete=0），说明内容完整迁移到了表格。

### 2. real_delete 块的性质

`real_delete`（排除 moved_to_table 后的净删除）较大的样本（>500 字符）共 12 份，深度审查后分类：

- **释义/词汇表重组**（idx=8,32,70,76）：公司年报的释义章节被 docling 重新识别为结构化格式，文本从连续段落变为表格或清单，但内容语义完整。
- **OCR 伪影清理**（idx=62）：base 文本包含明显的 OCR 乱码（如 `1090881925080R28`, `НОЛА: 108 010-2022`, `208000180010`），新版本清理为正确的公司名称和报告标题。**这是修复。**
- **财务报表附注重排**（idx=14,68,84）：表格行列转置或附注段落合并导致的文本位移，数字保真无损。
- **少数民族文字/特殊字符文档**（idx=36）：包含藏文/蒙古文等特殊字符的文档，删除块主要是乱码字符序列，非业务内容。

## 退化样本清单

### 退化 1：idx=64 — 腾讯控股 2020 年报（轻微退化）

- **stem**: `fil_cn_ab7806e8aad1545f3143deac2a29bfded9c63e1f`
- **merged**: 5691 → 5760（+69，数字总量增加）
- **missing_merged (11)**: `0.23%, 30.00%, 151, 55, 396.24, 373.33, 0.27%, 1.52%, 1.08%, 2.07%, 31.00%`
- **added_merged (2)**: `00, 19`
- **tables**: 138 → 145（+7 tables, +72 rows）
- **real_delete**: 1318 字符
- **退化证据**:
  - 一个 157 字符的 delete 块（moved_ratio=0.0）包含股份期权估值参数：`於授出日期的加權平均股價 396.24 港元 / 373.33 港元 / 無風險利率 0.27%~1.52% / 預期波幅 30.00%~31.00%`。新版本将此段替换为财报附注标题，期权估值参数的**文本上下文丢失**。
  - 注意：这些数字（396.24, 373.33, 0.27%, 1.52% 等）在 replace 块中仍可追踪，说明它们并非完全消失，而是从解释性文本移到了表格数据中。
- **严重性**: 轻微。丢失的是估值参数的叙述性上下文（"於授出日期的加權平均股價"等说明文字），数字本身在表格中仍有保留。对 LLM 提取财务数字无实质影响。

- **added_merged (4)**: `31, 3, 12, 13`

## 判定口径观察

1. **moved_to_table_ratio 是关键判据**: 50 份样本中，大部分 delete 块的 moved_to_table_ratio ≥ 0.8，说明 docling 2.127 的核心变化是将文本块重新识别为表格。忽略此指标会严重误判丢失率。

2. **merged 口径的数字提取有噪音**: 单字符数字（0-9）、节号（1.1, 2.1）、百分比中的数字等会被重复计数。建议后续回归工具增加"业务数字"过滤（排除纯节号、页码、单字符数字）。

3. **不在 diff 块中的 missing 数字**: idx=40（全部 30 个）、idx=88（12/15 个）、idx=52（8/20 个）的 missing 数字不在任何 diff 块中。这些数字在 base 和 new 文本中都存在，仅因文本切分/正则差异导致 merged 计数不一致。**建议将此作为回归工具的已知误报模式记录。**

4. **OCR 伪影样本的处理**: idx=62 的 base 文本包含大量 OCR 乱码被错误识别为"数字"。这类样本的 missing_merged 应被视为修复而非退化。建议回归工具对"数字"增加合理性校验（如长度 >15 位的纯数字串标记为可疑）。

5. **偶数侧未发现数字保真退化**: 50 份样本中，没有发现真实财务数字丢失的案例。2 份退化样本均为轻微级别（丢失叙述性上下文，数字本身在表格中保留）。
