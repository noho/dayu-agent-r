## Reviewed Target and Scope

Re-review of the plan after adjudication fixed findings from AgentDS (`docs/reviews/plan-review-20260619-125333.md`) and AgentMiMo (`docs/reviews/plan-review-20260619-125457.md`). The plan proposes creating durable diagnostic artifacts for compact proposal attempts rejected before a proposal manifest exists, specifically when `material_pack -> compact input -> previous_compacted_view` parsing fails with `ValueError: previous reference continuity text is invalid`.

## User Calibration Focus Areas

1. **descriptor_kind 属于 payload_descriptors.metadata_json metadata 语义，除非必要不改 durable schema**
2. **raw block.text 只可进 Host diagnostic artifact，不可进 EventLog canonical payload 和 LLM-facing material**
3. **EventLog 小字段、payload_descriptors、artifact JSON 三者追踪链是否足以定位 operation_id / attempt_number / failure_stage / parser_or_validator / offending block / artifact ref**
4. **plan 是否存在过度设计、跨层耦合、事务/partial failure、测试缺口**

## Assumptions Tested

1. **A1**: `descriptor_kind` is metadata in `payload_descriptors.metadata_json`, not a durable schema change.
2. **A2**: Raw block text is confined to diagnostic artifact JSON, never enters EventLog canonical payload or LLM-facing material.
3. **A3**: The tracking chain (EventLog payload -> payload_descriptors -> artifact JSON) is sufficient for diagnosis.
4. **A4**: Transaction boundary is correctly handled by caller append helpers sharing the rejected EventLog transaction.
5. **A5**: `failure_stage` classification algorithm is deterministic and covers all failure paths.
6. **A6**: Tests cover artifact creation, descriptor metadata, EventLog redaction, artifact readback, best-effort failure, and null localization.
7. **A7**: Offending block detection logic is bounded by diagnostic-only scope and parser contract documentation.
8. **A8**: Both proactive and reactive append helpers are wired for diagnostic artifact persistence.

### F5-未修复-中-failure_stage 分类算法边界条件未明确

- **位置**: Contract / Schema / State-Machine Changes "Stage classification algorithm"
- **问题类型**: 契约缺失
- **当前写法**: Plan line 118-122 定义了分类算法：
  1. If safe exception message is exactly `previous reference continuity text is invalid` and at least one previous `REFERENCE_CONTINUITY` block exists, use `previous_compacted_view_parse`
  2. Else if `proposal_manifest_reference is None`, use `material_pack_to_compact_input`
  3. Else use `proposal_execution`

  代码实现 (`compaction_operation.py:1589-1619`) 完全匹配此算法。
- **反例/失败场景**: 如果 `_parse_previous_reference_continuity_text()` 的错误消息被修改（例如从 `"previous reference continuity text is invalid"` 变为 `"invalid reference continuity text"`），分类算法将回退到 `material_pack_to_compact_input`，而不是 `previous_compacted_view_parse`。这会导致诊断精度下降。
- **为什么有问题**: 分类算法依赖精确的异常消息字符串匹配。如果 parser 错误消息变化，诊断将回退到更宽泛的 stage。Plan 的 adjudication 已将此标记为 "parser-diagnostic mirror drift" residual risk（adjudication line 88），但 plan 本身未明确此边界条件。
- **直接证据**:
  - `compaction_operation.py:1603-1606`: `if exception_message == _PREVIOUS_REFERENCE_CONTINUITY_TEXT_INVALID and has_reference_blocks`
  - `compact_material.py` 中 `_parse_previous_reference_continuity_text()` 的错误消息可能变化
  - Adjudication line 88: "Parser-diagnostic mirror drift: assigned to later production parser/root-cause work if parser protocol changes."
- **影响**: 实施 Agent 可能认为分类算法是稳定的，但实际依赖 parser 错误消息的精确匹配。后续 parser 修复可能需要同步更新诊断逻辑。
- **建议改法和验证点**:
  1. 在 plan 中显式声明分类算法依赖 parser 错误消息的精确匹配
  2. 在 plan 中说明如果 parser 错误消息变化，诊断将回退到 `material_pack_to_compact_input`
  3. 在 test 中验证当前错误消息的精确匹配行为
- **修复风险（低）**: 补充 plan 文本说明
- **严重程度（中）**: 不影响当前正确性，但制造了未来必然漂移的技术债务
