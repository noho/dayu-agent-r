## Findings

### 01-未修复-[高]-FY facts 获取与“不重下摘要”是互相排斥的 repair contract

- **位置**：P3.3 `:116-123`、P3.5 `:145-149`、P4.4 `:196-198`、P5.3 `:244`。
- **问题类型**：契约缺失 / 状态机漏洞 / 目标漂移。
- **当前写法**：P3.3 要求所有 FY 准入 raw 在本地命中失败时 gate 内取得 PDF 并抽取 facts；P3.5 又规定任一 FY facts 不可确认就整次 discovery 失败。P4.4 对旧摘要 `REPAIR_REQUIRED` 写明“不重下摘要”，但没有说明 facts GET 是否算重下，也没有 durable full/summary kind 可在原始 PDF 不可读时判定其性质。
- **反例/失败场景**：一个 hidden summary 的原始 PDF/文件缺失或损坏，metadata 只保留 `fiscal_period=FY` 与索引标题（标题没有“摘要”）。要判断它是否应被 selection 排除，facts owner 必须重新 GET 原 PDF；但 P4.4/DS2 要求不重下摘要。若提前拒绝，又无法证明它是 summary；若继续 GET，则违反 literal no-redownload 约束。
- **为什么有问题**：这不是偏好问题，而是同一 source 的类型真源在 durable state 中缺失时，两个已确认要求无法同时满足。实施 Agent 会自行选择“GET 后丢弃”“直接拒绝”或写入未授权类型字段，导致网络成本、错误作用域和历史恢复承诺不一致。
- **直接证据**：`cninfo_downloader.py:299-304` 当前 discovery 在 raw/selection 后才返回结果；`P3.3:118` 明确不命中 local 就 gate 内 GET；`source_integrity.py:309-344` 只有 repair status，没有 full/summary kind；`P4.4:196` 又写“不重下摘要”。
- **影响**：可能重复下载被排除摘要、把损坏摘要误当 full、或在没有 facts 时伪造 selection；验收无法唯一判断 expected GET 集合，且 repair/历史恢复边界会被实现细节重新解释。
- **建议改法和验证点**：
  - 明确把“不重下摘要”限定为“不进入 repair commit/不覆盖/不删除”，并把 discovery facts GET 的允许集合写入 DS2/P4.4/P5.3；或明确唯一 repair source 在 facts 不可读时前置 typed fail，并说明为什么 selected repair 例外。
  - 若选择前者，测试断言损坏 unselected summary 的 facts GET 可发生但 source/company/旧 bytes 零改写，且不生成 accepted/rejected/repair；若选择后者，必须给出不依赖未持久 kind 的 selected/unselected 判定规则。
- **修复风险（低/中/高）**：高。
- **严重程度（低/中/高/严重）**：高。

### 02-未修复-[高]-publication mismatch 的 request abort 与 single-filing failure 没有唯一 owner

- **位置**：P4.2 `:175-177`、P4.3 `:181-185`、P5.2 `:232`、P5.3 `:245-248`。
- **问题类型**：状态机漏洞 / 契约缺失 / 失败作用域。
- **当前写法**：`CnDownloadAnnualPublicationError(CnDownloadFilingError)` 的 reason 同时包含 `source_identity_conflict`、`period_metadata_mismatch`、`source_document_facts_mismatch`；P4.2 要求 local publication witness mismatch “终止本请求并要求重新发起完整 discovery”，P4.3 又把 acquired/prepared/retry 的 year/kind mismatch 归为 filing safe failure。计划没有说明哪些 reason 在 workflow 里升级为 integrity abort，哪些只产生单 filing failed。
- **反例/失败场景**：local witness 与 A 期 target revision/source 不一致时，若实现沿现有 `run_cn_download_stream_impl` 的 generic `Exception` catch（`cn_download_workflow.py:404-424`），会记录该 filing failed 后继续处理其它 candidate，违反 P4.2“终止本请求”；反之若所有 facts mismatch 都 request-abort，prepared 单 candidate 的普通错误会扩大到整次请求，违反 P3.5 对普通 selected transport 的隔离边界。
- **为什么有问题**：同一 exception/reason 被两个不同生命周期消费，但 plan 没有 owner 级 transition、终态或 retry/rollback 规则。仅写“filing 唯一 projection”不能决定 workflow 是否继续，也不能保证 durable summary/CLI 与实际中止作用域一致。
- **直接证据**：计划 `P4.2:175-177` 与 `P4.3:181-185` 的 scope 文本；当前 workflow generic catch `cn_download_workflow.py:404-424` 会继续后续 candidate；`project_cn_filing_failure` 当前只按 `FinsDownloadProviderError`/`OSError`/generic 分类（`cn_download_filing_workflow.py:73-90`）。
- **影响**：可能在 publication churn 后继续用旧 facts 发布其它 source，或把单 candidate 的远端变化扩大为整次失败；测试的“零半成品/下一请求重新发现”无法稳定验收。
- **建议改法和验证点**：为三个 reason 明确 request-level/candidate-level transition 和 workflow catch/abort；把 local witness mismatch 与 acquired facts mismatch 分成不同 typed owner 或封闭 reason 组；补 P5.2/P5.3 的实际 `filings`、company/source/blob/processed mutation 和后续 candidate 行为断言。
- **修复风险（低/中/高）**：中。
- **严重程度（低/中/高/严重）**：高。

### 03-未修复-[中]-COMPLETE source 在 local witness 被过滤时仍可 metadata-only skip

- **位置**：P3.2 `:106-112`、P4.2 `:175-177`、P4.3 `:181`、P5.2 `:224-232`。
- **问题类型**：并发恢复风险 / 陈旧事实 / 契约缺失。
- **当前写法**：`_read_local_cn_annual_pdfs` 只读取 `source_provider=cninfo`、`ingest_method=download`、`fiscal_period=FY`、`is_deleted=False`、日期在 FY 有效窗且 `files[].source=original` 的 COMPLETE entry；无 local witness 时，A 期只要求 `_require_matching_cn_annual_publication(meta,candidate)` 的 identity/period 元数据相等就 COMPLETE skip。
- **反例/失败场景**：storage 当前 `_optional_role_text` 允许 `files[].source` 缺省而仍可形成 COMPLETE；或旧 meta 的 filing_date 不在本次 FY window。该 source 不进入 local tuple，downloader 取得远端 PDF facts；若同 source key 的远端内容在非 overwrite 下变为 full，而本地仍是 summary，A 期没有 witness/facts 可比较，可能按 metadata-only skip，保留旧 summary 却报告成功。
- **为什么有问题**：`SourceSnapshotFileDescriptor` 没有 source role（`repository_protocols.py:733-751`），而 `source_integrity._parse_declared_source_files` 对 role 缺省是合法 optional；plan 把 role/date 过滤当成“无本地事实”，却没有规定 COMPLETE target 必须有 witness 或显式 typed reject。`CnAnnualReportPublication` 只含 opaque revision，不携带 facts。
- **直接证据**：`_fs_source_integrity.py:696-705` 允许 source role optional；`source_integrity` 可返回 COMPLETE；`P3.2:108` 只读 eligible entry；`P4.2:175-177` 仅在有 `local_annual_publication` 时增加 revision 完整性断言。
- **影响**：同 source key 的旧 summary/full 混淆、远端变化被静默跳过、A/B/retry 无法发现事实漂移；会破坏“摘要不冒充全文”和 incremental correctness。
- **建议改法和验证点**：要求每个 CN FY COMPLETE target 在 selection/filing 前有同 revision witness 并重新执行 facts owner；或把 role/date 不满足的 COMPLETE 明确视为 typed conflict，不得 metadata-only skip。补 source role 缺省、日期漂移、同 key 远端 bytes 改变的 A/B/retry 矩阵。
- **修复风险（低/中/高）**：中。
- **严重程度（低/中/高/严重）**：中。
