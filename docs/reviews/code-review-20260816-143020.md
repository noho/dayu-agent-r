### 1-未修复-低-`_read_published_marker` 仍存在旧 meta 解析路径

- **入口/函数**: `_read_published_marker()` in `_fs_source_snapshot.py:945`
- **文件(行号)**: `_fs_source_snapshot.py:972-995`
- **输入场景**: full snapshot 的 marker retry 路径（`_read_source_snapshot` line 578 调用）
- **实际分支**: 通过 `_source_meta_path_for_read` 独立解析 identity descriptor 与 meta path，再通过 `_source_revision_from_meta` 读取 revision
- **预期行为**: 按 §6.1 设计，snapshot 应消费 inspection payload；marker retry 独立读取是设计选择，但 identity descriptor 缺失时应有 typed 处理
- **实际行为**: identity descriptor 缺失时 `_source_meta_path_for_read` 抛出 raw `ValueError("identity descriptor")`，不经过完整性分类
- **直接证据**: `_fs_source_snapshot.py:972` 调用 `core._source_meta_path_for_read(...)`，该方法内部调用 `_identity_directory_for_read` → `_read_identity_descriptor`，descriptor 缺失时抛 `ValueError`
- **影响**: marker retry 路径遇到 identity descriptor 缺失时抛出 raw ValueError 而非 typed UNSAFE classification。但这是预存行为（`_read_published_marker` 未在本次 diff 中修改），且主 snapshot 路径已通过 inspector 返回 UNSAFE
- **建议改法和验证点**: Slice 3 或后续 slice 中考虑让 marker retry 也走 inspector，或在 `_read_published_marker` 中 catch ValueError 并返回 None marker（触发 retry/consistency error）
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
