## Evidence-Based Review Summary

### Correctness

All 22 rule functions in `tool_trace_analysis_rules.py` (1749 lines) consume only source-owned typed signals from `ToolTraceAnalysisDataset`. No rule reads raw files, re-parses JSON, derives timestamps, infers provider identity, or falls back to indirect evidence.

- `_timing_results` (`:616-712`): reads `tool_timing.duration_ms` only when `status=available` AND `duration_source=tool_result_meta`. Missing/invalid timing → limitation, not finding. Dual threshold (median × multiplier AND absolute delta) correctly applied per plan §9.3.
- `_truncation_results` (`:715-844`): strict same-Run, greater-event-sequence, typed `tool_request.arguments.cursor == cursor_hint` matching. No regex on summary text.
- `_context_results` (`:864-955`): consumes `context_pressure.soft/hard_threshold_exceeded` booleans with explicit invalid-value detection; `USAGE_REPORTED` without pressure → limitation only.
- `_failure_findings` (`:534-580`): dispatches on `failure_metadata.failure_kind` string; `tool_failed`/`tool_cancelled` → Tool layer, `policy_blocked` → Host layer. All per plan §9.3.
- `_repeated_request_findings` (`:475-531`): groups by `(run_id, tool_name, normalized_arguments_digest)` — digest-based, not raw text.
