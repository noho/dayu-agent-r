## Findings

### 01-未修复-高-selected repair gate 可因 document identity 漂移而漏关闸并继续处理后续候选

- **入口/函数**: `dayu/fins/pipelines/cn_download_workflow.py::run_cn_download_stream_impl`
- **文件(行号)**: `dayu/fins/pipelines/cn_download_workflow.py:298`、`:309`、`:339`、`:342`、`:441`、`:442`、`:445`、`:494`、`:528`
- **输入场景**: final inventory 将来源 `S` 的既有文档 `D_old` 判为唯一 selected repair，并据此设置 `repair_document_id=D_old`。在该 preflight 与候选循环的新鲜 identity read 之间，另一写入者把 `D_old` 换成同一 `(provider, source_id)` 的 `D_new`，或删除旧绑定后建立新绑定。
- **实际分支**: 循环内重新读取 identity 后得到 `document_id=D_new`。`D_new != D_old`，因此 `:441` 的 repair gate 整段不执行。如果 `D_new` 的单 filing 失败，`:442` 的“失败即 break”也不执行，后续候选继续处理；末尾没有 `repair_gate_completed` 的终态校验，最终仍可发 `PIPELINE_COMPLETED`。
- **预期行为**: selected repair 的目标身份发生变化时，应按 publication identity drift 明确中止或重新做 final preflight；selected repair 失败必须终止 repair gate 和后续 candidate，只有 post-repair inventory clean 且 company publication 完成后才能正常完成。
- **直接证据**: `:309-319` 用 initial index 固化 `repair_document_id`；`:339-342` 为每个候选重新解析 document ID；`:441-494` 只在新 ID 恰好等于旧 ID 时执行失败拦截、复查和 company publish。现有 `test_cn_selected_repair_transport_failure_preserves_old_company_and_source`（`tests/fins/test_cn_download_workflow.py:3474`）及 top-level repair 测试均保持 identity 不变，没有覆盖该漂移分支。
- **影响**: repair gate 被绕过；selected repair 失败后仍可能提交后续 source，并产生“外部成功但 company side effect 未完成”或“修复失败后继续 tail mutation”的状态不一致。已提交前缀虽由 batch 保留，但 repair 所有权和成功语义被破坏。
- **建议改法和验证点**:
  - repair gate 不应只保存陈旧 `document_id`；至少同时保存 selected source key，并在每个 repair candidate 后按新鲜 identity/inventory 判定是否仍是同一 repair intent。
  - identity 从 `D_old` 漂移到 `D_new` 时抛 `SourceIntegrityRevisionConflictError` 或重新进入 typed final preflight，禁止静默跳过 gate。
  - 单 filing 失败时无条件终止 repair gate 和后续 candidate；正常完成前断言 fresh inventory 为 clean 且 `repair_gate_completed=True`。
  - 新增隔离测试：在 initial preflight 后替换 identity 绑定，分别注入 `D_new` 成功/失败，断言 typed 中止、零尾部写入、失败时不 publish company，成功时才允许 company/后续候选。
- **修复风险（低/中/高）**: 中。修改的是 workflow 的并发状态机和 repair 权限边界，需要同时保持普通 clean gate、已提交前缀和取消/rollback 语义。
- **严重程度（高/中/低/严重）**: 高
