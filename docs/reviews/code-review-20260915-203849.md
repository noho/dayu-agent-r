## Findings

### 1-低-根 README 对增量跳过原因的表述与真源契约不一致
- **裁决**: **rejected-with-reason（controller）**。
- **原 finding 摘要**: 认为 README"已缓存的正文可能拥有完整的本地文件，因此普通增量仍会跳过"把"文件可能完整"写成跳过原因，主张普通增量"无论文件是否齐全"都会 skip。
- **拒绝理由的直接代码证据（本 review 复核确认）**: 该主张与真源冲突——skip 分支门槛是 `phase_a_integrity.status is SourceIntegrityStatus.COMPLETE and not overwrite`（`cn_download_filing_workflow.py:190-192`），而 COMPLETE 是由仓储完整性分类器按落盘文件与 manifest 逐项核对后给出的（`_fs_source_integrity._inspect_source_kind_unguarded`）；文件损坏/缺失时分类为 `REPAIR_REQUIRED`，CN workflow 在 preflight 阶段经 `classify_source_integrity_preflight` 得到 `SelectedSourceRepairRequired` 后把 repair target 排到首位进入下载修复（`cn_download_workflow.py:227-243`），即**普通增量对文件不齐全的来源会自动 repair，而不是 skip**。因此 README"完整的本地文件"表述准确，且其后一句已区分文件获取与财表内容，无需改措辞。
- **复审结论**: 接受裁决。原 finding 的"无论文件是否齐全"表述是错的，予以撤回；README 维持现状。
