### 逐维度证据汇总

**1. ModelFamilyIdentity 四字段 owner/脱敏**

- Owner：`dayu.runtime.assembly.ModelFamilyIdentity` 是层中立 public type；`dayu.cli.init_catalog._validate_resolved_choice` 是唯一 consumer 兼校验 owner。
- `model_family_identity()` 从 `ModelConfig` 四字段（`provider`/`model`/`endpoint`/`api_key_ref`）投影到 identity 四字段（`provider`/`provider_model`/`endpoint`/`credential_ref`）。映射是 1:1 typed copy，无语义漂移（`assembly.py:275-288`）。
- Family mismatch 错误消息只报告 `ordinary_model_id`、`thinking_model_id` 和字段名列表（`mismatched_fields`），不回显字段值（`init_catalog.py:637-642`）。测试 `test_static_pair_family_mismatch_reports_only_ids_and_field_names` 以 sentinel 值验证脱敏（`test_init_catalog.py:837-874`）。
- `credential_ref` 的 `None` 比较正确：`None != None` → `False`（无 mismatch）；`None != "OPENAI_API_KEY"` → `True`（正确检测 mismatch）。

**2. 15 choice 含 dynamic Custom**

- `validate_init_catalog` 只 skip `CUSTOM_OPENAI`（package 中本就不存在该 record），不再 skip `OLLAMA`（package 中存在 template）。新增 Ollama 的 `_validate_resolved_choice` 调用对 same-model pair（ordinary==thinking=="ollama"）是恒真校验，无新增失败路径（`init_catalog.py:467-471`）。
- `apply_model_selection` 在 dynamic mutation 后同时调用 `_validate_dynamic_selection` 和 `_validate_resolved_choice`（`init_catalog.py:537`）。后者对 same-model pair 冗余但防御性正确。
- 静态 13 choice 均在 `validate_init_catalog` 中通过 `_validate_resolved_choice` 验证 family identity。

**3. Field retry 只捕 owner exception**

六个 retry loop 逐一验证：

| 函数 | 捕获类型 | 非 owner 错误处理 |
|------|---------|------------------|
| `_read_model_choice` (`init.py:508-523`) | `CliInitOperationError` | EOF→`CliInitOperationError` 透传；`KeyboardInterrupt`/`OSError` 不捕获 |
| `_read_dynamic_model_name` (`init.py:547-566`) | `InitCatalogError` | 同上 |
| `_read_dynamic_endpoint` (`init.py:569-588`) | `InitCatalogError` | 同上 |
| `_read_context_window` (`init.py:591-628`) | `CliInitOperationError`（自构造） | `_read_input` 的 EOF/`KeyboardInterrupt`/`OSError` 不捕获 |
| `_read_environment_persistence_entry` (`init.py:707-731`) | `EnvironmentPersistenceError` | `_read_secret_input` 的 EOF/`KeyboardInterrupt`/`OSError` 不捕获 |
| `_confirm` (`init.py:897-920`) | `CliInitOperationError`（自构造） | `KeyboardInterrupt`/`OSError` 不捕获 |

测试 `test_unexpected_input_os_error_is_not_retried`（`test_init_command.py:1654-1672`）显式验证 `OSError` 只触发一次 `input()` 调用即透传。

**4. EOF / SIGINT / confirmation exit**

- `_read_input`：EOF → `CliInitOperationError`（`init.py:934-935`）；`KeyboardInterrupt` 透传。
- `_confirm`：EOF → `CliInitOperationError("confirmation input ended before completion")`（`init.py:907-910`）；非法输入 → retry；`KeyboardInterrupt` 透传。
- `run_init_command` 顶层 except chain（`init.py:229-248`）：`KeyboardInterrupt` → `EXIT_KEYBOARD_INTERRUPT`；`CliInitOperationError` → `EXIT_FAILURE`。
- RESET EOF 行为变更（由 `EXIT_SUCCESS` → `EXIT_FAILURE`）是 plan 中明确的 intentional contract change，非回归。测试 `test_reset_eof_and_interrupt_map_to_failure_and_interrupt_without_mutation` 覆盖此 contract（`test_init_command.py:1401-1421`）。
- RESET 非法确认 → 同步骤 retry，Enter（空输入）仍按取消处理。测试 `test_reset_invalid_confirmation_retries_same_prompt_then_cancels` 覆盖（`test_init_command.py:1424-1449`）。

**5. 锁内 snapshot / mode 与 target profile source**

- `_load_target_min_context_window` 在 `file_lock` context manager 内、`_require_confirmed_snapshot` 之后调用（`init.py:164-167`）。锁内 mode 已确认，snapshot 已验。
- PRESERVE：`workspace_config_dir = workspace_root / "config"`，触发 `_load_layered_config_file` 的 workspace overlay。
- FIRST / OVERWRITE / RESET：`workspace_config_dir = None`，仅使用 package config。
- `ConfigLoader` 以 `_PACKAGE_CONFIG_ROOT` 为 package base，与 `validate_init_catalog` 的 loader 同源（`init.py:420-422`）。

**6. PRESERVE missing / invalid workspace profile layering**

- Missing：`_load_layered_config_file` 在 workspace 文件不存在时返回 package config（`config_loader.py:981-985`）。测试 `test_preserve_missing_workspace_profile_uses_package_layer` 覆盖（`test_init_command.py:1237-1261`）。
- Invalid（malformed / schema / default-id）：`ConfigLoadError` → `CliInitOperationError` with actionable message（`init.py:423-434`）。测试 `test_preserve_invalid_workspace_profile_fails_closed_without_fallback` 覆盖三种非法场景，验证：零 model prompt、零 profile mutation、durable state 保留、零 transaction 残留、敏感值不回显（`test_init_command.py:1264-1329`）。
- `workspace_profile_exists` flag 用于区分 error source（workspace vs package），在 `ConfigLoader` 之前通过文件存在性判定。与 `_load_layered_config_file` 内部的 `workspace_path.exists()` 检查语义一致。

**7. Profile failure 零 prompt / secret / transaction / publication**

- `_load_target_min_context_window` 在 `_select_model` 之前、`prepare_workspace_transaction` 之前调用（`init.py:164-172`）。
- 任何 `CliInitOperationError` 或 `OSError` 从 `_load_target_min_context_window` 抛出时：
  - `_select_model` 不会被调用 → 零 model prompt
  - `_collect_environment_persistence_plan` 不会被调用 → 零 secret 输入
  - `prepare_workspace_transaction` 不会被调用 → 零 staging
  - `publish_workspace_transaction` 不会被调用 → 零 publication
- 测试 `test_package_profile_failure_is_actionable_and_has_zero_publication`（`test_init_command.py:1332-1391`）：验证三种 package failure 场景下 `_select_model` mock 未被调用，workspace 零残留（无 `config/`、`.dayu/`、`transaction-*`），敏感值不回显。

**8. Context minimum 下传**

- 链路：`_load_target_min_context_window` → `profile.min_context_window_tokens` → `_select_model(min_context_window_tokens=...)` → `_read_context_window(..., minimum=...)`。
- Ollama：`default=defaults.context_window_tokens`（template 值），`minimum=min_context_window_tokens`（profile 值）。若 template default < profile minimum，用户按 Enter 接受 default 会触发 retry。
- Custom：`default=min_context_window_tokens`，`minimum=min_context_window_tokens`。default 即 minimum，用户按 Enter 直接接受 minimum。
- `_read_context_window` 的双重校验：先验正整数（`isdecimal` + `> 0`），再验 `>= minimum`。测试 `test_preserve_workspace_minimum_retries_low_dynamic_context` 验证 Ollama 和 Custom 两种 provider 的低值重试行为（`test_init_command.py:1175-1234`）。
- 测试 `test_locked_target_mode_loads_typed_profile_once_and_passes_minimum` 验证四态（FIRST/PRESERVE/OVERWRITE/RESET）下 `ConfigLoader` 调用次数=1、`workspace_config_dir` 正确传递、`_select_model` 收到正确的 `min_context_window_tokens`（`test_init_command.py:1026-1098`）。

**9. 测试是否以 mock 固化错误**

- Mock 使用审查：
  - `test_locked_target_mode_loads_typed_profile_once_and_passes_minimum`：mock `ConfigLoader` 以验证调用 contract，但 `typed_profiles` fixture 来自真实 `ConfigLoader` 加载。测试验证调用参数而非绕过行为。
  - `test_preserve_invalid_workspace_profile_fails_closed_without_fallback` / `test_package_profile_failure_is_actionable_and_has_zero_publication`：mock `_select_model` with `AssertionError` 以验证"不应到达"的防御性断言。正确用法。
  - `test_unexpected_input_os_error_is_not_retried`：mock `input` with `OSError` 以验证错误传播。正确用法。
  - `test_invalid_choice_and_dynamic_fields_retry_in_original_steps` / `test_preserve_workspace_minimum_retries_low_dynamic_context`：integration 测试，通过 `cli_main.main` 走完整真实路径，无 mock 核心逻辑。
- 无测试将 mock 返回值固化到断言中形成"mock 驱动设计"。所有 mock 用于隔离外部依赖（`input`、`getpass`、`ConfigLoader` 构造）或验证防御性断言。
- 测试覆盖率报告：92%（per implementation artifact）。关键 fail-closed 路径（EOF、SIGINT、非法输入重试、profile 非法、敏感值脱敏）均有显式测试覆盖。

### 结构审查

- `ModelFamilyIdentity` 放置在 `dayu.runtime.assembly`，符合"层中立、运行期通用"的 `dayu.runtime` 定位。不依赖 `dayu.cli` / `dayu.engine` / `dayu.host` 等上层。
- `model_family_identity()` 是纯投影函数，不包含校验逻辑。校验逻辑由 `init_catalog._validate_resolved_choice` 唯一拥有。
- `validate_dynamic_model_name` / `validate_dynamic_endpoint` 作为 `init_catalog` 模块级 public 函数暴露，同时被 `init.py`（交互 retry loop）和 `OllamaModelSettings.__post_init__` / `CustomOpenAIModelSettings.__post_init__`（dataclass 构造校验）复用。单一真源，无重复实现。
- `_report_recoverable_input_error` 统一了所有 retry loop 的错误输出格式，接受 `CliInitOperationError | InitCatalogError | EnvironmentPersistenceError` 联合类型——覆盖了三个 owner 的 value-free exception。
- 删除的 `_read_non_empty_input` 和 `_read_positive_integer` 是通用 helper，被各自 owner 专用的 `_read_dynamic_model_name` / `_read_dynamic_endpoint` / `_read_context_window` 替代。新的专用函数各自只捕获对应 owner exception，符合 semantic ownership 原则。

## Residual Risk

1. **`_EXECUTION_PROFILES_FILE_NAME` 与 `ConfigLoader` 内部常量重复**：`init.py:74` 定义的 `_EXECUTION_PROFILES_FILE_NAME = "execution_profiles.json"` 与 `ConfigLoader._EXECUTION_PROFILES_FILE` 是同一字面量的两个副本。若未来 `ConfigLoader` 中文件名变更而 `init.py` 未同步，`_load_target_min_context_window` 中 `workspace_profile_exists` 的存在性检查会使用错误的文件名，导致 PRESERVE 模式下错误地将 workspace profile 错误归因为 package profile 错误（或反之）。当前两处值相同，风险仅存在于未来维护窗口。**建议**：`ConfigLoader` 可将该常量暴露为 public class attribute 或 module-level constant，`init.py` 直接引用。

2. **`validate_dynamic_endpoint` 对非数值 port 不做校验**：`urlsplit("https://example.com:abc/v1").port` 返回 `None`，跳过 `port <= 0` 检查。该 URL 在语法层面非法但被 validator 接受。实际连接时会由 HTTP client 报错，不会静默失败。影响范围：仅影响用户输入非法 port 字符串时的交互体验（错误从 init 阶段推迟到首次 Engine 调用时暴露）。严重程度极低。

3. **S3–S6 未实现**：当前 S2 已完成的 retry loop、family identity、profile minimum 下传和 fail-closed 边界为后续 slice 奠定了基础，但完整 init interaction state machine 的剩余部分（如 workspace transaction 内部的 model/manifest projection 校验强化、environment persistence 的 platform-specific edge cases、smoke validation）尚未在本 slice 中覆盖。这些是 plan 中明确分配给 S3–S6 的工作，非 S2 遗漏。

4. **`_confirm` EOF 语义变更的调用方影响**：`_confirm` 从"EOF = default no"改为"EOF = failure"，影响两处调用：
   - `_confirm_reset`（RESET 确认）：EOF 从 EXIT_SUCCESS → EXIT_FAILURE。contract 已通过测试 `test_reset_eof_and_interrupt_map_to_failure_and_interrupt_without_mutation` 锁定。
   - `_collect_environment_persistence_plan`（environment 确认）：EOF 导致 `CliInitOperationError` 传播到 `run_init_command` 顶层 except chain → `EXIT_FAILURE`。此时 `prepare_workspace_transaction` 尚未调用，无残留 staging。行为正确但调用方需知晓此 contract 变更。
