### 1-未修复-中-post-repair 窗口的 revision conflict 与非 typed commit 失败仍裸逃逸归零
- **位置**: S1 正文 post-repair 段「在 post-repair gate 周围专设 typed catch…所抛的同一 `SourceIntegrityPreflightError`…company gate 失败由原 typed 异常承载」；残余风险段（sibling 延期、未知 mid-stream 不守恒两条）。
- **问题类型**: 契约缺失 / 状态机漏洞
- **当前写法**: fix3 只把 `SourceIntegrityPreflightError` 收进 workflow 私有快照 abort；`SourceIntegrityRevisionConflictError` 按 sibling 延期不纳入，`commit_batch` 只提「包括其 `commit_batch`」的同一 typed 异常。
- **反例/失败场景**: repair filing 成功提交（`filings` 已有唯一 `downloaded` 行、来源已发布）后，post-repair `classify_source_integrity_preflight` 因两次分类间外部并发修改仍返回 `SelectedSourceRepairRequired`，`cn_download_workflow.py:341-342` 按设计 `raise SourceIntegrityRevisionConflictError`——该异常不是 `SourceIntegrityPreflightError`，不在新 catch 内，裸越 collector → producer 走 `_empty_download_summary_from_request`（`ingestion_runtime.py:4309-4323`）→ RESULT 全零摘要，已发布 repair filing 从结果中消失。同类：company `commit_batch` 对「descriptor+未声明条目」形状在 `_validate_complete_source_kind_tree` 抛 **ValueError** 而非 typed（`_fs_storage_infra.py:1136-1145`），以及「`COMMITTED` 后 publication release failure 不回滚 durable tree」的非 typed 抛错（`commit_batch` docstring）——都从同一窗口裸逃逸归零。
- **为什么有问题**: 这与 F02 被 accepted 的理由同构——F02 明确拒绝「保留 raw 透传与零摘要」，理由是「小概率 post-repair 窗口也不能保留已知不一致」；`:342` 是设计路径而非未知异常，其归零违反 AGENTS.md「durable state 与同一业务事实必须同源一致」。sibling 延期裁决管的是公开业务分类/提示，不管守恒；plan 既未收口也未把该归零登记为残余，实施与 code re-review 无从判定这是有意边界还是漏网。
- **直接证据**: `cn_download_workflow.py:332-355`（gate 在单 filing try 外，`:341-342` 设计 raise）、`ingestion_runtime.py:4309-4323`（异常路径零摘要）、`_fs_storage_infra.py:1120-1145`（commit ValueError 面）与 `:534-566`（pre-commit 回滚/post-commit 不回滚语义）；plan 第 42、84、85 行原文；裁决 F02「不能保留已知不一致」。

- **建议改法和验证点**: 二选一：(a) 把同一私有快照 abort 扩展到 post-repair gate 窗口的 `SourceIntegrityRevisionConflictError`（携带原异常，公开分类仍由 Fins 唯一映射保持 EXECUTION/sibling 延期不变——守恒修复不等于分类修复）；(b) plan 显式登记「revision conflict 与非 typed commit 失败在该窗口仍归零」为残余并写明理由与跟踪去向。验证点：用 repair 配方真实触发——repair filing 成功后、post-repair classify 前损坏另一 selected source 使 classify 仍返回 `SelectedSourceRepairRequired`，断言 RESULT 保留已完成行（(a) 方案）或断言残余登记与实现一致（(b) 方案）。

### 2-未修复-低-失败 RESULT 放宽谓词未钉死到 `reason_code` 非空，OSError→STORAGE 形状归属模糊

- **影响**: LLM-facing 输出可被误读；review 无从验收「投影可被无状态模型正确理解」。
