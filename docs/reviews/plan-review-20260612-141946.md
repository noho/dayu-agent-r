### Finding 1: Field-path helper 签名和路径拼接规则已明确

**状态**: ✅ 已修复

**证据**:

Plan Implementation Decisions #5 (lines 169-178) 现在明确定义了：

1. **路径拼接函数签名**:
   - `_field_path(parent: str, key: str) -> str`: `parent == ""` 时返回 `key`，否则返回 `f"{parent}.{key}"`
   - `_item_path(parent: str, index: int) -> str`: 返回 `f"{parent}[{index}]"`；调用方必须传入非空 array field path

2. **Helper 签名示例**（全部含 `parent_path: str` keyword-only 参数）:
   - `_required_value(source: Mapping[str, JsonValue], key: str, *, parent_path: str) -> JsonValue`
   - `_required_string(source: Mapping[str, JsonValue], key: str, *, parent_path: str) -> str`
   - `_required_array(source: Mapping[str, JsonValue], key: str, *, parent_path: str, max_items: int) -> tuple[JsonValue, ...]`
   - `_optional_non_negative_int(source: Mapping[str, JsonValue], key: str, *, parent_path: str) -> int | None`
   - `_required_enum(source: Mapping[str, JsonValue], key: str, *, parent_path: str, allowed_values: frozenset[str]) -> str`

3. **Error message 要求**: 必须使用 `_field_path(...)` 或 `_item_path(...)` 产出的完整路径，不能只用 leaf key。稳定测试示例包括 `evidence_backed_facts[0].evidence_kind` 和 `answer_anchors[0].anchor_items[1].ordinal`。

**与原始 finding 对比**: 原始 finding（DS F-01）指出 plan "未定义 helper 签名规范"和"field_path 组合机制的设计决策留给了实现 Agent"。当前 plan 已消除这两个缺口：`_field_path` / `_item_path` 的 join 语义明确，helper 签名含 `parent_path` 参数，error message 要求使用完整路径。

**残留风险**: 无。签名和路径规则足以让 implementation agent 直接编码。

### Finding 4: json.loads 到 JsonValue 的类型收窄模式已具体化

**状态**: ✅ 已修复

**证据**:

Plan Implementation Decisions #4 (lines 163-168) 现在提供完整类型收窄模式：

1. **json.loads 边界**: "`parsed: JsonValue = json.loads(raw)` immediately after malformed JSON handling."
2. **Object 收窄**: "`_json_object(value: JsonValue, field_path: str) -> Mapping[str, JsonValue]` validates `isinstance(value, Mapping)` and every key is `str`; it returns only after the object boundary is proven."
3. **Array 收窄**: "Array helpers accept `JsonValue`, validate `Sequence` / list semantics without treating `str` as array, enforce max item count, and pass each item as `JsonValue` to item parsers."
4. **递归收窄**: "Recursive helpers use `isinstance` to narrow each concrete JSON member before returning `str`, `int`, tuple values, enum values, candidate dataclasses, or `None`."
5. **禁止弱类型**: "Do not use `Any`, `object`, `# type: ignore`, or broad `cast(...)` to skip validation. If pyright cannot narrow a value, add a smaller helper with a proven input/output type instead of weakening the type boundary."

Stop condition (line 254) 也具体: "If pyright requires introducing `Any`, `object`, untyped parameters, `# type: ignore`, or a broad `cast(...)` to make the parser type-check, stop and redesign the helper boundary instead of landing weak typing."

**与原始 finding 对比**: 原始 findings（MiMo F-03, DS F-04）指出 `json.loads` 返回 `Any` 的类型收窄路径未提供具体模式。当前 plan 已提供从 `JsonValue` 到 `Mapping[str, JsonValue]` 到具体类型的完整收窄链，且 `_json_object` helper 作为 object 边界守卫的具体实现模式。

**残留风险**: 无。模式足够具体，implementation agent 可以直接编码。
