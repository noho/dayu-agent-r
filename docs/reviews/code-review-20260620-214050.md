### 01-未修复-低-terminal 诊断后缀双 id 场景无测试覆盖

- **入口/函数**: `_append_terminal_diagnostic_suffix` / `_terminal_diagnostic_suffix`
- **文件(行号)**: `dayu/host/_terminal_diagnostics.py:40-66`
- **输入场景**: `provider_request_id` 和 `client_correlation_id` 同时为非空字符串
- **实际分支**: `parts` 列表包含两个元素，`"\n".join(parts)` 返回两行后缀
- **预期行为**: plan Decision 7 允许同时输出两个 id；实现正确渲染 `provider_request_id=...\nclient_correlation_id=...`
- **实际行为**: 实现正确，但无测试锁定该行为
- **直接证据**: `tests/host/test_read_api_terminal_policy.py:test_failed_terminal_projection_appends_correlation_suffix` 只测 `provider_request_id=None` + `client_correlation_id="client-fallback"` 场景；无测试传入两个非空 id
- **影响**: 后续重构可能意外改变双 id 输出格式而不被测试捕获
- **建议改法和验证点**: 在 `test_read_api_terminal_policy.py` 或 `_terminal_diagnostics.py` 对应测试中增加 `provider_request_id="req-1"` + `client_correlation_id="client-1"` 场景，断言后缀包含两行
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

### 02-未修复-低-message=None 时后缀无前导换行但 message 为空字符串时有前导换行

- **入口/函数**: `_append_terminal_diagnostic_suffix`
- **文件(行号)**: `dayu/host/_terminal_diagnostics.py:33-37`
- **输入场景**: `message=None` 且诊断 id 存在 vs `message=""` 且诊断 id 存在
- **实际分支**: `message=None` 时返回纯后缀（如 `"client_correlation_id=xxx"`）；`message=""` 时返回 `"\nclient_correlation_id=xxx"`
- **预期行为**: 两种场景下诊断后缀的格式应一致
- **实际行为**: `message=""` 场景会产生前导空行
- **直接证据**: `dayu/host/_terminal_diagnostics.py:36-37`：`if message is None: return suffix` vs `return f"{message}\n{suffix}"`
- **影响**: 真实 terminal payload 中 `message` 不太可能为空字符串（`optional_payload_text` 对空字符串抛 `HostDurableError`），实际风险极低
- **建议改法和验证点**: 可在 helper 中增加 `message == ""` 时返回纯后缀的防御；或确认上游保证不传入空字符串，保持现状
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
