### 02-未修复-中-`publishes_new_corpus` 由 `Path.exists()` 派生，EACCES/EIO 被折叠为 False，存在既有 corpus 被空 staging 树覆盖的窗口

- **入口/函数**: `_FsStorageInfra.begin_batch` / `_prepare_company_identity_commit`
- **文件(行号)**: `dayu/fins/storage/_fs_storage_infra.py:541`（`target_is_published = target_ticker_dir.exists() or target_ticker_dir.is_symlink()`）、`:553`（`publishes_new_corpus=not target_is_published`）、`:798-846`（intent 为 `None` 时 `_prepare_company_identity_commit` 不复核 target 存在性）
- **输入场景**: begin_batch 时 portfolio root 或 target 目录的 stat 因 EACCES/EIO 失败（Python `Path.exists()` 把 stat 失败折叠为 `False`），且该权限问题在 commit 前被修复（运维 chmod、NFS 瞬态错误等）
- **实际分支**: `target_is_published=False` → 走 `_ensure_ticker_structure` 构建**全新空 staging 树** → `publishes_new_corpus=True` → commit 走 identity 路径 → `_prepare_company_identity_commit` 无 intent 时不调用 `_read_current_company_meta_for_commit`，scan 发现 target 已存在且其 canonical == staged canonical，self-owner 匹配通过 → `_commit_batch_with_publication_guard` 中 `target_ticker_dir.exists()` 此时为 True → backup → swap
- **预期行为**: accepted plan §7.2 冻结 `publishes_new_corpus` 为 "begin_batch 确认 target 是否存在" 的 exact transaction-local fact；plan-rereview-2 adjudication F1 binding constraint 要求 identity 驱动的文件系统事实用显式 `os.lstat` 分型，permission/I/O 保留为 storage failure，不得被 `Path.exists()` 抹平。存在性事实误判时 commit 必须在 swap 前 fail closed。
- **实际行为**: 既有 corpus 被空 staging 树整体替换，corpus 全部文档丢失；冲突校验因 self-owner 匹配而通过，没有任何 fail-closed 拦截。
- **直接证据**: 行 541/553 使用 `Path.exists()`；`_prepare_company_identity_commit`（行 798-846）只在 `company_meta_intent is not None` 时读 target（行 822-823），`final_meta=None` 分支（meta-less 首发）对 target 无任何存在性/descriptor 复核；swap 前唯一校验是 scan 的 self-owner 匹配（行 838-846）。对比同文件 `_lstat_optional_storage_path`（行 1097-1121）正是为这类判定提供 `ENOENT→缺失、其它 OSError→失败` 的 helper，但 begin_batch 未使用。
- **影响**: 静默数据丢失（既有 corpus 被空树覆盖）。触发窗口窄（需要 stat 失败与 rename 成功的时间差），但后果严重且无审计轨迹；同时违反 F1 binding constraint 的实现机制。
- **建议改法和验证点**: `begin_batch` 的存在性判定改用 `_lstat_optional_storage_path(target_ticker_dir)`：`None` → 新 corpus；非 `None` 且非目录/symlink → 既有校验路径；`OSError` → 原样失败。补测试：monkeypatch `os.lstat` 在 begin_batch 时对 target 注入一次 EACCES，随后放行，断言 commit fail closed 或 staging 按既有 tree 复制，且 published tree SHA 不变。
- **修复风险（低）**: 单点替换 + 一个测试；不改变锁图与 merge 语义。
