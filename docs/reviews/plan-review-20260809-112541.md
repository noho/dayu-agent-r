## Assumptions tested

1. **Typed trigger exists.** Both relevant RunInput paths load an `ActiveRecentWindowFallback`; the plan does not need to infer fallback from missing Memory, refs, strings or message counts.
2. **Existing projection seam is sufficient.** Ordinary system messages already classify `Execution guidance:` and merge them into one deterministic envelope, so one additional private projection does not require a new renderer or contract.
3. **Normal paths can remain unchanged.** The additional message can be constructed only inside the existing `fallback is not None` branches.
4. **The instruction can remain business-readable.** It can describe unavailable earlier material and permitted evidence recovery without exposing compaction operations, tiers, Host facts or internal identifiers.
5. **No state-machine change is needed.** An honest insufficient-context final answer can still be a successful Run; parser, repair exhaustion and deterministic dispatch fallback remain independent.
6. **Generic prompt-only change is inferior.** `fact_rules.md` already has generic grounding rules, while the missing fact is specific to a Host-owned fallback selection. A global prompt edit would affect normal calls without communicating the direct trigger.

## Special lenses

- Goal-bound minimal design: one slice and one production owner; every change maps directly to the confirmed G06-5 behavior.
- Architecture boundary: Host produces a direct LLM-facing projection of its own typed fallback fact; no reverse dependency or UI/Service compensation.
- Best practice / optimal solution: explicit degraded-context guidance plus tool-based re-grounding or honest insufficiency is safer than silent inference, rejected-proposal reuse or an output heuristic.
- Overengineering: no schema, public type, new protocol, new renderer, validator or retry state.
- Overcoupling: the change reuses the existing system-envelope classifier and keeps provider/tool/Memory lifecycles independent.
