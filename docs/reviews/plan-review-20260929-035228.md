## Findings

### 01-未修复-低-tool schema「省略或 null 表示未提供」语句未限定 material 语境，共享参数上对 filing 不准确
- **位置**: 「最小实现契约与数据流」第 4 条（tool schema 描述）；「S1 测试契约」tool 段「断言 schema 对这些输入的说明准确」。
- **问题类型**: 契约缺失 / LLM-facing 文本准确性风险。
- **当前写法**: plan 逐字要求 schema 写出「省略该参数或传 `null` 表示未提供；空字符串或纯空白会被参数校验拒绝」，同条又要求「保持 filing 1000..9999 与必填规则」，但未说明该句必须落在 material 分句内。
- **反例/失败场景**: `fiscal_period`/`fiscal_year` 是 filing/material 共享参数。若实施者把该句作为参数级总述写入，LLM 在 filing 上传中按「省略表示未提供」省略 `fiscal_period`，将撞 `MISSING_FISCAL_PERIOD`（「--fiscal-period 不能为空」，`ingestion_runtime.py:1042`）——schema 对 filing 变成假陈述；而 S1 的「说明准确」断言只覆盖空串/纯空白输入，测不出语境错位。
- **为什么有问题**: AGENTS.md LLM-facing 硬约束要求 schema 自足且与真实行为一致，必填/可选边界是模型必须准确知道的判断规则；plan 指定的引文在其字面适用范围（共享参数）内不真。
- **直接证据**: `upload_tools.py:249-257` 现有描述已按「上传 filing 时…；上传 material 时…」分句；`ingestion_runtime.py:1040-1042` filing 必填错误存在；plan 第 4 条引文无语境限定。
- **影响**: LLM-facing schema 与真实行为局部不一致（违反硬约束），或验收测试放行错位文案。
- **建议改法和验证点**: plan 补一行：该句必须写在 material 分句内（如「上传 material 时可选，省略该参数或传 `null` 表示未提供，空字符串或纯空白会被参数校验拒绝」），并保留 filing 分句的必填陈述（filing 省略/null 仍是必填错误）；schema 断言同时覆盖 material 省略/空值语义与 filing 必填语义两句。
- **修复风险（低）**: 低——plan 一行措辞 + 一条断言。
- **严重程度（低/中/高/严重）**: 低
- **残余**: 修复后仍共享一段 description 承载两类入口规则，长期看 filing/material 拆参或分 schema 可彻底消除歧义，属后续演进，不属本项。

### 02-未修复-低-现有 schema 精确文本断言未点名为迁移对象，存在「改回 schema 迁就旧测试」的失败路径
- **位置**: 「最小实现契约与数据流」第 4 条（schema 变更）与「S1 测试契约」tool 段；对应既有测试 `tests/fins/test_fins_ingestion_tools.py:1718-1723`。
- **问题类型**: 测试缺口 / 不可直接实施（测试迁移未显式登记）。
- **当前写法**: plan 要求更新 schema 描述并「断言 schema 对这些输入的说明准确」，但未提及既有测试用 `==` 逐字钉死当前描述（`fiscal_year_schema["description"] == "财年。上传 filing 时必填，且只接受 1000..9999 的整数；上传 material 时可选。"`、`fiscal_period_schema["description"] == …`）。
- **反例/失败场景**: 实施者改完 schema 跑必测文件 `test_fins_ingestion_tools.py`，精确断言立刻失败；若实施者为保绿改回 schema 文本或缩小改动，F1 的 schema 自足要求落空且 review 难以对照验收。
- **为什么有问题**: CLAUDE.md 要求「测试必须跟着实现边界迁移，不得为了保住旧测试而在生产代码里堆兼容逻辑」；plan 应把这一迁移显式纳入 S1，否则失败处置方向无 plan 依据。
- **直接证据**: `tests/fins/test_fins_ingestion_tools.py:1718-1723` 精确文本断言；plan 文件白名单已含该测试文件，但测试契约未点名此断言组。
- **影响**: 实施 gate 返工或 schema 改动被测试倒逼缩水；review 验收面留歧义。
- **建议改法和验证点**: S1 测试契约补一句：同步迁移 `test_fins_ingestion_tools.py` 中 schema 描述的精确文本断言至新文案（含 finding 01 的两句语义），断言更新属于实现范围，不允许为保旧断言回退 schema；验证点为必测文件全绿且新断言逐字覆盖省略/`null`、空串/纯空白、material 域与 filing 必填语义。
- **修复风险（低）**: 低。
- **严重程度（低/中/高/严重）**: 低
- **残余**: 同类逐字断言模式在日期字段描述上也存在（`:1724-1731`，`filing_date`/`report_date` 文案与其 tool 实际 strip 行为的分歧已知），归 O11 WU 验收，不在本项扩散。
