### 路径 2: `dayu/cli/upload_script.py` — Windows batch renderer owner（WIN2-F02）

**调用链**：`render_upload_script(platform="windows")` → `_render_windows_script()` → 对每个 argv 调 `_quote_windows_batch_argument()` → 拼接 `f"{fixed} %*"` → CRLF 输出。

**核心算法**（`_quote_windows_batch_argument`，`upload_script.py:206-236`）：

```
输入: argument (原始 argv 元素)
输出: caret-protected、CRT-quoted 的 batch body token

1. 校验 NUL/CR/LF → fail-closed
2. 以 ^" 打开（batch caret 保护的双引号 → CRT 看到字面引号）
3. 逐字符遍历:
   - \: 累积 backslash_count
   - ": 写入 \* (2*backslash_count+1) + ^" → CRT 奇数反斜杠后引号是字面量
   - %: 先写入累积反斜杠，再写入 %% → batch percent doubling
   - &|()<>^: 先写入累积反斜杠，再写入 ^X → batch caret 保护
   - 普通字符: 先写入累积反斜杠，再写入字面字符
4. 以 \* (backslash_count*2) + ^" 关闭（偶数反斜杠后引号结束 CRT quoted region）
```

**batch phase ordering 走读**：

cmd.exe 解析 batch 文件的三个 phase：
- **Phase 1（Percent expansion）**：`%%` → `%`（在 `DisableDelayedExpansion` 下 `!VAR!` 不展开）。renderer 对 `%` 做 doubling 进入此 phase。
- **Phase 2（Special char processing）**：`^X` → 字面 `X`；`&|()<>` 在此 phase 作为命令分隔符/重定向。renderer 对 metacharacters 用 `^X` 转义，并已用 `^"` 包裹整个 token。此时 `^&` → `&`，但已在 CRT 引号内，对 cmd 不是分隔符。
- **Phase 3（Command execution）**：`cmd.exe` 调用 `CreateProcess`，后者调用 `CommandLineToArgvW`（CRT）。CRT 只解析 `"` 和 `\`，所有其他字符（包括 `&|()<>`）在引号内都是字面量。

**逐场景验证**：

| 场景 | 输入 | 渲染 | batch Phase 1-2 后 | CRT 后 |
|---|---|---|---|---|
| 空串 | `""` | `^"^"` | `""` | `""` (空) |
| 普通文本 | `hello` | `^"hello^"` | `"hello"` | `hello` |
| 空格 | `a b` | `^"a b^"` | `"a b"` | `a b` |
| 字面引号 | `a"b` | `^"a\^"b^"` | `"a\"b"` | `a"b` |
| 尾部反斜杠 | `a\` | `^"a\\^"` | `"a\\"` | `a\` |
| 百分号 | `%PATH%` | `^"%%PATH%%^"` | `"%PATH%"` | `%PATH%` |
| `&` | `&` | `^"^&^"` | `"&"` | `&` |
| `^` | `^` | `^"^^^"` | `"^"` | `^` |
| 组合 | `%PATH% ! & \| ^ ( ) < >` | 各字符按规则编码 | CRT quoted literal | 逐字恢复 |

**关键证据路径**（`test_windows_cmd_script_round_trips_adversarial_argv_with_real_cmd`）：

- subprocess 使用 `("cmd.exe", "/d", "/c", str(script), *appended)`，不用 `shell=True`。

**`%*` boundary 分析**：
- `%*` 在 batch Phase 1 展开为所有传入参数（字面量，保留原始引号）。`DisableDelayedExpansion` 防止 `!` 在 `%*` 内容中二次展开。

### 详细说明

以下每个挑战领域都经过了直接证据检查，未发现缺陷：

1. **cmd batch phase ordering 下 caret/percent/CRT 是否成立**：已验证。`_quote_windows_batch_argument` 的 caret 保护位于 batch Phase 2 之前生效（`^X` → 字面 `X`），percent doubling 位于 Phase 1（`%%` → `%`），CRT 引号规则在 Phase 3 后由 `CommandLineToArgvW` 完成。三个 phase 的编码层互不冲突：percent 用 doubling（不走 caret），quote/metacharacter 用 caret（不依赖 percent），CRT 反斜杠规则只与 `"` 交互，与 percent/caret 正交。

2. **literal quote 后元字符**：已验证。字面 `"` 编码为 `\*(2n+1) + ^"`（CRT 奇数反斜杠 + 字面引号）。`^"` 后的下一个字符重新开始：若为 metacharacter 则 `^X`，若为普通字符则直接写入。CRT 在奇数反斜杠后将后续 `"` 视为字面量，不改变 quote state，因此后续 `^&`（→ `&`）仍在 CRT 引号区域内，不会被 cmd 误解为命令分隔符。

3. **raw `%*` appended argv 边界与 injection**：已验证。`%*` 与固定参数之间有一个空格，CRT 将其视为独立的命令行 token。固定参数的 closing `^"` 确保 CRT quote state 在 `%*` 前正确关闭。`%*` 展开的内容是调用方命令行的字面量（在 `DisableDelayedExpansion` 下），其中 `!` 不被展开。如果调用方传入含 `&` 的未引用参数，`cmd.exe` 会在解析调用方命令行时将其解释为命令分隔符——这是调用方 shell 的标准行为，不在本脚本 renderer 的安全边界内。真实 Windows test 中 `appended` 含 `f"& type nul > {marker}"`，且 marker assertion 在 argv recovery assertion 之前——正确的 defense-in-depth。

4. **CLI TextIOWrapper owner/嵌入与错误行为**：已验证。`_configure_cli_standard_stream` 通过 `isinstance(stream, io.TextIOWrapper)` 精确识别 OS 流，使用 `reconfigure`（Python 3.7+ 的正确 API）。非 wrapper 流（`StringIO`、pytest capture）保持原样。异常直接透传，不吞错不降级。这是唯一 CLI process owner，位于所有输出之前。
