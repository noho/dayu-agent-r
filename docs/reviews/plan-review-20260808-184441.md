## 3. Findings

### 01-未修复-[高]-F19 run root 没有授权父目录锚点，且中间 symlink 可把 durable evidence 逃逸到 root 外

- **位置**: plan 第 37-48、110 行；driver `_validate_real_paths()` 第 817-871 行；`main()` 第 968、1008-1019 行。
- **问题类型**: 契约缺失 / 架构边界 / 数据损坏风险。
- **当前写法**: plan 承诺 root、所有组件 symlink、F18/outside parent 与同 basename wrong root 均在写入前拒绝。driver 要求 `run_id` 使用 F19 prefix、`resolved run_root.name == run_id`，并将 workspace/evidence/wrapper/controller 文件绑定到该 root 下的固定相对布局；它只对各路径的最终组件调用 `is_symlink()`。
- **反例/失败场景**:
  1. 在任意未授权父目录（包括结构上等价的 F18 private parent）下创建 basename 等于合法 F19 `run_id` 的目录和完整相对布局。当前 `_validate_real_paths()` 接受该 root，因为 contract 没有冻结或验证授权 root parent。
  2. 让 `<root>/evidence/private` 成为指向 root 外目录的 symlink，而 `controller` 与 chain 目录本身是普通目录。`controller.is_symlink()`、`chain_private.is_symlink()` 及所有最终 path `is_symlink()` 均为 false；`resolve()` 比较又会在 actual/expected 两边共同跟随该 symlink，因此校验接受，后续 projection/harness evidence 实际写入 root 外。
- **为什么有问题**: `run_root_id` 只证明 basename 文本，不证明目录归属；相对布局只证明路径彼此一致，不证明它们仍被授权 root 包含。`Path.resolve()` 后双方相等也不能证明 lexical ancestor 没有 symlink。由于 `main()` 在该 gate 之后先 `_emit()` 再 spawn，这不是展示层问题，而是 formal durable evidence 的写 owner 可污染 F18 或任意 outside tree，直接违反 fresh F19 root 与 F18 immutable contract。
- **直接证据**:
  - plan 第 46-48 行明确承诺固定布局及 F18/outside/component-symlink 写前拒绝。
  - driver 第 841-843 行只校验 resolved root basename；allocation/deadline 的 `run_root_id` 也只等于同一 `run_id` 字符串，没有授权 parent identity。
  - 第 861-870 行只比较 resolved paths，并只检查最终 path/controller/chain/workspace 节点是否 symlink，没有遍历从 root 到 leaf 的每个组件。
  - provider-free 临时 fixture 的实际结果为：arbitrary outside root **ACCEPTED**；synthetic F18-like parent 下的合法 basename root **ACCEPTED**；`evidence/private` 中间 symlink escape **ACCEPTED** 且 resolved evidence 位于 root 外。相对地，同 basename wrong workspace root 与显式 `..` 已正确拒绝。测试未执行 `_emit()`，候选 projection 不存在，未修改 F18。
- **影响**: F19/F18 evidence ownership 混淆、冻结失败证据被污染、execution index 指向非本 run durable state、publication/audit 不可验收；provider 启动后难以恢复。
- **建议改法和验证点**:
  1. Controller 在 allocation owner 中冻结一个可验证的授权 runs-parent identity（或 run-root canonical path digest/descriptor），driver 以该 owner fact校验 `run_root.parent`；单独的 basename/run_root_id 不足以区分 F18/outside。
  2. 在任何写入前，对既有 root、workspace、controller、chain-private 以及它们从授权 parent 开始的每个路径组件执行 no-symlink walk；同时校验每个 resolved leaf 可用 `relative_to(resolved_root)` 保持 containment。不要只比较共同 follow-symlink 后的 actual/expected。
  3. provider-free 回归必须直接覆盖：合法授权 root 通过；同 basename 的任意 outside/F18-like parent 失败；root parent、`workspaces`、`evidence`、`private` 任一中间 symlink 均失败；现有 final symlink、`..`、wrong chain/segment/layout 继续失败；并断言失败发生在 `_emit()`/spawn 前。
- **修复风险（低/中/高）**: 中。
- **严重程度（低/中/高/严重）**: 高。
