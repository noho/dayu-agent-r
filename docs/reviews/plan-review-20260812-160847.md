## 3. Regression Pass：关键挑战项验证

### 3.1 canonical CancellationToken 是否能由 direct/durable checker 完整且同源实现

**验证结论：可实施，plan 已描述扩展路径。**

- 当前 `_DirectCancellationChecker`（ingestion_runtime.py L1306-1328）只有 `__call__` 方法
- 当前 `_RuntimeJobCancellationChecker`（ingestion_runtime.py L1164-1189）也只有 `__call__` 方法
- plan §6.2 要求两者扩展实现 `CancellationToken` Protocol 的 `is_cancelled/cancel_reason/requested_at`
- direct 路径：`_DirectStreamCancellationState` 需扩展存储 `reason` 和 `requested_at`，同一 locked snapshot 供三个方法读取
- durable 路径：首次观察到取消时以固定 `job_cancel_requested` 为 reason，以 persisted cancelling record 的 `updated_at` 解析 requested-at
- **关键点**：`_DirectStreamCancellationState` 当前有 `_cancellation_requested: bool` 但没有 `reason`/`requested_at` 字段。plan §6.2 明确了扩展内容："同一 locked state 保存首次取消的 bool、reason、requested-at 和 terminal claim"
- S2 allowed changes 包含 `ingestion_runtime.py`（仅 cancellation input 方法/type wiring）

### 3.2 child normal-return failure descriptor 与 runtime wrapper 可实施性

**验证结论：可实施。**

- `InterruptibleProcessHandle` 的 `_run_process_target`（interruptible_process.py L621-641）：target 正常 return → `_ProcessCompleted(value=...)`；target 抛异常 → `_ProcessFailed(error_type=..., message=..., exitcode=1)`
- plan §7.1 要求 child target 在内部 try/catch 所有业务异常，写 failure descriptor 到 output file，然后**正常 return**（不抛异常）
- 这样 runtime 返回 `InterruptibleProcessCompleted`，父进程从 output file 读取 failure descriptor
- 只有 child 崩溃（queue 无消息、非零 exit、无 descriptor）才归 `CHILD_CRASH`
- **与 DS F04 一致性**：修订 plan 消除了 "runtime `InterruptibleProcessFailed` → `CHILD_CRASH`" 的文字歧义——只有无可信 descriptor 时才归 `CHILD_CRASH`

### 3.3 sync facade async wiring

**验证结论：可实施。**

- `CnPipeline.upload_filing()`（cn_pipeline.py L713）是同步方法，内部 `asyncio.run(self.upload_filing_stream(...))`
- `upload_filing_stream()` 是 async generator，内部调用 `self._upload_service.prepare_upload(...)`
- plan 把 `prepare_upload` 改为 async 后，`await prepare_upload(...)` 在 async stream 中自然工作
- `asyncio.run()` 在 sync facade 中创建私有 loop，service/converter 在该 loop 上 await
- converter 在该 loop 上 await `InterruptibleProcessHandle.wait()`

### 3.4 commit ownership transfer/helper 是否引入错误 owner 或重复 rollback

**验证结论：不引入。**

- plan §9.1 定义 module-level `commit_prepared_upload_batch` helper
- helper 接收 service、batching repository、caller-owned batch、prepared mutation 与 canonical token
- helper 对 cancel 或 precommit failure **恰好调用一次** `rollback_batch`
- service/workflow 不重复 rollback
- ownership transfer 后 caller 不再 rollback/read cancel

### 3.5 S1/S2 各自 green 且最终无兼容层

**验证结论：各自 green，无兼容层。**

- S1 只新增两个文件，不修改旧文件，既有 caller 不受影响
- S2 删除旧文件、迁移 caller、删除旧 symbol
- S2 completion condition 要求 `rg` 对旧 symbol 结果为零
- 不保留 re-export/wrapper/alias

### 3.6 DefaultFinsRuntime identity wiring

**验证结论：已明确。**

- plan §11.2 明确 `get_ingestion_runtime()` 在构造任何 pipeline **之前**创建单一 `ProcessDoclingConverter()`
- 按同一 identity 顺序注入：CN download adapter、HK download adapter、SecPipeline、CnPipeline
- CN download、HK download 与 CN/HK upload 保留三个独立 CnPipeline 实例，但共享同一 converter identity
- standalone 若参数为 `None` 默认构造同一 concrete class

### 3.7 production cleanup diagnostics 必要性、层内性与非测试 hook

**验证结论：必要、层内、非测试 hook。**

- plan §8.2 说 "shared owner 为真实运行诊断记录结构化 cleanup phase（不是测试开关或 public schema）"
- 记录在 `docling_process_converter.py` owner 内部
- 每条带 monotonic elapsed、PID/PGID、outcome，不带 input path/traceback
- 正常 production 也保留，测试不得增加 marker/event/sleep 触发
- UF-PF09 用这些 diagnostics 对齐 cleanup phase 时间线

### 3.8 status closed mapping 是否符合真实 production values

**验证结论：符合。**

- 当前 production 返回的 status 值：`uploaded`（SEC/CN workflow）、`skipped`、`deleted`、`failed`、`cancelled`
- plan §10.1 mapping：`ok` → `COMPLETED`、`skipped` → `COMPLETED`、`deleted` → `COMPLETED`、`failed` → `FAILED`、`cancelled` → `CANCELLED`
- plan 要求 workflow 把 `uploaded` 映射为 `ok`（"upload service 内部的 `uploaded` 只能在 SEC/CN workflow owner 处 exact 映射为 summary `ok`"）
- 当前测试 fake 直接构造 `status="uploaded"` 是偶然行为，应迁移到 `ok`

### 3.9 UF-PF09 sampler/5.05秒是否可执行

**验证结论：可执行。**

- `py-spy dump --pid` 在 macOS 上可能需要权限，plan 已说 "采样权限不足时证据无效/重跑"
- `/usr/bin/sample` 是 macOS 原生工具，不需要额外权限
- 5.05s = poll 0.05 + terminate 2.0 + kill 1.0 + 2.0s margin
- 冻结报告 UF-L02 HK PDF 在 SIGINT 后 31.78s 才退出（同步转换不可中断）；修复后应在 5.05s 内
- 2.0s margin 已包含 `asyncio.to_thread` 调度、process join 与 sampling/harness 收口抖动
