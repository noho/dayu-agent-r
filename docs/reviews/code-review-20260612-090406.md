### 审查项 2: `_MaterialPackShape`/`_VNextInputShape` helper 是否符合 plan 的 typed contract，无 Any/object/untyped ✓ PASS

**直接证据**:

`_MaterialPackShape(NamedTuple)`:
```python
class _MaterialPackShape(NamedTuple):
    previous_labels: tuple[str, ...]
    trace_labels: tuple[str, ...]
    evidence_labels: tuple[str, ...]
    answer_labels: tuple[str, ...]
    current_anchor_label: str
    citable_source_labels: tuple[str, ...]
```
- 所有字段均为具体类型（`tuple[str, ...]` 或 `str`），无 `Any`、`object`、无类型参数。
- 字段名与 plan 完全对齐（`previous_labels`、`trace_labels`、`evidence_labels`、`answer_labels`、`current_anchor_label`、`citable_source_labels`）。

`_VNextInputShape(NamedTuple)`:
```python
class _VNextInputShape(NamedTuple):
    top_level_keys: tuple[str, ...]
    previous_count: int
    trace_count: int
    evidence_count: int
    answer_count: int
    current_anchor_label: str
```
- 所有字段均为具体类型（`tuple[str, ...]`、`int`、`str`），无 `Any`、`object`、无类型参数。
- 字段名与 plan 完全对齐。

`_material_pack_shape(pack: CompactMaterialPack) -> _MaterialPackShape`:
- 参数类型为 `CompactMaterialPack`，返回值类型为 `_MaterialPackShape`。无 untyped。
- citable_source_labels 构造逻辑正确：从 `previous_compacted_view`、`trace_material`、`evidence_material`、`answer_material` 的 prompt-local labels 拼接，不含 `current_input_anchor`（anchor 不是 citable source）。

`_vnext_input_shape(vnext_input: ConversationCompactInputVNext) -> _VNextInputShape`:
- 参数类型为 `ConversationCompactInputVNext`，返回值类型为 `_VNextInputShape`。
- `previous_count` 计算覆盖五类 stable block：session_summary（计数 1 若存在）、evidence_backed_facts、answer_anchors、forward_intents、reference_continuity_items。`previous_view is None` 时 `previous_count = 0`。逻辑正确。
- 使用 `assert isinstance(vnext_json, dict)` 做运行时 guard，与 docstring `:raises AssertionError:` 一致。

`_assert_material_pack_shape` / `_assert_vnext_input_shape`:
- 参数全类型，返回 `None`。
- 失败消息包含 `expected!r` 与 `observed!r`，通过 NamedTuple 字段名区分 section。

**观察 2 (non-blocking)**: Plan 要求 assertion helpers "emit boundary-specific failure messages naming `previous_compacted_view`, `trace_material`, `evidence_material`, `answer_material`, `current_input_anchor`, `instruction`, `prompt-local label`, or `citable_source_labels` as appropriate." 当前失败消息为 `"material pack prompt-local label shape mismatch: expected=..., observed=..."` 和 `"vNext material section shape mismatch: expected=..., observed=..."`，消息文本本身未显式命名各 section。但 `_MaterialPackShape` 和 `_VNextInputShape` 的 NamedTuple `__repr__` 会按字段名展示每个 section 的值（例如 `previous_labels=()`, `trace_labels=('T1',)`, ...），因此失败输出实际上已定位到具体 section 边界。这是合理的实现折中——在消息字符串中硬编码 section 名反而会增加维护负担。可接受。

### 审查项 3: vNext top-level key/section count 断言是否正确，包括 schema_version 与 instruction ✓ PASS

**直接证据**:

模块级常量定义:
```python
_CURRENT_VNEXT_MATERIAL_KEYS = (
    "previous_compacted_view",
    "trace_material",
    "evidence_material",
    "answer_material",
    "current_input_anchor",
    "instruction",
)
_VNEXT_TOP_LEVEL_KEYS = ("schema_version", *_CURRENT_VNEXT_MATERIAL_KEYS)
```

- `_CURRENT_VNEXT_MATERIAL_KEYS` 包含 plan 要求的全部 6 个当前 material section key。与 `docs/host/design.md` 定义的当前 material sections 一致。
- `_VNEXT_TOP_LEVEL_KEYS` 在 6 个 material key 前加上 `schema_version`，共 7 个顶层 key。正确的——vNext JSON 确实包含 `schema_version` 字段。

`test_conversation_compact_input_vnext_maps_material_without_citable_current_anchor` 中的断言:
1. `_assert_vnext_input_shape(..., top_level_keys=_VNEXT_TOP_LEVEL_KEYS)` — 通过 `tuple(vnext_json)` 精确比对全部 7 个顶层 key，包括 `schema_version` 和 `instruction`。
2. `for key in _CURRENT_VNEXT_MATERIAL_KEYS: assert key in vnext_json` — 逐 key 检查 6 个 material key 均在 JSON 中，缺失时输出边界特定的 `"vNext material JSON missing current key: {key}"`。
3. 旧 key 排除断言保留：`"stable_input" not in vnext_json`、`"history_input" not in vnext_json`、`"evidence_input" not in vnext_json`。

`test_build_compact_material_pack_uses_explicit_previous_view_without_snapshot` 中的断言:
- 对 explicit previous view 路径做 `_assert_vnext_input_shape(..., top_level_keys=_VNEXT_TOP_LEVEL_KEYS, previous_count=1, ...)` — 验证 post-compaction 路径的 key/section count。

section count 验证:
- `test_conversation_compact_input_vnext_maps_material_without_citable_current_anchor`: `trace_count=1, evidence_count=1, answer_count=1, previous_count=0` — 初始 pack 无 previous view，各一个 material。
- `test_build_compact_material_pack_uses_explicit_previous_view_without_snapshot`: `previous_count=1, trace_count=1, evidence_count=0, answer_count=0` — explicit previous 为 session_summary block，trace 有一条 delta。

所有 top-level key 与 section count 断言正确，覆盖 `schema_version` 和 `instruction`。

### 审查项 4: evidence chunk / explicit previous view shape 断言是否提高可读性且不引入 brittle full JSON snapshot ✓ PASS

**直接证据**:

`test_single_large_evidence_block_is_chunked_under_same_provenance`:

无 full JSON snapshot 比较。所有新增断言均为语义 shape 摘要（label 结构、section count、key 存在性），提高边界失败可读性，不引入 brittle 金文件依赖。
