## 4. 重点压测记录（用户指定攻击面）

- **最小性**：机制集 = 复用源码根 `.venv` + `pip -e -c` + 单 launcher 普通文件 + 单 PATH block + 安装后检查，
  每项映射到 goal 的一条要求（裸命令命中、来源绑定、Windows 免 symlink 权限、新 shell 生效）。已比较
  uv tool（旧树冲突+新前提）、`pip --user`（解释器/PATH/保留入口无保证）并给出排除证据；pipx 类"第二托管
  环境"同属被排除类别，且会脱离仓库 `.venv` 这一既定安装目标。无未比较的明显更简标准机制。
- **Bash 编排与默认入口/PATH owner**：脚本 owner 限于安装编排、入口发布、有限 PATH block、核验与阶段退出；
  版本属 pyproject、metadata 属 pip/venv、CLI 解析属 pyproject console script target、secret block 属
  `init_environment.py`（独立 marker，顺序互保）。无层泄漏（不进 UI/Service/Host/Engine/runtime，不 import Dayu）。
  显式 `--shell bash|zsh` 避免"脚本是 Bash ≠ 用户 shell 是 Bash"误推 —— 符合 direction 的方向纠正。
- **安装目标与来源绑定**：目标固定为源码根 `.venv`；`-I` 源外 cwd 核验 purelib/platlib 的 dist-info
  Name/Version/entry point/`direct_url.json` editable+source；help 用真实 console script 退出码；
  §7 再以 HEAD==核收 OID + clean 指纹绑定 commit。链条完整，且声明 `direct_url` 不等于 commit 证明。
- **旧入口/缺席/重复/失败/保留用户文件**：§4.2 状态表（缺席/dangling/历史 symlink/人工 symlink/同字节幂等/
  未知形态拒绝）+ §4.4 失败与重执行语义 + §6.1 类别 2/4 + §6.2 legacy/repeat 场景与保全 manifest
  （不用 atime、不跟随树外链接）。替换只动目录项、不沿旧链接写目标，与"绝不打开真实旧 uv 树"一致。
- **新正常 shell 生效**：`-ic`/`-lic`、剥离 VIRTUAL_ENV/PYTHONPATH/PYTHONHOME、干净初始 PATH、
  外部命令断言（`whence -w`/`type -t`）+ 裸 `--help` 真实退出；非 TTY job-control stderr 保留说明。
  receipt.json 的四路 startup probe 仅被用作机制证据，计划未冒充安装验收 —— 符合"marker 不当真实安装验证"。

  metadata，且不把 wheel 段改成默认入口发布；README 禁写"三 OS 已验证"、禁写 gate/commit 指纹。已核对
  `__main__.py` 与只读 help 证据。方向指令"可指导修复即可"满足。

  与 authorization-update 最新授权逐字对齐。
