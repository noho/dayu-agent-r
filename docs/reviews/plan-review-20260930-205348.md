- **位置**: plan §结果类型落地范围 `DigestDocument/TokenDocument` 定义（"文本元素 text/label 保持现有 `str(...)` 消费的 `JsonValue`"，未指明 Required/NotRequired）；§各文件表 `_headings` 行（"只补类型"）；`VerifyResult` 段（"读取 digest 的输入投影仅描述 numbers.missing_merged/added_merged 数组"，未指明投影键必填性）。
- **问题类型**: 不可直接实施（code-generation-ready 缺口）/ 契约缺失。
- **当前写法**: plan 把元素级键的必填性留给实施，同时禁止改算法行、禁止 Any、禁止用 cast 消真实类型错误。

### 03-未修复-中-schema 顶层 JSON 的 `dict[str, JsonValue]`/Mapping 落法与现行 `len(...get())` 计数行不兼容

- **位置**: plan §结果类型落地范围末段："schema 的顶层 JSON 仍以 `dict[str, JsonValue]`/Mapping 表达，既有 closed-JSON 与 Docling 验证保持"。
- **问题类型**: 不可直接实施 / 最佳实践偏离（与同节自建的 TypedDict+cast 模式不一致）。
- **当前写法**: 字面落地即把 `exported`/`baseline` 标为 `Mapping[str, JsonValue]`。
- **反例/失败场景**: `docling_schema_regression.py:82-84,91-94` 的 `len(exported.get("texts", []))` 在该标注下报 `reportArgumentType`（`JsonValue` 不可赋给 `Sized`）。消红只能加 `isinstance` 收窄（改变 malformed 输入的现行行为：当前是 TypeError 折叠进 `error` 字段）或退回 Any（违反 plan"无 Any"）——两条路都违反 plan 自己的约束。
- **为什么有问题**: plan 同节已为 digest/verify 建了可行模式（document TypedDict 的 `NotRequired[list[...] | None]` 字段 + `json.loads`/`export_to_dict` 边界 cast），该模式对 schema 同样成立且零运行时变化；但这一句把 schema 指向另一条被实证不可行的路径，实施者会在门禁前才发现矛盾。
- **直接证据**: 本路 pyright 探针 exit1：`Argument of type "JsonValue" cannot be assigned to parameter "obj" of type "Sized" in function "len"`；`docling_schema_regression.py:82-84,91-94`。探针同时证实 `cast(DigestDocument, json.loads(...))` 边界与 `exported.get("texts") or []` + `isinstance` 模式在同检查模式下零报错。
- **影响**: 同 finding 02——实施被迫即兴设计，类型收敛在四个文件间发散的风险。
- **建议改法和验证点**: 改写该句为：schema 的 `exported`/baseline 同样以脚本本地 document TypedDict（`texts/tables/pictures: NotRequired[list[JsonValue] | None]`、`version` 可为 None 的 `JsonValue`）+ 边界 `cast` 表达；`Mapping[str, JsonValue]` 仅作为 `_is_closed_json_value` 的入参视图。验证点：pyright 0 errors；schema 计数/校验行零改动；malformed `texts`（非 list）仍按现行路径折叠为 `error` 而非新拒绝。
- **修复风险（低/中/高）**: 低。
- **严重程度（低/中/高/严重）**: 中。
