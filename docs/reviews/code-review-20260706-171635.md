### 2. idle Ctrl+C 修复：root cause 验证

**复现路径**（auto-validation artifact `docs/reviews/wu-cli-smoke-01-auto-validation-codex.md:99-108`）：
- `dayu-cli interactive` 到达 idle `dayu>` prompt 后，单次 Ctrl+C 使进程退出
- PTY probe 记录：`prompt_seen=True`, `exited_after_first_ctrl_c=True`, `decision=fail`

**root cause 定位**（`dayu/cli/commands/interactive.py:504-517`，改动前）：
- `_run_interactive_repl` 的 `while True` 循环中调用 `effective_composer.read(INTERACTIVE_INPUT_PROMPT)`
- composer 的 prompt-toolkit key binding（`dayu/cli/composer.py:117-124`）在空 draft 时通过 `event.app.exit(exception=KeyboardInterrupt)` 抛出 `KeyboardInterrupt`
- 改动前 `_run_interactive_repl` 只 catch 了 `EOFError`，未 catch `KeyboardInterrupt`
- `KeyboardInterrupt` 逃逸到 `run_interactive_command`（interactive.py:206），被映射为 `EXIT_KEYBOARD_INTERRUPT`（exit code 130）

**修复逻辑**（`dayu/cli/commands/interactive.py:504-517`，改动后）：
```python
idle_interrupt_exit_pending = False          # L504
try:
    while True:
        try:
            user_prompt = await effective_composer.read(INTERACTIVE_INPUT_PROMPT)
        except EOFError:
            idle_interrupt_exit_pending = False  # L510
            return EXIT_SUCCESS
        except KeyboardInterrupt:
            if idle_interrupt_exit_pending:      # L513
                return EXIT_KEYBOARD_INTERRUPT
            idle_interrupt_exit_pending = True   # L515
            continue                             # L516 → 下次 read 重绘 prompt
        idle_interrupt_exit_pending = False      # L517 → 正常输入重置
```

**状态机验证**：

| 当前状态 | 触发事件 | 下一状态 | 副作用 | 与 plan 契约对齐 |
|---|---|---|---|---|
| `False` (初始) | `KeyboardInterrupt` | `True` | `continue` → prompt 重绘，不退出 | ✓ plan: "first Ctrl+C records exit-pending, redisplays prompt" |
| `True` | `KeyboardInterrupt` | 终态 | `return EXIT_KEYBOARD_INTERRUPT` | ✓ plan: "second consecutive Ctrl+C exits" |

| `False` → `True` (`continue`) | — | `True` 保持 | prompt redisplay 不经过 L517 | ✓ plan: "prompt redisplay alone does not reset" |
