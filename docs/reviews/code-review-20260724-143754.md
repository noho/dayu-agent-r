## 新增 ValueError invariant 攻击

### 攻击目标：`_public_payload_measure` 的三条 `ValueError`

**1. `"cold-line measure requires matching cold record owner"`** (line 1039)

触发条件：`COLD_LINE` category 的 measure 在 `dataset.cold_records` 中找不到匹配 `(event_id, event_sequence)` 的记录。

判断：**安全**。`COLD_LINE` measure 的定义本身就是 cold JSONL record 的投影。若 cold record 不存在，dataset 处于内部不一致状态，fail closed 是正确的——不应为不存在的 record 伪造 evidence。

**2. `"resolved payload measure requires available hot store owner"`** (line 1056)

触发条件：非 `COLD_LINE` measure 但 `hot_store_available=False` 或 `hot_db_path is None`。

判断：**安全**。非 `COLD_LINE` measure 来自 hot snapshot resolver，resolver 只能在 hot store 可用时产出 verified bytes。若 resolver 产出了 measure 但 dataset 声称 hot 不可用，属于 dataset 内部不一致，fail closed 是正确的。

**3. `"resolved payload measure requires matching hot row owner"`** (line 1069)

触发条件：非 `COLD_LINE` measure 在 `dataset.hot_rows` 中找不到匹配 `(event_id, event_sequence)` 的 hot row。

判断：**安全**。artifact resolver 必须依赖具体 hot row 的 `payload_ref` 才能定位并验证 artifact。resolver 产出的 measure 必然对应一条已处理的 hot row。若 measure 存在但 hot row 不在 dataset 中，说明 dataset 构造有 bug（如 resolver 与 loader 使用了不同的 hot snapshot），fail closed 是正确的。

### 合法生产 dataset 攻击结论

三条 `ValueError` 均保护内部一致性不变量，不会拒绝合法生产 dataset。合法 dataset 中：
- 每个 `COLD_LINE` measure 必然有对应 cold record（均由 Slice 1 loader 从同一 JSONL 产生）
- 每个 resolved measure 必然有可用 hot store 与匹配 hot row（均由 Slice 1 resolver 在同一 hot snapshot 上产生）

若合法生产环境触发这些 ValueError，说明 Slice 1 的 dataset 构造存在 bug——这是正确的 fail-closed 防御，不应削弱。

### 裁决：无新增 actionable finding
