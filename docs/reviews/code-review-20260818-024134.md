### 001-未修复-低-canonical 测试 finally 起点在 run_next 之后，activate/run_next 抛异常路径不清理 observation

- **入口/函数**: `test_upload_tool_raw_period_is_canonical_at_runner_contract_boundary`
- **文件(行号)**: `tests/fins/test_fins_ingestion_tools.py:1501-1510`

- **实际分支**: `activate_observation`（1501）与 `run_next()`（1502）在 `try`（1503）之外；异常直接传播
- **预期行为**: adjudication 要求「在断言后 abandon/清理 observation」；测试结构上清理应覆盖激活与执行失败路径，而不是只在断言失败路径成立
- **实际行为**: try 未进入，`finally` 中 `abandon_observation`（1508-1509）不执行，observation record 留在 `_observations`，`:1510` 的清理断言也不会被执行
- **直接证据**: `test_fins_ingestion_tools.py:1501-1502` 位于 `:1503` 的 try 之前；abandon 只在 `:1508-1509` 的 finally 内。`activate_observation` 的 re-raise 语义见 `ingestion_runtime.py:3957-3975`
- **影响**: 当前路径下实际不可达：`_HoldingExecutor.submit` 只 append 不执行（`:791-809`）、`_run_direct_stream_producer` 以 `except Exception` 把 producer 异常收口为 failed RESULT（`ingestion_runtime.py:4301-4303`）、`_put_direct_queue` 声明 Raises: 无（`ingestion_runtime.py:6379-6394`）。runtime 为 test-local，未清理不跨测试污染。属测试结构防护缺口而非当前行为错误；若未来 executor/producer 行为变化，observation 泄漏将与测试失败同时出现，且掩盖真实失败现场
