### enum invalid value diagnostic 安全性

`_required_enum` 的 S2 变更（`llm_compaction.py:1108-1114`）：

1. **脱敏**：`redact_sensitive_diagnostic_values(value, redaction_marker="<redacted>")` 使用 `dayu.runtime.diagnostic_text` 的 Bearer token 和 assigned-secret 正则模式。虽然 enum 值本身不太可能包含 API key，但作为通用 `_required_enum` 的防御性设计是合理的。
2. **截断**：`truncate_diagnostic_text(..., max_chars=240, truncated_suffix="...")` 确保异常消息不会无限膨胀。240 字符对 enum 值诊断足够。
3. **信息保留**：错误消息包含 field path + redacted/truncated actual value，对 repair/retry 决策有足够信息量。
4. **异常类型不变**：仍然是 `ValueError`，被上层统一包装为 `LLMCompactionProposalError`。

安全性结论：脱敏和截断链路正确，不存在过度泄露风险。
