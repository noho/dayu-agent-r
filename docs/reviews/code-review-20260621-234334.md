## Residual Risk

- failed / cancelled outcome digest alignment 无独立 callback-vs-direct digest 单元测试。Controller 接受此为低 residual risk，因两路径调用同一纯函数，且现有 resolve_wait 测试覆盖 failed/cancelled 行为。
- stale check vs resolve 并发按 accepted Slice 1 设计处理：竞争坍缩进 common resolve pipeline 或 typed invalid-state result。
- header casing、重复 header、payload ref / provider status ref 更细粒度非法 shape 等低优先级测试缺口按 controller adjudication 归为后续 Web route hardening。
- `auth_source` 和 `credential_ref` 缺失时使用字面值 `"missing"` 作为 sentinel，通过 `WaitCallbackAuthInput.__post_init__` 的 non-empty 校验。此为设计选择：认证判断交给 authenticator，不在 transport 层误分类。如果 authenticator 实现未正确处理 "missing" sentinel，可能导致误接受，但当前 `_AcceptingAuthenticator` 测试替身不覆盖此路径；生产部署依赖真实 authenticator 实现。
- `_required_utc_datetime` 接受带 UTC 偏移的 ISO 8601 格式（如 `+00:00`），与 Host durable 的 `format_utc_timestamp`（写入 `Z` 格式）和 `parse_utc_timestamp`（仅接受 `Z` 格式）不同。Service mapper 的宽松解析不影响 Host durable 写入一致性，但如果外部系统发送 `+00:00` 格式而 Host 内部比较使用 `parse_utc_timestamp`，可能产生格式不一致。当前无实际风险，因 callback `observed_at`/`completed_at` 只用于 stale 比较和 audit，不进入 durable 写入。
