## Lock Graph Verification

```
begin_batch:     writer lock (per-ticker, held throughout)
commit_batch:
  ├─ publish_new_corpus or company_meta_intent:
  │   recovery lock → company identity lock → publication guard
  └─ otherwise:
      publication guard only
```

- 死锁安全：锁序全局固定，无逆序获取
- recovery lock 保护 orphan 恢复期间不被 identity scan 干扰
- identity lock 保护跨 corpus uniqueness scan 的原子性
- publication guard 保护 per-ticker physical swap 的互斥
- writer lock 保护同一 ticker 的 batch 生命周期

## Residual Risk

1. **UF-PF05 排除**: `CompanyMeta.from_dict` 的 `exchange` 字段通过 `build_company_ticker_identity` 从 canonical ticker 重新派生，而非持久化存储。当前 ticker grammar 确保 exchange 是 canonical ticker 的确定函数，所以 round-trip 正确。若未来 grammar 扩展导致 exchange 不再可从 canonical 唯一确定，需重新评估。
2. **identity route 每次扫描 workspace**: `resolve_company_ticker` 每次调用都全量扫描 published identities。当前 corpus 规模下性能无问题，但若 corpus 增长到数百个 ticker，可能需要增量 index。
3. **ACL/NFS 未跨平台验证**: `os.lstat` 在 Linux NFS 上的行为可能与 macOS APFS 不同（特别是 inode/nlink 语义），当前测试仅在 macOS 运行。
4. **material company-name admission 未扩展**: `UploadCompanyNameRequiredError` 仅在 filing `create/update` 时触发，material 上传不强制 company-name。这是 accepted plan 的显式非目标。
