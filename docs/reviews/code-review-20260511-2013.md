## Findings

### 1-已修复-中-`AgentRunRequest.stream` 是公共参数但执行路径完全不消费
- **Controller decision status**: accepted
- **Fix status**: fixed
- **Re-review status**: fixed
- **入口/函数**: `run_agent_messages(request)` -> `_AsyncAgent._run_runner_iteration(...)`
- **文件(行号)**: `dayu/engine/contracts/agent_run.py:59`, `dayu/engine/agent.py:916`, `dayu/engine/README.md:56`
- **输入场景**: 调用方构造 `AgentRunRequest(stream=False, runner_options=RunnerCallOptions(..., stream=True))`，期望关闭 Engine 事件流里的增量提升；或构造 `AgentRunRequest(stream=True, runner_options=RunnerCallOptions(..., stream=False))`，期望启用流式提升。
- **实际分支**: `_run_runner_iteration` 直接把 `self._request.runner_options` 传给 `self._runner.call(...)`，没有读取 `self._request.stream`，也没有校验它与 `runner_options.stream` 的关系。
- **预期行为**: 公共请求对象里的显式 `stream` 参数必须有单一、可追踪的生效链：要么作为 Engine 是否产出 `content_delta` / `reasoning_delta` 的真源，要么作为 Runner 请求 `stream` 的真源，要么从公共契约中移除，避免和 `RunnerCallOptions.stream` 构成双真源。
- **实际行为**: `AgentRunRequest.stream` 只存在于 dataclass 和文档中。Runner 请求是否流式只由 `RunnerCallOptions.stream` 决定；Engine 是否提升 delta 只取决于 Runner 实际产出的 `RunnerContentDeltaData` / `RunnerReasoningDeltaData`。
- **直接证据**: `AgentRunRequest` 声明 `stream: bool`，docstring 写明“是否启用流式提升”（`dayu/engine/contracts/agent_run.py:65`, `:80`）。`dayu/engine/README.md:56-70` 把 `stream` 列入唯一请求对象字段，并声明“Engine 消费这些字段完成单次 run”。但 `_run_runner_iteration` 在 `dayu/engine/agent.py:916-921` 只把 `self._request.runner_options` 传给 Runner；`rg` 在 Engine 执行代码中未找到 `request.stream` / `self._request.stream` 消费点。`build_request_payload` 最终写入 provider payload 的也是 `options.stream`（`dayu/engine/runners/openai/payload.py:328-332`）。
- **影响**: 调用方会得到与公共参数相反的行为：关闭 `request.stream` 仍可能收到 delta 事件和 SSE 请求，开启 `request.stream` 也可能因为 `runner_options.stream=False` 走非流式。这个问题属于 parameter effectiveness 缺陷，会让 Host / Service 在装配 run 时无法判断哪个字段是真源，后续测试也容易只覆盖默认两者同值的 happy path。
- **建议改法和验证点**: 按全新契约收敛为一个真源。更稳妥的方向是移除 `AgentRunRequest.stream`，只保留 `RunnerCallOptions.stream`；或者让 Agent 在入口处根据 `request.stream` 构造最终 `RunnerCallOptions`，并删除/禁止冲突来源。补测试覆盖两者冲突时的行为，验证最终 provider payload 和 EngineEvent delta 提升都符合真源字段。
- **修复风险（低/中/高）**: 中。需要调整公共契约、README 和构造请求的测试/调用点，但修复面清晰。
- **严重程度（低/中/高/严重）**: 中
- **Gateflow 回写**: 已删除 `AgentRunRequest.stream` 公共字段与相关构造参数，保留 `RunnerCallOptions.stream` 作为唯一流式控制真源；见 `docs/reviews/gateflow-fix-agent-run-request-stream-20260511.md` 与 `docs/reviews/gateflow-re-review-engine-contract-readme-20260511.md`。
