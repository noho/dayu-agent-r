### H-1-严重-Runner 取消路径绕过 HTTP response.release() 导致连接泄漏

- **入口/函数**: `AsyncOpenAIRunner._do_attempt()`
- **文件(行号)**: `dayu/engine/runners/openai/runner.py:424-514`
- **输入场景**: HTTP 响应已建立（`response_ctx.__aenter__()` 成功完成），但在进入内层 `try/finally` 之前，下一行的 `await_or_cancel()` 检测到 cancellation token 命中
- **实际分支**: `await_or_cancel()` 将 `WaitCancelled` 翻译为 `_RunnerInterrupted` 异常（`dayu/runtime/cancellation.py:153-154`）。外层 `except (aiohttp.ClientError, asyncio.TimeoutError)` 不捕获 `_RunnerInterrupted`，异常直接传播到 `_call_impl` 的外层 `except _RunnerInterrupted`
- **预期行为**: 应调用 `response.release()` 归还 aiohttp 连接到连接池
- **实际行为**: 内层 `try/finally`（第 439 行）从未进入，`response.release()`（第 514 行）从未执行，aiohttp `ClientResponse` 及底层 TCP 连接被泄露
- **直接证据**: 第 427-428 行 `await_or_cancel(response_ctx.__aenter__(), token=self._token)` 可抛出 `_RunnerInterrupted`；第 430 行 `except` 仅捕获 `aiohttp.ClientError, asyncio.TimeoutError`；第 439-514 行的 `try/finally` 在异常路径上不执行
- **影响**: 每次在 HTTP 响应建立后的瞬间取消，泄露一个 TCP 连接。连接池耗尽后后续请求阻塞或新建连接造成性能下降
- **建议改法和验证点**: 将 `response_ctx.__aenter__()` 移入内层 `try/finally` 范围，或在外层增加 `_RunnerInterrupted` 异常处理器执行 `response.release()`；验证：取消竞态压力测试，检查连接池是否泄漏
- **修复风险（中）**: 需要仔细处理 response 尚未建立时的 `_RunnerInterrupted`（此时 `release()` 不可调用）
- **严重程度（严重）**
