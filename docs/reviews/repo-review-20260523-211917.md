## Open Questions

1. **memory projection event 引用格式变更** (Finding 01): 当前测试断言期望 `event_id=event-tool-result-accepted-` 前缀，但实际输出只含原始文本。需确认这是 intentional change 还是 regression。这直接决定是更新测试还是修复代码。

2. **`_render_headers` 的 `api_key.strip()` 语义**: 如果 env 中的值是 multi-line secret（如 PEM），strip 会破坏内容。当前模型 API key 不太可能是 multi-line，但值得确认是否有意为之。

3. **`_compactor_agent_policy_from_scene_inputs` 访问 `override.fallback_mode.value`**: 直接访问 SceneAgentFallbackMode 枚举的 `.value` 再传入 `AgentFallbackMode(value)`。两个枚举的 value 是否始终一致？

4. **`lane.py` `_await_task_after_outer_cancellation` 的无限循环风险**: `while True` 循环在理论上如果底层线程永不返回时会无限等待。是否需要添加超时限制？

5. **`_POST_COMPACT_SYSTEM_PROMPT_ESTIMATE` 硬编码字符串**: 该估算字符串与实际 post-compact system prompt 长度是否匹配？如果实际 prompt 更长，budget_after_compact 估算可能偏低。

3. **单 SQLite connection 写入瓶颈**: 所有 durable 写入通过单一 connection 的 `BEGIN IMMEDIATE` 事务。高并发 follow-up 场景下 busy retry 可能增加延迟。当前配置合理。

4. **Schema 无迁移路径**: 设计上明确不做迁移。DB 版本不匹配时直接失败。每次 schema 变更需 fresh DB。

5. **Recovery dispatch limit 为 1**: 如果 recovery attempt 也 orphan 了，Run 会被直接 mark LOST。

6. **EventLog 无大小上限**: 长期运行的 Session 可能导致 EventLog 表持续增长。

7. **密钥脱敏覆盖范围**: 当前正则只覆盖 Bearer token 和 `api_key/authorization/secret/token=xxx` 模式。其它格式密钥（OAuth refresh token、JWT）可能不被脱敏。

8. **`config_loader.py` (2253 行) / `scene_prepare.py` (1804 行) / `engine_ingest.py` (3000+ 行)**: 文件较大，但各自内部逻辑自成一体，无 God function。可接受但需持续关注。

9. **全仓 pyright 0 errors**: 静态分析基线健康，无 `Any`/`object` 类型违反，无反向依赖。

10. **全仓 1558+ 测试**: 覆盖面广，但 service 层 26 个私有函数中只有 4 个被直接测试。host 层 context/tooling 模块的集成测试覆盖较好。
