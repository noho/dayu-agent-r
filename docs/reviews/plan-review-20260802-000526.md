## 3. Findings

### 001-未修复-中-S5 mechanical total union 算术偏差 (33 ≠ 32)

- **位置**: §9.1 第三段、§10.5 倒数第二段、§13 S5 checklist 第 4 项
- **问题类型**: 契约缺失 / 算术错误
- **当前写法**: "S5 枚举 mechanical total union 从 30 修正为 32 个去重文件"；"两组闭包按 2-file utils delta 与 5-file builder-only delta 合并后的 S5 枚举 mechanical total union 必须为 32 files"
- **反例/失败场景**: 实现 agent 按 §10.5 的 inventory 命令运行后得到 33 个去重文件，与 plan 要求的 32 不匹配，导致 fail closed 误判
- **为什么有问题**: plan 的 "5-file builder-only delta" 计算方式是 8 个 builder 文件减去 3 个 "已在 S5 owner-level 清单" 的文件。但 `test_context_compact_events.py` 虽在 S5 allowed tests 清单（§9.1 14-file list）中，却不在第一 amendment 的 25-file tests identity/typed-return closure 中（它有 CB/RB hit 但无 FA/OA/CR hit）。因此与 27-file tests+utils union 的实际重叠只有 2 个文件（`test_compaction_operation.py` + `test_dispatch_scheduler.py`），delta 实际为 6，total 实际为 27 + 6 = 33
- **直接证据**:
  - `comm -12 /tmp/union_27.txt /tmp/builder_8.txt` 输出 2 个文件，非 3
  - `cat /tmp/union_27.txt /tmp/builder_8.txt | sort -u | wc -l` 输出 33
  - `test_context_compact_events.py` 不在 `rg -l '\bFinalAnswerData\s*\(' tests` 结果中，不在 `rg -l '\bEngineRunOutcomeFinalAnswer\s*\(' tests` 结果中，不在 CR 搜索结果中
- **影响**: 实现 agent 按 §10.5 的 "S5 枚举 mechanical total union 必须为 32 files" 检查时会得到 33，可能误判为 inventory 不闭合而 fail closed
- **建议改法和验证点**:
  - 方案 A：将 "32" 修正为 "33"，"5-file delta" 修正为 "6-file delta"，并明确 `test_context_compact_events.py` 是 builder-only 新增
  - 方案 B：将 `test_context_compact_events.py` 显式加入 identity closure 的 "已允许" 范围说明，保持 32 不变但修正 delta 描述
  - 验证点：修正后 `cat /tmp/union_27.txt /tmp/builder_8.txt | sort -u | wc -l` 输出与 plan 声称一致
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中 — 纯算术偏差，不影响 identity 构造正确性，但会导致实现 agent 的 inventory 闭合检查误判
