### 001-未修复-低-`cn_form_utils.resolve_target_periods` 错误聚合行为变更

- **入口/函数**: `cn_form_utils.resolve_target_periods`
- **文件(行号)**: `dayu/fins/pipelines/cn_form_utils.py:198-205`
- **输入场景**: 用户传入包含多个无效 token 的 form 输入，如 `("FY", "INVALID1", "INVALID2")`
- **实际分支**: 循环内第一个无效 token 调用 `parse_fiscal_period_filter_value` 时抛出 `ValueError`
- **预期行为**: 按旧行为，收集所有无效 token 后统一报告 `"不支持的 form 输入: ['INVALID1', 'INVALID2']"`
- **实际行为**: 在第一个无效 token 处立即失败，错误信息为 `"form 输入 不支持: INVALID1"`
- **直接证据**: 旧行为见 base 的 `cn_form_utils.py` `invalid.append(raw)` 循环 + 统一 `raise ValueError(f"不支持的 form 输入: {invalid!r}")`；新行为见 `parse_fiscal_period_filter_value` 在 `filing_semantics.py:320` 处 `raise ValueError(f"{field_name} 不支持: {value}")`
- **影响**: 用户体验差异——旧版一次报告所有无效项，新版 fail-fast 只报告第一个。不影响正确性，错误仍为中文 actionable message
- **建议改法和验证点**: 若需保持旧聚合行为，可在 `resolve_target_periods` 中 try/except 收集后统一 raise；若接受 fail-fast 则无需修改。当前测试 `test_cn_download_workflow.py` 无多无效 token 聚合测试
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
