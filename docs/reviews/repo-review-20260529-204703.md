### 1-CRITICAL-EventLog 并发 append 对同一 event_id 时跨事务 UNIQUE 冲突被错误分类

- **入口/函数**: `append_event(transaction, request)` → `INSERT INTO event_log`
- **文件(行号)**: dayu/host/durable/event_log.py:338-346, transaction.py:421-422
- **输入场景**: 两个并发写事务同时 append 相同 event_id 但不同 body_digest 的事件
- **实际分支**: Writer A 和 B 先后 read_event_by_id 均返回 None → A INSERT 成功并 commit → B INSERT 触发 SQLite UNIQUE constraint violation → `_classify_sqlite_error` 将其转为通用 `HostUniqueConstraintError` → 调用方收到 `HostUniqueConstraintError` 而非 `HostEventIdentityConflictError`
- **预期行为**: 应抛出 `HostEventIdentityConflictError`，携带 body_digest 对比信息，与同事务内冲突保持一致
- **直接证据**: event_log.py:338-343 在同事务内 read-then-compare 正确抛出 `HostEventIdentityConflictError`；event_log.py:346 的 INSERT 无 try/except 包裹；transaction.py:421-422 将 UNIQUE 约束统一转为 `HostUniqueConstraintError`
- **影响**: 调用方无法区分"同体 event_id 重放"与"异体 event_id 冲突"。若调用方将 `HostUniqueConstraintError` 当作可重试幂等冲突处理，可能导致静默数据不一致
- **建议改法和验证点**: 在 `append_event()` 的 INSERT 周围增加 try/except sqlite3.IntegrityError，捕获后重新读取该 event_id 的 row 并执行 body_digest 比较，正确抛出 `HostEventIdentityConflictError` 或返回已有 row。验证点：并发 append 测试
- **修复风险**: 低
- **严重程度**: 严重

## Residual Risk

1. **并发正确性未充分验证**: Durable 层的 CAS 保护逻辑在代码审查中验证正确，但缺乏并发压力测试（如 10+ 并发 admission/promotion/closeout）。单靠代码审查无法完全排除竞态条件，尤其在 Python asyncio + SQLite WAL 的组合下。

2. **SSE 解析器对非标准 provider 的兼容性**: 当前 SSE 解析器严格遵循 OpenAI 协议。如果接入非标准 provider（如通过 LiteLLM 代理的非 OpenAI 模型），可能在 finish_reason 映射、tool_call delta 格式等方面触发未测试的边界路径。

3. **Context budget token estimation 的精度**: 预算估算使用 `len(text) / 3` 作为 token 数估算，这是一个粗糙的近似。对于中文文本（每个字符 token 数不同）或含大量特殊字符的 JSON payload，估算误差可能较大，影响 compaction 触发时机的准确性。

4. **Purge 安全性的生产验证**: Purge 逻辑的 precondition 检查（Session closed、所有 Run terminal、无 active wait records）在代码审查中确认正确，但 purge 是一个不可逆操作。如果 precondition 检查有遗漏，可能导致生产数据丢失且不可恢复。

5. **LLM 输出质量对 Host governance 的影响**: compaction_operation 中的 budget_after_compact 和 context_governance 中的 quality check 均依赖 LLM 输出。LLM 的不确定性意味着 Host governance 的防御层可能在某些 LLM 输出模式下被绕过或误触发。

6. **测试覆盖的系统性缺口**: 缺少属性测试（Hypothesis）导致边界输入发现依赖人工构造；缺少 schema 迁移测试导致版本升级风险未验证；缺少端到端集成测试导致子系统交互 bug 未被提前发现。
