## Findings

### 001-未修复-低-capture 清理用 sys.exception() 误认 body 异常，可重抛外层无关控制流
- **入口/函数**: `dayu/runtime/process_diagnostics.py` `capture_process_diagnostics()` 的 contextmanager `finally`（`body_error = sys.exception()`，444-445 行判定）
- **文件(行号)**: `dayu/runtime/process_diagnostics.py:405`（取值）、`:444-445`（判定与 raise）
- **输入场景**: 调用方在某个外层 `except` 正在处理 KeyboardInterrupt/SystemExit/asyncio.CancelledError/GeneratorExit 期间执行 `with capture_process_diagnostics(dir): <正常 body>`（body 无异常、cleanup 也无故障）。
- **实际分支**: finally 首行 `body_error = sys.exception()` 取到线程当前 in-flight 的**外层**控制流对象 → `body_error is not None and not isinstance(body_error, Exception)` 成立 → 445 行 `raise body_error`。
- **预期行为**: 按 accepted plan DN-R1 控制流合同（“已有 body 控制流优先保原对象；没有 body 控制流而 cleanup 新收到控制流则保首个新控制流”），body 干净且 cleanup 干净时 scope 必须正常退出、不抛任何异常；只有真正穿过 body 或 cleanup 的控制流才允许传播。
- **实际行为**: scope 在退出时重抛一个从未进入 scope 的外层控制流对象，把成功的业务结果中断为控制流失败。
- **直接证据**: bounded probe（真实产品模块，`workspace/tmp/upload-material-converter-diagnostics-20261003/code-review-mimo-01/probe_sys_exception.py`，exit 0）：`case_outer_control_body_normal` 在外层 `except KeyboardInterrupt` 内正常完成 body，实际 raised=`KeyboardInterrupt('outer-control-object')`，`is_outer_KeyboardInterrupt_object=True`；对照 `case_outer_normal_exc_body_normal`（外层普通 OSError）不抛、`case_return_inside_except` 正常返回 descriptor、`case_body_raises_normal` 原样传播 ValueError。`sys.exception()` 语义同源小探针（stdlib 层）独立复现：外层处理 ValueError 时 contextmanager finally 读到 ValueError('outer')。实现机制与合同判定不是同一事实源：`sys.exception()` 返回线程 innermost in-flight 异常，不是“body 异常”。
- **影响**: 当前产品路径不可达（`interruptible_process._run_process_target` 裸调 `target()`，执行期间无外层 except 生效；`_DoclingProcessTarget.__call__` 内所有 `return`-in-except 均处理普通 Exception，被 `isinstance(body_error, Exception)` 过滤），故为潜伏缺陷。但 `capture_process_diagnostics` 是本轮新增的一次性 worker 公共运行时合同，DN-R1 对异常对象身份是 MUST 合同；未来任何在 except/重试包装中调用该 scope 的 worker 装配（含 `_run_process_target` 形态变化）都会把成功转换变成伪控制流中止，descriptor 丢失、IPC/crash 误判，且测试矩阵（body 在 with 内抛出）覆盖不到该形态。
- **建议改法和验证点**: 在 `yield` 外显式 `try: yield except BaseException as exc: body_error = exc; raise`，用真正穿过 body 的异常对象替代 `sys.exception()` 线程态判定；cleanup 逻辑保持现“暂存首控制流、继续回收、收口保首原对象”结构。验证点：新增 worker 测试在外层 `except KeyboardInterrupt`/`SystemExit` 内正常完成 capture body，断言 scope 零抛出且 records 正常收口；回归现有“body 控制流原对象传播”矩阵。
- **修复风险（低/中/高）**: 低（局部替换取值机制，cleanup 与资源回收结构不动）。
- **严重程度（低/中/高/严重）**: 低（当前调用图不可达 + 新公共合同的潜伏正确性/可维护性缺陷）。
