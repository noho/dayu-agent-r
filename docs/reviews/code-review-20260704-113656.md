## Residual Risk

- **`_cancel_request_event_id_from_cancelling` 跨模块 import 私有符号**: `engine_ingest.py` import `run_transition.py` 的私有函数 `_cancel_request_event_id_from_cancelling`。当前在 Host 包内部，属于合理复用。若未来 `run_transition.py` 重构该函数签名，`engine_ingest.py` 的调用点需要同步更新，但 pyright 会捕获类型不匹配。风险低。
- **`_cancel_request_event_id_from_cancelling` 不再校验 `occurred_at` 格式**: 原 `run_transition.py` 版本在 parser 中调用 `parse_utc_timestamp(event.occurred_at)`，现移至 `_normalized_event_occurred_at` 在 payload 构造时校验。若 `RUN_CANCELLING` fact 的 `occurred_at` 格式非法，parser 仍返回有效 `cancel_request_event_id`，但 payload 构造会抛 `HostDurableError`。由于两者在同一事务内，异常会回滚整个事务，行为安全。此变化使 parser 职责更清晰（只提取 id），timestamp 校验集中在 payload 构造点。
- **Provider/tool 物理执行未停止**: timeout `CANCELLED` 终端不物理停止 provider/tool work。Owner/destination: WU-TOOLS-CANCEL-01。
- **Watchdog loop、startup ordering、recovery 与 promotion**: 不在 Slice 1 范围。Owner/destination: WU-LIFE-03 Slice 2。
- **Timeout 默认值与 UTC 时钟偏差**: 不在 Slice 1 范围。Owner/destination: GitHub Issue #87。
- **Input validation negative path 未测试**: `_validate_active_cancel_timeout_closeout_input` 的 `HostDurableError` 路径（如 `timeout_seconds <= 0`、空 `watchdog_owner`、负 `last_observed_worker_event_index`）无对应测试。实现正确复用 `_require_non_empty_text` 和 `math.isfinite`，pyright 覆盖类型。风险低。
