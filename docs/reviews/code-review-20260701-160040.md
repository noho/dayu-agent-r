### 3. Lifecycle gate coverage

1. Before claim: `_claim_next_wait_record` → `if self._lifecycle_gate.is_closed(): return None` (`wait_adapter.py:845`)

### 4. Close ordering

`_PublicHostHandle.close()` (`open_host.py:751-804`):
1. `self._closed = True` (public gate)
2. `self._wait_poller.close()` via `asyncio.to_thread` (poller)
3. `self._scheduler.close()` (scheduler)
4. `self._projection_catchup_port.catch_up_projection()` (projection flush)
5. `self._command_handle.close()` (durable store)

Error handling: poller close failure captured, scheduler close still proceeds, first exception re-raised.

### 5. Thread-safe scheduler wakeup

`_ThreadsafeSchedulerWakeupPort._run_on_loop` (`open_host.py:287-304`):
- Uses `loop.call_soon_threadsafe(run_callback)` + `future.result()` to synchronously execute wakeup on event loop thread
- During `asyncio.to_thread(poller.close)`, the event loop is alive (awaiting `to_thread` future), so `call_soon_threadsafe` callbacks can execute
- If loop is closed (shouldn't happen during normal close), `call_soon_threadsafe` raises `RuntimeError` → caught by `resolve_wait` exception handler → backoff release

### 6. Factory thread-local durable store

`_OpenHostWaitPollerFactory.create_wait_poller` (`open_host.py:392-426`):
- Creates fresh `open_host_durable_store(...)` per poll round (new SQLite connection)
- Creates fresh `HostCommandHandle` with fresh `admission_service` (with thread-safe wakeup port)
- Wraps in `_ClosingWaitPoller` that closes command handle in `finally`
- No reuse of opener-thread `HostTransactionRunner`

### 7. resolve_wait integration

`_CommandHandleWaitResolver.resolve_wait` (`open_host.py:336-344`):
- Calls `_resolve_wait(self._command_handle, wait_id, request)` — same command path as public handle
- Command handle constructed with `admission_service=create_host_admission_service(transaction_runner, wakeup_port=self.wakeup_port)`
- After commit, admission service calls `wakeup_port.wake_dispatch` → scheduler wakeup

### 8. Construction-time fail-fast

`_validate_wait_poller_configuration` (`open_host.py:1028-1040`):
- Called early in `__aenter__` before durable store creation
- `_enabled_wait_poller_configuration` raises `HostApiError(INVALID_STATE)` when `policy.enabled=True` and `wait_poll_adapter_registry is None`
- `enabled=False` returns `None` without requiring registry

### 9. Default no-poller preserved

- `OpenHostOptions.wait_poller_policy` defaults to `None` (`api.py`)
- `_enabled_wait_poller_configuration` returns `None` when policy is `None`
- `_wait_poller_supervisor_from_open_host_options` returns `None`
- `_PublicHostHandle` receives `wait_poller=None`
- `close()` skips poller close when `self._wait_poller is not None` is false
- All existing no-poller tests continue to pass
