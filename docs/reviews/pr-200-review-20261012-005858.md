- **入口/函数**: `dayu-cli download` -> SEC accepted download -> `SecDownloader.list_filing_image_files` -> `_canonical_image_reference` -> `_is_same_image_archive`。
- **文件(行号)**: `dayu/fins/downloaders/sec_downloader.py:428`、`dayu/fins/downloaders/sec_downloader.py:436`、`dayu/fins/downloaders/sec_downloader.py:480`、`dayu/fins/downloaders/sec_downloader.py:484`、`dayu/fins/downloaders/sec_downloader.py:486`；测试缺口位于 `tests/fins/test_sec_html_image_assets.py:118`、`tests/fins/test_sec_html_image_assets.py:176` 的完整 URL/百分号矩阵。
- **输入场景**: 已接受 HTML 使用完整 SEC URL 引用同申报图片，但 archive 根或 accession 路径组件中的未保留字符采用合法百分号编码，例如 `%41rchives` 表示 `Archives`、`%30...%34%32` 表示 accession 数字；同一输入分别经 `img/src`、`img/srcset`、`picture/source/srcset` 出现。
- **实际分支**: `_validate_image_address_text` 允许这种单次合法编码；`_is_same_image_archive` 却直接比较 `urlsplit(url).path.split(...)` 的原始编码组件，`%41rchives != Archives`、编码数字 accession 也不等于原 accession，因此返回 `False`；`_canonical_image_reference:481` 返回 `None`，`list_filing_image_files:1947` 将其当作范围外候选静默 `continue`。
- **预期行为**: 同一 URL path 组件的未保留字符百分号编码应与字面字符表示同一资源。相同申报、相同 decoded path 的完整 URL 必须返回同一个 `plot.jpg` / canonical `ARCHIVE + plot.jpg`，进入完整 descriptor 集合、指纹、必要 GET、source files 和仓储寻址。
- **实际行为**: 该图片不进入 `images`，后续 `remote_files`、`build_source_fingerprint`、文件 GET 和 `source meta.files` 均缺失它；fresh/old accepted download 仍可发布并报告 `downloaded`，随后因已写入非空指纹进入 `already_downloaded_complete` 快跳。
- **直接证据**: 同一 helper 内文件身份在 `:484` 使用 `unquote(path)` 后取名，而范围判断在 `:428-436` 使用 raw path，两个 URL 语义真源不一致。独立探针 `workspace/tmp/sec-html-image-assets-pr-review-mimo/probe/percent_archive_identity_probe.py` 对编码 archive、编码 accession 均得到 `decoded_path_same_as_expected_asset=true` 且 `identity=None`，编码文件名则正确得到 `('plot.jpg', ARCHIVE + 'plot.jpg')`；日志 `workspace/tmp/sec-html-image-assets-pr-review-mimo/log/percent-archive-identity.log`，探针 pyright 为 0 errors。
- **影响**: 高。必要图片会被静默遗漏，但 CLI/下载终态仍可能成功并形成可快跳的不完整 publication，直接违反“已选 HTML 的同申报图片必须完整下载登记”和“必要发现失败不得假完整”的成功信号。
- **建议改法和验证点**: 在 `_is_same_image_archive`、base 归一和 name 提取之间建立同一个严格 path canonical owner；先沿用现有 raw 检查拒绝控制字符、反斜杠、编码分隔符和二次 `%HH`，再对 path 组件做一次严格解码/未保留字符规范化，以 decoded components 判断申报边界并生成文件名。补三入口、完整 URL、base 完整 URL、编码 archive/accession、编码文件名、其它 accession 与前缀假匹配的正反测试；断言 exact transport URL、完整 fingerprint、files/hash/URI、fresh/old 补齐、失败回滚及 repeat 快跳。
- **修复风险（低/中/高）**: 中。URL/path 边界是安全 owner，修复必须保留编码分隔符、点段、二次编码和跨 accession 拒绝，不可用宽松重复解码或 basename fallback。
- **严重程度（低/中/高/严重）**: 高。
