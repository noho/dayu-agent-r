### Root fix 沿调用链验证

**入口**：`convert_pdf_bytes_with_docling`（`docling_runtime.py:618-657`）

**基线行为**（`715b25a6`）：第 660 行在 lambda 外部构造一次 `stream = _build_docling_document_stream(raw_bytes, stream_name=stream_name)`，lambda 内对每个 converter 执行 `converter.convert(stream)`。当 `run_docling_pdf_conversion` 的 attempt loop（第 541-591 行）多次调用该 lambda 时，所有 attempt 共享同一个可关闭的 `DocumentStream` / `BytesIO`。

**修复后行为**（working tree）：第 651-652 行将 stream 构造移入 lambda 内部：`lambda converter: converter.convert(_build_docling_document_stream(raw_bytes, stream_name=stream_name))`。每次 lambda 被 attempt loop 调用时，`_build_docling_document_stream`（第 594-615 行）新建 `BytesIO(raw_bytes)` 并包装为新 `DocumentStream`。

**直接证据**：
- `_build_docling_document_stream` 第 615 行：`return DocumentStream(name=stream_name, stream=BytesIO(raw_bytes))`。每次调用必新建两个对象。
- `run_docling_pdf_conversion` 第 559 行：`result = convert_operation(converter)`。attempt loop 每次迭代调用一次 callback，callback 内现在每次构造新 stream。
- `raw_bytes` 是 `bytes`（不可变），`stream_name` 是 `str`（不可变），lambda 闭包捕获的是不可变引用，不存在跨 attempt 污染。

**结论**：root fix 正确。每个 attempt 获得独立 stream，第三方 converter 关闭自己的 stream 不影响后续 attempt。

### Stream 对象生命周期 / identity 测试稳健性

两个核心 owner tests 验证 attempt-local stream identity：

1. `test_convert_pdf_bytes_rebuilds_stream_after_closed_first_attempt_and_second_succeeds`（第 482-526 行）：
   - `_RecordingConverter` 在 `convert` 中读取 stream、记录 `id(source)` / `id(stream)` / `stream.closed` / `stream.read()`，然后 `stream.close()`，再抛异常或返回。
   - 断言：`first_observation.initially_closed is False`（首档 stream 初始可读）；`second_observation.initially_closed is False`（次档 stream 初始可读，证明非同一对象）；`wrapper_identity` 与 `stream_identity` 均不同；`name` / `payload` 相同。
   - 测试替身行为与真实 Docling converter 的 `convert(source: DocumentStream)` 读取流并可能关闭的外部行为一致，但测试验证的是**我们的 attempt-local stream 装配契约**，而非固化第三方关闭行为。

2. `test_convert_pdf_bytes_auto_three_attempts_use_distinct_streams_and_preserve_failure_chain`（第 528-576 行）：
   - 三档 converter 各自读取、关闭、抛不同预建异常。
   - 断言：精确 `[(docling-parse, auto), (pypdfium2, auto), (docling-parse, cpu)]` 顺序；三个 wrapper identity 与三个 stream identity 各自全唯一；三个 `initially_closed` 均为 `False`；`name` / `payload` 全相同。
   - 异常链断言：`caught is last_failure`（identity 比较），`caught.__cause__ is first_failure`（不是 `middle_failure`）。这精确验证 `run_docling_pdf_conversion` 第 589-590 行的 `raise last_failure from first_failure`。

**结论**：测试通过 `id()` identity 比较而非字符串/属性比较，精确验证 stream 对象独立性。`_RecordingConverter` 的 close-then-fail 行为是对已观察 production 行为的合理模拟，测试目的是验证我们的隔离契约而非固化第三方行为。
