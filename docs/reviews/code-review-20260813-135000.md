## 核销结果

### 核销 1 — FD2 隔离/restore/close 异常语义

逐路径走读 `_isolated_inherited_stderr`（`docling_process_converter.py:61-88`）：

- 入口 `sys.stderr.flush()` / `os.dup()` 失败 → 异常在复制前传播，无 fd 泄漏，被 `__call__` 既有 `except Exception` 收敛为 closed `CONVERTER_EXECUTION` descriptor（`:281-284`）。
- `open(os.devnull)` / 首次 `dup2(devnull, 2)` 失败 → 外层 `finally: os.close(inherited_stderr_copy)` 必执行，dup 出的 fd 不泄漏；`dup2` 原子失败时 fd 2 未变。
- 恢复路径 `dup2(inherited_stderr_copy, 2)` 前先 flush：隔离期间泄漏字节落向 devnull，不会回流公开 stderr；顺序正确。
- 唯一语义漂移：`yield` 体抛 `DoclingRuntimeInitializationError` 且内层 finally 的 `flush()` 同时抛 `OSError` 时，新异常遮蔽原始异常，kind 从 `CONVERTER_CONSTRUCTION` 变为 `CONVERTER_EXECUTION`（原始异常保留于 `__context__`）。flush 目标是 devnull 写端，双失败需极端条件。
- **裁决：核销通过。** 全部失败路径收敛到既有 closed descriptor 且 fd 无任何泄漏路径；双失败 kind 漂移为既有低严重度 finding（见 Finding 2），不阻塞。

## Findings

### 1-未修复-低-logger lastResort 泄漏路径未被测试实际覆盖

- **入口/函数**: `test_child_target_isolates_inherited_stderr_while_preserving_failure_descriptor`
- **文件(行号)**: `tests/fins/test_docling_process_converter.py` (752–833)
- **输入场景**: `failing_convert` 内 `leaking_logger.warning(...)`，logger 配置为 `handlers.clear()` + `propagate=False` + level WARNING。
- **实际分支**: `Logger.callHandlers` 在无 handler 且 `propagate=False` 时于该 logger 停止，不抵达 root，`lastResort` 永不触发；warning 在有无 fd 隔离时均零输出。
- **预期行为**: 测试声称覆盖第三方 logger 经 lastResort 写 inherited stderr 的路径。
- **实际行为**: logger 腿为恒空断言，不区分隔离生效与否；仅 `sys.stderr.write(...)` 直写 fd 2 腿真实证明 fd 级隔离机制。
- **直接证据**: `tests/fins/test_docling_process_converter.py` — `leaking_logger.handlers.clear()`、`leaking_logger.propagate = False`；stdlib `logging` 仅当传播链抵达 root 且 root 无 handler 时启用 `lastResort`。
- **影响**: 覆盖声明略宽于实际；fd 级机制（隔离的真源）已被直写腿证明，风险极低。
- **建议改法和验证点**: 如需覆盖 lastResort，改用 `propagate=True` 经 root 的 `logging.warning(...)`，或直接在 child 内断言隔离期 fd 2 写入不可见。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
