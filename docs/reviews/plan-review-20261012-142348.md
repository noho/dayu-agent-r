## 重点风险面深查结果（对应任务 focus）

1. **source inventory / snapshot 完整性 views 对 repair 的阻挡**：无新阻挡类别。early helper 与既有 final preflight 前两项检查同语义（Assumption #3）；唯一 selected repair 与 seeded 摘要场景均可在 final 新窗后继续原 repair / skip 链（Assumption #4、#6）。`classify_source_integrity` 本就做同 kind 全量扫描，A 期改用 integrity view 不引入数量级成本差。
2. **local witness 与 A/B/retry 陈旧事实**：witness 只绑定 opaque revision，A 期同窗复核；revision 不等 / 消失 → 原 typed conflict，REPAIR_REQUIRED → 原 repair error，UNSAFE 优先；A/B 同 identity 才允许 skip；retry 显式丢弃 prepared / witness 并 fresh identity / acquisition，三轮上限保持（`cn_download_filing_workflow.py:599-621` 与 `_MAX_SOURCE_IDENTITY_ROUNDS=3` 已核）。未发现可静默陈旧成功的路径。
3. **prepared / 原 GET / selector 契约**：`CnReportDiscoveryResult` 新必填字段的全部生产 / 测试构造点已列；`prepared.candidate` 同实例 + helper 校验可实施；selector 事实 map「缺 / 多 / 重复即 contract 错误」且无旧年 fallback。
4. **真实 HTTP 观察**：pin / 签名 / lifecycle（seq 闭合、hooks_intact、observer_error 即验收失败）与 grandchild 范围均与机制 probe 一致；生产 HTTP 在 CLI 进程内（sync httpx）、巨潮 PDF GET 不会落入不可观察的孙进程。
5. **verify / compare 证据链**：官方集合核对走本次 raw 解析 + `official_set_changed` 交总控；GET 集合同时从 transport 与 wire 两表构造并逐项相等；转换证明走既有 `download.conversion_started/completed` 进度行与 source.files 文件名精确匹配；存储事实走 Fs snapshot 读回（document ID / key / revision / SHA / COMPLETE）。均与现网 CLI / 仓储输出契约核对一致（Assumption #10）。
6. **allowed files / 迁移与 pyright / coverage**：coverage 11 个生产文件与 P1 allowed files 一一对应（含 source_integrity / protocols / hkexnews）；纯契约 helper 仍在既有 storage 纯 contract；pyright 全仓命令与严格签名要求符合 AGENTS。
