## Findings

### 1-未修复-[低]-skipped 原因对未被唯一投影严格校验，分类与公开原因可能漂移

- **入口/函数**: `project_sec_filing_disposition` 被 `warn_insufficient_filings` 和 `_project_sec_document_row` 消费。
- **文件(行号)**: [sec_download_disposition.py](/Users/leo/workspace/dayu-agent-r/dayu/fins/pipelines/sec_download_disposition.py:37)、[sec_download_diagnostics.py](/Users/leo/workspace/dayu-agent-r/dayu/fins/pipelines/sec_download_diagnostics.py:76)、[sec_pipeline.py](/Users/leo/workspace/dayu-agent-r/dayu/fins/pipelines/sec_pipeline.py:1931)、[test_sec_download_disposition.py](/Users/leo/workspace/dayu-agent-r/tests/fins/test_sec_download_disposition.py:28)。
- **输入场景**:
  - `status=skipped`，`skip_reason` 与 `reason_code` 都缺失；或
  - `status=skipped, skip_reason=6k_filtered, reason_code=already_downloaded_complete`。
- **实际分支**: helper 把缺失原因读成两个 `None` 并返回 `SKIPPED`；冲突原因则经第 41 行 OR 条件返回 `REJECTED`。typed 分支仍按 raw `status=skipped` 走第 1931 行，并优先把 `reason_code` 作为公开原因类别。
- **预期行为**: 新唯一投影应满足 typed owner 的 same semantics：skipped 行至少有一个非空原因；两者同时存在时必须一致；否则在 warning 计数或 public projection 前抛 `ValueError`。单一原因入口应继续支持，因为当前生产者可用 `skip_reason` 或 `reason_code` 表达同一事实。
- **实际行为**:
  - 原因全缺失时，独立复跑得到 `disposition=skipped`、warning“有效落盘数 1”，随后 typed 投影抛 `ValueError: SEC 下载结果缺少必填文本字段: skip_reason`。
  - 原因相同时，独立复跑得到 `disposition=rejected`，但 typed 行为 `reason_category=already_downloaded_complete`、`reason_message=该文档未通过来源筛选规则`，同一 public row 同时声称“拒绝”和“完整缓存成功跳过”。
- **直接证据**: helper 第 39-43 行只在原因存在时验证，缺失后仍返回 skipped；原测试第 28 行明确把缺失原因固化为 `SKIPPED`。warning 第 79-80 行据此计入有效数；typed 第 1932 行随后要求非空 reason。冲突输入则证明 helper 的 OR 分类与第 1932 行优先取 `reason_code` 的原因投影不是同一结果。
- **影响**: 当前所有内置 skipped 生产者都写非空且同值的 `skip_reason/reason_code`，因此已知主链不会触发，不否定 D1 修复的三项成功信号。若后续生产者、恢复/投影输入或测试夹具出现缺原因或冲突原因，会先得到错误 warning/计数，或生成 public disposition 与 reason_category 自相矛盾的结果；这违反本单元要求的严格非法字段与唯一语义 owner。
- **建议改法和验证点**: 在 `project_sec_filing_disposition` 内收敛 skipped 原因校验：两者都不存在时抛 `ValueError`；两者均存在但文本不同则抛 `ValueError`；保留只给其中一项的既有入口。不要再让 `_project_sec_document_row` 用 raw status 和独立原因优先级补全分类。补充 owner 测试：缺失原因、冲突原因均拒绝；单原因 `6k_filtered`、单原因缓存跳过及双字段同值仍分别投影正确，并和 typed row/quantity warning 联验。
- **修复风险（低/中/高）**: 低。只收紧确认行输入契约和测试，不改 6-K 政策、下载认证版本、持久化 schema 或公开枚举。
- **严重程度（低/中/高/严重）**: 低；当前生产者不可触发，但这是明确的 owner 边界缺口，不应假装已被现有 happy-path 测试覆盖。
