## 2. Findings

无 material findings。

以下候选问题经证据检验后均不成立，记录判断依据：

1. **“Fixed fake 的 batch read 返回与 published read 相同的固定 state，混淆 staging/published 视图”** — 不成立。S1 中 production 无任何路径调用该 fake 的 batch read（A7 钉死 `batch_calls == []`），该返回值只被新增 owner test 以同一对象断言固定，是有意 fixture contract 而非固化偶然行为；若 S2 需要 staging 视图差异，属于 S2 经 plan review 的扩展，非 S1 缺陷。相反，若让 batch read 抛错，S2 可能被迫再次修订 fixture，当前选择是最小且可演进。
2. **“static admission tests 加 `batch_calls == []` 的 census 可能漏测点”** — 不成立。amendment 以“在断言 `calls == []` 的同时”自定义 census；grep 证实全文件恰好 3 处 static admission `calls == []`（2298/2393/3166）+ 1 处 prevalidation 精确两读（1948），与 assertion 11 一一对应，无遗漏点。
3. **“保留 cast 更省事”** — 不成立。保留 cast 会让 `_Forbidden` 永久绕过 structural check，重演本次 drift；且与本项目禁止兼容逃逸的硬约束冲突。去 cast 使两个 builder 对称，是 owner 正确的最小迁移。
4. **“fake conformance 应推迟到 S2”** — 不成立。错误已存在于当前 partial diff，S1 的 completion signal 要求 focused/full pyright 无报错且无 expected red；fake conformance 只能属于 S1 fixture 边界，推迟即 S1 无法关闭。

## 3. 验证点结论（用户指定六项）

1. **两个 structural fake 实现 required batch method** — 成立。production contract 新增 required `read_filing_upload_state_in_batch(batch: BatchToken, document_id: str) -> FilingUploadPublishedState`；`_Fixed` 已被 castless 注入暴露缺口，`_Forbidden` 被 cast 掩盖；amendment 要求两者以精确签名实现，且 census 已证实全 `tests/` 无第三个 implementer。

3. **Forbidden fail-fast** — 成立。record-then-raise 与既有 published read 行为同构，把“static admission 禁止 filing state read”从 published read 扩展到 batch read，无宽松路径。
4. **Fixed 返回固定 state** — 成立。与 fixture“固定 state”语义一致；S1 production 零调用（`batch_calls == []` 钉死），identity 断言是新 owner test 的明确 fixture contract。

6. **static admission / runtime prevalidation 现有语义、S1 零行为与 production scope 不变** — 成立。
   - static admission：3 处测试断言 `calls == []` 与全部零副作用/workspace 快照不变，只新增 `batch_calls == []`。

   - production scope：allowed production files 不变，§8.2/§10.1 生产清单与 amendment §1 一致；README decision 不变。
