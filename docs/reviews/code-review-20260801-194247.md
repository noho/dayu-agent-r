### 4. New-work lease 与 actor future 绑定；竞态安全

- **入口/函数**: `_run_delayed_attachment_recovery`
- **文件(行号)**: `dayu/host/open_host.py:1272-1340`
- **审查结论**: PASS

完整竞态矩阵验证：

| 路径 | 行为 | 验证 |
|---|---|---|
| lease 获取失败 | `return`，不提交 actor | `work_lease is None` → early return |
| lease 成功 + actor submit 成功 | `release_when_done(actor_future)` 绑定 future 收口 | `work_lease = None` 防止 finally double-release |
| CancelledError（actor 未提交） | `actor_future is None` → 直接 re-raise | sleep 阶段的 CancelledError 不触发 fatal |
| CancelledError（actor 已提交） | shield actor_future，异常时 report fatal，re-raise | finally 清理 task dict |
| 非 CancelledError 异常 | report fatal | 不 re-raise（task 正常结束但 health 变 UNAVAILABLE） |
| finally（work_lease 未绑定 future） | `work_lease.release()` | 覆盖 actor submit 失败但 lease 已获取的路径 |
| finally（task dict 清理） | `del self._delayed_attachment_recovery_tasks[session_id]` 仅当仍是 current task | 防止跨 task 误删 |

测试覆盖：`test_attachment_close_cancels_sleeping_delayed_recovery_without_facts`（sleep 前 cancel）、`test_attachment_close_joins_submitted_delayed_scan_before_mutex_release`（actor 已提交 close）、`test_delayed_recovery_failure_reports_safe_fatal_and_does_not_leak_task`（异常 fatal + task 清理）。

### 5. attachment/Host close 顺序

- **入口/函数**: `_close_managed_attachment` / `_cancel_and_join_delayed_attachment_recovery` / `_close_owned_resources`
- **文件(行号)**: `dayu/host/open_host.py:1367-1409, 1847-1856`
- **审查结论**: PASS

attachment close 顺序：
1. `_cancel_and_join_delayed_attachment_recovery` — pop → cancel → shield(task)。CancelledError → return（正常 cleanup）。
2. `attachment.aclose()` — 底层 attachment close。

Host close 顺序：
1. `begin_host_close()` — 阻止新 attachment
2. `_cancel_and_join_all_delayed_attachment_recoveries()` — 批量取消/join 全部 delayed tasks
3. `begin_closing()` — health gate 进入 CLOSING
4. `stop_and_drain()` — actor 停止

关键 invariant：delayed tasks 在 actor stop 之前全部取消/join 完毕。`_cancel_and_join_all_delayed_attachment_recoveries` 使用 `tuple(self._delayed_attachment_recovery_tasks)` 获取快照后逐个 `pop`，防止重复 cancel。`task.done()` 检查避免对已完成 task 调用 `cancel()`。

测试覆盖：`test_host_close_cancels_all_sleeping_delayed_recovery_tasks_before_actor_stop` 在 actor stop 入口设 barrier，验证 dict 为空且 task 已取消，竞争 opener 保持 RO。

## Residual Risk

- **Delayed scan one-shot bounded invariant**：若 second scan 又得到 recent-heartbeat deadline，不会形成新调度链或 polling。这是批准的 bounded design — 后续 heartbeat 刷新场景仍依赖既有 recovery trigger（如 startup scan、periodic reconcile）。
- **Windows SIGKILL 未覆盖**：POSIX-only 执行；Windows 由测试显式 skip。plan §7.6 明确此为 non-goal。
- **Watchdog exact-count 单次观察**：前轮 DS review 报告一次 `token_threads` 重复断言失败，本 review 未复现（116 passed）。root cause 仍为 unclassified observation；按 controller 裁决保留记录但不阻塞 gate。
- **HEAD 已有 ruff F401**：`recovery.py::AttemptStatus` 与 `test_recovery_scan.py::create_running_run_with_starting_attempt_in_transaction` 为 HEAD 基线已有，S3 未引入或扩大。
- **Wall clock 依赖**：`_sleep_until_recovery_deadline` 使用 `datetime.now(UTC)` 计算 delay（非 monotonic），极端系统时钟回拨可能导致 delay 延长。`max(0.0, ...)` 防止负 delay。该模式与系统其他 recovery 组件一致，不构成 material finding。
