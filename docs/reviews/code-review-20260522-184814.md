### 正向确认

以下各修复项经逐行走读与测试验证，实现正确且无回归：

1. **ToolRuntime 大结果治理移除**（`dayu/host/tool_runtime.py`）：`_govern_inline_tool_result` 重命名为 `_observe_llm_inline_tool_result`，不再对无显式 truncation spec 的大工具结果执行默认 governed_error。函数始终原样返回 outcome，仅记录日志摘要。`_TOOL_RESULT_SIZE_LOG_THRESHOLD_BYTES`（65536）仅触发 verbose 日志，不改变 outcome 语义。截断后也不再二次拒绝。payload/secret 不泄漏到日志（日志只含 size_bytes、tool_name 等结构化字段）。

2. **Engine 64KiB inline guard 移除**（`dayu/engine/agent.py`）：`_message_inline_size_failure`、`_message_inline_texts`、`_assistant_tool_call_inline_texts`、`_MAX_ENGINE_MESSAGE_CONTENT_BYTES` 全部移除。普通迭代、force-answer 路径均不再执行 inline 大小检查。`_classify_iteration` 的 `_IterationDecision` 联合（`_FinalDecision | _ToolCallsDecision | RunFailedData`）在 force-answer 路径末尾由 `assert_never` 保证穷尽。CONTEXT_LENGTH_EXCEEDED 路径保留并新增 `_safe_log_message` 脱敏日志。

3. **Compaction failure 诊断日志**（`dayu/host/compaction_operation.py`）：`_log_rejected_attempt` 记录 session_id、run_id、failure_category、error_code、脱敏 message、diagnostic_refs、next_policy_decision、budget_after_attempted_compact。`_safe_exception_message` 使用 Bearer 和 assignment-style 正则脱敏，截断 240 字符。不泄漏完整 payload 或 secret。

4. **Smoke terminal failure 摘要**（`utils/smoke_host_public_multiturn.py`）：`_terminal_failure_summary` 只输出 label、run_id、kind、terminal_status、event_id、event_sequence、脱敏 message、summary_ref、summary_digest。`_safe_summary_text` 对 api_key/authorization/bearer/token/secret 等 marker 做整段 redaction，截断 240 字符。测试覆盖 Bearer redaction 和长度截断。

## Residual Risk

- `run_read` 复用 `write_busy_retry_count` 策略参数。当前设计合理（SQLite busy/locked 是数据库级竞争），但若未来需要读写分离的重试策略，需新增 read 专属 policy 字段。
- `_safe_log_message`（agent.py:243）与 `_exception_diagnostic_message`（agent.py:218）共享 `_SENSITIVE_EXCEPTION_MARKERS`，其中 `"header"` marker 范围较广，可能误杀含 "header" 的非敏感诊断消息。这是预存模式，非本次引入。
- Engine 移除 inline size guard 后，若 Host 未及时触发 Context Governance，超大 tool result 会直接到达 provider。provider 会以 CONTEXT_LENGTH_EXCEEDED 收口，但会消耗一次 Runner 调用。这是预期设计转移，不是缺陷。
