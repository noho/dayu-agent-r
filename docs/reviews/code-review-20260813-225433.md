### 详细分析：F1 修复验证

#### 1. static admission 是否只复用 canonicalizer shape owner — **确认成立**

`_admit_fins_upload_file_basename(basename)`（`ingestion_runtime.py:835-851`）只做一件事：调用
`canonicalize_fins_public_file_label(basename)`，捕获其 `ValueError` 并转成 `FinsUploadUsageCode.INVALID_FILE_BASENAME`。
未复制 `/`、`\\`、empty、dot-segment 等规则；所有 shape 判断继续由 `direct_events._validate_public_file_basename_shape`
唯一拥有。

**直接证据**：`_admit_fins_upload_file_basename` 函数体仅 3 行有效逻辑（try/except + 调用）；canonicalizer
入口 `direct_events.py:1070-1087` 调用 `_validate_public_file_basename_shape` 后再判断是否需要隐藏。

#### 2. INVALID_FILE_BASENAME 是否 closed/fixed/bounded 且不带 raw basename — **确认成立**

- **closed**：`FinsUploadUsageCode.INVALID_FILE_BASENAME = "invalid_file_basename"` 是 `str, Enum` 的显式成员。
- **fixed**：`_USAGE_MESSAGES` 中 message 为固定字符串 `"上传文件名无效；请提供单个非空文件名"`，无 `{file_name}` 占位符。
- **bounded**：message 长度 18 字符，远低于 `_MAX_TEXT_CHARS`。
- **不带 raw basename**：`INVALID_FILE_BASENAME` 不在 `_FILE_USAGE_CODES` 中（`ingestion_runtime.py:746-753`，
  只含 FILE_NOT_FOUND/FILE_NOT_REGULAR/FILE_SUFFIX_NOT_ALLOWED/CONVERTER_SUFFIX_UNSUPPORTED）。
  `fins_upload_usage_failure` 对非 `_FILE_USAGE_CODES` 的 code 在收到 `file_name` 参数时抛 `ValueError`
  （`ingestion_runtime.py:806-807`）。`_raise_upload_usage` 调用时不传 `file_name`（`ingestion_runtime.py:851`）。

**直接证据**：
- enum 定义 `ingestion_runtime.py:666`
- message 映射 `ingestion_runtime.py:771`
- `_FILE_USAGE_CODES` frozenset `ingestion_runtime.py:746-753`
- `fins_upload_usage_failure` else 分支 `ingestion_runtime.py:806-807`

#### 3. 检查顺序在 filesystem probe 前 — **确认成立**

`_validate_fins_upload_filing_static` 中文件循环体顺序（`ingestion_runtime.py:913-923`）：

```
L914: basename = file_path.name
L915: _admit_fins_upload_file_basename(basename)    ← admission
L916: if not file_path.exists():                     ← filesystem probe 1
L918: if not file_path.is_file():                    ← filesystem probe 2
L920: if file_path.suffix.lower() not in ...:        ← suffix check
```

admission 在 `exists()` / `is_file()` / suffix 检查前执行。pathful basename 在任何 I/O 前被 typed 拒绝。

**测试验证**：`test_filing_static_admission_rejects_pathful_basename_before_filesystem_probes` monkeypatch
`Path.exists` 和 `Path.is_file` 为始终抛 `AssertionError` 的 guard，证明 admission 路径不触发 filesystem probe。

#### 4. 普通/中文/fragment/Cc/Cf/超长不误拒 — **确认成立**

`_admit_fins_upload_file_basename` 只捕获 `canonicalize_fins_public_file_label` 的 `ValueError`。
canonicalizer 对以下输入**不**抛 `ValueError`：

- 普通 basename（`report.pdf`）→ 原样返回
- 普通中文（`审计报告.pdf`）→ 原样返回（不命中 fragment）
- fragment（`job_id_notes.pdf`）→ 返回固定隐藏标签（不抛错）
- Cc（`line\nbreak.pdf`）→ 返回固定隐藏标签（不抛错）
- Cf（`report‮name.pdf`）→ 返回固定隐藏标签（不抛错）
- 超长 241 字符 → 返回固定隐藏标签（不抛错）

只有 empty/dot/pathful（含 `/` 或 `\\`）才抛 `ValueError`。

**测试验证**：`test_filing_static_admission_accepts_every_canonicalizable_basename` 覆盖全部 6 种输入，
断言 `_admit_fins_upload_file_basename` 不抛错且 canonicalizer 输出符合预期。
