### 1. FinsDirectIngestionRuntime protocol read_job_events 与 S1/S2 contract 一致性

- **入口**: `FinsDirectIngestionRuntime.read_job_events` (fins_direct.py:110-127)
- **直接证据**: Protocol 签名 `read_job_events(job_id: str, *, after_sequence: int = 0, limit: int = FINS_DIRECT_JOB_EVENT_READ_LIMIT)` 与 `FinsIngestionRuntime.read_job_events` (ingestion_runtime.py:1840-1866) 的 `after_sequence: int = 0, limit: int = _DEFAULT_JOB_EVENT_READ_LIMIT` (100) 完全对齐。Protocol 只声明 `FinsIngestionJobEventRecord` 返回类型和 `Exception` raises，未引入 Host/Engine contract 变化。
- **import 边界**: `dayu.service.fins_direct` 新增 import `dayu.fins.ingestion_events.FinsIngestionJobEventRecord` 和 `FinsIngestionJobEventType`，属于 Fins public boundary 内的 event contract，不违反 Service → Fins 的允许依赖方向。
- **结论**: 无反向依赖或 contract 变化。

### 2. FinsDirectJobEvent 类型安全与业务语义

- **入口**: `FinsDirectJobEvent` dataclass (fins_direct.py:200-224)
- **直接证据**: 所有字段均有显式类型注解：`job_id: str`、`sequence: int`、`command_name: str`、`ticker: str`、`status: FinsIngestionJobStatus | None`、`event_label: str`、`message: str`、`payload: Mapping[str, JsonValue]`、`terminal_result: FinsDirectTerminalResult | None`。无 `Any`、`object`、裸容器或无类型签名。`payload` 使用 `Mapping[str, JsonValue]` 而非 `dict[str, Any]`，类型安全。
- **docstring**: 每个 Attribute 均有中文说明，`sequence` 明确说明"合成 terminal fallback 使用本地下一游标"，`status` 说明"普通 progress 可为空"，`terminal_result` 说明"非终态为空"。业务语义自解释。
- **结论**: 类型安全，业务语义清晰。

### 3. stream_job_events_until_terminal sequence/cursor 消费与 terminal 停止

- **入口**: `stream_job_events_until_terminal` (fins_direct.py:513-568)
- **直接证据**:
  - 游标初始化 `cursor = after_sequence` (line 531)
  - 事件读取 `read_job_events(handle.job_id, after_sequence=cursor, limit=...)` (lines 533-537)
  - 事件迭代更新游标 `cursor = event.sequence` (line 540)
  - terminal 判断 `_terminal_result_for_event(event)` 内部调用 `_is_terminal_event_type` 检查 `JOB_SUCCEEDED/JOB_FAILED/JOB_CANCELLED` (lines 579-592, 715-727)
  - terminal event 附带 `FinsDirectTerminalResult` 后 `return` (lines 547-548)
  - 非 terminal 批次读完后 `continue` 继续下一轮 (line 549)
- **结论**: 按 sequence/cursor 正确消费，terminal event 附带终态结果后停止。

### 4. empty read 后 sleep 与 terminal fallback 行为

- **入口**: `stream_job_events_until_terminal` empty read 分支 (fins_direct.py:551-568)
- **直接证据**:
  - empty read 后 `await self._sleep(self.poll_interval_seconds)` (line 551)，复用现有 `poll_interval_seconds` (默认 1.0 秒)
  - sleep 后 `read_job(handle.job_id)` 判断 terminal (line 552)
  - 若 terminal，记录 bounded WARN 并合成 terminal event (lines 554-567)
  - 若非 terminal，循环回到 `read_job_events`
- **tight loop 防护**: empty read 分支必经 `await self._sleep(...)`，不会 tight loop。测试 `test_stream_job_events_sleeps_after_empty_read_before_polling_again` (test_fins_direct.py:521-577) 通过 `sleep_calls` 断言 sleep 被调用且间隔正确。
- **误丢 event**: empty read 时 cursor 未变，下一轮 `read_job_events(after_sequence=cursor)` 会重新读取同一批；若有新 event 到达，它们的 sequence > cursor 会被正确读取。不会误丢。
- **结论**: 行为符合计划，无 tight loop 或误丢 event 风险。

### 5. terminal event 缺失 fallback 行为

- **入口**: `stream_job_events_until_terminal` fallback 分支 (fins_direct.py:552-567)
- **直接证据**:
  - 只在 empty read + `read_job()` 返回 terminal status 时触发
  - `_LOGGER.warning(...)` 只包含 `job_id`、`status.value`、`"missing_terminal_event"` 原因字符串 (lines 555-561)，不输出业务 payload
  - 合成事件 `_synthetic_terminal_job_event` 使用 `FINS_DIRECT_SYNTHETIC_TERMINAL_EVENT_LABEL` 标签 (line 751)，`payload={}` (line 753)
  - 合成事件不写回 store，只 yield 给消费方
- **测试覆盖**: `test_stream_job_events_synthesizes_terminal_after_missing_terminal_event` (test_fins_direct.py:469-518) 断言 WARN 日志包含 `"missing_terminal_event"`、`"job-1"`、`"failed"`，不包含 `failure_summary` 内容 `"boom"`。
- **结论**: bounded WARN，不把 event sidecar 当状态真源，不写回 store。

### 6. read_job_events/read_job failure 透传与 wait_for_terminal 语义

- **read_job_events 透传**: `stream_job_events_until_terminal` 内 `read_job_events` 抛错直接向调用方传播。测试 `test_stream_job_events_propagates_event_store_failure` (test_fins_direct.py:580-589) 断言 `RuntimeError("store failed")` 被正确传播。
- **read_job 透传**: empty read 后 `read_job()` 抛错直接传播。测试 `test_stream_job_events_propagates_unknown_job_after_empty_read` (test_fins_direct.py:592-614) 断言 `LookupError("unknown job")` 被正确传播。
- **wait_for_terminal 语义**: `wait_for_terminal` (fins_direct.py:499-511) 未被修改，保持原有轮询 `read_job()` + sleep + terminal mapping 语义。测试 `test_wait_for_terminal_sleeps_only_for_nonterminal_statuses` (test_fins_direct.py:618-655) 和 `test_terminal_status_exit_mapping` (test_fins_direct.py:658-678) 继续通过。
- **结论**: 异常透传正确，既有语义保持。
