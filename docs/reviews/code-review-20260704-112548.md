### 01-未修复-低-`_cancel_request_event_id_from_cancelling` 在两个模块中重复定义且实现不一致

- **入口/函数**: `engine_ingest.py::_cancel_request_event_id_from_cancelling` (line 5914, 已有) 与 `run_transition.py::_cancel_request_event_id_from_cancelling` (line 6271, 新增)
- **文件(行号)**: `dayu/host/engine_ingest.py:5914-5931`, `dayu/host/durable/run_transition.py:6271-6289`
- **输入场景**: 两个模块各自需要从 `RUN_CANCELLING` EventLog row 的 payload 中提取 `cancel_request_event_id`。
- **实际分支**: `engine_ingest.py` 版本使用 `_required_payload_text(_payload_object(event), field_name="cancel_request_event_id")`；`run_transition.py` 版本使用 `json.loads(event.payload_json)` + `parse_utc_timestamp(event.occurred_at)`。
- **预期行为**: 相同语义的 payload 解析应在同一模块中复用，避免两套实现。
- **实际行为**: 两个私有函数各自独立实现。`run_transition.py` 版本额外校验 `parse_utc_timestamp(event.occurred_at)`，失败时等同 malformed payload 返回 `None`；`engine_ingest.py` 版本不做此校验。此外，`run_transition.py` 版本接受 `EventLogRow | None`，`engine_ingest.py` 版本只接受 `EventLogRow`。
- **直接证据**: diff 中 `run_transition.py` 新增了完整的 `_cancel_request_event_id_from_cancelling` 函数（line 6271-6289），与 `engine_ingest.py` 已有函数（line 5914-5931）为同一语义的不同实现。
- **影响**: 如果 `RUN_CANCELLING` payload 结构未来变更，需要同步修改两处。`occurred_at` 校验差异可能导致 boundary case 下两个模块对同一 EventLog row 做出不同判断。
- **建议改法和验证点**: 将 `_cancel_request_event_id_from_cancelling` 提取到 `run_transition.py` 作为模块级私有函数，`engine_ingest.py` 通过 import 复用。统一使用更保守的校验逻辑（含 `parse_utc_timestamp`），并补一个 malformed payload 单元测试。
- **修复风险（低）**: 仅移动和统一已有逻辑，不改变语义。`engine_ingest.py` 当前版本不含 `parse_utc_timestamp` 校验，合并后行为变严格，需验证现有 cooperative cancel 测试仍然通过。
