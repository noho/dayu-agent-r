## Fixed Findings

### PR50-C-001: Post-commit wakeup must not block durable queue promotion

- Changed `_promote_after_release` so it first calls durable `promote_next_queued_run(session_id)` and only then calls `wake_queue_promotion(session_id)`.
- `wake_queue_promotion` `RuntimeError` is now best-effort after promotion and does not hide the returned `PromotionResult`.
- Durable promotion transaction failures are not swallowed; errors from `promote_next_queued_run` still propagate.
- Promotion dispatch wakeup `RuntimeError` after a successful promotion is also best-effort for the promotion path, so a committed promotion result is not masked.
- Added regression coverage for active cancel, terminal closeout, and the promotion dispatch wakeup path.
