## Adversarial Failure Pass

### 1. 非预期输入

| 场景 | 路径 | 结果 |
|---|---|---|
| `raw_bytes` 为空 `b""` | `BytesIO(b"")` 创建成功，converter 收到空流 | 转换器自行处理空 PDF；stream 隔离不受影响 |
| `raw_bytes` 极大（OOM） | `BytesIO` 构造可能抛 `MemoryError` | `MemoryError` 继承 `BaseException`，不被 `except Exception` 捕获，直接传播；正确 |
| `stream_name` 无扩展名 | `DocumentStream` 接收任意 name 字符串 | Docling 按扩展名判别解析模式；无扩展名时 Docling 自行决定，非本模块责任 |
| `device_name` 为 `None` | `build_docling_pdf_pipeline_options` line 431–432：`resolve_docling_device_name()` | 正确回退到环境变量或 auto |
| `table_mode` 非法 | `build_docling_pdf_pipeline_options` line 416–417：`ValueError` | 在 Docling 依赖装配前 fail-fast |

### 2. 取消/中断

- `KeyboardInterrupt` 和 `asyncio.CancelledError` 继承 `BaseException`，不被 `except Exception` 捕获，直接传播出 attempt loop。正确。
- `run_docling_pdf_conversion` 本身不处理取消信号；取消由上层 `ProcessCnDoclingConversionRunner` 的子进程 terminate/kill 机制覆盖。符合 goal 的 ownership 边界。

### 3. 依赖缺失

- **Docling 完全缺失**：`_build_attempt_converter` → `build_docling_pdf_converter` → `build_docling_pdf_pipeline_options` 中的 `import Docling` 失败，抛 `DoclingRuntimeInitializationError`。此异常在 `run_docling_pdf_conversion` 的 for 循环内但**在 try 块外**（line 549），因此直接传播出 attempt loop，不触发回退。这是既有行为，表示依赖缺失为 hard failure。
- **Docling 部分缺失（converter 模块可用但 `DocumentStream` 不可用）**：`_build_docling_document_stream` 在 lambda 内（line 612–613）抛 `DoclingRuntimeInitializationError`，被 attempt loop `except Exception` 捕获。每个 attempt 都会因 stream 构造失败而失败，最终 `raise last_failure from first_failure`。相比旧代码（在 lambda 外构造 stream 时即失败），新代码多了 attempt loop 的日志噪音，但最终错误信息一致。此路径有 `# pragma: no cover` 保护，属于依赖缺失边缘场景。

### 4. 并发

`convert_pdf_bytes_with_docling` 的 `raw_bytes` 是 immutable `bytes`，每次 attempt 新建 `BytesIO`，无跨 attempt 共享可变状态。函数本身不是 async，也不涉及共享状态。无并发风险。

### 5. 单 attempt 失败路径

`run_docling_pdf_conversion` line 591：当 `first_failure is last_failure`（仅一次 attempt 且失败，或多次 attempt 抛出同一异常对象）时，执行 `raise last_failure` 而不链式 `raise X from X`。此路径未被 core tests 覆盖（auto 模式最少两档），但行为等价于直接 raise，无正确性问题。属于 plan 80% 覆盖策略的可接受 uncovered area。

### 6. 重复调用 / 终态再推进

`convert_pdf_bytes_with_docling` 无状态；每次调用独立执行完整的 attempt 链。无终态概念，无重复调用风险。

### 7. 异常对象 identity 在 Python 异常链中的行为

Python 的 `raise X from Y` 设置 `X.__cause__ = Y`，且 `Y.__cause__` 可被后续 `raise Z from Y` 覆盖。在本代码中，`first_failure` 只被设置一次（line 562–563 的 `if first_failure is None` guard），`last_failure` 每次失败都更新。最终 `raise last_failure from first_failure` 只设置一次 `__cause__`。测试通过 `is` identity 比较验证 `caught.__cause__ is first_failure`，精确且不可被伪造。✓
