## Accepted Findings Verification

### Finding 001 (两轮 review 均提出): read_api projection 路径未经测试覆盖 policy matrix

**原始问题**: Plan 把 typed dataclass 构造测试等价于 read_api 投影路径测试，但 `_host_event_from_row` → `_failed_host_event` / `_cancelled_host_event` / `_lost_host_event` 是独立投影代码路径，需要独立的 EventLogRow→HostEvent 投影断言。

**当前 plan 修复**:
- Slice 1 新增明确要求: "Add direct read API projection tests for `RUN_FAILED`, `RUN_CANCELLED`, and `RUN_LOST` EventLog rows proving their projected `HostEvent.final_answer` is `None`. Dataclass construction tests do not satisfy this requirement because they do not exercise `_host_event_from_row(...)` / read API projection logic."
- Slice 1 allowed files 新增 `tests/host/test_read_api_terminal_policy.py`
- 验证命令包含该新文件

**验证结果**: ✅ **已修复**。Plan 现在明确区分 typed dataclass 构造测试与 read_api 投影逻辑测试，并要求后者。

---

### Finding 002 (两轮 review 均提出): memory.py 使用 payload reader 而非 continuity resolver 的差异未在 plan 中显式说明

**原始问题**: `memory.py` 使用 `assistant_final_answer_text_from_run_payload`（inline only, lenient），`compact_material.py` 使用 `assistant_final_answer_continuity_text`（artifact fallback, strict）。Plan 的 policy table 把它们合并为一行，丢失了设计信号。

**当前 plan 修复**:
- Policy table 拆分为两行:
  - "Compaction material / run input continuity": uses strict assistant final-answer continuity resolver; may fall back from `RUN_SUCCEEDED` descriptor to digest-checked terminal summary artifact `content`
  - "Conversation Memory selected recent window": uses inline `RUN_SUCCEEDED.final_answer` only, leniently; does not follow terminal summary artifact descriptor indirection
- Memory 行明确标注 "must not create evidence-backed facts from terminal summary or assistant final answer"
- Slice 2 要求 "Clarify consumer differences: compaction material / run input use the strict continuity resolver with artifact fallback; memory selected recent window uses the inline run-payload reader only and remains lenient."

**验证结果**: ✅ **已修复**。Consumer 行为差异现在在 policy table、Text handling 和 Slice 2 docstring 中均显式说明。

### Finding 003 (AgentDS 初轮): empty_final_answer 转为 RUN_FAILED 的 governance 决策未在 policy matrix 中显式建模

**原始问题**: `engine_ingest.py` 的 `_final_answer_plan()` 对空 `final_answer` 转投 `RUN_FAILED`，但 plan 未要求测试该路径下 terminal summary 不含 displayable final-answer `content`。

**当前 plan 修复**:
- Slice 1 新增明确要求: "Add or strengthen an `empty_final_answer` ingest test proving Host governance converts empty Engine `final_answer` to `RUN_FAILED` and the terminal summary payload does not contain displayable final-answer `content`."
- Slice 1 allowed files 新增 `tests/host/test_engine_ingest_mapping.py`（已存在，161KB）
- 代码验证: `test_engine_ingest_mapping.py:428` 已有 `test_empty_final_answer_closes_failed_without_run_succeeded`，断言 `payload["error_code"] == "empty_final_answer"`。Plan 要求在此基础上加强 terminal summary 不含 content 的断言。

**验证结果**: ✅ **已修复**。Plan 现在显式要求 empty_final_answer 治理路径的 terminal summary shape 断言。
