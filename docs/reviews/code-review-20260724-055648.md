## Findings

### 1-NEEDS-FIX-中-`build_context_budget_evaluated_payload` 在 validator 前无条件访问 `result.fallback_reason.value`

- **入口/函数**: `build_context_budget_evaluated_payload`
- **文件(行号)**: `dayu/host/context_events.py` diff 中 payload dict 构造 `"fallback_reason": result.fallback_reason.value`
- **输入场景**: Slice 3 实现将来创建一个 `fallback_reason=None` 的 `ContextSizingResult`（例如 anchored path 中 anchor 存在时 `fallback_reason` 为 `None`），随后同一 result 被传入本函数。
- **实际分支**: `result.fallback_reason.value` 在 `None.fallback_reason` 上触发 `AttributeError`，发生在 `parse_context_budget_evaluated_payload(payload)` validator 调用之前。
- **预期行为**: 要么在访问 `.value` 前判空（`None` 时序列化为 JSON `null`），要么在函数开头校验 `result.fallback_reason` 非空并给出明确 `ValueError`。
- **实际行为**: `AttributeError: 'NoneType' object has no attribute 'value'`，不可恢复，调用方无法区分这是合法 anchor result 还是代码缺陷。
- **直接证据**: `build_context_budget_evaluated_payload` 在构造 payload dict 时直接 `result.fallback_reason.value`，其后才调用 `parse_context_budget_evaluated_payload(payload)`（该 validator 只在 `estimate_method=CONSERVATIVE_FALLBACK` 时拒绝 null fallback_reason，但此时 `build` 已 crash）。
- **影响**: Slice 2 当前所有 producer 都确保 `fallback_reason` 非空，因此当前 workflow 不会触发。但 Slice 3 引入 anchored result 后，该函数是公开 API（`__all__` 导出），调用方传入 `fallback_reason=None` 的 anchored result 会静默 crash，破坏 canonical fact 构建的鲁棒性。
- **建议改法和验证点**:
  1. 在访问 `result.fallback_reason.value` 前加 `None` → JSON `null` 的分支；
  2. 或在 `build_*` 开头校验 `result.estimate_method` 与 `result.fallback_reason` 的 invariant（`CONSERVATIVE_FALLBACK` 时必非空，`USAGE_ANCHORED` 时必为空），不一致时抛 `ValueError`；
  3. 新增一个 `anchored result (fallback_reason=None)` 的 roundtrip test。
- **修复风险（低）**: 仅在 builder 入口加校验/判空，不影响 Slice 2 既有行为。
- **严重程度（中）**: 属前向兼容缺口；Slice 2 不受影响但 Slice 3 会直接 crash。

### 2-NEEDS-FIX-低-`parse_context_budget_evaluated_payload` 中 `estimate_method` exhaustive check 对 future enum 分支使用 `else: raise AssertionError`

- **入口/函数**: `parse_context_budget_evaluated_payload`
- **文件(行号)**: `dayu/host/context_events.py` strict parser 内 `if estimate_method is ContextEstimateMethod.CONSERVATIVE_FALLBACK: ... elif estimate_method is ContextEstimateMethod.USAGE_ANCHORED: ... else: raise AssertionError(...)`
- **输入场景**: `ContextEstimateMethod` enum 被 future Slice 3 或外部代码新增第三个成员（例如 `LEARNED_MODEL`）。
- **实际分支**: `else` 分支使用 `AssertionError` 而非 `ValueError`。
- **预期行为**: strict parser 应该对所有 unknown closed enum 成员统一使用 `ValueError`（与其他 `_required_enum` 一致语义），使调用方可以用一个异常类型捕获所有 payload 校验失败。
- **实际行为**: 新 enum 成员落入 `AssertionError`，与通用 `ValueError` 分支不一致，可能被上层 `except ValueError` 漏过。
- **直接证据**: `else: raise AssertionError("context estimate method is not exhaustive")` 行。
- **影响**: 极低——`ContextEstimateMethod` 是两年内固定 closed enum，新增成员的概率很低，且 `AssertionError` 也会被更上层 `except Exception` 捕获。但与模块内其他 exhaustive check（均抛 `ValueError`）不一致。
- **建议改法和验证点**: 改为 `raise ValueError("unknown estimate_method value")`。
- **修复风险（低）**: 仅改异常类型。
- **严重程度（低）**: 极低概率触发，属风格不一致。

### 3-NEEDS-FIX-低-`read_api.py:_context_usage_activity` 内 `_payload_object(row)` 返回类型未显式校验

- **入口/函数**: `_context_usage_activity`
- **文件(行号)**: `dayu/host/read_api.py` `_context_usage_activity` 函数
- **输入场景**: 某个 `event_type=CONTEXT_BUDGET_EVALUATED` 的 row 其 `payload_json` 被外部损坏（不满足 JSON object），`_payload_object` 返回非 mapping 值。

- **预期行为**: 与当前实现相同——fail closed。
- **实际行为**: 正确 fail closed。但 `_payload_object(row)` 的返回类型在函数签名中不显式（依赖 EventLog column 的 JSON 反序列化），代码路径覆盖了异常转换，但缺少显式的 `isinstance(payload, Mapping)` pre-check 作为防御。
- **直接证据**: `_payload_object(row)` 仅在异常分支被间接校验。
- **影响**: 当前行为正确；缺少显式 pre-check 不影响正确性但降低代码可读性。
- **建议改法和验证点**: 在 `parse_context_budget_evaluated_payload` 之前加一行 `if not isinstance(raw, Mapping): raise HostDurableError(...)`（可选）。
- **修复风险（低）**: 仅加 pre-check。
- **严重程度（低）**: 行为正确但不防御。

## Residual Risk

1. **`context_events.py` 模块的局部 durable import**（见 Finding 4）：当前由 implementation artifact 充分证明必要性，但长期是维护负担。未来若 `durable` 或 `api` 模块的重构改变 import 图，局部 import 的函数签名可能因未加载的 `TYPE_CHECKING` 类型而出现隐蔽运行时错误。**建议在后续 work unit 中提取 shared contract 层。**

2. **`build_context_budget_evaluated_payload` 前向兼容缺口**（见 Finding 1）：Slice 3 实现需要显式处理 `fallback_reason=None` 场景。**建议在 Slice 3 开始前修复，而非延后。**

5. **`parse_context_budget_evaluated_payload` 中 `estimate_method` exhaustive check 使用 `AssertionError`**（见 Finding 2），与其他 closed enum checks 不一致。**非阻塞，但建议统一为 `ValueError`。**
