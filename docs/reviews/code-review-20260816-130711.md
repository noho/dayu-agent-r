### 001-未修复-低-repository_protocols.py Protocol 内置 concrete rejection helper 非典型 Protocol 设计

- **入口/函数**: `SourceDocumentRepositoryProtocol.reset_source_document_for_repair()` 与模块级 `_reject_unimplemented_source_repair()`
- **文件(行号)**: `dayu/fins/storage/repository_protocols.py:61-74`, `dayu/fins/storage/repository_protocols.py:706-737`
- **输入场景**: 任何 concrete repository（`FsSourceDocumentRepository`、test fakes）调用 `reset_source_document_for_repair()` 时
- **实际分支**: Protocol 方法体直接调用 `_reject_unimplemented_source_repair()`，该 helper 返回 `NoReturn` 并始终 `raise NotImplementedError`
- **预期行为**: 按 Python Protocol 惯例，Protocol 方法应为 abstract stub（`...`），由 concrete class 提供实现
- **实际行为**: Protocol 提供了 concrete 方法体，concrete class 通过继承获得该行为；pyright 将其视为已实现方法而非 abstract
- **直接证据**: `repository_protocols.py:737` 方法体为 `_reject_unimplemented_source_repair()` 而非 `...`；`fs_source_document_repository.py` 未 override 该方法；pyright 0 errors 验证了此设计满足类型检查
- **影响**: 非典型 Protocol 设计，但属于已批准的 transitional pattern。implementation artifact 已记录动机：避免 concrete repository 和 test fakes 被 pyright 视为 abstract class（初始 129 个 `reportAbstractUsage` 错误），同时避免 inherited stub 静默返回成功。Phase B（Slice 4）将替换为真实实现。
- **建议改法和验证点**: 当前设计是 intentional transitional state，不阻塞。Slice 4 实现真实 repair method 时，应将 Protocol 方法体改回 `...` 并在 concrete class 中 override。reviewer 确认：(1) `_reject_unimplemented_source_repair` 类型签名为 `() -> NoReturn`，不是 `Any`；(2) docstring 明确说明了 transition intent；(3) `NotImplementedError` message 包含 actionable 信息。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

### 1. Fresh reason enum 无旧 alias/re-export，四态 revision/reason invariant 封闭

**结论: PASS**

- `SourceIntegrityReason` 删除了旧 `PHYSICAL_FILE_MISSING`，无 alias、无 re-export、无兼容 shim。
- 9 个 repairable reasons + 9 个 unsafe reasons = 18 个 enum members，与 test `test_source_integrity_public_contract_closes_states_reasons_and_comparison` 断言的 exact tuple 一致。
- 四态 invariant 由 `SourceIntegrityClassification.__post_init__` 强制：
  - `MISSING`: `revision=None, reasons=()`
  - `COMPLETE`: `revision is not None, reasons=()`
  - `REPAIR_REQUIRED`: `revision is not None, reasons ⊆ _REPAIRABLE_REASONS, reasons 非空`
  - `UNSAFE`: `revision=None, reasons ⊆ _UNSAFE_REASONS, reasons 非空`
- reasons 必须按 enum 顺序去重，`__post_init__` 构造 `ordered_reasons` 并比较。

### 2. UNSAFE 在 comparison/preflight 中 fail closed 且不与 MISSING 的 revision=None 相等
