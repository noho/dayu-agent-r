## Findings

### 1-未修复-[中]-terminal fence 与 drain 之间的 TOCTOU 窗口可能导致 late transient 在 terminal 后交付

- **入口/函数**: `_PublicHostHandle._watch_session_events_after` (open_host.py:964–1020)
- **文件(行号)**: `dayu/host/open_host.py:1010-1020`
- **输入场景**: Engine 的 terminal event 与同 Run 的 transient delta 在极短时间窗口内先后到达 ingest pipeline。具体触发序列：merge loop 执行 `drain_nowait()` 排空队列 → 另一个 execution/worker 的 transient delta 通过 `publish()` → `_offer()` 进入 subscription queue（此时 fence 尚未设置）→ `mark_run_terminal()` 设置 fence → `yield event` 交付 terminal → 下一轮循环 `drain_nowait()` 交出已被 fence 的 late transient D。
- **实际分支**: `drain_nowait()` 排空后、`mark_run_terminal()` 前的窗口内到达的 transient 先于 fence 进入 queue，在下一轮迭代被 yield 到 terminal 之后。
- **预期行为**: 同 Run 的 transient delta 应在 terminal 之前交付；terminal 后的同 Run delta 应被 fence 拒绝，永不交付。
- **实际行为**: 在 drain 与 mark 之间的竞态窗口内到达的 transient 会进入 queue，并在 terminal 之后被下一轮 `drain_nowait()` yield，形成"terminal → late transient"的倒序交付。
- **直接证据**:
  - `_offer` 的 terminal fence 检查在 `put_nowait` 之前（transient_delta.py:329），drain 时 fence 未设置所以通过 → 进入 queue
  - `mark_run_terminal` 在 drain 之后（open_host.py:1019），存在 TOCTOU 间隙
  - 下一轮 while 循环顶部的 `drain_nowait()`（open_host.py:985）会取出 queue 中已被 fence 的 item D
- **影响**: 消费者（Service/CLI）可能在 terminal answer 之后看到同 Run 的 thinking delta，破坏"thinking→answer"的用户可见顺序。在正常 Engine 事件流中概率极低（terminal 是 Engine 事件的最后一个），但并发 ingest 场景下理论上可能发生。
- **建议改法和验证点**: plan §12.1 已识别此风险并计划用 Slice 2 的 deterministic barrier 测试覆盖线性化边界。当前 Slice 1 的实现结构正确（drain→mark→yield），只是 drain 和 mark 之间缺少原子性。Slice 2 应通过 barrier 测试精确量化窗口并决定是否需要额外同步（如在 drain 后、mark 前再次检查 `_is_ready` 并重新 drain）。不建议在 Slice 1 引入锁或额外同步。
- **修复风险（中）**: 任何在 drain/mark 之间加的锁或重检查都可能引入 publish 路径的阻塞风险，违反 hub publish 必须 non-blocking 的架构约束。
- **严重程度（中）**: 仅在并发 ingest 的极端时序下触发，正常单 worker 流中 Engine 保证 terminal 在所有 delta 之后；影响范围限于单个 watcher 的单次 Run 的展示顺序，不破坏 durable state、不丢 terminal、不泄露资源。

## 专项检查结果汇总

### 1. Public dataclass discriminator/data strictness、UTC/identity/sequence validation、package exposure

**通过。** `HostTransientDelta.__post_init__`（api.py:3017–3054）对 runtime_id 非空、runtime_sequence 正整数、全部 identity 非空、worker_event_index 正整数、observed_at UTC、type 枚举、data 与 discriminator 严格对应（通过 `HOST_TRANSIENT_DELTA_TYPE_TO_DATA` mapping）、dedupe_key 非空均做严格校验。三种 payload dataclass（`HostContentDelta`、`HostReasoningDelta`、`HostToolCallDelta`）各自校验 iteration_id 非空与字段类型。`ValidatedTransientDeltaCandidate.__post_init__`（transient_delta.py:137–170）复用 `HostTransientDelta` 构造做 defense-in-depth 校验。Package exports（`__init__.py`）正确导出所有 public 类型，不导出内部 hub/subscription 类型。

### 2. HostTransientDeltaHub/subscription 的 runtime sequence、same-envelope multi-watcher、no-replay、overflow 连续前缀、detach/close、terminal fence、readiness

**通过。** Hub 在 `publish()` 中分配一次 `runtime_sequence`、构造一个 immutable `HostTransientDelta`，对 subscription snapshot 做 `put_nowait` fanout（transient_delta.py:434–464）。同 envelope 实例被多个 watcher 共享（`is` identity）。queue 满时标记 overflow 并 detach 慢 watcher，保留已接受的连续前缀，其它 watcher 继续。`wait_ready` 使用 level-triggered readiness（基于 `_is_ready()` 的 queue 非空/overflow/closed 检查），clear/set 前后均有 recheck（transient_delta.py:260–283）。detach 幂等（`close()` → `_hub._detach()`），hub close 唤醒全部 watcher（`_close_from_hub()`）。terminal fence 在 `_offer` 入口检查（transient_delta.py:329），drain 时过滤（transient_delta.py:255）。**已知风险**：drain 与 mark_run_terminal 之间的 TOCTOU 窗口（见 Finding 1）。

### 3. watch_session_events attach-before-return 的显式 closable iterator

**通过。** `watch_session_events`（open_host.py:905–929）在同步方法内：1) `_raise_if_closed()` gate；2) `hub.subscribe()` 注册；3) try/except 包裹 cursor future submit，失败回滚 subscription.close()；4) `add_done_callback(_observe_watch_cursor_future)` 确保 cursor future 被观察；5) 返回 `_ClosableHostSessionEventIterator`（拥有 subscription + cursor_future）。`_ClosableHostSessionEventIterator`（open_host.py:1194–1283）：`__anext__` 首次调用时 lazy 创建 generator，`cursor_future` 在 `_watch_session_events` 内 await；任何 `BaseException` 触发 `aclose()`；`aclose()` 幂等，处理 started 和 never-started 两种情况（finally 中 `subscription.close()`）。`_observe_watch_cursor_future`（open_host.py:1178–1191）通过 `future.exception()` 观察异常，不消费异常（后续 await 仍能抛出），防止 never-started iterator 的 "unhandled future exception" 告警。

### 4. durable/transient merge 的两域内序、terminal-before-buffer race、其它 Run 继续、polling/starvation

**通过（已知 TOCTOU 风险见 Finding 1）。** `_watch_session_events_after`（open_host.py:964–1020）保持双域各自内序：每轮迭代先 drain transient → 检查 overflow/closed → poll EventLog → 再次 drain transient → 对同 Run terminal 前 drain、后 mark_run_terminal、再 yield terminal。Poll interval 为 20ms（`_SESSION_WATCH_POLL_INTERVAL_SECONDS = 0.02`），使用 level-triggered `wait_ready` 而非纯 sleep，publish 时 `_ready.set()` 立即唤醒。Terminal fence 只影响同 Run，其他 Run 继续。无 EventLog 事件且无 transient 时，循环以 50Hz 轮询 EventLog（返回空 batch 后回到 wait_ready），CPU 开销可接受。

### 5. ingest validation transaction COMMIT 后 publish

**通过。** 时序：`_ingest_before_reactive_compaction` → `run_write(_IngestValidatedOperation)` → transaction 内 `_ingest_validated` 检查 `_is_transient_delta_event` → `_validated_transient_delta_candidate` 构造 candidate → `_accepted_no_event_result` 返回 `events=()`、`transient_delta=candidate` → transaction COMMIT → 返回 `_finish_ingest` → `promoted.transient_delta is not None` → `_publish_transient_delta`（engine_ingest.py:871–875）。Rollback/exception 无 result 无 publish。Stale/late/wrong identity 在 `_validate_durable_context` 返回 None → `_append_rejected_diagnostic` 的 `transient_delta=None`。Publisher 异常被 `_publish_transient_delta` 完全隔离，记录不含 delta 文本/secret 的 sanitized diagnostic（engine_ingest.py:5276–5302）。所有构造点显式传递 `transient_delta_publisher`（scheduler `__init__`/`open`、ingestor `__init__`），无 optional/default。

### 6. scheduler/open_host 必填 publisher wiring 与所有构造点

**通过。** Composition root（open_host.py:1460–1540）：`HostTransientDeltaHub()` 创建 → `HostDispatchScheduler.open(..., transient_delta_publisher=transient_delta_hub)` → `_PublicHostHandle(..., transient_delta_hub=transient_delta_hub)`。Hub 作为 publisher port（实现 `HostTransientDeltaPublisher` Protocol）传给 scheduler，同时作为 watch 的 subscription owner 传给 public handle。Open 失败时 `transient_delta_hub.close()` 清理（open_host.py:1549）。所有测试中 scheduler/ingestor 构造均显式传入 `NOOP_TRANSIENT_DELTA_PUBLISHER` 或 recording/failing variant。

### 7. Service public union 穷举、三个 live queue 单一 bounded owner、terminal-only 排除

**通过。** 三处 union 消费点均有 `assert_never` 穷举守卫：
- `_drain_available_watcher_items`（entrypoint_runtime.py:1181–1212）：`_WatcherFailure` / `HostEvent` / `HostTransientDelta` → `assert_never(item)`
