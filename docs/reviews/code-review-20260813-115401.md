### 2-未修复-中-prepare 期前置条件冲突被分类为 STORAGE_IO/UNEXPECTED_RUNTIME，可行动语义丢失

- **入口/函数**: `run_upload_filing_stream`（sec_upload_workflow.py:282-283）、`cn_pipeline.py upload_filing_stream` 的 `except Exception → fins_upload_failure_from_exception`

- **输入场景**: 并发状态竞争（recheck 后 source 出现 → create 触发 `FileExistsError`）或非 CLI 直接 facade 调用（stale company 缺 name → `upsert_company_meta_for_upload` 抛 `ValueError`）

- **实际行为**: 冲突呈现为存储 I/O 失败或通用 runtime 失败，用户无法据此修正输入
- **直接证据**: `tests/fins/test_sec_pipeline_upload_filing_stream.py:450-459`——`test_upload_filing_stream_stale_company_meta_requires_company_name` 断言从 `"--company-name" in str(failed_result["message"])` 被弱化为断言通用 `unexpected_runtime` 文案；该测试直接固化偏离
- **影响**: 失败可行动性丢失；测试弱化固化错误语义（违反 AGENTS.md 测试不得固化偶然行为）
- **建议改法和验证点**: 修复 finding 1 后该路径对 filing 仅剩并发竞争；竞争拒绝应保持 typed conflict 语义（在 workflow 内以既有 closed code 投影或由 batch owner fail closed），material 路径需显式保留既有 message 可行动性；恢复 owner 级断言（typed failure 对冲突场景给出可行动提示，而非通用 runtime 文案）
- **修复风险（中）**: 需避免为 material 事务新增行为变化
- **严重程度（中）**: BLOCKED（与 finding 1 同源，可合并修复后复评）
