### S1-2: current input anchor 不再静默截断

Plan S1 要求删除 current input 的私有字符上限和截断标记，使 LLM-facing text 不被静默缩短。

直接证据：

- 删除 `CURRENT_INPUT_ANCHOR_TEXT_MAX_CHARS = 1200`（原行 88-89）。
- 删除 `_CURRENT_INPUT_TRUNCATED_MARKER`（原行 92）。
- `_current_input_anchor`（行 2367-2374）：`anchor_text = normalized_material_text(current_input_text)`，不再按字符上限截断。`truncated` 固定为 `False`。`content_digest` 基于完整 `anchor_text` 计算。
- `__all__` 中删除 `CURRENT_INPUT_ANCHOR_TEXT_MAX_CHARS` 导出（行 3424）。

`CurrentInputAnchor.truncated` 是 Host 内部 dataclass 字段，LLM-facing `CurrentInputAnchor` schema 只有 `anchor_label` 和 `text`，不暴露 `truncated`。固定 `False` 不影响 LLM-facing contract。

测试证据：`test_compact_material.py:960-990` 构造长文本 `"current " + ("segment " * 400)`（约 3208 字符），断言 `anchor_text == expected`（完整规范化文本）且 `truncated is False`。

设计对齐：design.md 24.2 节禁止"字段级 silent truncation、preview 化或 summary 化"，要求"完整选中 material / item / section 的可读内容"。当前 input 超长时由 Context Governance 的 reactive compact / fallback 收口（design.md 25 节），不在 material builder 层截断。

### S1-3: oversized session summary 和 evidence fact 整体丢弃 + diagnostic

Plan S1 要求删除 `_bounded_text`，对超出 char cap 的 session summary 和 evidence fact 做 whole-item drop 并记录 budget diagnostic。

直接证据：

**session summary**（`memory.py:1715-1747`）：
- 旧逻辑：`text = _bounded_text(_required_str(...), policy.session_summary_char_cap)` — 静默前缀截断。
- 新逻辑：`text = _required_str(summary, _PAYLOAD_FIELD_SUMMARY_TEXT)`；若 `len(text) > policy.session_summary_char_cap`，返回 `_empty_session_summary_memory()` + `_budget_diagnostic(message="session summary dropped by memory policy")`。
- 返回类型从 `SessionSummaryMemoryView` 改为 `tuple[SessionSummaryMemoryView, tuple[MemoryDiagnostic, ...]]`。

**evidence facts**（`memory.py:1750-1850`）：
- 旧逻辑：`claim_text = _bounded_text(_required_str(...), policy.evidence_fact_char_cap)` — 静默前缀截断。
- 新逻辑：`claim_text = _required_str(fact, _PAYLOAD_FIELD_CLAIM_TEXT)`；若 `len(claim_text) > policy.evidence_fact_char_cap`，`append(_budget_diagnostic(...))` 后 `continue`（跳过该 fact）。
- 返回 diagnostics 从固定 `()` 改为 `tuple(diagnostics)`。

`_bounded_text` 函数整体删除（原行 2963-2973）。`_empty_session_summary_memory()` 是新增的构造空 view 辅助函数（行 1853-1865）。

调用点 `project_conversation_memory_event`（行 1253-1260）正确接收新增的 `summary_diagnostics` 并合并到 `diagnostics`。

测试证据：
- `test_accepted_compact_drops_oversized_fact_without_prefix_text`（`test_memory_projection.py`）：`evidence_fact_char_cap=8`，长 claim `"这是一条超过上限且不能被前缀截断的完整事实。"`，断言 facts 为空且前缀文本不在结果中，`BUDGET_LIMIT_REACHED` diagnostic 存在。
- `test_accepted_compact_drops_oversized_summary_without_prefix_text`（`test_memory_projection.py`）：`session_summary_char_cap=8`，长 summary，断言 `summary_text is None`，`BUDGET_LIMIT_REACHED` diagnostic 存在。
- `test_accepted_compact_limits_evidence_facts_and_records_budget_diagnostic`（既有测试，docstring 更新为"整体丢弃"）：`evidence_fact_item_cap=1`，断言 item cap 截断行为不变。

## Residual Risk

1. **S1 不含 S2 turn-group selector**：`turn_group_id` 已透传到 material block，但 S2 的 selected recent window turn-group floor 保护算法尚未实现。S1 改动不阻碍 S2——字段已就位，S2 只需在 selector 中消费它。

2. **S1 不含 S3 provenance guards**：compact input / ordinary RunInput / fallback RunInput 的 selected-id provenance 一致性检查属于 S3。S1 改动不阻碍 S3。

3. **answer_anchors / forward_intents / reference_continuity 未做 char cap whole-drop**：这三个 section 的 `_answer_anchors_from_accepted_event`、`_forward_intents_from_accepted_event`、`_reference_continuity_from_accepted_event` 原本就未使用 `_bounded_text`，而是通过 `_limit_items_by_count_and_chars` 做 item-level 整体选择。S1 范围正确限定在 session_summary 和 evidence_facts 两个曾有 silent truncation 的路径。

4. **continuity messages 不携带 `turn_group_id`**：`build_run_input_material_blocks` 中 continuity message block 的 `turn_group_id` 保持默认 `None`。设计允许 stable semantic block 为 `None`。S2 实现 turn-group floor 时需确认 continuity messages 的归属策略。
