### 2.1 C-R1：typed initial disposition 保留 explicit update identical stable skip

**验证结论：已修复，plan 规格正确。**

逐条核对：

- **predicate A（stable retransmission preservation）** §7.3.A 明确要求 `read_prepared_filing_initial_skip_disposition(prepared) is FilingInitialSkipDisposition.IDENTICAL_PUBLICATION`，但不限制 raw action 为 `auto`。§7.3 末段："该分支不限 raw action 为 `auto`；它精确保留现有 `_can_skip_upload` 能够判定的 sequential identical skip，特别包含 explicit `update` + `overwrite=False`。"
- **`_can_skip_upload` 语义同源**：代码 `:1289` `if overwrite: return False`；`:1291` `if require_source_meta_is_deleted(previous_meta): return False`；`:1293-1296` 指纹比较。因此 explicit `update` + `overwrite=False` + 非 deleted + 指纹 identical → `_can_skip_upload` 返回 True → disposition 为 `IDENTICAL_PUBLICATION`。与 predicate A 完全匹配。
- **changed COMPLETE→COMPLETE 不会误 skip**：§7.4 封闭表第 8 行明确 "observation changed → `SOURCE_PUBLICATION_CONFLICT`；即使 identity exact equal 也不得冒充 stable 重传或 MISSING 收敛"。§7.3 末段："changed `COMPLETE -> COMPLETE` 即使 prepared/durable exact equal 也不是 B；显式 `update` changed 也不是 B，固定 typed conflict。" predicate B 要求 `MISSING -> COMPLETE`，COMPLETE→COMPLETE 根本不进 B。
- **`_can_skip_upload` 对 `overwrite=True` 返回 False**：`:1289` `if overwrite: return False`，因此 `auto` + `overwrite=True` 的 disposition 固定为 `NOT_ELIGIBLE`，不会被 predicate A 误匹配。

**直接证据链**：`_can_skip_upload(:1286-1296)` → `FilingInitialSkipDisposition`（§6.3）→ predicate A（§7.3.A）→ §7.4 表第 6-8 行。完整闭合。

### 2.2 C-R1 续：explicit create/no-overwrite conflict 与 create-overwrite fresh rebase

**验证结论：已修复，owner 正确，版本不使用 stale plan。**

- **explicit create + `overwrite=False` → conflict**：§7.4 表第 4 行："其它情况，含 explicit `create` + `overwrite=False` ... → `SOURCE_PUBLICATION_CONFLICT`；explicit create failed terminal 保持 `create/create`"。§6.4 映射表第 1 行确认 failed terminal 的 `requested_action` 始终取 raw request，`resolved_action/filing_action` 取 initial prepared action。owner 清晰：conflict 路径不改写 action。

**直接证据链**：§6.3 rebase helper → §7.4 表第 3 行 → §7.1.8 "MISSING -> COMPLETE explicit create-overwrite branch 先经 Docling owner helper 以 fresh previous meta 重绑" → storage commit path。
