### 1.5 New `_compaction_trigger_source_for_compacted_event` function

The second-read provider historically didn't know whether the compact was PROACTIVE or REACTIVE because it only read `CONTEXT_COMPACTED` (which doesn't carry trigger_source). Now it reads the prerequisite `CONTEXT_COMPACTION_REQUESTED` event via `operation_id` to recover the trigger source and set `source_snapshot.trigger_source` correctly.

| Step | Implementation |
|------|---------------|
| Read `compacted_event.payload["operation_id"]` | `_required_text_field(compacted_payload, "operation_id")` |
| Read `CONTEXT_COMPACTION_REQUESTED` by that id | `EventLogStore().read_event_by_id(transaction, operation_id)` |
| Validate event type | `requested_event.event_type != CONTEXT_COMPACTION_REQUESTED` → `HostDurableError` |
| Extract `trigger_source` | `_required_text_field(requested_payload, "trigger_source")` |
| Parse enum | `ContextCompactionTriggerSource(trigger_value)` → `ValueError` → `HostDurableError` |

This is a necessary addition — without it, `source_snapshot.trigger_source` would be wrong for reactive compacts, which would cause `_segment_trigger(source_snapshot.trigger_source)` inside `build_normal_compact_request_plan` to produce wrong `CompactSegmentTrigger`. This function closes a provenance gap that was implicit in the old code (old code used `pending.display_text` and `pending.frozen_material_blocks` with hardcoded REACTIVE assumption).

### 3.2 Test fixture update: `_append_current_run_compacted_event`

Now writes a `CONTEXT_COMPACTION_REQUESTED` event before `CONTEXT_COMPACTED`, with `trigger_source=PROACTIVE`. The `_compact_payload` function accepts `operation_id` to link the events.

This is a **realism improvement**: production always has `CONTEXT_COMPACTION_REQUESTED` → `CONTEXT_COMPACTED` as an event pair. Old tests omitted the request event because the old code didn't need it. New code reads `trigger_source` from the request event — tests now model the real event topology.

**Risk assessment**: If any existing test calls `_compact_payload` without passing `operation_id`, it gets the default `"event-compact-requested"` which won't match any real `CONTEXT_COMPACTION_REQUESTED` event. The `_compaction_trigger_source_for_compacted_event` would fail with `HostDurableError`. But the only caller that uses `_compact_payload` alongside `_append_current_run_compacted_event` is `_append_current_run_compacted_event` itself (which sets `operation_id=request_event_id`), so the link is consistent. Other callers of `_compact_payload` (for non-raw-tail tests) don't go through the raw-tail provider path.
