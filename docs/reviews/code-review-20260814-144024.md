## Findings

### 1-未修复-低-`parse_iso_calendar_date` 的 isoformat round-trip 断言在当前实现下恒真，是不可达防御分支

- **入口/函数**: `parse_iso_calendar_date`
- **文件(行号)**: `dayu/fins/domain/filing_semantics.py:391-392`（`if parsed.isoformat() != value: raise ...`）
- **输入场景**: 任意合法输入，如 `"0001-01-01"`、`"0999-12-31"`、`"9999-12-31"`。
- **实际分支**: `_STRICT_ISO_CALENDAR_DATE_PATTERN.fullmatch`（51-55 行）已强制 `[0-9]{4}-[0-9]{2}-[0-9]{2}` 精确 shape；`datetime.date(...)`（384-388 行）已成功构造真实公历日期；随后 391 行 round-trip 比较。
- **预期行为**: 若存在"构造成功但 isoformat 输出与输入不一致"的输入，该分支应拒绝它。
- **实际行为**: 该分支永不触发。反例构造失败：regex 保证输入恒为 4-2-2 位 ASCII 数字；本机验证 Python 3.11 `date.isoformat()` 对 year `1/999/1000/9999` 均输出 4 位补零 `YYYY-MM-DD`（`date(1,1,1).isoformat() == "0001-01-01"`），因此 `parsed.isoformat() != value` 恒为 False。
- **直接证据**: coverage missing lines 精确包含 392 行（`coverage report -m`：`Missing ... 379, 392 ...`），证明该 raise 从未被执行。
- **影响**: 仅维护认知成本——不可达断言看似"二次校验"；它防御不了任何当前可构造输入。**不构成 correctness defect**：该 round-trip 是 accepted plan §5 的明确要求（"使用 `datetime.date` 构造并要求 round-trip `isoformat()` 与输入完全相同"），实现与 plan 一致，属于防未来 `date/isoformat` 行为漂移的有意防御。
- **反例**: 不存在可让 392 行执行的输入（在 regex 与 `date()` 构造成功的前提下）。
- **建议改法和验证点**: 保留实现不动（plan 要求），在 391 行补一行中文行内注释说明"防御标准库 isoformat 行为漂移，当前 regex+date 构造下为恒真断言"；验证点：注释后重新跑三文件 pytest 与 coverage，行为不变。
- **修复风险（低）**: 仅注释变更。
- **严重程度（低）**: 不可达防御分支的可维护性说明缺失，无行为错误。

### 2-未修复-低-year 范围文案 "1000..9999" 与 bounds 常量不同源，两处硬编码

- **入口/函数**: `parse_calendar_year`、`normalize_fiscal_year`
- **文件(行号)**: `dayu/fins/domain/filing_semantics.py:360`、`417`（两处 `f"{field_name} 必须是 1000..9999 的整数"` 字面量）
- **输入场景**: 未来某次需求将 year bounds 调整为其它闭区间（当前无此需求）。
- **实际分支**: message 字符串在 360、417 两处独立硬编码，与 `_MIN_CALENDAR_YEAR`（45 行）/`_MAX_CALENDAR_YEAR`（48 行）常量无任何构造关系。
- **预期行为**: 同一业务事实（year 合法范围）只由常量这一份真源派生，包括用户可见文案。
- **实际行为**: 合法范围这一事实现在存在三处字面量（两个常量 + 两处相同 message）；若只改常量不改 message，行为与对外文案会静默漂移，且无任何测试能捕获（现有测试 match 的是字面量本身）。

- **影响**: 仅维护风险；当前行为与 accepted plan §5 的 exact message 完全一致，不算正确性缺陷。
- **反例**: 把 `_MAX_CALENDAR_YEAR` 改为 `99999` 并只更新 354-359 行条件后，非法输入的错误文案仍声称 `1000..9999`，用户不可见真实合法域。
- **建议改法和验证点**: 模块级增加由常量构造的范围描述（如 `_CALENDAR_YEAR_RANGE_DESC = f"{_MIN_CALENDAR_YEAR}..{_MAX_CALENDAR_YEAR}"`），360/417 两处 message 改为引用该描述（两处同源）；现有 message match 测试无需改动即可验证等价性。该建议同时满足 AGENTS.md "禁止魔法数字、魔法字符串"。
- **修复风险（低）**: message 最终文本不变，全部现有测试应保持通过。
- **严重程度（低）**: 文案与真源漂移风险。
