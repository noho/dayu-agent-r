## 3. Findings

### 01-未修复-[高]-frozen PTY owner leaf 未进入 run-owned no-symlink/containment gate

- **位置**: plan 第 50-55、121-124 行；driver `_execution_identity()` 第 606-611 行、`_validate_real_paths()` 第 929-1029 行、`main()` 第 1126-1175 行。
- **问题类型**: 契约缺失 / 架构边界 / 测试缺口。
- **当前写法**: plan 承诺所有 run-owned existing lexical components（包括 leaf）在任何读取、写入或 spawn 前执行 `lstat` no-symlink 与 root containment。driver 的 path 集合覆盖 allocation/global/chain deadline、harness、segment prompt、workspace/evidence/wrapper，但没有覆盖 frozen harness 实际导入的 PTY owner 文件；execution identity 只对 `harness.parent / PTY_OWNER_NAME` 读取 SHA。
- **反例/失败场景**: 在合法 direct-child synthetic run root 中放置正常 frozen harness，并让其同目录的 PTY owner leaf 成为指向 run root 外、但内容恰好为冻结 owner bytes 的 symlink。当前 path gate 接受，execution identity 跟随 symlink 后得到期望 SHA 并接受；instrumented real control flow继续到 `emit=1`、`spawn=1`。冻结 harness 源码直接 `import prompt_observe_calibration_frozen as owner`，因此该 leaf 是实际被执行的 run-owned dependency，不是 repo/CLI location non-goal。
- **为什么有问题**: SHA 证明 bytes identity，但不能履行 plan 已确认的 lexical ownership/containment 义务。该遗漏允许一个被执行的 run-owned code leaf逃逸 canonical run tree，也使“所有 leaf symlink 写前拒绝”的 formal preflight 声明不真实。只保护 harness 文件而漏掉其直接执行 owner，会在同一 owner boundary 留下绕过路径。
- **直接证据**:
  - driver 第 607 行读取 frozen PTY owner SHA，但第 929-939 行 `checked_paths`、第 975-984 行 `expected_paths`、第 1014-1023 行 existing-file containment 均未包含该 owner leaf。
  - frozen harness 第 19 行直接导入该 owner module。
  - provider-free 直接反例结果：`pty_owner_leaf_symlink ACCEPTED emit=1 spawn=1`；随后使用真实 detached target、production CLI、frozen harness bytes 与 frozen owner bytes 调用实际 path gate + execution identity，结果仍为 `ACCEPTED`，owner resolved path 位于 run root 外。测试将 `_emit`/subprocess 替换为计数器，实际 projection/evidence 均未创建、provider 未启动。
- **影响**: formal execution identity 与 durable path ownership 不一致；run-owned executable dependency 可越过 trusted root，RR3 finding 未被完整关闭，formal pre-provider gate 不可验收。
- **建议改法和验证点**:
  1. 在唯一 path owner 中派生 `pty_owner = controller / PTY_OWNER_NAME`，把它加入 exact expected layout、lexical no-symlink、existing regular file 与 resolved-root containment；execution identity 复用这个已验证路径计算 SHA。
  2. 增加 provider-free 反例：PTY owner regular frozen file 正例通过；指向 root 内/外、存在或 dangling 的 owner leaf symlink均在任何 owner bytes读取、projection 与 spawn 前失败，并断言 `emit=0/spawn=0`。
  3. 不改变 repo/CLI 的既有 target/clean/SHA contract，也不把 machine-local canonical parent写入 plan/public artifact。
- **修复风险（低/中/高）**: 低。
- **严重程度（低/中/高/严重）**: 高。
