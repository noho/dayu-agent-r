## Findings

### 1-未修复-中-reset+create 路径重置 source meta `created_at`，与同库既有“首入库事实保持稳定”语义漂移

- **入口/函数**: `DoclingUploadService._store_upload_assets` → `_create_source_document` → storage `_upsert_source_document(is_create=True)`
- **文件(行号)**:
  - `dayu/fins/pipelines/docling_upload_service.py:477-488`：S2 把 reset 扩展到任一 `action == "update"`（不再依赖 overwrite），reset 后统一走 create；
  - `dayu/fins/pipelines/docling_upload_service.py:772-785`：`_build_upsert_meta` 只从 `previous_meta` 派生 `first_ingested_at`，未派生 `created_at`；
  - `dayu/fins/storage/_fs_source_document_core.py:1682,1701`：reset 后 `meta_path` 不存在 → `previous_meta = {}` → `merged_meta.setdefault("created_at", now)` 重新触发。
- **输入场景**: 任一 existing full-input changed update（同名 changed、改名 update、deleted→auto/update restore）在 S2 路径上进入 reset→create。
- **实际分支**: `replace_existing=True` → 同 batch `reset_source_document` → blob-first → `create_source_document`（storage `is_create=True`）。
- **预期行为**: 完整替换只替换文件集合与内容事实；“首次入库”类事实保持稳定。plan §5.2 已明确 version 与 `first_ingested_at` 由 reset 前 `previous_meta` 唯一派生；同库其他 owner 对 `created_at` 的语义同样是“一旦存在就保持稳定”——`sec_download_source_upsert.py:216-217`（注释原文：`` `first_ingested_at` 和 `created_at` 一旦存在就应保持稳定，避免重拉覆盖历史首入库时间``）、`cn_download_source_upsert.py:269`、`sec_rebuild_workflow.py:374`（`created_at = str(previous_meta.get("created_at", "")).strip() or first_ingested_at`）。
- **实际行为**: 同一份 meta 内两个“首次”字段出现不同语义：`first_ingested_at` 保持，`created_at` 被重置为本次替换时间。实测复现（真实 FS 仓储、真实 service 路径、tmp 目录）：renamed update 前后 `first_ingested_at` 相等，`created_at` 由 `2026-08-13T10:45:12+00:00` 变为 `2026-08-13T10:45:14+00:00`。对照 base 版本：非 overwrite update 走 `update_source_document`（`is_create=False`），storage `_upsert_source_document` 读到既有 meta，`setdefault` 不触发 → `created_at` 保持；S2 diff 把该漂移从“仅 overwrite=True 路径”扩散到全部 changed update 主路径，属于当前 diff 新增恶化。
- **直接证据**: 上述三处行号 + 实测输出（`created_at preserved: False`）；S2 新增测试 `test_execute_upload_existing_full_input_replaces_exact_complete_set` 只断言 `first_ingested_at`，未断言 `created_at`，漂移无测试守护。
- **影响**: durable source meta 事实语义漂移：同一 filing 的 `created_at` 从“首次创建时间”变为“最近一次替换时间”。下游 `sec_rebuild_workflow` / download owner 会继承重置值，processed/摘要投影（`DocumentSummary.created_at`）经 rebuild 后可能显示错误首建时间；违反 CLAUDE.md「durable state 中同一业务事实必须从同一真源派生并保持一致」。当前无功能故障，属 medium。
- **建议改法和验证点**: 在 `_build_upsert_meta` 从 `previous_meta` 派生 `created_at`（与 `first_ingested_at` 同模式，`previous_created_at or now`），保持在 owner boundary 内修复；owner test 对 renamed update 与 deleted restore 增加 `created_at` 保持断言，并复核 material parity 用例。
- **修复风险（低）**: 单函数 + 单断言，不改变 storage 协议、batch 时序或 admission 决策。
