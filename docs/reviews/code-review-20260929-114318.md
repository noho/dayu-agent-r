### 001-未修复-中-ValidatedFinsUploadMaterialRequest 缺少跨字段不变量校验，typed handoff 可携带互相矛盾的 request/selection/plan
- **入口/函数**: `ValidatedFinsUploadMaterialRequest`（`dayu/fins/ingestion_runtime.py:1404-1409`）；下游消费点 `FinsIngestionRuntime._validate_runtime_upload_request`（`ingestion_runtime.py:4615-4617`）、`sec_upload_workflow.run_upload_material_stream`（`sec_upload_workflow.py:461` 与 `:478`）、`cn_pipeline.upload_material_validated_stream`（`cn_pipeline.py:1088` 与 `:1107`）
- **文件(行号)**: `dayu/fins/ingestion_runtime.py:1404`；对照 `ValidatedFinsUploadFilingRequest.__post_init__`（`ingestion_runtime.py:718-757`）
- **输入场景**: 任何调用方直接构造 `ValidatedFinsUploadMaterialRequest(request, file_selection, asset_plan)` 且三个字段互不一致，例如 `file_selection.files` 有 2 个路径而 `asset_plan.ordered_pairs` 有 3 个，或 delete 请求携带非空 `file_selection` 但空 plan；或 raw `request.files` 数量与 selection 不符。
- **实际分支**: `_validate_runtime_upload_request` 对 validated material 直接 `return request`（4615-4616）；workflow 中 `file_list = list(request.file_selection.files)`（事件/`file_count`/摘要来源）与 `selection = request.asset_plan`（转换与发布来源）各自独立取字段，无交叉校验。
- **预期行为**: 不可变 handoff 类型应像 filing 同伴类型一样在 `__post_init__` 自证不变量：plan 的 `ordered_pairs` 路径与 `file_selection.files` 保序一致、material 的 `converter_pairs is ordered_pairs`、`filing_primary_original_name is None`、delete ⇔ 三者同时为空。
- **实际行为**: 三个字段无 owner 级一致性约束，工厂 `admit_fins_upload_material_request`（1412-1448）是唯一保证一致的地方；手工/未来构造可使事件与 `file_count` 报告 N 而仓储发布 M，或 delete 事件报告非零 requested 而空 plan 通过 `docling_upload_service._prepare_upload_asset_plan` 的 plan-only emptiness 检查。
- **直接证据**: material 类定义仅 3 个字段无 `__post_init__`（1404-1409）；filing 类同文件 718-757 有完整 `__post_init__`（含 `_validate_filing_selection_matches_request`）证明该边界预期模式；`_validate_filing_selection_matches_request` 的存在（`ingestion_runtime.py:~930-943`）表明项目把“selection 与 raw request 一致”视为 validated 类型自证责任。
- **影响**: 当前生产调用链只经工厂构造，暂无直接可触发的错误事实；但类型是 public（`fins_direct.py` protocol、SEC/CN public 方法签名均接收它），任何绕过工厂的调用（含测试替身、未来 Service/Runner 实现）都会让 summary/事件与持久化事实分叉，属于 typed handoff 边界失守。
- **建议改法和验证点**: 在 `ValidatedFinsUploadMaterialRequest.__post_init__` 中校验 selection/plan/request 三方一致（路径保序相等、converter/primary/delete 空状态约束），错误用 `ValueError` fail closed；补一个不一致构造被拒的 owner 测试。验证点：新测试 + 全矩阵回归。
- **修复风险（低/中/高）**: 低（纯增量校验，工厂产物天然满足）。
- **严重程度（低/中/高/严重）**: 中。
