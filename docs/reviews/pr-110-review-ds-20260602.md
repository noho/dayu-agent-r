### Finding 04 — PASS: WU-LAYER-02 Runtime Diagnostic Text Primitive

**检查项**: `dayu/runtime/diagnostic_text.py` 的层中立性。

- 仅 import `re` 与 `typing.Final`；不 import 任何 `dayu.engine` / `dayu.host` / `dayu.service` / `dayu.ui` / `dayu.fins` 模块。
- 三个公开函数: `contains_sensitive_diagnostic_value`, `redact_sensitive_diagnostic_values`, `truncate_diagnostic_text`。
- `redact_sensitive_diagnostic_values` 使用 callable replacement 传递给 `re.sub()`，确保 `redaction_marker` 中的 `\1`、`\g<name>` 等不会被 re replacement 解释；marker 含反斜杠的测试已覆盖。
- `truncate_diagnostic_text` 对 `max_chars <= 0` 和 `len(truncated_suffix) >= max_chars` fail fast `ValueError`；空字符串和精确边界 no-op 测试已覆盖。
- regex 采用 word-boundary + assignment-operator guard 控制 false-positive：`JWT token has expired`、`Content-Type header is invalid` 不误判；`api key <value>` 空格写法、`apikey=<value>` 等新增检测模式已覆盖。
- 无 `Any` / `object` / `hasattr` / `getattr`。
- `dayu/runtime/__init__.py` 不 re-export 模块符号，仅更新 docstring 能力清单。
- `tests/runtime/test_diagnostic_text.py` 394 行，覆盖 detection、redaction、truncation、marker literal handling、empty string、redact+truncate combo、幂等性。
- **结论: PASS. 保持层中立，API 窄而精确，不承载业务语义。**

### Finding 05 — PASS: WU-LAYER-02 Engine/Host Policy Preservation

**检查项**: Engine / Host 调用方策略差异未被 runtime 吞掉。

| 调用方 | redaction 策略 | truncation | 保留的本地常量/行为 |
|---|---|---|---|
| `dayu/engine/agent.py` | `contains_sensitive_diagnostic_value` → 命中时整条替换为 `"exception message redacted"` | `truncate_diagnostic_text` with `_EXCEPTION_MESSAGE_TRUNCATED_SUFFIX` | `_EXCEPTION_MESSAGE_REDACTED`, `_EXCEPTION_MESSAGE_MAX_LENGTH`, `_EXCEPTION_MESSAGE_TRUNCATED_SUFFIX` |
| `dayu/host/compaction_operation.py` | `redact_sensitive_diagnostic_values` → 保留非敏感上下文 | `truncate_diagnostic_text` | `_ERROR_CODE_PATTERN`, `_exception_error_code`, `_exception_diagnostic_suffix`, `_REDACTED_SECRET` |
| `dayu/host/llm_compaction.py` | `redact_sensitive_diagnostic_values` → 保留非敏感上下文 | 本地截断 (`text[:240] + "..."`), NOT runtime `truncate_diagnostic_text` | `_SAFE_ERROR_CODE_PATTERN`, `_safe_error_code`, `_MAX_SAFE_OUTCOME_MESSAGE_CHARS`, `_TRUNCATED_SUFFIX`, `_REDACTED_SECRET` |

- Engine 保持整条 redacted 语义（先检测，命中则直接返回 `RunFailedData.message = "exception message redacted"`）。
- Host compaction 保持局部 value redaction + runtime truncation（先 redact 再 truncate）。
- Host llm_compaction 保持局部 value redaction + 本地 truncation（`_safe_outcome_text` 的 truncation shape 是 `text[:240] + "..."`, 可能超出 240 字符；这是 aggregate review 中明确保留的 Host 行为，不改为 runtime bounded truncation）。
- 三个调用方的旧私有 secret regex 全部删除（grep 确认无残留）。
- 测试覆盖：`test_agent_phase2.py` 增 128 行（含 `_safe_log_message` 直接测试矩阵）；`test_compaction_operation.py` 增 139 行（含 Host migration 后新增检测范围 `api key <value>`、`apikey=<value>`、`password=<value>`、`api-key:<value>` / `api-key: <value>` 及 `JWT token` 不误伤）；`test_llm_compaction.py` 增 66 行。
- **结论: PASS. 三层策略差异完全保留，runtime 未吞掉 owner-specific behavior。**

### Finding 09 — NOTE (Non-blocking): `_safe_outcome_text` truncation shape divergence

`dayu/host/llm_compaction.py._safe_outcome_text` 保持本地 truncation (`text[:240] + "..."`)，返回的字符串可能超过 240 字符。这与 `truncate_diagnostic_text` 的 bounded semantics (`message[:max_chars - len(suffix)] + suffix`) 不同。

这是 aggregate review F-01 中明确裁决的 intentional behavior，由 controller adjudication 确认: "Host-specific `_safe_outcome_text` truncation shape remains intentionally local and is locked by test"。测试 `test_llm_compaction.py` 已有覆盖。

**不构成 blocking finding**，但值得作为未来 Host compactor diagnostic 统一化的 watch item 记录。
