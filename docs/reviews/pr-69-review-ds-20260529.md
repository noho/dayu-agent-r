### Adversarial Failure Pass 结论

- Audit/Tool Trace sink 都依赖 SQLite marker + 文件系统 append 两个非事务性介质，crash window 内物理文件可能重复。code 通过 marker-based idempotency（正常重试时）与 line_digest 冲突检测做防御，但不追求真正 exactly-once。该风险已由 plan 和 implementation-control.md 记录为 accepted P1。
- Outbox projection 全部在 SQLite 事务内，item upsert + drain idempotency 是 ACID 安全的，不涉及跨介质问题。
- `read_outbox_terminal_items` 的 catch-up 在事务外通过 `best_effort` 运行（`_catch_up_outbox_terminal_projection_best_effort` 调用 `host._transaction_runner()`），catch-up 失败通过 `OutboxTerminalProjectionCatchupError` 对象携带到后续 `projection_status=FAILED` 中，不静默。
- Drain idempotency 按 `(session_id, drain_request_id)` 固定；同一 request id 不同语义输入会抛 `HostIdempotencyConflictError`，由 `HostCommandHandle._run_write` 映射为 public `HostApiError`.
- `read_outbox_terminal_items` 对 `projection_status=LAGGED` / `FAILED` 的可见性通过 `read_outbox_terminal_projection_state` helper 正确暴露，batch 返回 `projection_status`、`projection_checkpoint`、`projection_error_code`。
