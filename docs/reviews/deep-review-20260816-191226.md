## Semantic Ownership Anti-Check Review

### 1. Typed 四态与 closed reasons/invariants 是否真唯一 owner

**PASS** — `SourceIntegrityStatus`（MISSING/COMPLETE/REPAIR_REQUIRED/UNSAFE）定义在 `source_integrity.py:13-19`，是唯一的 public enum。`SourceIntegrityReason` 18 个封闭原因通过 `_REPAIRABLE_REASONS`（9 个）和 `_UNSAFE_REASONS`（9 个）两个 frozenset 互斥分类。`SourceIntegrityClassification.__post_init__`（`:93-137`）对四态分别强制执行：
- MISSING：revision=None 且 reasons=()
- COMPLETE：revision 非 None 且 reasons=()
- REPAIR_REQUIRED：revision 非 None，reasons 非空，且全部属于 repairable
- UNSAFE：revision=None，reasons 非空，且全部属于 unsafe

全部 consumer（inspector、upload validator、snapshot、download workflow、commit validator）只消费 typed classification，不从 raw meta、文件存在性、目录扫描或异常文本重判。

### 2. Filesystem inspector 是否统一 original/primary Docling/meta size-digest/manifest/actual tree 且无 loose fallback

**PASS** — `_inspect_source_kind_unguarded`（`_fs_source_integrity.py:159-351`）是单次 filesystem scan 产生的 typed payload owner。扫描顺序严格：
1. ticker identity descriptor → `IDENTITY_UNTRUSTED` / `UNSAFE_FILESYSTEM_ENTRY`
2. source root lstat → `UNSAFE_FILESYSTEM_ENTRY`
3. 每个 child 的 identity descriptor → `IDENTITY_UNTRUSTED`
4. 每个 source directory：meta.json 存在性/regular file → `META_UNTRUSTED`
5. meta ticker/document_id/source_kind 一致性 → `IDENTITY_UNTRUSTED`
6. provenance 解析 + ingest_complete → `PROVENANCE_UNTRUSTED`
7. revision 解析 → `REVISION_UNTRUSTED`
8. files 声明解析 → `FILE_DECLARATION_UNTRUSTED`
9. actual tree 无额外/非法/symlink 条目 → `UNDECLARED_BUSINESS_FILE` / `UNSAFE_FILESYSTEM_ENTRY`
10. primary/derived projection → `PRIMARY_PROJECTION_MISMATCH` / `DERIVED_PROJECTION_MISMATCH`
11. physical missing/size/digest → `ORIGINAL_FILE_MISSING` / `PRIMARY_DOCLING_FILE_MISSING` / `DECLARED_FILE_MISSING` / `SIZE_MISMATCH` / `DIGEST_MISMATCH`
12. manifest 结构与投影 → `SOURCE_MANIFEST_MISSING` / `SOURCE_MANIFEST_PROJECTION_MISMATCH` / `SOURCE_MANIFEST_UNTRUSTED` / `CROSS_SOURCE_INCONSISTENCY`

所有非结构化 `ValueError` 路径已消除；每个不信任条件都映射到 typed reason 并走 unsafe/repair-required/complete 封闭路径。无 loose fallback、无 `hasattr`/`getattr`、无目录猜测。

### 3. Upload state/validator repair authorization 是否只允许 auto + 完整明确 local input 且显式 action/unsafe/identity 不确定 fail closed

**PASS** — `validate_fins_upload_filing_request`（`ingestion_runtime.py:1459+`）在新鲜 state 上执行：
- UNSAFE → `FinsUploadPrevalidationError(fins_upload_source_integrity_unsafe_failure())`，在 job 创建前抛出
- REPAIR_REQUIRED + action != "auto" → `FinsUploadUsageCode.EXISTING_SOURCE_REPAIR_REQUIRES_AUTO`
- REPAIR_REQUIRED + auto + 非空 selection → `ExistingSourceAutoRepair(expected_integrity=integrity)`
- MISSING/COMPLETE → 既有 create/update/delete + `NoExistingSourceRepair()`

`ValidatedFinsUploadFilingRequest.__post_init__`（`:782+`）二次校验：
- repair expected_integrity 必须 == published integrity
- repair 要求 raw action 精确为 auto、resolved action 为 update、非空完整 selection
- `_validate_filing_selection_matches_request` 校验 raw request files/selectors 与 validated selection 完全一致

create/update/delete 对损坏 target 继续 fail closed（`EXISTING_SOURCE_REPAIR_REQUIRES_AUTO` usage error）。

### 4. Trusted revision 是否贯穿 preflight/fresh/staged/commit/snapshot/download 且 UNSAFE/MISSING 不混

**PASS** — revision 流：
1. **Preflight**：`classify_source_integrity_preflight` 从 inventory 纯计算，MISSING 无 revision，COMPLETE/REPAIR_REQUIRED 携带 revision
2. **Fresh validation**：`read_filing_upload_state` 通过 `_inspect_source_kind_unguarded` 返回 `FilingUploadPublishedState(source_integrity=classification)`，MISSING/UNSAFE 不携带 source_meta
3. **Staged recheck**：`reset_source_document_for_repair` 在真实 staging tree 上调用 `_inspect_source_kind_unguarded`，用 `has_same_source_publication_identity` 比较 Phase A 与 Phase B 的 opaque revision；UNSAFE/非 REPAIR_REQUIRED → `SourceIntegrityRevisionConflictError`
4. **Commit validator**：`_validate_complete_source_tree` 使用 `_inspect_source_kind_unguarded` whole-kind mode，要求全部 source 的 content_classification 和 classification 都是 COMPLETE
5. **Snapshot**：`_require_complete_source_for_snapshot_unguarded` 要求 COMPLETE 且 revision 非 None；REPAIR_REQUIRED/UNSAFE → `ValueError("source snapshot 只允许读取 COMPLETE source")`
6. **Download**：SEC/CN Phase A 读取后检查 `UNSAFE → SourceIntegrityPreflightError`；Phase B staged recheck 同样检查 UNSAFE

UNSAFE classification 固定 revision=None（`_with_unsafe_classification`），与 COMPLETE/REPAIR_REQUIRED 的 revision 非 None 互斥。MISSING 也固定 revision=None。四态 revision 语义一致。

### 5. Repair reset/manifest rewrite/commit validator 是否 before mutation exact target + revision + status recheck，non-target/cross-source 阻断，old-or-new atomic

**PASS** — `reset_source_document_for_repair`（`_fs_source_document_core.py:373+`）：
1. 校验 expected_integrity 精确引用 REPAIR_REQUIRED filing target（ticker/document_id/source_kind/status/revision）
2. 在真实 staging tree 调用 `_inspect_source_kind_unguarded` exact-target mode
3. target 为 None → `SourceIntegrityRevisionConflictError`
4. staged status 非 REPAIR_REQUIRED 或 UNSAFE → `SourceIntegrityRevisionConflictError`
5. content_classification 不在 {COMPLETE, REPAIR_REQUIRED} → `SourceIntegrityRevisionConflictError`
6. `has_same_source_publication_identity` 比较 expected 与 staged revision → 不匹配则 `SourceIntegrityRevisionConflictError`
7. material inspection whole-kind mode → material UNSAFE/preflight error → `SourceIntegrityRepairBlockedError`
8. non-target canonical items → repair_blocked_reason 非 None → `SourceIntegrityRepairBlockedError`
9. `_reset_source_document_directory_for_repair` 删除 exact target directory
10. `_rewrite_source_manifest_for_repair` 用 non-target canonical items 重写 manifest

Commit 时 `_validate_complete_source_tree`（`_fs_storage_infra.py:1100+`）用 `_inspect_source_kind_unguarded` whole-kind mode 重新扫描，要求所有 source COMPLETE。Batch commit 是 old-or-new atomic（`FsBatchingRepository.commit`）。

### 6. Workflow/service/runtime/CLI 是否机械消费同一 typed fact，无字符串/raw meta/目录重判

**PASS** — SEC upload workflow、CN pipeline、SEC download workflow、CN download workflow 全部通过 `resolve_fresh_filing_request`（`_filing_upload_fresh_validation.py`）重读 fresh state、运行同一 validator、消费 `ValidatedFinsUploadFilingRequest.repair_disposition`。`DoclingUploadService.prepare_upload` 接收 `repair_disposition` keyword；`_can_skip_upload` 在 `ExistingSourceAutoRepair` 时固定返回 false；`publish_prepared_upload` 传递 disposition 到 `_commit_prepared_upload`。无字符串匹配、无 raw meta 解析、无目录重判。

### 7. Identical fingerprint bypass、requested/stored、primary/assets/downstream 一致

**PASS** — `_can_skip_upload`（`docling_upload_service.py:1265+`）：`isinstance(repair_disposition, ExistingSourceAutoRepair) → return False`。repair 时全量读取 originals、全量 Docling 转换、全量写入。`_PreparedAssetMutation` 携带 `repair_disposition` 从 prepare 到 commit。requested/stored summary 从同一 prepared mutation 投影。

### 8. Download/snapshot complete-only

**PASS** — Snapshot：`_require_complete_source_for_snapshot_unguarded`（`_fs_source_integrity.py:1699-1732`）检查 `classification.status is not COMPLETE → ValueError`。Download：SEC/CN Phase A `UNSAFE → SourceIntegrityPreflightError`；Phase B `UNSAFE → SourceIntegrityPreflightError`。

### 9. Failure bounded/path-free 且无 success 保留损坏

**PASS** — `FinsUploadFailureReason` 校验 message/retry_hint 不含路径分隔符（`/`、`\`）、控制字符、超 240 字符。`FinsUploadPrevalidationError` 携带 typed failure reason 在 job 创建前抛出。`fins_upload_source_integrity_unsafe_failure()`、`fins_upload_source_revision_stale_failure()`、`fins_upload_source_repair_blocked_failure()` 均为 path-free 构造。SEC/CN workflow 的 fresh validation failure 投影为 typed failure event 并 return，不继续 prepare/commit。
