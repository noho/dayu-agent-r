## Findings

### 1. 未修复-低-`_read_exact_prefix` 中 `len(chunk) > remaining` 分支不可达

- **入口/函数**: `_read_exact_prefix`
- **文件(行号)**: `dayu/host/tool_trace_analysis_input.py:832-851`
- **输入场景**: 所有 cold prefix 读取。
- **实际分支**: 第 847 行 `if len(chunk) > remaining:` 是 `handle.read(remaining)` 返回后的长度检查。Python `RawIOBase.read(n)` / `BufferedReader.read(n)` 的契约是返回最多 n 字节，绝不返回超过 n 字节。该分支在当前调用链中不可达。
- **预期行为**: 多余的 defensive check 不造成行为错误，但会让 reader 误以为存在一种实际不会发生的 failure mode。
- **实际行为**: 无害；`read()` 返回超过请求长度时正确拒绝，但这种情况在当前 Python 实现中不存在。
- **直接证据**: Python `io` 模块文档与 CPython 源码均规定 `read(n)` 返回 ≤ n 字节；`handle` 来自 `path.open("rb")` 返回的 `BufferedReader`，其 `read()` 委托 `RawIOBase.read()`，不返回超过请求的长度。
- **影响**: 无运行时影响；仅增加一个永远不会触发的代码分支，轻微降低可读性。
- **建议改法和验证点**: 可将该检查转为 `assert len(chunk) <= remaining` 或直接删除，仅保留 short read 检查。若保留为防御（例如未来可能替换 BinaryIO 实现），建议加注释说明防御意图。
- **修复风险（低）**: 纯清理，不改变行为。
- **严重程度（低）**: 不影响正确性。

### Cold File Identity、锁临界区和 Exact-Prefix 并发状态机

- **O(1) 锁临界区**：锁内仅执行 `_open_cold_binary_file` + `os.fstat`（获取 prefix length 与 device/inode identity）+ `S_ISREG` 校验。无 O(file-size) read、SQLite、resolver、report 工作。**通过**。

- **Identity invariant**：锁内捕获 `(st_dev, st_ino)`，锁外读取后 fstat 复核：device 不变、inode 不变、size 不缩到 prefix 以下。追加（size 增长）允许，替换（inode 变化）拒绝，截断（size 缩小）拒绝。**通过**。
- **Lock 异常映射完整性**：

- **Handle close failure fatal**：`_capture_cold_prefix` 的 finally 块中 close 失败抛出 `COLD_SNAPSHOT_READ_FAILED`。测试 `test_cold_handle_close_failure_is_fatal` 用 `_FailingCloseReader` 模拟 close 失败。**通过**。
