### 分析详情

**1. `test_watch_session_events.py` 新增授权是否必要/唯一**

必要。当前 `tests/host/test_watch_session_events.py:752` 的 `_TerminalWatermarkHookCallCounter` 是 class-level 全局计数器，通过 `monkeypatch.setattr(HostTransientDeltaHub, "advance_committed_terminal_event_sequence_high_watermark", local_hook_calls)` 注入，对所有 opener 实例生效。`call_count == 0` 断言（行 1489、1547）在 S2 语义下成立（local hook 尚未接线），但在 S3 接线后，opener A 提交 terminal 后推进 A 自己的 local watermark 是合法且必需的——全局计数器因此 ≥1，断言失败。正确 owner 不是 production coordinator 而是 test instrumentation。该 test 已在 S3 Allowed tests 列表中（行 574），但修改 barrier 语义需要显式授权，plan amendment 正确提供了这一授权。

唯一性正确。amendment 只授权修改 `test_dual_opener_b_fence_catches_up_pages_before_terminal_handoff` 的 barrier instrumentation，不授权其它 test、fixture、support file 或 production 文件。

**2. C-side local watermark/hook 与 no-cross-opener wake 是否为正确 owner 证据**

是。amendment 要求：
- 允许 opener A 本地 hook 前进（A 的合法行为）。
- 必须直接证明 opener C 的 `committed_terminal_event_sequence_high_watermark` 未被 A 的 terminal action 推进。
- 必须直接证明 C watcher 保持 pending、C reconcile clock 未推进时没有 page read 或其它 wake。

当前 test 已有 C-side watermark 直接检查（行 1491-1496）：
```python
assert (
    host_c._transient_delta_hub.committed_terminal_event_sequence_high_watermark(
        session.session_id
    )
    == 0
)
```
该断言是 instance-local 的，直接观测 C 的 owner state，不依赖全局计数器。amendment 正确要求保留此类 C-side 直接观测，并删除把 A 合法动作与 C barrier 混为一谈的全局 `call_count == 0` 断言。

**3. S2 shared DB/fence/multipage/A-before-B/timeout/cleanup 是否完整保留**

是。plan 修订明确要求：
- 共享 Host DB/lane DB（行 511）
- multi-page catch-up（行 511）
- B fence 迫使 C 多页 catch-up（行 511）
- A terminal 先于 B（行 511）
- page/timeout 与 cleanup 断言保持不变（行 511）
- `page_read_spy.cursors`、`waiter_c.timeout_count`、retained items 等业务断言不被删除或削弱

未发现任何 S2 correctness 断言被修改或删除的证据。

## Residual risks

1. **C-side 实现细节**：amendment 要求删除 `call_count == 0` 并替换为 C-side 局部观测。test 已有 `host_c._transient_delta_hub.committed_terminal_event_sequence_high_watermark(session.session_id) == 0` 断言，实现 agent 需确认：(a) 删除两个 `call_count == 0` 断言后，(b) 是否需要新增额外 C-side hook 观测（如 C 的 `advance_committed_terminal_event_sequence_high_watermark` 未被调用的 instance-local 证据），还是现有 watermark 值检查已足够。这属于实现时的 test-level 决策，不阻塞 plan gate。风险等级：低。

2. **A-side hook 是否仍需 monkeypatch**：删除 `call_count == 0` 后，`_TerminalWatermarkHookCallCounter` 是否仍作为 A-side hook 注入（此时 A 的 hook 调用会推进 counter 但不被断言），还是需要改为允许 A 真正推进 watermark。实现 agent 需在 test 中做出选择并确保不引入副作用。风险等级：低。
