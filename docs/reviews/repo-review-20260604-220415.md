### 2-未修复-高-无 Schema 迁移机制——版本升级需重建数据库

- **入口/函数**: `bootstrap_host_durable_store()` / `validate_host_durable_schema()`
- **文件(行号)**: `dayu/host/durable/schema.py:1291-1341`
- **输入场景**: `HOST_SCHEMA_VERSION` 从 15 变为 16（任何 DDL 变更）
- **实际分支**: `current_version != HOST_SCHEMA_VERSION` 且 `current_version != 0` → 抛出 `HostSchemaMismatchError`
- **预期行为**: 应有 migration 路径或至少提供数据迁移工具
- **实际行为**: 直接抛出错误，消息为 "recreate the durable database for this version"，意味着所有历史 session/run/event 数据丢失
- **直接证据**:
  ```python
  # schema.py:1314-1318
  raise HostSchemaMismatchError(
      "Host durable schema version mismatch: "
      f"expected fresh schema {HOST_SCHEMA_VERSION}, got {current_version}; "
      "recreate the durable database for this version"
  )
  ```
- **影响**: 版本升级时所有持久化数据丢失；生产环境无法平滑升级
- **建议改法和验证点**:
  - 实现 `ALTER TABLE` 迁移链（每版本一个 migration 函数）
  - 或在 `pyproject.toml` 中明确标注 `HOST_SCHEMA_VERSION` 为 breaking change
  - 至少提供 `dayu-cli migrate` 命令导出/导入数据
- **修复风险（中）**: 需要设计 migration 框架，但 SQLite DDL 限制使部分迁移（如改 CHECK 约束）需要重建表
- **严重程度（高）**: 无迁移路径意味着 schema 变更 = 生产数据丢失

### 5-未修复-中-Retry-After HTTP-date 格式不支持——Azure OpenAI 等 provider 的 Retry-After 被忽略

- **入口/函数**: `parse_retry_after()`

- **实际分支**: `except ValueError: return None`（line 50-51）
- **预期行为**: 正确解析 HTTP-date 格式的 Retry-After 头，尊重 provider 建议的重试等待时间
- **实际行为**: HTTP-date 格式解析失败，返回 `None`，runner 回退到自己的指数退避公式
