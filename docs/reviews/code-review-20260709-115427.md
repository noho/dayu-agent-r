#### MiMo 002（中）：`_wait_tool_call_requested_event` 缺少 `normalized_arguments_digest` fail-fast — **已修复**

- 新增 `_validate_wait_request_arguments_digest` 函数（`dayu/host/waiting.py:1534`）
- 该函数读取 `TOOL_AWAITING` event（`wait_record.created_event_id`），校验 identity 后比对 `normalized_arguments_digest`：request atom 的 digest 必须与 awaiting accept 时写入的 digest 一致
- `_wait_tool_call_requested_event` 在 tool_call_id/tool_name 校验后调用此函数（line 1526）
- 新增专项测试 `test_resolve_wait_rejects_request_atom_arguments_digest_mismatch`（`tests/host/test_resolve_wait_command.py`）：篡改 request atom 的 `normalized_arguments_digest` 后 resolve_wait 必须 raise `HostDurableError("arguments digest mismatch")`
- 这个实现比 MiMo 原始建议（直接在 `_wait_tool_call_requested_event` 入口比对 wait_record digest）更好：它 cross-check 同一事务中创建的 `TOOL_AWAITING` 事实，而非依赖 wait_record 的某个字段

#### MiMo 003（低）：request atom payload required field 演化说明 — **已修复**

- `docs/host/design.md` 新增两条显式设计声明：
  1. "当前 schema 下 awaiting accept 必须同事务写入 `TOOL_CALL_REQUESTED` request atom；wait-resolution 不实现旧库兼容读取分支。"
  2. "历史或测试构造的旧格式 wait result 若缺少 envelope / request atom，只能在 resume input 层降级为自解释 guidance，不能进入 self-explaining Conversation Memory evidence，也不能从 `TOOL_AWAITING` 反推 request/query 语义。"
- 无旧 request-atom 兼容分支引入；`_wait_tool_call_requested_event` 对缺失或不匹配的 request atom 直接 fail closed

#### MiMo 004（低）：SEC pipeline summary fallback — **已修复（更彻底）**

- `_summary_from_pipeline_result` 不再读取 `summary.failed` / `summary.downloaded` / `summary.skipped` 等 pipeline 聚合字段
- `discovered_count` 改为 `len(filings)`，各分类直接从 filing-level `status` 互斥计数
