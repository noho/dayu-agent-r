## 变更概要

本 PR 落地 Host P1.5 最小 EventLog 路径：

1. 新增 `InMemoryRunEventStore`（`_event_store.py`），实现单进程 append-only 事件事实层
2. 新增 `RunEventDraft`、`RunEvent`、`RunResult` 等强类型契约（`contracts.py`）
3. 新增 `_event_translation.py`，负责 EngineEvent → RunEventDraft 翻译与终态结果推导
4. 重构 `_run_harness.py`，将 Engine 事件流翻译并 append 到 store，再由 subscribe 消费
5. Engine 层 `run_agent_messages` 增加显式 `aclose()` 防御性清理
6. 补充 Engine 终态事件排序守卫测试

## 审查结论

**未发现实质性问题。** 本 PR 设计清晰、分层合理、测试覆盖充分。以下列出几项值得关注的观察，均不构成阻塞项。

## Findings

### 1. [Low] `_run_to_store` 中 `finally` 块关闭 stream 可能掩盖原始异常

**文件**: `dayu/host/_run_harness.py:216-217`

```python
finally:
    await _close_engine_events_if_supported(engine_events)
```

如果 `_close_engine_events_if_supported` 中的 `aclose()` 抛出异常，该异常会取代 `try` 块中原始的异常传播。在 Python 中，`finally` 块抛出的异常会覆盖 `try`/`except` 中的原始异常。

**当前影响**: 低。`_ClosableAsyncIterator` 协议要求 `aclose()` 返回 `None`，正常实现不应抛出异常。且 `_log_background_task_failure` 回调仍能捕获最终异常。

**建议**: 如需更稳健，可将 `aclose()` 包裹在 `try/except` 中吞掉关闭异常，或记录 warning。当前不影响正确性，可作为后续优化项。

**修复状态**: 已修复。`_close_engine_events_if_supported` 现在捕获 `aclose()` 异常并记录
`WARNING host.run.stream_close_failed`，不会覆盖原始异常，也不会写入 Host-owned failure。新增测试覆盖：
关闭失败不掩盖 Host 契约错误、关闭失败不改变 worker/proxy failure 事实、成功终态后关闭失败不追加
Host-owned failure。

### 2. [Low] `_subscribe` 返回类型标注为 `AsyncIterator` 但实际是 async generator

**文件**: `dayu/host/_event_store.py:190-194`

```python
async def _subscribe(
    self,
    run_id: str,
    after: RunEventCursor | None,
) -> AsyncIterator[RunEvent]:
```

该方法是 `async def` + `yield`，实际返回 `AsyncGenerator[RunEvent, None]`。标注为 `AsyncIterator` 在类型层面是安全的（`AsyncGenerator` 是 `AsyncIterator` 子类型），但与实际返回类型不精确匹配。

**当前影响**: 无。pyright 未报错，Protocol 契约满足。

**建议**: 可考虑将返回类型改为 `AsyncGenerator[RunEvent, None]` 以更精确反映实现，但非阻塞项。

**修复状态**: 已修复。`InMemoryRunEventStore._subscribe` 返回类型已改为
`AsyncGenerator[RunEvent, None]`，`RunEventStore.subscribe` public protocol 仍保持
`AsyncIterator[RunEvent]`。

### 3. [Info] `RunEventType` 与 `EngineEventType` 通过 value 隐式耦合

**文件**: `dayu/host/contracts.py:47-63`

`RunEventType` 的每个成员通过 `EngineEventType.XXX.value` 赋值，同时 `_event_translation.py:59` 通过 `RunEventType(event.type.value)` 做翻译。这要求两个枚举的 value 必须保持一一对应。

**当前影响**: 无。这是 P1.5 的设计选择，枚举成员稳定且有分类矩阵测试覆盖。若 Engine 侧新增事件类型，翻译层会抛出 `ValueError`，fail-fast 行为正确。

**建议**: 无需改动。测试 `test_engine_event_kind_classification_matrix` 已覆盖全部映射。

**修复状态**: 不改。该项是 P1.5 明确设计选择，新增 Engine 类型时 fail-fast 合理；当前分类矩阵测试已覆盖。

### 4. [Info] `_run_to_store` 中 `terminal_result_from_event` 抛出的 `TypeError` 不会被转换为 Host-owned failure

**文件**: `dayu/host/_run_harness.py:213`

```python
if terminal_result_from_event(stored_event) is not None:
```

如果终态事件的 data 类型与 event type 不匹配（如 `FINAL_ANSWER` 事件携带 `RunFailedData`），`terminal_result_from_event` 会抛出 `TypeError`。该异常不会走 `_append_worker_failure_if_needed` 路径，而是直接传播到 task 的 done callback。

**当前影响**: 这是正确的设计。契约不匹配是编程错误，不应伪装为 Host-owned failure。事件已成功 append 到 store，后续 `get_run_result` 会再次抛出同一 `TypeError`，保持诊断一致性。测试 `test_terminal_result_error_does_not_append_host_failure` 已验证此行为。

**修复状态**: 不改。该项不是 bug；Host 内部契约错误不应伪装为 worker/proxy failure，现有测试继续守护该语义。

### 5. [Info] Engine 层 `run_agent_messages` 返回类型从 `AsyncIterator` 改为 `AsyncGenerator`

**文件**: `dayu/engine/agent.py:1498`

返回类型签名从 `AsyncIterator[EngineEvent]` 改为 `AsyncGenerator[EngineEvent, None]`，同时增加 `try/finally` + `aclose()`。

**当前影响**: 这是正确的防御性改动。当 Host harness 在首个终态后停止消费时，显式 `aclose()` 确保底层 runner 的 close 流程被触发，避免资源泄漏。`AsyncGenerator` 是 `AsyncIterator` 的子类型，不影响现有调用方。

**修复状态**: 不改。该项是正确防御性改动，不属于 P1.5 bug。
