## Findings

### 01-未修复-低-同步 fallback 模式未覆盖 `close()` 重复调用的幂等行为

- **入口/函数**: `CliSigintMonitor.close()`
- **文件(行号)**: `dayu/cli/agent_entrypoint.py:92-112`
- **输入场景**: `close()` 被调用两次（例如 cleanup finally + Host close cascade）
- **实际分支**: 第一次 `close()` 将 `_installation_mode` 重置为 `NONE`；第二次调用时，`NONE` 不匹配 ASYNCIO 也不匹配 SYNCHRONOUS 分支，直接落到 `self._installation_mode = NONE`，再次将 `_loop = None`、`_previous_handler = None`。此时 handler 已经不被 CliSigintMonitor 持有，不会泄漏。
- **预期行为**: 重复 close 应为安全 no-op，当前实现已满足。
- **实际行为**: 重复 close 安全无事，但 `_loop` 与 `_previous_handler` 被重复赋 `None`（已是 `None`）。
- **直接证据**: 第 101-112 行：`if ASYNCIO: ... elif SYNCHRONOUS: ...` 后直接 `self._installation_mode = NONE`。
- **影响**: 无运行时缺陷。重复 close 为安全 no-op，不泄漏 handler、不调用不支持的 remove API。
- **建议改法和验证点**: 可考虑显式 early return `if self._installation_mode is NONE: return` 避免重复赋值，但当前行为正确。优先级极低，属 clarity 可选改进。
- **修复风险（低）**: 纯防御性改动，不影响行为。
- **严重程度（低）**: 无 runtime defect，仅为代码意图显式化建议。
