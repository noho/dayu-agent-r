## Finding 1: 未发现实质性问题 — finish reason authority 彻底迁移

**严重度**: N/A（验证通过）

**证据**:

1. `RunnerContentCompletedData` 已删除 `finish_reason: FinishReason` 字段。当前字段集为 `{"content", "reasoning_content"}`。验证：

2. `ContentCompleteData` 已删除 `finish_reason: FinishReason` 字段。当前字段集为 `{"iteration_id", "content", "reasoning_content"}`。验证：
   - 生产代码: `dayu/engine/contracts/engine_events.py:140-150`
   - 字段锁测试: `test_content_completed_fields_exclude_finish_reason` (test_engine_event_contract.py:191)

3. `RunnerDoneData.finish_reason` 是唯一 Runner-call completion authority:
   - SSE parser `_finalize_success()` (sse_parser.py:707): `finish = FinishReason.TOOL_CALLS if self._tool_calls_seen else self._finish_reason or FinishReason.STOP`
   - Non-stream parser `_emit_from_dict()` (non_stream_parser.py:286, 364-368): `finish_reason = _resolve_finish_reason(choice)` → TOOL_CALLS override → `RunnerDoneData(finish_reason=finish_reason)`
   - 两种 parser 的 `RunnerContentCompletedData` 均不再接收 `finish_reason` 参数

4. `IterationCompletedData.finish_reason` 是唯一 EngineEvent completion authority:
   - Agent `_consume_runner_event()` (agent.py:1449-1475): `state.finish_reason = data.finish_reason`（仅从 `RunnerDoneData` 写入），`IterationCompletedData(finish_reason=data.finish_reason)`
   - Agent `_classify_iteration()` (agent.py:1551): `finish_reason = state.finish_reason or FinishReason.STOP` — 仅从 state 读取（state 仅由 RunnerDone 设置）

5. Agent mismatch/override 逻辑已删除:
   - 旧代码 (agent.py 删除部分): `if state.finish_reason is not None and state.finish_reason is not data.finish_reason: ... finish_reason = state.finish_reason`
   - 新代码 (agent.py:1451): `state.finish_reason = data.finish_reason` — 无条件从 RunnerDone 取
   - 测试 `test_runner_done_finish_reason_is_authority` (test_agent_phase2.py:537): 验证 content-completed 的 FINISH_REASON=STOP 与 RunnerDone 的 FINISH_REASON=LENGTH 不一致时，最终 `IterationCompletedData.finish_reason` 是 LENGTH。同时验证 `assert not any("engine.agent.finish_reason_mismatch" in ...)` — mismatch warning 不再出现。

6. Host content_completed preview/audit 不再投影 finish_reason:
   - `_preview_payload()` (engine_ingest.py:4656-4659): `ContentCompleteData` 分支只投影 `iteration_id`、`has_content`、`has_reasoning_content`，不投影 `finish_reason`
   - `_preview_payload()` (engine_ingest.py:4688-4692): `IterationCompletedData` 分支仍正确投影 `finish_reason`、`provider_request_id`、`client_correlation_id`

**裁决**: 通过。finish reason 的语义所有权已从双源竞争收敛为 `RunnerDoneData` → `IterationCompletedData` 单一权威链。

## Finding 3: 未发现实质性问题 — parser event ordering 正确

**严重度**: N/A（验证通过）

**证据**:

14. SSE parser `_finalize_success()` 事件顺序:
    - Tool-call 路径: `RunnerToolCallsCompletedData` → `RunnerDoneData(finish=TOOL_CALLS)`
    - 正文路径: `RunnerContentCompletedData(content, reasoning)` → `RunnerDoneData(finish=STOP or mapped)`
    - Usage chunk: 在 `[DONE]` 处理时通过 `_emit_usage_from_completion_tokens()` 产生独立 `RunnerUsageRecordedData` 事件
    - 事件排序正确: usage 在 done 之前（由 `_handle_done_token()` 调用 `_emit_usage_from_completion_tokens()` 后在 `_finalize_success()` 之前）

15. Non-stream parser `_emit_from_dict()` 事件顺序:
    - Tool-call 路径: `RunnerProtocolErrorData`（如有 fatal error）→ `RunnerDoneData(finish=ERROR)` 并 return
    - 正常 tool-call: `RunnerToolCallsCompletedData` → `RunnerUsageRecordedData`（如有usage）→ `RunnerDoneData(finish=TOOL_CALLS)`
    - 正文路径: `RunnerContentCompletedData` → `RunnerUsageRecordedData`（如有usage）→ `RunnerDoneData(finish=mapped)`
    - `finish_reason` 变量无条件在 line 286 初始化（`_resolve_finish_reason` 对未知值返回 `FinishReason.STOP`）

16. Tool-call finish reason 正确:
    - SSE: `finish = FinishReason.TOOL_CALLS if self._tool_calls_seen else self._finish_reason or FinishReason.STOP`
    - Non-stream: `if tool_calls_emitted: finish_reason = FinishReason.TOOL_CALLS`
    - 两个 parser 的 `RunnerDoneData.finish_reason` 在 tool-call 场景下均为 `TOOL_CALLS`，且 `RunnerContentCompletedData` 不再承载与之冲突的 finish_reason

17. Usage chunk provider id 正确:
    - Stream: `self._provider_request_id` 在 SSEParser 构造时从 response header 提取，在 usage chunk 时使用
    - Non-stream: `provider_request_id` 作为参数从 `parse_non_stream_response` → `_emit_from_dict` 透传

**裁决**: 通过。事件顺序、tool-call finish reason、usage chunk provider id、non-stream usage provider id 均正确。
