### Host stage / sequencing owner

Host 五阶段矩阵对 `CONTINUATION` 的 normal/soft/hard 均返回 `ALLOW_DISPATCH`；Engine tool-result 后续 Runner call 被 Host 明确登记为 `tool_result_continuation` 并以 `ContextSizingStage.CONTINUATION` 生成 sizing fact。新用户 Run 的 dispatch candidate 则由 dispatch owner固定以 `ContextSizingStage.ORDINARY` 评估，soft pressure 才返回 `COMPACT_SOFT_THRESHOLD`。

因此：R1 内 grounding→read_section 继续同一 Run 是 continuation，不应被误当 baseline；R1 completed 后 R2 的 pre-start ordinary 是合法 baseline；R2 accepted baseline 后的 grounding/read 是 continuation；completed R2 material 到 R3 pre-start ordinary 才是唯一 replacement target。plan 同时规定任何 reactive operation立即 seal，防止用错误 boundary 补覆盖。

68,039-char R1 与 61,252-char R2 material 分别为下一次 ordinary boundary提供直接压力来源；plan 不承诺 stochastic provider 必然触发，而是未触发即原样 `needs-more-evidence`，并禁止 padding/调参/同链重跑，故没有把可行带冒充成功保证。

### Iteration / call budget owner

production assembly 的固定优先级是 `run_override > scene_override > execution_profile > base_policy`。现存 typed calibration与配置直接显示 profile `max_iterations=24`、interactive scene override `max_iterations=20`、effective field source=`scene_override`、fallback=`force_answer`。Engine ordinary loop为 `range(max_iterations)`；工具循环耗尽后 `force_answer` 最多再发起一次禁用工具的 Runner call。因此 typed hard cap为 21/Run；25/Run只能作为更宽外部停止 ceiling。plan 对 R1-R3 使用 63、R1-R4 使用84，并保留75/100 external ceiling，owner解释正确。
