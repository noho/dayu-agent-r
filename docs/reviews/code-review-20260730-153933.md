#### 攻击面 1：no-follow stat 六态分类正确性

**入口/函数**：`_workspace_execution_profile_is_regular_file`

| Path shape | `os.stat(follow_symlinks=False)` 行为 | `FileNotFoundError`? | `S_ISREG`? | 函数返回/抛出 | 正确? |
|---|---|---|---|---|---|
| absent | 抛 `FileNotFoundError` | 是 | — | `return False` | ✓ |
| ordinary regular file | 返回 stat_result | 否 | True | `return True` | ✓ |
| symlink → external regular | 返回 symlink 自身的 lstat | 否 | False (S_ISLNK) | `raise CliInitOperationError` | ✓ |
| dangling symlink | 返回 symlink 自身的 lstat | 否 | False (S_ISLNK) | `raise CliInitOperationError` | ✓ |
| directory | 返回目录 stat | 否 | False (S_ISDIR) | `raise CliInitOperationError` | ✓ |
| FIFO | 返回 FIFO stat | 否 | False (S_ISFIFO) | `raise CliInitOperationError` | ✓ |

**直接证据**：`init.py:457-466` — `os.stat(path, follow_symlinks=False)` 对 symlink 返回 lstat（不跟随）；`stat.S_ISREG` 对 symlink/dir/FIFO 均返回 False；`FileNotFoundError` 仅在路径不存在时抛出并归为 absent。

**结论**：六态分类正确。no-follow stat 不会错误地将 symlink 判为 regular file，也不会将 dangling symlink 误判为 absent。

---

#### 攻击面 2：FileNotFoundError 捕获边界

**入口/函数**：`_workspace_execution_profile_is_regular_file` (`init.py:458-460`)

**场景**：`workspace_config_dir` 父目录缺失。

在 PRESERVE 模式下，`workspace_config_dir = workspace_root / "config"`，其中 `workspace_root` 已经过 `_require_workspace_identity` 复核（`init.py:147`）——该函数要求 `canonical_path.resolve(strict=True)` 且 `stat.S_ISDIR(current.mode)` 为 True。若 `workspace_root` 存在且为目录，则 `workspace_root / "config"` 的父目录必定存在。

但存在一个极窄窗口：`workspace_root / "config"` 目录本身被删除。此时 `os.stat(profile_path, follow_symlinks=False)` 会抛 `FileNotFoundError`（因为 `workspace_root / "config"` 不存在导致路径解析失败）。代码将其归为 absent（`return False`），随后 `ConfigLoader` 以 `workspace_config_dir=workspace_root/"config"` 调用 `_load_layered_config_file`。该函数 `workspace_path = workspace_config_dir / file_name` 的 `workspace_path.exists()` 对不存在的父目录也返回 False（因为 `Path.exists()` 对缺失父目录返回 False），因此返回 package root。行为等价于"workspace profile missing → package layer"。

**直接证据**：`init.py:458-460` 只捕获 `FileNotFoundError` 不区分"文件缺失"还是"父目录缺失"；`config_loader.py:981-985` 的 `workspace_path.exists()` 对父目录缺失也返回 False。

**影响**：极窄窗口下的行为退化（directory 被删除后应报 workspace error 而非静默 fallback），但此窗口与 S2-MIMO-002 的 TOCTOU 窗口同源，且 directory 删除在 init lock 内不可触发。Severity 低，可接受。

**PermissionError 场景**：`os.stat` 因权限不足抛 `PermissionError`（`OSError` 子类，非 `FileNotFoundError`）。不被 `_workspace_execution_profile_is_regular_file` 捕获，传播到 `_load_target_min_context_window` → 不被 `except ConfigLoadError` 捕获 → 传播到 `run_init_command` → 被 `except OSError` 捕获（`init.py:243-248`），输出 `"filesystem operation failed: PermissionError"` — 不含路径、不含原始值。✓ 脱敏正确。
