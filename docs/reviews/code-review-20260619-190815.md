### reactive frozen material assembly 恢复 protected recent turn group material

### memory selected recent window 与 raw tail dedupe
**确认基本可靠。** Dedupe 逻辑 (`_raw_tail_block_represented_by_memory`, run_input.py:3561-3583) 三层检查：
1. `content_digest` 匹配：`block.content_digest in content_digests`
2. `canonical_source_refs` 匹配：逐 ref 检查 `ref in source_refs`
3. `evidence_refs` 匹配：检查 `accepted_evidence_id`、`tool_result_event_ref`、`tool_call_event_ref`

对于 user input / assistant answer blocks，`canonical_source_refs = (row.event_id,)` 与 memory `selected_recent_source_refs`（含 `item.event_id`，即同一 event id）匹配。对于 evidence blocks，`tool_result_event_ref`（即 TOOL_RESULT_ACCEPTED event id）与 memory source_refs 中的 TOOL_RESULT_ACCEPTED event id 匹配。详见 F3 关于 content_digest 规范化偏差的分析。

`MemorySnapshotView` 新增的 `selected_recent_source_refs` 和 `selected_recent_content_digests` 字段默认值为空 tuple，不影响现有调用方。`_memory_snapshot_view()` (run_input.py:2384-2391) 从 `snapshot.trace_memory.selected_recent_window` 提取 source refs/digests，通过 `_memory_selected_recent_source_refs` / `_memory_selected_recent_content_digests` 构造（排除 current input event_id）。

测试 `test_post_compaction_raw_tail_dedupes_memory_selected_recent_window` (test_run_input_builder.py:2758) 验证去重后 user prompt 和 answer 各出现一次。

### accepted readable tool evidence LLM-facing 渲染不泄露 internal state
**确认正确。** `_accepted_tool_evidence_content` (run_input.py:3156-3180) 使用 `readable_tool_name`、`readable_query_text`、过滤后的 `readable_source_text`、`block.text`。`_llm_facing_evidence_source_text` (run_input.py:3183-3202) 按 `", "` 分隔 source note 后逐段检查 `_INTERNAL_EVIDENCE_SOURCE_PREFIXES`（含 `tool_call_event:`、`tool_result_event:`、`event:`、`eventlog:`、`payload:`、`artifact:`、`digest:`），过滤匹配前缀的部分。`_fallback_message_from_material_block` 仅使用 `block.text`（已规范化的业务可读文本），不渲染 `block_id`、`canonical_source_refs`、`payload_refs` 等内部标识。测试验证了 `tool_call_id` 和 `event-prior-tool` 不出现在最终 messages 中。详见 F1 关于过滤器单元测试覆盖不足的分析。
