### 02-未修复-低-`_close_handle` 重试循环理论上无退出上界

- **入口/函数**: `_close_handle`
- **文件(行号)**: `dayu/fins/pipelines/docling_process_converter.py:641-667`
- **输入场景**: `handle.close()` 持续抛出非 `CancelledError` 的异常
- **实际分支**: `while True` 循环在 `except Exception` 分支返回 `_CloseOutcome(failure=exc)`，循环退出。但如果 runtime `close()` 在 `_cleanup_completed=False` 时被再次调用且 `_cleanup_task` 已 done 但失败，会创建新的 cleanup task 并可能再次失败
- **预期行为**: `handle.close()` 的重试应有明确上限，防止极端场景下的无限循环
- **实际行为**: runtime `close()` 内部使用 6 个幂等 checkpoint guards，每步独立推进；正常情况下 cleanup 要么完成（`_cleanup_completed=True`）要么在首次失败后保持失败。converter 的 `while True` 循环在非 CancelledError 异常时立即 return，不重试。当前 runtime 实现下不会无限循环
- **直接证据**: `_close_handle` L641 `while True`、L648-656 `except Exception` 直接 return。runtime `close()` 的 checkpoint guards 保证幂等推进
- **影响**: 当前 runtime 实现下实际不会触发无限循环。但 converter 的 `while True` 缺少显式上限，若 runtime 行为变化可能引入风险
- **建议改法和验证点**: 可考虑在 `_close_handle` 中增加最大重试次数（如 3 次）作为防御性措施，但优先级低——当前 runtime 的幂等 guards 已足够
- **修复风险（低/中/高）**: 低
