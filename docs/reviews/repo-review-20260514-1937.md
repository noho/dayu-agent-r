### 01-未修复-高-liveness.py 允许已终态 Host instance 被回退到 RUNNING

- **入口/函数**: `liveness.register_current_instance`
- **文件(行号)**: dayu/host/durable/liveness.py:196-209
- **输入场景**: 一个已被标记为 STOPPED 或 CRASHED_SUSPECTED 的 Host instance 行，如果进程用相同的 `host_instance_id` + `pid` + `process_start_token` 再次调用 `register_current_instance`
- **实际分支**: else 分支（existing 存在且身份一致），直接 `SET status = RUNNING`
- **预期行为**: 已终态（STOPPED / CRASHED_SUSPECTED）的 instance 不应被复活；lifecycle 状态机 `RUNNING -> STOPPING -> STOPPED` / `CRASHED_SUSPECTED` 是单向的
- **实际行为**: `register_current_instance` 只检查身份一致性，不检查当前 status。STOPPED 行被强制回退到 RUNNING
- **直接证据**: 代码第 196-209 行，`else` 分支无条件 `SET status = RUNNING`，无 `existing.status` 检查
- **影响**: 下游 recovery 逻辑若依赖 STOPPED/CRASHED_SUSPECTED 作为终态判定，会被错误覆盖，导致本应被回收的 instance 被视为存活
- **建议改法和验证点**: 在 `else` 分支增加状态校验，如果 `existing.status` 已经是 STOPPED 或 CRASHED_SUSPECTED，抛出 HostDurableError 或拒绝回退。验证：构造 STOPPED 实例后调用 register_current_instance，确认抛出异常
- **修复风险（低）**: 增加校验不影响正常路径，只限制非法 lifecycle 回退
- **严重程度（高）**: 终态可回退破坏状态机不变量，recovery 误判影响全局

### 03-未修复-高-cancel_session_runs 取消 active Run 后未触发 queue promotion

- **入口/函数**: `HostAdmissionService.cancel_session_runs`
- **文件(行号)**: dayu/host/admission.py:501-536 及 1069-1136
- **输入场景**: Session 同时有一个 pre-dispatch STARTING Run 和一个 QUEUED Run，调用 `cancel_session_runs` 取消所有非终态 Run
- **实际分支**: cancel 事务内成功取消 STARTING Run，释放 active slot，但事务外不触发 promotion
- **预期行为**: 取消 STARTING Run 释放 active slot 后，应触发 queue promotion，把 QUEUED Run 提升为 RUNNING，与 `cancel_run` 行为一致
- **实际行为**: `cancel_session_runs` 在取消 active Run 后不触发 promotion。QUEUED Run 会一直停留在 queued 状态
- **直接证据**: `cancel_run` 路径检查 `result.released_active_slot` 并调用 `_promote_after_release()`（行 486-498），而 `cancel_session_runs` 直接返回 transaction 结果（行 526-536），没有检查是否释放了 active slot
- **影响**: 调用 `cancel_session_runs` 后，session 中 QUEUED Run 可能永远无法被 promotion，违反 Host 对 Agent 生命周期的治理约束
- **建议改法和验证点**: 在 `cancel_session_runs` 的 write transaction 完成后，检查被取消的 Run 中是否有释放 active slot 的，若有则调用 `_promote_after_release()`。需要在 `SessionCancelResult` 中增加 `released_active_slot: bool` 字段。验证：构造 active + queued 两个 Run，cancel_session_runs 后确认 queued Run 被 promotion
- **修复风险（中）**: 需要修改 `SessionCancelResult` 结构和方法逻辑；promotion 在独立事务中执行，不破坏 cancel 事务原子性
- **严重程度（高）**: 直接导致 QUEUED Run 死锁，用户可见的执行卡住
