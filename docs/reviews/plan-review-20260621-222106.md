## Finding Verification

### F01 — Dispatch wakeup gap

- **Controller 要求**: 定义 callback resolve port / command-layer adapter，返回 `RunSnapshot` + `idempotent_replay`，保证非 replay 时唤醒 dispatch 一次，replay 不唤醒。
- **Fixed plan 证据**:
  - `CallbackWaitResolvePort(Protocol)` 定义于 §Contract (line 170-176)，返回 `CallbackWaitResolveResult(run: RunSnapshot, idempotent_replay: bool)`。
  - Line 176: "it must call the existing resolve pipeline, convert any internal `RunRow` to `RunSnapshot` before returning, and preserve the existing command wakeup behavior: when resolve creates a dispatch record and `idempotent_replay` is false, it must call the dispatch wakeup port exactly once. Replay must not wake dispatch again."
  - Line 304: "This port returns `RunSnapshot` plus `idempotent_replay`, converts internal rows before producing the adapter result, and guarantees dispatch wakeup for non-replay resolves that create dispatch."
  - Tests (line 358-359): "Accepted callback that creates resume dispatch wakes dispatch exactly once." / "Same callback replay returns `REPLAYED`, appends no new EventLog, and does not wake a second dispatch."
  - Validation expectations (line 452): "Callback accepted path wakes dispatch once when resolve creates dispatch; replay path does not wake dispatch again."
- **状态**: ✅ 已修复

### F02 — Callback digest formula

- **Controller 要求**: callback digest 对齐现有 `_wait_resolution_digest` 语义 `{wait_id, idempotency_key, outcome}`；`observed_at`/`completed_at` 不影响 replay conflict。
- **Fixed plan 证据**:
  - Line 178-188: `payload_digest` 计算使用 `sha256_digest_json` over `{wait_id, idempotency_key, outcome}`，明确排除 `observed_at` 和 `completed_at`。"A same callback replay with a different `observed_at` or `completed_at` remains `REPLAYED` when the outcome is unchanged."
  - Line 332: adapter step 4 验证 `payload_digest` 使用与 `_wait_resolution_digest` 相同的材料。
  - Tests (line 359-360, 367): replay 返回 `REPLAYED`，同 key 不同 outcome 返回 `IDEMPOTENCY_CONFLICT`，`observed_at`/`completed_at` 变化不影响 replay。
- **状态**: ✅ 已修复

### F04 — INVALID_STATE mapping 不解析 message

- **Controller 要求**: 禁止解析 `HostApiError.message`；并发 race 安全 collapse 到 `INVALID_WAIT_STATE`。
- **Fixed plan 证据**:
  - Line 338: "Do not parse `HostApiError.message`. `INVALID_STATE` from the resolve port maps to `INVALID_WAIT_STATE` unless the adapter already made a stable pre-resolve classification such as `LATE_WAIT_CANCELLED`, `LATE_WAIT_LOST`, or `STALE_CALLBACK`. Concurrent races may safely collapse to `INVALID_WAIT_STATE`. A more precise raced late-state classification requires a future structured subcode/result and is not part of this WU."
  - Line 362-363: Tests 区分 stable pre-existing cancelled/lost（返回 `LATE_WAIT_CANCELLED`/`LATE_WAIT_LOST`）与 concurrent race（返回 `INVALID_WAIT_STATE`）。
  - Line 477: Risks 章节确认 race 下 collapse 行为可接受。
- **状态**: ✅ 已修复

## New Regression Check
