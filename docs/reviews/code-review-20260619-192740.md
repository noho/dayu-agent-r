## Adversarial Failure Pass 摘要

对以下风险面做了独立 adversarial 检查，均未发现 correctness blocker：

- **并发/race**：Provider 在自己管理的 read transaction 内查询 EventLog；EventLog 已提交 fact 不可变。compact provider 与 raw tail provider 在不同 transaction 中读取同一 compacted event——`_validate_loaded_compact_view_matches_event` 校验 artifact ref/digest 一致，若不一致则 raise `HostDurableError`（正确行为）
- **空状态**：`compact.compact_artifact_ref is None` 时 provider 不被调用（build() 层短路）；provider 自身也有防御性空检查；`_latest_compacted_event_before_attempt` 返回 None 时 provider 返回空
- **重复请求/幂等**：dedupe 三层检查防止 raw tail 与 memory selected recent window 重叠；current input 通过 `render_scope.user_input_event_id` 排除
- **异常处理**：`_protected_recent_raw_tail_blocks` 在 `protected_recent_turn_group_ids_for_material_blocks` 抛出 `ValueError` 时转换为 `HostDurableError`；`_validate_loaded_compact_view_matches_event` 在 provenance 不匹配时 raise；`build()` 在 provider raise 时自然传播到调用方
- **边界值**：`selected_recent_window_turn_floor == 0` 时 `_protected_recent_raw_tail_blocks` 直接返回空——正确
- **架构边界**：raw tail provider 通过 `HostTransactionRunner` + `EventLogStore` 读取 durable store，不绕过 Host 边界；不上层依赖 UI/Service；不反向 import
- **过度耦合**：`_ProtectedRecentRawTailProvider` 是 Protocol，支持 noop/durable 两种实现；factory 函数通过可选参数注入，不强制所有调用方传参
