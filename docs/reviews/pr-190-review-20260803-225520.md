## Semantic Ownership 深度分析

### Accept 路径

- **Owner**: `dayu/host/context_governance.py:59` `accept_compact_candidate_v2()`
- **强制机制**: `CompactAcceptedTruthV2` 需要 `_COMPACT_ACCEPTANCE_PERMIT` 私有哨兵（`compaction.py:1676-1682`），仅 `context_governance.py` 导入并使用该哨兵。任何其他模块尝试构造 `CompactAcceptedTruthV2` 会在 `__post_init__` 触发 `ValueError`
- **验收标准**: 按固定顺序执行 5 层检查 —— label existence/kind → exact coverage partition（`represented ∩ dropped = ∅` 且 `represented ∪ dropped = boundary`）→ duplicate/contradiction → information sufficiency → policy caps
- **结论**: 无语义所有权漂移。`_permit` 模式是 Python 中最强的 ownership 运行时强制

### Repair 路径

- **Owner**: `dayu/host/compaction_operation.py:743` `_run_compaction_operation()`
- **Feedback 构造**: `context_governance.py:117` `build_compact_repair_feedback_v2()` —— governance 生成 report，operation 将 feedback 路由回 LLM
- **Bounding**: 32 issues max、240 chars/issue、8192 chars total —— 防止 runaway repair loop
- **Repair 语义**: `COMPACT_REPAIR_REQUIRED_ACTION` 常量要求完整 candidate 重新生成（非 patch）
- **结论**: repair 所有权正确分层 —— governance 诊断、operation 调度、LLM 重新生成

### Fallback 路径

- **Owner**: `dayu/host/dispatch.py:3385` `_append_compaction_failed_with_proactive_fallback()`，fallback 构造由 `compact_pipeline.py:741` `build_fallback_decision_input()` 拥有
- **行为**: 确定性 recent-window 选择（非 LLM 生成），使用 `ContextSizingStage.DISPATCH_FALLBACK` 强制保守估计
- **安全性**: 若 fallback window 仍超 hard budget，dispatch fail closed
- **结论**: fallback 有意产生与 accept/repair 语义不同的结果（raw material vs. compacted semantic），由设计决定

### Terminal 状态

- **Owner**: `dayu/host/compaction_terminal.py:98` `begin_compaction_terminal_commit_in_transaction()`
- **强制机制**: 在 write transaction 内 fresh read 作为唯一线性化点；返回 `CompactionTerminalCommitPermit`（可写）或 `CompactionTerminalClosed`（已关闭）
- **4 种 disposition**: `OPEN`、`COMPACTED`、`FAILED`、`INVALID_MULTIPLE`
- **结论**: terminal ownership 集中且正确；所有 5 个 call site 遵循一致的处理模式
