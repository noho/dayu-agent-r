## N1 Root Cause / Call Chain

1. `_HtmlImageExtractor.handle_starttag` 只收集直接 `img`/`picture source` 输入、首个带 `href` 的 base 和首属性值。
2. `SecDownloader.discover_html_image_dependencies` 校验既有 descriptor，解码 HTML，解析有限 srcset，对每个 candidate 调用 `_canonical_image_reference`；错误由 SEC downloader owner 投影为封闭 typed error。
3. `_parse_image_address` 先做 raw backslash/control/drive/percent/encoded separator 检查，再对 path 做一次严格 UTF-8 `unquote`，拒绝解码后仍存在的 percent triplet、控制字符和编码点段，返回 decoded `SplitResult`。本文件中 `unquote` 只出现在这个 owner。
4. `_resolve_image_address` 在 decoded path 上解析 relative、full、protocol-relative、root-relative 和首 base，保留 `%`、`;`、query/fragment 的边界语义，不把 decoded path 重新序列化给 URL parser。
5. `_is_same_image_archive` 用同一 decoded path components 做 origin/申报边界比较，包含 Archives、edgar、data、CIK、accession 和文件名组件。
6. `_canonical_image_reference` 统一产生 `name` 与 `archive_base + quote(name, safe="")`，丢弃最终 query/fragment；子目录、碰撞和本页 fragment 保持原 typed/ignore 边界。下游只消费该 identity，不再二次解码或从 raw path 反推。
7. 同一 key 的字面/编码表示去重；descriptor 统一排序后才 HEAD/GET。正式 Fs workflow 验证 404 原子保留、fresh/old 补齐、retry、repeat 零请求、meta-files/blob/manifest/URI/SHA/fingerprint 一致。
