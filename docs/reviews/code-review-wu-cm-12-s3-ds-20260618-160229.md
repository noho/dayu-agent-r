## 逐项重点审查结论

### 1. selected_material_view_digest 覆盖范围

**结论: PASS。** `selected_material_view_digest`（`compact_material.py:569-591`）的 digest 输入为 `{block_id, canonical_source_refs, content_digest}` 的排序列表。

- **block_id**：覆盖 block 身份标识，防止 selected view 中出现非预期 block。
- **canonical_source_refs**：覆盖来源事件 provenance，证明 material 来源一致。
- **content_digest**：`content_digest` = `sha256(normalized_material_text(text))`，覆盖实际 LLM 可见文本内容。文本变更必定导致 content_digest 变更 → view_digest 变更 → mismatch 被捕获。

不覆盖的字段（`kind`、`section`、`event_sequence`、`turn_group_id`、`source_labels`）在 fallback 渲染上下文中是安全的省略：
- `kind` / `section`：从同一 `material_blocks` tuple 按 `block_id` 取回的 block 对象本身，其 `kind`/`section` 在构建时即确定，不可能在 selection→rendering 之间变化。
- `event_sequence` / `turn_group_id`：排序与分组一致性通过独立的 `_validate_fallback_protected_groups` 与 `selected_raw_turn_count` 保护。
- `source_labels`：prompt-local label，不影响 LLM-facing 内容同源性。

**digest 足以证明 LLM-facing 内容与 selection 时同源，不会造成漂移。**

### 2. EventLogContextFallbackProvider fail-closed 行为

**结论: PASS。** `_load_context_fallback_tx`（`context_fallback.py:314-386`）的 fail-closed 改造完整：

| 检查点 | 旧行为 | 新行为 | 行号 |
|--------|--------|--------|------|
| window 或 digest 缺失 | `return None`（静默跳过） | `raise HostDurableError("active fallback input window is missing")` | 358-359 |
| window digest 与记录不一致 | 无检查 | `raise HostDurableError("fallback input digest mismatch")` | 360-361 |
| current_input_ref 不匹配 | `return None`（静默跳过） | `raise HostDurableError("fallback current_input_ref mismatch")` | 363-364 |
| current_input_ref 为 None | `return None`（静默跳过） | `raise HostDurableError("fallback current_input_ref is missing")` | 366-367 |

不再有任何路径将损坏/不匹配的 fallback 静默转换为 `None`。每个异常都通过 `HostDurableError` 明确失败，由 `load_context_fallback`（行 290-312）向上传播至 `RunInputBuilder.build()`，导致 dispatch 失败（fail-closed）。

**注意**：`source_refs` 现在为 fallback window 中的必填字段（`_required_text_tuple`，行 371）。若存在 S2 写入的 fallback window（不含 `source_refs`），S3 代码读取时将触发 `HostDurableError`。这是预期的格式不兼容——开发分支上的状态应随代码演进重建。若计划在已有持久化状态的环境部署，需要迁移或兼容读取逻辑。
