## Findings

### 1-未修复-低-`_rollback_without_business_terminal` 捕获 `BaseException` 会吞掉信号异常

- **入口/函数**: `execute_prepared_filing_publication()` 的 SKIP/cancel 回滚路径
- **文件(行号)**: `dayu/fins/pipelines/filing_upload_publication.py:507-512`
- **输入场景**: SKIP 或 checkpoint 取消路径中，`rollback_batch()` 内部发生 `KeyboardInterrupt` 或 `SystemExit`
- **实际分支**: `except BaseException as rollback_error` 捕获所有异常，包括信号异常
- **预期行为**: 信号异常（`KeyboardInterrupt`/`SystemExit`）应立即传播，不应被业务逻辑拦截
- **实际行为**: 信号异常被包装为 `FinsUploadFailureError(fins_upload_prevalidation_io_failure())` 抛出，丢失信号语义
- **直接证据**: 行 509 `except BaseException as rollback_error`，行 510-512 `raise FinsUploadFailureError(...) from rollback_error`
- **影响**: 进程优雅关闭路径被阻断。用户 Ctrl+C 后本应立即退出的流程会继续执行异常处理逻辑。注意：同文件的 `rollback_prepared_upload_batch()`（由 `_raise_failure_after_rollback` 调用，用于 CONFLICT/validation failure 路径）也捕获 `BaseException`，但它保留了原始异常作为 primary，信号语义损失较小
- **建议改法和验证点**: 改为 `except (OSError, RuntimeFileLockError, ValueError, RuntimeError) as rollback_error`，只捕获仓储协议文档中 rollback 可能抛出的业务异常类型。或在 `BaseException` 捕获中显式 re-raise `KeyboardInterrupt` 和 `SystemExit`
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低 — `rollback_batch` 在实际实现中不太可能抛出信号异常，但作为防御性编码应修正

### 2-未修复-中-`_read_fresh_state_or_raise` 和 `_begin_publication_batch_or_raise` 遗漏 `RuntimeError` 映射

- **入口/函数**: `execute_prepared_filing_publication()` 的 fresh state 读取和 batch acquire 路径
- **文件(行号)**: `dayu/fins/pipelines/filing_upload_publication.py:544-575`（`_read_fresh_state_or_raise`）和 `:578-603`（`_begin_publication_batch_or_raise`）
- **输入场景**: batch staging view 中 inspector 未返回 target、可信状态缺少 business meta、或 writer lock 内部 reservation 失败
- **实际分支**: 两个函数都捕获 `CompanyTickerIdentityCorruptionError`、`ValueError`、`OSError`、`RuntimeFileLockError`，但未捕获 `RuntimeError`
- **预期行为**: 按仓储协议文档，`read_filing_upload_state_in_batch` 可抛出 `RuntimeError`（行 496："exact inspector 未返回 target 或可信状态缺少 business meta 时抛出"），`begin_batch` 可抛出 `RuntimeError`（行 429："本地 reservation 或跨进程 writer lock 失败时抛出"）。这些应被映射为 typed `FinsUploadFailureError(STORAGE_IO)`
- **实际行为**: `RuntimeError` 穿过 `try/finally` 块。`finally` 正确执行 rollback（`batch_terminal_started` 仍为 `False`），但异常最终以裸 `RuntimeError` 抛出调用方
- **直接证据**: `_read_fresh_state_or_raise` 行 564-575 只有三个 except 分支；`_begin_publication_batch_or_raise` 行 596-603 同样只有三个 except 分支；协议 docstring 行 496 和 429 明确列出 `RuntimeError`
- **影响**: 调用方（SEC/CN/HK workflow）的 `except FinsUploadFailureError` 无法捕获此异常，导致它穿透到 workflow 的 `except Exception` generic handler，被 `fins_upload_failure_from_exception` 分类为 `UNEXPECTED_RUNTIME` 而非 `STORAGE_IO`
- **建议改法和验证点**: 在两个函数中增加 `except RuntimeError as error: raise FinsUploadFailureError(fins_upload_prevalidation_io_failure()) from error` 分支
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中 — 异常契约违反，failure code 映射不正确

### 3-未修复-中-`validate_fins_upload_filing_request` 的 `ValueError` 未在 `execute_prepared_filing_publication` 中被捕获

- **入口/函数**: `execute_prepared_filing_publication()` 的 fresh validation 路径
- **文件(行号)**: `dayu/fins/pipelines/filing_upload_publication.py:671-683`
- **输入场景**: `validate_fins_upload_filing_request` 内部 storage producer 返回非法 identity 或状态不变量违约
- **实际分支**: 行 676 捕获 `FinsUploadUsageError`，行 681 捕获 `FinsUploadPrevalidationError`，但 `ValueError` 未被捕获
- **预期行为**: `validate_fins_upload_filing_request` 的文档声明会抛出 `ValueError`（"storage producer 返回的 target identity 或状态不变量违约时抛出"）。按函数 docstring（行 633）承诺的异常契约，应只抛出 `FinsUploadFailureError`/`FinsUploadUsageError`/`TypeError`/`ValueError`/`BaseException`
- **实际行为**: `ValueError` 穿过 inner try 块，在 outer try 块中也未被捕获。`batch_terminal_started` 仍为 `False`，`finally` 正确执行 rollback，但异常以裸 `ValueError` 抛出调用方
- **直接证据**: 行 671-683 的 try/except 只处理 `FinsUploadUsageError` 和 `FinsUploadPrevalidationError`；`validate_fins_upload_filing_request` 的 docstring 明确列出 `ValueError`
- **影响**: 调用方预期 `execute_prepared_filing_publication` 只抛出 typed failure，但实际可能收到裸 `ValueError`。与 Finding 2 同类问题——failure code 映射不正确
- **建议改法和验证点**: 在 inner try 块增加 `except ValueError as error: validation_failure = fins_upload_prevalidation_corruption_failure()` 分支，或在 `execute_prepared_filing_publication` 的 outer try 块增加统一的 `ValueError` 映射
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中 — 异常契约违反
