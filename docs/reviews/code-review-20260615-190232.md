- **文件(行号)**: `dayu/fins/ingestion_runtime.py:3652-3653`, `dayu/fins/ingestion_runtime.py:3773-3774`, `dayu/fins/ingestion_runtime.py:2199-2212`, `dayu/fins/ingestion_runtime.py:2214-2227`; `tests/fins/test_fins_ingestion_runtime.py` (缺失断言)

  2. 上传 `FinsUploadResultSummary.status="failed"`（completed_with_failures 路径）
  3. 预处理文档触发 `_PreprocessNotSupportedError`（document_not_supported progress）
  4. 预处理文档因任意 `Exception` 失败（document_failed progress）
- **实际分支**: 上述四个分支的 progress event 写入均已实现，但测试未断言这些分支的 `source_event_type` 实际值。
- **预期行为**: `pytest` 应能直接断言 `source_event_type` 为 `"download.completed_with_failures"`、`"upload.completed_with_failures"`、`"preprocess.document_not_supported"`、`"preprocess.document_failed"`。

  - 没有测试为 adapter/runner 注入 `failed_count > 0` 或 `status="failed"` 并断言 progress 类型
  - 没有测试为 preprocess 文档注入不支持处理器或异常来断言 `document_not_supported` / `document_failed` progress

### DS-S2-F02-未修复-低-semantic-preprocess-skipped-not-supported-overlap

- **入口/函数**: `_execute_preprocess_request` 的 summary 构造，`_preprocess_summary_progress_payload` 的 payload 构造
- **文件(行号)**: `dayu/fins/ingestion_runtime.py:2261`, `dayu/fins/ingestion_runtime.py:3889-3904`
- **输入场景**: 预处理请求中部分文档被 `not_supported`、部分被 `skipped`。
- **实际分支**: `FinsPreprocessResultSummary.skipped_count = len(skipped_ids) + len(not_supported_ids)`（line 2261），即 `skipped_count` 将 `not_supported` 文档纳入计数。`_preprocess_summary_progress_payload` 将此值原样写入 progress event 的 `skipped_count` 字段（line 3893）。
- **预期行为**: per-document progress 事件已正确区分 `document_skipped` 和 `document_not_supported`。consumers 可能据此预期 summary 中 `skipped_count` 只包含实际 skipped（不含 not_supported），即 `skipped_count == len(skipped_ids)`。
- **实际行为**: `preprocess.completed` progress event 中 `skipped_count=5` 可来自 3 个 skipped + 2 个 not_supported，而 per-document 事件只发出 3 条 `document_skipped`；consumers 做计数交叉校验时可能困惑。
- **直接证据**:
  - Line 2261: `skipped_count=len(skipped_ids) + len(not_supported_ids)` — 两个语义不同的类别合并
  - Line 3889-3904: progress payload 直接复用此值，未在 progress 层归一化
  - `test_start_preprocess_skips_existing_processed_document_without_rebuild` (line 2074) 断言 `skipped_count=1` 对应 1 个 skipped 文档，此时 `not_supported_count=0`，巧合正确
- **影响**: 下游 Service/CLI consumers 做进度展示时，若尝试将 `skipped_count` 与 `document_skipped` 事件数量对齐，会发现不匹配。该语义重叠是 pre-existing（S1 的 summary model 已如此），S2 将其投影到 progress 事件后首次暴露给下游。
- **建议改法和验证点**:
  - 选项 A（保守）：在 `_preprocess_summary_progress_payload` 中将 `skipped_count` 纠正为 `len(skipped_ids)`（仅真正 skipped，不包含 not_supported）。需同步修改 `FinsPreprocessResultSummary` 构造以保持 job record 和 progress payload 一致，但可能影响既有 test 对 job record 的断言。
  - 选项 B（轻量）：在 progress payload 中新增字段或 docstring 说明 `skipped_count` 包含 `not_supported`。不改变 job record 语义。
  - 考虑到本条是 observation-only progress，S2 scope 内可接受 defer 到后续 slice 由 Service consumer 需求驱动决策。
- **修复风险（低）**: 选项 A 涉及 job record 和既有 tests 改动，S2 scope 外；选项 B 无需改动。
- **严重程度（低）**: observation-only 信号，不改变业务终态；语义重叠可被 downstream consumer 适配。
