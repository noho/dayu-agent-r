## Review 逐项裁决

### 1) memory/compact/fallback selector 是否真的按 newest non-null host_run_id/turn_group_id group floor

**结论: PASS。** 三个 selector 均从 raw item count 切换为 turn-group-based floor：

- `memory._protected_recent_run_ids` (`memory.py:2003-2038`): 过滤 eligible items (USER/ASSISTANT/EVIDENCE) → 校验 `run_id is None` 则 raise → 按 `run_id` 分组取 newest → 返回 top N group ids。
- `compact_material._protected_recent_turn_group_ids` (`compact_material.py:1530-1566`): 过滤 eligible blocks (USER_INPUT/ASSISTANT_FINAL_ANSWER/ACCEPTED_TOOL_EVIDENCE) → 校验 `turn_group_id is None` 则 raise → 按 `turn_group_id` 分组取 newest → 返回 top N group ids。
- `context_fallback._protected_recent_turn_group_ids` (`context_fallback.py:614-647`): 同上逻辑，作用于已校验的 blocks。

三个 selector 的 eligible filter 一致包含 EVIDENCE material（`_is_selected_recent_turn_item` / `_is_turn_group_material_block`），与 design 24.1 "一个受保护 turn group 至少覆盖该 Run 的 user prompt、assistant final answer、accepted tool evidence" 一致。

测试覆盖：`test_selected_recent_window_floor_protects_recent_run_groups` 证明 memory selector 保护 run-mid (3 blocks) + run-new (3 blocks) 共 6 items；`test_proactive_segment_recent_floor_uses_turn_groups` 证明 compact selector 保护 run-mid (2 blocks) + run-new (2 blocks) 共 4 blocks；`test_recent_window_fallback_floor_preserves_turn_group_blocks_over_caps` 证明 fallback selector 保护 run-new (3 blocks)。

### 2) floor/cap/hard-budget priority 是否符合 plan

**结论: PASS。** fallback selection (`context_fallback.py:334-433`) 实现了 plan §S2 的 5 步算法：

1. **Floor 先建**: `floor_ids` 由 `_protected_recent_turn_group_ids` 确定，通过 `_required_block_ids` 进入 `selected_ids`（行 382-386）。
2. **Floor-only hard budget check**: `required_budget` 估算 floor + current + stable 的预算（行 388-394）。floor 本身不被裁剪。
3. **Non-floor whole-block append under caps**: 迭代 `raw_blocks` 中非 `selected_ids` 的 block，先检查 `_fallback_caps_allow_append`（行 400-406），再检查 hard budget（行 409-418）。
4. **Hard budget rollback whole block**: `candidate_budget.hard_budget_passed` 为 False 时设 `blocked_next_block_id` 并 `break`（行 416-418），不追加该 block。
5. **Floor-only remains if no append**: 若无 non-floor block 可追加，`selected_ids` 保持 floor + current + stable。

`_fallback_caps_allow_append` (`context_fallback.py:650-672`) 中 `len(selected_blocks)` 包含 floor blocks，这是正确的：floor 本身不受 cap 约束（floor 在进入循环前已加入 `selected_ids` 并在循环中被 `continue` 跳过），但 non-floor append 的 item 计数以 floor 为基数，确保 "cap 不裁剪 floor 但 cap 限制 non-floor 总量"。

测试覆盖：`test_recent_window_fallback_floor_preserves_turn_group_blocks_over_caps` 证明 floor (3 blocks) 不受 `fallback_selected_recent_window_item_cap=1` 裁剪；`test_recent_window_fallback_caps_stop_without_later_backfill` 证明 cap 拒绝 mid:user 后不选择更旧的 old:user；`test_recent_window_fallback_hard_budget_rolls_back_appended_block` 证明 hard budget 超限时整块回滚；`test_recent_window_fallback_floor_only_over_hard_budget_is_fail_closed_input` 证明 floor-only 超 hard budget 时 selection 保留 floor，budget result 标记失败。
