## 3. Findings

### F01-已闭合-低-CTRL-PR-01: source policy strict-load 循环已消除

- **位置**: plan §5.3.1 "Shared RunInput owner contract" 段 + amendment §5
- **问题类型**: 循环依赖
- **当前写法**: plan 新增 `load_run_input_policy_snapshot_in_transaction`，从 source `RunRow.input_event_id` 精确读取 `USER_INPUT_ACCEPTED.effective_execution_config`，经共享 strict parser 重建 `PolicySnapshot`；source loader 随后用该 policy 校验 manifest/candidate ref/digest/request-semantics。
- **反例/失败场景**: 若 policy 从 candidate 反向构造，startup 无法独立取得 typed policy。
- **直接证据**: plan §5.3.1 `load_run_input_policy_snapshot_in_transaction` 签名 + "它不得读取 current opener policy/current config，也不得从 candidate 只保存的 policy ref/digest 反向构造 policy"；production `run_input.py` 已有 `_execution_config_projection.effective_execution_snapshot_from_json` 共享 parser。
- **结论**: plan 正确描述了消除循环的链路。`load_run_input_policy_snapshot_in_transaction` 与 `load_prepared_runner_call_source_in_transaction` 尚未在 production 代码中实现（amendment 明确标记 implementation `not accepted`），但 plan 描述的接口签名与 failure matrix 完整。
- **Original blocker disposition**: CTRL-PR-01 已通过 plan fix 闭合。

### F02-已闭合-低-CTRL-PR-01: wait resume 闭集正确收窄为 completed/cancelled

- **位置**: plan §5.3.1 pending producer 总表 "wait completed/cancelled resume" 行 + failure matrix "wait failed/lost outcome" 行
- **问题类型**: 闭集遗漏
- **当前写法**: plan 明确 "failed/lost 不调用 continuity helper，不写 candidate/manifest，也不创建 new Attempt"；amendment §4.1 "failed/lost wait 继续由 existing terminal owner 收口，零 manifest、零 new Attempt、零 pending dispatch"。
- **直接证据**: production `waiting.py:977-1006` 中 `_resolve_in_transaction` 只把 `ResolveWaitCompletedOutcome` 与 `ResolveWaitCancelledOutcome` 交给 `_resolve_resume`；`ResolveWaitFailedOutcome` 交给 `_resolve_failed`（调用 `fail_run_from_waiting_in_transaction`）；`ResolveWaitLostOutcome` 交给 `_resolve_lost`（调用 `mark_run_lost_from_waiting_in_transaction`）。两者均不创建 resume Attempt。
- **结论**: plan 与 production 行为一致。Controller CTRL-PR-01 已通过 plan fix 闭合。
- **Original blocker disposition**: CTRL-PR-01 已通过 plan fix 闭合。

### F03-已闭合-低-CTRL-PR-03: direct promotion 删除范围完整

- **位置**: plan §5.3.1 pending producer 总表 "queued promotion" 行 + amendment §3.1
- **问题类型**: 生产旁路残留
- **当前写法**: plan 要求 "删除 admission method/operation、durable direct transition、promote_queued_run_row 与专属 request/result/skip/validation/event/row helpers 及专属 tests"，"queue promotion 唯一路径为 scheduler `_read_startable_run` 选择 earliest queued 后执行 ordinary candidate/sizing/manifest/start"。
- **反例/失败场景**: 若只删 admission caller，`promote_queued_run_in_transaction` 仍可直接创建 `RUN_STARTED`/`ATTEMPT_STARTED`/pending row。
- **直接证据**: production `run_transition.py:1784` 仍有 `promote_queued_run_in_transaction`，`run_transition.py:1174` 仍有 `create_running_run_with_starting_attempt_in_transaction`；`admission.py:1493` 仍调用 `promote_queued_run_in_transaction`。plan 明确要求删除这些且允许 `run_transition.py` 出现删除 diff。
- **结论**: plan 的删除范围描述完整且明确。production 代码尚未按 plan 执行删除（amendment 标记 `not accepted`），但 plan 本身无遗漏。
- **Original blocker disposition**: CTRL-PR-03 已通过 plan fix 闭合。

### F04-已闭合-低-CTRL-PR-04: 三 slice 边界明确

- **位置**: plan §4.2 + design §25 "交付顺序固定为三个独立 slice"
- **问题类型**: 跨 slice 混淆
- **当前写法**: plan §4.2 明确 "Slice 1 只冻结 candidate、conservative sizing atoms、stage/action 与 manifest，不读取或写 `CONTEXT_BUDGET_EVALUATED`。Slice 2 才为每条完整 sizing 路径在 manifest 后、start/link 前写 canonical fact。Slice 3 才允许 eligible complete candidate 使用 usage anchor。"
- **直接证据**: design §25 "Slice 1 只冻结 complete candidate、conservative sizing atoms、stage/action 与 manifest，不要求也不写 `CONTEXT_BUDGET_EVALUATED`；Slice 2 才追加 canonical fact 与 public projection。startup replay 在 Slice 1 只从 source manifest 复用 candidate 与 canonical sizing atoms 并把 stage 重绑定为 `continuation`；Slice 2 必须从 matching source manifest/fact 校验这些 atoms，以新 Attempt identity 重新派生 `continuation` action 并追加新 Attempt 自己的新 fact，不得复用 source fact identity。Slice 3 才允许 eligible complete candidate 把 conservative method/value 替换为 usage-anchored method/value。"
- **结论**: 三 slice 边界在 plan 与 design 中一致，无跨 slice 混写。
- **Original blocker disposition**: CTRL-PR-04 已通过 plan fix 闭合。

### F05-pass-低-5-stage 显式穷举要求明确但 enum 尚未包含 CONTINUATION

### F08-pass-低-Engine limited manifest 非 pre-start recorder 已正确分离

- **位置**: plan §5.3.1 pending producer 总表 "Engine within-Attempt continuation" 行
- **问题类型**: 架构边界
