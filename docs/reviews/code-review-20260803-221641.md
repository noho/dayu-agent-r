### 5. 四种 drop reason 互斥与 policy_limit cap 前提

**结论：定义互斥、policy_limit 可见来源正确。** 四种 reason 分别定义：

- `superseded`：旧内容被更新/更完整/更权威替代，继续保留会过时/冲突/误导；replacement 保留替代后的当前内容
- `redundant`：内容仍有效但已完整表达，丢弃不损失独立信息；不能掩盖冲突或遗漏
- `out_of_scope`：与当前输入/任务/可预见后续无关；不能因难分类/冲突/依据不足使用
- `policy_limit`：仍相关且原本应保留，当前 repair feedback 明示具体 cap，为满足 cap 必须舍弃；首次请求/无 feedback/无具体 cap 禁止使用

四种 reason 的互斥性由各自定义中的 distinct triggering condition 保证：
- superseded：需要存在更新的替代 source
- redundant：需要信息已被其它 source/semantic item 完整表达
- out_of_scope：需要与任务无关
- policy_limit：需要 repair feedback + 具体 cap + 必须 drop 才能满足 cap

line 68 显式声明"四种 reason 是对 source 实际业务关系的互斥解释，不是固定优先级"，防止模型按固定优先级机械选择。

`policy_limit` 的可见来源链正确：`context_governance.py:492-577` → 只在 candidate 超限后生成 per-section item/char cap issue → `build_compact_repair_feedback_v2` 投影为 repair feedback JSON → prompt 告知模型只有收到 repair feedback 且其中有具体 cap 时才能使用 `policy_limit`。首次请求无 repair feedback，因此无具体 cap，禁止使用——链闭合。

owner test 覆盖 drop reason 的 11 项语义，漏 3 项——见 F01。
