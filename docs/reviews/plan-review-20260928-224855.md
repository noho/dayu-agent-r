## Residual Risks（建议跟踪去向：implementation gate 与其后的 code review gate）

1. **隐藏树扫描无上界（低）**：helper 对点号目录做全树 `lstat` 递归，树规模由外部环境工具控制而非 storage owner；超大隐藏树（如误放的 `.git`）会使每次 exact/whole classification（snapshot 还会按 attempt 重复）产生无界扫描成本。现有业务扫描成本由 manifest 声明界定，隐藏树无此界。不阻塞：现实触发场景（`.claude/.cc-writes` 类工具元数据）规模小，且 plan 决策 4 的"无缓存/无白名单"是 goal 认可的最小设计；implementation review 可评估是否值得在 owner 内加注或上界（注意：任何上界都会把"大但安全"的树转为 unsafe，属语义变更，需重新 goal 确认，不得在 implementation 中擅自加入）。
2. **并发写入下 whole preflight 仍可能 flap（低）**：工具在检查期间活跃写入 `.cc-writes` 类目录时，递归命中消失条目会 fail-closed 为 `UNSAFE_PUBLICATION`。此为 plan 已声明的既有 TOCTOU 类风险（"不扩大为全局无竞态保证"），方向安全，仅提示 retry 语义由上层既有机制承载。
3. **回归测试集合未枚举（低）**：S1 结束信号以"受影响测试通过"为 bar，示例命令只列 `test_fins_storage_atomicity.py`；`fs_filing_upload_state` 消费路径的既有测试分布在 `test_filing_upload_publication.py`、`test_fins_ingestion_runtime.py` 等文件。implementation gate 应按 AGENTS.md"运行受影响测试"补上该回归集合，review gate 核对实际运行清单。
4. **候选测试 hunk 不得机械复制（已在 plan 内，提醒执行）**：已声明点号文件、FIFO/嵌套特殊文件、staged exact、`materialize_files=True` 及"snapshot 只含已声明文件"断言须在实施时补齐；review gate 应核对最终测试与 plan S1 三条测试设计的逐项映射。
5. **根 README 措辞约束（已在 plan 内，提醒执行）**：最终句子必须限定"未声明的安全来源元数据"，不得暗示任意点号内容（含已声明点号业务文件）被忽略；若裁定不更新需记录理由。
6. **行为变化记录（信息项）**：root 下"安全点号目录内含可解析 identity descriptor"的条目，新行为为忽略而非按文档检查。真实 API 只产生 `id-` 目录，不可达；方向更安全，无需处理，供 review gate 知悉。
