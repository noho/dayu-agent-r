## Findings

### F1 — Medium — `run_id=None` 的 user row 被错误当成完整已消费 Run group

直接证据：

- accepted plan 的 metadata-first contract 明确规定 `run_id=None` 不能证明完整 Run group 已消费，必须从该 row 开始保守投影；见 plan 第 112–118 行。
- `dayu/host/compact_material.py:2740-2754` 虽然把 `run_id=None` row 包装成 singleton `group`，但 `group_consumed` 只检查“恰有一个 user anchor 且其 event id 在 consumed refs 中”，没有要求 `row.run_id is not None`。
- 因此，只要一个 `run_id=None` 的 canonical `USER_INPUT_ACCEPTED` ref 出现在某条 strict accepted boundary 中，该 row 就会在 payload/atomic proof 之前被静默跳过。实现自己的 docstring 第 2719–2721 行也声称这类 group 无法证明消费，代码与其矛盾。
- 当前新增 owner tests 没有覆盖 accepted chain + consumed `run_id=None` user row，故该偏差未被 85% coverage 与 341-test union 捕获。

影响：

- metadata anchor proof 本应只把 Host admitted Run group 的唯一 user anchor当作 whole-group selection proof。`run_id=None` 没有 group identity，不能证明同一业务 turn 的 answer/evidence 是否完整进入 accepted boundary。
- 当前行为会绕过 suffix typed projection 与 `_atomic_material_units` 的缺失 group id fail-closed，形成 silent consumption；这违反 F14 的“无法证明则保守保留或明确安全终态”以及 accepted plan 的实现约束。
- 正常 production admitted Run 通常携带 `run_id`，所以严重度为 Medium 而非 High；但 durable corruption/restart 边界必须 fail closed，不能由偶然数据形状决定。

owner-level 修复：

1. 在 `_conservative_unconsumed_row_start_sequence` 中要求 `row.run_id is not None` 才允许 `group_consumed=True`；不要在 downstream 增加 fallback。
2. 新增 owner regression：构造 accepted chain whose `compacted_source_refs` 含 `run_id=None` user ref，断言 builder 不静默越过它，并经现有 typed/atomic owner path fail closed（或按 owner 已有严格契约返回明确保守结果）。旧实现必须失败，修复后通过。
3. 复跑 `tests/host/test_compact_material.py`、受影响 union、focused pyright/Ruff 与 coverage。
