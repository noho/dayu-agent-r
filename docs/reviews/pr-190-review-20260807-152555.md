## Findings

### 1-未修复-中-Dual StructuredOutputCapability 枚举定义双真源

- **入口/函数**: `StructuredOutputCapability` vs `StructuredOutputCapabilityConfig`
- **文件(行号)**: `dayu/engine/contracts/structured_output.py:19-31` 和 `dayu/runtime/config_loader.py:108-113`
- **输入场景**: 未来新增 structured output capability 值（如 `json_schema` 的 provider-native 变体）
- **实际分支**: `host_assembly.py:1807-1808` 通过 `.value` 字符串桥接两个枚举；`_execution_config_projection.py:215-218` 同样通过字符串构造引擎枚举
- **预期行为**: 引擎 contract 层应为 structured output capability 的单一真源；config 层不应维护语义等价但定义独立的并行枚举
- **实际行为**: 两个枚举定义各自独立，通过字符串 `.value` 桥接。若一端新增 capability 值而另一端未同步，运行时 `ValueError` 在 config 解析或 host assembly 阶段抛出，但编译期/类型检查期无保护
- **直接证据**:
  - `dayu/engine/contracts/structured_output.py:19-31`：`StructuredOutputCapability` enum with `JSON_OBJECT`, `NONE`
  - `dayu/runtime/config_loader.py:108-113`：`StructuredOutputCapabilityConfig` enum with `JSON_OBJECT`, `NONE`
  - `dayu/service/host_assembly.py:1807-1808`：`StructuredOutputCapability(model.structured_output_capability.value)` — 字符串桥接
  - `dayu/host/_execution_config_projection.py:215-218`：`StructuredOutputCapability(required_json_text(...))` — 字符串桥接
- **影响**: 维护风险——新增 capability 值需要两处同步修改，否则运行时 `ValueError`。当前两个枚举值集合恰好一致，但无 invariant test 保证一致性
- **建议改法和验证点**: engine contract 层增加 invariant test 验证 config enum 成员集合是 engine enum 成员集合的子集；或让 config loader 直接构造引擎 enum 而非定义独立平行类型。当前非阻塞，但应在 merge 前显式记录为 accepted technical debt
- **修复风险（低）**: 添加 invariant test 不改变产品行为
- **严重程度（中）**: semantic ownership drift，但当前两处枚举值一致，实际行为正确

### 2-未修复-低-stream+structured_output 互斥性未校验

- **入口/函数**: `build_request_payload` / `AgentRunRequest.__post_init__`
- **文件(行号)**: `dayu/engine/runners/openai/payload.py:426-443`, `dayu/engine/contracts/agent_run.py:143-146`
- **输入场景**: 未来代码路径同时设置 `stream=True` 和 `structured_output` 非 None
- **实际分支**: `validate_structured_output_request` 只校验 structured_output 自身参数合法性，不检查与 stream 的组合
- **预期行为**: 引擎 contract 应在 `AgentRunRequest.__post_init__` 或 `build_request_payload` 中拒绝 `stream=True` + `structured_output is not None` 的组合
- **实际行为**: payload 会同时包含 `"stream": True` 和 `"response_format": {...}`，OpenAI API 和大多数兼容 provider 会在 HTTP 层拒绝此请求
- **直接证据**:
  - `dayu/engine/contracts/agent_run.py:143-146`：`validate_structured_output_request` 不检查 `runner_options.stream`
  - `dayu/engine/runners/openai/payload.py:426-443`：`build_request_payload` 无条件设置 `stream` 和 `response_format`
- **影响**: 当前不可触发（compactor 使用非流式，interactive 不传 structured_output），但为 latent contract violation
- **建议改法和验证点**: 在 `AgentRunRequest.__post_init__` 中添加互斥校验，以 engine contract 层为唯一 owner
- **修复风险（低）**: 纯校验添加，不影响现有调用路径
- **严重程度（低）**: latent risk，当前无触发路径

### 4-未修复-低-session scope 统一迁移无向后兼容路径

- **文件(行号)**: `dayu/cli/host_context.py:23-27`, `dayu/cli/session_identity.py:50-78`
- **输入场景**: 用户在 PR 190 之前创建了 `--kind prompt` 或 `--kind interactive` 的 session，升级到此分支后运行 `session list` 或 `session resume`

- **直接证据**:

- **影响**: 升级到此分支后，既有 labeled session 无法通过 CLI 管理。如果部署环境中存在活跃 session，需要手动清理 durable store
- **建议改法和验证点**: 确认这是否为预期行为。如果是：在 PR description 或 CLI help 中明确说明 session scope 统一迁移为 breaking change。如果不是：在 `_build_session_label_key` 中增加 fallback 查找旧 scope
