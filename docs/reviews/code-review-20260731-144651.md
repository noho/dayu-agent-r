## Findings

### P1 — SEC Windows drive 校验只检查 basename，路径前缀中的 drive 可被丢弃

位置：`dayu/fins/pipelines/sec_filing_collection.py`

`_normalize_sec_primary_document_name` 先按 `/` 切分，再只对最后一个 segment 调用
`PureWindowsPath(filename).drive`。因此：

- `C:primary_doc.xml` 会被拒绝；
- `C:/primary_doc.xml` 会被接受并投影成 `primary_doc.xml`；
- `xsl/C:/primary_doc.xml` 同样会被接受。

这违反已接受计划的“拒绝 drive syntax”契约，也使严格 owner 边界退化成对非法输入的
loose basename parsing。虽然真实故障输入
`xslSCHEDULE_13G_X02/primary_doc.xml` 不受影响，但通用 producer 不应在下游
storage 之前吞掉非法路径前缀。

要求：逐 segment 校验 Windows drive syntax，并为 drive 位于首段和中间段的反例
补测试。
