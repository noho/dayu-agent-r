## Findings

### 001-未修复-低-Slice 1 测试增量可能极小

- **位置**: Slice 1: Policy Matrix Tests
- **问题类型**: 测试缺口 / 不可直接实施
- **当前写法**: Plan 提出 6 项测试添加，但使用了条件语言："only add assertions if current tests do not already cover"
- **反例/失败场景**: 实施 Agent 执行 Slice 1 时发现 9 项现有测试 + `test_public_host_event.py` + `test_memory_projection.py` 已经覆盖全部 6 项，导致 Slice 1 实际产出为零新增测试
- **为什么有问题**: Plan 的 goal 是 "converge and test the policy"，但 test novelty 可能被高估。实施 Agent 可能困惑于"到底要新增什么"
- **直接证据**:
  - `test_run_payload_final_answer_is_read` 已证明 `final_answer` 优先于 artifact `content`
  - `test_continuity_resolver_reads_digest_checked_terminal_content` 已覆盖 descriptor 一侧缺失时返回 None
  - `test_allowed_non_string_field_strict_raises_and_lenient_returns_none` 已覆盖 malformed descriptor field
  - `test_public_host_event.py` 已覆盖 FAILED/CANCELLED/LOST 不含 final_answer
  - `test_memory_projection.py` 已覆盖 `summary_text`/nested `summary` 不 materialize
- **影响**: Slice 1 可能产出空增量，review agent 难以判断"policy 是否已收敛"
- **建议改法和验证点**: 在 plan 中明确列出 "the following specific test scenarios are NOT yet covered"，逐项确认现有测试不覆盖后再列为 Slice 1 deliverable。如果全部已覆盖，将 Slice 1 改为 "document existing coverage matrix" 而非 "add tests"
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

### 002-未修复-低-Policy table 未区分 consumer 行为差异

- **位置**: Policy Target → Policy table + Text handling
- **问题类型**: 契约缺失
- **当前写法**: Policy table 有一行 "Conversation Memory / compaction continuity"，allowed source 写 "may use assistant final-answer continuity for recent-window continuity"
- **反例/失败场景**: 实施 Agent 读到 policy table 后，可能假设 compact material 和 memory projection 走同一路径，实际上 compact material 走 `assistant_final_answer_continuity_text`（follows artifact indirection, STRICT），memory projection 走 `assistant_final_answer_text_from_run_payload`（inline only, LENIENT）。如果未来有人基于 policy table 修改 memory projection 让它也 follow artifact indirection，会改变 memory projection 的 resilience 语义
- **为什么有问题**: 两个 consumer 的行为差异是设计决策，不是实现细节。Compact material 需要 strict + artifact hydration 以保证上下文完整性；memory projection 需要 lenient + inline-only 以保证 resilience。Policy table 把它们合并为一行，丢失了这个设计信号
- **直接证据**:
  - `compact_material.py:1995`: `assistant_final_answer_continuity_text(transaction, payload, text_policy=PayloadTextReadPolicy.STRICT_NON_EMPTY)`
  - `memory.py:1616`: `assistant_final_answer_text_from_run_payload(event.payload, text_policy=PayloadTextReadPolicy.LENIENT_NON_EMPTY)`
  - `tests/host/test_memory_projection.py`: `test_run_succeeded_payload_refs_do_not_materialize_assistant_window` — memory projection does NOT follow artifact indirection
- **影响**: Future agent 可能误解 policy，修改时破坏一个 consumer 的行为
- **建议改法和验证点**: 在 policy table 的 Conversation Memory 行或 Text handling 部分，明确说明 compact material 和 memory projection 使用不同 helper、不同 text policy、是否 follow artifact indirection。Slice 2 docstring 收敛时在 `_terminal_answer.py` 和 `terminal_summary_payload.py` 的 module docstring 中记录这个分工
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

## Conclusion

**PASS-WITH-FINDINGS**

Plan 结构合理：motivation 成立（收敛已有 policy，非重复设计），scope 适当窄（tests + docstrings），sequencing 正确（先测试后文档），layering 未违反 `UI -> Service -> Host -> Engine`，未引入兼容 wrapper/re-export 风险。Non-goals 明确且合理。Overlong text 归属正确。

两个 findings 均为低严重度：(1) Slice 1 测试增量可能极小，plan 应更明确列出哪些场景确实未覆盖；(2) Policy table 未区分 compact material 和 memory projection 的行为差异，docstring 收敛时应补充。两者均不阻塞 implementation，但应在 Slice 1 实施前由实施 Agent 确认。
