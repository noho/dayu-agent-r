## Findings

以下是对关键正确性路径的逐条走读结论：

### 1. Construction contract: `OpenHostOptions.wait_poller_policy` / `HostToolingOptions.wait_poll_adapter_registry`

`api.py` adds `wait_poller_policy: WaitPollerRuntimePolicy | None = None` to `OpenHostOptions`. `tooling.py` adds `wait_poll_adapter_registry: WaitPollAdapterRegistry | None = None` to `HostToolingOptions`. Both use `TYPE_CHECKING` import to avoid circular dependency. `None` defaults preserve existing no-poller behavior. Correct.

### 2. `WaitPollerRuntimePolicy.enabled` as Slice 3 API increment

`wait_adapter.py` adds `enabled: bool = True` as first field with default. `__post_init__` validates `isinstance(self.enabled, bool)`. The `enabled=False` path in `_enabled_wait_poller_configuration` returns `None` (no poller) without requiring a registry. This allows policy validation without starting the poller. Backward compatible: existing code constructing `WaitPollerRuntimePolicy(...)` without `enabled` gets `True` (poller starts). Correct.

### 3. Enabled policy without registry: construction-time fail-fast

`_validate_wait_poller_configuration` calls `_enabled_wait_poller_configuration` which raises `HostApiError(code=INVALID_STATE, ...)` when `policy.enabled=True` and `tooling_options.wait_poll_adapter_registry is None`. Called early in `__aenter__` before durable store creation. `test_open_host_wait_poller_policy_without_poll_registry_fails_fast` verifies `HostApiError` with `"wait_poll_adapter_registry"` in message. Correct.

### 4. Poller factory creates thread-local durable store/command handle

`_OpenHostWaitPollerFactory.create_wait_poller` calls `open_host_durable_store(...)` inside the supervisor thread, creating a fresh SQLite connection per poll round. Creates `HostCommandHandle` with fresh `admission_service` and `active_registry`. Wraps in `_ClosingWaitPoller` that closes the command handle in `finally`. No reuse of opener-thread `HostTransactionRunner`. Correct.

### 5. Poller `resolve_wait` goes through command path and wakes scheduler

`_CommandHandleWaitResolver.resolve_wait` calls `_resolve_wait(self._command_handle, wait_id, request)` — the same command path as manual/callback resolution. The command handle is constructed with `admission_service=create_host_admission_service(transaction_runner, wakeup_port=self.wakeup_port)`, where `wakeup_port` is `_ThreadsafeSchedulerWakeupPort`. After `resolve_wait` commits, the after-commit wakeup calls `wake_dispatch` → `_run_on_loop` → `loop.call_soon_threadsafe(callback)` → `future.result()`. Correct.

### 6. `_ThreadsafeSchedulerWakeupPort` deadlock safety

`_run_on_loop` uses `loop.call_soon_threadsafe(run_callback)` + `future.result()` to synchronously execute the wakeup on the event loop thread. The close sequence is: `__aexit__` → `asyncio.to_thread(poller.close)` (yields to loop) → poller thread drains → poller thread finishes → `to_thread` future resolves → `__aexit__` continues → `scheduler.close()` → loop exits. During poller close, the loop is still alive (awaiting `to_thread`), so `call_soon_threadsafe` callbacks can execute. If the loop is already closed (shouldn't happen during normal close), `call_soon_threadsafe` raises `RuntimeError`, which propagates to `resolve_wait` exception handler → backoff release. Correct.

### 7. Public handle close: poller-before-scheduler

`_PublicHostHandle.close()` closes `self._wait_poller` first (via `asyncio.to_thread`), then `self._scheduler`. If poller close fails, the error is captured and scheduler close still proceeds. First exception is re-raised at the end. `test_public_host_close_closes_wait_poller_before_scheduler` verifies `order == ["poller", "scheduler"]`. Correct.

### 8. Open failure cleanup: poller-before-scheduler

In `__aenter__`, after `wait_poller.open()` succeeds but before `_PublicHostHandle` construction, if an exception occurs, the failure path closes poller before scheduler. `test_open_host_startup_failure_closes_poller_before_scheduler` monkeypatches `_PublicHostHandle.__init__` to raise, verifies `order[:2] == ["poller", "scheduler"]`. Correct.

### 9. Default no-poller behavior preserved

`OpenHostOptions.wait_poller_policy` defaults to `None`. `_enabled_wait_poller_configuration` returns `None` when policy is `None`. `_wait_poller_supervisor_from_open_host_options` returns `None`. `_PublicHostHandle` receives `wait_poller=None`. `close()` skips poller close when `self._wait_poller is not None` is false. All existing no-poller tests continue to pass. Correct.

## Residual Risk

- **`WaitPollerRuntimePolicy` not in package-root `__all__`**: `dayu/host/__init__.py` was outside allowed Slice 3 file list. Service composition must import from `dayu.host.wait_adapter` or `dayu.host.api` (TYPE_CHECKING). Low risk; follow-up namespace cleanup.
- **Service configuration mapping not implemented**: explicit non-goal. Service composition owner must map config to `wait_poller_policy` / `wait_poll_adapter_registry`.
- **Synchronous poll adapters cannot be forcibly interrupted**: accepted design tradeoff. Close waits for in-flight calls.
- **`_ThreadsafeSchedulerWakeupPort._run_on_loop` blocks poller thread**: if the event loop callback takes long, the poller thread blocks. Mitigated by the callback being a simple scheduler wakeup (no I/O).
