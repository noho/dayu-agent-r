## Call-chain / Ownership Review

- 三类图片入口和 base 都进入 `_canonical_image_reference`，由同一 owner 产生 `name + canonical URL`；literal/encoded 分号同 canonical，最终 query/fragment 从 path 身份去除，不同名称不合并。没有在 workflow、adapter 或展示层补 basename。
- HTMLParser 的首值语义只在 extractor owner 决定；下游不收集重复属性或反推浏览器行为。
- `%25`、二次 `%HH`、编码分隔、控制字符与 collision 均在 downloader 发现边界处理；storage `source_asset_name_collision_key` 仍是文件名真源，非法基础名只在 downloader 的 typed exception 边界投影，不在 workflow 兜底。
- 发现结果先合并 `base descriptors ∪ image descriptors`，再由原 `build_source_fingerprint` 产生完整集合指纹；upsert、files[]、blob URI/hash/size、manifest、document_version、download_version、processed 标记沿既有 owner 链消费同一结果。
- 发现失败在 `begin_batch` 前返回 `FILING_FAILED`；图片 transport/存储失败在同一 batch rollback。fresh 失败保持 MISSING，upgrade/overwrite 失败保留旧 meta/files/bytes/manifest/revision/hash/version/processed 状态。
- Phase A/B 使用同一 `_can_skip_fast` 版本资格，完整集合 `_can_skip` 位于图片发现后；旧/缺版本普通升级，当前版本空 fp 在基础 GET/发现/可选 HEAD 后才允许等价 skip。rebuild 不授予 download version。
- 取消检查进入候选循环、HEAD 与 prefetch；identity churn rollback 后重试，竞争 writer 的当前版本 publication 被保留，旧版本 writer 仍触发升级。该主链的回归由 owner tests 205 项覆盖。
