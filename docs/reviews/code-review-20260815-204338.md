## Review Detail

### 1. Identity formula — PASS

`_build_filing_original_asset_identity` (line 1090-1114) 使用 `fins-upload-asset-v1 + NUL + normalized_path.as_posix()` 的 SHA-256，输出形状为 `original-<64-hex><lower-suffix>`。

- **无绝对路径明文**：SHA-256 digest 不可逆，测试 `test_filing_same_basename_assets_are_collision_free_and_path_private` 断言 `tmp_path not in identity`。
- **稳定 / 顺序无关**：`test_filing_identity_is_stable_and_request_order_independent` 验证正反序一致、重复调用一致。
- **suffix.lower() 一致化**：大写后缀（`.PDF`）被归一化为 `.pdf`，避免因大小写产生不同 identity。
- **输入校验**：要求 `is_absolute()` 且 `resolve(strict=False) == self`，拒绝相对路径和未规范化路径。
- **同 basename 不同目录碰撞**：不同路径 → 不同 hash → 不同 identity，测试已覆盖。

### 2. Collision detection — PASS

`_require_unique_filing_original_identities` (line 1135-1150) 在 `_build_original_assets` 末尾执行，于 converter/batch 前 fail closed。

- `test_filing_generated_identity_collision_fails_before_converter_and_batch` monkeypatches identity 函数为常量返回，断言 `RuntimeError("identity 必须唯一")` 且 converter 未被调用、batch 未开始、published tree 为空。

### 3. Filing fingerprint — PASS

`_build_upload_source_fingerprint` (line 1223-1272) 对 filing 使用 `original_filename/sha256/size/source`，排除 path-derived identity 和请求顺序。

- **移目录 skip**：同 basename + 同内容 → 同 fingerprint → skip。`test_filing_fingerprint_excludes_path_identity_but_tracks_filename_and_content` 验证 moved file `status == "skipped"`。
- **改名 update**：不同 basename → 不同 fingerprint → upload + version increment。
- **改内容 update**：同 basename 不同 sha256 → 不同 fingerprint → upload + version increment。
- **排序稳定**：按 `(original_filename, sha256, size, source)` tuple 排序，`json.dumps(sort_keys=True)` 保证序列化确定性。
