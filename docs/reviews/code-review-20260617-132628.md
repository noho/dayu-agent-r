## Residual Risk

- `_tool_display_name` 在投影每条工具 activity 时需要两次额外 SQLite 查询（read_run_by_id + read_event_by_id），在高频 tool call 场景下可能增加 read projection 延迟。当前 SQLite 本地查询足够快，不构成阻塞，但 Slice B 的 Service activity callback 消费路径应评估是否需要批量预取或缓存 input payload lookup。
- `_activity_payload_without_descriptor` 对 `CONTEXT_COMPACTED` / `PROVIDER_PROTOCOL_ERROR` 等 canonical_fact 事件不跟随 payload descriptor。如果这些事件的 payload 被外置到 descriptor，投影会降级为空 summary 而非 `activity=None`。当前实现符合 plan 允许的降级策略，但如果 engine_ingest 对这些事件使用 descriptor，应补充对称测试。
- `HostEvent` 新增 `event_class` / `event_type` / `activity` 三个字段改变了 frozen dataclass 构造签名。所有已有构造点（包括测试 fixture）都需要同步更新。当前 diff 已更新所有测试，但未在 diff 范围内的外部调用方如果直接构造 `HostEvent`，会在 pyright 下报错。这是 breaking change 的正确行为，不是缺陷。
- terminal `HostEvent` 的 `activity` 字段当前由 `_run_lifecycle_activity` 填充（如 `RUN_SUCCEEDED` → `COMPLETED` / `运行已完成`）。Slice B 的 Service activity callback 在消费 terminal event 时应判断 terminal `activity` 是否需要去重或抑制，避免 live watcher 和 outbox terminal fallback 产生重复的 terminal activity 展示。这属于 Slice B 范围，当前 Slice A 不阻塞。
- `tests/host/test_host_activity_event_projection.py` 中 `test_tool_activity_uses_admission_display_snapshot` 和 `test_tool_activity_falls_back_to_stable_name_without_display` 使用 `_BlockingWorkerFactory` 确保 Run 不会在投影前终态，这是一种隐式时序依赖。如果未来 admission 或 projection 路径变为异步，这些测试可能需要调整同步方式。当前同步 `open_host` 上下文内的操作序列足够可靠。
