## 动机与 owner 判定

三项 accepted fix 的动机均由直接代码证据成立：

1. `dayu/host/compact_structure.py` 是 strict JSON structure parser owner；原实现只把稳定 code/path 编入 `ValueError` 文本，`dayu/host/llm_compaction.py` 再从脱敏后的 message 解析语义，违反 typed semantic ownership。
2. `parse_conversation_compact_output_vnext` 的 `request` 只做类型检查，不参与 structure parse；request/source/cap acceptance 由后续 Context Governance accept barrier 拥有，旧参数形成错误的接口承诺。
3. Tool Trace analysis 已正确从 resolver 的 typed `successful_response_identity` 投影 rejected post-success response，但 owner test 只覆盖 accepted disposition，缺少 rejected + identity 的 JSON/Markdown 回归证据。

## 实施

### 1. Typed structure parse failure

- 在 `dayu/host/compact_structure.py` 新增 `CompactStructureParseError`，由 strict parser boundary 直接携带：
  - `CompactValidationIssueCodeV3 code`
  - `str json_path`
  - `str message`
- 所有 LLM JSON structure rejection 分支直接产生 typed code/path；不再要求下游解释 message 前缀或冒号后缀。
- `dayu/host/llm_compaction.py::_structure_validation_report` 只读取 typed fields，再对 `json_path` 与 `message` 分别执行既有脱敏、240 字符上限投影。
- 删除 `_structure_error_path` 与 message-prefix code mapping；未改变 issue code taxonomy、strict validation、repair prompt、output schema、acceptance 或 bounded feedback contract。

### 2. Fresh parser contract

- `parse_conversation_compact_output_vnext` 改为只接收 `final_answer: str`。
- 唯一生产调用方与直接 tests 同步迁移。
- 未保留旧签名 wrapper、alias、兼容分支或旧签名测试。

### 3. Rejected successful response identity owner test

- 在 `tests/host/test_tool_trace_analysis_rules.py` 新增 `ATTEMPT_REJECTED + successful_response_identity` owner test。
- 测试从 `RunnerCallResolvedProjection.compactor_response_identity` 的 typed response identity 出发，断言 structured report、JSON 与 Markdown 均包含实际：
  - effective provider/model；
  - 完整 runner request identity；
  - provider request-id availability/value。
- 邻近 source event payload 刻意写入冲突的 config-like provider/model/request-id，最终输出断言不含这些 poison 值，证明 analysis owner 未从 config 或邻近事件推断 identity。
