## Findings

### 1-未修复-低-旧 US durable document 若 ID seed 含非闭集财期，将无法再通过 upload_filing 更新/删除
- **入口/函数**: `_validate_fins_upload_filing_static`（admission）→ `build_sec_filing_ids`（ID 算法）
- **文件(行号)**: `dayu/fins/ingestion_runtime.py:1279-1287`；`dayu/fins/pipelines/docling_upload_service.py:1954-1970`
- **输入场景**: 在 base `0b7dced4` 下，US filing 曾以非闭集财期成功上传并发布，例如 `--fiscal-period annual`。此后用户用相同参数对该 document 执行 `--action update` 或 `delete`。
- **实际分支**: base 版本 `_validate_fins_upload_filing_static` 的 `else: normalized_period = period_text` 分支（`git show 0b7dced4:dayu/fins/ingestion_runtime.py` 中 1273-1283 行附近）对 US 放行任意非空文本并作为 `build_sec_filing_ids` 的 seed 输入；S1 后所有市场统一走 `normalize_fiscal_period`，`annual` 抛 `ValueError` → `_raise_upload_usage(UNSUPPORTED_FISCAL_PERIOD)`，在 `_filing_upload_request_identity` 阶段失败（`service_runtime.py:81` 先于 workspace read；CLI 先于 service factory）。
- **预期行为**: 该 document 的 update/delete 请求应能重建同一 document ID 并继续既有 action/overwrite/repair 流程。
- **实际行为**: document ID 由 `sha1(f"{ticker}|{fiscal_year}|{period}|{int(amended)}")` 派生，旧 document 的 ID 嵌入了非 canonical period 文本；新 admission 拒绝该文本，因此无法再构造出同一 document ID，update/delete 一律 exit 2 usage failure，旧 document 成为「只能读、不能通过 upload_filing 更新或删除」的冻结状态。
- **直接证据**: base 版本 US 分支为 `normalized_period = period_text`（任意文本放行，无闭集校验）；`build_sec_filing_ids` 以该值直接进 sha1 seed。S1 后 `normalize_fiscal_period` 只接受 `FY/H1/Q1/Q2/Q3/Q4`（`filing_semantics.py:293-314`）。
- **影响**: 仅影响曾在旧宽松 admission 下用非闭集财期成功发布的 US durable document；不损坏数据、不产生错误 ID，但对应 document 的 update/delete 操作被永久阻断（静默表现为 usage failure，无数据破坏）。
- **建议改法和验证点**: 该风险在 accepted plan §11 已按「旧 durable 非法 fiscal period 的兼容读取：schema 规则要求全新设计且用户未要求升级，assigned to later work unit」分类。本 finding 只是把后果从「兼容读取」明确为「update/delete 入口不可达」：后续 work unit 若要处理，需在 owner boundary 提供 legacy ID 重建或一次性迁移路径，而不是在 admission 加兼容分支。S1 无需改动。
- **修复风险（低）**: 无 S1 动作；后续处理若选择做，属独立 work unit。
