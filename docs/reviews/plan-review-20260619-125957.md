## Architecture Change Summary

Plan 的核心架构变化：原设计在 `run_compaction_operation()` 内注入 durable recorder（独立 transaction），现改为：

1. `run_compaction_operation()` 只构建**内存态** diagnostic body/summary，挂到 `CompactionAttemptRejected.diagnostic`。
2. 调用方 append helper（`dispatch.py` / `engine_ingest.py`）在已有的 EventLog **同一事务**内写 artifact bytes + descriptor + rejected event。
3. 不再需要 `run_compaction_operation()` 的 recorder 参数或 `CompactorProposalManifestRecorder`-style protocol。

这个变化是正确的：它消除了 DS-F1 发现的独立事务 orphan 窗口，因为 descriptor insert 和 EventLog append 现在共享同一个 SQLite transaction。

## New Issue Check: Architecture Regression

对架构变化进行 adversarial check：

1. **In-memory diagnostic builder failure**: 如果 `_compaction_rejected_attempt_diagnostic()` 内部抛出意外异常（例如 `CompactMaterialBlock.to_json()` 序列化失败），该异常会落入 `run_compaction_operation()` 的 `except Exception` 分支还是传播到调用方？当前代码结构中，diagnostic builder 在 catch block 内调用（line 210: "Called from both proposal failure catch branches before `_attempt_rejected()`"）。如果 builder 本身抛异常，它会从 catch block 中传播出去，绕过 `_attempt_rejected()` 和后续的 `rejected.append()`，导致 `run_compaction_operation()` 以未处理异常退出。Plan 没有显式要求 diagnostic builder 内部 try-catch。

   **判断**: 这不是 blocker。Diagnostic builder 是纯内存操作（dataclass 构造 + `to_json()` 调用），失败概率极低。但如果 plan 要求 "best-effort"，builder 也应该被 try-catch 包裹。建议在 Implementation Decision #2 中增加一句："If the diagnostic body builder itself raises, catch and return `None`; do not propagate the exception."

2. **Caller append helper transaction scope**: Plan 说 descriptor insert 和 EventLog append 共享同一事务。`dispatch.py:2289` 的 `_append_compaction_attempt_rejected_event()` 已接收 `transaction` 参数。`engine_ingest.py:2064` 的 `_append_reactive_compaction_attempt_rejected_event()` 也需要验证是否在同一事务内。这是一个 implementation detail，plan 已正确指定了架构方向。

3. **Slice 2 test coverage**: Plan Slice 2 tests 说 "Prefer unit-level assertion that a rejected attempt with diagnostic fields builds an event payload through append helper without raw text"。这比 Slice 1 tests 弱。但 Slice 2 的核心职责是 wiring，不是 logic。Slice 1 已覆盖 diagnostic body builder 和 best-effort failure，Slice 2 只需验证 payload 传递。可接受。

**结论**: 架构变化没有引入 blocker 级 regression。In-memory diagnostic builder 的 try-catch 是一个小的防御性改进，不阻塞 implementation。
