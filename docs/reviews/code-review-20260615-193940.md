### 01-未修复-低-`render_fins_direct_terminal_result` 在 S4 后变为未被引用的 public dead code

- **入口/函数**: `render_fins_direct_terminal_result`
- **文件(行号)**: `dayu/cli/output.py:144-177`
- **输入场景**: S4 已将 Fins direct live command 路径改为调用 `render_fins_direct_event`，不再调用 `render_fins_direct_terminal_result`。
- **实际分支**: `_run_fins_direct_command_async` 现在直接返回 `terminal.exit_code`，不经过 `render_fins_direct_terminal_result`。该函数已从 `fins.py` 的 import 列表中移除。
- **预期行为**: 如果该函数已无生产代码或测试使用者，应从 `__all__` 移除或标记为 deprecated internal。
- **实际行为**: 函数仍保留在 `__all__` 中 (`output.py:474`)，但无任何 import 方。`grep -rn 'render_fins_direct_terminal_result'` 仅命中定义行和 `__all__` 行。
- **直接证据**: `fins.py:39-41` 的 import 已从 `render_fins_direct_terminal_result` 改为 `render_fins_direct_event`；`fins.py:229` 改为 `return terminal.exit_code`；全仓搜索无其他 import 方。
- **影响**: 无运行时影响。维护风险低：未来开发者可能困惑于应使用哪个 renderer，或误用旧函数导致 UI 行为与 `render_fins_direct_event` 不一致。
- **建议改法和验证点**: 选项 A：从 `__all__` 移除该函数，保留函数体作为 fallback 供未来直接调用 terminal result 的场景使用。选项 B：保持现状，在函数 docstring 中标注"not used by Fins direct live command path; use render_fins_direct_event for event-stream-based rendering"。无论选哪种，验证 `pyright dayu/cli/output.py` 通过。
- **修复风险（低）**: 仅涉及 `__all__` 或 docstring 修改，不影响运行时行为。
- **严重程度（低）**: 纯维护性问题，不造成重复 UI 或行为错误。

3. **进度事件粒度依赖 S2 runtime-owned coarse progress**：S4 CLI 正确消费了 S1-S3 提供的事件流，但事件内容细粒度由 Fins runtime（S2）决定。如果 coarse progress 不足以提供用户可见的下载/处理进度感，需要回到 Fins pipeline stream consumption 做细粒度改造。Risk owner: 后续 Fins pipeline live-event refinement work unit。
