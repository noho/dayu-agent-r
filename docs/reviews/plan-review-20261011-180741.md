### Lens 应用结论（code-generation-ready / goal-bound minimal design）

- **Goal-bound minimal design**：未发现新增 schema/存储/调度/下游补偿层或新公开 CLI 参数；图片作为正常 blob/source 资产复用既有 batch 事务，owner 划分（downloader 发现/地址边界、workflow 跳过与失败状态、upsert 版本与指纹）与现网代码职责一致，未发现 goal drift。
- **Code-generation-ready**：方法与错误类型签名、URL/命名/碰撞规则、Phase A/B 状态表、测试矩阵、真实 CLI argv 与故障注入接口均已具体到可直接实现；除 `SECIMG-A1`（文件边界不完整）与 `SECIMG-A2`（一个边缘状态的期望行为未收敛）外达到可直接实施标准。
- **Overcoupling**：单 slice 覆盖「发现集合 + 版本资格 + 原子发布」有充分理由（拆开会留下仍不可补齐或可假报完整的中间态）；rebuild 停止授予下载版本被证实是成功信号 2/3 的必要条件（否则 rebuild 先跑会把旧漏图来源盖上 v1.3.0 从而被快跳吞掉），不属于范围漂移。
- **Overengineering / Optimal-solution**：无无依据的抽象、factory、profile 或兼容 shim；对照备选路径（只升版本、统一要求 overwrite、读图时补文件、按图片名/logo 筛选）计划给出的否定理由均被代码/证据支持。

### SECIMG-A2-未修复-低-「当前版本但 fingerprint 为空」状态的期望行为未收敛：reorder 后该状态会先全量 GET/发现再 skip，失败语义也随之外移

- **位置**：plan 调用与数据流 :113-117（item 4 unconditional 预取、item 7 `_can_skip` 移至发现之后）与 :137（「它仍可按既有 `_can_skip`…走 `remote_files_equivalent`」）。

- **影响**：低——多余传输与罕见状态下的失败语义漂移；测试若不显式固化会选择偶然行为。
- **建议改法和验证点**：在 plan/测试矩阵中写清该状态的期望（推荐：仍允许 `remote_files_equivalent` 跳过，但明确「跳过判定晚于一次完整 base 预取与发现」，并在 `test_sec_pipeline_download*.py` 中把 current-version + 空指纹用例改为断言完整集合等价下仍 skip、且 GET/发现发生过一次），或说明为何接受轻微行为变化。
- **修复风险（低/中/高）**：低。
- **严重程度（低/中/高/严重）**：低。
