## 5. Residual Risks（非阻塞，含 owner 与 destination）

1. **脚本预检"解释器确属本源码根 `.venv'"的实现陷阱（低）**。macOS/homebrew 下 venv 的 `bin/python` 常为指向基础解释器的 symlink；若实现用 `Path(sys.executable).resolve()` 与 `.venv/bin/python` 直比会误判失败，导致 README 安装第三步假失败。plan §7.3 已对该陷阱发出显式警告（面向 §7 探针），§4.1.3 对脚本预检只写了语义要求。In-plan 缓解存在，不构成 plan 缺陷。Owner：IE1 实现者；Destination：代码审核确认预检采用 `sys.prefix`/未 resolve 路径语义；跟踪于 IE1 代码审核。
2. **`--cov=scripts.publish_source_entry` 点分路径可导入性（低）**。pytest-cov 按模块路径度量时，无 `__init__.py` 的 `scripts/` 可能需包化或改路径形 `--cov`。属局部实现选择，留实现者与代码审核，不倒逼生产结构。
3. **§6.2 隔离真实安装体量（低）**。`".[test,dev,browser]"` 含 docling/torch 栈，隔离副本全量真实安装耗时占盘；但这是"与 README 逐字同命令"保真所必需，pip 缓存大概率已热。不是缺陷，提示执行者预留资源。
4. **非 macOS/zsh、ZDOTDIR、链接/特殊 profile、用户在受管 block 之后追加覆盖（低）**。plan 显式失败或不承诺，已入 §9 行5 owner/destination（Dayu 安装维护者；真实验收遇阻时主控裁决）。本审核未把未知用户配置当确定缺陷；真实 `~/.zshrc` 实测仅 init block，无上述迹象。
5. **真实 HOME sync 与正式验收证据待工程核收 + 明确安装通知（低，流程性）**。goal 与用户授权明确此为停点；不是工程阻塞，不得提前执行或将整个安装目标宣称完成（§9 行4）。
