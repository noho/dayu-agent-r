### 1. 语义 Ownership 收敛性

全部 6 个存储层文件均无 `hasattr`/`getattr`/fallback 模式。`FilingUploadPublicationIdentity`（`repository_protocols.py:183-306`）为 `frozen=True, slots=True` dataclass，20 个字段参与 `__eq__`，`__post_init__` 校验覆盖 SHA-256 格式、asset 排序、primary/companions 分割、`ingest_method`/`source_provider` 精确值、`is_deleted=False`、ticker canonical 与非空文本。`_build_upsert_meta()`（`docling_upload_service.py:283-327`）已提升为模块级私有唯一 owner，`prepare_upload`（第 511 行）与 `rebase_prepared_filing_create_overwrite`（第 1326 行）共同调用它；九字段无复制拼装。

### 2. Batch Fresh Read 边界

`read_filing_upload_state_in_batch()`（`_fs_filing_upload_state_core.py:202-235`）通过 `_resolve_active_batch(batch, batch.ticker)` 校验 token，只读 `state.staging_ticker_dir`，不读 published path。published read（第 139-200 行）使用 `_target_ticker_dir` + publication guard。两者共享 `_read_filing_upload_state_from_ticker_dir_unguarded` 函数，但根目录不同。staging company meta 唯一由 `_fs_company_meta_core.py::_read_company_meta_from_ticker_dir_unguarded`（第 84-122 行）解析，传入 `state.staging_ticker_dir`。

### 3. Shared Publication Owner 生命周期

`execute_prepared_filing_publication()`（`filing_upload_publication.py:586-761`）固定执行顺序：begin_batch → checkpoint1（fresh read 前）→ fresh read → fresh validator → arbitration → checkpoint2（任何 mutation 前）→ dispatch。两个 checkpoint 均返回 `request`（initial request），SKIP/PUBLISH 返回 `fresh_request`（第 637/685 vs 709/751 行）。state-dependent usage codes（`_STATE_DEPENDENT_USAGE_CODES`，第 63-70 行）正确映射为 `SOURCE_PUBLICATION_CONFLICT`。SKIP 路径先 `_rollback_without_business_terminal`（第 705-707 行）再返回，不 commit。PUBLISH 路径设置 `batch_terminal_started=True` 后转交 `commit_prepared_upload_batch`。finally 安全网仅在 `batch_terminal_started is False` 时触发。`_rollback_without_business_terminal`（第 475-498 行）只捕获 `(OSError, RuntimeFileLockError, ValueError)`，不吞 `KeyboardInterrupt`/`SystemExit`。

### 4. Workflow 集成正确性

SEC（`sec_upload_workflow.py:261`）和 CN/HK（`cn_pipeline.py:892`）均将 filing upsert 委托给 `execute_prepared_filing_publication()`。completed terminal 使用 `publication_outcome.authoritative_request`（fresh request），failed terminal 使用 workflow-level `authoritative_request`（initial request）。started event 使用 initial action。material 路径（SEC 第 413+ 行、CN 第 1035+ 行）完全不变。delete 路径保持既有 `stage_upload_company_meta_decision` + `commit_prepared_upload_batch` 直接调用。无 `FileExistsError` 捕获、无复制 arbitration 逻辑。

### 5. Filing Identical 继续 Conversion

`prepare_upload()`（`docling_upload_service.py:473-494`）在 `_can_skip_upload` 命中时，filing 不 early return，只设 `initial_skip_disposition = IDENTICAL_PUBLICATION` 并继续执行 conversion。material 仍 early return `_build_skipped_result`。`_PreparedFilingAssetMutation`（第 203-230 行）通过 `__post_init__` 严格校验 `source_kind is SourceKind.FILING` 和精确 `FilingInitialSkipDisposition` 类型。

### 6. Typed Failure 契约

`SOURCE_PUBLICATION_CONFLICT`（`upload_failure.py:51`）归属 `STORAGE` kind（第 182-191 行），factory 函数 `fins_upload_source_publication_conflict_failure()`（第 399-418 行）固定 message/retry_hint，`file_label=None`。`to_json`/`upload_failure_reason_from_json` roundtrip 测试在 `test_sec_pipeline_upload_filing_stream.py:2321` 覆盖。failure code 分组由模块级 `frozenset` 完整性/互斥性断言保护（第 199-208 行）。

### 7. 取消与 Rollback

checkpoint1（`filing_upload_publication.py:631`）在 fresh read 前；checkpoint2（第 679 行）在任何 mutation 前。waiter-wait cancel 通过 `test_writer_wait_cancellation_stops_before_fresh_read_for_all_candidate_classes`（第 1695 行）覆盖 publish/skip/conflict 三类。checkpoint2 cancel 通过 `test_second_checkpoint_cancels_closed_candidate_before_any_publication_mutation`（第 1380 行）覆盖。rollback signal exception 通过 `test_cancel_rollback_signal_exception_propagates_unchanged`（第 1527 行）覆盖 `KeyboardInterrupt`/`SystemExit`。

### 8. Same Ticker Union / Different Ticker Parallel

same-ticker different-filing 在 `test_concurrent_distinct_targets_preserve_exact_union`（第 2389 行）`same_ticker=True` 分支覆盖：两个 filing 携不同 aliases（MSFT/GOOG），结果 `"ok"/"ok"`，`frozenset(aliases) == {"MSFT", "GOOG"}`。different-ticker 在同一测试 `same_ticker=False` 分支覆盖：`_BatchReadBarrierFilingUploadStateRepository` 用 `ThreadBarrier(2)` + per-ticker `entered_events`，断言两个 fresh-read 均越过 barrier。
