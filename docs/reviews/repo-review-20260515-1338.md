### 1-未修复-严重-[runtime] CancelledError 被 lane release 异常吞噬

- **入口/函数**: `LaneController._try_claim_once`
- **文件(行号)**: `dayu/runtime/lane.py:547-556`
- **输入场景**: 外层 Task 被 `task.cancel()` 取消；SQLite claim 已成功写入；随后 `_release_untracked_claim` 的 SQLite 操作失败（如 DB 连接中断、磁盘满）。
- **实际分支**: `except asyncio.CancelledError` -> `claim = await claim_task`（shield 保证了已完成）-> `claim.acquired is True` -> `await self._release_untracked_claim(...)` 抛出 `RuntimeLaneError` -> 原 `raise`（CancelledError）**永不执行**。
- **预期行为**: 外层 Task 的 `task.cancel()` 应收到 `asyncio.CancelledError`，调用方能按 CancelledError 路径清理。
- **实际行为**: 调用方收到 `RuntimeLaneError: "SQLite runtime lane release 失败"`，而非 `asyncio.CancelledError`。原取消信号丢失。
- **直接证据**: `lane.py:553-556`，`except asyncio.CancelledError` 块内 `await self._release_untracked_claim(...)` 可能抛异常，导致 `raise` 从不执行，CancelledError 被替换为 RuntimeLaneError。
- **影响**: 调用方依赖 `CancelledError` 做 Task 级 cleanup；被替换为 `RuntimeLaneError` 后可能导致资源泄漏或 shutdown 死锁。属于任务取消语义完整性被破坏。
- **建议改法和验证点**: 在 `except CancelledError` 块内用 try/except 包裹 `_release_untracked_claim`，release 失败时用 `logging.error` 记录不阻塞 `CancelledError` 传播。验证点：构造 `task.cancel()` 触发此路径，并强制 `_release_claim_sync` 抛出 `sqlite3.Error`，确认最终异常仍为 `CancelledError`。
- **修复风险**: 低。release 失败意味着 DB claim 成为孤儿（由 TTL 自动回收），比取消信号丢失更可接受。
- **严重程度**: 严重

### 2-未修复-高-[engine] cancelled token 场景下 CancelledError 被误标为 ToolFailedOutcome

- **文件(行号)**: `dayu/engine/agent.py:1748-1772`
- **输入场景**: `ToolExecutor.execute` 抛出 `asyncio.CancelledError`，但 `cancellation_token.is_cancelled()` 返回 False（工具实现内部自行取消，不是 run-level 取消）。

### 4-未修复-中-[host] 幂等写入存在 SELECT-then-INSERT 竞态窗口

- **入口/函数**: `record_idempotent_result`
- **文件(行号)**: `dayu/host/durable/idempotency.py:148-154`
- **输入场景**: 两个并发事务分别在不同 SQLite 连接中执行 `record_idempotent_result`，各自的 SELECT 都找不到既有记录。
- **实际分支**: 两个事务各自通过 SELECT 检查后执行 INSERT。第二个 INSERT 遇到 UNIQUE 约束冲突 -> `_classify_sqlite_error()` 映射为 `HostUniqueConstraintError`，而非正确的 `HostIdempotencyConflictError`。
- **预期行为**: 同 key 同 digest 应正确返回幂等重放结果（不抛异常），同 key 不同 digest 应返回 `HostIdempotencyConflictError`。
- **实际行为**: UNIQUE 约束冲突被错误映射，调用方收到错误类型不匹配，无法区分幂等冲突与 schema 冲突。
- **直接证据**: `idempotency.py:148-154` SELECT + INSERT 非原子；`transaction.py:_classify_sqlite_error` 将 UNIQUE 约束映射为 `HostUniqueConstraintError`。

- **建议改法和验证点**: 改为 `INSERT ... ON CONFLICT DO NOTHING RETURNING ...` 或 `INSERT OR IGNORE` + 再次 SELECT 判断。
- **修复风险**: 低
- **严重程度**: 中

### 7-未修复-中-[runtime] lane heartbeat 错误全局停止所有 lane

- **入口/函数**: `LaneController._record_heartbeat_error`
- **文件(行号)**: `dayu/runtime/lane.py:803-820`
- **输入场景**: 多 lane 配置下，lane A 的 heartbeat refresh 抛出 `RuntimeLaneError`（如磁盘满），但 lane B 的 claim 仍有效。
- **实际分支**: `_record_heartbeat_error` 设置 `self._closed = True`（全局关闭），所有 waiters 被唤醒，所有 lane 的后续 `acquire` 立即返回 cancelled/errored。
- **预期行为**: lane 之间的错误应尽可能隔离。仅受影响的 lane 停止新 acquire，其他 lane 继续服务。
- **实际行为**: 所有 lane 都停止。持有 lane B claim 的 token 也无法再刷新（heartbeat loop 已返回），虽然它们尚未过期。
- **直接证据**: `lane.py:809-820`，`_record_heartbeat_error` 设置 `self._closed = True` 且未按 lane 隔离。
- **影响**: 如果 lane 用于隔离不同层面的资源（如 lane A 控制并发模型调用数、lane B 控制文件句柄数），A 的故障会导致 B 也完全不可用。
- **建议改法和验证点**: 将 `_closed` 拆为 per-lane 状态，或其他 lane 的 acquire 不受影响。或保留全局语义但更新 docstring 明确说明"单 lane 不可恢复错误会导致 controller 整体不可用"。
- **修复风险**: 中（拆 per-lane 状态涉及 `_held_tokens`、`_waiters`、`_closed` 重构）
- **严重程度**: 中

## Open Questions

1. **`dayu/engine/__init__.py` 双源 re-export**: `dayu.engine.__init__` 从 `dayu.contracts` 重新导出 22 个符号到 Engine 的公共 API surface。严格按项目"禁止兼容性代码 re-export"规则审查，这构成技术上违规。但代码文档明确标注这是架构意图（为调用方提供单一 API surface），不是兼容性转发。需裁决是否接受该设计。

2. **RunnerEvent 公开暴露**: `RunnerEvent` 及所有 Runner 事件类型都在 `dayu.engine.__all__` 中，而项目指令规定"RunnerEvent 不含 session_id/run_id，不直接暴露给 Engine 调用方"。需裁决是移除该导出还是更新架构指令。

3. **`response.release()` 同步性**: `runner.py:520` 和 `runner.py:572` 调用 `response.release()` 时未加 `await`。需确认当前 aiohttp 版本中 `ClientResponse.release()` 是否是同步方法，否则存在资源泄露。

4. **`CancellationToken` Protocol 所有实现的方法 docstring 缺 `:raises:`**: 项目硬约束要求"至少包含参数、返回值、异常"。Protocol 的三个方法只有 `:returns:` 未写 `:raises:`。当前所有实现不抛异常，但若将来某实现需要抛异常，docstring 不覆盖此场景。

5. **`dayu/fins`、`dayu/service`、`dayu/ui` 包不存在**: 这些包在架构文档中引用，但代码中不存在。禁止 import 规则当前为前瞻性约束。需确认这些包的引入计划和阶段。

6. **ToolResultFailure.error/message 无非空校验**: `dayu/contracts/tool_result.py:59-69` 中的 `ToolResultFailure.error` 和 `message` 字段均为 `str`，但未做非空校验。对比 `ToolCancelledOutcome.message` 有 `strip() == ""` 校验，模式不一致。

7. **`EngineEventType` 枚举缺少 completeness 测试**: `TERMINAL_ENGINE_EVENT_TYPES` 常量定义哪些事件会导致 Run 终止，但没有测试断言其完整性（即没有遗漏某个终态事件类型）。新增 `EngineEventType` 枚举值时可能漏更新该集合。
