## Regression Check

The plan's architectural shift from "diagnostic recorder inside `run_compaction_operation()`" to "in-memory body at operation layer + durable write at caller layer" changes the responsibility boundary. Verified for internal consistency:

1. **Data flow coherence**: `run_compaction_operation()` → builds `CompactionRejectedAttemptDiagnostic` → stores in `CompactionAttemptRejected.diagnostic` → rejection flows via `CompactionOperationResult.rejected_attempts` → caller `_append_compaction_attempt_rejected_event()` reads `rejected.diagnostic` → persists artifact/descriptor in its EventLog transaction → passes refs to `build_context_compaction_attempt_rejected_payload()`.

2. **Transaction integrity**: Descriptor and EventLog row share the same SQLite transaction in the caller's append helper. Artifact-file-only orphan (bytes written, transaction rolled back) is explicitly accepted as a local artifact tradeoff — consistent with existing `LocalArtifactStore` behavior.

3. **No new interface required**: Plan line 239 confirms `run_compaction_operation()` signature does not change — no new recorder parameter needed. The diagnostic body flows through the existing `CompactionAttemptRejected` dataclass.

4. **`CompactMaterialBlock.to_json()` exists**: Verified at `dayu/host/compaction.py:412-427`. Returns a `JsonValue` dict with `block_label`, `section`, `kind`, `text`, `size_units`, `source_labels`, `canonical_source_refs`, `content_digest`.

## New Assumptions Introduced by Fix

One new assumption was introduced by the DS-F1 fix — it is explicitly accepted but worth noting:

- **A-new**: When the caller's SQLite transaction succeeds (committing both the descriptor row and EventLog row) but the process crashes before the artifact file bytes are fsynced, the descriptor's `payload_ref` points to an artifact file that may not exist or may be corrupted. The plan accepts this as the same tradeoff already made by `DurableCompactorProposalManifestRecorder` (which writes artifact bytes before descriptor in the same transaction). This is not new risk; it is the existing artifact-store behavior.
