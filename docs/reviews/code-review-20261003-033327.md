### 1-未修复-中-O33 verified-skip 原件描述符顺序规范不一致，多文件竞争可误报 conflict

- **入口/函数**: `execute_prepared_material_publication`（材料发布执行器）→ `arbitrate_material_upload_publication`（纯竞争裁决）中的 `published == replace(candidate, document_version=published.document_version)`。
- **文件(行号)**:

- **输入场景**: 多文件材料（≥2 originals）且请求 `--files` 顺序不是文件名字典序（例 `files=(b.txt, a.txt)`）；两个相同 `auto`、非 `--overwrite` 请求并发竞争同一新身份（O33 窗口），winner 完整提交后 loser 进入执行。
- **实际分支**: loser 的 `fresh_state.publication_identity`（storage 同次投影，originals 按名排序）与 `describe_prepared_material_publication(prepared)`（D 候选，originals 为请求顺序）在 `originals` tuple 上顺序不同，`replace(document_version)` 只豁免版本字段，`==` 仍为 False → arbiter 走 `CONFLICT` 分支。
- **预期行为**: 按已裁 O33（`docs/reviews/upload-material-um-o33-oracle-adjudication.md`：权威边界确认当前已发布 identity、fingerprint、完整性相同后返回 skipped）与 plan §6.5（"一方业务成功，一方 skip"；相同原件 descriptor/role-aware fingerprint/primary/amended/公司事实即应 verified skip），loser 必须得 `IDENTICAL_SKIP`，终态恰一 ok 一 skipped。
- **实际行为**: loser 得到 typed `source_publication_conflict`（"目标材料在上传准备期间已发生变化，本次材料上传未提交"），与 winner 实际状态不符；同一请求无竞争时可成功。单文件材料（V12 探针输入）与字典序文件顺序不受影响，故既有验证未暴露。
- **直接证据**: ①两构造点顺序不对称（2101 `sorted(...)` vs 2215 请求序推导）；②`MaterialUploadPublicationIdentity` 为普通 frozen dataclass，`__post_init__`（`repository_protocols.py:138-156`）只校验非空/无重名、不归一顺序，默认 `__eq__` 对 tuple 顺序敏感；③本轮独占探针实测：同 descriptor 集 `(a,b)` 与 `(b,a)` 构造的 identity `==` 为 False，`replace(..., document_version=...)` 后仍 False；④指纹 `_build_upload_source_fingerprint` 对 companions 按名排序（顺序无关），故仅 identity 比较暴露差异；⑤真实调用链 `material_upload_publication.py:202` 传 `describe_prepared_material_publication(prepared)` 候选，而 `tests/fins/test_material_upload_publication.py:243-246` 的裁决断言直接传 `final.publication_identity` 绕过两构造点差异，`test_old_admission_winner_actual_final_then_identical_skip` 亦为单文件，均未覆盖此路径。
- **影响**: 已接受的 O33 并发承诺（同 identity 并发 verified skip / 真实双 CLI 一成功一 skip）对多文件非字典序请求失效；用户可见伪 conflict 错误（fail-closed，无数据损坏、无半发布、无公司反向删除；重试可恢复）。
- **建议改法和验证点**: 把 originals 顺序收敛到 identity 唯一 owner——建议 `MaterialUploadPublicationIdentity.__post_init__` 按 `name` 排序归一（两个生产者自动同源），或 `_describe_material_candidate` 与 storage 投影共用同一排序 helper；补 owner 级测试：两文件非字典序请求、两个 old MISSING admission、winner 提交后 loser 经 `describe_prepared_material_publication` 真实候选得 `IDENTICAL_SKIP`；现有单文件 V12/race-final-13/14 结果与顺序 skip 断言保持。
- **修复风险（低）**: 归一化只统一新构造 identity 的相等语义；持久化事实不变（storage 投影本已是排序序）。
