#### 2. idle Ctrl+C 修复真实性与跨层泄漏检查

**root cause 证据**：

- auto-validation PTY probe (`docs/reviews/wu-cli-smoke-01-auto-validation-codex.md:99-109`)：idle `dayu>` prompt 下单次 Ctrl+C 直接退出进程，`exited_after_first_ctrl_c=True`，`decision=fail`。
- 代码走读 (`dayu/cli/commands/interactive.py:505-508`)：原 `_run_interactive_repl` 捕获 `EOFError` 但不捕获 `KeyboardInterrupt`，空 prompt 中断逃逸到 `run_interactive_command` 的 `except KeyboardInterrupt` (line 206) → exit 130。

**修复验证**：

- 新增代码 (`interactive.py:504-517`)：8 行 CLI-local 状态管理。
- `idle_interrupt_exit_pending` 是函数局部 `bool`，不进入任何持久化、Host state、EventLog、durable schema 或 composer 协议。
- 状态机行为矩阵（走读 `interactive.py:507-520`）：

| 当前状态 | 触发事件 | 下一状态 | 副作用 |
|---|---|---|---|
| `False` | `KeyboardInterrupt` | `True` | `continue` → prompt 重绘 |
| `True` | `KeyboardInterrupt` | 终态 | `return EXIT_KEYBOARD_INTERRUPT` |
| `True` | `composer.read()` 返回文本 | `False` | 正常处理输入 |
| `True` | `EOFError` | 终态 | `return EXIT_SUCCESS`（先重置为 False） |

- PTY probe post-fix (`docs/reviews/wu-cli-smoke-01-slice-s1-implementation-codex.md:42-43`)：`exited_after_first_ctrl_c=False`，`exited_after_second_ctrl_c=True`，`decision=pass`。

**跨层泄漏检查**：

- `InteractiveComposer` 协议（`dayu/cli/composer.py`）：未修改。
- prompt-toolkit key binding（`composer.py:116-124`）：未修改。
- Service / Host / Engine：未修改。
- durable schema / EventLog / Fins storage / wait lifecycle：未修改。
- `_submit_interactive_turn_handling_sigint`（运行态取消路径）：未修改。

**结论**：修复真实关闭复现问题，严格限制在 CLI-local REPL 状态管理，无跨层泄漏。
