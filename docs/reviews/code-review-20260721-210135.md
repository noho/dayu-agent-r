## Findings

### 1-已修复-严重-`pop_next_nowait()` 丢失 watcher-local terminal fence，stale transient 可被错误交付

- **入口/函数**: `HostTransientDeltaSubscription.pop_next_nowait()`
- **文件(行号)**: `dayu/host/transient_delta.py:415-436`
- **输入场景**: mailbox 中已预存同 Run transient item；`_watch_session_events_after` generator 在 `pop_next_nowait()` 返回 None（mailbox 空）后 `await self._durable_actor.call(...)` 读取 durable batch；await 期间同 Run transient 通过 `_offer()` 进入 mailbox；durable batch 返回后 generator 调用 `mark_run_terminal(run_id)`；下一次 `anext()` 调用 `pop_next_nowait()`
- **实际分支（修复前）**: `pop_next_nowait()` 直接 `self._mailbox.popleft()` 取出 item，不检查 `self._terminal_run_ids`
- **预期行为**: watcher-local terminal fence 命中的 mailbox item 应被丢弃，不进入 `_in_flight`，不交付给 caller
- **实际行为（修复前）**: stale transient 被转为 in-flight 并交付给 caller，形成已终态 Run 的虚假增量
- **直接证据**:
  1. 修复前 `pop_next_nowait()` 行 427-435 直接 `popleft()` 不检查 `_terminal_run_ids`
  2. accepted base 的 `drain_nowait()` 有 `item.run_id in self._terminal_run_ids` 过滤（旧代码行 930-931）
  3. `_offer()` 仅能拒绝 `mark_run_terminal()` 之后的新 publish（行 524 `event.run_id in self._terminal_run_ids → return`），不能处理 mark 之前已进入 mailbox 的项
  4. Codex 红灯复现：`test_single_pop_filters_prequeued_terminal_stale_item` 加入后、修复前，精确 node 失败并输出实际返回 `run-1`（预期 `run-2`）
- **影响**: 已终态 Run 的 stale transient 被错误交付给 watcher；S4 Service exact-five 的 terminal identity dedup 可能因此看到虚假事件
- **修复**: `pop_next_nowait()` 现在在 while loop 内逐项检查 `event.run_id in self._terminal_run_ids`，命中时 `continue`（丢弃），首个有效 item 才 transfer 到 `_in_flight`（`dayu/host/transient_delta.py:428-434`）
- **验证点**: `tests/host/test_transient_delta.py::test_single_pop_filters_prequeued_terminal_stale_item`（stale-only + mixed stale+valid 两个确定性场景）；Controller 描述的 durable read await 交界 race 场景
- **修复风险（低）**: single-pop stale 扫描受现有 retained item policy 上界约束；不引入 batch 返回、额外 retained copy 或 Slice 2 causal fence
- **严重程度（严重）**: correctness finding — terminal delivery 语义缺失，已修复

## Open Questions

1. **大量 Session 的 20ms polling CPU**：在大量 Session 同时处于 CLOSING polling 的极端场景（per-Session cap=4，多 Session 同时关闭），N × 20ms polling 的累积 CPU 开销是否需要关注？当前 stress test 仅覆盖单/少 Session 场景，S2/S3 双 opener + 多 Session stress 可加入此维度。此为非 S1 新行为（常量在 base 已存在），非阻塞。

2. **S1 期间 Service relay 256 与 Host mailbox 512 的交叉**：`entrypoint_runtime.py` 的 `asyncio.Queue(maxsize=256)` relay 在 S1-S3 期间继续运行。上游 Host delivery 已改为 512 item-bound mailbox。若 Service consumer 极慢（callback 阻塞），relay queue 先满（256）而 Host mailbox 尚未满（512），可能导致 relay `QueueFull` 行为不同于设计预期。S4 删除 relay 后此风险清除。plan 已冻结 S1-S3 中间态不创建 PR，非阻塞。

## Residual Risk

1. **S2 causal fence 对 S1 基础设施的依赖**：S1 reservation/mailbox/in-flight/overflow 状态机已完成单 opener 边界验证。S2 cross-opener reconciliation 在此基础上进行。若 S1 有未被发现的 off-by-one（当前无 direct evidence），S2 的跨 opener ordering 可能将其放大。缓解：S1 测试覆盖了 cap−1/cap/cap+1、并发 attach 线性化、detach readmission 和 different-Session isolation。

2. **Host close ordering 的完整验证**：S1 实现了 hub close 移到 producer cleanup 之后（`open_host.py:1097`）。S3 将在两者之间插入 coordinator in-flight drain/port close。必须确保 S3 插入的 coordinator close 不改变 delivery close semantics。缓解：S1 测试覆盖 CLOSING → wait_ready → close wakeup 路径。

3. **Config `512/4` 在 packaged JSON 与多测试 fixture 中重复出现**：packaged default 与独立 construction fixtures 的重复是 plan 要求的"无 hidden fallback"设计 — 各层独立构造 policy 可作为独立 drift detection。变更默认值需全量搜索，但不构成 hidden coupling。

4. **`_clear_retained_state()` 同时清除 `_terminal_run_ids`**：旧实现 `_clear_queue()` 不清除 `_terminal_run_ids`（close 后 subscription 不再使用）。新实现增加了 `_terminal_run_ids.clear()`，语义上是 close cleanup 的自然延伸。确认无 caller 在 close 后仍访问 `_terminal_run_ids`（当前无），非风险。

5. **`test_watch_factory_cancellation_close_race_and_allocation_failure_release`（`tests/host/test_watch_session_events.py:544-693`）** 将三个独立 failure scenario 合并为单一 test function。若任一 scenario 的 assertion 因 regression 失败，需排查三个 scenario 的共享 monkeypatch 和 shared Host instance，降低故障隔离效率。建议 S2 实施时拆分为三个独立 test functions。

### 架构与 owner boundary 检查

- **分层**: `dayu.runtime.config_loader` 定义层中立 typed config，不 import Host；`dayu.service.host_assembly` 一对一构造 Host policy；`dayu.host.transient_delta`/`open_host` 是 delivery owner。无反向依赖。
- **Public contract**: `HostSessionEventDeliveryPolicy` frozen/slots，两个 required positive-int 字段无默认值；`HostSessionEventIterator` Protocol 与 `Host.watch_session_events` async factory 对齐；所有 new types 通过 `dayu.host.__all__` 导出。
- **Semantic ownership**: transient mailbox/in-flight/terminal fence/overflow/reservation cap 的唯一 owner 均为 `HostTransientDeltaSubscription`/`HostTransientDeltaHub`；Service 仅消费 public iterator，不保存 Host event 副本或第二 observation channel。
- **State machine**: RESERVED → ATTACHED → OVERFLOWED → DETACHED 状态机由 owner-loop 无 `await` 临界段保证线性化；retained_items = mailbox + in-flight 不变量在 7 条操作路径逐一验证。
- **Overcoupling**: 未发现。delivery policy 经 typed config → assembly → Host 单向传播，无跨层穿透或双向依赖。
