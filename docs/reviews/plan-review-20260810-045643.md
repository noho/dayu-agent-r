## Findings

### 01-未修复-低-`_PipelineDownloadFakeConverter` 同步到异步迁移未显式说明

- **位置**: §5.2 第 1 点
- **问题类型**: 不可直接实施
- **当前写法**: amendment 声称"把 `_PipelineDownloadFakeConverter` 迁为实现 `CnDoclingConversionRunner` 的 typed deterministic fake runner；方法必须为 `async convert_pdf_to_docling_json(...)`"
- **反例/失败场景**: 实现 agent 可能只修改方法名和签名而不移除 `asyncio.to_thread` 包装，或不理解当前 `_PipelineDownloadFakeConverter.__call__` 是同步的这一事实
- **为什么有问题**: 当前 `_PipelineDownloadFakeConverter.__call__` 是同步方法（`test_cn_pipeline.py:242`），被 `cn_download_filing_workflow.py:331` 通过 `asyncio.to_thread(convert_pdf_to_docling_json, pdf_bytes, pdf_filename)` 调用。迁移为 `async` 方法后，filing workflow 的调用方式必须从 `asyncio.to_thread` 改为 `await`，这涉及 production 文件 `cn_download_filing_workflow.py` 的修改。amendment 隐含了这一变更但未显式说明。
- **直接证据**:
  - 当前同步签名：`test_cn_pipeline.py:242` `def __call__(self, raw_data: bytes, stream_name: str) -> bytes`
  - 当前 to_thread 调用：`cn_download_filing_workflow.py:331-335` `await asyncio.to_thread(convert_pdf_to_docling_json, pdf_bytes, pdf_filename)`
  - amendment 要求新签名：`async convert_pdf_to_docling_json(pdf_bytes: bytes, stream_name: str, *, cancellation_checker: Callable[[], bool]) -> bytes`
- **影响**: 实现 agent 需要同时修改 test fake（同步→异步）和 production filing workflow（to_thread→await），但 amendment 未明确指出这一联动。风险较低，因为 base plan §5.5 已明确说明 Docling 将使用 typed runner 替代 asyncio.to_thread。
- **建议改法和验证点**: 在 §5.2 第 1 点补充说明"当前 `_PipelineDownloadFakeConverter.__call__` 为同步方法，被 filing workflow 通过 `asyncio.to_thread` 调用；迁移后 fake 变为 async，filing workflow 改为直接 await runner 方法"。验证点：migration 后 `cn_download_filing_workflow.py` 中不存在 `asyncio.to_thread(convert_pdf...)`。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低
