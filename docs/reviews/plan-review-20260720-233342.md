**直接证据：**

- Plan §4.3（第 183–184 行）冻结唯一 owner："Service bounded relay 的唯一 owner 是 `dayu/service/entrypoint_runtime.py` 中由 `_WatchAndWaitRuntime` 及其 factory 创建的 `queue`…factory 使用有名常量 `_ENTRYPOINT_LIVE_EVENT_BUFFER_CAPACITY = 256` 构造 `queue(maxsize=...)`"。
- Plan §4.3（第 184 行）明确排除："terminal-only（例如目标 Run 在 attach 前已终态）、无 watcher、一次性 outbox/drain 的 queue 不属于 live relay，保持现有语义，不机械设限"。
- 代码证据确认当前 3 个 live relay queue 创建点：`entrypoint_runtime.py:647`（submit_followup path）、`:719`（cancel_entrypoint_run_and_wait 的 live watcher path）、`:770`（startup reconnect path）。1 个 terminal-only queue：`:707`（cancel path 且 `is_terminal_run_status` 已为 true 的 early-return）。
- Plan §4.3（第 187–201 行）完整写出 backpressure 链：`await queue.put` 阻塞 → 不再调用 Host iterator `__anext__` → Host merge iterator 暂停 → Host subscription queue 满 → `put_nowait` overflow → typed `UNAVAILABLE/slow_consumer` → `_WatcherFailure` 保存原 `HostApiError` → 既有 typed diagnostic/Outbox fallback。
- Plan §4.3（第 201 行）禁止 Service 侧破坏链："禁止对 live relay 使用 `put_nowait`、捕获 `QueueFull` 后丢 item、替换旧 item、预留旁路槽、把 Host error 改造成另一异常，或仅写日志后继续伪装连续流"。
- Plan §8.4（第 461–463 行）增加 owner-level propagation test 断言："relay 满时 `_drain_host_events` 停在 `await queue.put`…Host subscription 最终 overflow…`_WatcherFailure.error` 是原 `HostApiError`"。
- Plan §8.4（第 463 行）确认 terminal/outbox 不丢："构造 relay 满、Host overflow 与 durable terminal/outbox 紧邻的受控场景，断言 Outbox terminal identity 未丢、Run 不 cancel/fail"。
- 当前代码 `_drain_host_events`（`:979-996`）使用 `await queue.put(event)`，异常由 `_WatcherFailure` 保存 — 与 plan 的传播链一致。

**评估：**唯一 owner 已冻结；terminal-only queue 已准确排除；backpressure 传播链完整且禁止了所有破坏路径；owner-level test 已纳入 Slice 2 acceptance。满足 controller 要求。

### C. attach/cursor error timing、Host public typed error 与 aclose cleanup

**裁决：fixed**

**直接证据：**

- Plan §4.2（第 149–156 行）冻结 attach 语义："同步调用 `watch_session_events` 时先完成 public lifecycle gate；handle 已关闭时当场抛 `HostClosedError`，且不创建 subscription。打开状态下必须在返回 iterator 前同时注册 transient subscription，并把 Session 存在性检查所需 durable cursor read 提交给 durable actor"。
- Plan §4.2（第 151–153 行）冻结 cursor failure contract："iterator 首次 `__anext__` 必须先 await cursor future；Session 不存在/已 purge 时抛 public `HostApiError(code=NOT_FOUND, retryable=False)`。其它 durable read failure 继续由 `HostCommandHandle._run_read` 的 public error mapping 表达为 `HostApiError`…不得泄漏 `HostDurableError`、actor future/private operation exception"。
- Plan §4.2（第 155–156 行）冻结 cleanup owner："cursor future failure、首次或后续 `__anext__` cancellation、iterator 内部异常、显式 `aclose()` 都在同一个 Host iterator owner boundary detach subscription；同步 attach 中途失败必须回滚已注册 subscription"。
- Plan §4.2（第 156 行）明确解决 never-started 问题："Host 返回的内部 closable iterator 必须拥有 subscription 与 cursor future，而不能只依赖 async generator 首次进入后的 `finally`。调用方取得 iterator 后从未开始迭代便立即 `aclose()`，也必须 detach；cursor future 由 done observation/owner cleanup 收口，不产生 unhandled-future warning"。
- 代码证据 `open_host.py:895-915`：当前 `watch_session_events` 已同步 `_raise_if_closed()`（lifecycle gate），submit cursor future 并 add done callback，返回 async generator `_watch_session_events`。当前 `_watch_session_events` 在首次 `__anext__` 时 `await cursor_future`。
- 代码证据 `open_host.py:1127-1140`：`_observe_watch_cursor_future` 已消费未开始 future 的异常，避免 unhandled-future warning。
- Plan §5.3（第 267–270 行）确认 never-started cleanup："Host 内部 closable iterator 共同拥有 cursor future 与 subscription；同步 attach 中途失败、cursor failure、首次/后续 `__anext__` cancel、iterator error、started `aclose()`、never-started immediate `aclose()` 都幂等 detach，并观察/收口 cursor future"。
- Plan §8.3（第 453 行）测试矩阵冻结："cursor future failure、首次 `__anext__` cancellation、后续 iteration cancellation/error、started `aclose()`、never-started immediate `aclose()` 各自把 subscription count 恢复到 attach 前…future exception 已观察且无 pending task/warning"。
- Design diff 确认设计真源同步："cursor future failure、首次或后续 `__anext__` cancellation、iterator error、显式 `aclose()`，以及 iterator 返回后从未开始迭代便立即 `aclose()`，都必须在同一个 iterator owner boundary detach subscription…未开始迭代的 cursor future 仍须被观察/收口，不能产生 unhandled-future warning 或遗留 subscription"。

**评估：**error timing 精确（同步 lifecycle gate → 首次 `__anext__` await cursor → typed public error）；Host public typed error 映射完整（NOT_FOUND/INTERNAL_ERROR 沿既有 mapping）；closable iterator owner 解决了 async generator never-started finally 不执行的问题；cleanup 测试矩阵覆盖所有路径。满足 controller 要求。

- Plan §3.3（第 69 行）："一个 accepted transient candidate 只构造一个 public envelope；所有已 attach 的目标 watcher 收到相同 `runtime_id`、`runtime_sequence` 与 `dedupe_key`"。

**用户明确非目标：**
- Plan §3.2（第 57–63 行）的非目标未改变：不提供 durable delta replay、历史查询、断线补放、跨进程 broker、统一 cursor、Engine contract 修改、canonical HostEvent/outbox/audit 重写、R2 thinking panel、通用 delta callback、public buffer tuning、retention/purge、generic event bus、`dayu.runtime` helper。
- Plan §12.2（第 544–545 行）："跨进程/跨 Host instance 多 watcher 不可见…未来若需要 broker/replay，必须重新设计"。
- Controller adjudication："跨进程、Host restart、reconnect replay…是用户已确认的明确非目标，不能据此扩大当前 WU"。Plan 未违反。

**评估：**plan-fix 未引入 semantic ownership 漂移、delta row 回归、multi-watcher 破坏或非目标扩张。
